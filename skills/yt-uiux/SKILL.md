# yt-uiux: 设计

让一个模糊的产品想法，长成一个扛得住审问的界面。

## 认知起点

界面不是装饰，是把「用户任务」翻译成「一眼就懂、一步就完成」的秩序。设计就是排秩序：先排对，再排美。多数人一上来就排美，所以做出来的东西只能看，不能用。

所以先问任务，后问好看。五个阶段按序走，前面没定，不进下一步。

## 输入

产品/页面描述、功能需求、截图、竞品链接，或一句模糊想法。给得越少，第一阶段问得越多；不要怕问，怕的是不问就画。

## 五阶段流水线

### 一、需求淬炼

先把模糊需求淬成一句不可再分的话，再动手。

产出三件：

1. **核心任务**：这个界面要让用户完成的那一件事，用一句话写死。不是「提供 XX 功能」，是「用户在 3 秒内完成 XX」。
2. **目标用户**：谁在用，什么设备，什么场景，什么情绪。
3. **成功标准**：怎么算成了——完成率、耗时、误操作率，不是「好看」。

禁词：赋能、闭环、一站式、沉浸式、极致体验。出现一个，打回重写。

### 二、信息架构

定完任务，排内容。界面上的东西按什么分组、什么层级、用户先看到什么后看到什么。

产出：

- **页面清单**：一共几个页面/视图，每个承载哪个子任务。
- **导航结构**：层级树，用户从哪进、到哪去。
- **关键路径**：完成核心任务的最短路径，画出每一步。

规则：能少一个页面就少一个。每个多出来的页面都要交代「为什么不能并进别的页面」。

### 三、线框

不动颜色字体，只排结构。每页画区块、标优先级、写交互。

产出：每页的区块布局（ASCII 结构图）+ 每个区块的一句话职责 + 关键交互标注（点击后发生什么、空态/错误态长什么样）。

规则：

- 一个页面一个主任务，主区块占最大面积，其余全部给主任务让路。
- 空态、加载态、错误态必须画出来，不然不算完成。

### 四、设计系统

结构和交互定完，才谈视觉。产出一套可复用的 token 和组件规范。

产出：

- **颜色 token**：主色/中性色/语义色（成功/警示/错误），每色给用途和对比度说明。
- **字体**：字族 + 字号阶梯 + 行高 + 字重，说清哪一级用在哪。
- **间距/圆角/阴影**：刻度与使用场景。
- **组件规范**：按钮、输入、卡片等关键组件的状态与尺寸。

反 AI 味铁律（不可破）：

- 禁 Inter、禁纯黑 #000、禁三等分卡片、禁居中 Hero。
- 颜色给具体 hex 和用途，不给「柔和的蓝色」这种废话。
- 每一级字号都要答「为什么是这一级」。

### 五、对抗审查

设计做完，最后自己拆自己。不许说好话，只找会失败的地方。

逐条审：

1. 核心任务是否真的三步内完成？哪里会卡？
2. 哪个假设没被验证？（用户真的会这么理解吗？）
3. 空态/错误态真的处理了吗？
4. 移动端/窄屏会不会崩？
5. 有没有为了好看牺牲了可用？（装饰压过了任务）

每条给：问题 + 理由 + 改法。最后给一版「改单」，按优先级排。

## 输出

- 格式：Markdown（用户可要求 org-mode）。
- 内容：五个阶段的产物，阶段间用清晰标题分隔，对抗审查放在最后。
- 呈现：直接在对话输出；用户要求落盘时，写到指定路径并告知完整路径。

## 生成规则

1. 基于用户给的真实需求，不编造。缺信息就问，不硬撑。
2. 敢下判断。「可以考虑 A 也可以考虑 B」是废话，选一个给理由。
3. 每个设计决定附理由——为什么这么分组、为什么这个字号。
4. 禁词：赋能、闭环、一站式、沉浸式、极致、丝滑。
5. 以说透为准，不计字数。
6. 中文撰写。
