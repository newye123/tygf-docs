# 官制模板（编制册 + 回收算法）

用法：把下面「编制册」整块复制到 `总控/官制.md` 作为唯一在册账；每次派工/收包只改这张表，不改历史。
**在册即有权，不在册即无权**：没有槽位的会话不得写入任何共享面。

## 一、编制册（表头固定，行可增删，列不得改）

```markdown
# 官制 · 编制册

维护者：总控（只派不做）  最后巡检：YYYY-MM-DD HH:MM  巡检手：副总控/御史
编制上限：8（六部 + 御史 + 将作）  当前存活：N/8

| 槽名 | sessionId | 当前任务 | 状态 | 最后写入面 | 开工基线 SHA | 收包路径 | 备注 |
|---|---|---|---|---|---|---|---|
| 户部 | 00000000-… | 账务对账列 | 在飞 | src/lib/server/**, prisma/** | a1b2c3d | 总控/回收_/S1_回包.md | |
| 刑部 | — | — | 空闲 | scripts/smoke-*, package.json(test:*) | — | — | 未建会话 |
| 工部 | — | — | 空闲 | scripts/*metrics*, docs/records/ | — | — | |
| 兵部 | — | — | 空闲 | config/release-identity.json, deploy/** | — | — | 发版窗口独占 |
| 礼部 | — | — | 空闲 | src/components/**, src/app/(页面) | — | — | |
| 吏部 | — | — | 空闲 | docs/**, product-specs/**, AI_MEMORY/** | — | — | 文档独占，禁与代码同包 |
| 御史 | 11111111-… | 只读巡检 + 记账 | 在飞 | （无写权）总控/巡检_*.md | — | — | 可直报 Owner |
| 将作 | — | — | 停用 | 临时树 worktrees/<task>-<date> | — | — | 用完即撤 |

状态取值：空闲 | 在飞 | 挂起 | 已解任
```

字段口径（写死，避免各自解释）：

- **槽名**：六部之一或御史/将作；一个槽同一时刻**至多一个在飞任务**。
- **sessionId**：真实会话 id；`—` 表示该槽尚未建会话。
- **状态**：
  - `空闲`＝可派；`在飞`＝有任务且未交回包；`挂起`＝超时无回包或等平台拒；`已解任`＝交包后逻辑退编。
  - `已解任` 的槽**不再接受派活**（防僵尸 worker 被复用），要复用得先由总控"重新起复"并写明日期。
- **最后写入面**：上一次实际改动的路径集合（用于判越界）。
- **开工基线 SHA**：派工时钉死的 commit；收包时产物必须长在它之上，或显式声明"另起分支"。

## 二、派工算法（写死，不留自由裁量）

```text
派活(任务):
  0. 读能力现状 = 总控开场先核 总控/产品功能全景_<最新日期>.md 页眉"核验时刻"日期
     不是当日 → 先派一次吏部重核包，再派任何活（不建 cron、不新建自治轮）
     再定位本任务触碰能力所在行，取该行 file:line + 状态（T/P/N/U）；表里没有这一条，
     或该行已过上述日期 → 先派一次盘点（吏部），不得凭印象拟令，也不得写"没有该功能"
  1. 选槽 = 按任务写入面匹配"槽名.授权写入面"
     若命中多个 → 取写入面最窄者；若无命中 → 停车上报 Owner（不硬塞）
  2. 在册中找 选槽 且 状态=空闲 的行
     有 → 复用该 sessionId，置状态=在飞，写当前任务/基线 SHA
     无 → 若 存活槽数 < 8：新建 chat 会话 → 立即入册（状态=在飞）
          若 存活槽数 = 8：先解任"最老的空闲槽"（状态=已解任），再新建并入册
  3. 发一次任务书（八字段齐全，含"能力现状"）。不追加、不追问、不等批复。
     分界：2026-09-23 11:00 前已派出的在飞包按七字段收，缺"能力现状"不是封驳理由。
     封驳只认五类：基线错／写入面越界／退出码或锚点造假／判据未满足／与权威清单冲突且未实测。
  4. 记录"派工时刻"，用于超时判挂起。

收包(回包):
  5. 门下复验（另一只手）→ 七项全过则考功入账
     （第 6 项＝与全景表对齐；第 7 项＝任务书判据本身可跑，判据错单开"总控判据错"一节，
       记总控不记执行手）
     通过   → 状态=已解任（会话不删，逻辑退编）；结论与表不符则由吏部回写该行
     驳回   → 同槽重派，轮次 +1；轮次 >3 → 换槽新会话；仍不合格 → 停车上报
     超时无包 → 状态=挂起；巡检手核对现场（porcelain/mtime），先保存孤儿现场再续派
```

关键取舍（照抄会出事的地方）：

- **新建会话的窗口不稳定**（平台在被委派轮次内拒绝 `create_chat_session`），所以算法**先查册复用**，新建是兜底路径而非默认路径。
- **长活/跨夜一律 chat 会话**，不派后台 Agent（会被用户插话连带杀死且不发完成通知）。
- **解任 ≠ 删除**：历史必须可查；膨胀的是"可派池"，不是磁盘。

## 三、巡检（御史，只读）

```bash
# 一棵树该不该报"有人在写"
git -C <树> status --porcelain              # 非空 = 有未提交现场
git -C <树> log --format=%H -1              # 在册基线是否还是它
find <树>/{src,scripts,config} -newermt '-10 minutes' -type f | head   # 分钟级活动
```

巡检只得出三种结论：`无主未提交`（立即存补丁快照 + 登记）、`在册在飞`（不动）、`基线漂移`（上报）。**不推断意图**，不采信任何会话自述。

## 四、发版窗口的特殊规则

兵部（发布与部署）在发版窗口内**独占**：窗口期禁止其他槽写发布身份相关文件（版本号、manifest、latest 文案、安装包），否则会出现"包与声明不符"。窗口开闭都要在编制册写明起止时间与负责人。
