03四个问题的对抗式审查

G1

开源主程序？——数学不成立，不批

不批

① 助手引擎含自攻保护（反提取/自删除/完整性锚点）——开源=把防御摊开给逆向者；② attempt/ticket 逻辑公开=伪造回执的门票；③ 此刻开源=公开审计一个自己没审完的仓库（37 棵脏树、contracts 三版、4 条 blocker）；④ GPL 传染会污染用户交付物口径，法务未排期。触发重议的四前提：云端侧剥离+自攻重构+blocker 清零+法务意见——90 天窗口外。

G2

README 重写？——最高杠杆，稿已备好

做

门面是每个触点（GitHub 搜索、尽调、分享链接）的第一眼，现在是负资产。待签替换稿（对标 comic-translate 骨架，禁写清单逐条自查）：定位一句话（中英）→ 它是什么/不是什么对比表 → 工作流四步 → 能力矩阵 → 隐私数据流 → 平台要求 → 内测开始 → FAQ → 协作者技术栈。前置：Owner 一句 + 礼部文本流程；demo 区只用合成样例描述（客户件 5857 禁外传）。

G3

public 化策略？——学 ImageTrans，三仓分层

一句授权

主仓维持 private。新建两个 public 辅仓：tygf-docs（安装/使用/FAQ/更新日志，对标 ImageTrans-docs，不进业务逻辑）+ tygf-samples（PSD 样例+CSV 模板+术语表，只放合成/脱敏图谱）。不含源码、客户素材、密钥。维护判据：随每个助手版本更新，否则 stale 即负资产、下架。

G4

stars 值多少？——不设 KPI，设尽调判据

改判据

客群是 LSP/外包设计团队，不在 GitHub 找工具；2,976★ 对应免费开源用户池，与我们 ¥199 买断层不同构。GitHub 不进引流 KPI，定位「尽调可信度层」：判据＝「10 家试点尽调 ≥3 家查阅过公开仓/文档」。流量主渠道仍按运营方案 §5.2/§5.3（B 站/知乎/服务商定向）。
