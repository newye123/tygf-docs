## 2. 对抗式审查：四个必须回答的问题

### G1 · 开源主程序？—— 数学不成立，不批

- **立论**（为什么会被提）：开源 = 信任 + 口碑 + PR 贡献；comic-translate/BallonsTranslator 双例引诱。
- **反证**：① 本地助手引擎含**自攻保护机制**（反提取/自删除/完整性锚点，历史 #100 方案链）——开源即把防御代码摊开给逆向者看；② 商业闸（Batch Billing V3、票据/结算）全在云端侧，但助手侧 attempt/ticket 逻辑公开=伪造回执的门票；③ 我们的代码卫生状态：37 棵脏树/412 行的现场、`test:contracts` 三版并存、4 条 blocker ISSUES 未收口——**现在开源等于公开审计一个自己没审完的仓库**（10-09 审查 §3D）；④ license 传染：参考 BallonsTranslator 的 GPL 模式会污染用户生成的交付物口径，需法务未排期。
- **判决**：**不开源主程序**。同理不批 public 镜像源码仓。
- **触发**：cloud 侧剥离 + 自攻保护重构完成 + ISSUES blocker 清零 + 法务 license 意见——四件事齐了再议（不在 90 天窗口内）。

### G2 · README 重写？—— 最高杠杆，今天可做

- **立论**：门面是 every touchpoint 的第一眼（GitHub 搜索、尽调、分享链接）。v0.1 版 README 现在起的是**负资产**作用： prospect 看到"内测版 v0.1""演示模式""demo 邀请码"会直接判定为 demo 项目。
- **反证**：① README 属 tracked 仓库文件，改动要走"对外文本"写入面（礼部流程 + Owner 一句）——不是完全零成本；② demo 素材受禁写清单约束（客户件素材 5857 禁外传）⇒ 新 README 的 demo 区只能用**合成样例图谱**或措辞描述，不能直接贴真实案件截图；③ 私有仓状态下 README 无外部读者——**先 public 化才有读者**（与 G3 绑定）。
- **判决**：**写，且已写好待签**。排序在"public 化"之前完成，public 那一刻门面即在线。
- **触发/前置**：Owner 一句 + 礼部过口径；替换稿 `README-宣传版-待签替换_20261014.md` 已按其禁写清单逐条自查。

### G3 · public 化策略？—— 学 ImageTrans，三仓分层

- **立论**：B2B 尽调要"真实存在感"（E2 §4 判据：主体未公示、无 DPA 是采购硬门槛）；GitHub 公开面是运营主体透明化的最轻补丁。
- **反证**：① 主仓 public 需要 G1 四前提，短期不可达；② 新开 public 辅仓（docs/模板）本身也是"对外承诺"——文档仓内容同样受禁写清单约束；③ 新仓维护成本：一旦 stale 就是负资产（G5 同款逻辑）。
- **判决**：**两仓方案**：① `tygf-docs`（公开文档：安装/使用/FAQ/更新日志，对标 ImageTrans-docs，不进任何业务逻辑）② `tygf-samples`（PSD 样例 + CSV 模板 + 术语表模板，**只放合成/脱敏图谱**）。两仓都不含源码、不含客户素材、不含密钥。**主仓保持 private，运营期不动。**
- **触发**：Owner 一句（新建 public 仓库=对外动作）。维护判据：每随一个助手版本更新，否则下架。

### G4 · stars/流量值多少？—— 不设 KPI，设尽调判据

- **立论**：GitHub 面=发现渠道，运营方案 §5.3 阶段 0 闸门三"用户找得到"。
- **反证**：① 我们的客群是第一层（LSP/外包设计团队）不是开发者——他们不在 GitHub 找工具（E2 §4.1"买家千级"在 LinkedIn/ProZ/行业社群，不在 GitHub）；② comic-translate 的 2,976★ 对应免费开源用户池，与我们 ¥199 买断层不同构——**stars 与付费承诺零传导证据**；③ 内容飞轮 K5（6 个月观看 <1000/月停投）的同类逻辑适用于此。
- **判决**：**GitHub 不进引流 KPI**。它的定位是"尽调可信度层"：判据写为「10 家试点尽调中 ≥3 家查阅过我们的公开仓/文档」。流量主渠道仍按运营方案 §5.2/§5.3（B 站/知乎/服务商定向）。
- **触发**：试点尽调记录里没人提仓库 ⇒ 两仓维护降级为年度更新。
