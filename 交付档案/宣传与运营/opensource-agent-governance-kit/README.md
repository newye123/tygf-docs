# Agent Governance Kit

**一套让「多个 AI 会话协同干活」时，'绿'这个字重新变得可信的最小工具集。**

> 不是又一个多智能体编排框架。这里解决的是编排框架普遍不管的那半边：**怎么让 AI 说出的"做完了"值得相信。**

---

## 这个包解决什么问题

如果你用多个 AI 会话（或换着用 Claude Code / Codex / Cursor / OpenCode）在同一个仓库上干活，几乎必然遇到这五件事：

| 症状 | 根因 |
|---|---|
| AI 说"测试全绿"，上线就出事 | 门写了，但没做过**负控**——不知道它拦不拦得住 |
| AI 说"我没找到/没有这个功能" | **探针失灵伪装成 0 命中**，没人先跑阳性对照 |
| 同一个地方反复返工 | 上一轮的错误结论被下一轮继承，**没人记账"我推翻了什么"** |
| 两个会话同时改，台账出现冲突标记 | 把 Git 合并当成**多 Agent 的并发数据库**用 |
| 记忆文件涨到几百 MB，AI 读不动 | 只追加不提炼，**没有热/冷分层** |

这五条都有确定性的解法，而且都不需要更聪明的模型——只需要**把纪律写成代码**。

---

## 四条核心机制

### 1. Maker–Checker：写的人不能给自己签字

出处可追溯：银行业 maker-checker 内控 → Clark–Wilson 安全模型 → NIST SP 800-53 AC-5（职责分离）。

工程含义很直接：

- **拟令的人不动手**（派活的不写代码）
- **动手的人不自证**（写代码的不能判自己合格）
- **判定的人只读**（复验者没有写权限，否则它顺手改了，你不知道它在审哪一版）

实测证据（arXiv 2608.18167 消融）：让模型**自我批评**，pass 率与零样本完全相同——77% vs 77%，因为"critic 和 generator 是同一个模型，犯同样的错"。换成独立审查者 + 批评者互辩，同任务 87%。

### 2. 负控：证明门真的拦得住

> **负控不红的断言 = 没有断言。绿门数不等于门数。**

做法：故意注入一个已知的破坏，检查门必须变红，然后还原。

```
① 跑门，确认绿（基线前置，堵"门本来就红"的假阳性）
② 注入破坏
③ 跑门，确认红，且红在你注入的那个点上
④ 还原
⑤ 跑门，回到绿
⑥ 还原物哈希 == 原物哈希
```

血泪案例：一次门的判据极性写反，五门全绿，把 Node 从 22 静默降回了 20.20.2，没人发现。

### 3. 探针自证：报 0 之前先证明探针有效

任何"0 命中 / 没找到 / 没有这个问题"的结论，必须先喂一条**已知会命中的样本**，确认被抓到。否则那个 0 是探针坏了，不是世界干净了。

`scripts/scan-secrets.mjs` 就是这个模式的完整实现：先跑 7 类阳性对照，全中才允许进入真实扫描。

### 4. 冷热分层：大账别让 AI 直接读

一份 1.6 MB 的任务日志，AI 每次开机都读 = 又慢又贵，而且**手工置顶插入会吞掉上一节标题**（真实事故：一天犯三次）。

解法：

- **冷**：原始账本只追加，永不压缩、永不删改（审计需要）
- **热**：用一个脚本从冷账里只读抽取「最近 N 条 + 未关闭项 + 最新产物指针」，生成一份 < 20 KB 的热索引，开机只读这个

配套 `scripts/append-section.mjs`：置顶追加时用代码强制校验"插入后二级标题计数必须恰好 +1"，不满足直接拒绝写入。用确定性代码消灭这类事故。


## 怎么用

### 推送前扫一遍密钥

```bash
node scripts/scan-secrets.mjs src docs config
# 或者只扫即将提交的文件集（推荐）
git -c core.quotepath=false ls-files --cached > /tmp/staged.txt
node scripts/scan-secrets.mjs --from-file /tmp/staged.txt
```

退出码：`0` 干净 / `1` 有命中（禁止推送）/ `2` 探针自身异常。

> 注意：`core.quotepath` 默认会把中文路径转义成 `"\344\272..."`，导致脚本**静默漏扫**。取文件清单时务必带 `-c core.quotepath=false`。

### 安全地往大日志顶部追加一节

```bash
# 先自检（1 正控 + 3 负控，全过才算可用）
node scripts/append-section.mjs --self-test

# 真正写入
node scripts/append-section.mjs --section-file /tmp/new-entry.md --target AI_MEMORY/TASK_LOG.md
```

强制校验：新条目必须以 `## YYYY-MM-DD` 开头、只含 1 个二级标题、写入后全文二级标题数精确 +1。

## 边界（诚实说明）

- 这两个脚本只覆盖上面四条机制里的两条（探针自证、防吞标题）。Maker-Checker 和负控需要你在**流程和 CI** 里落实，不是脚本能代替的。
- 负控的"注入破坏"必须针对你自己的门定制，本包不提供通用注入器。
- 没有任何工具能保证 AI 说的"做完了"是真的。这些机制的价值是让**假话更容易被抓住**，而不是让假话消失。
