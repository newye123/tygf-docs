# 十条可执行的 Agent 协作纪律

每条都配「判据」（怎么算做到了）和「反例」（真实发生过的失效形状）。没有判据的纪律等于没有纪律。

---

## 一、拟令不自准

**规矩**：写下任务判据的人，不能是判定完成的人。写代码的人，不能是判自己合格的人。

**判据**：同一份交付里，出现"执行者"与"判定者"两个不同会话/身份，且判定者有独立的只读取证记录。

**反例**：manager 既派活又判绿——自己写的诏书自己准。实测后果是本该被抓的缺陷全部放行。

---

## 二、未复验不记账

**规矩**：没有 `file:line` 或真实退出码支撑的"绿"，一律记为 `unverified`，不得写进状态、发版说明或对外口径。

**判据**：台账里每条"已交付"都能追到一条命令回显或一个代码位置。

**反例**：把静态阅读判断写成 `PASS`。这类"绿"会在下一次部署时集体崩塌。

---

## 三、一槽一写者

**规矩**：同一时刻、同一棵树、同一个写入面，只允许一个写者。分工按**写入面**（钱/门/量/发/文案/档案）切，不按话题切。

**判据**：判"谁在写"只看 `git status --porcelain` 与文件 mtime 的分钟级变化——**不信任何自述、不信声明文档**。

**反例**：两个会话同时改同一棵候选树。协调成本远高于串行等待。

---

## 四、负控不红 = 没有断言

**规矩**：写完任何门，先在"已知坏"的状态上跑一次，必须变红。不做负控的门不许计入"绿门数"。

**判据**：
```
① 基线绿 → ② 注入破坏 → ③ 必须红且红在注入点 → ④ 还原 → ⑤ 回绿 → ⑥ 哈希一致
```

**反例**（三条真实形态）：
- 门极性写反 ⇒ 五门全绿，把运行时版本静默降级
- 负控样本本身是好的 ⇒ 假负控
- 负控脚本只在最后统一还原 ⇒ 第二发的"咬点"其实是第一发的

---

## 五、探针先自证再报 0

**规矩**：报"0 命中 / 没找到 / 没这个问题"之前，先喂一条已知会命中的样本，必须被抓到。

**判据**：探针的退出码三档——`0` 全绿 / `1` 有 FAIL / `2` 探针自己坏了。**坏掉的探针绝不能被读成"安全"。**

**反例**：`git grep -- <不存在的路径>` 的 rc=1 冒充"0 命中"；`--since` 传带秒的时间串解析成 NaN ⇒ 恒假 ⇒ 印成 `(none)`，看起来像"没人交件"。

---

## 六、禁止无出处的否定式断言

**规矩**：说"我们有 X"必须给位置；说"我们没有 X"必须给命令原式 + 真实退出码 + 0 命中证据。缺出处一律写「未核实」。

**判据**：每条否定式结论后面能贴出可复跑的命令。

**反例**：把"已有能力"当成"待新建"派活——病根是规则只要求肯定式给证据，却允许否定式随口讲。

---

## 七、推翻自己必须记

**规矩**：实测推翻了先前的结论，必须在报告显眼处写明推翻的是哪条、为什么。已交付的加更正块，不许静默改口。

**判据**：报告里有独立的"本轮推翻了什么"段落。

**反例**：错判被继承到下一轮，下一轮在上面继续搭。三路调研里"主假设被自己派的件推翻"是常态，不是意外。

---

## 八、冷热分层：大账只追加，热索引只读生成

**规矩**：原始账本 append-only，永不压缩、永不删改（审计需要）；另外用脚本只读抽取一份 < 20 KB 的热索引供开机读取。

**判据**：冷账里没有"为了瘦身"而删除的历史；热索引可随时重新生成且内容只来自冷账。

**反例**：1.6 MB 的日志手工置顶插入，一天吞三次上一节标题。**置顶插入后必须立刻数 `^## ` 计数，必须恰好 +1。**

---

## 九、多树记忆必须对账

**规矩**：如果协作使用多个工作树（worktree），每个树里的记忆副本会各写各的。必须定期扫描"子树的独有条目"，无损归并回主账。

**判据**：对账脚本输出 `missing_in_main = 0`。

**反例**：真实事故——31 个工作树里散落 42 条重大记录（含 9 轮功能调整、一次架构改造、一组真机实测），主账一条都没有。**这不是"忘了同步"，是结构性的脑裂。**

---

## 十、推送前扫描，删改前留证

**规矩**：
- 任何推向远端之前，跑一次带阳性对照的密钥扫描；有命中即禁止推送。
- 禁止 `git reset --hard` / `git checkout -- .` / `git clean -fd` / force push。
- 进程收尾只按 PID，禁止按镜像名/进程名批量杀。

**判据**：扫描脚本阳性对照全中；危险命令有替代方案记录。

**反例**：按进程名批量杀，连带杀掉用户的编辑器；把未脱敏的运维档案推上公开仓库。

---

## 附：这十条的共同点

每一条都不是"更努力一点"，而是**把判据从人的自觉，搬到可执行的代码或可复核的记录上**。

人（和模型）的自觉是不可靠的：这是测量问题，不是态度问题。所以规矩必须能被机器验证——否则它只是一个愿望。
