## 要改的四块

### 1. 撤下内部标识（反抄，纯展示层）

用户界面与交付报告里现在直接印着内部结构：

| 现在显示 | 泄露了什么 | 改法 |
|---|---|---|
| `M-7@1\|*Compatible with bumpers…@3` | `ledgerEntryId` 的构造法（组路径 + `name@兄弟序号`） | 换成人话位置名（照范本），完整 ID 只在「导出对账结果」/运营层出现 |
| `译文行 "source:wb-d51beb0d:1"` | rowId 命名规则与 workbench 前缀 | 同上 |
| 「…同组争夺的其余对象会按同一组译文自动完成（**计费仍按译文行一次**）」 | 把**匹配模型 + 计费口径**一次讲完 | 只留"确认后这几处会一起写入同一句译文"，删掉机制与计费解释 |
| 「结构缺陷 = 计划写入行数少于设计稿行数（必须修）」 | 你的排版判据定义 | 移到运营/帮助层，用户侧只给"这 N 处需要你调整译文或手动断行" |

### 2. 版式例外清单：先修噪音，再谈收敛

`src/lib/workbench/overflow-estimator.ts` 约 `:155-156`：`widthRatio = widestLineEm(target) * fontSizePt / width` —— **分子是估算、分母是原稿实测墨迹宽，两个来源不可比**；且**没有 `target === source` 的短路**（grep 零命中）。

现场后果（2026-09-21 实测截图）：32 条"仍需人工处理"里至少 3 条是**译文与原文逐字相同**却被要求逐条点"保留原文"：

- `原稿 VS → 译文 VS` 报 **1486%** 原宽
- `原稿 VS → 译文 VS` 报 **975%**
- `原稿 ID 6877 → 译文 ID 6877` 报 **190%**

**任务**：加一条守卫——归一化后 `target === source` 的层**不产出版式例外**。这是纯降噪，不改任何裁决。

⚠️ **不要顺手做两件事**：① 不要重新引入朴素溢出公式——Owner 已于 2026-09-17 主动删除 `linesFitFrame`（`lineCount×leading×1.333` vs ink height 不可靠）；② 不要把 `FALLBACK_FONT_LANGUAGES`（`overflow-estimator.ts` 约 `:83-84`，现为 `Set(['KO','TH'])`）扩到日语——注释明写那是 Owner 决定"接受 PS 兜底，只做信息性提示"，**扩语言是产品决定，不是技术活**。

### 3. 三类内容的展示分层

| 类 | 判据 | 处理 |
|---|---|---|
| **必须问用户** | 缺译文、译文为空、表里真没有这句原文、原文不同的真争夺 | 保留。只给结论 + 动作，不给机制 |
| **不该问** | 结果唯一确定的（同原文层、等价候选、可自动闭合的多行对象） | 静默闭合，最多一行"已自动处理 N 处"可折叠 |
| **不该出现** | 版式估算超宽这类"仅提示不阻断" | 挪到运营/审计层；用户侧只留一句"实际以 Photoshop 渲染为准" |

第二类里"同原文层自动闭合"依赖 **S2 的豁免先落地** ⇒ 本任务先做第 1、2 块和第 3 块的第三类，第二类留接口等 S2。
