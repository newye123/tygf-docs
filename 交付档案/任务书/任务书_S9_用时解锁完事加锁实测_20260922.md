## 任务

### M1 先把"现状敞口"测成数字（没有基线就别谈改进）
用只读探针量三件事：① 一次真实执行周期里，明文 `.jsx` 在盘上**驻留多久**（从落盘到被删除/或永不删除）；② 缓存目录里现存**几个版本、共多少字节明文**；③ 文件 ACL 是什么（`icacls` 读，默认继承 ⇒ 同机其他进程/恶意软件多半可读）。
⇒ 产出基线表。若①②与 #95 描述不符，点名更正。

### M2 攻击面实测（这是"能不能算防住了"的唯一判据）
写一个**与助手同权限**的旁观探针进程，在"写入 → 交给 PS → 执行 → 删除"整个窗口内高频轮询目标目录，统计：**拿到完整可读字节的次数**。三种攻击各测一次：
- (a) 直接轮询缓存/临时目录读文件；
- (b) 抢到窗口内把内容复制走（模拟恶意软件）；
- (c) 执行结束后到目录里翻残留（含崩溃后的残留）。
⇒ 结论必须是"某形态下 (a)(b)(c) 各自成功/失败"，**不许写"已防护"**。

### M3 三种目标形态的对比测量（同一把尺）
| 形态 | 内容 |
|---|---|
| A 现状 | 明文长期驻留 + 历史版本累积 |
| B 卫生 | 用后**立即删** + 缓存目录 ACL 收紧（`icacls` 仅当前用户、去继承）+ 启动清扫覆盖全模式（含 `tygf_com_*`） |
| C 静态加密 | 盘上存 `encodeState` 密文，用时解密到临时文件 → 执行 → 立即删（**密钥仍是 MachineGuid，明写这一点**） |
| D = B+C+jsxbin | 编译件（无明文注释/叙述）+ C 的窗口最小化 |

每种测四项：**明文驻留时长**、**M2 三攻击成功率**、**崩溃残留量**（在"解密后/执行中/执行后"三个点强杀探针进程，看盘上留下什么、下次启动能不能扫掉）、**对 sha 校验链的影响**（会不会触发 `script-fetcher.js:108` 那类按下载字节算摘要的拒收；注意该文件是死文件，真实校验在 `script-distribution.cjs`）。

### M5 一句话结论（不许越界）
按"明文窗口从 X 秒缩到 Y 秒、崩溃残留从 A 降到 B、三攻击成功率变化 C"给结论，并明确写出：**剩余不可闭合的敞口是什么**（预期答案：同权限进程在执行窗口内可读、解密器自身可读 ⇒ 唯一能改变性质的是把值钱的判断挪到服务端，即 2.3 含匹配梯）。
