**② 从当前 develop 出包会把两条已推送 URL 打成 404。**
`check:sitemap-parity` 对 develop 树实测 **RED**：`/en/terms`、`/en/privacy` 在本树无路由，而线上 `sitemap.xml` 8 条里含它们、IndexNow 也已按 8 条推送过。根因：**4 枚提交只在本地 `main`（`4fa9d4f`），`origin/main` 停在 `cb3596d`**——英文法律页三张、首页内容卡两笔、IndexNow key 文件那一笔，**都没推到任何远端分支**。
⇒ 附带风险：生产在跑的那份代码目前**只有这一台机器上有第二份都没有**。这条与出包无关，但优先级更高（见 §5 第 0 步）。

**③ 合流会静默丢能力，不是丢在冲突里。**

## 4 接手 AI 的执行顺序（照做，每步都给判据）

**第 0 步（不是出包步骤，但先做）：把生产代码的第二份存下来。**
需要 Owner 点头（推 `main` 属发布线动作）。命令：`git -C worktrees/develop push origin main`。
判据：`git -C worktrees/develop ls-remote --heads origin main` 返回 `4fa9d4f…`。
回退：无破坏性；若远端 main 已被他人推进，会被 non-fast-forward 挡下——**那时停下问 Owner，不要 force**。

**第 1 步：确认没有别手在飞。**
`git -C worktrees/develop status --porcelain` 必须为空；`git -C worktrees/develop rev-list --left-right --count refs/remotes/origin/develop...HEAD` 必须 `0 0`。
不为空 ⇒ **停**，等那会话收笔。禁止 `git add -A`、禁止 `git stash`（共享树，见 #164/#165）。

**第 2 步：合流（把本机 main 并进 develop）。**
在**新孤立 worktree** 做，不在 `worktrees/develop` 里做：
`git -C worktrees/develop worktree add ../merge-main-to-develop refs/remotes/origin/develop`
`cd ../merge-main-to-develop && cmd //c mklink //J node_modules <develop 树 node_modules 绝对路径>`（**Windows 下删树前必须先 `cmd //c rmdir` 删这个 junction**，否则递归删除会穿透到 develop 的依赖目录——#146）
`git merge main`（不是 `origin/main`，理由见 §3②）
五处冲突的处置建议：
- `TASK_LOG.md`：两边都是置顶追加 ⇒ **两节都留**，顺序按时刻。
- `public/llms-full.txt`（add/add）：先 `git cat-file` 比两枚 blob 哈希；develop 侧那枚是 `61d4709` 从 main 逐字节搬来的，**若哈希相同取任一**；不同 ⇒ 停下问 Owner（这是引擎面文件，别手 3e1fcf6 刚改过内容）。
- `en/page.tsx`、`en/layout.tsx`、`en/download/page.tsx`：**这是产品决策不是机械合并**——main 是 237 行内联版（带内容卡），develop 是 71 行外壳＋`home-view-en.tsx` 560 行重构版（不带内容卡）。**我的推荐：保留 develop 的重构组件，把 main 的 `checklist` 键与渲染搬进 `home-view-en.tsx`**，这样既保住已上线能力又不退回内联版。但这一格**必须 Owner 或英文面属主拍**，别自动合。
- 合完必查：`grep -c "checklist\|check-item" src/components/site/home-view.tsx src/components/site/home-view-en.tsx src/config/siteContent.ts src/config/siteContentEn.ts` **四个都不能是 0**（这是防"静默丢内容卡"的唯一硬判据）。

**第 3 步：合流后跑全套门（在合并树上）。**
`npx tsc --noEmit`（约 136 s）→ rc=0
`npm run lint`（约 97 s）→ rc=0
`npm run check:sitemap-parity` → **必须 GREEN**（RED 就说明第 2 步没真补齐）

若动到助手/计费面（本会话没动）：`test:batch-row-contract` 与 `test:trust-chain` 是部署测试站前的硬前置。

**第 4 步：出包与部署测试站。**
