对抗式审查怎么钻得更深：公开实践里真正起作用的是结构，不是"更努力地想"

这轮不看别人怎么夸对抗式审查，只看他们把流程写成了什么形状。读了四个公开 skill 的原文（含验证模板和维度规则文件）、三个红队框架、几篇论文摘要和中文实践文章。结论之一是：我们自己的 skill 已经踩到了大部分硬思想；差的是把它们变成可复核的机械动作。

核心结论 深度来自"几道互相独立的关卡"，不是更长的提示词

审查者不写代码 → 验证者不是审查者 → 每条意见先找反例、再给三态裁决 → 结论绑住被测物指纹 → 漏网的变成下次必须失败的攻击用例。公开实现把这五步都做成了固定格式；我们做到的是"两个 agent、自由文本、绑 commit"。

0一句话

对我们最有用的一句"钻得深"在公开实践里几乎都被翻译成了同一件事：把审查拆成几道互相独立的关卡，并且每道关卡的产出都能被机器复核。审查者不写代码；验证者不是审查者；结论绑住被测物的指纹；每条意见必须先找反例；历史漏网变成下次的攻击用例。我们的 skill 已经踩到了其中大部分思想，缺的是机械化——规则还写在脑子里、裁决还不是结构化数据、批准还没有绑方案指纹。

这对你意味着什么：同样的模型、同样的时间，只把流程改成"审查／验证分人 + 意见结构化 + 结论绑哈希"，就能把"看起来审过了"变成"审过哪一版、哪条被证伪、哪条还缺证据"可查。下面五件事都能在一到两天内落地，都不需要换模型。

1六个做法（按对"深度"的贡献排序）

#做法公开实现里的原话 / 形状我们的现状
1.1 审查者必须换人，最好换厂 read-frog 写死硬约束：reviewers MUST run via the opposite model's CLI，不许用子代理；claudex-loop 让 Claude 写、Codex 审，终检用全新会话；deep-review：「an agent that just wrote the code is grading its own homework」，且「Review and verify must never share an agent」 已是"分面取证 + 主审证伪"两个人，但同模型同会话；skill 里有跨模型方向性数据，却没落成硬闸
1.2 规则写成可执行清单，并写明"什么不算问题" deep-review 14 个维度文件，每个四段：Quick checklist / How to check / Violations / Not violations；配一张剪枝表；还有一条：改 AGENTS.md、prompt、skill 的 diff 不算文档，按代码审 切面按对象临时定，没沉淀成可版本化规则；深度差异主要来自这里
1.3 意见过独立验证关，裁决机器可读 验证模板十步：先找反例（上游保证/提前返回/框架行为）；区分 introduced 与 exposed_legacy；校准到代码库现状（over-scrutiny: 前缀）；三态 confirmed / false_positive / need_more_context + 四类 override；去重判据＝"一处修复能否同时解决两条" 三分处置思路一致，但自由文本、无 schema、无理由前缀、无"同根"判据
1.4 结论绑被测物指纹，改了就失效 claudex-loop：批准记录方案路径 + SHA256，方案一改批准失效；终检记录构建前 commit + 改动指纹（含已暂存与未跟踪文件） 绑 commit 有了，方案文本没有指纹——这轮施工图在被审期间被另一只手改过，说不清审的是哪一版
1.5 反方固定镜头，过半存活才采信 fable-harness 三反方：skeptic（逻辑漏洞）/ red-team（安全与失效）/ simplifier（过度工程），三镜头过半存活结论才采信；read-frog 按 diff 规模配 1/2/3 个镜头 分面贴合对象是优点，但缺专门盯过度工程的那一路
1.6 把"找茬"变成"证伪"：负控 / 变异 / 攻击库 变异测试杀不死的变异体＝测试真实盲区；promptfoo（26,422★）用攻击成功率并把历史失败沉淀成回归集；garak（9,699★）、PyRIT（4,687★）同理 负控已有且写得比公开实现细；缺变异测试，缺"漏网→可重放"的入口

2四条"别抄错"的反面证据

反面 1没有外部信号的自我纠错无效

Huang et al. (ICLR 2024)：内在自我纠错在推理任务上常无提升、甚至下降。近期工作把反思重新定义为"受限再生成"——没有新信息时，迭代只是重采样。所以"再想想"不是深度，加一道独立验证才是。

反面 2强制"每人至少报一条"会逼出捏造

我们 skill 里记的实测：为凑数的 hedge 会被判捏造（3/5 条）。claudex-loop 也写死：「Zero findings is valid; a large number of findings is not a quality score.」

反面 3找茬式审查诱发过度工程

被要求找茬的审查者即使没问题也会报东西；追着每条改会催生多余抽象和防御性代码。deep-review 用 Not violations 段和 over-scrutiny: 前缀对抗它。

反面 4裁判偏差是结构性的

MT-Bench（arXiv 2306.05685）列了位置 / 冗长 / 自我增强三类偏差，缓解手段是换顺序各判一次、多裁判、剥离长度与风格信号。对审查的含义：先看到谁会影响判决；报告长度不能当质量。

5我们比公开实践做得好的地方（别改掉）

  • 负控：弄红一次才算数。公开实现只有零星的 "proof checks"，我们把它写成了四式。
  • 分歧离散化（AGREE / DISAGREE_EVIDENCE / DISAGREE_CONCERN，F1 0.457 → 0.533）：公开实现只做"验证者改判"，没有强制批评者给离散结尾。
  • 覆盖缺口节与 NOT RUN 就写 NOT RUN：公开模板有 need_more_context，但没把"这次没查什么"当正式交付项。
  • 成本闸：按风险配额开对抗环（约 4.5× token）。公开实现有 round 上限，但没有风险分档。
