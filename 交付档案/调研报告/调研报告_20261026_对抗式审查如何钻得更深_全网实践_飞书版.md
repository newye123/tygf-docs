# 对抗式审查怎么钻得更深：看了 GitHub 和全网之后，结论是「结构」不是「更努力想」

日期：2026-10-26
调研范围：四个公开 skill 的原文（含验证模板与维度规则文件）、三个红队框架、几篇论文摘要、几篇中文实践文章。

## 结论先说

大家把「钻得深」都翻译成了同一件事：**把审查拆成几道互相独立的关卡，每道关卡的产出都能被机器复核**。不是让模型想更久。

具体是五道关：审查者不写代码；验证者不是审查者；每条意见先找反例再下三态裁决；结论绑住被测物的指纹、改了就失效；历史漏网变成下次必须失败的攻击用例。

**这对你意味着什么**：我们的 skill 其实已经踩到了其中大部分硬思想（负控、分歧离散化、证据分级、覆盖缺口），差的是把它们变成机械动作——规则还写在脑子里、裁决还是自由文本、批准还没绑方案指纹。改这几处不用换模型，最多两天。

## 六个做法，按对深度的贡献排

**一、审查者必须换人，最好换厂。** read-frog 的 skill 写死了硬约束：审查必须走另一个厂模型的命令行，**明确禁止用子代理**，理由是同模型等于自己给自己判卷。claudex-loop 让 Claude 写、Codex 审，最后用全新会话再检一次，协调者自己动手改的代码也必须重检。lobehub 的 deep-review 有一句话说得最直白：写代码的 agent 审自己，是在给自己的作业打分。我们已经是两个 agent，但同模型同会话，只做到「换上下文」。

**二、规则要写成可执行清单，还要写明「什么不算问题」。** deep-review 把审查拆成 14 个维度文件，每份四段：逐条打勾的清单、怎么查、什么算违规、**什么不算违规**。还有一张剪枝表说明哪些维度在什么改动上不适用。它甚至规定：改 AGENTS.md、prompt、skill 这类给 agent 看的文件，不算文档，要按代码审，因为「说明文字里带着控制流和契约」。我们的切面是按对象临时定的，没有沉淀成可版本化的规则文件——审查深度忽深忽浅，主要差在这里。

**三、意见必须过一道独立验证，裁决要机器可读。** 验证模板规定每条意见走同一套十步，最狠的三条是：先找反例（上游保证、提前返回、框架行为）；区分「这次新引入」和「存量老问题」，存量要给出具体触发前后对比，给不出就降级；校准到代码库现状，库里到处都是且这次没让它更坏，就不算问题。裁决固定三态：确认、误报、缺证据，还要给「是否阻塞发布」「能不能自动修」，并允许验证者改判严重度。最后去重的判据是「一处修复能不能同时解决两条」，不是同一个主题就算同根。

**四、结论要绑被测物的指纹。** claudex-loop 的批准记录方案路径和 SHA256，方案一改批准立刻失效；终检记录构建前的 commit 和改动指纹，连已暂存、未跟踪的文件都要算进去。我们绑了 commit，但方案文本没绑——这轮就吃了亏：施工图在被审期间被另一只手改过，报告审的是哪一版文字说不清。

**五、反方镜头要固定，过半存活才采信。** fable-harness 派三个独立反方：找逻辑漏洞的、找安全与失效风险的、**找过度工程的**，三个里过半没被推翻，结论才采信。read-frog 按改动规模配一到三个镜头。我们的分面贴合对象是优点，但缺专门盯过度工程的那一路。

**六、把「找茬」变成「证伪」。** 变异测试是往代码里注入小缺陷，看测试抓不抓得住——抓不住的地方就是测试的真实盲区。promptfoo 这类红队框架用攻击成功率衡量，并且把历史失败沉淀成回归集。翻成我们的话：每次漏网的缺陷都该变成一条可重放的负控。我们有台账，没有重放入口。

## 四条别抄错的地方

没有外部信号的自我纠错基本无效——ICLR 2024 那篇就证明内在自我纠错在推理任务上常无提升甚至下降，所以「再想想」不是深度，多一道独立验证才是。

强制每人至少报一条会逼出捏造——我们自己的记录里就有 3/5 条被判捏造；claudex-loop 也写明「零发现是合法的，发现多不是质量分」。

找茬式审查会诱发过度工程——被要求找茬的审查者即使没问题也会报东西，追着每条改会催生多余抽象和防御性代码。deep-review 用「什么不算」那一段和「过度挑剔」理由前缀来对抗它。

裁判偏差是结构性的——位置、冗长、自我偏好三类偏差都有论文实测。含义是：对比两个方案时要换顺序各判一次；报告长短不能当质量。

## 可以直接抄的五件（按代价排）

**A 方案审查绑指纹，半天。** 审完记下方案文件的哈希，之后任何编辑让批准失效必须重审。判据能复跑：改一个字，批准状态必须变失效。

**B 审查和验证分人，裁决结构化，一到两天。** 验证子代理只看意见清单和范围，不看审查者的推理；只能回三态加证据加缺什么。误报必须带理由前缀（过度挑剔、超范围存量、假想输入），前缀就是校准口径。

**C 维度规则库落成文件，两天。** 先落六个最贵的：支付结算、权限授权、删除与保留期、跨层合同、发布闸与回滚、界面状态。每份必须有「什么不算」那一段，否则过度工程会复发。

**D 固定加一个「简化者」镜头，半天。** 只回答一个问题：这里有什么可以删掉而不损失目标。产出单独列成「可删清单」，不和问题清单混。

**E 历史漏网变成可重放攻击，一天。** 每条漏网补一条可跑的负控，加一个统一重放入口；只有在重放里变红才算销账。

## 拿这把新尺子量我这一轮

诚实说，这轮审查按新尺子是打折的：审查者同模型，独立性只做到换上下文；没绑方案指纹；裁决是自由文本不是结构化数据。

还有一条要自己更正：覆盖率比执行宽那条（F-05），我有代码对照证明两处口径不同，但没有真的跑一个「含不间断空格的行进执行匹配器会漏」的端到端探针。按新尺子它应该记为 A−，并把端到端复现列进未决，而不是当完整的 A 级。

## 我们比公开实践做得好的，别改掉

负控（弄红一次才算数）——公开实现只有零星的证明检查，我们写成了四式。
分歧离散化（同意／有证据反对／有疑虑反对）——实测把分歧质量从 0.457 提到 0.533，公开实现只做验证者改判。
覆盖缺口节和「没跑就写没跑」——公开模板有「缺证据」状态，但没把「这次没查什么」当正式交付项。
成本闸——按风险开对抗环，公开实现有轮次上限但没有风险分档。
