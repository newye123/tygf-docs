1
先分清是源站慢还是回源链路慢

看 Cloudflare 面板的 Origin TTFB 与缓存命中率。首字节就要 3–14 秒，说明源站自己在忙。

2
给营销页加缓存规则

首页、下载页、指南页、协议页不随登录变化，让 Cloudflare 缓存 5–30 分钟即可，现在它们每次回源。

3
看源站负载

同一台机器还跑着业务接口，营销页回源会和业务抢内存与 CPU。

04按严重度排的清单

高英文页描述以中文开头，而且全都超长/en/download · /en/terms · /en/privacy

三条描述的开头都是四个汉字「图译工坊」：例如 /en/download 是「图译工坊 local assistant (Windows 10 / 11, 64-…」。英文用户搜索时先看到中文，然后看到被截断的英文。

高分享卡文案说过头og-cover.png 1200×630

卡上写「本地驱动 Photoshop · 回读核对 · 文件不出本机」，而真实口径是 PSD/PSB 源文件不出本机、图层文字与译文会上传。建议改成「源文件不出本机」。

高9 个页面 0 张内容图片全站 <img> 计数 = 0

首页画面全是 CSS 画的模拟界面。对设计类产品来说，没有真实截图与流程图，等于放弃了图片搜索与 AI 引用这两条入口。

中sitemap 缺 2 个页面、全站无 lastmodsitemap.xml 3,089 B

只有 changefreq 与 priority，这两个 Google 已明确不看；真正有用的 lastmod 一个没有。

中下载页教人核对 SHA-256，却没印这个值/download

整页 64 位十六进制串出现 0 次。值其实在接口里（/api/local-assistant/latest 返回 1C53D1FA…042CE8）。顺带核对：页面标的 v3.7.15 就是接口里的最新版，没有发旧包。

中结构化数据可以再补一层首页 · 指南页 · 子页

SoftwareApplication 缺 offers / image；Organization 缺 sameAs；下载页与协议页缺 BreadcrumbList；指南文章缺 author。

中指南文章只有中文/guide/ps-batch-replace-text

没有 /en 对应页，hreflang 为空。它是全站唯一一篇教人判断「稿件能不能自动改」的内容，最该被英文用户搜到。

低三个安全头各出现两次X-Content-Type-Options / X-Frame-Options / Referrer-Policy

Cloudflare 加一次、Next.js 加一次。不影响使用，属配置卫生。

低canonical 与 sitemap 写法不一致首页

canonical 写 https://tuyigf.com（无尾斜杠），sitemap 与实际访问都是 /。统一即可。

低内链混进一条 Cloudflare 邮箱混淆链接/cdn-cgi/l/email-protection

用户点了不受影响，但爬虫看到的是死链。

05修法顺序

第一批 · 本周 · 只动配置 1–2 小时

查源站 TTFB 与缓存命中 → 给营销页加缓存 → sitemap 补两个页面并加 lastmod → 四条描述压短（英文页去掉中文开头）。

第二批 · 1–2 周

改分享卡文案 → 下载页印出 SHA-256 → 首页与下载页各补 1–2 张真实截图并配 alt。

第三批 · 1–2 个月

指南写英文版并接 hreflang → 补 offers / sameAs / BreadcrumbList / author → 接一套真实用户体验指标监测。

06这次没做到的部分

  • 没有 Google 官方数据。本机连不上 googleapis.com 与 google.com（12 秒超时），所以没有收录量、点击量、真实用户速度指标。速度结论来自我自己的 HTTP 计时。
  • 没有 Lighthouse 分数。这不是「跑过没通过」，是这套安装里没有 Lighthouse 运行器，所以没有 LCP / CLS / INP 的具体数值。
  • 单点测量。所有速度读数来自这一台电脑、这一条出口，建议从第二个地点复测，确认是「所有人都慢」还是「只有我这条线慢」。
  • 没做排名与竞品。DataForSEO、Firecrawl 扩展没装，这次没有关键词排名与竞品对比。
