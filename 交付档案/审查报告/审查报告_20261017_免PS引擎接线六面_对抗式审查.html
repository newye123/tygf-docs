免 PS 引擎接线六面：层号身份没绑死才是真风险

接线的风险不在行号搬家，而在扫描引擎与执行引擎的身份没有绑死。layer_id 是各自引擎内部的层号空间；现有前置检查挡不住"同一段原文出现在多层"——那种情况下比对通过、读回通过、回执全绿，而该翻的那层被静默漏掉。本轮已在隔离树补第一道 fail-closed 防线并跑绿。

六面逐条结论与证据

面 1 阻断execution-manifest.js:158,165,166 · TASK_LOG.md:752,767

manifest 只允许 expected_source / layer_id / object_id / target_text 四键，无法回答"这批层号是谁扫出来的"；而 PS Layer.Id 实测有遍历期确定性串号（paramId=14207 realId=12075），跨引擎"只认 ledgerEntryId"是既有结论。本轮动作：编辑前清点"同原文命中层数 vs 投喂替换条数"，命中多于投喂 ⇒ 整批拒执行；码复用 SOURCE_STALE，真相进 details 的 SOURCE_TEXT_AMBIGUOUS。实测 dup-ambiguous 拒、dup-paired 放行。

面 2 重server.js:5590,5606,6711,6746,5482,4582,5243

develop 实测执行入口只有两处（本地 :5590／云批次 :6711），分派回调 :5606/:6746，组件检查 :5482；扫描闸 :4582 与就绪扫描 :5243 属扫描链，不在执行链。⇒ 扫描兜底与执行接线不能混一次改，混改最容易留下"哪条门放行哪条门拦"说不清的后门。

面 3 重v1.5 server.js:435,3372 ↔ feature-flags-store.ts:184

B1 白名单在助手本地判 install_id＝用户改本机 JSON 就自开，按既定判据（只能靠自觉＝无效）。本轮只保留默认关，F 段仅放您那台笔记本；任何对外放开前，服务端判定必须先落地。

面 4 中test:contracts → smoke-batch-error-zh-mapping

接线若引入 PHOTOCRAFT_EXECUTOR_MISSING/PHOTOCRAFT_TIMEOUT 两码，必须同笔补中文映射，否则前端显示英文原句；PC_EXE_SHA_UNPINNED、PC_EXE_VERSION_* 只进 details，不进用户句子。

面 5 中server.js:408-414

v1.5 用 existingPsExe(cfg.pcExePath) 判引擎存在性。实测该函数只做"路径存在且是文件"，不校验是否真是 Photoshop.exe ⇒ 今天没坏，但属语义借用：将来给 PS 加真实名校验会连带影响引擎路径。接线时拆成 bundledEnginePresent() 与 PS 探测两个函数。

面 6 中v15-runner.js:208

issueCode = TERMINAL_CODES.has(code) ? code : 'EXECUTOR_FAILED' ⇒ 新增码即被折成通用码，等于静默降级。所以刻意复用 SOURCE_STALE。代价说白：用户句与"原文真的变了"相同、不够准；要准就得扩码 + 四层同步 + fixture，那是另一班车，不该塞进这条线顺手做。
