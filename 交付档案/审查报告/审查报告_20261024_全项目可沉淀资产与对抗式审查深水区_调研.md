## 4. 外部怎么把对抗式审查做深（8 条硬共识）

以下每条都附来源；"对我们意味着什么"是我按本仓现状给的判断（D 级，除非另有实测）。

### 共识 1：不能让写的人审自己——要独立上下文

Huang 等 2023 的结论很硬：**没有外部反馈时，模型的内在自我纠错在推理任务上可能不升反降**，会把原本正确的答案改错（B）。Anthropic 的多代理研究系统也把"子代理各自持有不同工具、提示和探索轨迹"当作分离关注点的来源（B）。

**对我们**：同一会话里"我刚写完，我再审一遍"不算独立审查。至少要换一个没有写码上下文的会话/代理。

### 共识 2：只给"产物 + 契约"，不要给"结论"

`doubt-driven-development` 的硬规则：reviewer 只收 **ARTIFACT + CONTRACT**，**绝不传 CLAIM**；传了结论，拿回来的就是对你结论的背书（B/A，公开 skill 原文）。

**对我们**：审查任务书里不要写"我认为这里没问题，你确认一下"；写"这份产物必须满足这三条不变量，找出违反处"。

### 共识 3：跨模型不是锦上添花，是补盲区

read-frog 的 `adversarial-review` 明确要求：reviewer 必须跑在**对立模型的 CLI** 上，**禁止用同模型子代理**，否则" defeats the purpose"（B）。alecknielsen 的实现用 Claude + GPT Codex 双模型辩论（B）。

**对我们**：本机已有多个模型入口；先在高风险面（计费、发布、PS 写回）试点，不必全量。

### 共识 4：多轮辩论要配"共识过滤"和"断路器"

alecknielsen 的四阶段是：独立评审 → 交叉评审 → 元评审 → 综合；两边都指出的问题算高置信，最后回到第一阶段验证修复，直到双方都报 NO_ISSUES（B）。它还设了三类断路器：3 轮无进展、5 轮以上无法一致、3 轮以上重复同一批不可修问题（B）。

**对我们**：不要"审到天荒地老"；3 轮不收敛就停下来，说明方案本身要重做。

### 共识 5：评审要落地到工具证据，不是纯文本推理

CRITIC、Chain-of-Verification 这类工作的共同点是：用外部工具/证据校验，再把证据转成修正（B/C）。开源代码审查协议也在强调 Plan → Tool Use → Reflect → Output，输出必须带证据链（C）。

**对我们**：每条 finding 必须带 `file:line` + 命令原式 + 真实退出码；只有推断的，标 D 并写反证条件。

### 共识 6：评审循环要有界

`doubt-driven-development` 规定：3 轮封顶、只审非平凡决策、发现只剩 trivial 就停；还专门列了"doubt theater"检查信号——两轮以上都有实质发现，却零条被判为可执行，说明你在走过场（B/A）。

**对我们**：把"本轮 0 条可执行"当异常信号，而不是当"没问题"。

### 共识 7：审查本身也要被 eval

我们自己的 `adversarial-review` skill 已经写了：任何逃逸到生产的缺陷，追加到 `REVIEW-EVALS.md`；改 skill 后用全部历史 case 重放，**命中数上升且干净改动上的有害误报不增加**才保留改动（A，本仓 skill 原文）。另设"干净改动探针"统计"照建议改会造成危害"的条数。

**对我们**：`REVIEW-EVALS.md` 只有 2 行，说明这条闭环基本没跑。这是最该先补的"审查沉淀"。

### 共识 8：深水区不是"再读一遍代码"，是主动制造失败

- **变异测试**：故意把 `>=` 改 `>`、`+` 改 `-`、`true` 改 `false`，看测试会不会红；它衡量"测试有没有牙齿"，覆盖率只衡量"跑没跑到"（B）。
- **属性测试**：不断言单个输入输出，而断言"对所有合法输入都成立的性质"（B）。
- **差分测试**：同一批输入跑两个独立实现，比较输出；适合重写、迁移、优化（B）。
- **故障注入**：主动制造 409/403/503、PS 429、断网、超时，看失败面是否如实（本仓已有大量此类 smoke，可复用）。

**对我们**：计费（v2 vs v3）、PS 保存（源稿 vs 产物逐层读回）、台账投影（跑两次结果相同）是三个最适合强破坏的面。

## 5. 深水区七层探针阶梯（本项目可直接照做）

| 层 | 动作 | 本仓示例 | 产物 |
|---|---|---|---|
| L0 固定真相 | 锁 SHA、命令、时刻；不接受"应该是" | `git rev-parse --short HEAD` + 命令输出 + `date` | 基线三件套 |
| L1 反演契约 | 先写"必须永远成立的 3 条不变量" | 同一稿保存后 kerning 分布不变；投影两次飞书行数不变；预览价=服务端价 | 3 条可判定句 |
| L2 六镜头 | 正确性/契约/安全/数据与状态/测试证据/意图 | 跨层白名单两侧一致；用户可见面不露内部字段；迁移可逆 | 每镜头 1–3 条线索 |
| L3 独立复现 | 能跑就跑，留命令+预期+实际；做负控 | 摘 Txt2 → 复现；保留 Txt2 → 不复现 | 证实/证伪/未判定 |
| L4 异构交叉 | 换模型/换会话，只给 artifact+contract | 计费与发布面 | 交叉评审记录 |
| L5 强破坏 | 变异/属性/差分/故障注入 | 计费金额运算做变异；v2/v3 做差分；投影做幂等 | 生存突变清单 + 反例 |
| L6 逃逸回放 | 生产事故 → eval 行；改规则后全量重放 | `REVIEW-EVALS.md` | 命中率 + 有害误报两个数 |

**纪律**：L3 之前不下结论；L4 的返回是线索不是事实；L6 的两个数必须一起看，只报命中率会鼓励审查自增。
