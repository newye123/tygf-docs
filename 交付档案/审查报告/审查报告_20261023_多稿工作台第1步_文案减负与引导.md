## 0. 一句话结论

**页面上那些字，大部分不是"用户文案"，是"写给我们自己的设计说明"。**

它们回答的是"我们为什么这样设计"，不是"你现在该做什么"。所以正确的处置不是把它们改短，而是**让它们退出常驻层**：设计理由删掉，操作说明改成"首次 4 步引导 + 常驻的问号 + 就地提示"，需要时拉出来，不需要时看不见。

实测：同一块屏，常驻汉字 **716 → 357（−50%）**；常驻的解释性段落 **23 处 → 1 处**。删掉的每一句都有新落点（见 §6 文案账本），没有一句是"折叠即失踪"。

## 1. 这次查了什么，怎么查的

三路并行：

1. **逐句过堂**：把第 1 步每一句常驻文字拿出来，问三个问题——
   - 删掉它，用户会不会做错决定？
   - 它在回答"怎么用"，还是在回答"我们为什么这样设计"？
   - 如果必须保留，它有没有第二个落点（引导 / 问号 / 折叠 / 悬停）？
2. **实测字数**：在 1180px 视口里对渲染后的页面取 `document.body.innerText`，用汉字正则计数。同一方法量"改前""改后"两版，避免口径漂移。
3. **外部对标**：GitHub 上找现成的引导库（看星数、许可、活跃度），网上找 NN/g、Appcues 这些做可用性研究的机构怎么做首次引导与情境帮助。

| 类型 | 典型句子（现状） | 它其实在回答 | 该去哪 |

| **C 重复提示** | 页脚"不定就不往下走：我们不会按修改时间或目录排序替你猜"＋按钮已禁用＋"还有 2 件待定" | 已经说了三遍 | 删。留禁用态和计数即可 |
| **D 防御性解释** | "这些表**不会丢**，也不会被乱配给别的 SKU。以前的界面把它们直接吞掉，所以你根本不知道自己这批少了哪几个。"（`:528-530`） | 我们在为旧版道歉 | 压成一句"不会被丢，也不会配错稿" |
| **E 安全感文案** | "只读，不会动你的文件" | 我会不会弄坏素材 | **保留**。这是唯一值得常驻的非动作文字 |

判断标准不是我拍的，是项目里已经批准过的两条（`changes/active/20260923-quiet-ui.md` §0）：

> 1. **展示结论和动作，不展示机制；只有"用户能改变业务结果"的决定才展示。**
> 2. **折叠不得删报**：任何从常驻层移走的信息必须在新位置原样可见。

按这两条，"设计说明"连折叠都不该进——它不是"用户能改变业务结果"的信息，它是我们的工作底稿。

两条关键事实：

1. **星数最高的两个（intro.js、Shepherd）恰好是许可最危险的**——AGPL 会传染，商用产品不能"顺手引一下"。
2. **本项目已经有 Radix**（popover / tooltip / dialog 全在依赖里），自研一个遮罩 + 卡片大约 200 行，样式和现有界面完全一致。**首选自研，driver.js 作为备选**（如果以后要跨页面复用、不想维护）。

### 4.2 业界怎么做（不是"做个 tour"这么简单）

- **NN/g《Onboarding Tutorials vs. Contextual Help》**：一次性长导览的问题不是"不好看"，是**用户记不住**——关掉就忘，因为步骤和任务对不上号。更有效的是"拉取式"帮助（pull revelation）：用户在做某个动作时，帮助就在那儿。
- **NN/g 空态研究**：空态是最好的教学位。第一眼看到的是"这里将来会有什么、现在该做什么"，比在页头写一段说明书有效。
- **Appcues《10 onboarding patterns》**：有效的引导通常**组合 2–4 种模式**（欢迎语、产品导览、清单、热点、情境提示、空态……），而不是单押一种；最常见的错误是"第一天塞太多"。
- **UserOnboard**：空态就是引导，不要浪费。
- **Trevor Calabro**：别把关键帮助只放进 tooltip——悬停不可发现、触屏不可用；帮助要放在**做决定的地方**。

对我们的直接结论：

> **不要做一个 7 步的首次长导览。**
> 做"4 步、每步一句、随时可跳过、只看一次"的首登引导 + 常驻可重看的「?」+ 只在异常/空态出现的就地提示。

这也正好是 Owner 提的那个方向——"第一次用给个引导，不懂的时候再点一下就能出来"——只是加上一条边界：**引导要短、要能跳过、要能重看，不能变成另一种噪音。**

## 5. 方案：三层引导，加一条文案预算

### 第 1 层：首次进入的 4 步引导（coach mark）

只在**这一步第一次进入**且**有数据可指**时自动出现一次。

| 步 | 指哪 | 一句话 |
|---|---|---|
| 1 | 文件夹栏 | 换文件夹等于换整批，不用再点"加入本批"。 |
| 2 | 左栏"要你处理的" | 选一个方案会自动跳下一件；其余我们自己归位。 |
| 3 | 语言覆盖矩阵 | 点任意格子，看它从哪张表、哪个 sheet 来。 |
| 4 | 「下一步」按钮 | 读表在下一步自动做，不会再弹旧确认框。 |

规则（写进实现验收）：

- **可跳过**：每步都有"跳过"，Esc 也能关；
- **只弹一次**：完成后写 `localStorage['tygf.step1.guide.v1']='1'`；内容大改时升版本号，才会再弹一次；
- **可重看**：页头「?」里的"带我看一遍"，从第 1 步重新走；
- **不挡目标**：卡片会自动避开被指的元素，窄屏改成底部卡片；
- **不锁页面**：不是模态框，用户可以无视它直接操作；
- **键盘可用**：←/→ 翻步，Tab 能到每个按钮，Esc 关闭；
- **无数据不弹**：扫描没完成不弹，避免指着一个空壳讲。

### 第 2 层：常驻的「?」——这一步怎么做

位置：**页头标题「准备素材」右侧**，不是全站顶栏。

理由：用户的问题是"**这一步**怎么做"，不是"这个产品怎么用"。放在页头，内容就能跟着步骤换；放顶栏会变成一个大而全的帮助中心，又一次把说明堆回常驻层。

点开是一个抽屉，四步清单 + 一条异常提示 + "带我看一遍"：

```
1 选文件夹     换文件夹就是换整批，不用再点"加入本批"。
2 拍板冲突     左栏亮着的几件有歧义：选一个，自动跳下一件。
3 看矩阵       一行一份稿，一格一门语言；点格子看来源。
4 进下一步     读表我们自己做，不会再弹旧确认框。
```

底部再放一条"文档"链接（离开界面看完整说明），以及"表头读不到怎么办""有表无稿怎么办"的入口。

### 第 3 层：就地提示——只在需要时出现

- **区块小「?」**：左栏标题旁、矩阵标题旁，各一个 18px 的圆点问号，点开一句话气泡（"亮着的是要你拍板的；灰的是已自动归位"）。不做 hover-only，触屏也要能点。
- **空态**：没选文件夹 / 没有稿，给一句"先选一个工作文件夹"+ 一个按钮。
- **异常态**：表头读不到、两份同名稿 MD5 不同、有表无稿——各给一句原因 + 一个动作，不写历史。
- **悬停补充**：统计卡的数字来源放 `title`，鼠标停着能看，不占版面。

### 文案预算（写进验收，防止反弹）

| 位置 | 上限 |
|---|---|
| 页头说明句 | **0 句**（只留标题 + 问号） |
| 统计卡 | 数字 + ≤5 字标签；解释进悬停 |
| 左栏条目 | ≤2 行（名称 + 状态） |
| 右栏 | 1 句结论 + 证据折叠 |
| 图例 | ≤3 项，无括注 |
| 整屏常驻 | **≤360 汉字**（本次实测 357） |
| 引导每步 | ≤35 汉字（本次实测 34） |

## 8. 反方意见：我自己先拆一遍

1. **"删了说明，新手不是更懵？"**
   如果只删不加，是。所以方案的核心不是删，是**把说明搬到动作发生的地方**。第 6 节每一条都有落点；没有落点的（设计理由）本来就不该给用户看。

2. **"首次引导不也是另一种噪音？"**
   是，所以有硬约束：4 步、每步 34 字、可跳过、只弹一次、不锁页面。超过这个量就会变成用户每次都要关的广告。

3. **"为什么不做视频/文档？"**
   用户正在流程里，不想离开页面。文档链接放抽屉底部，给需要深入的人。

4. **"为什么帮助入口不放顶栏？"**
   顶栏是全局的，放上去内容就得覆盖四步，又变成一篇说明书。页头跟着步骤走，才能一句话说清。

5. **"为什么不用 intro.js？星最多。"**
   AGPL-3.0 + 商业双许可。商用嵌入要么开源整个产品，要么买授权。Star 多不等于能用。

6. **"为什么不直接用 driver.js？"**
   可以，MIT 很干净。但项目已有 Radix，自研 200 行能把样式、键盘、窄屏都控在手里，也少一个依赖。**driver.js 作为备选写进方案**，不是否决。

7. **"360 字是不是拍脑袋？"**
   不是。716 字的构成里，能删的是解释句（约 359 字），剩下的是标签、状态、按钮（357 字）。360 是"标签 + 状态"的自然量，不是硬凑的目标。

8. **"会不会把错误原因也删了？"**
   不会。第 6 节第 11、12 条明确保留：错误原因、Smart Review 的可见性、表格格式说明都是硬要求，删了就是静默降级。

9. **"窄屏怎么办？"**
   引导卡片改底部固定，矩阵横向滚动不变；小「?」保持可点，不做 hover-only。
