03三处结构深看

F1 · smoke

英文单源的回归，恰好没有门看着

高

中文 FAQ 的披露有钉子：smoke-seo-consistency.mjs:366-367 断言答案必须含「图层文字」+「译文」。英文段的全部断言是 :437-455——inLanguage、FAQ 可见性、CJK 允许词表——没有一条管内容诚实性。

这不是理论风险：#130 的病根就是「DB 中文 FAQ 退回『一切本地、不上传』的陈旧声明」，且已在测试站实证（Q2 现含「网页只负责整理与审查表格」）。EN 是 git 单源，改错只可能来自提交——而这道门对提交内容的披露恰好不看。修法一行级：镜像 :366-367，对 EN FAQ 答案断言已有的英文披露 token 集合。

F4 · 法律可达性

英文用户看得见「Privacy Policy」这个词，点不着它

中

探针 3 复核了绝对与相对两类链接：/en 与 /en/download 的全部 href 中，terms / privacy / subprocessor 零命中。正文隐私段落的「Privacy Policy」是纯文本，footer 只有 Download 与中文站。FAQ Q2 再怎么诚实披露「per the Privacy Policy」，用户也到不了那份政策。

根因是 G3 裁决（本轮不建 EN 法律页，404 fail-closed 是对的），但「不建」不等于「不链」。裁决项二选一：footer 加带语言标注的中文法律链接，或下轮定稿 /en/terms /en/privacy。

F5 · 部署链

生产「碰巧正确」，不是「设计正确」

中

AR-62 给测试线补了 NEXT_PUBLIC_SITE_URL 注入（deploy-test-release.sh:403），生产线 deploy-release.sh 至今 0 命中。今天生产出的所有绝对 URL 仍正确，唯一原因是 site.ts:4-8 的回退值恰等于生产域名——这正是 AR-10 当年报过的「env 未设靠回退」风险换了条命活着。

触发条件不是假想：域名变更、www 规范化、或任何把生产 origin 与回退值分开的操作，都会让 sitemap / canonical / hreflang 整条链静默换错源，而 smoke 测试线因为自己注入了变量，照样全绿。修法与测试线对称的四行注入。

为什么 F2 与 F3 一起说

两者同根：两份 layout 的 openGraph 都只写了 locale 系字段。og:url 缺失让社交抓取时 URL 归属靠猜；locale:alternate 不对称让中文页无法向抓取方声明「英文版存在」。都是一行级修复，但因为 smoke 不查（F8），它们不会被任何门拦住——这正是「结构盲区成对出现」的典型形态。

04通过的防线

九项，全部测试站实测——不是代码里写了就算，是探针打出来算。

  • hreflang 矩阵 4/4 对称——探针 F：/、/en、/download、/en/download 全部 OK symmetric。
  • sitemap 6 locs / 12 xhtml:link——精确等于 4 双语 loc × 3；terms/privacy 各 0 是正确行为（sitemap.ts:6 注释即此约定：EN 法律页未定稿不带 alternates）。
  • EN robots=index,follow、无 noindex——探针 A；og:locale=en_US + alternate=zh_CN 在位。
  • 归一化与大小写——/en/ → 308 /en 无重复副本；/EN、/en/Download → 404 不产生副本。
  • 404 fail-closed——/en/terms、/en/privacy、/en/nonexistent 全 404，不发错误语言内容。
  • EN 站内链接全部落在存在路由——探针 B + 探针 3（绝对链接复核）双轮确认。
  • EN header/footer 零 DB 依赖——site-header.tsx / site-footer.tsx grep DB 相关 0 命中，#130 打不进英文页。
  • JSON-LD 双语正确——zh=inLanguage: zh-CN、en=inLanguage: en 各 6 问；EN 披露 token 7/7。
  • smoke 本轮 fetch failures=0——2 个 FAIL 均 #130 族 DB 漂移（断言引入者 bfad6e1，非本轮回归）。

05负向验证与上生产前的门

smoke 到底能抓什么

逐条想过：hreflang 单向断链 → 双语对检查红；sitemap 缺路径 → required 红；EN FAQ 不进可见文本 → invisibleContent 红；英文页混入未授权 CJK → 红。唯一不抓的就是 F1 披露、F2/F3 og 字段、F8 footer 结构——发现清单与盲区清单精确互补，说明门的边界摸清了。

1

修 F1：smoke 英文段补披露断言

镜像 :366-367，对 EN FAQ 答案断言英文披露 token（layer text / translations / Privacy Policy，7/7 那套可复用）。一道小补丁，钉住英文单源唯一的回归入口。上生产前必须完成。

2

修 F5：deploy-release.sh 补域名注入

与 deploy-test-release.sh:403 对称的四行，让生产不再靠回退值碰巧正确。与门 1 同批提交。

3

修 F2/F3：两处 layout 补 og 字段

openGraph.url 双语补齐；中文侧补 alternateLocale: ['en_US']。全是一行级改动，与门 1、2 同批，改完重跑 smoke。

4

F4 裁决（Owner）：英文法律链接怎么给

① EN footer 加带语言标注的 /privacy /terms 链接（注明中文版） ② 排期 /en/terms /en/privacy（G3 口子）。不阻塞门 1–3，但阻塞「英文站对外承诺完整性」。

中文 FAQ 承诺微信、英文承诺 email，两侧各自自洽但对用户是两套承诺。确认后统一口径或明确分治。

6

gate token 轮换（Owner 批后执行）

诊断时回显过一次。改 nginx Set-Cookie + reload 属访问门变更，未经批不执行。

门 1–3 全是小改动，一批修完重跑 smoke 即可上生产；门 4–6 是拍板项，不阻塞代码修复。

06顺带查明，不影响判定

  • F7 展开：llms.txt 硬编码 tuyigf.com 含尚不存在的 /en——今天安全只因它与页面同一提交原子部署；单独回滚页面或先发 llms.txt 会对外指路 404。测试站副本跨域指向生产，但有访问门无碍。
