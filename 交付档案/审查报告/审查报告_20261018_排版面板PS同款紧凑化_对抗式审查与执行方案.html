抽屉并不是「新功能就一定好」。翻译类浏览器扩展用悬浮球，是因为它们寄生在别人的页面上，必须有一个常驻入口；我们自己的应用已经有卡头和折叠条，再加一只球只会遮住 PS 预览。外来参考只取模式，不引依赖：抽屉的可访问性做法对照 Radix Dialog 与 shadcn Sheet 的公开模式，模拟里的抽屉是原生 React + portal 手写。

04对抗式审查：会失败的地方

24px 格子对触屏偏小接受，带条件

24px 刚好达到 WCAG 2.5.8 的最小目标尺寸，但手指点选不如 32px 稳。本轮按桌面优先保留 24px；移动端若成主场景，只在窄屏抬到 32px，代价是再高约 96px。

360px 单列 12 行，面板 623.5px 高有意的取舍

360 下两列会把字体下拉压到 140px 以下，长字体名更难认。单列可读，代价是滚动；不想滚动可以选抽屉方案（331px 宽，900px 内可容纳）。

状态点只靠颜色，读屏拿不到原因已修

每个非可写字段现在都有一段 sr-only 文本，读出状态与原因；8/8 有说明。图例仍保留给肉眼。这是本轮审查真抓到并修掉的问题。

高级与结算明细折叠后可能没人点接受

摘要行始终露「本次会发 N 项」或「本次不发排版字段」；折叠标题写明「高级与结算明细」，右侧显示脸名状态。数据没有删，只是默认不占高度。

原生下拉与 datalist 跨浏览器差异未核实

本轮只在 Chrome 验证；Safari 对 datalist 支持历来不完整，Firefox 样式也不同。预设只是加速入口，输入框始终可以手输，不把预设当唯一路径。

8 个不可写字段仍占格子有意保留

字号、字偶距、缩放、基线、对齐、语言、抗锯齿在本版 PS 写不进去，但位置保留、原因可见，不伪装成可用控件。全删会让用户以为产品没有这些概念。

产品入口尚未接线边界

当前产品代码里仍是内联折叠条；抽屉只在模拟壳里。模拟里的字符面板是产品组件真码，外围工作台是模拟壳，不是真实 Next.js 工作台。不把模拟通过写成产品已上线。
