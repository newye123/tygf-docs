## 3. 对抗式审查：8 条攻击

> 每条攻击都是"这个方案可能怎么错"，逐条给验证方法与读数。

**A-1 攻击：首页 SSR 注入会话，会不会被 CDN 缓存成别人的首页？**
验证：`page.tsx:10` 已是 `force-dynamic`（E-9）；实测生产首页响应头 `private, no-cache, no-store`（E-15）。
结论：**成立**（当前不会串号），但这是"配置正确"而不是"结构保证"。执行时必须补一条契约测试锁死 `Cache-Control` 与 `force-dynamic`，否则将来有人改成静态化就会把 A 用户的头像发给 B 用户。

**A-2 攻击：裁掉 `name` / `betaUserId` / `sessionId` 会不会打坏现有调用方？**
验证：全仓 grep `auth/me` 只有 4 个消费者（E-14），逐个读源码确认消费字段：`account-gate` 用 `email/accountStatus`、`user-account-menu` 用 `email/name`、`sessions` 页用 `email` 与状态、`login` 页用 `email`。**`betaUserId` 与 `sessionId` 在客户端零消费**（grep 命中 0），`name` 只有账号菜单这一处消费——正是要改的那处。
结论：**裁剪安全**。唯一风险是"将来有人又用 `name`"——所以要在 `BetaUser` 侧留注释说明 `name` 是运营字段，不得当作用户显示名。

**A-3 攻击：SSR 注入 + 客户端再取一次，会不会闪一下或水合不一致？**
验证：React 19 的水合不匹配会以 console error 形式暴露；根因是同一状态有两个来源。
结论：**设计上必须单源**：首帧身份只认服务端注入的 props，客户端不再首屏请求；后续变更（登出、停用、过期）由统一 Provider 推送。方案已按此设计（P0-3 + P1-1），并要求实现时观察 console 不得出现 hydration 警告。

**A-4 攻击：账号被停用（403）和"网络不可达"是不是被当成"未登录"了？**
验证：`me` 接口现行口径是 `accountStatus !== 'active' || accountDeletedAt !== null || accessExpiresAt` 过期 → 403 `AUTH_ACCOUNT_DISABLED`（`api/auth/me/route.ts:12-18`）；工作台侧对网络不可达有专门口径（AccountGate）。
结论：**必须分开**。方案里停用态保留头像 + 琥珀点 + 菜单说明原因（不让用户反复登录一个已停用的号），不可达态保留"上次已知状态 + 可重试"，不回落到"登录"。

**A-5 攻击：一个标签页登出，其他标签页还显示头像，算不算"登录态没清干净"？**
验证：现状就是这样（无任何跨标签同步），不算本次引入的新缺陷；但既然本次要引入共享会话，顺手做掉。
结论：**做**。用 `BroadcastChannel`（+ `storage` 事件兜底）广播登出/登录，其他标签页立即更新。

**A-6 攻击：把"前往工作台"改成 `/#workbench`，未登录用户直接访问会不会白屏？**
验证：`view-context.tsx:19-24` 的 `readHash` 对 `#workbench` 放行；工作台整树被 `AccountGate` 包裹（E-13），未登录时渲染登录引导卡而非空白。
结论：**安全**，且比现状（落到营销首页再自己找入口）更符合按钮文案。

**A-7 攻击：头像入口在移动端/键盘下不可达吗？**
验证：现有账号菜单用的是 radix `DropdownMenu`（shadcn/ui 体系），键盘导航、焦点环、`Escape` 关闭、`aria-expanded` 全部具备；触发器是 34px 圆形按钮，命中区与项目现有工作台一致。
结论：**沿用现有组件即可**，不新造控件。

**A-8 攻击：改导航会不会踩坏现有 smoke？**
验证：`scripts/` 下无任何 `nav-login` / 首页"登录"文案断言；`smoke-identity-account-gate.mjs:18` 只读 `me/route.ts` 源码，不校验返回字段（本次实跑 PASS，E-16）。
结论：**无回归断言可被踩**，但也意味着**现在没有任何测试守着"me 接口不泄漏运营字段"**——执行时必须新增字段形状断言，否则这次修完下次又会漏。

## 4. 外部开源方案对照（不凭空设计）

| 来源 | 借用的模式 | 我们的落法 |
|---|---|---|
| Next.js 官方 Authentication 指南（App Router） | 会话存 cookie，服务端组件直接读会话渲染账号态 | 首页 `page.tsx` 服务端读会话，把摘要作为 props 下发（E-9 已具备条件） |
| Auth.js `useSession` | `loading` / `authenticated` / `unauthenticated` **三态**，不把"未知"当"未登录" | 首屏骨架态独立成态（模拟件第 3 档） |
| Clerk `Show` / `UserButton` | 未登录渲染 fallback，登录渲染头像菜单，二者同一位置互斥 | 头像**替换**"登录"，不并列出现 |
| shadcn/ui `DropdownMenu` + `Avatar` | 触发器与菜单成对、聚焦与键盘可达 | 沿用项目现有 radix 实现，不新造控件 |
| Supabase `onAuthStateChange` + `BroadcastChannel` | 跨标签页广播会话变化 | 登出/登录跨标签即时同步 |
| Stack Overflow #79865034（刷新闪"登录"） | 客户端才取会话 → 首帧必然闪；解法是 SSR 或骨架 | SSR 注入 + 34px 骨架，零布局跳动 |
| OWASP API3:2023 Excessive Data Exposure | 响应只回客户端该看到的字段，过度返回即泄漏 | `/api/auth/me` 只回 `email/emailVerified/accountStatus` |

**不引入 Clerk / Auth.js / Supabase**：沿用项目 2026-08-18 的结论，保留现有自建身份与 `BetaUser` / `billingPrincipalId` 体系；本次只借模式，不换依赖。

## 5. 执行方案

### P0（先做，止泄漏 + 止"登录态断裂"）

**P0-1 裁剪身份接口**
- `src/app/api/auth/me/route.ts`：返回体由 `{betaUserId,email,name,emailVerified,accountStatus,sessionId}` 改为 `{email,emailVerified,accountStatus}`。
- `src/app/api/auth/login/route.ts:118`：去掉 `name`。
- 前端类型同步（`me` 的 TS 类型定义处一并收窄）。
- 保留 `me/route.ts:2` 的 §7.4 注释口径，并在注释里补一句：`name` 属运营字段，不得下发。
- 影响：需先跑 A-2 的 grep 复核（已做）。

**P0-2 账号菜单不再显示运营备注**
- `src/components/workbench/user-account-menu.tsx:77-81`：`displayName` 改为邮箱本地部分（`me.email.split('@')[0]`），去掉 `me.name` 分支；同时把 `:4` 的注释改回与实现一致。
- 头像首字母同样取邮箱本地部分（`:81`）。

**P0-3 首页服务端注入会话，登录后用头像替换"登录"**
- `src/app/(zh)/page.tsx`：服务端读 cookie → `getCurrentUser(...)` → 判定"可用 / 停用 / 未登录"三态，作为 props 传给首页。
- `src/components/site/home-view.tsx:135`：`session.state === 'anonymous'` 时保留现在的"登录"链接；`authenticated` 时渲染与工作台同款的账号菜单（头像 + 下拉）；`blocked` 时渲染头像 + 琥珀点 + 菜单说明。
- 触发器组件按需动态加载，避免给营销首页增加首屏 JS 负担。
- 前置条件已满足：E-9 动态渲染 + E-15 私有缓存。

### P1（同批做完，把"同一个用户"这件事做完整）

**P1-1 共享会话 Provider**：抽一个 `AuthSessionProvider`，首帧取服务端注入的摘要，之后只由它持有 `/api/auth/me` 结果；`account-gate` / `user-account-menu` / `sessions` 页 / `login` 页四处改为读它（消除 E-14 的重复请求）。

**P1-3 跨标签页同步**：`BroadcastChannel`（`storage` 事件兜底）广播登录/登出。
**P1-4 状态分型**：停用（403）与不可达分开呈现，沿用 AccountGate 现行口径，不把"网络问题"当"退出登录"。
