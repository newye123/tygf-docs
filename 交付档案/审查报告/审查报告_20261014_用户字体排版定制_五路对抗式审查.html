01判定

结论

方向可做，链路有现成注入点。
但「读字体」的权威源不是浏览器也不是裸扫字体目录——是 Photoshop 自己的字体清单。真正缺的只有三段：字体清单的运行时读取、用户界面与按语言持久化、写回时应用排版属性。

已成立（实测）

  • 注入点现成：执行信封（envelope）顶层加旁路字段向后兼容，且不进 executionManifestDigest——不碰四层合同。
  • 存储模板现成：decision-persistence.ts（localStorage + TTL + 扫描绑定）照抄即可，试验期无需新 Prisma model。
  • 端点模式现成：无票只读端点（/ping、/config）与 Origin 白名单闸现成。
  • 字形裁决纯函数现成：glyph-coverage.js 可直接注入 face 复用（现只被离线工具链消费）。

缺口（要新建）

  • 运行时字体枚举：零。清单要靠 PS app.fonts 探针（或搭车 readiness 扫描）——现在一个都没有。
  • 写回排版属性：零。薄执行器只写文字不碰字体；经典脚本也只观测 fontChanged。字体全靠 PS 静默兜底（豆腐块问题的土壤）。
  • 用户设置面：零。无用户偏好存储、无任何排版设置 UI。

03路一 · 链路事实（全部实测 file:line）

注入点

执行信封：顶层旁路字段向后兼容、不进摘要

v15-runner.js:193-199 把 {schemaVersion:1, executionManifestDigest, workingCopyPath, previewPath, manifest} 原子写入 execution-envelope.json；薄执行器只校验其中 4 个字段（Thin_Executor.jsx:81-83）⇒ 顶层加未知字段旧执行器无感；digest 只算 manifest（v15-runner.js:144）⇒ 旁路不进摘要。

写回现状

执行器一字不碰字体——这正是豆腐块问题土壤

Thin_Executor.jsx:107-128：选中图层→校验原文→写 contents→逐字符回读→保存。经典路径脚本同样只观测字体：MultiLangStudio_Replacer_v2.9-beta.jsx:1175-1194（fontBefore/fontAfter）、:1432-1434（fontChanged）。文件名写 v2.9、内含 SCRIPT_VERSION='2.12-beta'（:50），服务端要求 2.12-beta（server.js:100）。

字体枚举

运行时零枚举；纯函数与离线工具链已在

glyph-coverage.js（建索引 :29 / 解析 :53 / 覆盖裁决 :111）消费方只有 scripts/typography-census.mjs:18,64-66,197 与 scripts/smoke-glyph-coverage.mjs:13-17,101-122。扫描器已采每层字体名（TYGF_V15_Preparation_Scanner.jsx:143），无人消费。

存储/端点

两个模板可直接照抄

存储：decision-persistence.ts:30,38,41-55（key tygf:v15:decisions、12h TTL、scanId+fingerprint+digest 三重绑定）。端点：server.js:4037（/ping 无票只读）、:4372-4386（/config）、Origin 白名单 :2236-2242；浏览器侧 local-assistant-client.ts:183-208（fetchLocal 15s）。

时机

字体清单读取的现成时机

readiness 扫描器（TYGF_V15_Readiness_Scanner.jsx:3,47）由助手 runReadinessScan（server.js:5235-5298）驱动——字体清单可搭车或独立极小探针（diagnostics/Probe-LineTerminator.jsx:15 已有 app.fonts 用法先例）。

04路二 · PS 端写回兼容（先 spike 后动码）

已知机制：PS 按文字里的脚本切分样式 run 再逐脚本挑字体；原字体渲染不了目标语言时才补。⇒ 用户设置的字体对「多脚本混排层」的语义必须真机定死。

1

app.fonts 名称格式

返回显示名还是 PostScript 名？必须能与 textItem.font 接受值对齐。仓库唯一先例：Probe-LineTerminator.jsx:15。

2

可写性与设置顺序

textItem.font / tracking / leading 在 PS 2021（#141 教训：严格 ES3）与产品声明下限上的行为；先字体后 contents 还是反之（写 contents 可能重切 run）。

3

读回归一规则

设进去→读回，值是否相等（显示名/PostScript 名归一）。这是「设没设进去」唯一诚实判据：回读≠所设 ⇒ 显式 FONT_FALLBACK，不许静默。

4

缺字体时的行为三态

设一个本机没有的字体名：抛错 / 静默改回 / UB——三种都要有报告字段承接。

红线

不得 faux bold 静默替代；不得自动缩小字号（前序方案已否决「字号阶梯缩小=静默降级」）；设置失败必须显式失败码。

结论

0 件可直接装。组件写起来不难（shadcn 已有 Select/Slider/Popover），难的是字体清单来源与写回语义——那两件没有开源件可替。

06路四 · 治理与契约（红线清单）

  • 摘要冻结：typography 若进 manifest → 动 executionManifestDigest → 四层同步+fixture。试验版走 envelope 旁路，把风险从「合同级」降到「本机级」。
  • 版本纪律：动 JSX 或助手 JS = 新助手版本（runtime 身份/安装包/release identity 全同步）。试验版至少一次 bump，走下一班车。
  • 不得静默降级：#66 已证明「PS 静默替换+链路不检测=豆腐块无人知」的代价（ISSUES.md:641-648）。本功能不带回读判据，就是给 #66 再开一个入口。
  • 学习隐私边界：本地证据禁止 fontName/fullFontName 字段名（learning-evidence.js:33）；字体清单是机器画像，试验版只留本机，上云需新同意位。
  • L2 立项：用户可见新行为 ⇒ changes/active/* + IN/OUT SCOPE + Acceptance，Owner 批准前 flag=false。
  • 学习库时机：schema 注释写明「作为按用户定制的基础」（schema.prisma:1322），但 rule-resolver 生产零引用（全景 20261003 §D3）——试验版不搭学习库，P2 再接。
  • #78 保留事实：交付判定链路不看字形可行性——试验版至少做到「回读 applied font 并上屏标志」，覆盖预检留 P2。

07路五 · 产品与创收视角

为什么值得做

  • 日语（游明朝/思源系列的字距与选择）、品牌字体一致性、多语言营销图排版——都是「设计稿字体在目标语言没字形/不协调」的延长线需求。
  • 创收载体已存在：付费档挂现有套餐/积分；「品牌排版预设」可挂 LearningBrandScope（schema.prisma:1162）。

做什么不做

  • 做：本机字体清单 + 按语言定制 + 写回应用 + 回读标志；成本 P0 半天 + P1 约 2-3 工作日。
  • 不做：字体文件分发/安装引导（法务与体积）；服务端字体授权代理；预览=终态的承诺。

08最后一句

这不是「缺前端组件」的功能，是缺一段本机链路：字体清单怎么上桌、定制怎么不下摘要地骑到写回那一刻、写没写进去怎么证明。三件事各有一半现成——spike 半天把不确定性钉死，再决定要不要发包。
