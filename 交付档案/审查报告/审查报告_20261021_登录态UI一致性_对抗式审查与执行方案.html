VERDICT：两个问题都真，其中一个是隐私泄漏

A（后台备注被当用户名显示，并随接口明文下发到浏览器）是 P0；B（登录后首页导航仍写“登录”）是 P1。两者同源：登录态没有一份统一的事实。

这对你意味着什么

运营在后台给某人填一句内部备注（比如“王先生 / 已付尾款”），这句话现在会直接出现在这个人的工作台账号菜单里，而且他在浏览器开发者工具的网络面板里也能读到原始值——不需要任何越权，只要他是登录用户。而反过来，用户登录后回到官网，导航上还是写着“登录”，界面上完全看不出他已经登录过。这两条修完，界面才会像“同一个人”。

03对抗式审查：8 条攻击

A-1首页 SSR 注入会话，会不会被 CDN 缓存成别人的首页？结论：当前不会，但靠配置不靠结构

首页已是 force-dynamic（E-9），实测生产响应头 private, no-cache, no-store（E-15）。但这是“配置正确”而不是“结构保证”——将来有人改静态化就会把 A 用户的头像发给 B 用户。

执行时必须补契约测试，锁死 force-dynamic 与 Cache-Control。

A-2裁掉三个字段会不会打坏现有调用方？结论：安全

全仓 grep auth/me 只有 4 个消费者（E-14），逐个读源码：betaUserId 与 sessionId 客户端零消费；name 只有账号菜单这一处消费，正是要改的那处。

唯一风险是将来有人又拿 name 当显示名——需在 BetaUser 侧留注释定性。

A-3SSR 注入 + 客户端再取一次，会不会闪一下或水合不一致？结论：必须单源

水合不匹配会以 console error 暴露，根因是同一状态有两个来源。首帧身份只认服务端注入的 props，客户端不再首屏请求；后续变化由统一 Provider 推送。

验收要求：控制台不得出现 hydration 警告。

A-4账号停用（403）和“网络不可达”是不是被当成“未登录”？结论：必须分开

现行口径：accountStatus !== 'active'、已删除、访问过期 → 403 AUTH_ACCOUNT_DISABLED（api/auth/me/route.ts:12-18）；AccountGate 对网络不可达另有专门口径。

方案：停用保留头像 + 琥珀点 + 说明原因（不让用户反复登录一个已停用的号）；不可达保留上次已知状态 + 可重试，不回落成“登录”。

A-5一个标签页登出，其他标签页还显示头像？结论：现状如此，顺手做掉

现状没有跨标签同步，不算本次新引入的缺陷；但既然要引入共享会话，用 BroadcastChannel（storage 事件兜底）广播登录/登出，其他标签页立即更新。

A-6把“前往工作台”改成 /#workbench，未登录直接访问会白屏吗？结论：安全

readHash 对 #workbench 放行（E-11），整树被 AccountGate 包裹（E-13），未登录时渲染登录引导卡而非空白。比现状（落到营销首页再自己找入口）更符合按钮文案。

A-7头像入口在移动端/键盘下不可达？结论：沿用现有组件

现有账号菜单用 radix DropdownMenu（shadcn/ui 体系），键盘导航、焦点环、Escape 关闭、aria-expanded 齐备；触发器 34px 圆形按钮，命中区与工作台一致。不新造控件。

A-8改导航会不会踩坏现有 smoke？结论：无回归断言可踩，但也没有护栏

scripts/ 下无任何 nav-login / 首页“登录”文案断言；smoke-identity-account-gate.mjs:18 只读 me/route.ts 源码、不校验返回字段（本次实跑 PASS，E-16）。

即：现在没有任何测试守着“me 接口不泄漏运营字段”，本次必须新增字段形状断言。
