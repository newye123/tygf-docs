# 我把自己的上一版审了一遍：界面承诺了一个没做的功能

上一轮落地完 v12，我又审了一遍自己刚写的东西。结论不太好听：**最严重的问题不是代码写错，是我在同一份交付件里自己打架。**

## 说错的那句话

确认框里原来写着：「开始之后不能撤销……**中途只能「停止」**——后面的不再派发、没执行的不扣费。」

而「停止」这个功能，我在同一份交付件的「不做项」里写得很清楚：**C1 停止，本轮不做。** 界面上根本没有停止按钮。

这两句话同时成立意味着什么？您跑到第 5 份想停下来，会去找那个「停止」——找不到，然后开始怀疑是不是自己点错了，接着可能关页面、或者重复点开始。重复点开始会撞上「结算未确认」的锁，界面告诉您「执行已锁定」，但没告诉您在等什么。

用户会照着界面上的话去做，然后扑空——这比没有确认框更坏，因为确认框让他以为有退路。所以我把它按 Critical 处理，不是当文案瑕疵。

现在的说法是：「**开始之后不能撤销**：已经写进 PSD 的内容不会自动还原（本产品没有 PSD 备份）。另外，**这一版还没有「停止」按钮**——跑到一半想停下来，目前只能联系支持处理；没执行的部分会按实际交付核对退回，不会照收。」

## 一共九条，八条已改

除了这条，还审出：

**确认框少了两个 spec 要求的东西**。产品的第 4 步规范写的是「确认语言、文件名、保存位置、费用」四项，我只给了语言和费用。现在两个档位都补上了「文件名」和「保存位置」，而且写的是真实规则：多语言会加 `__N-languages` 后缀；没另选目录时，批次链会在设计稿同目录建 `<稿名>_ALL_<语言数>LANG__时间戳` 文件夹，单语言是 `<稿名>__时间戳`。

**预估为 0 会显示「0 积分」**。那个数是前端估的，某些行组合下会是 0，写 0 等于告诉您免费。现在 0 的时候改写成「按受理时报价并冻结（此处无预估）」。

**切档会留一个过期弹层**。确认框开着时切到另一档，它跟着分支消失，但状态还在；切回来会冒出一个「范围已变」的红框。现在切档就清掉。

**指纹只记了语言的个数，没记是哪几个**。英语+日语换成英语+韩语，个数一样，指纹不变。虽然弹窗挡着改不了，但草稿恢复这类后台动作可能改，所以改成记名单。

**测试里有一条永远是「通过」的假断言**。它检查的是源码里根本不存在的字符串，等于没测。换成了真正能拦住「单稿按钮被拼上份数」的断言。

还有两条小的：批量确认框没写「某稿失败会怎样」（实际会暂停并提示，界面没说）；React 的 key 用了标签名，同名两行会冲突。

第九条我判定**保留**：多稿档右上角那个范围条和顶部状态带数字重复。理由是一个回答「我在哪一档」，一个回答「现在该做什么」，两处数字同源不会打架，删哪个都少一个常驻锚点。

## 怎么验的

类型检查 0 错；三个改动文件 lint 0 error（7 条告警是原来就有的表单标签问题）。新门从 44 条加到 **52 条，全过**——新增那组专门钉三件事：不许再写「中途只能停止」、两个框必须有文件名和保存位置、切档必须清空弹层。既有 7 个相关检查也全部通过。

中途红过一次，如实记：类型检查报 `preferredOutputBaseName` 未定义——那个变量原来声明在提交函数内部，不在组件顶层。我没有把闭包变量提出来（那会动执行路径），而是在顶层按同样的回退顺序重算了一个预览值。所以确认框里的文件名是「预览」，规则和提交时一致，但不是同一个变量。

## 这轮学到的一条，已写进检查表

**「不做项」清单必须和「界面文案」逐条互查。** 同一份文件里一边写「X 没做」、一边对用户说「可以 X」，这种矛盾不需要写错一行代码就能发生，静态门也测不出来——因为它测的是「有没有这个按钮」，不是「文案有没有说这个按钮存在」。

具体做法：凡是声明「本轮不做」的能力，在界面源码里**反向断言那个说法不出现**。这条已经落进新门了。

## 还是没做的

停止、取消并退回、撤销已写入、默认信息密度、渲染级回归、浏览器实拍——和上一轮一样，没变。停止和取消要动结算，得单独立项；撤销没有 PSD 备份可用，做不到。
