01判定

VERDICT

有条件放行——两条候选方案都可以做，但顺序必须是「先装眼睛 → 再放真画面 → 再把唯一动作改便宜」。在没有访客级观测之前上线演示或视频，改完之后我们无法判断有没有用，也无法判断有没有变坏。

03根因链：从"0 申请"钻到"无法验收"

L1 现象

官网 27 天 0 申请；Owner 感知"每天 100 多人进来没人申请"。

L2 分母本身不成立

94.7/天是 Cloudflare 按整个域名去重的读数，官网＋内测站＋后台接口混在一起；nginx 侧首页 IP 头部被机房占据、外部搜索来路个位数。真人很可能只有几十/天，且现在给不出绝对值。

L3 就算是目标设计师，也没有任何证据面让他相信"这玩意能替我干活"

首屏是 CSS 画的假界面，"看看它怎么改语言"滚到静态插图；没有真截图、没有录屏、没有价格、没有案例。而产品价值主张（批量写回 + 逐层回读核对）本质上必须"看见"才可信。

L4 唯一动作贵到不像邀请

7 项必填含两段小作文（home-view.tsx:657-663 的 requiredOk 六条 + 两个强制选择组），提交后还要等人工发码（schema.prisma:325-343，maxActivations 1、trialDays 14、source: from_application）。同类竞品首屏是"免费下载 / 观看视频"两个按钮。

L5 本质（不可再分）

没有访客级观测 ⇒ L2 到 L4 每一层我们都只能"合理怀疑"，既不能证明，也不能在改完之后证明改对了。这就是"卡死"——不是缺方案，是方案无法验收。

05处置梯：第 1 步是 2–5 的前置

1

先装眼睛（1a 当天可做，不改产品代码）

1a：nginx 日志格式加 $host 与 $request_time，把官网／内测站／接口／爬虫拆开——这正是 10-20 那份读数点名、被本机权限层挡住没执行的那条改动。1b：匿名访客级埋点（首页曝光、"看看它怎么改语言"点击、滚到申请表、表单首次聚焦、放弃、提交），只存事件与匿名 id，不存正文。1c：UTM 接上——表单已在发 attribution、服务端已有 sanitizeApplicationAttribution（beta-applications/route.ts:15），但生产库 没有 ApplicationAttribution 表（实测 no such table）⇒ 特性未上线，发布须带迁移。

红线：新增采集必须与隐私政策/服务条款披露一致，不能先采后说。这条不满足就不开 1b。

2

把真画面放上首页（不新拍，用现成链路重采一次）

对着当前批量台四步界面重跑采集→合成，出 15–25 秒 1920×1080 录屏；画面持续带"演示录屏 · 数据为示例"；聚合数字（"43 已核对／1 失败""0/175 层"这类）一律不入画。首页补 <video> 渲染 + public/videos/ + 填 hero.video.src，并把首屏那张 CSS 假界面换成真实截图或直接用它的首帧当 poster。

3

把唯一动作改便宜：7 必填 → 2 必填

只留邮箱 + 一句话说清你要处理什么；角色/物料两组保留但改成"默认不拦人"，人工耗时等挪到申请后的第一封邮件里问。不删字段，只把"必填"降级为"选填"——那两项你定价和写文案还要用。纯表单与文案层，不动授权、计费、合同。

4

交互沙盘（今天那份方案的"第二批" try-sandbox）排第四

不是没价值，是排序：它是工程活（新路由 + 新组件 + 脱敏固定数据 + V7/V8 双验），内容却可以从 73 份模拟件里拼；且在第 1 步之前无法验收。今天实测 src/app/(zh)/ 与 src/app/en/ 下都还没有 try-sandbox 目录。

这条动授权链（对应今天方案第九节 A"真实匿名试跑"：临时凭证、安装绑定、有效期、撤销、单设备额度识别、并发原子扣减、重放、成本归属），风险等级远高于前四步。
