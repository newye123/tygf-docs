03真必要：三件

判据只有一条：不做会不会让客户丢东西、或者让账算错。只是"更规范""更好看"的，一律不进这一栏。

真必要

① 身份核对（前置，0 成本）

审计报告自报的 buildId 是 transport-hardening-20261011-r1，对应 3.7.15，不是它写的 3.7.24。行为类结论很可能取错了版本。先让客户机把 /ping 原文贴回来，对得上出厂件再谈别的。

补充事实：persisted-state.js 从 3.7.15 到 HEAD 逐字节相同，所以 ACL 那条不用等重测；但"24 条回执""CORS"必须重测。

真必要

② ACL 故障停损（可以比方案便宜）

代码现在用 process.env.USERNAME 作为授权目标，还把"断继承"和"授权"塞在同一条命令里；授权只在写盘成功后做，启动时不修复。一旦名字解析到另一个账号，当前进程读不了自己刚写的文件，远程没法修。

更便宜的反方案：配置在 %LOCALAPPDATA%\Programs\…，这个目录本来就只对当前用户开放，自定义 ACE 的安全收益接近 0，故障面却是实打实的。建议停写自定义 ACE，启动时对读不了的文件跑一次 icacls /reset 恢复继承权限；修不好就进入"不覆盖 + 停"。不需要 whoami、不需要 SID 缓存，代码量约为方案的三分之一。

若 Owner 坚持保留加固，再按方案的 SID 版做；但要写清"文件属主不是当前用户时自愈会失败"这个残留风险。

真必要

③ 读不到绝不覆盖（含托盘闭锁）

这是"授权反复丢"的真正放大器：读失败 → 返回默认配置 → saveConfig 合并后写盘 → 第二次写把唯一的好备份也覆盖掉。而 ensureMachineId 在三个请求路径里都会触发写盘，所以只要进程活着，任何一次请求都能把令牌冲空。

三处必须同笔改：读函数要能区分"不存在 / 读不了 / 坏了 / 解不开"；闸要下沉到 saveConfig，不能只在启动时拦；托盘要记住"引擎已经因配置错误退出过"，停止 5 秒重启并显示原因。只做"退出"不做闭锁，会变成重启风暴，比现在更难诊断。

04条件必要：四件

该做，但要么得改写法，要么得排在热修之后。

条件必要

④ 未签名不得冒充正式版

现网清单就是 UnsignedBeta，下载页没说清楚，用户看到 SmartScreen 会以为下到假货——这是真实的信任损失，方向必须做。

但不能按方案写"证书没到之前生产发布失败闭合"：那会让证书到位前所有生产发布都过不去，包括马上要发的 ACL 热修。正确写法：保留清单与 flag，给 flag 加"原因＋到期日"；新增 beta 通道；下载页如实标注未签名。证书和四签名位排到热修之后。

条件必要

⑤ 回执墓碑（降级为 2 行）

它不是账务缺陷：unresolved 只写一条本地日志，不上云、不进结算。真实后果是"每成功一次，下次启动的假告警就多一条"，把真未知淹没。

修起来极便宜：ACK 成功后写一个标记，恢复时跳过。必须避开共用清理函数——它在永久拒绝和防御终态时也会跑，写在那里就会把"被拒收"记成"已结算"，那才是真错账。也不必新建目录和 30 天清理。

条件必要

⑥ 最小证据闸（替代 P1-A 主体）

现在的收费闸只认"等级字符串 ＋ 摘要非空"。sha256("[]") 是一个合法的非空字符串，能直接过闸——被改的客户端不需要伪造任何内容就能结算。

最小修法：服务端加 64 位十六进制形状校验；有 VERIFIED 行时拒绝空数组摘要。零客户端改动、零合同变更。能挡住"什么都不发直接白拿"，挡不住"编 N 个对象算自洽摘要"，所以不能写成"改不了结算"。

条件必要

⑦ 本地 HTTP 卫生

Vary: Origin 是正确性问题，PNA 是面向未来 Chrome 的兼容，Host 白名单能挡 DNS rebinding——三件都便宜，该做。

但不能当成 MAJ-1 的修复：本机进程可以随手伪造 Origin 和 Host。给浏览器发设备密钥在这条链上不可实现，所以 MAJ-1 只能显式记为接受风险。实现时端口要从环境变量取，别写死 49152。

1

P1-A 降级

主体改成服务端最小形状闸；全量对象上传另立单，并在单里写清白名单、体积、对象清单、行映射、双版本五件前置。

附带三条低成本修正

Host 白名单端口从 PORT 取；CONFIG_UNREADABLE 的路径写进独立诊断文件或托盘提示，别指望落盘日志；方案里的 422 要落到路由层——现在失败一律映射成 404/409，没有 422 这条路。

07更正

  1. 对方案：方案说 P1-A 是"本轮最该先做的一条"。本轮回读，它是最不该先做的一条——五件前置一件都没落地。真正最该先做的是身份核对与 ACL 停损。
  2. 对方案：CORRUPT 时"当前与备份一起改名"与代码的恢复路径矛盾，也与方案自己的验收（"备份哈希逐字不变"）矛盾。按它做，那条验收永远过不了。
  3. 对方案："证书没到就生产发布失败闭合"会把 ACL 热修一起停发；而现网清单已经是未签名。
  4. 对审计报告：它自报的 buildId 对应 3.7.15，不是 3.7.24。行为类结论必须重取；代码类结论（ACL）不受影响。
  5. 对我自己上一版：我上一版把回执墓碑当成账务缺陷。本轮回读，它只写本地日志、不上云、不进结算，应该降级为告警质量问题。上一版也照抄了"一起隔离"的错，这次一并改掉。
