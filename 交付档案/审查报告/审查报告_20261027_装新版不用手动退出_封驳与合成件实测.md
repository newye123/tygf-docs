# 封驳｜"装新版不用手动退出"这套做法，我先把它打回了一次（附八个case的实测日志）

日期：2026-10-27 16:5x（各钟点以每条日志原式为准）
被审对象：`交付档案/执行方案/执行方案_20261027_发版不再砸客户_讲人话定稿.md` 里 Owner 16:3x 追加令带进来的第 3 批（D6 改口）
审查方式：不是纸上过一遍。在 `tmp/selfexit/` 里造了一对**假托盘＋假引擎**和一份复用同一段安装脚本逻辑的**测试安装器**，真跑了 8 个 case，包括"故意把要拦的东西放出去，看它拦不拦得住"。
结论：**方案的方向成立，但我第一版的实现形状是错的，已经被实测打回并改掉；改完的四条安全性质逐条有日志。**

## 一、先说被打回的那一条（这是这轮最有价值的产出）

我方案里第 3 批第 1 步原本打算这么写：新增一个 `图译工坊本地助手.exe --exit`，它去杀引擎、把退出标志置真、自己退出，安装器调它就行。

**实测证明这样做不成立。**

日志 `log-T1.txt` 原文（16:49 那次）：

```
[selfexit] --- 自关开始（SELF_CLOSE=1）---
[selfexit] --exit 返回码 = 0
[selfexit] 互斥体 15 秒未释放 ⇒ 走旧版兜底强杀
[selfexit] taskkill 托盘 返回码 = 0
[selfexit] taskkill 引擎 返回码 = 0
[selfexit] 兜底后互斥体已释放
```

`--exit` 很高兴地返回 0，**可是那个正在跑的托盘根本没退出**。原因很朴素：`exiting` 是一个进程内的变量，`--exit` 是**另一个进程**，它改不到别人的变量；那个托盘的 5 秒定时器还在，引擎被杀了又拉起来。要不是我这条链后面还留了"互斥体没释放就兜底"，装到一半就会因为文件被占而失败——也就是说，**我差点交一个"只在兜底那一步才碰巧能用"的方案**。

根因写成人话：**"叫它自己退出"必须是"正在跑的那个进程"自己执行的，不能由别人替它退出。**

改法（已验过）：`--exit` 只做三件事——判断忙不忙、把一个**命名事件**点着、然后等托盘的**互斥体**消失。正在跑的托盘在自己的循环里看到事件点着，就执行它本来那条干净退出路径（停定时器 → 杀引擎 → 释放互斥体 → 退出）。改完的日志 `log-T4b.txt`（16:55）：

```
[selfexit] --exit 返回码 = 0
[selfexit] 托盘互斥体已释放
...
Dest filename: ...\app\fake-engine.exe
Dest filename: ...\app\fake-tray.exe
[selfexit] 收尾：已拉起托盘
```

1.1 秒释放、没走兜底、文件真被覆盖、装完自动起来。**方向对，实现形状换了。**

## 二、第二条差点写错的判据：忙不忙不能看 errorCode

我本想用"有没有错误码"来判"能不能关"。在本机那个**正在跑的真助手**上做了一次只读请求（没动任何进程）：

```
HTTP 200  bytes 438
busy= false   phase= "idle"   errorCode= "PHOTOSHOP_COM_UNAVAILABLE"   lastJob= null
```

`errorCode` 在明明空闲的时候也是非空的（这台机器没开 Photoshop 的 COM）。**如果拿它当"忙"，所有没装／没开 Photoshop 的客户机都会永远装不上新版。** 判据只认一个字段：`busy === true`（该字段由 `download/local-assistant/server.js:2650` 的 `publicQueueStatus` 公开）。

## 四、顺手挖出来的一条老老虎（今天就存在，与客户点不点"退出"有关）

托盘菜单"退出本地助手"今天走 `TrayHost.cs:277` 的 `ExitAssistant()`，它**不看忙不忙**，直接 `process.Kill()`（`:146`）。跑批的时候点它，会打断 Photoshop 执行；助手自己的代码写着打断之后落下恢复锁，`server.js:2380` 那句原文是「检测到未完成 Photoshop 执行或恢复标记；请先人工核实现场，**不会自动重试**」，`:2575` 是「恢复确认前不会接收新任务」。

也就是说：**客户今天手动退出，就可能把自己的助手锁成不能用**，而且没有任何提示。第 3 批把忙判断放进这条路径本身，这个老洞跟着一起堵。

## 五、我没证到的地方（不装成证到了）

1. **真实 3.7.28→3.7.29 覆盖安装没做。** 您机器上真助手正在跑（托盘 PID 53524、引擎 PID 23568 占着 49152），动它＝改别人现场，所以整条链是用**同形状的合成件**证的。真机上还要看的是：真托盘的互斥体名、真端口 49152、真注册表卸载项 `InstallLocation` 这三处取值是否如我假设。
2. **注册表取不到安装目录时的行为只写了策略没实测**（回退默认目录，两条都拿不到就中止不硬装——§四-9）。
3. **忙中止那句提示，客户到底看没看见**：交互式安装 Inno 会把 `PrepareToInstall` 返回的文字弹出来；我全程用 `/SILENT /SUPPRESSMSGBOXES` 跑，没往您屏幕上弹窗，所以"看得见这句话"属推断未观测。
4. **`CloseApplicationsFilter` 现有那行的语法到底生效没有＝未核实**：本机 Inno 没随包装帮助文件（`whatsnew.htm` 里只提了一次该名字），官方文档页取不到正文。我的设计不依赖它。
   **并且我在动手时把这条判错过一次，代价是一次真红**：我一度认为"三个名字用分号分隔"是笔误，顺手改成 `*.exe,*.dll` ⇒ `npm run test:trust-chain` 立刻红在 `scripts/smoke-pc-bundled-engine.mjs:321`（[D4] 按 `;` 切这一行、要求列出内置引擎文件名 `tygf-engine.exe`，因为它以 serve 子进程常驻并持有自己的文件句柄，漏名会让删除退化成"重启后才删"、旧引擎作为孤儿永久留在 `{app}\bin`）。已改回原样并在 `.iss` 里留注释"不要改成逗号"。教训：**仓库内部约定优先于我对上游文档的推测**；上游语义不明时，改之前先找有没有门在管这行。
5. **按映像名强杀这条兜底不是零风险**：它会带走同机器同名的所有进程（含别的 Windows 账户里的副本），Inno 里没法按可执行文件路径过滤。T7 反而证明它"杀不到别名的东西"，但也正因为杀不到别人才中止——这条兜底只作为旧版过渡，且必须先过忙判据。

## 六、方案已经按这次封驳改掉的地方

- 第 3 批第 1 步：从"改静态标志"改为"**命名事件 + 互斥体探测**，由正在跑的托盘自己执行干净退出"；`--exit` 的返回码语义定死：0 已关／3 忙拒／4 叫不动（`tmp/selfexit/fake-tray.cs` 就是按这个写并跑绿的参考件）。
- 第 3 批第 2 步：忙判据只认 `busy === true`，明确不得看 `errorCode`／`phase`。
- 新增第 3 批第 5 步：`ExitAssistant()` 本身加忙判断，把今天手点退出锁死助手的洞一起堵上。
