结论先说

VERDICT：有条件放行——但对外口径必须先降一档再谈重设计。

一句话根因：这个产品最硬的那条差异化（写完重开文件、逐对象回读核对，源码里是真的硬：v15-runner.js:96 抛 REOPEN_READBACK_MISMATCH、:278 才给 REOPEN_VERIFIED）在官网上被讲成了"批量改语言"这种和 PS 原生批处理、图片翻译工具混在一起的词；而官网用来撑卖点的两个数字（单批 12 语种、PSD/PSB）恰好是盘上证据最薄的两处。

三件必须知道的事：

  1. 首页主打"单次最多 12 个目标语种"，测试站实测 12 语种批次 71 个里 STALLED 47 个，中止率 66%、成功率 24%（AI_MEMORY/ISSUES.md:1986，A 级，我自己复读过原行）。5 语种对照组 4/4 全成。这是对外主张与内部读数之间最大的一条缝。
  2. 首页与隐私文案反复写"PSD / PSB"，但助手侧对 PSB 是硬拒：download/local-assistant/psd-sanitize.js:23 抛 PSD_SANITIZE_UNSUPPORTED_PSB（A 级，两侧行号我都自己 grep 到）。而客户真实母版就是 PSB（AI_MEMORY/ISSUES.md:1523 记 Owner 真实场景 12 SKU × 12 语种）。这不是措辞问题，是"承诺的能力面比实现宽"。
  3. 视觉部分的前提不成立：你让我重评"黑色背景、朱红色强调、琥珀色渐变、白卡、毛玻璃、悬浮工作台"——线上实测是白底 #fff、墨字 #111311、绿色强调 #2d7356、黑胶囊按钮、白卡 26px 圆角、全站只有 2 处 backdrop-filter（我从 /_next/static/chunks/2ipj_5zcyik5q.css 里直接 grep 到这几个色值，A 级）。黑底朱红琥珀最接近的东西是你给的那个包 运营/tuyigf-full-site-video-v6-package（--navy:#080e38 --blue:#536dff --red:#e54835），那是一份未上线的提案。所以下面第四部分我做的是"以线上实测为基线，四套方向一起比"，而不是去改一套不存在的配色。

把握度：结论 1、2、3 是 A 级，可当场复跑。第 4 节的方向推荐是设计判断（D 级），但每套方向的对比度/溢出/点按区都是实测出来的（A 级）。

第一部分 第一性原理

核心用户（不是"设计师"这个笼统词）：手上有母版 PSD/PSB、译文已由译员定稿、要出 6—12 个市场版本的改稿方。盘上证据：真实语料 F:\改语言 实测 69 GB、265 个 .psb + 33 个 .psd（B 级，别手数；注意与旧记录的 52.87 GB/66 psb 不符，差异含"完成的"子目录 35 GB，口径待你定）。真稿规模样本：单稿 175 个文字层（AI_MEMORY/ISSUES.md:86，A 级）。

核心任务：把"每个语言都要重走一遍找图层→对译文→写入→保存→核对"这套重复动作，压成"一次批量 + 只看例外"。

付费动机（最贵的那一环）：不是"改字快"，是返工与排期。价值链八环里，产品真正吃掉的只有三环——找图层、批量写入、逐层回读；排版适配仍由人做（字号/缩放/对齐/语言/锯齿六格写不进，src/lib/workbench/typography-capabilities.ts:55-56 记 2026-10-23 Owner 令撤下，typography-profile.js:33-37 的 LOCKED_KEYS 硬拒 fontSize/size）。所以"译文变长撑破版"这个客户最疼的问题，产品今天不解决。这一条决定了：能收的钱，只能锚在"确定性的核对与交付"，不能锚在"全自动"。

替代方案（用户真的会走的路）：

  • PS 原生变量 + 数据组 + 批处理。这条不是假想敌——本仓库 2026-10-17 的 SERP 实测判定四写着它在前排赢着：PSD 批量替换文字 第 11 位、psd 批量改文字 电商 第 12 位（交付档案/GEO测量/测量记录_20261017_中文SERP前排形态与百度收录在场性.md:43，A 级，我今天为另一件事读过原文）。它的弱点是只适合模板化可变位，不适合"175 层成品稿逐层回读"。产品的窄赛道应该正对着这个弱点。
  • 人工。今天 12 语种跑不完（24%）时，人工就是更可靠的那个选项——这是最贵的竞争对手。
  • 图片翻译工具。产出的是图，不是能继续编辑的源文件；首页 FAQ 已经自己划清（src/config/siteContent.ts:373）。这条划得对，保留。

转化路径（首访 → 付费）现状，逐环带证据：

  • 首访：品牌词 20 条前排0 条本站，被"智图工坊"等语义邻居占了第 8 位（测量记录:48、:53-58，A 级）。也就是说：连"你是谁"这一步都要靠客户自己找对门。
  • 看懂：首页无 <video>、无 iframe、无录屏（B 级实测）；真录屏 2026-09-19 就有，但首页没用。
  • 申请：表单前端卡 7 个必填（我自己读线上 JS bundle js_28221jmglfy6d.js 的提交函数：role、materials、name、email、scope、problem、manualTime 全非空才发请求），后端只校验 3 个（src/app/api/beta-applications/route.ts:133/142/156，A 级）。字段映射本身是对的（contact←wechat、useCase←problem、monthlyVolume←scope），所以不是坏单，是自己给自己加了四道门。
  • 发码：后台人工点（src/app/api/admin/applications/[id]/invite/route.ts:98，B 级）。
  • 观测：CSP script-src 'self' 'unsafe-inline' 把 Cloudflare Insights beacon 拦死（CSP 头我自己 curl 到，beacon 报错为别手实测）⇒ 站点今天没有可用的访客统计；历史库侧 BetaApplication 全历史 12 行、末条 2026-09-29（B 级，出处 AI_MEMORY/TASK_LOG.md）。没有读数，任何"改版有效"的说法都无法证伪。
  • 付费：线上 /api/site/feature-flags 我实测为 alipayPaymentsEnabled:false、showPayment:false、showPricing:false，但 creditPacksEnabled:true、manualPaymentConfirmationEnabled:true、manualQrFallbackEnabled:true 被运营台打开，与仓库里写明的内测安全态要求相反（src/config/featureFlags.ts:25-35 注释：不暴露任何人工收款入口）。/pack 公开可达（HTTP 200），文案是"积分包需要先在工作台完成激活才能购买"。历史订单 credited 0（B 级）。⇒ 收款这条路从未真正走通过，但人工收款开关是开着的，这是合规与口径的双重风险。

第二部分 对抗式审查（四立场）

四态区分：已验证事实 / 页面宣称 / 源码可证明 / 仍需实测。

怀疑型设计师会问的

  • "四态是哪四态？"——首页演示卡写"已核对完成 / 需要判断 / 执行失败"，任务状态区写"全部 48 / 已核对完成 43 / 需要判断 3 / 无法处理·失败 2"。同一页两套数，且卡上那套 43+3+1=47≠48（我直接从线上 HTML 文本里读出来，A 级）。引擎真实档位是三档 ok|review|blocking，产品自己的指南页写三组"已确认 / 待复查 / 需要你决定"（src/app/(zh)/guide/ps-batch-replace-text/page.tsx:84）。四态只活在营销组件里（src/components/site/home-view.tsx:85-87、:219-221、:391-393，B 级）。⇒ 客服解释成本会全落在你身上。
  • "12 个语种是能力还是上限？"——上限判定发生在表的列数上：多一列备注就 13 列被拒（AI_MEMORY/ISSUES.md:1523，A 级）。首页把它写成卖点"12 个语言一起处理"。
  • "54 种语言识别？"——src/lib/workbench/lang-display.ts:63-65 有威尔士语/苏格兰盖尔语/巴斯克语三个名字，但 csv.ts 的别名表里我 grep 不到对应项（0 命中），别手按 54 个界面名实跑得 51 可识别；而"54 种"整句在两棵树源码里 0 命中——它是运营台 DB 覆盖出来的文案（src/lib/server/site-settings.ts:270-287、:338）。⇒ 对外报一个查无底稿的数，是最容易被客户当场打脸的一类。

跨境电商团队负责人会问的

  • "我的 PSB 母版能用吗？"——文案说能（siteContent.ts:62/64/315/373），代码硬拒（psd-sanitize.js:23）。他跑到第三天才发现，这单就没了。
  • "撑版谁管？"——不管（六格写不进）。他最怕的恰恰是"改完字，图不能看"。
  • "有没有同行在用？"——无客户名、无案例、无第三方评价（brands=0，B 级实测），品牌词前排还被邻居占着。
  • "多少钱？"——全站无价格入口（showPricing:false，实测），/pack 只说"先激活"。B2B 采购看不到价，就只能来问，而你这边没有可用观测承接。

技术负责人会问的

  • 回读到底回读什么？——重开文件、逐对象 ID + 归一化全文比对，不过就不发布（v15-runner.js:83-110、:272-278，A 级）。这条是全站最硬的卖点，官网上却只用"写入后核对"四个字带过。
  • 失败会不会被吞？——会，且有三条未修：终态回执触发 catch 引用 try 内 const → ReferenceError 被吞、outbox 排水停摆（ISSUES #247）；回执生成抛出被显示成"语言 X 未完成"（#116）；免 PS 层号歧义可致"回执全绿的静默漏翻译"（#159）。（B 级，行号出自别手，我未逐条复跑 ⇒ 标待确认）
  • 版本漂移：官网 /download 给 3.7.15（我实测 200），生产 config/release-identity.json 也是 3.7.15（一致，不是缺陷）；但 develop 已到 3.7.29 且发布说明含 3.7.25+ 的安装号鉴权。⇒ 首页若描述新版能力，客户装到的是旧引擎。
  • 导航里"工作台"是个 <button class="nav-login"> 而不是链接（我 grep 线上 HTML 确认），而 /workbench 返回 404（别手实测）⇒ 未登录访客点它没有明确去处。

信息安全负责人会问的

  • "留在本机"这句：本体确实不出机，但上传面比首页那句话宽——图层原文+译文进 DeepSeek（workbench/ai-review/route.ts:64-72）、设计稿/输出目录路径字符串随扫描上云（local-assistant/preparation/scan/route.ts:45-59）、字体/颜色 TopN、设备与 IP 哈希、漏斗事件、排障内容包（勾选后含原文译文）。首页只写"范围见隐私政策"。（B 级行号，方向与我今天为另一件事读到的 receipt 拒收正文一致）
  • 反过来还有一处过度披露：隐私页列"路径字符串｜会"，但我方代码里设计稿路径只发本机助手 127.0.0.1:49152，云侧 local-assistant/config 路由全仓 0 调用点（B 级）⇒ 要么删残留，要么改披露，两边不一致本身就是风险。
  • 保留期：对外承诺 7/90/180/365 天，生产侧只装了 tygf-site-traffic 一个 timer，cleanup 单元全是 test（deploy/install-timers.sh:15-16、:54，我自己读到，A 级）；测试站的 learning-cleanup 还是 dry-run 无 --apply。⇒ "到期即删"目前靠缺省行为与人工，不能当承诺讲。
  • 限流是单实例内存 Map（rate-limit.ts:21 注释自陈多实例需换 Redis）⇒ 若生产多实例，撞码/撞 AI 配额防护形同虚设（实例数未核实）。
  • 越权读别人批次：已防（按 principalId 过滤，B 级）。CSRF 面未逐条核 ⇒ 待确认。

第三部分 UI/UX 审查（问题 → 证据 → 影响 → 改法）

商业转化类（最贵）

  1. 对外承诺宽于实现（PSB、12 语、54 语言）。影响：首跑失败与信任崩塌。改法：文案改口径——PSD 支持、PSB 标"即将支持"；12 语写成"上限 12，建议 5—8"；语言数改"界面可识别 51 种语言名，其余直接填代码"，并在运营台留底稿。成本：改文案 + 一条守卫。证据：A 级。
  2. 无访客观测。影响：任何改版都是盲改。改法：先修 CSP 放行分析脚本（或换成自建最小埋点：首页曝光 / CTA 点击 / 表单开始 / 表单提交），拿到 14 天基线再谈转化优化。证据：A 级（CSP 头）+ B 级（beacon 报错）。
  3. 表单 7 必填 vs 后端 3 必填。影响：申请量被自己掐住。改法：前端只留 3 必填，其余转可选并标注"知道就填"。成本：一处组件。证据：A 级。
  4. 无价格可见性。影响：B2B 采购无法自评预算。改法：给一页"怎么算钱"（按标准单位 + 一个算例），不必给价目表也能给口径。证据：A 级（flags）+ B 级（无入口）。

产品定位类

  1. 首页卖"批量改语言"，护城河其实是"重开回读 + 例外清单 + 交付报告"。改法：首屏第二句直接讲这条硬机制（今天它藏在第 03 段），并把 PS 原生路线的适用边界写明白（模板化可变位归它，成品稿逐层回读归我们）。证据：A 级（v15-runner.js:96）。
  2. 无案例、无录屏。改法：先上真录屏（09-19 已有素材）+ 一份脱敏交付报告样例（报告本身是产品产物，比任何文案可信）。注意：不得编客户名与百分比。

交互类

  1. "工作台"是按钮且 /workbench 404。改法：未登录时该入口指向 /download 或 /auth/login，登录后进真工作台。证据：A 级（markup）+ B 级（404）。
  2. 移动端 /en 横向溢出（scrollWidth 421 > 390，别手实测）；首页无汉堡，点 header 按钮后导航链接从 5 变 2（行为可疑）。改法：英文页表格容器加横向滚动包裹；导航统一折叠。证据：B 级，需复跑确认。
  3. 点按区：线上桌面 58 个可点元素里 35 个小于 44px（B 级）。改法：见第四部分规范里的 44px 规则。

视觉类

  1. 小字与弱色不达标：small 9.6px 且 #929892 在白底 2.68:1；卡片正文 15px #747a75 = 4.39:1（B 级）。我用同一套令牌复算得 2.95:1，同一结论：不过 AA。改法：最小字号 12px、次级文字最低 #6b7168（≥5:1）。
  2. 层级只靠字号不靠字重：h1 78px 但 font-weight 400，h2 68px/800 —— 两个层级用两套逻辑，扫读时抓不住主干。改法：统一字重阶梯（见规范）。
  3. 圆角与阴影不成系统：实测圆角分布 50%×23、999px×19、12px×20、20px×11，阴影 6 种。改法：收敛到 3 档圆角 + 2 档阴影。

第四部分 视觉与色彩系统重构

前提纠正

线上是白底墨字绿强调（A 级，见结论第 3 条）。你描述的黑底朱红琥珀是 tuyigf-full-site-video-v6-package 那份未上线提案（--navy:#080e38 --blue:#536dff --red:#e54835）。因此我做四套：D0 现站基线（照实测令牌复刻）、D1 专业设计生产力工具、D2 现代工业软件（暗底 + 朱红）（把你原本的方向认真做一版）、D3 简约高端 SaaS。四套渲染同一份内容（导航/首屏/工作台示意/流程/表单），只差令牌，可直接对比：运营/视觉方向_20261029/视觉方向四选一_同一内容实测.html。

实测对比（A 级，visual-audit.json，每套 8 组读数：4 方向 × 1440/390）

  • 对比度：修完弱色后 四套全部 0 不过（检查元素数 D0 44、D1 65、D2 54、D3 41）。首轮我曾把次级色定得过浅，四套各 12—18 处不过 AA，已按实测改深（D0 #6b7168 / D1 #616a75 / D2 #7c8794 / D3 #6a6f77）。
  • 横向溢出：四套 1440 与 390 全部无。
  • 点按区：D0/D2/D3 全部控件 ≥44×44；D1 剩 4 个 <44 的是表单 label 文本（非控件），控件本身达标——D1 是桌面密度档，导航链接 40px 高，满足 WCAG 2.5.8 AA（24px）不满足 AAA（44px），这是有意选择，写进规范而不是当缺陷藏。
  • 控制台错误：0。

四套的方向判断（D 级判断 + A 级数据）

  • D0 现站：识别度中等（绿色在 PS 生态里不站队），阅读效率被小字与弱色拖累，转化上"温和但没牙齿"——它把最硬的机制藏在第 03 段。
  • D1 生产力工具：品牌识别靠"密度 + 等宽数字 + 单一蓝"，专业可信度最高，阅读效率最高（信息密度大但层级靠字重与分割线，不靠字号跳变），视觉疲劳中等（亮底）。适合"给采购和负责人看"的落地页。
  • D2 工业软件暗朱红：品牌识别度最高（朱红在同类工具里少见，且与"图译工坊"的"工"字硬感一致），与设计师的真实工作环境（Photoshop 暗色 UI）同频；风险是暗底长文阅读疲劳、以及朱红在中文小字上对比度要单独校（我实测把次级色提到 #7c8794 才过 5:1）。
  • D3 高端 SaaS：好看，但对这个产品是减分项——它暗示"轻决策、按月订阅"，而真实决策是"要不要把母版交给你"。衬线大字与柔阴影会削弱工程可信度。

推荐

双令牌体系，一套语义：营销站用 D1（专业生产力工具，亮底、密度、等宽数字），产品内的工作台用 D2（暗底 + 朱红，与 Photoshop 同环境）。理由三条，都可证伪：① 看官网的人里有非设计师（项目/交付负责人），亮底 + 高对比读得快；② 用产品的人是设计师，整天在 PS 暗色界面里，工作台跟着环境走降低切换成本；③ 朱红只留给"需要你决定"这一件事——把品牌色和业务上最贵的动作绑在一起，而不是当装饰。

设计规范（推荐方案完整令牌）

D1 · 营销站（亮）

  • 背景三层：页面 #f2f3f5 / 卡片 #ffffff / 下沉面板 #fbfbfc
  • 文字四层：主 #1c1f24 / 次 #333a42 / 弱 #5b636e / 注 #616a75（注级在 #fff 上 5.49:1、在 #f2f3f5 上 4.94:1）
  • 边框 #dfe2e6；分割线同色，不用阴影画线
  • 品牌/交互蓝 #1f6feb（白字 5.2:1）；主按钮底 #1c1f24 白字（16.1:1）
  • 状态三色只服务三态：已确认 #16794f / 待复查 #9a5b00 / 需要你决定 #b3261e；状态必须"色 + 文字 + 形状"三通道，不允许只靠颜色
  • 圆角 8（卡片）/ 6（控件）；阴影两档：0 1px 2px rgba(16,20,26,.08)（静态）、0 8px 24px rgba(16,20,26,.06)（浮层）
  • 间距基数 4，区块节奏 12 / 16 / 24 / 40 / 64；导航高 56
  • 字体：正文 Noto Sans SC / PingFang SC；数字与代码 IBM Plex Mono（tabular-nums）
  • 字阶：h1 56/700/1.08/-.02em，h2 32/700，h3 20/600，正文 15/400/1.75，辅助 13/400，最小 12（禁用 9.6—11px 正文）
  • 按钮：主 44px 高、次 44px 高（描边 #dfe2e6）、文字按钮 ≥24px 命中；焦点环 2px #1f6feb offset 2
  • 卡片：1px 边框 + 8 圆角 + 静态阴影；禁止玻璃
  • 表单：label 常驻（不做 placeholder 当 label）、控件 ≥44px、错误就近显示、必填只标 3 项
  • 工作台组件（D2 暗）：页面 #0b0d10 / 面板 #12151a / 浮层 #171b21 / 边 #23282f / 主文 #e8ebef / 弱文 #98a2ae / 注 #7c8794；朱红 #ff5c38 仅用于"需要你决定"与主操作；表格行高 32、字号 12.5、等宽数字、选中行左侧 2px 朱红条

保留 / 删减 / 重做

  • 保留：白卡分层、单一强调色的克制、"示意界面"标注（这条是诚实性资产，不许撤）、任务状态四→三对齐后的分组思路
  • 删减：999px 全胶囊（23 处 50% + 19 处 999px 的圆角噪声）、多档阴影、9.6px 小字、h1 用 400 字重、毛玻璃（只留导航一处或直接去掉）
  • 重做：状态徽章（三态 + 三通道）、首屏第二句（换成讲回读机制）、数字区（等宽 + 单位说明 + 分母）、价格口径页

桌面 IA（首页）：① 首屏（一句话 + 一句机制 + 两个 CTA + 四枚事实徽章 + 右侧工作台示意）② 它替你做什么 / 不做什么（两栏对照，含 PS 原生路线边界）③ 一次执行的四个环节（检查→写入→重开回读→例外）④ 例外清单实例（截图级报告样例）⑤ 开工前六件事（现有 pre-flight，保留）⑥ FAQ（含"我不做翻译""不处理智能对象"）⑦ 申请试跑（3 必填）⑧ 页脚（隐私/第三方清单/条款/下载）

移动 IA：首屏压成 标题 + 一句机制 + 主 CTA + 一枚徽章；工作台示意改为纵向三步卡片（不做双栏表）；表格全部套横向滚动 + 滚动提示；导航折叠为抽屉；申请表单分 2 步（先 3 必填，再补可选）

第五部分 落地方案

优先级矩阵（P0=先做；每条给商业影响 / 用户影响 / 成本 / 证据强度）

  • P0-1 对外口径降档（PSB→即将支持、12 语→上限并给建议值、54→51+代码、四态→三态、删"路径会上传"或补实现）｜商业：高（防信任崩塌）｜用户：高｜成本：低｜证据：A
  • P0-2 关掉人工收款暴露（creditPacksEnabled/manualQrFallbackEnabled 回到安全态）｜商业：高｜用户：中｜成本：低｜证据：A
  • P0-3 修观测（CSP 放行或自建 4 个事件）｜商业：高（否则 A/B 无从判断）｜用户：低｜成本：低—中｜证据：A/B
  • P0-4 表单前端必填 7→3｜商业：中—高｜用户：高｜成本：低｜证据：A
  • P1-1 首屏文案重排：把"重开回读 + 不一致不落盘"提到第二句｜商业：中｜用户：中｜成本：低｜证据：A（机制）/D（效果）
  • P1-2 上真录屏 + 一份脱敏报告样例｜商业：中—高｜用户：高｜成本：中｜证据：B
  • P1-3 12 语跑不完的产品侧修复（#199 备注列、#247 outbox 停摆、#159 静默漏翻译）｜商业：高｜用户：高｜成本：高｜证据：A/B（后两条待逐条复跑）
  • P1-4 视觉系统按第四部分令牌落地（先营销站 D1）｜商业：中｜用户：中｜成本：中｜证据：A（可达标）/D（偏好）
  • P2-1 移动端 /en 溢出与导航折叠｜用户：中｜成本：低｜证据：B（需复跑）
  • P2-2 "工作台"入口指向修正｜用户：中｜成本：低｜证据：A/B
  • P2-3 圆角/阴影/字重系统收敛｜用户：低｜成本：中｜证据：A
  • P2-4 生产删除调度补齐（让"到期即删"可兑现）｜商业：中（合规）｜用户：低｜成本：中｜证据：A

分阶段

  • 第 0 周（止血，不改设计）：P0-1、P0-2、P0-4。验证：线上文案与 flags 逐项对表；表单必填数=3。
  • 第 1—2 周（可度量）：P0-3 观测 + 基线 14 天（曝光/CTA 点击/表单开始/表单提交/发码）。验证：拿到 4 个数并存档。
  • 第 3—5 周（信任资产）：P1-1、P1-2、P2-2。验证：首屏停留、CTA 点击率对基线的增量。
  • 第 6—10 周（能力兑现）：P1-3 三条修复 + 把"建议 5—8 语"写进产品引导。验证：12 语批次成功率从 24% 抬到 ≥60%（同分母、同窗口、测试站 ExecutionBatch 口径）。
  • 第 8—12 周（视觉落地）：P1-4 营销站 D1 → 工作台 D2 → P2-1/P2-3/P2-4。验证：对比度 0 不过、控件 ≥44、无横向溢出（用我这次的探针当门）。

A/B 方案（前提：P0-3 观测先落地）

  • 实验 1 首屏主张：A=现文案（批量改语言）/ B=机制文案（重开回读，不一致不落盘）。主指标 CTA 点击率；护栏 表单完成率、跳出率。判断：B 提升 ≥15% 相对值且表单完成不降，连续 14 天，每组 ≥300 UV（按当前流量这可能要 4—8 周，先估分母再开）。
  • 实验 2 表单长度：A=3 必填 / B=3 必填 + 渐进式第二步。主指标 提交率；护栏 线索质量（发码后激活率）。
  • 实验 3 信任模块：A=无录屏 / B=首屏下方 45 秒真录屏。主指标 申请点击；护栏 加载时间。
  • 实验 4 价格可见性：A=不展示 / B=展示计价口径页链接。主指标 提交率；护栏 咨询量。
  • 统一纪律：一次只跑一个实验；先定分母与判停线再开；结果连同原始数一起存档。

交付给设计与开发的清单

  1. 令牌表（第四部分）→ 落成 tokens.css / Tailwind 主题；状态色必须映射到引擎三档常量，不允许页面自造。
  2. 组件改造清单：按钮（44px/焦点环）、卡片（去玻璃、圆角 8/6）、徽章（三态三通道）、表格（等宽数字 + 行高 32）、表单（label 常驻 + 就近报错）、导航（折叠 + 44px）。
  3. 文案改口径逐条 diff（P0-1 的 5 条）。
  4. 守卫：把"对外主张词表 + 三态名 + 最小字号 + 对比度"做成一条可复跑的门（我在 运营/kwland_20261028/_build/ 已有同类实现可直接搬：review-a11y.mjs、review-copy.mjs、negctl.mjs 负控）。

覆盖缺口（明确没查的）

  • 没有真访客：所有转化判断只能到"路径与卡点"，不能到"哪一步流失多少"。
  • 没有异地/多网络实测：本机对 tuyigf.com 出现 HTTP/2 TLS 重置需 --disable-http2 才通（别手报告），影响面未测 ⇒ 待确认。
  • 三条"失败被吞"（#247/#116/#159）我只核到行号出处，未逐条复跑 ⇒ 标待确认。
  • 生产实例数、机房真实位置、CSRF 全端点面 ⇒ 未核实。
  • 视觉四套只测了对比度/溢出/点按区，没有做真人偏好测试；推荐是设计判断。
