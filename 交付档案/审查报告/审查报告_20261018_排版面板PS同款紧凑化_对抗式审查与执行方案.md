## 一句话结论

按 Photoshop 字符面板的密度重做后，桌面展开态是 **432.75px 高**：12 个能力字段排成 **6 行 × 2 列**，每格 **24px**，字族/样式用同款下拉，行距/字距带预设。高级与结算明细默认折叠，同一面板展开它时是 741.25px，**默认折叠省下 308.5px**。360px 窄屏自动改成单列 12 行，面板高 623.5px、宽 294px，无横向溢出。门禁全绿：排版面板 smoke **197 断言 + 4 个 Vitest 用例**、浏览器模拟 **92 项全过**、`tsc` 与构建 `rc=0`。

## 1. 核心任务与验收

核心任务一句话：**让用户在 3 秒内看清 12 个字符能力各自能不能写，并直接改字族、样式、行距、字距，不用先翻一张大表单。**

目标用户与场景：在桌面工作台做设计稿校对的人，左手对着 Photoshop 字符面板，右手在我们的面板里设同一组值；窄屏是次要场景。

成功标准（本轮全部实测）：

- 桌面展开态高度 ≤ 480px：实测 **432.75px**。
- 字段格 24px、两列 6 行：实测 **24px、6 行、12 格**。
- 360px 不横向溢出：实测面板 **294px**，文档与主体滚动宽度均 360px。
- 结算口径不变：会发项数仍等于真实下发键数，界面不能自称会发未接入的字段。
- 不可写字段不伪造控件：灰底、虚线、琥珀点三态可见，悬停给原因。

## 2. 已落地的信息架构

面板从上到下只有五段，顺序照 Photoshop 字符面板：

- 语言页签：日语、德语，保持原样。
- 12 个字段格：字族/样式、字号/行距、字偶距/字距、水平缩放/垂直缩放、基线/对齐、语言/抗锯齿。
- 状态图例：虚线＝可写未接入，琥珀点＝未实测，灰底＝本版写不进，悬停看原因。
- 8 个开关：仿粗体、仿斜体、全部大写、小型大写、上标、下标、下划线、删除线。
- 结算摘要与保存按钮：只露一行「本次会发 N 项 / 本次不发排版字段」，高级与结算明细收进折叠区。

字段格用固定的 18px 图标列加 `minmax(0,1fr)` 内容列，长字体名不会撑破；24px 高度由 `h-6` 锁死，行距和字距的下拉预设沿用 Photoshop 的常用档位。

## 3. 入口方案：四个候选的对抗式审查

结论先说：**本轮产品默认仍是内联折叠条，抽屉只做到模拟并验证，不接进产品。** 原因是用户这一轮要的是「按这个 UX 做、别占空间」，紧凑内联已经把桌面高度压到 433px；抽屉是备用方案，不是这一轮的交付面。

内联折叠条（当前实现）：桌面展开 432.75px，1280 下宽 784px，360 下宽 294px。没有遮罩、没有焦点陷阱、不挡 PS 卡片。适合「边看 PS 边改」的主路径，推荐继续作为默认。

卡头按钮 + 右侧抽屉（模拟已验证）：抽屉宽 360px，360 视口下 331.19px（92vw），带 `role=dialog`、`aria-modal`、焦点陷阱、Esc 关闭、背景 `inert`、关闭再开保留未保存草稿。它把页面占位降到 0，但会盖住右侧 360px 内容，且多一层焦点管理。适合以后做「专注编辑」模式，不适合当默认。

右缘竖签（模拟已验证，≥1280 才出现）：点击开同一只抽屉，占用极小，但会跟浏览器滚动条和 PS 面板抢右缘；只适合桌面宽屏，作为可选入口。

悬浮球（模拟已验证，≥1280 才出现）：不推荐。它和翻译类浏览器扩展的悬浮球不是一回事——那些扩展寄生在别人的页面上，必须有一个常驻入口；我们自己的应用已经有卡头和折叠条，再加一只球只会遮住 PS 预览、制造 z-index 和键盘焦点冲突。

外来参考只取模式，不引依赖：抽屉的可访问性做法对照 Radix Dialog 与 shadcn Sheet 的公开模式，悬浮球只对照翻译扩展的入口形态；模拟里的抽屉是原生 React + portal 手写，没有为入口新增运行时依赖。

## 4. 对抗式审查：会失败的地方

**第一，24px 格子对触屏偏小。** 24px 刚好达到 WCAG 2.5.8 的最小目标尺寸，但手指点选不如 32px 稳。本轮按桌面优先保留 24px；如果移动端成为主场景，建议只在窄屏把格子抬到 32px，代价是面板再高约 96px。

**第二，360px 下单列 12 行，面板 623.5px 高。** 这是有意的取舍：360 下两列会把字体下拉压到 140px 以下，长字体名更难认。单列可读，代价是滚动。抽屉方案在 360 下是 331px 宽、内容区 900px 内可容纳，不想滚动可以选抽屉。

**第三，状态点只靠颜色，读屏拿不到原因。** 这是审查中真抓到的问题，已修：每个非可写字段现在都有一段 `sr-only` 文本，读出「可写未接入／本版写不进／未实测」加原因；8 个非可写字段 8/8 有说明。图例仍保留给肉眼。

**第四，高级与结算明细被折叠后可能没人点。** 摘要行始终露「本次会发 N 项」或「本次不发排版字段」，折叠标题写明「高级与结算明细」并在右侧显示脸名状态；数据没有删，只是默认不占高度。展开实测 333.5px，折叠 25px。

**第五，原生下拉和 datalist 的跨浏览器差异。** 本轮只在 Chrome 验证；Safari 对 datalist 的支持历来不完整，Firefox 的样式也不同。预设只是加速入口，输入框始终可以手输，不把预设当唯一路径。

**第六，8 个不可写字段仍占格子。** 这是为了保持 Photoshop 的心智模型和诚实：字号、字偶距、缩放、基线、对齐、语言、抗锯齿在本版 PS 写不进去，但位置保留、原因可见，不伪装成可用控件。若为了再省高度把它们全删，用户会以为产品没有这些概念。

**第七，抽屉的遮挡与焦点成本。** 模拟里全部通过，但它会盖住右侧内容，且需要处理 Esc、焦点返回、背景 inert、草稿保留。没有明确收益前不接进产品，避免为「看起来新」增加一条长期维护的交互链。

**第八，产品入口尚未接线。** 当前产品代码里仍是内联折叠条；抽屉只在模拟壳里。这是本轮最需要说清的边界，不把模拟通过写成产品已上线。
