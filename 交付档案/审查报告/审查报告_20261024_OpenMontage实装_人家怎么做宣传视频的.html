二、人家怎么做宣传视频

1 第一原则：所有片子必须走流水线

AGENT_GUIDE.md:49 写死一条 Rule Zero：要做视频，先找对应流水线、读清单、跑预检、一阶段一阶段做；禁止临时写脚本直接调工具。理由在同文件 :68："智能在技能里，不在即兴代码里"。

2 屏幕演示片的两个模式

pipeline_defs/screen-demo.yaml:22-42：真拍（录真实桌面/浏览器，必选 screen_recorder）与合成（终端动画用 Remotion 画）。Playwright 录制只写在描述文字里（:4-16），没进结构化 modes。

对我们的用法：该真录的（PS 里真改一层）真录，能合成的（译文表落位、进度条）合成——别拿录屏演可以画出来的东西。

3 七道工序，五道要人点头

screen-demo.yaml:77-239：idea → script → scene_plan → assets → edit → compose → publish。其中 idea/script/scene_plan/assets/publish 五关要人批（:85/:111/:134/:165/:239），edit/compose 自动过。预算默认 1 美元、每关最多返修 3 次、全线最多 10 分钟（:46-49）。

4 脚本不是文案，是动作地图

skills/pipelines/screen-demo/script-director.md:29-48：先标一张动作表——时间点、动作类型、对象、重要度、建议处理（实时/加速/切掉/高亮/缩放）；:79-87 给速度档：关键点击 0.75–1.0x、常规输入 1.5–2.0x、安装构建 3.0–6.0x、纯等待 cut；:87 明写"不要把关键证据放在加速段里"；:124 反面清单第一条："别解说着光标，要说结果"。

5 画面硬规格与缩放档位

场景倍数过渡 / 说明
整页结果1.0–1.3x先多给上下文，再决定下次缩放
终端 / 代码1.5–2.2x保留足够周边上下文
小按钮 / 图标2.0–3.0x带边距，让观众知道它在哪
弹窗1.4–2.0x框整个弹窗，不要切一半

倍数表来源 skills/pipelines/screen-demo/scene-director.md:54-60；过渡参数（0.8s ease-in-out、回总览 0.6s）见 skills/creative/screen-recording.md:67-76。短视频规格另见 skills/creative/short-form.md:11-18：9:16 1080×1920、安全区 900×1400、底部死区 300–320px、正文 42px+ 粗体、1–3 秒一变、20–40 剪/分、−14 LUFS / −1 dBTP。同屏最多 2 个提示、提示在动作之前、高亮与缩放二选一（scene-director.md:76-79）。

6 风格是一份可校验的文件，不是形容词

styles/premium-minimalist.yaml（投资人更新 / 产品叙事）：炭黑 #111827、钴蓝 #2563EB、底色 #F9FAFB、不用装饰性渐变；单场景最少停 2.75s、最多 12s，文字卡 3.75s，转场 0.45s；对比度 ≥4.5:1、同屏最多 2 个强调色、动效用来揭示层级而不是加能量。

审片时"不够高级"没法改；"单场景只停了 1.4 秒，低于 2.75 秒下限"能改。把风格变成数字，是这套东西最实用的地方。

7 调性三旋钮 + 模板/定制 + 区别性审查

skills/meta/taste-direction.md:8-45：先写一句设计判断，再拧三个 1–10 旋钮（视觉变化 / 动效强度 / 信息密度）。AGENT_GUIDE.md:143-146 把成片分两条路：模板档——"也是大多数片子看起来都一样的真正原因"；定制档——"复用引擎知识，绝不复用创意组件"，营销/发布/品牌片默认走定制。

收尾一道区别性审查（:146）："这片子换成别家产品还成立吗？我是不是又用了自己做过的那个样子？"——把"AI 味"变成了可以回答是/否的问题。

8 自检：逐项过，不靠"我觉得行"

skills/pipelines/screen-demo/executive-producer.md:248-259 G1–G7 七道闸 + 终检：裁剪区是否真框住目标 UI 且 ≥ 源分辨率 50%；字幕会不会挡内容；ffprobe 查时长/分辨率/编码；界面文字在成片分辨率下还读得清吗；压缩后文字抗锯齿有没有崩。

skills/meta/reviewer.md:9-17 的 CHAI 三条：准（每条问题指到字段/行号/某一帧）、全（发现一个错要扫完同类）、可改（严重项必须给具体改法，给不出就降级为"待查"，见 :42）。

9 决策留痕：改主意只能追加

AGENT_GUIDE.md:117-137：换供应商/声音/引擎都必须新追加一条决策，用同一"类别+主题"覆盖旧条，不许改旧条、不许改主题名。渲染引擎在提案阶段锁定后一路不变，静默换引擎＝严重治理违规（:389、pipeline_defs/animated-explainer.yaml:245）。

三、一个诚实的反面证据

它自己渲染的零键 demo（第 14 秒）就是深紫渐变 + 环形图 + 大数字，而它自己的风格文件把"generic AI-purple gradient"写进负面提示（styles/premium-minimalist.yaml:78）。

这不是打脸，是印证它自己的判断：默认档必然长得像模板，所以营销片才必须走定制档。这套系统给的是方法，不是审美——照默认跑，和我们现在的片子一个毛病。

四、对我们意味着什么

条拿走什么落到哪
1三旋钮先定，再动手片子开工检查
2模板档 / 定制档二选一，营销片默认定制防止再出"一眼 AI"
3区别性审查："换别家产品还成立吗"成片验收加一问
4CHAI 三性 + 严重项必须带改法并入对抗式审查规则
5缩放/速度/安全区硬数字审片尺子（可直接量）

可以真用的能力：Playwright 真录屏（已验证，补上了上次 HyperFrames 只能截静态板的缺口）；Remotion 合成（已验证，适合"表格→逐语言落位"这类画出来比录出来更清楚的段落）。

不建议接的：12 条流水线 + Backlot 看板（对单人体量过重）；它的代码（AGPL-3.0，内部出片可以，搬进产品就是传染性开源）；100+ 外部服务（要 key 付费，性价比低）。

三个国内网络坑（和上次 GSAP 同一类）：① 官方 PyPI 被重置 → 清华镜像；② Chrome Headless Shell 113 MB 从 Google 存储下载卡住 → 用系统 Chrome；③ 它的 HyperFrames 路线仍引用 jsdelivr 上的 GSAP（上次实测 23 处）→ 离线渲染前必须本地化。

五、覆盖缺口（未核实）

· 完整流水线没跑：七阶段里至少四关要人工点头 + 大量要 key 的工具；本机只验证了零键 demo 渲染和 Playwright 录制两件事。
· Backlot 看板没试（FastAPI 能起，体验未评估）。
· 117 个不可用工具只代表本机环境，不代表它产品能力。
· /product-launch-video 路由指向的 skill 目录不存在：7 个文件引用、0 个目录；可能是上游遗漏，未向上游确认。
· AGPL 判断是工程常识（内部使用 vs 对外分发），不是法律意见。
· 录制用系统 Chrome，不是它的标准环境（Playwright 自带 Chromium）；换机器要重验。
