## 二、更正（本轮推翻了此前哪些说法）

1. 推翻「r1 装好、`/ping` 回 build＝bundled-engine-20261020-r1 ⇒ 出厂身份已自证」。**身份自证的方向反了**：那串 buildId 恰恰是站点合同门不接受的值（RR2-01）。r1/r2/r3 三包一律**不可安装**，已在各目录 `说明.txt`／`测试卡.txt` 加作废抬头，并 `git checkout -f` 之前的构建树内容已不再等于任何入库提交。
2. 推翻「门全绿：bundled 18/18 …」。bundled 门当时不在任何 npm 入口里（RR2-03）；`smoke-pc-scan-live.mjs` 缺件即 exit 0（RR2-04）⇒ 那两个"绿"都不覆盖真实出厂件。本轮真 rc 逐条另取（见第四节）。
3. 推翻「带字体重建后 exe 字节完全相同」（RR2-06）。
4. 撤回上一轮的方案里**改名这一步**（见第三节理由）：工具链已不可达，改不了 VersionInfo，硬改文件名只会造出 OriginalFilename 与实际名不一致的新残留。

## 三、方案（先证伪自己，再定；已按此执行）

第一性原理一句：**免 PS 出厂要成的是"用户装上这个包，工作台敢让他用、引擎件换不了、装完看不到别人的名字"。三样缺一件就不算出厂。**

上一轮我提的"改名 tygf-engine → tygf-typography"经自己证伪后**降级为待办**，理由三条：① 改名要改 Windows 版本资源就得重编 Rust，而这台机器现在 `cargo`/`rustc` 取不到（PATH 里无 rust 条目、`C:\Users` 深度 5 内无 cargo.exe、`where cargo` 找不到）——改名会造出"文件叫 A、属性里原始文件名写 B"的新不一致，比现在更糟；② 收益是观感，代价是又一代孤儿名（RR2-02 正好是它）；③ 引擎件目前只有两枚拷贝，都在我建的临时建树里，**先保住可交付性**比先漂亮更要紧。

于是本轮方案收敛成五步，全部可当场验证：

| 步 | 做什么 | 判据（可复跑） |
|---|---|---|
| P1 身份纠偏 | `release-identity.json`／`.env.example`／`installer.iss`／`deploy/server-setup.sh`／助手 `server.js`＋`package.json` 六面统一前进 3.7.16，**`assistantBuildId` 一字不动** | `npm run repo:check` ⇒ `[release-identity] passed: assistant 3.7.16` |
| P2 出厂链补口 | `[InstallDelete]` 加"曾出厂名都要留一行"纪律；`CloseApplicationsFilter` 补引擎名 | 门内 [D3]/[D4] 且经 mutation 验证 |
| P3 门接线 | 新增 `test:pc-bundled` 并入 `test:trust-chain`；门内再加 [E] 断言"本门已被接线"；`smoke-pc-scan-live` 默认件改按出厂钉值解析 | `npm run test:pc-bundled` 真 rc=0；探针回显指向仓内件 |
| P4 出 r4 | 出包树内容＝将提交内容（八个被消费文件逐字比哈希），非别手在飞改动；ISCC 实编 | `ISCC rc=0`，件 sha/size 回读一致 |

不在本轮做（各有明确理由）：服务端下发 `pcExecutorEnabled`（动授权面，本技能规定永远需要人，且我先把设计约束写清楚）；改名（等工具链）；许可扫描重跑（仓内仍无可复跑脚本）；生产部署（Owner 已冻结到约 10-23）。
