# 有：官网能一键抓成视频素材，但不是"录屏"，也拍不到登录后的界面

你问的"GitHub 上有没有专门做视频的 skill，把官网走一遍录下来再剪辑"——有，而且我在你这台电脑上真跑通了。先给结论，再给证据。

## 结论

第一，官方有这个东西，叫 HyperFrames（作者 heygen，许可证 Apache-2.0，可商用，目前 7 万多星，今天还在更新）。它有一条命令 `hyperframes capture 网址`，专门把网站"走一遍"：自动滚到底、截 13 张整屏图（每屏重叠约三成），同时把品牌色、字体、板块结构、页面上的文字全部抽出来。我拿我们官网 tuyigf.com 试了，一次成功，1 分钟左右。

第二，要纠正一个说法：它不是录屏。它截的是静态图，然后把图放到时间轴上，用网页动画重新编排成视频，最后一帧一帧渲成 MP4。所以"然后剪辑"这件事，更像是"用真截图重新排一条片"，而不是拖一段录像。

第三，也是最要紧的一条：它不能点按钮、不能填表、不能登录。命令的所有参数我都列了一遍，只有网址、输出目录、超时、跳过资产这类，没有任何"登录/点击/脚本"的口子。这意味着：公开官网能拍，产品里登录以后那些真实操作画面拍不到。这跟我们已有的约束是一致的——产品内的执行入口要云端票据，真机跑批要你本人登录。

## 对你意味着什么

好消息是，我们片子第一镜右边那张"图层/译文表"现在是画出来的示意图。用它抓一次官网，就能换成官网真实像素，别人问"这是不是真的"时更站得住。

另一个好处是你可以自己拖时间轴了：它自带一个本地网页版剪辑台，运行一条命令就在浏览器里打开，能拖能改，改完直接重渲。不过它的桌面版 App 在 Windows 上能不能装，我没验证，只能说网页版实测能用。

坏消息有两个。一个是产品内的真实操作演示拍不到，还是得靠动画演。另一个是坑：它的模板默认要从国外的 jsdelivr 服务器加载动画库 GSAP（检查它自己的安装包里，有 23 处这么写）。国内网络下这一步会卡住，或者渲出来动画全丢。我们现在的渲染流程完全不出网，这是它当下实打实的一个优势。

## 我的建议

不整体换。理由很实际：我们现有的片子已经能出，38 秒、1080p、横竖两版都有；换过去意味着 11 个镜头全部要按它的规矩重写，还要把动画库搬进本地，收益主要是"渲染快一点"和"你能自己拖"。

建议只做三件小事：一是用它抓一次官网，把首屏那张示意图换成真实截图；二是借它的"逐帧快照"做法，给我们的片加一道审片检查（现在是我肉眼抽帧看）；三是以后拆竖版短视频时，用它的剪辑台当时间轴。

唯一值得整体搬过去的条件，是"你希望以后每次都能自己拖时间轴改片"。如果是这样，跟我说一句，我按这个方向重排。

## 实测记录

环境检查全部通过：Node 24、16 核 CPU、32G 内存、FFmpeg 9、系统 Chrome 就位，只缺语音合成和音乐生成这几个可选组件（我们用不上）。

抓官网：成功，13 张滚动图加 1 张整页大图，识别出 12 个板块、215 行页面文案，字体识别为"图译工坊思源黑体"可变字重 100 到 900，抓到 142 个页面动画。有个小瑕疵：有 1 个图片资产没抓到，不影响正文。

自测出片：10 秒、300 帧，23 秒渲完，退出码 0。

另外两个候选也查了：一个是第三方写的同类 skill（0 星、没有许可证，文字不能直接抄，但七步流程值得照着做）；另一个叫 motionable（MIT 许可）只有 macOS 版，我们这台 Windows 用不了。
