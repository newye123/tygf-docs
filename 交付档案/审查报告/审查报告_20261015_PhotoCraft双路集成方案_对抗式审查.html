01必断流程（8 处）

FLOW-00扫描/就绪两阶段没进方案server.js:2712 / :3211

执行前有两道 PS 扫描闸。方案只改 launchExecutor，无 PS 机在扫描阶段先失败。策略案 :73 自己列了「prepare CLI 等价」后续任务——两份文件一对，方案漏接自家前置。

FLOW-01成功结果写进不存在的合同文件v15-runner.js:134/:144/:56-66

runner 只认 taskRoot/executor-result.json（schemaVersion/ok/code='SAVE_SUCCEEDED'/count 硬校验），PS 路由 Thin_Executor.jsx:9 写它。方案写 report/receipt.json——全目录 0 读者 0 写者；真链是 journalRoot/receipts/<attemptId>.json（server.js:4334）。照方案写，PC 全对也 ENOENT 判死。

FLOW-02计数阈值算错 + 无人结算 → promise 永挂方案 :66 / v15-runner.js:143

完成条件 steps.length + 2，但 steps 已含 open/save/inspect/close，回复恒等于 steps.length，永远到不了 +2；且无 exit/close/timeout 的 settle。10min spawn 杀子进程后无人 reject → 任务卡 RUNNING → busy 看门狗锁保留（server.js:1484-1489「确认前不接收新任务」）→ 助手不重启不接活。

FLOW-03stdout 分帧脆断 → 进程崩溃风险方案 :61-63

split('\n') 不留残行 + JSON.parse 无 try，且包在 async 监听器——半行即 unhandled rejection（Node ≥15 默认终止进程）。正确写法就在自家原型：nops_scan.cjs:13-31 readline + pending map 按 id + 单行 try。

FLOW-04进度文件没人写 → 第 3 分钟必判死server.js:1480/:188 · attempt-runtime.js:51-58

progress.jsonl「由 CLI 写入」是编造（photocraft-cli crate 全部 .rs grep 0 命中、原型 0 命中）→ onProgress 永不触发 → 初次心跳后 3 分钟（BUSY_TIMEOUT_MS）被 markStalled 判 PHOTOSHOP_HEARTBEAT_STALE（还是 PS 错误码）→ 锁保留。10 分钟硬超时活不到。

FLOW-05manifest 键全不存在 → spawn 前即抛 + 存盘绕过发布契约execution-manifest.js:28-34/:66-71

manifest.masterPath 不存在（exact-keys 白名单）→ path.dirname(undefined) 秒死；output.destination_path 不存在（实为 destination_directory + LOCALE_SUFFIX_V1 + 碰撞策略）→ doc.save 丢 path 键 = 回写文档本体，绕过 WORKING_COPY_THEN_PUBLISH 与 publishVerifiedWorkingCopy；manifest.digest 不存在（现算 server.js:4029）→ 结算 SHA256 必抛。

FLOW-06回执四连违规，过不了结算断言settlement-receipt.ts:19/:73/:83 · attempt-state.ts:14-21

'SUCCESS'（合同要 SUCCEEDED）、'COMMITTED'（枚举无）、'INFO_READBACK'（枚举无）、openResp.timestamp（协议回复只有 id/ok/result，无 timestamp）——任一触发即 TypeError；且 PUBLISHED 还要求 verification ≥ DISK_OUTPUT_VERIFIED，方案的 outputFingerprint 注释说「从 inspectResp 计算」但从未算。

FLOW-07不看错误的假成功——违「不得静默降级」铁律方案 :188-194

不检查回复 ok/error（协议有错误回执形态 control-protocol.md:35），错误照样计数；attemptStatus 硬编码成功、completedAssignmentCount 硬编码满额、issueCodes 恒 []——部分失败也报 100%。

FLOW-08第二分派点（云批次）没覆盖server.js:4045-4067

server.js 有两处 runV15Execution + launchExecutor：本地 :3456（方案改了）与云批次 :4045/:4061（cloudAttemptId，独立 acquire :4032）——方案通篇未提，批次任务无 PS 依旧原样失败。
