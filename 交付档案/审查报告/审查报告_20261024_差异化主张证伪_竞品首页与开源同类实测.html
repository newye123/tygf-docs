Prevoda4ka 与我们的重叠：译文表驱动、PSD/PSB、含智能对象、还自写二进制解析器。差异（D 级，待实现级复核）：它的 validate 命中 20 处，但读上下文是校验母版文件与"显示原始英文短语供参考"，不是"写完重新打开逐层读回比对"。它 ★0、无 license、单人、只在 UXP（要较新 PS）——但这些都不改变"主张只有我们能写回图层讲不得"。

三、三条主张逐条判

主张判定依据改法
"把译文批量写回 PSD 原图层"＝独家能力必须撤Prevoda4ka 已做到（含智能对象）改讲形态：产品化交付（批量、逐语言、可核对），不讲"没人做过"
"含智能对象"当卖点改措辞开源侧已宣称嵌套智能对象检测差异落到工程完成度（12 语种批量×逐对象结算×失败可重试），不落"支持智能对象"这个功能点
"写完重新打开逐层回读比对、不一致单列"暂时站得住15 家商业首页 0 家讲；4 个开源仓库无一做成"写后回读比对"片子那句"能替换的文字层，写完都回读一次"可讲（讲我们做了什么），不得升级为"业界唯一/别人做不到"，直到读完 Prevoda4ka 源码

四、对片子的具体影响

  • 第 7、8 镜不用改——现有措辞已经是"我们做了什么"的形状，不是"只有我们能"。
  • 禁止新增任何"只有我们／别人做不到／独家"句式，含竖版 dev-log 口播稿。这条要进禁词闸（画面像素文字目前还没进闸）。
  • 若做对比型内容，只能比形态、不能比能力有无。

五、覆盖缺口

· 只查了 GitHub 英文检索（6 组查询式，total_count 56／9／50／4／9／279）。中文圈商业同类没查——淘宝／闲鱼／小红书上的"PSD 多语言代改"服务与报价，那才是真正抢预算的对手，我们的对手很可能不是软件，是人。
· Prevoda4ka 只读 README 没读源码，"它的 validate 不是写后回读"是 D 级推断。
· Canva Translate／Adobe Express／稿定翻译页未取到＝未核实。
· 未查这些开源项目的实际可用度（★0 不等于不能用，也不等于能用）。
· 上一轮"没有任何开源实现做过按原图层行数重排译文"这条旧结论本轮未复核，不得当新证据引用。
· 两路在跑的调研 agent（品牌话术结构／同品类宣传口径）未并入本报告。

六、下一步建议

  1. 读 Prevoda4ka 源码（半天可判），把"回读核对是否独占"钉死——它决定第 8 镜能否从"我们这样做"升级成"只有我们这样做"。
  2. 补中文圈同类普查：淘宝／闲鱼／小红书搜"PSD 多语言""设计稿代改"，看真实在售服务与报价。
  3. 把"禁用'只有我们/独家/别人做不到'句式"写进对外主张闸，与画面像素文字闸同批。
取证脚本（本会话实跑，可复跑）：launch-probe-1024/competitor-copy.mjs（15 站首屏文案）、gh-psd.mjs（GitHub 6 组检索＋仓库元数据）、gh-readme2.mjs（4 仓库 README 正文四轴判定，走 /readme API 端点）。
