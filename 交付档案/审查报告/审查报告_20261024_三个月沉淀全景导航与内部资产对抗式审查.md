# 三个月沉淀全景导航与内部资产对抗式审查（2026-10-24）

- **承接**：Owner 令「先给我一份导航 HTML，然后看看内部可以沉淀的内容呢，都有哪些，使用对抗式审查继续看看」。
- **方法**：按刚建成的 `yt-adversarial-review` 技能跑完整一轮——固定基线（容器根 + `worktrees/develop` 只读取证）→ 四把混沌压力刀（跨接缝探针 / 时间旅行 / 规模跳变 / 存在性质疑）切入内部沉淀物 → 区分 `Survived: YES`（真资产）与 `Survived: NO`（已过期/分裂/腐烂的负资产）→ 给出对外分享导航与对内封装路线。全程只读，未改任何业务代码、未碰两站。
- **一句话结论**：3 个月攒下了 **247 个冒烟门、165 条测试链、985 份交付档案、4 套自研 Skill**；对外可切出 **8 个零泄密选题/开源物**，但对内用压力刀一砍，暴露出 **Skills 四目录分裂、开机必读文件滞后 4～44 天、记忆账本膨胀至 1.65MB、联调排障靠手摸** 四个真问题——内部最值得立刻沉淀的是 **5 个收口工具/Skill**，而不是再写新文档。

## 二、对抗式审查：用四把压力刀审视「内部现有沉淀」

不跑对抗审查，很容易把「文件多」当成「沉淀好」。我们用 `yt-adversarial-review` 的四把压力刀逐一实测，给每块内部沉淀打上 `Survived: YES / NO`：

### 刀 1：跨接缝探针（Cross-Seam Probe）→ 审 Skills 沉淀
- **判定**：`Survived: NO`（分裂在不同工具目录，互相看不见）
- **实测证据**：
  1. `C:\Users\ivan\.agents\skills\`：放着 `yt-adversarial-review`（今日新建）、`yt-uiux`、`goalpro`、`ljg-*`。OpenCode 能读，但 Qoder 默认不读这里。
  2. `F:\工具开发\图译工坊内测版\.qoder\skills\`：放着 `yt-zongkong-round`（总控轮次机械流程 + `redlines-and-pitfalls.md` + `round-scan.mjs`）。OpenCode 的技能列表里**没有它**。
  3. `C:\Users\ivan\.qoder-cn\skills\`：放着 `yt-sansheng-liubu`（三省六部制度母本）。它甚至不在仓库里，OpenCode 也看不见。
  4. `C:\Users\ivan\.config\opencode\skills\`：放着 4 个视频类 skill。
- **影响**：不同 AI 工具（OpenCode vs Qoder）各自只拥有一半大脑。你在 OpenCode 里无法直接调总控与三省六部，在 Qoder 里调不到刚沉淀的对抗式审查与 UI/UX 引擎。

### 刀 2：时间旅行（Time Travel）→ 审 `AGENTS.md` 开机必读四件套
- **判定**：`Survived: NO`（4 件里有 3 件已过期或指错路，正在误导新会话）
- **实测证据**：
  1. `AI_MEMORY/CURRENT_STATUS.md`（规定开机第 1 必读）：最后修改于 `2026-10-20 10:16`，**已滞后 4 天**。原因是「单写者令」规定只有总控长槽能改，总控不更，所有业务会话读到的就是 4 天前的旧盘面。
  2. `总控/产品功能全景_20261003.md`（规定开机第 4 必读）：最后修改于 `2026-10-04 09:26`，**已滞后 20 天**。近三周的多稿工作台、字体排版定制、免 PS 引擎等关键进展均不在册。
  3. `AGENTS.md:71-73`（关键路径速查）：仍写着 `worktrees/v1.5-trust-chain/docs/HANDOFF.md`。实测该文件停在 `2026-09-10 09:03`（30 KB，**滞后 44 天**），而真正活着的接力账是 `worktrees/develop/docs/HANDOFF.md`（`2026-10-24`，223 KB）。

### 刀 3：规模跳变（Scale Shift）→ 审记忆账本与文档检索
- **判定**：`Survived: NO`（单文件越过 MB 级，AI 检索频发超时与吞标题）
- **实测证据**：
  1. `TASK_LOG.md` 达 **1.65 MB**、`ISSUES.md` 达 **526 KB**。由于「法条萃取令」禁止随意删改历史，文件只增不减；AI 用 `edit` 置顶插入时已多次发生「吞掉上一节标题」的事故。
  2. `交付档案/` 下 **985 个文件**只有按类型分文件夹，没有一份按「业务模块 / 有效状态（现行 vs 已推翻）」的轻量级总索引。AI 找一份最新方案全靠 `glob` 猜文件名日期。
  3. `worktrees/` 下 **30 个目录**含大量 `tmp-*`、`pack-*`、`release-*` 阶段性快照，全盘搜索时如果不显式排除，极易超时（今日 PowerShell 全盘搜即触发 120s 超时）。

### 刀 4：存在性质疑（Existence Question）→ 哪些内部沉淀真正扛住了压力？
- **判定**：`Survived: YES`（这 5 块是全项目最硬的真金白银）
- **实测证据**：
  1. **247 个 `smoke-*` 冒烟门 + 门内自带负控**（如 `smoke-ops-logging-conf.mjs:116`、`smoke-local-assistant-errors.mjs:489`）：因为 LLM 天然有「否定式盲区（Negation Blindness）」，文档里写一百遍「禁止 X」不如写一道 `rc=1` 的确定性脚本门。
  2. **中台控制面与飞书三值对账闸**（`scripts/control-plane.sh`、`sync-task-ledger.mjs`、`test-sync-reconcile.sh` 35 断言）：把散乱对话变成了 `ledger.jsonl` 机器账，并用 `L/F/P` 三值比对守住人手批注。
  3. **总控一键只读扫盘与假结果陷阱库**（`round-scan.mjs` + `redlines-and-pitfalls.md`）：一条命令零写入拉齐八组状态，封死了 22 种 `rc=0` 静默假结果。
  4. **对外写法定则与线上复扫门**（`写法定则_20261017` + `smoke-legal-pages-drift.mjs` + `smoke-seo-consistency.mjs`）：把文案宣传纪律变成了每次发布必过的第 17 道预检门。
  5. **今日落地的 `yt-adversarial-review` 引擎**：把散落 3 个月的审查套路（负控四式、探针自证、IS/IS-NOT、七把压力刀、分歧三选一）正式收口成可调用的技能包。

## 三、内部沉淀行动清单：接下来最该封装的 5 件事（按 ROI 排序）

既然审查出了真缺口，内部沉淀就不该是「再写几篇总结文档」，而是把下面 5 件事做成**工具、Skill 或确定性门禁**：

1. **【P0·统一大脑】打通 `.agents/skills` 与 `.qoder/skills` 的四套自研 Skill**
   - **内容**：把 `yt-adversarial-review`（对抗审查）、`yt-zongkong-round`（总控轮次）、`yt-sansheng-liubu`（三省六部制度）、`yt-uiux`（UI/UX 引擎）统一收进仓库受版本管控的母目录，再双向链接到 OpenCode 与 Qoder 的读取路径。
   - **收益**：消除工具隔离，任何一个 AI 窗口进来都能调用全套沉淀。
2. **【P0·联调排障】新建 `yt-testsite-doctor`（测试站与本地助手联调诊断 Skill + 脚本）**
   - **内容**：把今天摸出来的整套暗门（测试站 `?key=` 门令牌自动提取、Prisma 测试账号与邀请码一键生成、助手 49152 端口 `ping` 与 `authorization/check` 状态核验、回调地址 `localhost:3000` 错配检测、`ASSISTANT_INSTALL_BINDING_MISMATCH` 归属比对、10 秒 `VERIFY_TIMEOUT` 慢跳统计）封成一个只读诊断脚本 `scripts/doctor-testsite-assistant.mjs` + 配套 Skill。
   - **收益**：以后再遇到「工作台点了没反应」，10 秒钟直接打印出断在哪一层，不用每次重花半小时排障。
3. **【P1·指针与冷热分层】修正 `AGENTS.md` 死指针 + 生成 `AI_MEMORY` 轻量级热索引**
   - **内容**：① 把 `AGENTS.md` 里指向 `v1.5-trust-chain` 的旧指针更正为 `worktrees/develop`；② 写一个小脚本 `scripts/build-memory-index.mjs`，不删改 `TASK_LOG.md`（1.65MB）和 `ISSUES.md`（526KB）一字（严守治理三令），只自动提取最近 7 天条目 + 所有未关闭 ISSUE 标题 + 985 份交付档案中的「现行有效方案」生成一份 `<20KB` 的 `AI_MEMORY/HOT_INDEX.md` 供新会话秒读。
   - **收益**：既不违背「禁止删改历史三账」的铁律，又让新会话开机读取速度提升 10 倍、不再被 44 天前的旧指针带偏。
4. **【P1·规矩变代码】把「防吞标题」与「台账追加」封成唯一写入口脚本**
   - **内容**：现在 `TASK_LOG.md` 置顶插入靠 AI 手写 `edit`，一天吞三次标题（虽然写了规矩要 `grep -c '^## '` 核对，但 AI 会忘）。直接参考 `.qoder/skills/yt-zongkong-round/scripts/ledger-write.mjs`，提供一个 `scripts/tasklog-prepend.mjs`，脚本内部强制校验「插入后 `^## ` 计数精确 +1、日期合法无 `x` 占位」，不合格直接拒绝写入。
   - **收益**：用确定性代码消灭 D 族记账吞历史事故。
5. **【P2·工作树减负】30 个 Worktree 的只读体检与归档建议单**
   - **内容**：写一个只读脚本扫一遍 `worktrees/` 下的 30 个目录，按 `git merge-base --is-ancestor` 对比 `origin/develop` 与 `origin/main`，输出一张表：哪些是「100% 已合入、无未提交改动、可由 Owner 确认后清理的临时构建树（如 `tmp-*`、`pack-*`）」，哪些含独有提交必须保留。
   - **收益**：防止全盘搜索超时，腾出几十 GB 磁盘空间。
