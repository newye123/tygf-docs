这批件的价值不在好看，在于它把「一个搜索词该看到什么」拆成了可判定的三件事：此刻在干什么 → 用哪种形态接 → 配哪族色调。审查要证伪的就是这三件事有没有编。结论：数字有出处，出处覆盖率被夸大了（已改），能力面有两处超出实现（已撤），五道闸里有三道原本会假绿（已补，并用负控证明现在会咬人）。

一、事实层：页面说的数字，仓库里到底有没有

证据源两份，都是盘上真实存在的文件：

  • 交付档案/GEO测量/测量记录_20261017_中文SERP前排形态与百度收录在场性.md —— 四个中文词的前排 76 条分桶
  • 交付档案/宣传与运营/答复_20261014_SEO-GEO关键词与自查词表.md —— 关键词分档词表

逐条核完，数字本身全部对得上：教程形态 38/76（测量记录:40）、产品落地页 1 条（:35、:40）、Adobe 官方帮助在「PSD 批量替换文字」前排 4 条（:21）、四词合计 9 条（:30）、电商词问答 5 博客 4（:23）、素材站 14/20（:22）、品牌词前排本站 0 条（:48）、单批 12 语种（worktrees/develop/src/lib/workbench/batch-limits.ts:6，执行面 5 处硬拦）。

但下结论的方式有三处越界，已改：

  1. 把跨词合计说成词族专属。原句「这个词族的前排…76 条里教程 38 条」——38 是四个词的合计，其中一个还是我们主动放弃的词。现改为「本仓库实测的四个中文词（含一个我们主动放弃的词）前排共 76 条里…」，并补一句「本页这个词未单独测过」。_build/kwdata.mjs:112
  2. 把供给形态读成有效性证据。原句「教程形态已经在 SERP 里被证明吃得开」——测量只数了前排是什么，没有任何点击或排名读数。现改为「那组词的前排本来就是教程形态在承接」。_build/kwui.mjs:452
  3. 出处覆盖率虚高。索引页原写「形态依据来自 10-17 的中文 SERP 测量」，而 12 页里只有 4 页的词真被测过，11/12 还是英文词（测量记录:63 明写 Google/Bing 未测）。现改为「只有四个中文词实测过，其余按词表档位与搜索意图推定」，并逐个在引数字的页里写明本页测没测过。_build/kwui.mjs:435、kwdata.mjs:112/167/330

另外两处内部矛盾也修了：02 页原说「前排谁也没压住谁」，而同一份测量的判定 4 明写 PS 原生路线在第 11、12 位赢着（测量记录:43）——现按实测口径改写。

二、能力层：两处超出实现面的承诺，已撤

这是本次最该拦下来的两类，因为对外说了就是假话。

  • 「字号按语言设」写不回去。助手的字段白名单里 fontSize / size 在 LOCKED_KEYS（worktrees/develop/download/local-assistant/typography-profile.js:33-37，硬拒），而界面侧 2026-10-23 已按 Owner 令把字号/缩放/对齐/语言/锯齿六格撤下（src/lib/workbench/typography-capabilities.ts:55-56 注释原文）。三处文案里的「字号」全部改成实测可写的项：字体、行距、字距、自动字距。kwdata.mjs:200/297/683
  • 「不支持的语言不会静默跳过，会出现在报告里」查无实现。穷尽 grep 只命中文档类 unsupported 与字体清单分支，没有语言级不静默跳过的实现面。换成有出处的同一位置边界：「一批超过十二种会被拦下并逐张给原因」——依据 src/lib/workbench/csv.ts:723-724（CSV_TOO_MANY_LANG_COLUMNS）与 src/lib/workbench/table-grouping.ts:348-352（超限逐张给原因）。kwdata.mjs:489

三处措辞与产品口径对齐：三态名「已写入」改回产品的「已确认」（src/app/(zh)/guide/ps-batch-replace-text/page.tsx:84）；「缺字形掉成方框」改成产品的真实说法「会用 Photoshop 的替代字体，写进去后宽度可能变化」（src/components/workbench/layout-exception-list.tsx:22-23）；页脚「不上传、不追踪」改成「本页不上传、不统计」——因为产品确实要上传图层文字与译文（src/config/site.ts:14），旧说法在真站上就是虚假陈述。

「德语、俄语、葡萄牙语通常最长」这条全仓无测量出处，改成不点名语言长短的做法（先拿最长的几种试）。

三、交互层：三个真 bug，都是点开才会发现的

  1. 清单卡片的语言名被自己的计数器盖掉。勾选后 paint() 用 .chk-card-h span 取计数格，这个选择器先命中了卡头里语言名的 <span class="zh">，于是「简体中文」原地变成「0 / 6」。修法：计数格改成 [data-count] 专属性选择（kwui.mjs:112、client.js:335），并给探针加一条反向断言「卡头必须还是语言名」（interact-kw.mjs）。
  2. 对比表转一次就永久丢样式。转置只搬 th.innerHTML，把 class="a"（强调下划线）和 class="og"（断行控制目标）全丢了，来回点两次也回不来。修法：连 class 与 scope 一起搬（client.js:281-313）。
  3. 英文关键词页默认出中文。11/12 两页服务的是英文搜索词，却硬编码 data-lang="zh"，首屏给访客看中文。修法：按页给默认语言（kwdata.mjs 的 uiLang、page.mjs:43-46），<title> 与 description 同步。

顺手补掉的降级态与无障碍：无 JS 时不再烘焙假读数（0 / 72、3 已确认 一律改 —，noscript 明说「带 — 的读数按未启用看待」）；语种按钮的 aria-selected 在 <button> 上无效，改 aria-pressed（CSS 选择器同步）；三张横向滚动容器加 tabindex="0" + 区域名 + 窄屏「可以左右滑」提示；计数加 aria-live="polite"；阿拉伯语演示整块跟着 RTL 走（原来只翻 .ps-body 半块）；.sr 加 user-select:none（否则 Ctrl+A 会复制进 72 条隐藏文本）。

清单形态本身也换了：原来 12 张卡片重复同一套六项，滚三屏全是同样的字；改成 6 行 × 12 列一张矩阵表（72 格），一屏看全，列头带每语种进度。

四、闸门层：三道闸原本会假绿，已补并用负控证明会咬人

这是本次最值钱的一层——前面所有「0 命中」的可信度取决于闸门本身。取证发现：

  • 五道闸里四道失败时也退出码 0（只有 review-copy.mjs 有 process.exitCode）。也就是说「报 50 条」和「报 0 条」在记账脚本眼里一样。现五道全部有退出码，且都打印「扫了几个文件 × 几档宽度 × 几种语言」的自证行。
  • review-lines.mjs 的根目录取 process.cwd()，换目录跑就扫 0 个文件还打印同一行「0 instances」；现改 import.meta.dirname，扫到 0 个直接 exit 2。
  • verify.mjs 的首屏标题选择器写的是 .page.active h1，13 个产物里 0 命中——「首屏标题实测」是死代码；现改真实选择器，回显里能看到 h1Size:"68px"。
  • interact-kw.mjs 把 demo / 转置 / 清单三段全写在 if (元素存在) 里，整段被删也全绿；现按 kwdata 派生「哪几页必须有什么」，缺了就报（负控 NC3 实测：删掉 01 页的 [data-demo] → FAIL 01-psd-batch-edit.html 缺 [data-demo]）。
  • 对比度检查遇到带 background-image 的祖先就整棵跳过，且从不报跳过了多少——注入白底白字（约 1.0:1）仍报 contrast 0。现改为「越过渐变继续找实心背景并照算」，同时打印 skippedGrad。
  • 文案闸的豁免白名单里有品类词「翻译工具」，能放过「不是通用翻译工具，而是排版流水线」这种正经违规；已从 ALLOW 移除（换成「承诺」这个真正的诚实限定词）。另外补了跨句形态：不是快。而是稳。 原来因句号断链而 0 命中。
  • 断言只测 zh@1440 / en@1440 / zh@390 三格，en@390 从未测过。补上后立刻抓到 6 页英文首屏在 390px 被缩到 22—25px；修法是把缩字下限从 22px 抬到 28px，宁可换行也不缩到不可读。
  • 320px 任何闸都没扫过；宽度档从 4 档加到 5 档。

负控全案：node negctl.mjs → 五发注入（跨句反义 / 白底白字 / 删演示容器 / 单字成行 / 横向溢出）逐发要求对应闸 rc=1，五发全 PASS，且跑完产物与注入前逐字节一致（脚本自带还原与哈希比对）。
