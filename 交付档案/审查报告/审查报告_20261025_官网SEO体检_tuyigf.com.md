- 体检时间：2026-10-25 上午
- 工具：claude-seo v2.5.0（本轮刚装好的那套）
- 范围：sitemap 里的全部 9 个页面，逐页抓 HTML、逐页解析、桌面与手机截图
- 方式：只读。没有改站点、没有提交代码、没有上传任何文件

## 一句话结论

**站点底子很好，唯一拖后腿的是「打开速度」。** 同一台电脑、同一时段，无关站点都在 2.4 秒内载完，而官网首页最快 3.0 秒、最慢 50 秒都传不完，6 次里有 2 次直接超时。健康分 **72/100**，扣分几乎全在这一项。

## 一、最要紧的一条：站点会间歇性「卡住不传完」

这是这次体检唯一算得上「影响生意」的问题，所以放最前面。

### 实测读法（都在同一台电脑、同一时段）

| 测什么 | 结果 |
|---|---|
| 官网首页 96 KB，连测 6 次（每次最多等 25 秒） | 完成 4 次：5.3s / 6.7s / 16.9s / 21.6s；**超时 2 次**（分别只收到 87,417 B、93,160 B） |
| 官网一个 8.3 KB 的静态脚本，连测 5 次 | 完成 3 次：4.3s / 5.5s / 9.7s；**超时 2 次**（一次 0 字节，一次只收到 8,027 B） |
| 首页分享图 22.7 KB | 第一次下载只收到 17,797 B（图片不完整、打不开），重下才拿到完整文件 |
| 对照：cloudflare.com（1.33 MB），4 次 | 1.58s / 1.56s / 2.10s / 2.36s，**4/4 全部完成** |
| 对照：example.com，4 次 | 0.62s / 0.68s / 0.58s / 0.64s，**4/4 全部完成** |

### 这条读数说明了什么

- **不是我的网卡**：同一分钟内，1.33 MB 的外站 2 秒载完，说明出口带宽正常。
- **是站点这一侧的问题**：卡住的位置在「服务器已经开始回话、但内容传不完」，而且连 8 KB 的静态文件都会卡。这种形态通常出在 Cloudflare 边缘回到新加坡源站这一段，或者源站进程忙不过来。
- **首页 HTML 完全没走缓存**：响应头里 `cf-cache-status: DYNAMIC`，意思是每次访问都要回源站现算。对一个内容几乎不变的营销首页，这是最容易被省掉的一秒钟。
- **静态资源缓存是好的**：脚本与样式是 `max-age=604800, immutable`（7 天），这点做得对。

### 对生意的直接影响

1. **搜索收录会变慢**：Googlebot 抓取时有时间预算，一个要 20 秒才传完的页面会被降低抓取频率。
2. **首屏速度（LCP）会被拉低**：这是 Google 排名三大体验指标之一。
3. **来一个走一个**：从搜索结果点进来的人，等待超过 3 秒就会退。

### 建议先做的三件事（只动配置，不改代码）

1. 到 Cloudflare 面板看 **源站响应时间（Origin TTFB）** 和 **缓存命中率**：如果源站本身就要 3–14 秒才吐出第一字节（这次实测首字节 1.0–14.3 秒），问题在源站，不在 CDN。
2. 给营销页加一条 **Cache Rule**：首页、下载页、指南页、协议页这类不随登录变化的页面，让 Cloudflare 缓存 5–30 分钟。现在它们每次都要回源。
3. 顺手看源站的进程负载和内存：这台机器同时跑着业务接口，营销页回源会跟业务抢资源。

## 三、其余要修的（按严重度排）

### 高

**1. 英文页的描述以中文开头，且全都超长**
`/en/download` 的描述是「图译工坊 local assistant (Windows 10 / 11, 64-…」，`/en/terms` 是「图译工坊 User Agreement: …」，`/en/privacy` 是「图译工坊 Privacy Policy: …」。英文搜索结果里会先看到四个中文字，再看到被截断的英文。三页描述分别 292 / 193 / 200 字符，都超过 160。

**2. 分享卡上的文案和隐私政策口径不一致**
`og-cover.png`（1200×630，22,717 B）上写的是「本地驱动 Photoshop · 回读核对 · **文件不出本机**」。而隐私政策与 `llms.txt` 的真实口径是：PSD/PSB 源文件不出本机，**图层文字与译文会上传到新加坡的服务器**。分享卡把「文件」笼统地说成不出本机，属于对外主张说过头，风控上不划算。

**3. 全站 9 个页面，内容图片 0 张**
`<img>` 计数为 0、`<picture>` 计数为 0，首页的画面全靠 CSS 画的模拟界面。好处是快，代价是：设计类产品没有任何真实界面截图、流程图可供搜索与 AI 引用，图片搜索这条入口也是空的。

### 中

**4. sitemap 缺 2 个真实页面，且全站没有 `lastmod`**
sitemap 里只有 `changefreq` 和 `priority`，这两个标签 Google 已经明确不看；真正有用的 `lastmod` 一个都没有。

**5. 下载页教用户核对 SHA-256，但页面上没有印这个值**
下载页常见问题写着「安装前可对安装包计算 SHA-256 校验，与我们提供的校验值比对」，但整页 64 位十六进制串出现 **0 次**。值其实存在接口里（`/api/local-assistant/latest` 返回 `sha256: 1C53D1FA…042CE8`），只是没展示给人看。顺带核对过：下载页标的 **v3.7.15 就是接口里的最新版**，不存在发旧包的问题。

**6. 结构化数据可以再补一层**
已有的很扎实：Organization / WebSite / SoftwareApplication / FAQPage / TechArticle，日期齐全，FAQ 问答在页面上真的可见（不是藏起来骗收录）。可补的是：
- `SoftwareApplication` 缺 `offers`（价格）、`image`、`screenshot`
- `Organization` 缺 `sameAs`（社交/代码托管主页）
- 下载页、协议页缺 `BreadcrumbList`
- 指南文章缺 `author` 与 `image`

**7. 指南页只有中文，没有英文版**
`/guide/ps-batch-replace-text` 没有 `/en` 对应页，hreflang 也是空的。它正好是全站唯一一篇教人「怎么判断稿件能不能自动改」的内容，是最该被英文用户搜到的一篇。

**8. 安全响应头重复**
`X-Content-Type-Options`、`X-Frame-Options`、`Referrer-Policy` 各出现两次（Cloudflare 加一次、Next.js 加一次）。不影响使用，属于配置卫生问题，可以清理。

### 低

**9. 首页 canonical 是 `https://tuyigf.com`（无尾斜杠），实际访问的是 `/`**
小瑕疵，建议统一成与 sitemap 一致的形式。

**10. 内链里混进一条 `/cdn-cgi/l/email-protection`**
这是 Cloudflare 的邮箱混淆机制，用户点不受影响，但爬虫看到的是一个死链。

## 四、已经做得好的（这些别动）

- **AI 爬虫规则是明确放行的**：robots.txt 逐个写了 OAI-SearchBot、Claude-SearchBot、PerplexityBot、ChatGPT-User、Claude-User、Perplexity-User、Google-Extended，全部 `Allow: /`；同时挡住 `/api/`、`/admin/`。
- **`llms.txt` 与 `llms-full.txt` 双份都在，而且内容是诚实的**：明确写「不做翻译」、写清「什么会上云、什么不会」、还专门澄清了与 ImageTrans 撞名的问题。这在同类站点里属于少见的高质量。
- **多语言标注是齐的**：zh-CN / en / x-default 三向互指，`<html lang>` 分别正确。
- **协议与隐私页没有偷懒**：4,044 / 3,570 个汉字，还给第三方处理清单单独开了一页。
- **安全与规范化到位**：HSTS（1 年、含子域）、CSP、COOP、CORP 齐全；登录页 `noindex, nofollow`；不存在的地址返回真 404；`http://` 与 `www.` 都 301 归一到主域；`/en/` 308 归一到 `/en`。
- **压缩与缓存对**：首页 HTML 原始 96,429 B，gzip 后 27,196 B（压掉 72%）；静态资源 7 天 immutable。
- **服务端渲染正常**：抓下来的 HTML 里标题、正文、结构化数据都在，不依赖 JS 执行。

## 五、修法路线（建议顺序）

**第一批（本周，只动配置，1–2 小时）**
1. 查 Cloudflare 源站 TTFB 与缓存命中率，确认卡点在源站还是回源链路
2. 给营销页加缓存规则（5–30 分钟）
3. sitemap 补上两个 `/privacy/subprocessors` 页面，并给所有页面写 `lastmod`
4. 首页描述从 98 字压到 70–75 字；三个英文页描述压到 150–160 字符，并去掉开头的中文「图译工坊」

**第二批（1–2 周）**
5. 换掉分享卡文案（把「文件不出本机」改成「PSD 不出本机」或「源文件不出本机」）
6. 下载页把 SHA-256 印出来（值从接口取，别手抄）
7. 首页、下载页各补 1–2 张真实界面截图，配好 `alt`

**第三批（1–2 个月）**
8. 指南文章写英文版并接进 hreflang
9. 结构化数据补 `offers` / `sameAs` / `BreadcrumbList` / `author`
10. 全站加一次真实用户的体验指标监测（需要 Google API 或第三方监测，本机做不到）

## 六、这次体检没做到的部分（如实交代）

1. **没有 Google 官方数据**：本机连不上 `googleapis.com` 与 `google.com`（12 秒超时），所以拿不到收录量、点击量、真实用户的核心网页指标（CrUX）。报告里的速度结论来自我自己的 HTTP 计时，不是 Google 的实测面板。
2. **没有 Lighthouse 实验室分数**：这不是「跑过没通过」，是这套安装里没有 Lighthouse 运行器，所以没有 LCP / CLS / INP 的具体数值，只有「多久传完」这个更粗但更硬的读数。
3. **单点测量**：所有速度读数来自这一台电脑、这一条出口。建议从第二个地点（比如服务器上、或用第三方监测）复测一次，确认是「所有用户都慢」还是「只有我这条线慢」。
4. **没做排名与竞品**：DataForSEO、Firecrawl 这些扩展没装，所以这次没有关键词排名、没有竞品对比。
