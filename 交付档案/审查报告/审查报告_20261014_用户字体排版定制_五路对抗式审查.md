## §01 判定

**方向可做，链路有现成注入点，但"读字体"的正确来源与想的略有不同——权威源是 Photoshop 自己的字体清单（`app.fonts`），不是浏览器也不是裸扫字体目录。** 全链路上真正缺的只有三段：① 本机字体清单的运行时读取（目前只有离线工具链有）；② 用户界面与按语言持久化（目前完全没有）；③ 写回时应用字体/字距/行距（目前执行器一字不碰，字体全靠 PS 静默兜底——这正是历史"豆腐块"问题的土壤）。**开源侧 0 件可直接装**，可借的是交互形状与面板语言。试验版必须走"envelope 旁路、不进摘要"的轻路径，否则会撞上 `executionManifestDigest` 四层同步的合同面。

## §03 路一——链路事实（全部实测，file:line）

1. **v1.5 执行链三层**：浏览器 `prepare`（`src/lib/workbench/local-assistant-client.ts:1193-1215`，提交体含 translations/excludedLayerObjectIds/forcedBindings 等）→ 助手编译并运行（`download/local-assistant/v15-runner.js`）→ PS 薄执行器（`download/local-assistant/scripts/TYGF_V15_Thin_Executor.jsx`，v1.1.0）。
2. **注入点=envelope**：`v15-runner.js:193-199` 把 `{schemaVersion:1, executionManifestDigest, workingCopyPath, previewPath, manifest}` 原子写入 `execution-envelope.json`；执行器只校验其中 4 个字段（`Thin_Executor.jsx:81-83`）。⇒ **顶层加旁路字段向后兼容**（旧执行器忽略未知字段），且 `digest = computeExecutionManifestDigest(manifest)`（`v15-runner.js:144`）**只算 manifest**——旁路字段不进摘要。
3. **执行器现在完全不碰排版**：`Thin_Executor.jsx:107-126` 只做 选中图层→校验原文→写 contents→逐字符回读→保存。字体=原图层继承 + PS 自动兜底。经典路径脚本同样只**观测**字体：`MultiLangStudio_Replacer_v2.9-beta.jsx:1175-1194`（fontBefore/fontAfter 仅记录）、`:1432-1434`（fontChanged 标志）——文件名写 v2.9、内含 `SCRIPT_VERSION='2.12-beta'`（`:50`），服务端要求 2.12-beta（`server.js:100`）。
4. **字体枚举现状**：运行时零枚举。`download/local-assistant/glyph-coverage.js` 是纯函数（`:29` 建索引 / `:53` 解析 / `:111` 覆盖裁决），消费方**只有离线工具链**：`scripts/typography-census.mjs:18,64-66,197` 与 `scripts/smoke-glyph-coverage.mjs:13-17,101-122`（用 fontkit 读真字体文件）。执行链没有任何一个 JS 引用它。
5. **扫描器已采字体名**：`scripts/TYGF_V15_Preparation_Scanner.jsx:143`（`out.font = readStr(...)`）——每层字体名已在证据里，只是无人消费。
6. **本机字体清单想读取的现成时机**：readiness 扫描器（`scripts/TYGF_V15_Readiness_Scanner.jsx:3,47`，输出 observations）由助手 `runReadinessScan`（`server.js:5235-5298`）驱动——字体清单可同车或独立极小探针。
7. **存储模板现成**：`src/lib/workbench/decision-persistence.ts:38`（key `tygf:v15:decisions`、12h TTL `:30`、scanId+fingerprint+translationDigest 三重绑定 `:41-55`）——新设置照抄这个骨架即可，无需新建 Prisma model（试验期）。
8. **端点模式现成**：无票只读看 `/ping`（`server.js:4037`）；本地设置读写照 `/config`（`:4372-4386`）；浏览器侧统一走 `fetchLocal`（15s 超时，`local-assistant-client.ts:183-208`）；Origin 白名单是浏览器→助手唯一入口闸（`server.js:2236-2242`）。

## §04 路二——PS 端写回兼容（待实测三项，评审意见：先 spike 后动码）

**已知机制（前序审查件《PSD 原生改文字》已证）**：PS 按文字里的脚本切分样式 run 再逐脚本挑字体；原字体渲染不了目标语言时才补。⇒ 用户设置的字体对"多脚本混排层"的语义（只保证主 run？还是整层？）必须真机定死。

**spike 四问（一次手跑 jsx 即可回答，见执行方案 P0）**：

1. `app.fonts` 在目标 PS 版本返回的名字是显示名还是 PostScript 名（仓库内唯一先例：`diagnostics/Probe-LineTerminator.jsx:15` 用 `app.fonts[0].name`）——它必须能与 `textItem.font` 的接受值对齐。
2. `textItem.font / tracking / leading` 的可写性——尤其 **PS 2021**（历史教训：`#141` 记 PS 2021 严格 ES3、缺 `toISOString/trim` 直接报错 24）与**设置顺序**（先字体后 contents，还是先 contents 后字体？PS 写 contents 可能重切 run）。
3. **读回归一规则**：设进去 → 读回，值是否相等（显示名/PostScript 名归一后）。这是"设没设进去"唯一诚实判据（回读≠所设 ⇒ 显式 FONT_FALLBACK，不许静默）。
4. **缺字体时的行为**：设一个本机没有的字体名 → `textItem.font` 抛错、还是静默改回原值、还是 UB？——三种都要有报告字段承接。

**红线**：不得 faux bold 静默替代；不得自动缩小字号（前序方案《执行方案_20260920_排版质量》已否决"字号阶梯缩小=静默降级"）；设置失败必须显式失败码。

## §05 路三——开源复用裁决（2026-10-14 检索）

| 候选 | 事实 | 裁决 |
|---|---|---|
| `samuelmeuli/font-picker-react`（165★ MIT） | Google Fonts 专用，需 API key，最近发版 5 年前 | 不装：字体源错位（我们要本机 PS 字体） |
| `ae9is/react-fontpicker`（57★ MIT） | 1600+ Google 字体，SVG 预览图，免 key | 不装：同上；预览图机制与本机字体无关 |
| `wipeautcrafter/jsfontpicker` | 系统字体 + Google + 自定义 woff/ttf，模糊搜索、指标筛选 | **借形状**：列表/搜索/预览行的交互最接近；不直接装（仍是网页字体语境，且要接我们的清单源） |
| 浏览器 `Local Font Access API`（`queryLocalFonts`） | Chromium 独占、需权限弹窗、字体清单口径与 PS 不同（Adobe Fonts 不进浏览器） | 不作权威源：只可当兜底预览 |
| Adobe 官方 `ParagraphStyle`（UXP 文档，24.1+） | 段落面板全字段参考：justification / firstLineIndent / **kinsoku（日文禁则）/ mojikumi（日文文字组）** / spaceBefore/After | **界面与字段语言的参照基准**（尤其日语的"段落"到底有哪些旋钮） |
| Radix Themes / Control UI 排版 token | 字号/行距/字距成套 token 化思路 | 借鉴建模：用户设置=一组显式 token，不散落 |

**结论**：0 件可直接装。组件写起来不难（shadcn 已有 Select/Slider/Popover），难的是字体清单来源与写回语义——那两件没有开源件可替。

## §06 路四——治理与契约（红线清单）

1. **摘要冻结**：typography 若进 `manifest`（frozen contract）→ 动 `executionManifestDigest` → 浏览器投影/助手 evidence/服务端 verifyTicket/回执四层同步+fixture（`AGENTS.md` 合同变更纪律）。**试验版走 envelope 旁路，不进摘要**——这是把风险从"合同级"降到"本机级"的关键开关。
2. **版本纪律**：动 JSX 或助手 JS = 新助手版本（runtime 身份/安装包/release identity 全同步，worktree `AGENTS.md`）。试验版至少一次 bump，必须走下一班车，不偷步。
3. **不得静默降级**：设置没生效（读回不符）→ 显式失败/标志；`#66` 已证明"PS 静默替换+链路不检测=豆腐块无人知"的代价（`AI_MEMORY/ISSUES.md:641-648`）。本功能若不带回读判据，就是给 `#66` 再开一个入口。
4. **学习隐私边界**：本地证据**禁止 `fontName/fullFontName` 字段名**（`learning-evidence.js:33`）；字体清单是机器画像，试验版**只留本机**（浏览器显示用），不上云；将来上云需新同意位。
5. **L2 立项**：用户可见新行为 ⇒ `changes/active/*` + IN/OUT SCOPE + Acceptance，Owner 批准前默认 flag=false（Product Drift Guard）。
6. **学习库时机**：schema 注释写明学习 run"作为按用户定制的基础"（`prisma/schema.prisma:1322`），但 `rule-resolver` 生产零引用（全景 20261003 §D3）——试验版**不搭学习库**，P2 再接，避免把未接线子系统当承重墙。
7. **`#78` 保留事实**：交付判定链路不看字形可行性——试验版至少做到"回读 applied font 并上屏标志"，覆盖预检留 P2。

## §07 路五——产品与创收视角

- **真实需求**：日语（游明朝/思源系列的选择与字距）、品牌字体一致性、多语言营销图排版——都是"设计稿字体在目标语言里没字形/不协调"的延长线上需求。
- **创收载体已存在**：付费档位挂在现有套餐/积分体系；"品牌排版预设"可挂 `LearningBrandScope`（品牌域表已在 `prisma/schema.prisma:1162`）。
- **成本**：P0 半天（spike，零代码）；P1 约 2-3 个工作日（助手端点+执行器应用+网页面板+存储+报告标志+smoke）+ 一次真机验证。比"云端字体服务"便宜两个量级。
- **不做的**：字体文件分发/安装引导（法务与体积）；服务端字体授权代理——至少 P2 前不碰。

## §08 最后一句

这不是一个"缺前端组件"的功能，是一个**缺一段本机链路**的功能：字体清单怎么上桌（PS 自己最权威）、用户的定制怎么不下摘要地骑到写回那一刻（envelope 旁路）、写没写进去怎么证明（回读判据）。三件事各有一半现成——spike 半天就能把全部不确定性钉死；钉死之后再决定要不要发包。
