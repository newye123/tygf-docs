01判定

有条件放行

报告抓到了一个真问题：会话文件的 ACL 是按“用户名”授权的，不是按“当前进程的身份”。
但它把三件事判错了，还漏了一个更严重的放大器：读不到会话文件时，程序会拿默认配置覆盖它，并且先删掉最后一份好备份。

可以照单修的

  • BLK-1 / F-01：ACL 目标 SID 用裸 USERNAME 去解析，域账号与同名本地账号并存时会锁错人。源码确认，必须修。
  • MAJ-2 / F-03：官方 3.7.24 安装包实测 NotSigned；发布闸还有 --allow-unsigned-beta 绕过；卸载器没配签名。
  • MAJ-5 / F-05：收费门只认“等级字符串 + 非空摘要”，服务端不重算摘要。被改的客户端可以伪造 VERIFIED / FAILED，结算跟着走。

不能照单信的

  • MAJ-3 根因：说 journal“没有 fsync、没有重放”，源码里两样都有。真问题是 ACK 后把重放输入删了、把 journal 留着，导致已成功尝试被重新数成“未知”。
  • MAJ-4 未知：ticket 是一次性、短时、强绑定的，源码里写得很清楚。不需要再做黑盒重放实验。
  • MAJ-1 生产信任 dev：localhost:3000 是响应头回退值，不是放行条件。它是配置被 ACL 故障打回默认值后的症状。
  • MAJ-2 锚点自我抵消：本地身份文件确实可改，但代码签名也挡不住本机管理员改程序。签名照做，口径要收窄。

03报告说对了什么

F-01 · persisted-state.js:18-28 / 75-76

ACL 用名字而不是进程 token

Important

源码是 const user = process.env.USERNAME，然后 icacls file /inheritance:r /grant:r ${user}:F，stdio:'ignore'。在“域账号 + 同名本地账号”的机器上，名字解析可能命中本地账号；/grant:r 是替换语义，当前进程反而读不回文件。报告观测到的 PAIR_BOUND_LOCAL_AUTH_PERSISTENCE_FAILED 与这条链吻合。

边界：报告的 A/B 是黑盒观测（C 级），本次没有在客户机复现；但源码机制是 A 级，修法不依赖复现。

F-03 · publish-local-assistant.cjs:17 / 71-72；installer.iss

交付物没有代码签名，闸还能被绕过

Important

官方 3.7.24 安装包本会话实测 Status=NotSigned，SHA256 223F68D2…、25,519,666 B 与发布清单逐字一致；signatureStatus=UnsignedBeta。发布脚本带 --allow-unsigned-beta；installer.iss 没有 SignTool，也没有 SignedUninstaller。企业 EDR / SmartScreen 不信任、用户无法区分“厂商发的”和“别人重打包的”，都是这条的直接后果。

F-05 · execution-batch.ts:1384-1399

客户端持有判定，服务端不重算证据

Important

收费门只检查 verificationLevel === 'REOPEN_VERIFIED' 且 objectEvidenceDigest 是非空字符串；服务端没有用逐对象证据重算这个摘要（本文件的 createHash 只用于 rowSet 摘要）。被改的客户端可以伪造 VERIFIED / FAILED，结算跟着走。报告 MAJ-5 的方向对，但它把修法定成“整个判定权搬云端”的 L 级项；先做摘要重算，成本低得多。

04报告说错了什么

四条更正。第一条最重：它把“症状”写成了“根因”，如果照它重写 journal，会改错地方。

ID报告原话源码 / 实测新结论
C-01 MAJ-3 根因：“journal 写入与回执状态更新非幂等、无崩溃一致性（无 fsync 序 + 重放/裁决缺失）” execution-journal.js:96 有 fs.fsyncSync；server.js:4147 是 fsync + rename；server.js:4423 会从 journal 重建；execution-journal.js:148 有 reconcileUnfinishedJournals 根因不成立。真实问题是 ACK 后清理删了 .inputs.json、journal 留着；恢复时把已成功尝试误报为未知。不要重写 journal。
C-02 MAJ-4：“ticket 与会话的绑定关系未知”，建议做重放实验 execution-ticket.ts:94-179：HMAC、5 分钟（批次票 60 分钟）、n nonce、绑定 install / activation / job / attempt / origin；ticket/verify/route.ts 事务消费 nonce；只读操作 30 秒重放窗口 已关闭。一次性、短时、强绑定；不需要再做黑盒实验。
C-03 MAJ-1：“生产构建信任 dev 源” server.js:2606-2612 的 localhost:3000 是响应头回退值；server.js:2614-2620 的 isAllowedOrigin 对未知来源仍拒绝；只有 isLocalDevServer(cfg) 为真才放行 localhost，而这只在配置被打回默认值后成立 是症状，不是独立缺陷。修 F-02 + 打包版移除 dev 回退即可；报告提的“浏览器持有 device secret + 每请求 HMAC”按原样不可实现。
C-04 MAJ-2：“完整性锚点自我抵消”，应服务端签名下发、客户端仅验签 本地 release-identity.json 确实可改；但客户端的验签代码同样可被改 口径收窄签名用于分发 / EDR / 重打包；服务端签名清单可拒收摘要不匹配的回执，但不能替代服务端证据校验。
两处文本问题

① 验收项 TimeStallerCertificate 是错字，应为 TimeStamperCertificate；照抄会取到空值，造成假失败。② §2 要“统一明文/bytecode 强度”，§3 又说“不建议 bytecode 混淆”，自相矛盾；按 §3 执行。

05报告没看见的两个放大器

F-02 · server.js:738-755 / 8134 / 8171；persisted-state.js:68-70

读不到会话文件，不是停下来，而是覆盖它

Important

链路是这样的：loadConfig 读不到文件 → 返回默认配置（serverUrl 还是 http://localhost:3000）→ 启动时 ensureMachineId(loadConfig()) → 发现 machineId 与当前 MachineGuid 不同 → saveConfig → writeHiddenStateFile 先 removeFile(backupPath)，再把读不到的文件 renameSync 成 .bak，然后写默认配置。

后果：最后一份好备份被默认值覆盖；用户不是“这次要重新授权”，而是每次启动都可能把凭据和备份一起弄丢。报告把 BLK-1 写成“每次升级复发”，但漏了这条放大器——只修 ACL 不同时改这里，已有坏文件仍会被覆盖。

F-06 · release-identity.json:4；report-renderer.js:7；check-release-identity.cjs:121

报告自报的 buildId 不是 3.7.24 的

Important

报告写 3.7.24 + transport-hardening-20261011-r1；官方 3.7.24 是 in-app-folder-picker-20261023-r1。仓库记忆里，前者对应 3.7.15 / 3.7.19。三处出厂文件逐字一致，check-release-identity.cjs 还用正则钉住了这个值。

这意味着：报告的行为证据（24 条回执、CORS、自启覆盖）可能来自旧引擎；BLK-1 仍然有效（当前源码里有），但不能把旧版行为当成 3.7.24 的缺陷清单。

F-04 · server.js:4224-4228 / 4423-4474；v15-runner.js:1029-1033

24 条“状态未知”，主要是误报

报告看到症状，归因反了

ACK 之后只删 pending 与 .inputs.json，journal 回执永久保留；下次启动对“缺 inputs 的 journal”直接 unresolved += 1。每一个已成功送达的尝试，都会在下次重启时被重新数成 COMPLETION_UNKNOWN。报告的 N 序列 12→23→24 与成功批次数增长同形，这更像是累计噪声，不是 24 笔卡单。

但别急着删：先分类（已 ACK 成功 / 待重放 / 真未知），再决定数据修复；直接删会毁掉证据。

06整改方案

1

P0.5 先核对身份（5 分钟，阻塞其余）

curl.exe -s http://127.0.0.1:49152/ping
Get-Process | Where-Object { $_.ProcessName -match '图译工坊|tygf' } | Select-Object ProcessName, Path
Get-Content "$env:LOCALAPPDATA\Programs\图译工坊本地助手\release-identity.json"

期望：version=3.7.24、assistantBuildId=in-app-folder-picker-20261023-r1，进程路径在 %LOCALAPPDATA%\Programs\图译工坊本地助手。如果 buildId 是 transport-hardening-20261011-r1，报告审的是旧引擎；如果路径在 D:\…，这是复制安装，升级可能只更新了另一个目录。

2

P0-A ACL 改为“进程 token SID + 启动自愈”

  • 新增 currentUserSid()：绝对路径 %SystemRoot%\System32\whoami.exe /user /fo csv /nh，timeout 5s；失败再试 PowerShell WindowsIdentity；都失败就跳过 ACL 收紧并记 ACL_SID_UNAVAILABLE。
  • icacls.exe 用 *SID:F 形式，先授权、回读确认，再单独执行 /inheritance:r；任何一步失败都不会把当前用户锁在外面。
  • 启动时在读 loadConfig 之前，对 .tygf_session 和 .bak 各跑一次自愈；owner 有 WRITE_DAC，即使读被拒也能补回 ACE。
  • setHidden 同样改绝对路径 attrib.exe，加 timeout 和退出码日志。
  • 测试：扩展 scripts/smoke-local-assistant-state-persistence.mjs；静态断言源码里不再用 process.env.USERNAME 作为 ACL 目标；在临时文件上 icacls /findsid <当前 SID> 必须命中。

这是鉴权面，按治理需要 2 人复核。

3

P0-B 读不到就不覆盖；备份先立后破

  • loadConfig 返回状态：OK / MISSING / UNREADABLE / CORRUPT。只有 MISSING 才按首次启动处理。
  • UNREADABLE：先自愈并重读；仍不可读 → 打 CONFIG_UNREADABLE 后退出，不调用 ensureMachineId / saveConfig，不改任何文件。
  • CORRUPT：当前文件与 .bak 一起改名成 .corrupt-<时间戳> 保留证据，再按首次启动处理。
  • writeHiddenStateFile：新备份复制 + fsync + 原子改名成功之后，才替换旧 .bak；当前文件不可读就中止；当前文件损坏就另存 .corrupt-*，保持 .bak 不动。删掉现在这行“先删旧备份、再挪当前文件”。
  • 测试：模拟不可读 → .bak 哈希不变、没有新配置、日志有 CONFIG_UNREADABLE；恢复 ACL 后原授权还在。
4

P0-C 发布完整性：闸先闭合，证书再补

  • 生产发布移除 --allow-unsigned-beta；未签名只能走独立的 --beta 清单 / 目录，不更新生产下载页。
  • installer.iss 加 SignTool 与 SignedUninstaller=yes，覆盖 setup、内层引擎 exe、托盘 exe、unins000.exe 四件。
  • 证书采购现在启动（OV/EV 是外部周期）。代码闸本周能落，证书到位时间不承诺。
  • 验收：四件 Get-AuthenticodeSignature 全 Valid，TimeStamperCertificate 非空；不带 --beta 的未签名发布非零退出。
5

P0-D 回执恢复误报：ACK 后留“已结算”标记

  • removeAttemptReceiptArtifacts 删除 pending / inputs 之前，写 <attemptId>.acked.json；journal 回执继续保留作审计。
  • 恢复时先建 acked 集合，命中的跳过并单独计数；日志拆成 ACKED_SKIPPED=n 与 COMPLETION_UNKNOWN=m。
  • 对现有 24 条：不自动删、不自动重投；先跑只读分类脚本（已 ACK 成功 / 待重放 / 真未知），再出数据修复工单。
  • 验收：成功批次 → ACK → 重启，COMPLETION_UNKNOWN 不增；人为制造一条真未知仍被计为 1。
6

P1 服务端重算证据 + 打包版移除 dev 回退

  • P1-A：云端回执带逐对象证据（objectId / layerId / actualTextDigest），服务端用同一规范化重算摘要；不匹配 → 422 EVIDENCE_DIGEST_MISMATCH，不结算。负控：改一个对象、删一个对象都必须拒收。
  • P1-B：打包版 DEFAULT_CONFIG.serverUrl 用生产地址；getAllowedOrigin 不再回 localhost:3000；isLocalDevServer 在打包版恒为 false。
7

P2 判定权与暴露面（下一个大版本，不塞进 3.7.25）

先量化：当前有多少 REOPEN_VERIFIED 行是在“客户端自报、服务端没重算”的情况下结算的。如果答案是“全部”，P1-A 优先，P2 的“判定权回云端”往后放。客户端 JSX 保留为预检 / 展示；最终结论由服务端按原始证据计算。移除 C:\snapshot\… 这类构建路径字面量；保留中文错误文案；不做 bytecode / 加壳 / 反调试。

08不做清单

  • 不重写 journal 为两阶段提交。fsync + 原子改名 + 重放已经够用；真问题是 ACK 后的误报。重写风险大于收益。
  • 不做“浏览器持有 device secret + 每请求 HMAC”。浏览器无法对同机进程保守秘密；这会把“可伪造 Origin”换成“可读浏览器存储/内存”，还会破坏现有配对与一次性票链路。
  • 不做 bytecode / 加壳 / 反调试。报告 §3 自己也用实测说明收益低、代价高，还会伤自家可诊断性。
  • 不删除中文错误文案。用户和支持需要它；只移除泄漏构建路径的字面量。
  • 不在未确认客户机 buildId 前，按报告的 3.7.24 行为结论改代码。先做 P0.5。
  • 不自动删、不自动重投那 24 条。先分类，再出数据修复工单；删了就没证据了。
  • 不拆客户过渡件。等 ACL 修复在那台机器上连续重启验证通过，再用 tygf-assistant-patch.ps1 -Uninstall 一次性拆除并留回滚。修复前拆，等于把客户再推下去一次。
  • 不在自启值上做“存在即不覆盖”。报告 §5 的值名与 MIN-1 的“覆盖”说法对不上（U-03）；先取升级前后注册表快照，再决定改不改安装器。
