## 0. 一句话结论

**今天没有任何地方能看到「每天的访客」。** 原因不是缺工具，是三条路各自断在不同环节：官网一行统计代码都没埋；服务器日志有原始行但去不了重；Cloudflare 其实每天都在算访客，只是我们没把它接出来看。

对抗式审查后，我不建议现在装 Umami/Plausible/Matomo 任何一套（理由见 §2，其中 Umami 的既有草案含一处事实错误）。**最短路径是先花 1 小时把 Cloudflare 的只读分析接口每天拉成一行账**，零改前端、零新增常驻服务；本周把本来就卡着正式发布的 nginx 日志三件事一起修掉，那之后才谈得上"真实访客"。

## 2. 对抗式审查

### 2.1 先立尺子

评分：F 契合度 × E 上线省力 × C 数据可信度（各 1–5，分高好）。
四道硬闸，任一不过即出局，不看总分：

- **G1 隐私红线**：不新增境外处理方；新增处理方或**变更处理目的**须逐项登记《第三方处理方清单》并同步政策（`deploy/observability/README.md` §1；清单已登记 Cloudflare 用于"网络加速与安全防护"，`src/app/(zh)/privacy/subprocessors/page.tsx:52-57`，EN 版 `:61-66`）。
- **G2 资源红线**：生产机要求 **1 核 2G**（`deploy/部署三步走.md:5`），应用是 Next.js + nginx + **SQLite 单文件库**（`deploy/server-setup.sh:62` → `DATABASE_URL=file:${APP_DIR}/db/custom.db`）。任何新增常驻服务要自己算内存与备份账。
- **G3 泄漏面红线**：`?key=` 明文进访问日志是**卡正式发布**的已知案（O-01，`AI_MEMORY/ISSUES.md` #120 与 `总控/立案_F061_key口令进访问日志_20261007.md`）。凡把 URL/Referer 原样交给新统计系统，等于把这个泄漏面复制一份到新存储。
- **G4 口径可证伪**（我给自己加的）：产出的数字必须能说清"UV 按什么去重"，且不许把 API 调用、助手轮询、静态资源算成访客。说不清就不许用"访客"这个词。

### 2.3 我先砍掉我自己前两版方案（这才是对抗审查该审的对象）

- **第一版我本来要推"按 OBS-2 草案上 Umami"**——因为它是盘上已有的批准件，看起来最省事。三个口子砍穿：① 前提错（没有 Postgres 可复用）；② 1 核 2G 的机器上新增一个数据库引擎，等于给主站新增一种死法（备份、磁盘、OOM 全要多算一笔）；③ JS 统计对 AI 爬虫恒 0，而我们正在做 GEO/出海（`ai-crawler-log-report.mjs:3-4` 自己就写了这句）。
- **第二版我本来要推"自建一张 PageView 表"**——被 G3＋写锁面砍掉：这条路的"顺手"是把别人踩过的坑重踩一遍。
- **审查后留下最值钱的一条判断**：「每日访客」真正的阻塞不是缺工具，是**缺一条按日落账的账**。本仓已经证明过这件事——快照面画不出曲线（`UserActivityProjection` 只有 `lastActivityAt/lastRunAt`，`schema.prisma:100-121`），而跑得动的东西都是"一天一行 jsonl"那种形态（`总控/工具/northstar-ledger.jsonl`）。所以正确的产物形状是**一张每日运营账 + 一句飞书日报**，不是一块 Grafana 大屏。

## 4. 建议动作（按代价从低到高，三档）

### 档一 · 今天，0 改动，约 1 小时可验收

1. **你自己在 CF 控制台看一眼**：Analytics & Logs → HTTP requests / Domain，时间范围拉到 30 天（CF 2026-10-13 起**所有套餐含免费版至少保留 30 天**域名分析数据）。这是今天唯一"零成本就能看到的每日访客类读数"。我没有你的凭据，看不到这个数——**当前站内也没有任何地方存过它**。
2. 或者给我一个**只读 Analytics Token**（只放服务器 root-only 环境文件，禁止进仓库/文档，按密钥纪律），我做三件事：
   - `scripts/site-traffic-daily.mjs`：按 hostname 拉 `uniques / pageViews / requests` 每日一行；
   - 落 `总控/台账/运营日报_<日期>.jsonl`（一天一行，与 northstar 台账同形态）；
   - 接现有飞书日报通道，每天早上推一句人话：「昨天官网 X 个访客 / Y 次浏览，注册申请 N 条，激活 M 台」。
   - **验收判据（可复跑）**：同一时间窗跑两次结果幂等；字段名与取值以实测 JSON 回显为准，**没实测到的字段不写进口径**；脚本只输出聚合计数，不打印 IP/UA 原文（沿用 `ai-crawler-log-report.mjs` 的脱敏纪律）。

### 档二 · 本周，和发布闸同一批做

nginx 日志三件事（本来就已卡发布，不该为统计单独立项）：`log_format` 加 `$host` 与 `$request_time`、`?key=` 类参数脱敏（含 Referer 第二泄漏面）、`set_real_ip_from` CF 段 + `real_ip_header CF-Connecting-IP`。

做完这三件才有：分站能力、真实客户端 IP ⇒ UV 去重成立、AI 爬虫事实源、时延可测（现格式无 `$request_time`，时延一直测不了）。
**判据**：改后单行测得 `host` 非空、带 key 的 URI 里参数值为 `REDACTED`、出现非 CF 网段的客户端 IP；`nginx -t` rc=0 且两站都过一遍首页。
**风险提示**：该补丁动的是 `http` 块，**会同时影响生产与测试两站日志**（`deploy/nginx/security-logging.patch.md:138`）⇒ 需你明确授权，我不自行执行。

### 档三 · 等你拍过合规再动

- **CF Web Analytics（beacon）**：多拿"跳出/停留/UA 级访客"，但要改 CSP 一行（现 `script-src 'self' 'unsafe-inline'` 会拦掉外部 beacon）、Next.js 客户端路由需手动补 `track()`、且 CF **不记 query string ⇒ 拿不到 UTM**、暂不支持自定义事件。合规上属"处理目的变更"。
