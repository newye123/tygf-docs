## 1. F-1（Important，本次引入的"半修"）：闸门跳过了真正上送的 `translations[].rowId`

**失效场景**：用户表格的「记录编号」是中文 / 空格 / 全角符号（就是这次生产事故的种子形状）⇒ 浏览器拼出 `record:第一行` ⇒ 浏览器闸放行 ⇒ 助手编译成 `fragmentRowIds: ["record:第一行"]` ⇒ 清单白名单拒绝 `MANIFEST_FRAGMENT_ROWS_INVALID` ⇒ Photoshop 不启动、attempt 已建、取消/完成都点不动。**和修复前完全同形。**

证据链（全部 A 级，本会话实读 / 实跑）：

1. `c3e3247` 的闸只声明了四类字段，没有 `translations`：`git show c3e3247:src/lib/workbench/local-assistant-client.ts:92-97`。
2. 同文件 `:103` 的注释把错误前提写成了理由：*"translations[].rowId 助手不校——跨文档共用表里多出来的行、空译文行都带着不合形的编号今天照跑，拦它就是误伤（对抗审查 F-010）"*。
3. 同一错误前提被写进测试锁死：`c3e3247:scripts/smoke-row-id-whitelist.mjs:162-167` 用 `assert.doesNotThrow` 断言"仅出现在 translations 类字段里的不合形编号**不得**被拦"。
4. 助手根本不看这个注释：`download/local-assistant/generated/binding-core.js:1068` 与 `:1108` 都是 `fragmentRowIds: [translation.rowId]`，原样保留；多行拼接在 `:945`。
5. 清单校验是硬拒：`download/local-assistant/execution-manifest.js:9`（`/^[A-Za-z0-9][A-Za-z0-9._:-]{0,127}$/`）、`:168`（不合规即抛 `MANIFEST_FRAGMENT_ROWS_INVALID`）。
6. 本会话探针 `probe-gap-final`（`tmp/review-c3e3247/probe-gap-final.out`）：修后的浏览器闸输出 `BLOCK(EXECUTION_ROW_ID_UNSUPPORTED)`；助手侧同一输入仍编译出 `record:第一行`，清单仍 `REJECT(MANIFEST_FRAGMENT_ROWS_INVALID)`——证明这道闸是必需的，也证明被审版本放行了。

**处置（已落盘 `2c06da3`）**：闸扩到 `translations` / `translationsByLanguage` / `targetsByLanguage` 三类 `rowId`（`local-assistant-client.ts:99-127`）；测试把 (18)/(18b)/(18c) 从 `assert.doesNotThrow` 翻成 `assert.throws(..., EXECUTION_ROW_ID_UNSUPPORTED_CODE)`（`scripts/smoke-row-id-whitelist.mjs:176-185`），并新增 12c–12h 断言兜底编号的形态与稳定性。

## 2. F-2（Important）：错误码在浏览器两处 catch 里被丢掉，新码形同虚设

**失效场景**：就算闸在派发前拦下，用户与漏斗也拿不到原因码 —— 因为闸抛的是 `ExecutionRowIdError extends TypeError`（`row-identifier.ts:54`），而界面两处 catch 只认 `LocalAssistantRequestError`：

- 语言级：`execute-step.tsx:1310` `const code = error instanceof LocalAssistantRequestError ? error.code : null`
- 外层：`execute-step.tsx:2028-2031` 同样只认该类型

后果：`EXECUTION_ROW_ID_UNSUPPORTED` 在 `batch-error-policy.ts:53/196` 与 `funnel-event-contract.ts:115` 里登记的系统性 / 可上报分类**永远收不到这个码**，界面也落不到 `error-messages.ts:65` 的中文文案。

**处置（已落盘 `2c06da3`）**：在闸内把异常换成 `requestError(error.message, EXECUTION_ROW_ID_UNSUPPORTED_CODE)`（`local-assistant-client.ts:146`），保留原因文案、带上机读码；测试 (15)/(18)/(18b)/(18c)/(20)/(21) 逐条断言码。

## 3. F-3（Important，存量，同类卡点）：字距上限浏览器 10000、助手 9999

**失效场景**：用户把字距拉到 1000%（内部 10000‰em）⇒ 浏览器接受并持久化 ⇒ 助手校验器拒 `TYPOGRAPHY_INVALID / tracking-range`。这条与行标识是同一族：**浏览器放行、助手在冻结积分之后才拒**。

**处置（已落盘 `a75ce4d`）**：浏览器持久化上限改 9999（`typography-persistence.ts:53`）、面板输入 `max={9999}`（`typography-panel.tsx:498`）、输入换算夹紧到 `[-1000, 9999]`（`typography-capabilities.ts`），并在 `scripts/smoke-typography-picker.mjs` 增三条夹紧断言。
