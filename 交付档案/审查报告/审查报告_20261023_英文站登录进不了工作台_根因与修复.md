# 英文站「登录后进不了工作台」：根因与修复

**一句话：不是登录坏了，是英文用户被送去了中文登录页，而且英文首页根本不知道你已经登录。**

测试站已经换上修复后的版本（提交 `9f6f5a29`），可以复验。

## 你看到的现象，对应两个真问题

1. **英文工作台的「Log in」按钮指向中文登录页**。它写死了 `/auth/login?next=%2F%23workbench`——点下去进的是中文站登录页，登录完被扔进**中文工作台**。同一处的「邀请码注册」也指向中文 `/auth/register`。这段代码在英文站和中文站**共用**的组件里，英文站一直在替中文站的路由买单。
2. **英文首页的导航是静态的**。登录之后回到 `/en`，右上角仍然写着「Log in」，没有工作台入口、没有账号菜单、连退出登录都没有——看起来就像没登进去。中文站 2026-10-21 就修过同一件事（服务端注入会话 + 头像菜单），英文站当时没跟上。

## 现在改成什么样（和中文站同一套处理）

- 工作台账号门的登录链接：英文站 → `/en/auth/login?next=%2Fen%2Fworkbench`；中文站保持原样 `/auth/login?next=%2F%23workbench`。
- 英文首页改成**服务端注入会话**，导航按「已登录 / 状态未知 / 未登录」三种态渲染：已登录显示头像菜单（邮箱、Workbench、Log out），未登录才显示 Log in。
- 英文首页新增 **Workbench** 入口，指向 `/en/workbench`。
- 新增英文注册页 `/en/auth/register`（中文注册页的镜像：同一套接口、同一套错误分支、同样在本机写入激活记录），邀请码注册不再跳到中文页。
- 英文站没有的中文页面（设备与会话、积分包）**不显示入口**——宁可少一个入口，也不把你送回中文页。

## 顺带挖出并修掉的第三个问题

英文登录/注册/重置页原来直接把接口返回的 `message` 显示出来，而 `/api/auth/*` 的 message 是**中文原文**——输错密码会看到「邮箱或密码错误」。现在按错误码说英文：真浏览器实测提示为 **Wrong email or password.**，整页 0 中文。

## 验证（都是实跑，不是"应该"）

- 真浏览器全链路：未登录 `/en/workbench` → 点 Log in → 落到 `/en/auth/login?next=%2Fen%2Fworkbench`（英文页）→ 登录 → 回到 `/en/workbench`。
- 登录后回 `/en`：导航出现 Workbench + 头像；点头像菜单里的 Workbench 能直接进工作台；退出后留在 `/en` 并恢复 Log in。
- 中文站回归：`/` 导航仍是「工作台 / 登录 / 申请试跑」，中文工作台的登录链接仍是 `/auth/login?next=%2F%23workbench`，一处没变。
- 新增两道守卫：英文工作台必须用英文登录入口且 next 回英文工作台；英文页不得出现中文站路由；英文认证页不得直接渲染接口 message。对照实验：把关卡改回写死中文路径 ⇒ 门立刻红；还原 ⇒ 绿。
- 测试站实测：`.deploy-commit`＝`9f6f5a29…`，运行身份接口 BOUND 且提交号一致；`/`、`/en/workbench`、`/en/auth/register` 全部 200；线上 `/en` 首屏 24 条链接里中文站路由 **0 条**；三个常驻进程 online、重启 0、身份 ubuntu；数据库没动；回滚点 `deploy-20261023_214138-9f6f5a2960d0`。

## 还差什么（按该补的先后排）

1. **工作台「助手」相关的中文错误提示还有 135 处没接翻译**（`local-assistant-client.ts`）：断网、授权过期、报价失败、扫描超时这些分支，英文站走到就会露中文，而且很多是带数字的拼接句，靠词典命中不了。这是下一块最该收的口子。
2. **验证邮件链接仍是中文页**：服务端把链接写死 `/auth/verify`，英文站没有这个页。要真正修得让发信时带上语种（涉及认证代码，需要你点头再动）。
3. **设备与会话、积分包**：英文站没做，入口已隐藏。要的话我照中文站镜像一版。
4. 批量流程的深层分支仍要本机 Photoshop 真跑才能验。
