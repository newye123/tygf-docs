02被实测推翻的假设

1

「从 TASK_LOG 读条目、约百行脚本」严重低估

方案步 3 写「输入：TASK_LOG.md 条目……约百行」。实测该文件：

项实测
总条目数209
含「- **目标**」31（14.8%）
含「- **测试结果**」52（24.9%）
含「- **下一步**」7（3.3%）

⇒ TASK_LOG 是自由格式：字段名不统一，绝大多数条目根本没有这些结构字段。把 209 条异构文本解析成结构化行，不是百行的活，且格式会继续漂移——今天我刚写的新条目格式就与旧条目不同。

修正：不解析历史。改为「AI 收尾时直接产出一行结构化记录（追加 AI_MEMORY/ledger.jsonl），脚本只做 JSONL → 表格的搬运」，脚本确实只有几十行。历史 209 条不回溯。

2

「CLI 装好可复用 connector 授权」基本否定

原方案列为「待确认」，实测后应升级为「基本确定需重新登录」：WorkBuddy 的 connector 凭据存于 ~/.workbuddy-ai/connectors/<userId>/，该目录 README 自述「本目录包含 WorkBuddy 连接器的本地凭据」；connector-states.v3.json 的 connectors 键实测为 ["github","feishu"]，加密方案含 scheme/kdf/salt，密钥是本目录 .master.key。

⇒ connector 授权由 WorkBuddy 自己加密管理，与 lark-cli 的 auth 是两套独立存储。

修正：步 1 描述与耗时都改（10 分钟 → 15–20 分钟）。

3

「约半天」低估

拆解：装 CLI（含 Windows/权限/版本排错）＋ 建表（试模板、对字段）＋ 脚本 ＋ 改 AGENTS.md ＋ 验证与降级。

修正：1–2 天，且第一版应接受「半自动」（先手工触发，稳定后再接自动）。

03内部矛盾 · 最要紧

矛盾

「单向投影、git 为准」与表格里的「状态」列互相打架。

您要的正是「哪些做没做到什么地步」——您很可能想在表格里直接改状态。这正是多维表格的价值。但一旦人工改状态：表格就从「只读投影」变成「写入源」，「git 为准」失效；且与下一次投影互相覆盖（投影按 git 写回，会抹掉您的手改）。

选项甲 · 纯投影

  • 状态列只读；改状态必须回 git（改 TASK_LOG / ledger）。
  • 安全、无歧义；代价是您不能直接改。
  • 我的建议：选甲，但加一个例外——单独设一列「Owner 批注」（自由文本，只由您在表格里写，投影永不覆盖）。既保留您的输入通道，又不破坏「git 为准」。

选项乙 · 双写

  • 允许表格改状态，约定「表格状态优先，投影不回写状态列」。
  • 顺手；但表格与 git 分歧时无法自动判定谁对。
  • 与项目「不得静默降级」的精神有张力。

04遗漏 4 条

4

权限面变化没提示 安全

lark-cli 的授权身份是 user（插件配置 statusMatchJson.identity = "user"），不是 bot。而 connector 带 28 个 lark-* skill，其中包含 lark-mail、lark-drive、lark-doc、lark-calendar。

⇒ 装完 CLI 并扫码后，本机任何能执行命令的 AI 会话，都能读写您的飞书邮件、云盘、文档、日历。这是实质的权限边界扩大，而原方案只说了「凭据不进仓库」，完全没提这一层。

缓解：① 至少要让您知道；② 可考虑「用时登录、用完 auth logout」；③ 评估能否改用 --as bot（代价：bot 建的表您可能看不到，需另做分享）。

5

自动化 workflow 被一刀切掉 过度收缩

原方案问 8 写「不做仪表盘、不做甘特图、不做自动化 workflow」。但「状态变成『等您定』时自动推一条到飞书群」恰恰是您最需要的——您就不用天天打开表格看。我把它连同仪表盘一起砍掉，属于过度收缩。

修正：P0 保留一条最简自动化（状态 = 等您定 → 推群），其余不做。

6

BaseApp（应用模式）没提

lark-base skill 明确：BaseApp（AppMode）通过 Page 和组件组织 Base 数据，是应用界面，不是 Base 的别名。它可能比「裸表格」更贴合「打开就能看」。

修正：步 2 增加一步——评估 BaseApp 形态再决定。

7

任务 ID 从哪来没定义

原方案说「用稳定键（如 T-20261015-01）」，但没写谁生成、怎么保证唯一。多会话并行时两方可能生成同一个 ID。

修正：定义生成规则（日期 + 会话槽 + 序号），脚本里做去重校验。
