## 2. 第三轮两个红的定性

### 2.1 `test:refund-credit-provenance`（真问题，已修）

- 现象：`AssertionError: 账户缺失必须说清是缺失`，actual＝「订单积分来源或使用状态无法自动证明，已转人工审核」。
- 根因两层：
  1. **我上一轮（`840b03a`）写错了断言**：断在 `missingResult.message` 上，而 `refund-orders.ts:157` 的 message 按设计就是通用文案——那条断言**任何输入都过不了**（「上一轮已转绿」的会话摘要与事实不符，已按此教训改记忆纪律）。
  2. **真退化**：拒绝码合并成 `REFUND_CREDIT_PROVENANCE_MISMATCH` 时，「账户缺失 / 发放额不符」被并成同一句 reason，人工审核队列里分不清是哪种。
- 处置（`4e07c3d`）：
  - 源码：`inspectRefundCredit` 拆回两句 reason（精确区分只落 DB `reviewReason`；拒绝码仍合并、面向调用方的 message 仍保持通用）。
  - 测试：同时钉三个面——合并码 / 通用 message / DB `reviewReason` 精确措辞。

### 2.2 `test:seo-consistency`（一个目标选错 ＋ 一个真缺口，都已闭环）

**本地为什么恒红**：门禁里 sitemap / hreflang / og 全是绝对 URL，读的是 `SITE_URL`（默认 `https://tuyigf.com`），不是请求 Host ⇒ 对 localhost 目标必然 origin 不符。基线：172 PASS / 59 FAIL，FAIL 全是 origin 类。
**跑绿办法（实测）**：先 `SITE_URL=http://127.0.0.1:3078 node node_modules/next/dist/bin/next dev -p 3078`，再 `SEO_TARGET=http://127.0.0.1:3078 npm run test:seo-consistency` ⇒ 255 PASS / 0 FAIL / 0 SKIP。注意 dev server 必须用后台任务方式起（`nohup &` 会被连进程组杀掉，表现为全量 `FETCH_FAILED`）。

## 4. 环境侧发现（已写进记忆，长期有效）

1. **`next build` 挂在 "✓ Running next.config.ts" 之后、0% CPU、无输出无落盘 ⇒ 先查 `.next` 残留**：被 kill 的构建会留下 `start-server.js` 子进程继续持有 `.next`（**父进程被 kill 不死**，`mv .next` 直接 Permission denied）；`next dev`、standalone server 也留句柄。修法：按 CommandLine 杀掉该 worktree 全部 node 进程 → `mv .next .next.stale` + 空目录重建。清 cache / 换 webpack / 禁遥测 / 绕沙箱都无效。
2. **`timeout N npm run build` 至少给 1200s**：冷缓存 ~10 分钟（今天本机负载高时 30 分钟未完），热缓存 ~2 分钟；砍在 "Finalizing page optimization" 前会白跑一轮（standalone 后置步骤没执行）。
3. 本机 `.next` 目前是**不完整产物**（本轮 5 次构建尝试都超时）⇒ 下次用之前需重跑 `npm run build`，预期 30+ 分钟。
4. 上一轮遗留的 `next dev -p 3077`（10-18 12:06 起）已被停掉（它持有 `.next` 是构建挂死的原因之一）；如需要可重拉。
5. 端口 3000 的 standalone 服务已停（第三轮全量测试里 `seo-consistency` 之外无测试依赖它）。
