测试版「扫描总是不成功」：根因是本地助手被装成了管理员身份

对象：Owner 机器上的本地助手 3.7.28 ／ 测试站扫描链路 · 取证时刻 2026-10-27 16:0x–16:12 · 本机实测

结论：不是设计文件的问题，也不是 Photoshop 版本的问题。
助手以管理员身份运行（完整性级别 12288），Photoshop 以普通身份运行（8192）。Windows 不允许高权限程序控制低权限程序，所以助手每次去驱动 Photoshop 都被告知「不存在」，重试十轮、每轮约一分钟，12 分钟后报一个看不懂的错。

一、这对你意味着什么

  1. 扫描能力本身没坏。同一时刻、同一台机器、同一份 Photoshop，我用普通权限跑一条探针，一秒就连上（证据三）。
  2. 今天的表现是「卡 12 分钟再报错」。旧版助手不知道这两种权限不能互控，只会傻等重试。
  3. 旧版还会把你带偏。它把这种情况说成「Photoshop 没注册」建议重装 PS；另一条分支建议「以管理员身份运行修复工具」——正好是把问题钉死的方向。两处已改。
  4. 不是测试站独有的问题。任何用户只要助手是被提权安装、又被安装包自动拉起，都会一模一样地失败。

六、根因链

  1. 安装程序以管理员身份运行（安装包声明的是「最低权限」，说明这次它是被提权启动的）。
  2. 安装脚本最后一步「装完立即启动助手」把助手拉起来，子进程继承父进程的提权身份。
  3. 助手再拉起引擎，引擎同样是管理员身份。
  4. 引擎通过脚本创建 Photoshop 的 COM 对象 → Windows 拒绝 → 脚本只拿到笼统的 429 ActiveX 部件不能创建对象。
  5. 旧逻辑把 429 当成「没注册」并重试十轮 → 12 分钟后失败，给出一条指错方向的建议。

用户会看到的新文案：
本地助手当前以「管理员身份」运行，Photoshop 以普通权限运行，两者权限级别不一致，Windows 拒绝控制。请完全退出本地助手（右下角托盘图标右键 → 退出），再从开始菜单正常启动（不要选「以管理员身份运行」），然后重新扫描。
保险：若这台机器上 Photoshop 本来就是管理员启动的（两边同级），这条守卫会在「最近 10 分钟内成功握过手」时自动放行，不误伤。

八、还没做的

  • 把修复做成新版安装包：本机没有 Inno Setup，develop 树还有别的会话在改。出包要换构建机 + 代码签名 + 走 GitHub 三段轨。
  • 安装脚本的根治改动（候选，未改）：在「装完立即启动」那一行加「以原用户身份启动」，即使安装程序被提权，自动拉起的助手仍是普通身份。没直接改的原因：本机无编译器，改完无法编译验证——不验证就写进去属于「坏判据比没有判据更坏」。建议随下一版出包在构建机上改并实机验一次。
  • 旧指引：以前把「以管理员身份运行」当修 COM 的推荐做法，是这次事故的诱因之一。下载页／帮助文档里若还有类似指引应一起改（未核查，标「待确认」）。

九、现在要做的一件事：A 还是 B

A · 现在就恢复这台机器的扫描 一次操作

  • 屏幕上还有 Windows 的「是否允许此应用对你的设备进行更改」提示 ⇒ 点「是」。
    那个提示是我起的，只做一件事：关掉管理员身份的助手与引擎，再用普通身份重新拉起（脚本 %TEMP%\tygf-deelevate.ps1，结果写 %TEMP%\tygf-deelevate-result.txt 可回查）。
  • 提示已消失 ⇒ 右键托盘图标 →「退出本地助手」，再从开始菜单正常双击启动。
  • 恢复后我用探针复验：两个进程的完整性级别应回到 8192，/diagnostic 应返回 200 与 PHOTOSHOP_READY。

B · 把修复做成新版安装包给所有用户 需要构建机

  • 效果：新用户即使安装时用了管理员身份，助手也会在扫描前秒级给出正确指引；装到已出问题的机器上同样能立刻说清原因。
  • 代价：一台有 Inno Setup + 签名证书的机器，走 GitHub 三段轨（先推 GitHub → 测试站验 → 通过后再上生产）；生产上线需要你点头。

两件事不冲突：A 解决你眼前的扫描，B 解决别人以后踩同一个坑。

十、覆盖与未核实

  • 已实测：三组证据、失败史、门禁 42 条、语法检查。
  • 未核实：① 那次安装被提权的具体上下文（安装程序未留日志，只能由时间戳与清单反推）；② 下载页／帮助文档是否还留着「以管理员身份运行」的旧指引；③ 本机之外是否已有用户踩坑——新版助手发出去之前，可按 PHOTOSHOP_COM_UNAVAILABLE + 约 12 分钟耗时这两个特征反查历史批次。
