图译工坊（tygf）
PSD 多语言版本的生产线

目标：让接手的 AI 在 20 分钟内建立准确心智模型——有哪些能力、各自什么状态、改哪里会炸。不是营销材料，不能对外当宣传口径用。

先记住这四句

它是容器仓库 + 多 worktree。根目录只有记忆系统，真实代码在 worktrees/*；只允许改 worktrees/develop。

它不做机器翻译。吃的是用户自带的译文表；DeepSeek 只做文本清洗与双语对齐。

它不接管设计。默认不动字号/字距/行距/颜色/位置/对齐，只解决"塞不塞得下"；用户在面板上的显式设置是另一条路径。

设计稿不出本机。PSD/PSB 全程在用户电脑，云端只经手译文表与状态数据。

工作台工作流程 · 四步与闸门

阶段枚举唯一来源 src/lib/workbench/workbench-machine.ts:2-6；闸门是纯函数 deriveWorkbenchReadiness（:31-63）。

materials → translation_review → design_reconcile → delivery

reviewOpen           = translationCommitted
allLanguagesReviewed = 每个选中语言都有 digest，且 reviewedDigest === digest
reconcileOpen        = designReady && allLanguagesReviewed
reconcileComplete    = reconcileOpen && reconcileCurrent && reconcileReady
deliveryOpen         = reconcileComplete && photoshopReady
关键机制：语言级 digest 快照

审的是"某一版译文"，审完记下 reviewedDigest。译文一改 digest 就变，该语言立刻退回"未审"——这是防"审了 A 版、跑了 B 版"的唯一机制。任何改译文内容的代码路径都必须让 digest 变化，否则闸门失效。

UI 折叠、手动切步骤不影响 deliveryOpen——门禁只认这个纯函数。

步骤做什么硬约束
1 准备素材
materials		 选文件夹、导入译文表 取前 12 个 PSD；单表 5MB；最多 12 语种 / 300 行；多 sheet 未选中的全部进警告不静默丢；该屏常驻保活，卸载即断轮询
2 智能检测
translation_review		 洗表、对号、挑歧义 确定的自动做，拿不准的一律停；不得 0 warning 就跳步；不得静默应用
3 设计稿校对
design_reconcile		 对账（多行 / 缺译）+ PS 就绪检查 PS 就绪必须在这一步完成，不许拖到第 4 步（产品硬规定）
4 生成交付
delivery		 确认语言/文件名/位置/费用 → 真实执行 只负责确认与启动；产出 psd + jpg + report.html

一次执行的完整数据流

① 扫描（助手 → PS 只读扫描器）
      ↓ 文字层清单（原文/字体/字号/行数/对齐）
② 云端对账 + 智能检测（DeepSeek 只做对齐）
      ↓ 逐语言 digest（审完冻结）
③ 报价（标准行×语种）→ 冻结积分 → jobId
      ↓
④ 助手 prepare：绑定计划 + Readiness + attempt + 不可变清单（含排版偏好）
      ↓
⑤ 服务端签一次性票据（防重放窗口 + nonce 表）
      ↓
⑥ PS 瘦执行器：逐层「确认还是原来那层」→ 写文字 → 写排版 → 读回比对 → 保存
      ↓
⑦ 关闭再重开验证（确认真的持久化，不是内存假成功）
      ↓
⑧ 回执（脱敏）→ 结算（完成率 <95% 则比例 0）→ 本地报告 + 网页对账

每一步 fail-closed：任何一环拿不到凭据/对不上就停下报错，不静默降级（第一红线）。

十大子系统

01 · 只读扫描

PSD 预扫描 RUNNING

不改动设计稿一个字节，读出所有文字层信息交给云端对账。五个 PS 侧脚本：预扫描（嵌套组递归）、就绪检查、几何扫描、重开验证、字体清单导出。

为什么字体必须问 PS：本机目录扫出 1293 个字体、PS 认 1587 个，只重合 1235 个——扫目录会漏 352 个 PS 能用的、多给 58 个 PS 不认的（TYGF_Fonts_Probe.jsx:1-7）。

02 · 洗表对号

智能检测 + 双语对齐 RUNNING

检五类：技术元数据行 → 内部保留；同原文同译文重复 → 自动合并；同原文多译文 → 必须人选；AI 判的对齐异常 → 建议重排/丢孤儿/排除；对账问题 → 缺译、多行、原文变了、歧义等。

双语对齐：窗口化 DP 序列对齐，零 token 零写入，每行命运唯一——要么落地，要么显式标 DROP/FLAG/EXCLUDE，不允许静默消失。

AI 角色：DeepSeek 只做清洗与对齐（单次 ≤12 万字符 / ≤300 行），不做翻译；结果未知由管理员裁决，不自动重试。

03 · 排得下

译前版式适配 RUNNING（档①）

六条硬不变量：行数不变 · 只换行 · 行宽预算 · 合法断点 · 做不到就上报 · 可复现（逐字节）。

档位动作状态
① 换行按原稿行结构重排生效
② 连字符词内加 - 断行查无实现
③ +1 行需区域数据未生效
④ 缩字号自动缩小已排除
⑤ 扩区域—未做

例外清单只在四种情况出条目：估算超宽、写入行数少于原稿（结构缺陷必报）、无合法断点、字体兜底。BOXTEXT 不插换行，交给 PS 折行。

04 · 字体

字体与排版系统 RUNNING

写入链路保守到苛刻：只写 PostScript 脸名（写显示名会被 PS 静默换成 MyriadPro-Regular），写完立刻读回比对，不一致就记码上报。原则：宁可发不出去，也不发错。

偏好存本机 localStorage，不上传；每个字段标四态（可写 / 可写未接入 / 写不进 / 未实测），不假装全能。

有代码未接线：字形覆盖检查、版式几何（只测量不门禁）、DP 换行求解器、按源稿分组配字体。

05 · 可追溯

执行信任链 RUNNING

五段，每段 fail-closed：就绪 → 执行记录 → 一次性票据（防重放窗口 + nonce 表）→ 执行（逐层确认"还是原来那层" + 写 + 读回）→ 关闭重开验证。

跨来源防护：PS 扫描出来的稿交给引擎执行会被直接拒——凭记来源必须与执行通道一致。

06 · 免 PS

免 PS 引擎 扫描 GATED 写回 FROZEN

外挂独立 Rust 可执行文件（约 43.3 MB，随安装包出厂），助手用标准输入输出逐行驱动，改写图层级文字块与文档级字距块。

与 PS 并行，PS 优先：PS 在跑一定走 PS；只有"无 PS + 开关开 + 引擎哈希已固定"三条同时满足才走引擎，其余一律拒绝，禁止静默降级。

已跑通：175 层真稿保存成功、字距校验通过、175/175 层新文字、字节级与 PS 原件一致。

但写回是冻结的：写回链在助手里被负向断言钉死不许接，三个开关默认全关，现行产物 PS 打开尚未复核。对外只能说"免 PS 扫描，内测默认关"。

真实状态：只记录、不执行。采集在跑；聚合只能手动跑脚本（默认 dry-run）；规则解析器生产零引用且恒返回空建议。对真实执行影响恒为 0——这是刻意的安全设计，规则部署只准"影子"模式。

08 · 钱

计费与积分 RUNNING 支付 OFF

口径 = 标准行 × 语种：每行取原文与该语种译文里更长的一个，每满 200 字符 1 标准行（向上取整），单行单语种封顶 15。单次最低 20 分。50 行 × 12 语种 = 600 分。

一批一份报价、一次预留、一次结算；被忽略/未匹配行不计费。

结算门：结果不可用或完成率 < 95% → 结算比例 0（"做不出来就不收钱"的硬实现）。

积分：预冻结 → 按实际结算 → 失败释放，原子更新；冻结 10 分钟未结算可释放。内测分账 100 + 788 = 888 守恒上限。支付 6 个开关全 false。

红线与"不能说的话"

红线（违反即停）

  1. 不得静默降级；未完成能力必须明确报错。
  2. 不得从 develop 直接构建生产站；不得静默替换下载 URL。
  3. BATCH_EXECUTION_READY 保持 false，未获明确批准不得翻转。
  4. 助手行为变更必须走版本纪律（改 PS 脚本＝必须发版重装）。
  5. 生产支付开放须满足 checklist，缺一不可。
  6. 用户可见面不得展示后台实现（不写能力位、错误码解释、执行器、运营字段）。
  7. 禁止 git reset --hard / checkout -- . / clean -fd / restore . / force push。
  8. 发布走三段轨：先推 GitHub → 测试站从 GitHub 取 → 通过后生产从 GitHub 取。
