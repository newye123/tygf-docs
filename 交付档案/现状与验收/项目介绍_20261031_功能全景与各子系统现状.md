## 1 一句话说清产品

**把「同一份 PSD 要出 N 个语言版本」从"每个语言手工重排一遍"，变成"一次准备、批量替换、逐项核对、出交付包"。**

三条定位决定了它**不是**什么：

1. **不做机器翻译。** 用户自带译文表（供应商/翻译公司/自译）。官网首屏写"已有译文的多语言 PSD / PSB"（`src/config/siteContent.ts:867`）。DeepSeek 只做**文本清洗与双语对齐**（`src/lib/server/deepseek-align.ts:22` 的 `stage: 'text_clean_align' | 'ocr_clean_align'`），全库无"原文→译文"调用。
2. **不接管设计。** 字号/字距/行距/颜色/位置/对齐默认不动，只解决"译文塞不塞得进去"（`product-specs/typography-fit.md:8,19-24`）。用户可在面板显式覆盖（见 §4.4）。
3. **设计稿不出本机。** PSD/PSB 全程在用户电脑，云端只经手译文表与状态数据。

## 3 工作台工作流程（核心）

### 3.1 四步 + 闸门公式

阶段枚举**唯一来源**：`src/lib/workbench/workbench-machine.ts:2-6`

```
materials → translation_review → design_reconcile → delivery
```

闸门由纯函数 `deriveWorkbenchReadiness` 推导（`:31-63`），**公式如下**：

```js
reviewOpen           = translationCommitted                     // 译文表已提交
allLanguagesReviewed = 每个选中语言都有 digest，且 reviewedDigest === digest
reconcileOpen        = designReady && allLanguagesReviewed
reconcileComplete    = reconcileOpen && reconcileCurrent && reconcileReady
deliveryOpen         = reconcileComplete && photoshopReady      // PS 就绪是第 3 步的完成条件
```

**关键机制：语言级 digest 快照。** 审的是"某一版译文"（`languageDigests[lang]`），审完记下 `reviewedLanguageDigests[lang]`。**译文一改 digest 就变，该语言立刻退回"未审"**——这是防"审了 A 版、跑了 B 版"的唯一机制。任何改动译文内容的代码路径都必须让 digest 变化，否则闸门失效。

UI 折叠、手动切步骤**不影响** `deliveryOpen`——门禁只认这个纯函数（`:65-67` 注释明写）。

### 3.2 第 1 步 · 准备素材（materials）

| 动作 | 实现 | 约束 |
|---|---|---|
| 选文件夹 | `design-file-card.tsx:963` | 递归列 PSD/PSB，自然序取**前 12 个** |
| 导入译文表 | `src/lib/workbench/table-file.ts:15-33` | csv/tsv/txt/xlsx/xls，单文件 **5MB**；多 sheet 按交付物选，未选中的 sheet 全部进 warnings，**不静默丢** |

### 3.3 第 2 步 · 智能检测（translation_review）

**干什么**：把译文表洗干净、对上号，把有歧义的挑出来让人拍板。

**检五类**（`src/lib/workbench/smart-review-contract.ts:56-64,155-219`）：

| 情形 | 结论 |
|---|---|
| 技术元数据行（资源链接等不该翻的） | `INTERNAL_ONLY` |
| 同原文 + 同译文重复 | `AUTO_OPTIMIZED`（自动合并） |
| **同原文 + 多个不同译文** | `NEEDS_CONFIRMATION`（必须人选） |
| AI 判的对齐异常 | `REALIGN` / `DROP_ORPHAN` / `EXCLUDE` |
| 对账问题 | 缺译 / 多行 / 原文变了 / 重复原文 / 歧义 / 被合并 / 目标非法 |

**两维状态**：`category` 4 种（`NEEDS_CONFIRMATION / AUTO_CORRECTED / AUTO_OPTIMIZED / INTERNAL_ONLY`，`:3-7`）× `action` 4 种（`NO_CHANGE / AUTO_APPLY / REQUIRE_CONFIRMATION / BLOCK`，`:9-13`）。语言级 phase 6 种：未检测 / 排队中 / 检测中 / 已检测 / 失败 / **结果未知**（`workbench-terms.ts:73-141`）。

**双语对齐**（`src/lib/server/bilingual-align.ts:1-17`）：供应商双语表常见局部错位、孤儿重复行、真空缺、噪声行。用窗口化 DP 序列对齐，**零 token、零写入**，产出逐行命运唯一的修复计划——每行要么落地，要么显式标 DROP/FLAG/EXCLUDE，**不允许静默消失**。

**AI 用量护栏**：单次输入 ≤12 万字符 / ≤300 行（`deepseek-align.ts:17-18`）；一次逻辑动作一把幂等键，DB 只存摘要不存明文（`smart-review-gateway.ts:5-16`）；供应商结果未知时由管理员裁决，**不自动重试**（`smart-review-adjudication.ts:8-10`）。

**产品不变量**（`product-specs/smart-review.md:24-47`，SR-001~017）：其中 SR-002「不得 0 warning 就跳步」、SR-008「不静默应用」是红线。

### 3.4 第 3 步 · 设计稿校对（design_reconcile）

两件事，缺一不可：

**① 对账**：把"表格里多出来的行"和"设计稿里缺译文的对象"对上账。
- 阻断清单 + 覆盖统计：`readiness-board.tsx`
- 交付物矩阵（行=物料、列=语种）：`coverage-matrix.tsx`
- 阻断组按**跨语言去重**计数（`workbench-machine.ts:19` 的 `blockingIssueCount`，唯一聚合器口径）

**② Photoshop 就绪检查**：版本 / 连接 / 响应三态各一张明确状态卡（`product-specs/workbench-flow.md:24-30`）。
**PS 就绪必须在这一步完成，不许拖到第 4 步**——这是产品硬规定，不是实现细节。

### 3.5 第 4 步 · 生成交付（delivery）

只负责确认语言、文件名、保存位置、费用，然后启动真实执行（`workbench-view.tsx:6797`）。

**执行前必过的链**（`src/lib/workbench/local-assistant-client.ts:1860-1900`）：
1. `ensureAssistantBinding()` —— 助手绑定有效
2. `requireBoundWebRuntimeProvenance()` —— 运行身份可证
3. `confirmPhotoshopExecution()` —— **云端计费确认（冻结积分 → jobId）**
4. `POST /v1.5/execute/prepare` —— 唯一编译点：浏览器只提交冻结快照 + 译文行与决策，助手完成绑定编译、正式 Readiness、云端 attempt 创建、不可变清单组装

**产出三件套**：`psd` + `jpg` + `report.html`（`download/local-assistant/report-renderer.js`；当前 schema `local-report-v3` / renderer `renderer-v4`）。

### 3.6 一次执行的完整数据流

```
① 浏览器扫描（助手 → PS 只读扫描器）
      ↓ 文字层清单（原文/字体/字号/行数/对齐）
② 云端对账 + 智能检测（DeepSeek 只做对齐）
      ↓ 逐语言 digest（审完冻结）
③ 报价（标准行×语种）→ 冻结积分 → jobId
      ↓
④ 助手 prepare：编译绑定计划 + Readiness + attempt + 不可变清单（含 typography 偏好）
      ↓
⑤ 服务端签一次性票据（防重放窗口 + nonce 表）
      ↓
⑥ PS 瘦执行器：逐层「确认这层还是原来那层」→ 写文字 → 写排版 → 读回比对 → 保存
      ↓
⑦ 关闭再重开验证（确认改动真的持久化，不是内存假成功）
      ↓
⑧ 回执（脱敏）→ 结算（完成率 <95% 则结算比例 0）→ 本地报告 + 网页对账
```

**每一步都 fail-closed**：任何一环拿不到凭据/对不上，就停下报错，**不静默降级**（项目第一红线）。

### 4.4 字体与排版系统 —— `RUNNING`（面板 5 键）

**① 写入链路（保守到苛刻）**
- 只写 **PostScript 脸名**；写显示名会被 PS 静默换成 MyriadPro-Regular（`TYGF_V15_Thin_Executor.jsx:45`）。
- **写完立刻读回比对**，不一致记 `FONT_FALLBACK_APPLIED`，抛错记 `FONT_UNAVAILABLE`（`:62-71`）。原则：**宁可发不出去，也不发错**。

**② 用户面板（按语言设，存本机 localStorage，不上传）**
真正下发的 **5 个键**（`src/lib/workbench/typography-persistence.ts` 的 `toAssistantTypographyProfile`）：

| 键 | 含义 | 备注 |
|---|---|---|
| `face` | PostScript 脸名 | 空＝不改字体 |
| `size` | 字号 pt | **2026-10-31 加回**（见 §9） |
| `tracking` | 字距 ‰em | 0 是合法值，不能当"没设" |
| `leading` | 行距 | 只发 `fixed` 磅值；`percent` 本版不发 |
| `autoKerning` | 自动字距 | `METRICS` / `OPTICAL`；`follow` 不发 |

面板对每个字段标四态：可写 / 可写未接入 / 本版写不进 / 未实测（`typography-capabilities.ts:8-12`）——**不假装全能**。

### 4.5 执行信任链 —— `RUNNING`

**五段，每段 fail-closed**：readiness → attempt → ticket（一次性 + 防重放窗口 + nonce 表）→ execute（逐层 `expected_source` 校验 + 写 + 读回）→ reopen 验证。

配套件：执行清单/日志（`execution-manifest.js` / `execution-journal.js`）、工作副本（`working-copy.js`）、失败快照（`failure-snapshot.js`）、断点恢复（`/v1.5/recovery/acknowledge`）、回执脱敏（`receipts.js`）。

**跨来源防护**：PS 扫描出来的稿交给引擎执行会被拒（`pc-channel.js:97-112`）——凭记来源必须与执行通道一致。

### 4.6 免 PS 引擎 —— `FROZEN`（写回）／`GATED`（扫描）

**技术路线**：外挂独立 Rust 可执行文件（`tygf-engine.exe`，约 43.3 MB，随安装包出厂，`build/vendor/photocraft/BUILD-MANIFEST.txt:5-9`）。助手用 stdin/stdout 逐行 JSON-RPC 驱动：`doc.open` / `doc.inspect` / `type.info` / `type.edit` / `doc.save` / `doc.close`（`pc-executor.js:118-125,211,234,409,431`）。改写图层级 `TySh` 与文档级 `Txt2`。

**与 PS 的关系：并行，PS 优先**。PS 在跑一定走 PS；只有"无 PS + 开关开 + 引擎哈希已固定"三条同时满足才走引擎；其余 `refuse`，禁止静默降级（`pc-channel.js:87-94`）。

**三个开关**：`pcExecutorEnabled` / `pcExePath` / `pcExeSha256`（`server.js:820-823`），**默认全关**。只能脚本开（`scripts/pc-enable-on-machine.cjs`），无界面入口。

**已跑通的证据**：2026-10-20 PS 22.0 真机 12/12；2026-10-24 175 层真稿 `SAVE_SUCCEEDED` 34.3s、`kerningCensus {"Optical":175}`、`Txt2` 175/175 新文；字节级与 PS 原件一致（`pc-executor.js:441-443`）。

**为什么仍冻结**：三个 P0（#6968 写回后 PS 打开即崩、#6971 文档级 `Txt2` 未同步、#6129 TySh 重建丢字段）中 #6968 的现行产物**尚未用 PS 复验**；且写回链在 `server.js` 被**负向断言钉死不许接**（`smoke-pc-wiring-freeze.mjs:59-67`，`runPhotoCraftExecutor` 引用数 0）。

⇒ **对外只能说"免 PS 扫描（内测、默认关）"，不能说"支持免 PS 写回"。**

### 4.7 学习系统 —— `RUNNING`（采集）／`CODE_ONLY`（规则）

**做什么**：记录"系统建议了什么 → 用户改成了什么 → 结果验证没有"，攒脱敏证据，将来把常见决策变成规则。

**六段证据**：`before` / `proposal` / `action` / `correction` / `final` / `verification`（`src/lib/learning/contracts.ts:5-6`）。10 类决策族实采前 4 类；动作码 5 个；特征白名单**只有 15 个键**（`privacy-reducer.ts:19-35`）。

**四级作用域（就是"个人库/公共库"）**：

| 作用域 | scopeKey | 中文叫法 | 晋级门槛 |
|---|---|---|---|
| personal | `user:<id>` | 个人经验 | 5 任务 / 90% 接受率 |
| template | `tpl:<指纹>` | 同模板经验 | 逐级抬升 |
| brand | `brand:<id>` | 同品牌经验 | 逐级抬升 |
| public | `public` | 公共经验 | 10 品牌 / 50 用户 / 200 次验证 + 30 天影子期 |

**隐私三层闸**：consent-gate（无同意不记，fail-closed）→ privacy-reducer（白名单 + 值级扫描）→ forbidden-field-scanner（字段名与值双黑名单，递归任意层级）。服务端再拦一次（`signal-validator.ts:63-215`）。

**当前真实状态（必须照实说）**：

| 环节 | 状态 |
|---|---|
| 采集 | **在跑**（注册自动同意，前端 4 个采集点，执行成功后批量上报） |
| 聚合 | **手动**（只能跑脚本，默认 dry-run，需 `--apply` 写库） |
| 规则消费 | **零**（`rule-resolver.ts` 生产零引用，且恒返回 `mode: recorded_only, suggestions: []`） |
| 对执行的影响 | **恒为 0** |

这是**刻意的安全设计**：规则部署只准 shadow，`suggestion`/`active` 直接被拒（`api/admin/learning/candidates/[id]/deploy/route.ts:22`）。

### 4.8 计费与积分 —— `RUNNING`；支付 `OFF`

**计费口径 = 标准行 × 语种**：每行取 max(归一化原文, 该语种译文) 字符数，每满 200 字符 1 标准行（向上取整），单行单语种封顶 15（`src/lib/billing/rules.ts:6-8,119-132`）。单次最低 20 分；审查解锁阶梯 40/80/160；50 行 × 12 语种 = **600 分**（`batch-v3.ts:1-6`）。

**批次原则**：一批一份报价、一次预留、一次结算；语言子任务不得二次报价；被忽略/未匹配行不计费（`billing-scope.ts:1-7`）。

**结算门**：结果不可用或完成率 **< 0.95 → 结算比例 0**（`rules.ts:190-197`）——"做不出来就不收钱"的硬实现。

**积分**：预冻结 → 按实际结算 → 失败释放，SQL 条件更新保证原子；冻结 10 分钟未结算可释放。内测分账：注册 100 + 内测专属 788 = **888 守恒上限**，已有 ≥888 不再补。

**支付 6 个开关全 false**（`src/config/featureFlags.ts:26-33`）：`creditPacksEnabled` / `manualPaymentConfirmationEnabled` / `alipayPaymentsEnabled` / `alipayCloseEnabled` / `alipayRefundEnabled` / `manualQrFallbackEnabled`。

### 8.1 改排版字段的连带影响（踩过）

改一个字段要同步 **6 处**，漏一处就出"界面说会发、实际没发"或"保存即丢"：

1. 助手白名单 `typography-profile.js`（`ALLOWED_KEYS` / `LOCKED_KEYS` / 范围校验 / `fieldsTouched`）

3. 浏览器形状与映射 `typography-persistence.ts`（`TypographyProfile` / `AssistantTypographyProfile` / 校验 / **归一必须显式补键**）
4. 能力表与结算 `typography-capabilities.ts`（`SEND_PROBE` / `CHAR_ROWS` / `buildSettlement`）
5. 面板控件 `typography-panel.tsx`（`EMPTY_PROFILE` / `hasValue` / `charControl`）
6. 测试 4 个 smoke + 1 个 vitest（含**负向断言**，撤下的字段有守卫不许回潮）

⚠️ **归一函数漏键 = 保存永远失败**：`saveTypographyProfiles` 是"落盘后读回比对"才报成功，`validateTypographyProfilesByLanguage` 的 `normalized` 少一个键，读回值与存盘值就不等。
