# 英文站工作台：登录之后，四步界面已经没有中文字了

日期：2026-10-23　提交：`14b0dfd4`（仅本地，未推、未部署）

## 一句话结论

用英文站登录进去以后，工作台四步（准备素材 / 智能检测 / 设计稿校对 / 生成交付）界面全部是英文，逐步实测中文残留 0 字；而在这之前，第 1 步一屏就有 **277 个中文字**。

## 这对你意味着什么

- 之前我说"英文站已经能用了"，依据是**数首屏有没有中文**。这个尺子是错的：它只能看到当前能走到的画面，且只数一次。
- 这次换了判据：**用语法树静态查 + 用真账号登录后逐步点**。一换就露出三类漏洞，而且它们**一个都不会报错**——不崩、不弹错、日志干净，只是界面继续显示中文。
- 现在"登录后走到第 1~4 步"这条路是干净的、有截图为证；但还不能说"英文站没有中文了"：静态扫描显示还有 **325 处**中文藏在"扫过 PSD 之后才走得到"的分支里。英文用户真跑流程时会碰到，这是下一步。

## 三类漏洞，各是什么

**一、写在组件外面的翻译，会在程序启动那一刻就被定死。**
工作台的"草稿状态徽章"（等待 Photoshop / 扫描中 / 已扫描 …）的文案写在一张模块级常量表里，翻译函数也是在那张表里调用的。程序一加载就把它们算成中文并固定下来——那时语言还没切到英文。结果：徽章永远是中文。改法：表里只放中文原文，等真正渲染时再翻译。

**二、整个工作台的大段文案来自后台文案表，没经过翻译。**
第 1 步的"导入表格 / 粘贴文本 / 选择或拖入表格文件 / 表格格式说明…"这些不是写死在组件里的，而是从站点文案（后台可改的那份）取的。我之前只包了十来个直接引用点，剩下 223 条全部绕过翻译层，所以第 1 步整屏中文。改法：在文案**出口**（一个函数）统一翻一次，一处覆盖所有取用的地方——比逐个调用点改安全，也不会漏。

**三、术语表和报错消息是拼出来的中文。**
"重新检测""重新扫描"这类按钮文字来自术语表；"解决必须处理项后开放"这类锁定原因来自状态机；"无法连接本地助手（http://127.0.0.1:49152）…"是把本机地址拼进中文句子里。改法：术语表改成"取值时才翻译"（不是加载时算好），状态机的原因文案接上翻译层，带地址的那句改成带占位符的翻译模板。

## 真实读数（不是静态判断）

- 测试方式：隔离测试库（20 条迁移、种子邀请码、已验邮箱的测试账号），真登录，真点四个步骤。
- 中文残留：第 1 步 277 → **0**；四步依次 **0 / 0 / 0 / 0**；页面无 JS 报错。
- 词典：662 → 898 条；组件里所有 `t()` 键 **659/659 = 100%** 有英文。
- 自动检查：`tsc` 0 错；eslint 本轮 8 个文件 0 错；英文工作台 10 条断言、英文首页布局 61 条、工作台 UI 合同、用户可见文案 48 条，全部通过。
- 新增两道永久守卫：① 禁止在组件外调用翻译函数 + 词典不许有缺口（进 CI 断言）；② 扫描"还没被翻译包住的中文"，作为余量刻度。
- 中文站未受影响：翻译函数在中文下原样返回同一字符串；中文外壳显式声明中文语言，不再依赖"中英文是两套页面所以整页刷新"这种框架行为。
