01结论

给 Owner 的一句话

长期方案的代码侧齐了：装一条命令、跑一次冒烟，测试站的「站点流量」板就会每天自己长出数。
做的时候撞出一件必须提前讲的事——不在服务器上显式指定数据文件位置，面板就会永远空着，哪怕定时器天天成功。

为什么"永远空着"（这条是设计后果，不是 bug）

发布打包规则把我们的内部账本目录整个排除在包外（.gitattributes:7，AI_MEMORY/ export-ignore）。而面板缺省就是去那个目录找数据文件。所以服务器上必须用 TYGF_TRAFFIC_LEDGER 把路径指到发布时不会被删的状态目录——这一步不是可选优化，是面板能不能出数的前提。安装脚本现在会强制检查它，没配好就不许装。

02剩下的三条命令（已投队列，等一只到得了测试站的手）

步命令为什么这么设计
① sudo install -m 0600 /dev/null /etc/tygf-site-traffic.env
再写入 CF_ANALYTICS_API_TOKEN／CF_ZONE_ID		 令牌只落这一枚 root-only 文件，不进应用环境文件、不进仓库、不进任何文档；单元里用不带 - 的 EnvironmentFile——缺文件就让单元判红，不许"今天静默没数"。
② TYGF_TRAFFIC_LEDGER=/var/www/tygf-test-state/traffic-daily.jsonl 写进 /var/www/tygf-test/.env 写侧与读侧同源（本轮把采集脚本的缺省路径也改成先认这个键）。路径落在状态目录：候选目录会被删，状态目录不会。安装脚本还会验它确实在状态目录下。
③ sudo -n bash deploy/install-test-timers.sh tygf-test-site-traffic 前置校验四件事（文件在／权限 0600／两键非空／台账在状态目录），任一不满足拒绝安装；装完 systemctl start 当场冒烟并核台账行数与末行日期。病根：本仓有过"定时器路径写错连红七周、清理其实一直没跑"的先例。

03本轮改了什么

两个单元模板（新增）

deploy/tygf-test-site-traffic.service ＋ .timer。沿用同族既有形状：路径一律占位符（@APP_DIR@／@NODE_BIN@，本轮新增 @STATE_DIR@），由安装脚本从 deploy-test-release.sh 推导后渲染，模板里不出现任何手写绝对路径。定时用 OnCalendar ＋ Persistent=true：同族旧写法是相对定时，机器停几天就少几天数。

安装脚本（加固）

状态目录从 SUPPORT_BUNDLE_DIR 取父目录（唯一权威源）；请求本单元时走四道前置校验；渲染后仍由 check-unit-paths.sh 验路径存在性；末尾新增"当场跑一次并核台账落盘"。缺令牌文件时 fail 并给出建文件的确切命令，不打印任何值。

采集脚本（同源）

缺省输出路径改为先认 TYGF_TRAFFIC_LEDGER。此前写侧只认 --out、读侧只认这个环境变量，两边不同源——在服务器上就是"写进状态目录、面板去应用目录读旧文件"。
