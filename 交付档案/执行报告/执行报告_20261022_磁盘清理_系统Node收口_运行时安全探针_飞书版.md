# 磁盘清理 ＋ 系统 Node 收口 ＋ 安全探针（2026-10-22 下午执行报告）

**三件事都办完了，您不用做任何事。**

一是磁盘。这台服务器原来只剩 4.9G 可用（88% 满），现在剩 12G（69% 满），清出 7.1G。顺手治了根：系统日志加了 200M 上限，以后不会悄悄涨回去。

二是那个"停止维护还在干活"的 Node。上午登记的问题——系统自带的 Node 20 官方已经不再发安全补丁，而 PM2 管理进程和测试站一枚定时任务还在用它。现在系统 Node 升到 22.23.4，跟业务用的完全同一个版本、同一个模块接口编号，敞口没了。

三是把那两次"您看到新闻才让我查"换成一条命令。新写了一枚探针，跑一下给退出码：0 是干净、1 是有事要办、2 是探针自己坏了。它查九项，包括去官方发行索引看有没有出安全新版。已经跑通，并且验过它真的会红（不是永远绿的假门）。

## 磁盘删了哪些，凭什么敢删

我给自己定的规矩是：能证明它是垃圾才删，删之前先跑一遍"只列不删"的预演，两份清单都留在服务器上。

删掉的：测试站两枚 10 月 21 日的部署失败候选（3.0G）——它们是失败尝试留下的半成品，不是回滚点，真正的回滚点我一枚没碰；第三代生产发布目录（1.7G）——只保留最新两代，删之前查过没有任何服务或站点配置引用它，代码在 git 里随时能重建；七枚超过七天的上传安装包（1.83G）——只删包体，收据全部留着，现役那两个版本的包按名字保留；一个名字里就写着 stale 的残件和三个部署暂存目录（151M）——暂存目录逐枚查过不含数据库、不含环境配置才删；系统日志收到 195.6M（省 505M）；apt 包缓存。

有意没删的，也写清楚，免得下一位以为漏了：npm 缓存 3.9G 看着最好删，但实测两枚缓存这个月都还在被写，而两条部署链都要跑依赖安装——清了下次部署就得重新下载整套依赖，为 3.9G 换部署变慢不值。生产状态目录里那 1.6G 要先验证是不是死重量，本轮不猜。数据库历史快照 418M 属证据。测试站的回滚点 1.8G 是另一个会话中午刚用的，不碰。旧内核和两枚交换文件（一共 6G）是回滚手段和这台只有 1.9G 内存的服务器的构建兜底，留着。

## 系统 Node 这一步，我把两跤如实写出来

第一跤：脚本第一次跑的时候，我用普通用户身份执行，而日志目录只有 root 能写，写日志被拒，脚本误以为升级失败，自动把配置还原了。结果是盘上什么都没变——这一跤反而证明我写的自动回滚是真能跑的。

第二跤更难看：第二次跑，五项健康检查全部通过（新版本、包管理器、PM2 版本、两个站点都返回 200、三个应用都在线），但我把判断的返回值极性写反了——命令行里 0 才代表通过，我用 1 代表通过——于是脚本把一次成功的升级判成失败，按预案自动降回了旧版本。升级被我自己的 bug 回滚了一次。

改对之后，我先做了一件该早点做的事：在还是旧版本的机器上单跑这道门，确认它会红。门能红，它给的绿才有意义。第三次跑通过。

现在的实测状态：系统 Node 22.23.4、业务 Node 22.23.4，模块接口编号同为 127；两个站点本机访问都是 200、身份校验都是 BOUND；公网访问生产站首页和下载页都是 200；PM2 守护进程已经在新二进制上；失败的服务还是只有一枚，就是中午那枚存量问题。那枚对账任务在升级之后报的还是同一句 403，说明运行时切换没有改变它的毛病——它是另一件事，我没顺手修。

留一个尾巴要告诉您：这台机器上现在有两个 Node 安装通道（系统包管理器装的，和我们自己装的目录）。版本此刻一致，但通道不一致，以后只升一个就会重新漂移。要么把业务也收到系统包通道，要么把那枚单元指到我们自己的目录。这是又一次生产改动，而且方向该您认，所以我没做。

回滚路径也实测过：备份的配置文件拷回去、重装旧版本号、重启 PM2 就行——这条链今天被我自己那两跤真实跑通了两次。

## 探针查什么

一条命令跑九项：业务运行时和系统运行时的版本、模块接口编号有没有变、待装安全包数量（按安全源那一栏数，不拿"全部待装"糊过去）、自动更新是不是真的还允许安全源、自动重启是不是关着、失败服务数量对不对基线、磁盘可用率，以及去官方发行索引看这条版本线有没有更新版——如果是安全版就判红，普通版只提醒。

判据集中在一个基线文件里，改它就是改闸，所以文件里每一条都写了出处。

实测两遍：正常跑全绿，只有一条提醒（tmux 被 Ubuntu 官方按批次灰度推送，不是安全项，没强推）；负控跑是把基线门槛临时抬到一个不存在的版本，它立刻报两条红、退出码 1，然后我按备份还原，文件哈希一致。

有一件故意没做：没有把它接进每天早上的控制面检查或服务器定时任务，因为那是别的会话的写面。要接就加一行，等您点头。

## 边界

磁盘还有 6G 级的可换空间，但每一块都带代价，要更多空间就按上面那张"有意没删"的清单逐条拍。双安装通道的漂移风险还在。探针只覆盖这一台服务器，而且它只判版本水位，不判"某个漏洞是否真的走到我们的调用路径上"。测试站那枚 403 存量问题未修。本轮全部改动都在运维层：没碰业务代码、没碰数据库、没碰支付开关、没推远端。
