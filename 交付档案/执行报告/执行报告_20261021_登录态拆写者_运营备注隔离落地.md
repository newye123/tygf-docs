- 执行日期：2026-10-21 12:50

## 1. 结论

**泄漏闭环了**：后台运营备注（`BetaUser.name`）不再流到用户界面，也不再随身份接口下发到浏览器。**用户可自设昵称按 Owner 定调未做**；**问题 B（登录后首页仍显示"登录"）不在本轮范围，也未做**。

一句话机制：过去`name` 一个字段被**两个写者**抢——用户申请时填的自报姓名，和运营写进"姓名 / 运营备注名"框里的内部备注。运营之所以要抢这一格，是因为**所有后台用户资料载荷都过隐私守卫 `assertSafeUserProfile`，而守卫把 `adminNote` 列为禁键**（`src/lib/admin/user-profile-contract.ts:14`）——"用户资料载荷里不许混运营内部备注"这条契约早就存在，运营手里却没有"备注"这一格可用，只好拿 `name` 顶替。这次是给运营备注**补一个合规的独立通道**，而不是去动那条契约。

## 2. 改了什么

### 用户端（切断泄漏）

| 位置 | 改前 | 改后 |
|---|---|---|
| `src/app/api/auth/me/route.ts:19-27` | 回 `{betaUserId,email,name,emailVerified,accountStatus,sessionId}` | 只回 `{email,emailVerified,accountStatus}`；并在 §7.4 注释旁写明"**`name` 属运营字段，不得下发**" |
| `src/app/api/auth/login/route.ts:114-122` | 登录响应带 `name` | 去掉 `name` |
| `src/lib/auth/services/login-user.ts:69-76` | 服务层结果回 `name` | 去掉 `name`（**结构上防复发**：有人再转发也带不出去） |
| `src/components/workbench/user-account-menu.tsx:76-81` | 显示名优先取 `me.name` | 显示名＝邮箱本地部分；文件头注释与实现对齐 |
| `src/app/(zh)/auth/sessions/page.tsx:71-74,173` | 携带 `me.name`（只存不显示） | 不再携带 |

### 运营端（拆写者：用户自报姓名 vs 运营内部备注）

- `src/app/api/admin/users/[id]/route.ts:583-624`：`update_profile` **不再写 `name`**；若请求带了与库内不同的 `name`，返回 **409 `ADMIN_USER_NAME_READONLY`** 并点名"用户姓名由用户在申请时填写，运营不可改写；运营备注请写'运营备注'栏"——**不静默忽略**。校验从"姓名和联系方式不能为空"改为"联系方式不能为空"。
- **新增** `src/app/api/admin/users/[id]/operator-note/route.ts`：运营备注的独立通道（`GET` 读 + `PATCH` 写），owner 限定（`requireOwnerDb`），写操作审计 `user.update_operator_note`，**唯一写者**（`update_profile` 一概不碰 `adminNote`）。
- `src/lib/admin/client.ts:589-601`：新增 `getOperatorNote` / `updateOperatorNote`。
- 两个后台界面（装机列表 `installs-credits-panel.tsx:472-520`、360° 详情 `user-detail-panel.tsx:850-920`）拆成两块：**「用户姓名（只读）」**（灰底只读框 + "用户在申请表里填写，运营不能改"提示）＋ **「运营备注（仅后台可见）」**（独立 Textarea + 独立保存按钮 + "只保存在运营侧，绝不下发到用户界面；认人请用邮箱 + 用户 ID"）。

### 护栏

- **新增** `scripts/smoke-auth-session-shape.mjs`（**26 项**源码契约）：身份接口键集合、登录/服务层不带 `name`、三个消费者不消费 `name`、运营改姓名有 409 闸、写库块不含 `name`、备注唯一写者、两个用户资料载荷仍不带 `adminNote` 且仍过隐私守卫、契约仍禁 `adminnote`；**含两条负控**（给探测器喂坏源码，确认能抓到——证明断言不是假绿）。
- **新增** `scripts/smoke-auth-session-runtime.mjs`（**12 项**运行时验证）：隔离库真建用户（`name` 故意写成"王先生 / 已付尾款"这种脏值）、真发会话、真调路由——`/api/auth/me` 键集合恰为四键且不含脏值；运营改姓名→409 且不落库；资料保存不写 `adminNote`；备注经独立通道写入并原样读回；360° 详情载荷不含 `adminNote`；**写完备注后再取用户端接口仍无备注**。
- `scripts/smoke-admin-security.mjs`：新路由补登三处清单（owner 门、审计清单、路由清单）——该 smoke 要求每个 admin 路由都有门禁断言，不登记就等于没人管。

## 4. 没做什么（以及为什么）

1. **用户可自设昵称**——Owner 定调"先只拆写者"。若将来做，建议**新增 `displayName`** 而非让用户直接改 `name`（历史行的 `name` 里存的正是运营备注，用户"第一次改名"等于"擦掉备注"，语义混乱；新字段可零数据迁移）。**且按 Owner 第二问"昵称还要给运营在后台认人用"：认人锚点必须是邮箱 + BetaUser.id + 申请单自报姓名，不能是任何用户可写内容**——否则改个名就换了身份。这条约束要写进将来的实现方案。
2. **问题 B（登录后首页仍显示"登录"）**——本轮范围外（需要首页服务端注入会话摘要 + 统一会话 Provider + 骨架 + 跨标签同步，即审查报告的 P0-3 + P1）。**用户端目前仍会看到"登录"按钮**。
3. **存量脏数据**——库里已有若干行的 `name` 存着运营备注（本轮最典型的是截图那位）。**无法自动区分"用户真名"与"运营备注"**，需要人工/一次性脚本点名清理，本轮**未连生产库、未做**。
4. **两个新 smoke 的 npm 入口**——`package.json` 当前有别手在飞改动，本轮**不碰**；直接命令见下。
5. **未推远端、未部署测试站/生产**。
