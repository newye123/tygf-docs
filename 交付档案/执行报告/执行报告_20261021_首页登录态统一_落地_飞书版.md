首页登录态统一已落地：登录后官网不再写"登录"（2026-10-21）

结论先说

你报的两个问题现在都修完了。**登录后回到官网，导航上是你的头像菜单，不是"登录"**；而且首页是服务端直接知道你是谁的，所以不会再先闪一下"登录"、刷新也不会闪。

做法是按你说的"用对抗式审查做"：先把方案写了 10 条攻击逐条证伪/坐实，审完**改掉了方案里的三处做法**，再动手。

审出来改掉的三处

一，账号门没有改成读共享状态。方案原本想把"查登录状态"收到一个地方，但账号门是**授权路径**：它必须自己再查一次，否则"会话刚被撤销"的用户还能看见工作台。所以门保持原样、自己查、查不到就拦住；共享状态只管显示。结果是：首页首屏 0 次额外请求，工作台从 2 次降到 1 次。

二，"登出后留在原地"只用在首页。工作台那边仍��跳登录页——因为工作台内容是敏感面，门的检查是一次性的，留在原地就等于"已登出还看得见内容"。这属于安全性质，不为了顺滑牺牲。

三，不给顶部那个通用导航加账号入口。它只出现在工作台，而工作台自己的工具条里已经有账号菜单，加了就会变成两个账号入口。顺带修正审查报告里的一处误读：**英文站不用改**——那边导航里根本没有登录入口。

改了什么

服务端多了一个"会话摘要"：把当前用户压成三样——是不是登录了、邮箱、邮箱验没验。**不包含**姓名、内部编号这些（延续上一包的口径）。首页读它一次，注进页面。

客户端多了一个会话管理器：首帧就用服务端给的值，**不在挂载时再发请求**；网络连不上时**保留上一次已知状态**（不会把"网络问题"当成"退出登录"）；跨标签页用浏览器广播同步（只广播"登录/登出"这件事，不传任何身份数据）。

首页多了一个轻量账号菜单（不引工作台那套组件，不给营销页加负担）：点开头像出菜单，含邮箱、"已登录 · 内测账号"、工作台、设备与会话管理、退出登录；按 Esc 或点外面关闭；账号被停用时头像带一个琥珀点、菜单里写明"账号当前不可用"且**只留退出登录**——不诱导你反复登录一个已停用的号。登出后留在原地并提示"已退出登录"。

另外把登录页那张"已在登录状态"卡的按钮修对了：文案写"前往工作台"，以前实际落到营销首页，现在直接进工作台。

验证读数（都是本会话实跑）

静态门：类型检查 rc=0；8 个改动文件 eslint 0 问题；新增一支 39 项的源码契约 smoke 全过；账号门控、登出设备语义、用户资料隐私三支既有门全绿。

端到端真跑：起了本地服务、连隔离库、真注册真登录——未登录时首页有"登录"没头像；登录后首页有头像、"登录"链接消失、邮箱在、**运营备注一个字都不在页面里**；身份接口的字段还是最小集；把账号置为停用后，首页仍画头像、不回落成"登录"。

真浏览器（无头 Chrome + 调试协议）：**控制台 0 错 0 警、水合告警 0 条**；菜单能开能关；头像和"申请试跑"按钮不重叠（实测间隙 12 像素）。

没做的

用户可自设昵称按你定的"先只拆写者"没做；"登录后首页隐藏申请试跑"是产品级改动、等你拍；库里有几行历史数据的姓名格里存着运营备注，没法自动区分真名和备注，要点名清理，我没连生产库；**未推远端、未部署两站**。
