# 免 PS 引擎已改成"随本地助手安装包内置"：代码入库 develop 3ec8a4b

## 你说得对，这条是"已定未做"

10-17 那份执行方案确实写了"内置进本地助手安装包，用户不需要单独再装 PhotoCraft"。我核对了代码：**方案在，代码没落**。具体是——判定层的函数名叫 `bundledEnginePresent`（内置引擎在不在），实现却只看本机配置里写的 `pcExePath`，而那个键缺省是空串；出包脚本和安装脚本里也没有引擎文件与许可文件那两条。所以"内置"一直停在纸面上，我之前给你的候选包只是把文件放在旁边、再靠脚本往配置里写路径。这次把它做成真的。

## 现在的行为

- 助手自己按**安装目录下的 `bin\engine.sha256`** 找引擎：那行写着 `<64位哈希>  <引擎文件名>`，取件和校验都以它为准。
- **缺钉值、钉值坏形、文件名带路径、引擎件不在、目录没给**——五种情况各有各的错误码，一律拒绝走引擎道，不会"看见 exe 就先用着"。
- 配置里显式写路径仍然生效，但降级成"开发直跑／受控换引擎"的口子；正式安装包形态下，用户改本机 JSON 换不掉引擎。
- 开关 `pcExecutorEnabled` 出厂还是 false：装了引擎不等于启用，仍是物理断路，白名单机才开。

## 出包链补上的两处

- 新增 `build/vendor-engine.cjs`：先验钉值与实际文件字节是否一致，再复制进包，复制完再复核一次。换件、漏钉值、许可不全，任何一项都让出包直接失败（rc=1），不会带着缺口出厂。
- `build-engine.bat` 加了第 4b 步调它；`installer.iss` 加了两条 Source：`dist\bin\*` 装到 `{app}\bin`，`dist\licenses\*` 装到 `{app}\licenses`。
- 上游许可八件（MIT／Apache／NOTICE／ATTRIBUTION／两只 OFL 字体／SCOWL 词表／自动生成的第三方清单）和钉值文件已入库；**引擎 exe 本体不入库**（67 MB 二进制，且它仍带上游身份）。

## 怎么验的（都是本轮真实回显，不是判断）

- 新契约门 `smoke-pc-bundled-engine.mjs`：**15 项全过，退出码 0**。里面有专门负控：把引擎字节换掉 ⇒ 判哈希不符、rc=1；把钉值删掉 ⇒ 判缺钉值、rc=1；在没有内置件的机器目录上执行 `--bundled` ⇒ 直接拒绝（不许"先把开关打开再等运行时报错"）。
- 既有四门同轮复跑：通道判定 7/7、接线冻结 9/9、启用脚本 6/6、观测归一 9/9。其中观测门里两条断言是**按新形状重定靶**而不是删掉——仍然要求"取件视图只算一次并冻结"、探针仍受"没开 PS ＋ 开关确实开着"两道限制，另加一条"不得绕过取件视图直接吃裸配置"。
- 端到端模拟装包形态：用真的 67 MB 引擎走一遍 staging（rc=0）⇒ 造出 `{app}\bin` 布局 ⇒ 取件解析判 `source=bundled` ⇒ 实跑只读扫描 **rc=0 全 PASS**（扫描成功、`psVersion=null` 证明没起 Photoshop、三层原文齐、母版前后哈希相同＝真只读）。
- 候选包补了 `bin\engine.sha256`，和值重算：**25 个文件，逐条复算 0 处不符**。
