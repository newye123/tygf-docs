先说结论

  1. 判定内核：新增 binding-evidence.ts，把「这张表属于这稿」分成六档——实证、声明、推定、存疑、不符、未核。归属证据和原文集覆盖都对上才算「实证」，只看表名 SKU 最多算「声明」（binding-evidence.ts:121）。
  2. 界面看得见：第 1 步左栏每份稿的行头、组卡头上各一枚档位徽章，组卡下面单独一行写依据句（step1-stage-view.tsx:1008 / :1048 / :1746）。
  3. 对不上就地拦：「不符」时组卡按钮换成「这一组的表对不上：换一张表再进第 2 步」，待办条记一条「绑定不符」（:997-998 / :1201 / :1650）。

这对你意味着什么：以前「表归到这一组」就等于「对」，界面不会告诉你凭什么；现在每份稿都有一句可读的理由，数字和覆盖率矩阵同源，不会出现「矩阵说 100%、这里说不符」。

一、六档怎么定、界面长什么样

档位什么情况界面
实证归属对上（表名 SKU 或表里「模块」列）＋ 本稿原文集全覆盖绿字「实证」，依据句带覆盖百分比
声明只有归属对上，表还没读蓝字「声明」，注明「原文集未核」
推定没有归属证据，但原文集全覆盖蓝字「推定」
存疑原文集只对上一部分琥珀「存疑」——交给覆盖率闸在执行前要一次放行
不符原文集零交集，或「模块」列指向别的 SKU玫瑰色「不符」，按钮换成「换一张表」，待办条记一条
未核稿还没扫到原文，无从比较虚线灰「未核」，交给扫描闸

两处口径纪律：

  • 覆盖口径只有一个来源：内核直接 import { calcCoverage } from './coverage'（binding-evidence.ts:24），95% 阈值也只在 coverage.ts；证据内核里没有任何自带阈值，门里专门有一条判据盯这件事。
  • 颜色＋文字双编码（色盲也读得出）；「推定」和「声明」都走蓝档——它们是「能用但没双证据」，不是异常。

「模块」列只作佐证：这一列在用户表里可能写的是分区名（解析层别名里就有 SECTION），所以只有全部取值都命中本稿 SKU才认它归属；一个都对不上、但两边都带数字，才判「指到别的稿」→ 不符。分区名混着写的一律当「没有归属证据」，不冤枉人。

二、为什么只拦「不符」，不拦「存疑」

存疑＝原文集只对上一部分。这个情况执行闸那边本来就会拦：矩阵里低于 95% 的格必须显式勾选放行才能开始（workbench-view.tsx:3628 / :3820；execute-step.tsx:2415）。同一件事在待办条里再报一遍，就是同一段文字出现两处、迟早说岔。所以待办条只收「不符」，存疑交给覆盖率闸——门里有一条判据（E4）盯住「只有不符进待办」。

同理，本轮没有再建一道批级硬闸：0% 重叠的格在执行前已经被覆盖率闸拦住，再加一道只是把同一份安全重复一遍。
