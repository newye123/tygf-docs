02系统 Node 20 → 22.23.4（收口 #235）

  • /usr/lib/node_modules 里原生模块 0 个（find … -name '*.node' 计数 0）⇒ 换解释器不用重装任何依赖。

  • 而且一行 unit 配置都不用改。

残留（如实）

机器上现在有两个 Node 安装通道：NodeSource 的 apt 包，和我们自己的 tarball 目录。版本此刻一致，但通道不一致——以后只升一个就会重新漂移。建议二选一：业务也收到 apt 通道，或把那枚单元指到 tarball 路径。本轮不做（又一次生产改动，方向该 Owner 认）。

回滚：nodesource.sources.bak 拷回 → apt-get update → apt-get install nodejs=20.20.2-1nodesource1 → 重启 pm2-ubuntu。这条链今天实测跑通过两次（就是那两次误回滚）。

03探针：一条命令，退出码说话

主入口scripts/security-runtime-probe.sh

bash scripts/security-runtime-probe.sh（网络受限加 --offline）。查九件事：业务与系统运行时版本、ABI 是否还是 127、待装安全包数（按 noble-security 这个源数，不拿"全部待装"糊）、自动更新是否真放开安全源、自动重启是否关着、红单元数对不对基线、磁盘可用率、官方那条版本线有没有更新版（安全版判红，非安全版只提醒）。

判据scripts/security-runtime-baseline.json

唯一判据来源：最低版本、ABI、必须放开的安全源、自动重启必须 false、磁盘下限、红单元基线。改这个文件＝改闸，里面写明每条出处。

解析scripts/security-runtime-latest.mjs

读 nodejs.org 官方发行索引，取该版本线最新版与它的安全版标记。

实测（正控＋负控）

  • 13:33:42 全绿：FAIL=0 WARN=1（那条 WARN 是 tmux 被 Ubuntu 灰度推送，非安全项）；官方索引给出"已是 22.x 最新（v22.23.4，2026-10-20，security）"。
  • 13:35 负控：把基线临时抬到 22.99.0 ⇒ FAIL=2、rc=1；随后按备份还原，哈希一致（cc47c4003bd6cac2）。

两个坑（已写进代码注释）

  • 本机 curl nodejs.org 取不到（实测 http=000）⇒ 索引必须在服务器上取（服务器 0.05 秒 335 KB）。
