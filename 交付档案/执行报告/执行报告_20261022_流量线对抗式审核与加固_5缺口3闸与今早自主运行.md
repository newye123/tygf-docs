## Round 2：横向扫同类缺陷

- **全仓 .sh 的可执行位**：9 个文件全是 100644（`git ls-files -s`）。发布包由 `git archive` 出，索引模式直接写进 zip ⇒ 线上 .sh 无 exec 位 ⇒ 任何"直接执行 .sh"的地方都会 Permission denied。
- **"直接执行 .sh"的地方**：逐条核过——`deploy/deploy-release.sh:435` 已是 `bash` 调用、`deploy/server-setup.sh:327` 已是 `bash` 调用、`deploy/install-test-timers.sh:9` 已是 `exec bash`；**唯一的一处真凶就是 `install-timers.sh:151`（昨天已修）**。所以这一类缺陷在仓库里已经闭合，只差"以后新增 .sh 不会再犯"的闸。
- **grep 模式里未转义 `$` 的假绿陷阱**（GNU grep 把 mid-pattern `$` 当行尾锚点 ⇒ 模式永远匹配不到 ⇒ 断言永远绿）：全仓 1081 个文件精确扫描（只认单引号里的字面量）**命中 0 处**；粗扫出的 9 处经逐条核对全是双引号里的 shell 变量（grep 前已展开），属假警报。
- **自测门的环境依赖**：那条"缺令牌文件即拦"依赖真机上 `/etc/tygf-site-traffic.env` 不存在——而它现在存在（这是它本来的用途）。门必须能在真机上跑。

## Round 3：数据可信度——"看起来对但其实不对"

- **同源两份拷贝会漂移**：两站采的是同一个 Cloudflare zone 与同一组主机名，数据内容本就相同，却各存一份。Cloudflare 边缘数据会事后修订，两站各抽各的版本 ⇒ 同一日期在两块运营台上可能显示不同值。**这是真的会发生的事，不是理论风险**（脚本注释里就写着"边缘数据会后到并修订"）。
- **陈旧不可见**：采集任务静默停掉（令牌过期／CF 抖动／机器没开机），面板照样显示上次的数字，看起来像"最近就是这样"。
- **补救指令不可执行**："手工补一次跑 npm run ops:site-traffic"在服务器上不成立——令牌在 root-only 文件里，`npm run` 读不到它。
- **同一个洞在两个方向上出现**：补数据入口（安装器）与读数入口（面板）都只在"本机视角"成立，服务器视角不成立。

## 方案与执行结果

### A. 面板：补救指令按环境分站 + 补跑给 systemctl（已做）

- `src/app/api/admin/traffic/route.ts`：新增 `trafficRemedy()`，按 `TYGF_ENVIRONMENT` 分站给命令——生产给 `sudo -n bash deploy/install-timers.sh --target production --confirm-production` 与 `/var/www/tygf/.env`、台账路径、主机名 `tuyigf.com`；测试站给 `install-test-timers.sh tygf-test-site-traffic` 与 `/var/www/tygf-test/.env`、`test.tuyigf.com`。单次补跑统一给 `sudo systemctl start tygf[-test]-site-traffic.service`。
- 自测断言：新增两条（分站、补跑给 systemctl），旧的门不变。

### B. 自测门沙箱化：门必须能在真机上跑（已做）

- `deploy/install-timers.sh`：`TOKEN_FILE="${TYGF_TRAFFIC_TOKEN_FILE:-/etc/tygf-site-traffic.env}"`（生产用法不变，只给离线自测覆盖）。
- `scripts/smoke-site-traffic-timer.sh`：两条"缺令牌文件即拦"改用沙箱路径；**新增两条真断言**——沙箱令牌文件到位且 0600 ⇒ 令牌闸放行并拦在下一道（.env 闸，不碰真系统）；令牌文件 0644 ⇒ 权限闸拒装。
- 实测：昨天在服务器红两条 → 今天在**同一台机器**（令牌文件真实存在）19 条全绿 rc=0。

### C. 发布包可执行位：根治 + 加闸（已做）

- 9 个 .sh 的索引模式 100644 → 100755（`git update-index --chmod=+x`），发布包因此带 exec 位。
- `scripts/check-release-package-hygiene.cjs` 新增两道断言：① 索引里 .sh 必须 100755；② 最终 zip 里 .sh 必须带 unix exec 位（读 zip 中央目录的 external attributes）。
- 实测：`git archive` 出的包里 8 个 deploy .sh 全部 0755（creatorHost=3，unix）；出包卫生门 rc=0（trackedShellScriptCount=9，shellScriptsWithoutExecBit=0）。
- **红侧证据**：昨天服务器上的 `Permission denied` 就是这条的现场；旧安装器放回沙箱 → 新断言判红 rc=1。

### D. 面板陈旧可见（已做）

- `src/lib/server/site-traffic.ts`：新增 `lastFetchedStamp()`／`staleDaysSince()`（按 UTC+8 日历日，不依赖服务器时区），读数带 `lastFetchedAt`（台账行 updatedAt 的最大值）与 `staleDays`。
- `src/components/admin/traffic-panel.tsx`：显示"最后抓取：…"，`staleDays ≥ 2` 时红字提示"采集已 N 天没更新（数字可能停在旧值，别当现状用）"。0/1 为正常（凌晨到排程时刻之间本来就是 1）。

### E. 两站台账漂移巡检（已做）

- 新增 `scripts/check-traffic-ledger-drift.mjs`：同日 zone 行逐值比对；按两站各自排程（读已装 timer 单元的 `OnCalendar`）区分"今天还没轮到"与"真漏采"，避免误报；退出码 0/1/2（一致／实质差异／缺输入）。
- 实测：服务器上跑 → rc=0（两站 5 个数据日逐值一致）；夹具三种情形（一致 0／漂移 1／缺输入 2）自测通过。
- **我在写这个脚本时自己踩了一次**：第一版把 CST 墙钟当 UTC 戳去比较，导致"今天还没轮到"被误判成"漏采"；服务器实跑当场抓到，已改（两条坐标系分开）。
