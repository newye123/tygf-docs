## 问题项

### 问题 1 🟠 覆盖率矩阵恒 100%，执行前覆盖率闸永不触发（新立案 #190）

- 现象：给 draft-a 换上「一行都对不上」的表，矩阵仍显示 `DE 100% / FR 100%`。点开格子明细是 `覆盖率 100% · 可翻译文本 0 条 · 精确 0 · 空白等价 0 · 部分包含 0 · 未匹配 0`；而同一稿的设计对象清单明明写着 `可写对象 3`。
- 根因：分母取的是浏览器侧摘要里的逐层原文，但出于隐私，下发给浏览器的削减摘要**不含逐层原文**——`BrowserPreparationSummary` 只有计数没有 `textLayers`（`worktrees/tmp-e2e-v7/src/lib/trust-chain/preparation-contract.ts:305-319`），于是 `src/lib/workbench/coverage.ts:114-115` 拿到空数组，`src/lib/workbench/coverage.ts:78` 对空分母直接返回 100。
- 影响面：矩阵与 #140/D5「执行前覆盖率闸」是同一份取数（`src/components/workbench/workbench-view.tsx:1801-1808` → 传给执行步 `:3879`），所以**这道闸在真实批次里永远不会拦**——它看起来在工作，实际是常亮的绿灯。
- 兜底仍在：第 3 步对账（助手侧真匹配）能报「3 处没有对应行」，所以用户不会被静默扣积分；但界面先给了 100%，是误导。
- 建议修法（推荐第 2 条）：① 分母为 0 时不要显示 100%，如实显示「无法估算（浏览器侧没有逐层原文）」并让闸判红；② 矩阵改为直接吃第 3 步的服务端/助手对账结果（口径唯一，但要把对账提前）。

### 问题 2 🟡 批量页文案与 v7 相反

`src/components/workbench/design-file-card.tsx:1019` 和 `:1116` 仍写「本批次所有设计稿共用一张表」，而 v7 的实际行为是每稿一张、互不共用。用户按文案理解会以为导一次表就够。

### 问题 3 🟡 本地一体化（代理模式）状态轮询必红

站点以代理模式调用助手时（`NEXT_PUBLIC_ASSISTANT_DIRECT=0`，`worktrees/develop/.env:9` 现值），服务端轮询 `/v1.5/preparation/status` 既不带执行票据、又只能从**明文 `config.json`** 读内部令牌（`src/lib/server/local-assistant.ts:336-344`、`:472-484`），而 3.7.15 助手已把配置迁进加密的 `.tygf_session`（`download/local-assistant/server.js:256-258`）——结果恒 403：助手事件日志 `GET /v1.5/preparation/status/psn_… -> 403 code=TICKET_REQUIRED origin=(none)`（06:36:45Z）。改成直连票据模式后同一条链路立刻跑通（三次 `outcome=prepared`）。按脚本口径线上是直连（生产构建前置门强制 `DIRECT=1`：`scripts/check-production-env.cjs:84-85`；主机安装脚本写 1：`deploy/server-setup.sh:78`、`:137`），但**两台服务器的运行态 env 本轮未实机复核**（标未核实）；确定受影响的是「本地开发一体化」这条路。
