# 免 PS 引擎：已经装着并跑着；端到端跑通了，但抓到整稿字距被静默改写（175/175 层）

**一句话**：引擎不用我再装——它今晚 20:03 就已经由你机器上那个助手起起来了。我用它在一份真稿上跑通了"改文字→存盘→摘坏块→逐层回读"，链路确实能跑；但逐层回读抓到一个静默改动：**整稿 175 个文字层的字距模式全部从「光学」被改成「度量」**，连一个都没碰过的层也被改。所以"能跑"和"能交付"是两件事，后者现在一句都不能对外说。

---

**现场读数（实测，不是猜）**

- 现役助手：图译工坊本地助手 3.7.24，今晚 19:44 起（进程 40276）。
- 引擎进程：图译工坊引擎.exe，20:03:20 起，父进程就是那个助手，一直挂着约 1 小时 50 分没退（进程 50936）。
- Photoshop 22.0（2021）两个实例在跑，助手报握手正常。
- 引擎件身份：我实跑它的版本探针，回显 tygf-engine 0.7.0 (dev build)；仓库里的钉值和三份文件逐字节一致，件没被换过。

一点诚实话：我说"这台机器开关已经开了"是从行为反推的——助手只在「PS 没在跑＋旗标开」的时候才会去起引擎探针，而 20:03 正好是 PS 没跑的时段。配置文件的值我读不到，那份安装目录属于提权进程，本会话没权限，这条记未核实。另外仓库自己的守卫脚本写着"引擎以常驻子进程形式跑、会持有自己的文件句柄"，所以那个没退的会话以后会挡住换件和升级。

**端到端跑通了什么（用的真稿，原件一个字没动）**

先说挑稿就踩到两个坑：语料里最小的那份真稿（25.5MB）其实是成品稿、一个文字层都没有；而 5857、6877 那两份母版全是 PSB 格式，现行清洗器对 PSB 一律硬拒，整条免 PS 路走不通。最后用一份 616 层、175 个文字层的真稿副本跑：引擎 3 秒读完 25MB 真稿、层树全读出来（这说明**当"免 PS 读稿器"用是没问题的，扫描和就绪判断不需要 Photoshop**）；然后改一层文字、另存新文件、摘掉引擎自写的那个坏块（1 块、437,190 字节，说明 10-20 那个清洗修复没回潮）；最后从盘上的成品文件逐层回读——新文字落盘正确，行距、字间距、字号、变形都没变。

**问题出在回读普查**：把 175 个文字层在"源稿"和"成品稿"两份文件上逐层对读，结果是 175/175 全部从光学字距变成度量字距。复现脚本和两份逐层数据都留在 tmp/pc-run-20261023/ 里，可以直接重跑。

**为什么这条要命**：你今天刚让我上线的"自动字距三档"（沿用／度量／光学）就是拿字距模式当交付内容在传的。引擎会把标成"光学"的稿存成"度量"，而且是逐层都偏——这不是"文件能不能打开"的问题，是"打开以后已经不是同一份稿"的问题。已登记为 ISSUES 第 276 条，严重度高。

另外两条实测数：引擎重新存盘会让文件变大，从 176,855,002 字节变成 263,343,834 字节（涨 49.2%）。还有，写回这条路在代码里是被一道守卫**刻意冻结**的——守卫明令不许把引擎的写回执行器接进助手的服务链路，挂着三个未解的上游问题（打开即崩、文档级文本数据不同步、重建文字数据丢段落字段）。我没有绕过它，接它需要显式改守卫并写下"三个问题已解"的证据。

**这对你意味着什么**

- 现在就能用：引擎当免 PS 的读稿器，扫描、就绪判断，不装 Photoshop 也能读层树。
- 不能对外说：一句都不能写"免 PS 写回可用/保真"。第 276 条修掉之前，交付出去的是"能打开但排版被改"的稿。
- 我没做的：没接写回链路、没动你机器的助手配置、也没杀那个常驻引擎进程。

**要你拍三选一**

- A：只认"引擎跑起来能读稿"——已经达成，不用再动代码。我把扫描道用在没有 PS 的场景，顺手加一条"常驻会话不退出"的回收口子。
- B：要能交付改过的稿——先修第 276 条。两条路：一是引擎侧改（我们的那份 fork 在保存时保留原字距模式），干净，但要重新建 Rust 工具链出件；二是助手侧兜底（存完按源稿逐层把字距写回去），改动小，但等于把引擎的缺陷长期背在自己身上。我建议走第一条，第二条当临时挡板。
- C：你亲眼验收——改好的成品件在 F:\工具开发\图译工坊内测版\tmp\pc-run-20261023\out.psd（252MB），用 PS 2021 打开看那层日文和整体排版，这正是你 10-20 定的验收前置。

**没查清的（不装查过）**：像素层有没有逐字节变化没做图像比对；除字距外还有哪些字段会被改，只比了四类；那个常驻会话算不算泄漏，没读句柄；本机三键的实际配置值读不到；语料其余稿的文字层占比只扫了 4 份，不足以推全量。
