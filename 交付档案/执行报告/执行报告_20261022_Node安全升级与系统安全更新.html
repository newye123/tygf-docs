02对抗式审查：执行前钉死的六条

契约/opt/tygf-node-v22

两站共用同一个 Node 目录：生产 systemd 的 ExecStart 与测试 PM2 的 script path 都指它 ⇒ 换运行时等于同时换两站，必须一起停、一起验，不能只动一边。

状态~/.pm2/dump.pm2

PM2 把 Node 二进制当脚本路径存：只有 save → kill → resurrect 才真换运行时；只 pm2 restart 会保持旧二进制，看起来成功其实没换。

数据apt 模拟

普通 upgrade 会漏掉新内核：需要装新依赖的包被跳过。改用 --with-new-pkgs，读数 254 个 Inst、0 个 Remv；基线（11:23:27）测得 158 个包来自 noble-security。

根因50unattended-upgrades:8

自动安全更新形同虚设：那一行 -security 是注释状态，日志里允许源只有 o=Ubuntu,a=noble ⇒ 装了工具但从不打安全补丁。这一条是「为什么会积压 158 个」的答案。

归属failed-before.txt

测试站那枚红单元是存量：重启前先存证。若不先存，重启后它还红会被误算成本次造成的；若它恰好不红了又会被误算成本次修好的。

容量df -h /

只剩 4.9G（88%）：254 个包约 1G 下载 ⇒ 必须先清 apt 缓存。写到一半满盘比不补丁更危险（dpkg 半装状态）。
