033. 过程与守卫（两次都按设计跑）

第一次尝试失败，守卫拦住了。 锚点正则我写成 ^access_log，而配置里该行行首是制表符 ⇒ awk 返回 ANCHOR_NOT_FOUND rc=3，脚本按设计退出，配置未动、未重载（原式回显 STEP2_PATCH_FAILED rc=3 (config untouched)）。改正则为 ^[ \t]*access_log 后重跑。

中途差点下错结论。 改完 http 级后我自测两发，官网行带上了 host=、测试站行没有。当时我怀疑"重载未完成/旧 worker 残留"，用 ps -o pid,etime -C nginx 查了：两个 worker 都是 96 秒前起的，旧 worker 已全退 ⇒ 排除该假设，才去查站点级配置，找到 tygf-test:11 那条覆盖。

顺带记一条工具教训：我先前用 grep -rn access_log /etc/nginx/sites-enabled/ 得到"没有站点级日志"的假结论——sites-enabled/ 里全是符号链接，grep -r 默认不跟随。改查 sites-available/* 真文件才看到。

每次改动都有回滚点：

  • /etc/nginx/nginx.conf.bak-20261027T023757Z
  • /etc/nginx/sites-available/tygf-test.bak-logfmt-20261027T024047Z

（另有一次失败尝试留下的 nginx.conf.bak-20261027T023533Z，内容与线上原版一致）

回滚一条命令即可：sudo cp -a <对应 .bak> <原文件> && sudo nginx -t && sudo systemctl reload nginx
