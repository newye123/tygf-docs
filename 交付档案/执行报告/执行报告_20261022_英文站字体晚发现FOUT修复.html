01真缺陷 A：英文站字体「晚发现」（FOUT）

缺陷字体请求落在最后一个关键资源

真浏览器请求时间线（已上站的 /en）：document@0ms → stylesheet@1393ms(3 个) → script@1394ms → font@3380ms ⇒ 字体比 CSS 晚约 2 s 才被发现。

对照：中文站 / 预加载了 4 个分片 ⇒ 英文站一个 font preload 都没有 ⇒ 两站不对称。

后果：英文首页 H1（LCP 元素）先用回退字体画一遍、再换成思源黑体（可见 FOUT）。

修英文站布局加 preload

src/app/en/layout.tsx 加 <link rel="preload" as="font">。放 layout 不放首页：字体规则是 html[lang="en"] body ⇒ 全部 /en 页面（首页/下载/条款/隐私）都渲染英文正文；中文站「只首页预加载」是因为其余路由不渲染中文正文。

修后实测：font@1283ms ⇒ 与 CSS 同一刻并行（原来在 CSS 之后约 2 s）。

02真缺陷 B：粗体与前文粘在一起（两处）

缺陷线上就是「tool.It」与「Emailtuyi@tuyigf.com」

线上 HTML：<span>…over to a tool.</span><b>It is about never rebuilding…</b> ⇒ 「tool.It」；<div class="try-contact">Email<b>tuyi@tuyigf.com</b></div> ⇒ 「Emailtuyi@tuyigf.com」。

根因：粗体标记（**）是 markup，splitBold 切出来的第一段不自带空格 ⇒ 标记前必须留一个。

为什么只有真浏览器能看见：HTML 结构是对的，缺的是元素边界上那个空格 ⇒ 读源码看不出来，静态字面量扫描也容易漏。

修英文两处补空格；中文不改

src/config/siteContentEn.ts（粗体标记前补空格）＋ src/components/site/home-view-en.tsx（标签与 <b> 之间补空格）。

中文那边同样写法是对的（中文标签与值之间、中文句号后本来就不加空格）⇒ 只改英文。

03门缺口：缺陷能上线，是因为没人管

门补什么位置
真浏览器门「英文页必须预加载自己的字体子集」＋「中文页必须预加载 4 个分片（把现状钉住防回退）」＋「粗体段落与前文之间必须有空格（只判拉丁文）」scripts/smoke-en-layout.mjs（42 → 55 断言）
出包门「声明该 @font-face 的 layout 必须预加载它」（按 <link …> 块解析，判块内同时出现 preload 与该字体文件名）scripts/build-en-font-subset.mjs --check（在 test:contracts 链尾）
门只钉确定性事实，不钉毫秒数

毫秒随网络抖，钉毫秒就是假门。「晚发现 2 秒」是为什么要修的量化证据，门负责钉住原因。

04出包途中被自己的门第三次拦下：生成物相对源过期

缺陷中文子集少了「搬」字

[zh-font] FAIL 中文文案用了子集里没有的字符 1 个：搬(U+642C) ⇒ PACKAGE_RC=1。「搬」来自已提交的 3.7.21 源码 ⇒ 旧子集少了这个字 ⇒ 那个字会落系统字体。

处置重新生成，不是改文案绕过

另一会话的处置是「把发布说明里的一个字换掉，避开这道门」（31bed477）—— 那是反过来的：子集是生成物、文案是产品事实，为了让构建产物过关去改产品文案，等于让产品事实迁就构建产物，而且改完那行字对用户毫无意义。

⇒ 本轮按已提交状态重新生成（478bae42：4 片 394,880 B、字符集 1454 码位），并把守卫的失败提示补全为「不要改文案绕过」＋「在已提交状态下生成」（cad83e4f）。生成必须在已提交状态下做 —— 开发工作树里有别的会话的在飞改动，在那边生成会得到与包不一致的子集。

05门自己被审出的三个坑（本轮全修，ISSUES #168）

坑一模板字符串里写了反引号 ⇒ 门报假象

MEASURE（页面内测量脚本，外层是模板字符串）的注释里含反引号 ⇒ 模板提前结束 ⇒ 页面脚本语法错误 ⇒ 门报「重叠 undefinedpx」这种与真问题无关的假象。

坑二只看紧邻文本节点 ⇒ 漏一半

粗体前面常常是 <span> 而不是文本节点 ⇒ hero 那处漏掉了（直到对照实验只报出 1 处才发现）⇒ 门里加了「跨过元素往前取紧邻文字」的辅助函数。

坑三取最后一个字符时把空格 trim 掉了 ⇒ 永远红

判据写成 before.trimEnd().slice(-1) ⇒ 恰好把要检查的那个空格 trim 没了 ⇒ 文案修好后门仍报红（是门错不是代码错）⇒ 改成取原始最后一个字符。

教训：新增断言必须用对照实验验两端 —— 人为制造缺陷 ⇒ 门必须红；修好缺陷 ⇒ 门必须绿。本轮验证：修后线上 55 断言全绿；人为去掉空格 ⇒ 报 1 处；还原 ⇒ 0 处。
