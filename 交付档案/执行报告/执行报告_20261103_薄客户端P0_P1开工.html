① 反破解探针：先修「假绿」

旧版按 process.cwd() 找脚本目录。换到别的目录跑（自动化里很常见），探针集静默变成空集，于是任何 exe 都判「干净」。

  • 探针改按脚本自身位置上溯仓库根；
  • 探针数达不到下限（jsx ≥ 4、注释 ≥ 3）直接 exit 1，不再给「空集合=干净」；
  • 新增 --self-test：空探针集必须被拒、植入泄露必须被抓、干净文件不得误报；
  • generated/*.js 探针默认只点名不拦：这些明文资产今天确实还在包里（P5 才撤），现在变红等于让出包链停摆。每次出包都会打印 DEBT 行，P5 之后加 --strict 变硬门。

② 出包与发布接线

位置行为
package-release.cjs本树有 build/dist/图译工坊引擎.exe 就必须过探针；没有则打印跳过原因，不写「已扫干净」
publish-local-assistant.cjs发安装包前扫内层引擎，不过即拒发；引擎不在本机则明确告警

扫内层引擎而不是扫安装包：安装包是压缩壳。实测现役 3.7.31 安装包扫出来是 CLEAN——那只能说明它压缩了，不能证明里面干净。

③ 脚本分发：限流换 DB 桶 + 审计落库

  • 限流：进程内 Map（重启清零、多实例各算各的）→ 仓里现成的 DB 桶，key 用安装号的 HMAC 摘要。
  • 审计：每次成功分发落一行 AssistantScriptDistribution（安装号摘要/前缀、版本、exe 摘要、脚本名）。此前 exeSha256 只进 console.log。
  • 落库失败返回 503，不发脚本——不制造「发过但查不到」的黑洞。
  • 迁移只新增表，不动存量数据。

撞到的墙（比做了什么更重要）

删死码会撞助手脚本哈希。P1 要删的 buildLegacyHtmlReport（123 行，全仓 0 调用点）我试删了，test:contracts 当场红：6e3ed056… != 882a4a86…。

原因：删代码改 jsx 字节 → 改脚本哈希；replacementScriptSha256 是现役 3.7.31 助手内置的期望值。服务端一发新哈希，装机用户会拒收脚本。

结论：死码清理必须随下一支助手包（新 runtime 身份）走，不能塞在服务端批次里。已回滚。
