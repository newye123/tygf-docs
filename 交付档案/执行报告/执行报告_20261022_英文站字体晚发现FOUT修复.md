## 二、对抗式审查：查出来的东西，逐条自审

### 2.1 真缺陷 A：英文站字体「晚发现」（FOUT）

| 项 | 内容 |
|---|---|
| **证据** | 真浏览器请求时间线（已上站的 `/en`）：`document@0ms` → `stylesheet@1393ms`(3 个) → `script@1394ms` → **`font@3380ms`** ⇒ 字体是**最后一个关键资源**，比 CSS 晚约 2 s 才被发现 |
| **对照** | 中文站 `/` 预加载了 4 个分片（`font /fonts/shsc/zh-subset-0..3.woff2`）⇒ **英文站一个 font preload 都没有 ⇒ 两站不对称** |
| **后果** | 英文首页 H1（LCP 元素）**先用回退字体画一遍、再换成思源黑体**（可见 FOUT） |
| **修** | `src/app/en/layout.tsx` 加 `<link rel="preload" as="font">`。**放 layout 不放首页**：字体规则是 `html[lang="en"] body` ⇒ **全部 /en 页面**（首页/下载/条款/隐私）都渲染英文正文；中文站「只首页预加载」是因为其余路由不渲染中文正文 |
| **修后实测** | `document@0ms` → **`font@1015ms`** → `stylesheet@1015ms` ⇒ **字体与 CSS 同一时刻并行**（原来在 CSS 之后约 2 s） |

### 2.2 真缺陷 B：粗体与前文粘在一起（两处）

| 项 | 内容 |
|---|---|
| **证据（线上 HTML）** | ① hero：`<span>…over to a tool.</span><b>It is about never rebuilding…</b>` ⇒ 渲染成「tool.It」；② 联系块：`<div class="try-contact">Email<b>tuyi@tuyigf.com</b></div>` ⇒ 「Emailtuyi@tuyigf.com」 |
| **根因** | 粗体标记（`**`）是 markup，`splitBold` 切出来的第一段**不自带空格** ⇒ 标记前必须留一个 |
| **为什么只有真浏览器能看见** | HTML **结构是对的**（`<span>…</span><b>…</b>`），缺的是**元素边界上那个空格** ⇒ 读源码看不出来，静态字面量扫描也容易漏 |
| **中文那边不改** | 中文标签与值之间、中文句号后本来就不加空格 ⇒ 同样写法是对的 |
| **修** | `src/config/siteContentEn.ts`（粗体标记前补一个空格）＋ `src/components/site/home-view-en.tsx`（标签与 `<b>` 之间补一个空格） |

### 2.3 门缺口（缺陷能上线，是因为没人管）

| 门 | 补什么 | 位置 |
|---|---|---|
| **真浏览器门** | 「英文页必须预加载自己的字体子集」＋「中文页必须预加载 4 个分片（把现状钉住防回退）」＋「**粗体段落与前文之间必须有空格**（只判拉丁文）」 | `scripts/smoke-en-layout.mjs`（42 → **49 断言**） |
| **出包门** | 「声明该 @font-face 的 **layout 必须预加载它**」（按 `<link …>` 块解析，判块内同时出现 preload 与该字体文件名） | `scripts/build-en-font-subset.mjs --check`（**在 `test:contracts` 链尾**，每次出包都跑） |

> **门只钉「preload 标签在」「粗体前有空格」这些确定性事实，不钉毫秒数** —— 毫秒随网络抖，钉毫秒就是假门。「晚发现 2 秒」是**为什么要修**的量化证据，**门负责钉住原因**。

### 2.4 出包途中被自己的门第三次拦下（真缺陷 C：生成物相对源过期）

```
[zh-font] FAIL 中文文案用了子集里没有的字符 1 个：搬(U+642C)  ⇒ PACKAGE_RC=1
```

「搬」来自**已提交**的 3.7.21 源码 ⇒ 旧子集（生成于其之前）少了这个字 ⇒ 那个字会落系统字体。

**两处关键处置**：

- **正确处置是重新生成子集，不是改文案绕过。** 另一会话的处置是「把发布说明里的一个字换掉，避开这道门」（提交 `31bed477`）—— 那是**反过来的**：子集是**生成物**、文案是**产品事实**，为了让构建产物过关去改产品文案，等于让产品事实迁就构建产物，而且改完那行字对用户毫无意义。⇒ 本轮按**已提交状态**重新生成（`478bae42`：4 片 394,880 B、字符集 1454 码位），并把守卫的失败提示补全为「**不要改文案绕过**」＋「**在已提交状态下生成**」（`cad83e4f`）。
- **生成必须在「已提交状态」下做**，不能在开发工作树里做 —— 本机工作树里那个会话有在飞改动（注释里没有「搬」了）⇒ 在那边生成会得到「按工作树算」的子集，**与包里那份不一致** ⇒ 门红而包不对。⇒ 在干净 detached 树里生成，再把产物拷回工作树入库。

### 2.5 差点误报（动手前查清，没写进任何文档）

我一度以为「**已提交**的助手源码 require 了未提交的文件 ⇒ 干净检出下助手加载不了 ⇒ 下个助手包是死的」—— **实测证伪**：`git grep` 搜的是**工作树**（含别人在飞的改动），改看**提交版本**（`git show HEAD:…`）就没有那个 require；已提交树是自洽的。已记一笔，免得下一班重复查。

### 2.6 门自己的两个坑（本轮自己踩的）

1. **模板字符串里不能出现反引号**：MEASURE（页面内测量脚本，外层是模板字符串）的注释里写了含反引号的说明 ⇒ 模板提前结束 ⇒ 页面脚本语法错误 ⇒ 门报「重叠 undefinedpx」这种**假象**而不是真问题。已去掉并留注记。
2. **只看 `previousSibling` 是文本节点会漏一半**：粗体前面常常是 `<span>`。⇒ 门里加了「跨过元素往前取紧邻文字」的辅助函数（改完立刻多抓到 hero 那处 ⇒ 实得 2 处而不是 1 处）。
