## 二、三条新结论（本轮新增，交接文档未覆盖）

### 2.1 引擎授权已查明：MIT OR Apache-2.0（解除拍板第 2 项的大部分）

上游 `github.com/storytold/photocraft`（ArtCraft Team，纯 Rust，约 53.9 万行）。

- **双许可 MIT OR Apache-2.0**，二选一 ⇒ **可商用、可修改、可 fork 改名、可分发**。
- **两条硬约束**：
  1. **Apache-2.0 要求分发时随附 `LICENSE` 与 `NOTICE`**。当前 `C:\Program Files\PhotoCraft\` 安装目录内**两者都没有** ⇒ 这是**真实的合规缺口**，随包分发前必须补（B 档第 2 项的直接动作）。
  2. **ArtCraft 的名称、字标、Logo（`docs/brand/`）属商标，不在许可范围，修改版/fork 必须移除**。⇒ 若要改名重编（F2），除改标识外还必须清掉这些品牌资产。
- 结论：**F2 从「卡授权」变成「卡工作量 + 品牌资产清理」**；B 档「单独标注为第三方组件」的做法在许可上成立，补 LICENSE/NOTICE 即可。

### 2.2 测试站**不需要**重新部署（省掉一整轮构建+打包+传输）

`git diff --stat e8f8452..1fe356e` 显示只有 7 个文件：`AI_MEMORY/` 四份文档 + `package.json` + `scripts/pc-enable-on-machine.cjs` + 新增的 smoke 脚本。

```
git diff --stat e8f8452..1fe356e -- src/ download/ prisma/
(空)
```

⇒ **产品面（`src/`、`download/`、`prisma/`）零差异**。`pc-enable-on-machine.cjs` 是**运维脚本，不进站点**。

**因此三键打不开的原因不是站点旧，而是测试机上跑的是旧脚本**。`1fe356e` 修的是机制性问题：`.tygf_session` 带 `FILE_ATTRIBUTE_HIDDEN`，Windows 对隐藏文件拒绝 `CREATE_ALWAYS`（`fs.writeFileSync` 走的正是这条）⇒ **旧脚本在任何真机上都必 EPERM**，三键从未被真正打开过。

**动作**：把 `1fe356e` 版的 `scripts/pc-enable-on-machine.cjs` 拷到测试机重跑即可，不必动站点、不必出包。

### 2.3 A3「清文档里的 photocraft」应**收窄**，不能全清

方案原文要求「交付文档/运维文字里的 `photocraft` 全部换名」。对抗式审查后**不采纳全清**：

- `交付档案/` 下 **20+ 份历史报告/交接**含该串。它们是**归档记录**，记的是「当时确实用了 PhotoCraft」这一事实。改它等于**篡改历史记录**，且破坏可追溯性。
- 真正该改的只有**操作者可见的运行时字符串**（错误提示、脚本用法）。
- 函数名 `runPhotoCraftScan/Executor/Reopen`、进度标签 `'photocraft scan activity'` 属内部标识，**用户看不见**，改名要动 6 个测试，性价比低。
- 持久化值 `engine:'photocraft'` **不能单独改**：全仓唯一比较点 `pc-channel.js:47` 将来接线时，磁盘上的旧 provenance 会命中 `PC_SCAN_PROVENANCE_PS_SOURCE`（被误判成"PS 扫的件"）⇒ 改值必须**同时接受旧值**。

⇒ 本轮只改运行时串与脚本注释，历史归档原样保留。

### 传输踩的坑（比记忆里那条更严重）

`for` 循环 scp 传完 6 片，服务器上只有 5 片（缺 `part-ad`），而 `|| echo FAILED` 的回显**没落到任务输出**。更糟的是重传后**文件存在但内容不对**（sha256 与本地不一致，是上次失败残留）。

⇒ 纪律更新为：**分片传完必须逐片 sha256 比对 → 合并 → 再校总包 sha256**，两步都不能省。最终 `part-ad` 用 `ssh 'cat > file' < local` 单流传成功。

另注：本机 git bash 的 ssh **不支持 `-o ServerAliveCountInterval`**，一用就报 `Bad configuration option`。
