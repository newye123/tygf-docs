# 线上巡检三轮：英文站两个真缺陷已修并上站（2026-10-22）

## 一句话

**这一轮不看代码，看线上。** 我用真浏览器加 SSH 隧道对**已上站的测试站**巡检，查出**两个真实的用户可见缺陷**——都只有真浏览器能看见：

1. **英文站没预加载自己的字体** ⇒ 浏览器要等 CSS 下载完才开始找字体（实测字体请求落在 **3380 毫秒**，是最后一个关键资源）⇒ 英文首页大标题（首屏最重要的那个元素）**先用回退字体画一遍、再换成思源黑体**（肉眼可见的闪一下换字）。
2. **英文首页两处粗体跟前一��粘在一起**，中间没有空格 ⇒ 线上就是「**tool.It**」和「**Emailtuyi@tuyigf.com**」。

两处都修了，而且**都补了门**（一道真浏览器、一道出包门）。另外出包途中被自己的门第三次拦下（中文子集相对源过期），也修了。

## 一、巡检怎么做的

- **真浏览器**（本机 chromium ＋ SSH 隧道 `localhost:3000` → 服务器 3001，绕开 Cloudflare 与令牌门）：真实渲染、真实字体请求、**真实请求时间线**、真实控制台、真实元素边界。
- **HTTP 巡检**（18 个公开面 ＋ 21 条站内链接）：**18/18 全 200；站内 4xx/5xx ＝ 0**。
- 另跑英文站自己那道真浏览器门（量几何与渲染）：断言数 **42 → 49**。

**巡检边界（如实）**：工作台（`/#workbench`）要登录态，**我这边进不去** ⇒ 多稿台的界面仍只能由您点；本轮只覆盖**公开面**。

## 二、查出来的东西（逐条自审）

**真缺陷 A：英文站字体「晚发现」**
- 实测时间线（已上站的 `/en`）：`document@0ms` → `stylesheet@1393ms` → `script@1394ms` → **`font@3380ms`** ⇒ 字体是最后一个关键资源。
- 对照：中文站预加载了 4 个分片，**英文站一个 font preload 都没有 ⇒ 两站不对称**。
- 修：英文站布局加 preload。**放布局不放首页** —— 字体规则是 `html[lang="en"] body`，**全部 /en 页面**都渲染英文正文；中文站「只首页预加载」是因为其余页面不渲染中文正文。
- **修后实测**：`font@1015ms`，**与 CSS 同一时刻并行**（原来在 CSS 之后约 2 秒）。

**真缺陷 B：粗体跟前一��粘在一起（两处）**
- 线上 HTML：`<span>…over to a tool.</span><b>It is about never rebuilding…</b>` ⇒ 「tool.It」；`<div class="try-contact">Email<b>tuyi@tuyigf.com</b></div>` ⇒ 「Emailtuyi@tuyigf.com」。
- 根因：粗体标记是 markup，切出来的第一段**不自带空格** ⇒ 标记前必须留一个。
- **为什么只有真浏览器能看见**：HTML **结构是对的**，缺的是**元素边界上那个空格** ⇒ 读源码看不出来，静态扫描也容易漏。
- **中文那边不改**：中文标签与值之间、中文句号后本来就不加空格。

**门缺口（缺陷能上线是因为没人管）**
- 真浏览器门加三条：英文页必须预加载自己的字体；中文页必须预加载 4 个分片（把现状钉住防回退）；**粗体段落与前文之间必须有空格**（**只判拉丁文**，中文不判）。
- 出包门加一条：声明该字体的**布局必须预加载它**（这道门在出包链里，每次出包都跑）。
- **门只钉确定性事实，不钉毫秒数**（毫秒随网络抖，钉毫秒就是假门）。「晚发现 2 秒」是**为什么要修**的量化证据，**门负责钉住原因**。

**真缺陷 C：中文子集相对源过期（出包途中被自己的门拦下）**
- 「搬」字来自新入库的 3.7.21 源码 ⇒ 旧子集少了这个字 ⇒ 那个字会落系统字体。
- **正确处置是重新生成子集，不是改文案绕过。** 另一会话的处置是「把发布说明里的一个字换掉，避开这道门」—— 那是**反过来的**：子集是**生成物**、文案是**产品事实**，为了让构建产物过关去改产品文案，等于让产品事实迁就构建产物，而且改完那行字对用户毫无意义。⇒ 本轮按**已提交状态**重新生成，并把守卫的失败提示补全为「**不要改文案绕过**」＋「**在已提交状态下生成**」。
- 顺带一个坑：生成**必须在已提交状态下做**，不能在开发工作树里做（那边有别的会话的在飞改动，会生成出与包不一致的子集）。

**差点误报（动手前查清，没写进任何文档）**
- 我一度以为「已提交的助手源码引用了未提交的文件 ⇒ 干净检出下助手加载不了」—— **实测证伪**：那个搜索命令搜的是**工作树**（含别人在飞的改动），看**提交版本**就没有那行；已提交树是自洽的。

**门自己的两个坑（本轮自己踩的）**
- 页面内测量脚本的注释里写了反引号 ⇒ 模板字符串提前结束 ⇒ 门报「重叠 undefinedpx」这种**假象**而不是真问题。
- 只看紧邻文本节点会漏一半（粗体前面常常是 `<span>`）⇒ 加了「跨元素往前取紧邻文字」的辅助函数（改完立刻多抓到一处）。

## 四、如实说的边界

1. **工作台界面仍无浏览器实测**（我这边没有登录态）⇒ 多稿台那 8 条点验清单仍在您手上。
2. **助手门槛本轮再抬一次** ⇒ 测试站现要求 **3.7.22**（3.7.19/3.7.20/3.7.21 仍在归档里可回退安装）。
3. **全站死链巡检仍是手写探针，没固化成门**（如实记为未固化）。
4. **「元素边界少一个空格」这一类缺陷，现在只有英文站首页被门覆盖**；其它富文本形态还没有同等的门。
5. **中文站字体是构建期快照**（运行期改出的新字落系统字体，字形不一致非破版）。
6. **服务器磁盘紧**（剩 4.8 G / 88%）。
7. **本轮出包被门拦下三次**：一次是环境噪声（机器被别的会话的 MCP 服务占满，数据库事务超时，单独重跑 5 秒通过），两次是真缺陷。
