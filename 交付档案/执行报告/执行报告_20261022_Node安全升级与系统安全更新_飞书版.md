# Node 安全升级 ＋ 系统安全更新｜执行报告（2026-10-22）

**结论先讲：已经按方案执行完了，两站都在正常跑，您不需要做任何事。**

这一轮补上了两个真实的洞。一是我们用的 Node（网站跑起来依赖的那个运行环境）落后了整整一个安全版本，官方 10 月 21 日刚发的三个高危漏洞正敞着；二是服务器上欠着 158 个系统安全补丁没装，而且本来该自动打补丁的机制被一行注释关掉了，等于从来没工作过。现在两样都补齐了，验收全部通过，回滚的路也留好了。

对用户侧没有感知，含重启总共停了大约 3 分钟。

## 一、先说 PHP 那件事：我们没有 PHP，那是假警报

您转来的公告（攻击者能在 PHP 服务器上装后门、拿到全部权限）我逐条查了这台服务器：PHP 的包一个没装、配置目录不存在、PHP-FPM 程序也不存在；nginx 上五个站点的后端全部转发到两个 Node 进程。所以公告里 PHP 8.x / 7.x / 5.x 的三套处置方案对我们**全部不适用**，这一项零动作。

但顺着这条线索往下查运行时，才查出上面那两个真问题——这才是该动手的地方。

## 二、做了什么（五件事，按顺序）

第一件，动手前先留底。在服务器建了一个只有 root 能进的备份目录，里面放了：改动前的系统读数、生产库和测试库各一份备份（生产那份校验结果 ok）、PM2 的应用清单、软件包清单、自动更新配置的原件、以及**重启前就已经失败的定时任务清单**（最后这份是为了不把别人的旧问题算到这次头上）。

第二件，换 Node。没有直接覆盖旧目录，而是新版本装进带版本号的新目录，旧目录改名留着，再把两站共用的那个路径做成指向新版本的软链接。服务器上 13 个业务单元里有 12 个引用这个路径，一次全切过去，一个字都不用改配置，回滚也只是把链接换回去（剩下那 1 个是测试站每 10 分钟的对账任务，它写死用系统自带的旧 Node，切不到它——第四节单说）。换之前先核对了安装包哈希（官方源和国内镜像两个源算出来一模一样），也确认了新版本的模块接口编号和旧版相同——这意味着不需要重装任何依赖。

第三件，切的时候按真实顺序来：停生产服务和相关定时任务，换运行时，起服务（生产实际中断 3 秒），然后 PM2 那边用「保存清单 → 停守护进程 → 按清单拉起」这条链才真正换掉二进制（只 restart 是不换的，看着成功其实还在跑旧的）。

第四件，装系统补丁。用能带出新依赖的那条命令，一共装了 254 个包（227 个升级、27 个新装），删除 0 个。里面包括新内核 6.8.0-147（旧内核保留着可以退回）、OpenSSL、sudo、systemd、C 库、OpenSSH、nginx 等。中途磁盘一度紧张到 92%，清了安装包缓存后回到 4.9G 可用。

第五件，把自动更新修好，然后重启换内核。配置里那行被注释掉的安全源放开了，同时明确写了「不许自动重启」（这台机器没人值守，自动重启的风险比收益大）。重启后开机时间戳 11:36:29，业务进程 11:36:40 起来，**11 秒**。

## 五、回滚（都是盘上真文件，不是纸面预案）

Node：停三个生产服务 → 删软链接 → 把旧目录名改回来 → PM2 重新按清单拉起 → 起服务，分钟级。

## 六、边界（没做的我写清楚，不粉饰）

没有做漏洞利用验证——三个 Node 高危（Brotli 解压越界写、DNS 解析截断、TLS 主机名校验绕过）是按官方公告判定「我们跑的版本在受影响区间内」，不是我们自己复现过攻击；现在的状态是版本已经离开那个区间。

PM2 这个**管理进程**本身还在用系统自带的 Node 20.20.2（已经停止维护）。业务进程不受影响，它们走的是我们自己的运行时目录。系统那个 Node 20 也没升，它走另一条安装通道，风险和这轮不同，我没扩大范围——但要说清一件：**它不只是"摆在那里"，测试站那个每 10 分钟的对账任务写死在用它**（13 个业务单元里唯一一个不引用我们运行时目录的），所以这轮软链接切换切不到它。这两件已登记成独立后续项。

另外：没有整机快照（只有文件级备份）；没有逐包读更新说明；没有跑业务全链路（不占您的 PS 和积分）；没有做入侵痕迹排查（这轮是打补丁，不是取证）；只覆盖了这一台服务器，读数不能推到其他机器；nginx 配置没动没重载；两站代码没重新构建；助手侧没碰。

## 七、建议的下一步（等您一句话，我不自己扩范围）

一是把 PM2 和系统 Node 20 一起收口，要么换到受控的新 LTS，要么把测试站那两个常驻进程改由 systemd 承载、彻底不要 PM2。

二是把「运行时版本 对 官方安全公告」做成每月自动比对的探针。这两次（PHP 恐慌、Node 落后）都是您看到新闻才发起的被动响应，这个不该靠人盯新闻。

三是磁盘只剩 4.9G（88% 满），下次大版本更新前得先规划，不然会踩到「写到一半满盘」。
