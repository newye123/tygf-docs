## 部署我为什么停手

跑了测试站的出包前置门，结果是这样：
- GitHub 一致性那条腿**通过了**（"已核：HEAD 708142718801 已在 origin/develop 上"）——这是三段轨最要紧的一道，说明代码确实在 GitHub 上了。
- 但卡在一条：**工作树必须干净**。而脏的是**别手正在写的 15 个文件**（工作台主视图、排版估算器、覆盖矩阵、清稿那几笔、package.json 等），不是我的。

我**没有**用这三种办法去"清树"，因为都不该用：
- 暂存（stash）——共享工作树上禁用，会连带吞掉别人的现场；
- 把别人文件一起提交——等于替别人发布没验收的代码，这正是我自己审查时立的规矩；
- `git add -A`——同上。

合规做法是有的（磁盘还剩 568 GB，够）：从 GitHub 拉一棵干净树单独出包，大约 6 到 10 分钟。我没往下做，是因为**测试站是共用的**：部署会重启测试站服务和两个后台 worker，**可能打断别的会话正在测试站上跑的验证**。这种事该由你或者总控定时点来拍，不该我在别人干活时抢。

## 你问的"跟生产站差多少"——这个数比想象大得多

- develop 比生产多 **242 笔**，348 个文件，**加了 4 万零 5 百行、删了 2 千 6 百行**。
- **而且不是简单快进**：生产上有 **2 笔是 develop 没有的**（首页字体分片，14.13 MB 瘦到 406 KB 那两笔）。麻烦在于——**其中一笔改的就是 `home-view.tsx`，正是我这次改的同一个文件**，合流必冲突。
- 助手侧差异有 19 个文件；生产期望助手 **3.7.15**，测试站期望 **3.7.28**。生产要跟上不是换个网页包，涉及安装包重建。
- **最要紧的一条还在**：生产库缺"申请来源"那张表，而生产部署脚本根本不跑建表，那道检查对生产恒返回"需人工核对，不算通过"。**现在直接发生产，官网申请表会从"没人填"变成"填了就报错"。**
- 本机 main 分支还停在旧位置，跟远端 main 也不同步。

## 所以要推生产，得先落四件事

1. 把生产独有的那 2 笔合回开发线（含 `home-view.tsx` 冲突处理，合完我的官网验证要重跑一遍）；
2. 定助手要不要随发（要就是真建 exe，不是重打压缩包）；
3. 生产库人工补建表；
4. 测试站先跑通留证据，再走第三段。

## 给你三条路，我推荐 A

- **A（推荐）**：我从 GitHub 拉干净树把包和收据做出来，**但不部署**，同时列出"部署会重启哪些服务"，交给你或总控定时点执行。生产按上面四件事单独立项。
- **B**：你确认此刻没人在用测试站，我就出包 + 部署 + 跑健康检查和官网三项判据。代价是可能打断别的会话的验证。
