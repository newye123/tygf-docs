# 结算证据可验证性 · 对抗审查结论与已执行（2026-11-03）

## 一句话

我上一轮自己提的"下一刀＝写回带服务端签名 nonce"，**被对抗审查打死了，我复跑后接受这个推翻**：nonce 和摘要算法都在客户端手里，攻击者不碰 Photoshop 也能算出合法摘要。**结论是：只要成品字节不经过服务端，"这一单到底交付了没有"在数学上就不可判别**——想拦死，只能改变产品形态或改变"什么时候把额度还给用户"。

## 审查怎么说的（两轮，我已独立复跑承重项）

- **必要条件**：一条证据要能被服务端验证，只有两种情况——服务端能**自己重算出期望值**，或者服务端**独立持有一份副本**。现成的正面例子是报价行集：服务端握着确认表全文（`prisma/schema.prisma:896 tableJson`），所以 `billing-challenge.ts:107-136` 的服务端重算是真校验。而产物 PSD 的字节服务端一份都没有 ⇒ 任何"摘要类"方案都是同一种死法。
- **S2 抽样上传也被否**：回执是助手主动 POST 的，服务端**没有下行强制通道**；而变体④走 FAILED 分支会当场释放并关闭这一单（`execution-batch.ts:1332/1337`），抽样根本没机会被注入 ⇒ 对④的有效抽样率≈0。而且匿名 installId 由客户端本地提供、可重置（`src/lib/workbench/local-assistant-client.ts:403-406`），抽样记忆也能清空。
- **顺带查出三个"我们自己的破口"**（都不是新写，是早就在但被当成证据用）：
  - 逐行证据摘要 `evidenceDigest = sha256(attemptId : rowToken : status)`（`src/lib/server/execution-batch.ts:1425-1427`）——对客户端自己的断言取哈希，**零信息量**，不能当产物证据引用。
  - 回执幂等号 `receiptEventId` 收下只回显（`src/app/api/local-assistant/execution-attempts/[id]/receipt/route.ts:49-50,182`），**schema 里根本没有这一列**（换三个关键词 grep 全 0 命中），幂等实际只靠状态不回退。
  - `deviceSignature` 的钩子在 `download/` 里 0 调用（未接线），且它的密钥必须下发到客户端 ⇒ 双重无效。
- **落后笔数勘误**：develop 树落后 `origin/develop` 是 35 笔（我复算），不是备忘里写的 33。

## 本轮我已经执行的部分（安全、零语义变化）

三处签名密钥原先在环境变量缺失时回退到**仓库里可读的字符串**（`tygf-assistant-fallback` / `tygf-exec-ticket-fallback`）——生产有 `check-production-env.cjs:51-52` 拦（且 `deploy-release.sh:111` 真跑它），但只要运行形态偏离部署脚本（自托管、漏配、本地起给别人连），读过仓库的人就能伪造运行码和执行票据。现在统一改成**每进程随机、三处共用一份、首次使用打一行告警**，代价如实写明：重启后旧票据与运行码一律失效（有意的 fail-closed）。

- 提交 `f196af1f` 已推 `origin/develop`（生产未动、未部署）。
- 验证：新入口 `npm run test:signing-secret` 7 条断言 rc=0，内置两条负控（扫描器对合成件必须命中；跨进程取值必须不同）；变异测试把字面量塞回去 ⇒ rc=1、还原 ⇒ rc=0；相邻回归五条全绿（token-binding / security-hardening / admin-security / execution-ticket-v15 / batch-row-contract，均 rc=0）。
- 顺手在批次 nonce 处写了语义边界注释：它随派单发到客户端，只能证明"票出自本服务端"，不能证明"PS 真跑过"。

## 还剩三条路，按性价比排（都需要你点头，我不擅自动钱和形态）

1. **把"FAILED 立刻退额度"改成冷却期**（我推荐做这条，纯服务端）：现在回执说失败就当场释放冻结，服务端没有任何下行杠杆去要求出示证据。改成"FAILED 先进冷却期，期内服务端可要求上传真文件或转人工复核，期满无异议再释放"——白嫖者要拿回自己付过的额度，就必须出示东西。这条给了 S2 一个真正的触发点。代价：诚实失败的用户额度回来得慢一些（要不要给白名单/上限时长，是产品口径），且属钱语义变更 ⇒ 按合同变更纪律同批抬 `minAssistantVersion`，否则旧助手可能卡在"活干完了永不结算"的方向（B 路实测 fail-closed 方向是平台漏收，不是攻击者失败）。
2. **把 `receiptEventId` 真做成唯一约束**（小改动，需要一次迁移 ⇒ 要过迁移批准台账）：现在重复回执只靠状态机挡，幂等号是装饰。
3. **成品经服务端**（唯一能数学上堵死④的形状）：最后一步装配或分发经过我们服务器 ⇒ 白嫖拿不到可用成品。但它与"设计文件不出本机"、离线可用、大体积出网三个主张正面冲突，本质是**另一个产品形态**，不是一刀能切完的重构。

另：生产站仍未部署这套（`origin/main` 不含薄客户端代码），要在生产开 enforce 得先走完三段轨。
