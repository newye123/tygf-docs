## 做了什么

**① 反破解探针（`scripts/check-exe-no-plaintext.cjs`）**

旧版的病根很具体：探针按 `process.cwd()` 找 `download/local-assistant/scripts`。换到别的目录跑（自动化里很常见），探针集静默变成空集，于是**任何 exe 都判"干净"**——这是标准的假绿。

现在：探针按脚本自身位置上溯仓库根；探针数量达不到下限（jsx≥4、注释≥3）直接 `exit 1`，不再给"空集合=干净"的结论；新增 `--self-test`（空探针集必须被拒、植入的泄露必须被抓、干净文件不得误报）。

同时给 `generated/*.js` 加了探针，但**默认只点名不拦**：今天这几份明文资产确实还打在 exe 里（方案 P5 才撤），现在就把门变成红色等于让出包链停摆。所以它每次出包都会打印 `DEBT` 行；P5 撤完 assets 后加 `--strict` 变硬门。

**② 出包与发布接线**

- `package-release.cjs`：本树有 `build/dist/图译工坊引擎.exe` 就必须过探针；没有就明说"跳过"并给理由。
- `publish-local-assistant.cjs`：发安装包前扫内层引擎，不过即拒发。

为什么扫内层引擎而不是扫安装包：安装包是压缩壳，扫壳等于没扫——我实测过，现役 3.7.31 安装包扫出来是"CLEAN"，但那只能说明压缩了。

**③ 脚本分发：限流 + 审计**

- 限流从进程内 `Map`（重启清零、多实例各算各的）换成仓里现成的 DB 桶，key 用安装号的 HMAC 摘要（新增 `digestInstallId`）。
- 每次成功分发落一行 `AssistantScriptDistribution`：安装号摘要/前缀、助手版本、**exe 摘要**、脚本名。此前 `exeSha256` 只进 `console.log`，服务端没有任何可查询的事实。
- 落库失败返回 503，不发脚本——宁可让助手重试，也不制造"发过但查不到"的黑洞。
- 新增表 `AssistantScriptDistribution` + 迁移（只新增表，不动存量数据）。

**④ P1：判断边界清单与门**

- `config/thin-client-function-ownership.json`：`moved`（已搬走、客户端不许再有）与 `stay`（必须留在客户端的量测）两张名单。

## 撞到的墙（这条比做了什么更重要）

P1 要删的那段死码 `buildLegacyHtmlReport`（replacer jsx 里 123 行，全仓 0 调用点），我试删了——`test:contracts` 当场红：**`6e3ed056… != 882a4a86…`**。

原因：删代码会改 jsx 字节，进而改脚本哈希；而 `replacementScriptSha256` 是**现役 3.7.31 助手内置的期望值**。服务端一发新哈希，装机用户就会拒收脚本——等于让所有现役用户的分发断掉。

所以死码清理必须**随下一支助手包（新 runtime 身份）一起走**，不能塞在服务端批次里。这条已回滚，代码原样保留。
