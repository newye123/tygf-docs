先更正我上一条的说法。我说"英文流量现在走的是死路"，这句话不对——我把页面测完之后是反的。

一、英文站内其实已经通了，不用修

英文首页上有两枚「Request beta access」按钮，还有两条直接发信的链接（主题写的是 Beta access request / 内测申请）；页面的常见问题原文是"提交内测申请，作者会用邮件联系你"，并且明写现在是邀请制内测、不是正式 SaaS。英文下载页我也测了安装包能不能真下：文件头返回 200、总长 12,432,662 字节、支持分段，取前 1024 字节实测返回 206 并真收到 1024 字节，版本号 3.7.15。另外两个英文页里搜 Mac 和 macOS 都是 0 次，没有乱承诺跨平台。

所以要改的不是站内管道，是"外面没人读到我们"。方向就按这个定了。

顺带一个口径教训：海外收款通道确实是 0（我第一遍搜 Paddle 命中五个文件，全是 PaddleOCR 的假匹配，换成带域名的精确串才是空）。搜专有名词不带词形边界就会自己骗自己。

二、补了一个我上轮留下的洞

第七轮我给自己定了发布前机扫，但那套正则全是中文的，英文稿等于没闸。所以先写了英文专用的闸门，十三类禁写形态：绝对量词、保证类、时长与速率、百分比、营销黑话、排名类、跨平台承诺、其他设计套件、识图翻译类、金额、内部机制、案例主张、套话开头，再加结构校验（定义句在不在、反分类句在不在、有没有把 12 语种上限写准）。

闸门先证明自己不是瞎的：写了十四行样本、每行故意塞一处违规，它报了十八处，十三类每一类都至少抓到一条。中间我自己还写坏过两处——有一处会把合法句子"每批最多 12 个目标语种"误报成价格，另一处把排版术语"行距"（leading）当成"行业领先"的 ranking 词。改完重跑负控还是十八处，说明修闸没把闸修瞎。这一步是硬要求：判据没自己跑过就不算数。

三、四件英文稿都写完了，全过闸（可疑行各 0）

GitHub 门面两份。现状实测很偏中文：profile README 英文只有 2 行、中文 22 行；那份清单英文 0 行、中文 53 行。海外买家尽调时唯一会自己搜到的入口就是这个，所以补了英文 README 和一份"多语言 PSD 交付前清单"（六段可照做：开工前、图层体检、逐语言字体、执行中、交付前、六类最容易出的错）。

站外两篇。一篇是"自己写脚本还是用工具"的英文形态——开篇就承认脚本能做，差别只在图层定位、字符转义、缺字体弹窗、版本属性差异、跑完有没有回读和回收这五件事，用"40 个文字层 × 8 个语言 = 320 次动作"这种能自己算的数代替百分比。另一篇是包装/说明书的印前六检，开头就声明"这不是某个客户项目的复盘，我们不公开客户稿，所以没有案例"，弧状文字和变形文字写成"先拿一份真稿跑一遍看报告"，不假装什么都能做。

四件都遵守同一套约束：定义句在前、写明"不做翻译"、写明不是 ImageTrans、只说 Windows、不写价、不写速度、每条都留一句对自己不利的话。
