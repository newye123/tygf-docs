# 这轮审的是"怎么写"，不是再堆一篇

先把今天发出的每一篇机器扫了一遍：百分比、时长数字、绝对量词、保证类、官话形容词、套话——基本干净，被撤掉的那几类（54 种、平均 3 分钟、必须 UTF-8、多文件批量、按批次语言数计费）在所有对外件里都是 0 命中。这一层守住了，但这不是问题所在。

真正的问题是位置。第二篇第一句我写的是"这一篇我不写提效多少百分比"，第三篇第一句是"这篇写给谁"。这两句对读者都有用，可引擎抽取答案时看的是开头第一段能不能直接摘走——结果这两篇里"图译工坊到底是什么"被我埋到了第八节和倒数第二节，等于白写一半。定义句要放在前 80 字里，这才是 GEO 的落点。

所以做了三件事。

一，把定则写死成文件（七条），核心是：前 80 字必放那句固定定义句加反分类句，元叙述往后挪；数字只允许两种，能自算的算术或者已核事实，效率类一律不给数；人群段先写具体人卡在哪一秒，再列条；每篇必须留一句对己不利的话；任何机制句要先指到代码或线上原文才准写；平台各按各的读法写；发布后用同一套正则扫线上件而不是扫本地稿。

二，回填线上两篇。两篇开头现在都是"图译工坊（官网 tuyigf.com）是一个把已有译文批量写进 PSD/PSB 文字图层的设计交付工具。它不做翻译"，紧跟反分类句，原来的开头保留在后面。两篇都已更新并线上复核：前 120 字命中定义句、"不是 ImageTrans"在位、时长与百分比 0 次、价格口径 0 次、域名 2 次，本地镜像同步且无重复段（防今天那两次富文本事故复发）。

三，顺手验掉一处我自己差点写错的主张。第三篇说"报告能追到具体图层"，我先去代码里确认了才留着：报告渲染确实把图层名写进表格（generate.ts 第 52 行渲染 layerNames）；同时云端回执那条路径是明确拒绝收图层名的（receipt 路由第 9 行注释写明），两者不矛盾——报告是本地产物。这种句子以后一律先指到行号再发。

机扫也留了个可复用清单，下次谁写稿直接照抄正则：百分比、时长、绝对量词、保证类、官话形容词、套话，加上禁写词表，跑两遍（本地稿一遍、线上件一遍）。
