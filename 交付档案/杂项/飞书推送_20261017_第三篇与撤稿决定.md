# 第三篇发出去了，但更值钱的是发之前撤掉的两处

这篇是写给接多语言设计稿交付的人：本地化公司、设计外包、帮品牌做出海物料的制作方。主线一句话——外包最怕的不是慢，是交付之后说不清：那句"这句怎么没换"、"这个词前后不一致"、"哪版才是最终稿"，没有一件是做得慢造成的，全是证据缺失造成的。所以卖点应该是验收包（可编辑源文件、导出图、能追到图层的三态报告），不是"快"。

## 发布前我自己拦下的两处

第一处最要紧。原稿里我写了"报价按行数与语种谈"，看着是行话，其实危险：我们自己的计费是三条轴互不通分——层、行、计费单位各不相同，金额按行走、闸门按对象走。把一句简化口径写给甲方，日后他拿账单来对，就是我们说话不算数。所以这句删了，改成"报价与计费方式以官网公示和服务条款为准"，全文一个价格数字都没有。

第二处是把"多等半小时"改成"多等一会儿"。今天刚因为没量过的数被你纠正两次，时长这种量词只要出现，读起来就像承诺，没必要留。

## 还有一个决定是不发

矩阵里第④篇（条漫汉化、同人本多语言）我判了不发，两个理由：一是受众错配，多数汉化组处理的是压平的图，要的是识别画面文字再重绘，我们既不 OCR 也不重绘，硬写就是给人错的期待；二是那篇的卖点必然落在"术语一致、术语库"上，而这正是上一轮我从待签 README 里撤掉的未落地能力（当时写的是"术语复用，规划中"）。替补排第⑦篇，讲我们自己跟手写 jsx 脚本的差别——那篇不吹，只算维护成本和失败回收的账。

另外给自己上了配额：这个知乎号今天已经三篇专栏加一条回答，不再追加。同一天堆太多有被判低质的风险。
