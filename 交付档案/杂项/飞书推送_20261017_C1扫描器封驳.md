# 封驳通报：免 PS 扫描器（C1）我自己判不通过

一句话：我把原型重写成产品模块，端到端跑通了、计数器逐项一致，但同一 exe、同一 224 MB 真稿、同一天两次跑，排版字段对不上——原型 `leading` 有 16/30 层给出值，我的实现是 0/30。原型有两条合成分支（单 run 与多 run 混合态逐 run 读行距），我重写时只搬了一条。这不是等价移植，所以不判绿，也不进主干、不接线。

影响说清楚：`leading` 是自动换行和排版判定的输入之一。丢掉它之后报告还会写"扫描成功"，等于静默少一个依据，比报错更坏。

下一轮怎么改（四条都可验证）：

一，不再手抄重写，改成包裹原型：原型原样进树，只改三处外部面——入参化（母版路径、exe 路径、taskRoot）、导出扫描入口函数、写来源凭记。改动面越小，回归风险越小。

二，判据升级：从"只看八项计数器"改成"与原型逐字段取差集"，包括每层的台账身份、层号、原文、文字类型，以及排版 38 个字段，差集必须为空（除已登记的悬挂标点一项）。上一版判据就是只看计数器，才让我假绿了一次。

三，夹具补一条断言：多 run 混合态时行距必须非空。现有四条用例没覆盖那条分支，正是它放我过去的。

四，当前重写版留在隔离树当对照材料，不进 develop。

这轮真正拿到手的东西（不是安慰）：

来源凭记这块跑绿了，四条用例全过，包括"隐藏层不进排版数据"、"缺一层信息就标 PARTIAL 并登记原因"、以及三道拒（母版不存在、没钉哈希就拒、引擎身份读不出就拒）。凭记里的哈希是实测值，真稿实跑回填跟我给执行器钉的那个值逐字符一致。

还证实了一件：引擎身份现在是真的从 exe 运行时取的，真稿跑出来是 `photocraft-cli 0.7.0 (dev build)`，上一版那个硬编码的 `f0e8d404` 已删——回执里不会再出现我们没验过的构建身份。
