# GitHub 上加了一份「可复查清单」，这是今天最省心的一条增量

先说我在五个候选里怎么挑的，再说做了什么。

## 砍掉的四个

知乎答题没做。答题理论上能吃到问题页的权重，但我拿不到那个问题现在的浏览量和排名，答错了大概率沉底，甚至替竞品导流。等有曝光读数再说。

今天第三条微头条没发。一个 9 粉丝的账号同一天发三条，堆量观感不好，而且排期本来就定的明天。

向别人的目录站提 PR 没做。那要等对方合并，而且"往第三方仓库提交内容"这类动作你没批过。

头条草稿箱里那三条旧稿我没删。删除是破坏性的，而且我不能确定你想留哪条，所以只报不动。

## 做的那一个

在我们自己的 GitHub 公开仓里加了一份《多语言设计稿交付检查清单》。选它的理由很实在：不经过任何平台审核、不会被风控拦、随时可回滚，而 github.com 是搜索引擎和 AI 都愿意抓的域；清单这种形态也是最容易被 AI 直接摘进答案的——外部数据里"可核验的清单和数字"是正向要素。

内容八节：开工前的图层体检、译文表、对账、执行中的三条硬规则、交付三件套、判断一个工具靠不靠谱的四条判据、常见替代做法的能力边界对照、已知不可解的情形。一共 26 个检查项加 3 张对照表。README 里加了链接。

两个细节值得单独说。

一，上次被你纠正掉的编码那条，我在清单里按**事实**写回去了：不是"必须存成 UTF-8"，而是"编码无需手工迁就，导入端会探测，非 UTF-8 的中文表格会自动回退 GB18030 并只给警告"。这有代码行号撑着（那张表的 628 行走探测、713 行回退）。撤掉的是假门槛，不是这个话题本身。

二，清单里第一次如实列了免费替代做法各自能做到什么、边界在哪：PS CC2019 之后的查找和替换文本、图像到变量到数据组导 CSV、jsx 脚本遍历文字图层、表格化插件和快捷动作、图片翻译类。以后写对比内容就照这个尺度说差别——它们不做译文表逐行绑定、不做回读核对、不出可复查报告——不再说"别人做不到"。

公开性我是不带登录态验的：清单文件返回 200、4,187 字节；README 返回 200、3,691 字节，链接在位，页面上官网域名出现 9 次。主张扫描全绿：没有"平均 3 分钟"、没有"54 种"、没有百分之百自动正确的说法、没有备案声明、没有 Mac 承诺，也没有"必须 UTF-8"这种写法。

## 还是要你的四下点击

头条长文（草稿箱三条同题稿，建议留"刚刚"那条、删另外两条，另两条里有一版还带着写错的编码要求）；抖音那条图文等你输短信验证码；CSDN 那篇我在编辑器里填好了但保存和发布都卡在平台侧，需要你手点；站内 title 和 FAQ 要不要换成新词面"PS 批量替换文字"，那是对外口径改动，要走礼部再随部署。
