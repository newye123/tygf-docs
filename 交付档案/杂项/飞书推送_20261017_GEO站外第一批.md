# 站外信源第一批：知乎旧文改完上线了，GitHub 公开面也建好了

这轮按你说的「继续」做，先审后做。做成了两件，卡住两件，另外审掉了五处不该发出去的话。

## 一、知乎那篇旧文改好了，已经生效

那篇文章里写着「单批最多 12 个语种，平均 3 分钟一套 A+ 和主副图（单个语种）」。「平均 3 分钟」这条我们早就在官网上有意撤掉了，因为没有真机留底，但这篇站外的一直没跟上。你也在飞书台账里把它点成了「进行中」，所以这轮我直接改了。

改法是最小改动：只把那半句换成「单批最多 12 个语种，逐语言连续执行」，其他一个字没动。改完重新加载公开页核过：整篇「分钟」出现 0 次，新句子在，链接和其余内容不变。

中间出过一次事故，跟你说清楚：知乎用的是 Draft.js 富文本编辑器，我先整段替换是成功的，但句尾残留了一个字母，我以为剩个小尾巴要清，就用「选中那个字母再按退格」——结果它把整行 20 个字一起吞了。我又在那段末尾重新把这句话补回去，才发布的。教训是这种编辑器不能做逐字修补，只能整句一次替换，我已经写进长期记忆。

## 二、GitHub 公开面建好了，这是「让模型认得出域名」那件事

先普查了一下哪些站有登录态：知乎和 GitHub 有，CSDN 直接被弹回登录页，掘金没登录，百家号那个路径是 404，B站跳登录。所以能真发出去的只有知乎和 GitHub 这两块。

GitHub 这边建了一个公开仓库，专门当个人主页的说明书用（GitHub 的规则是：建一个跟你用户名同名的仓库，里面的 README 会自动显示在你的公开主页上）。仓库描述和 README 都写了同一组信息：产品名、英文名、这个仓库是干什么的、官网域名。README 是中英双语，讲清楚了它是什么、不是什么、四步流程、数据边界、运行环境、怎么申请内测。

公开可见性我是用不带登录态的请求验的：原始文件返回 200、三千多字节；我的个人主页返回 200，页面上「Tuyi Workshop」出现 2 次、官网域名出现 9 次。主仓库还是私有的，这轮没动它。要收回也简单：那个新仓库删掉或者转私有就行，一句话的事。

为什么做这个：上一轮查到 ChatGPT 从 8 月开始会把问题拆成带站点限定的子查询去搜，模型如果认不出「这个域名属于这个产品」，就会在「有没有工具能批量改 PSD」这类对比题里直接跳过我们。解法不是加结构化数据，是让「产品名＋域名＋主体」在别人的可信页面上反复一起出现。GitHub 个人主页正好是搜索引擎和 AI 都爱抓的域名。

没做成的一件小事：GitHub 个人简介那个字段两次都没存上，第一次连接被重置，第二次页面已经死了。不影响上面这件事的效果，下轮补。

## 三、审掉的五句话（别手那份 README 稿，今天已经不能原样发）

我审的是 10-14 那份「README 宣传版待签替换稿」，它自己写着「禁写清单逐条过 ✓」。逐条对今天的盘，有五处不成立：

一是「一次 N 语言乘 M 文件」「可多文件批量」。多文件批量现在还在未提交未验收的分支上，测试站那个开关也没落地，写进公开面就是对外主张失真。删了。

二是「不训练客户译文」。这句没有留底出处，而且跟智能检测、学习那条数据通道的口径没对齐。删了，不写否认式承诺。

三是「OCR 图片识别不在本产品范围内」。这句跟我们自己的出厂文案打架：官网三处写着「使用 OCR 或 AI 功能时还会发送必要内容至对应服务」，而第三方处理方清单里 PaddleOCR 写的是「接口级能力，当前产品流程未接入」。所以不能一刀切说「不支持」，也不能暗示快支持了。改成中性的事实句：图像文字识别未接入当前产品流程。

四是「按批次语言数计费」。实际计费是三条轴互不通分（层、行、计费单位），金额按行、闸门按对象，这么写等于给了个错的口径。改成「具体以官网最新公示为准」。

五是「批次间术语复用（规划中）」。未实现的能力不写进对外文本，删了。

最后真正发出去的版本，只包含我这一轮亲手对过代码行号或者线上原文的句子。
