# 双工作台 + 批量上传：方案已出，等你拍板

## 解决什么问题

**结论：你说的三件事我查清了，方案写好了，一行代码没动。**

- 你说得对。批量功能不是"多开一个工作台"，是把原来那个工作台直接改掉了——开关一开，老界面就没了。
- 现在选文件的框，一次只能选一个设计稿。而且上一个还在扫描的时候，"添加"按钮是灰的。所以实际体验是"选一个、等它扫完、才能选下一个"。
- 想一次选多个，得改本机助手那个 Windows 选文件框。改完要重新发版、用户重装——这是唯一的大成本，所以要你拍板。

## 还有什么问题

**结论：测试站上有代码但开关是关的，正式站没受影响；另外我查出 4 个隐患。**

- 测试站 10-16 早上 8:59 上的那版，里面确实带了这批代码，但站点开关是关的，所以老工作台还在。
- 正式站（tuyigf.com）和正式代码没被碰过。
- 覆盖率检查现在只是"提示"，94% 也照跑，不拦。
- 批量里删掉中间一个设计稿，进度格子会对错位置。
- 那次上测试站的部署，谁批的、谁执行的，记录是空的——这个要补上规矩。

## 接下来怎么办

**结论：建议改成"两个工作台并排"，老的一行不动。**

- 老工作台原样保留，另开一个"批量工作台"，两个各自独立开关、独立回滚。
- 分三步走，每步都能单独撤回：① 先做界面骨架（不用发版）→ ② 再改助手多选（要发版）→ ③ 最后上队列和进度。
- 去 GitHub 看了同类开源项目（Uppy、HandBrake、Crowdin 等），可借鉴的一条核心是：**"选文件"和"开始跑"要分开**——先攒够文件，再统一开跑，而不是选一个跑一个。
- 有 7 个点等你拍板，最重要的 3 个：要不要并排（建议要）、第一步要不要现在做（建议做）、助手要不要改（建议先放一放）。
