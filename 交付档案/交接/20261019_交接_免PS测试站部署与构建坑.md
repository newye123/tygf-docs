## 2. ⚠️ 构建三步必踩的坑（本轮花一整轮才定位，先做干净环境再 build）

本机 `npm run build` 有 **3 个连环坑**，不做干净必然失败或产物损坏：

### 坑 A：Tailwind v4 自动扫描 `.next.stale`，污染 CSS 并放大 OOM
- **现象**：生成 CSS 里出现 `\uFFFD`（替换符）和 C0 控制字符（`app-:\x01 6`、`key:\x17\x1e b` 之类垃圾选择器），Lightning CSS 报 `Unexpected token Delim('\u{1}')`，严重时 Rust 分配器 OOM。
- **根因**：v4 按 `.gitignore` 自动扫描源码树。**`.next/` 在 .gitignore，但 `.next.stale/` 不在**，所以我把旧 `.next` 改名挪到一边时，它成了 1.6GB 的“源码”被扫描。
- **处置（已做）**：旧的 `.next` / `.next.stale` 已移出仓库树，现位于 `_parked/next-stale-archive-20261019/`。**接手者：确认仓库树内没有任何 `.next*`(除 `.next` 自身且是从零重建) 再 build。**
- 验证法（不跑全量构建也能定位）：`node .twprobe/probe.cjs` 直跑 `@tailwindcss/postcss` 看是否出现控制字符。

### 坑 B：`.env.local` 把 proxy 分支编译没了 → `verify-client-assistant-contract.cjs` 门失败
- **现象**：build 跑完所有步骤，最后 `BUILD_RC=1`，报错 `proxy build does not contain the server diagnostic route`。
- **根因**：`.env` 是 `NEXT_PUBLIC_ASSISTANT_DIRECT=0`（proxy 模式，部署站正确模式），但 **`.env.local` 是 `=1`（direct 模式）且优先级更高** → 编译器把 proxy 分支（`fetch('/api/local-assistant/photoshop/diagnostic')`）常量折叠删掉。
- **处置**：build 时显式用 shell 变量覆盖（已验证 `@next/env` 不会覆盖已存在的 `process.env`）：
  ```
  NEXT_PUBLIC_ASSISTANT_DIRECT=0 npm run build
  ```
  部署站必须走 proxy 模式；direct 模式只用于本机直连助手（127.0.0.1:49152），**不要**把 `.env.local` 的 `=1` 带进发布构建。

### 坑 C：CSS 优化阶段 Rust 分配器 OOM
- **现象**：`memory allocation of N bytes failed` → `BUILD_RC=127`。
- **处置**：给足堆。`NODE_OPTIONS=--max-old-space-size=6144`。
- 本机冷缓存构建约 **10 分钟**（热缓存 ~2 分钟）；`timeout` 给 **≥1500**。被 kill 的构建会留 `start-server.js` 子进程持锁 `.next` → 杀光该 worktree 全部 node 进程 + `rm -rf .next` 重建（见 MEMORY「本机构建链」节）。

### 推荐 build 命令（一步到位）
```bash
cd worktrees/develop
# 1) 确认仓库树内无 .next.stale / 残留 .next（Tailwind 会扫 → 坑A）
ls -d .next* 2>/dev/null   # 只应看到 .next（且将被重建）
# 2) 干净重建
rm -rf .next
NEXT_PUBLIC_ASSISTANT_DIRECT=0 NODE_OPTIONS=--max-old-space-size=6144 timeout 1500 npm run build
# 3) 验证：末尾应 BUILD_RC=0；且 .next/static/chunks 内含字符串 /api/local-assistant/photoshop/diagnostic
```
> 注：本机 `.next` 当前已被我清掉（移进 `_parked`），所以这次是冷缓存 ~10 分钟。

## 5. 已知陷阱（避免重复踩，详见 MEMORY.md）

- **假 0 / 假绿**：`npx tsc --noEmit | tail -20; echo $?` 取的是 tail 的码 ⇒ 用 `> log 2>&1; echo $?`。`npm run` 与 `node` 直跑结果可能不同。`&&` 链前序 grep 无命中会短路后续。会话摘要计数常与正本不符，以实际文件为准。
- **`node` 进程内 spawn 子进程被拦（EBUSY）** ⇒ 这类调用必须改「mjs 纯变换 + bash 编排」。
- **对照实验**是“运行时才发作、症状是啥都不发生”类缺陷的唯一硬证据：改回旧写法跑同一探针，看是否复现；实验后必须恢复 + 负向断言复验 + `git diff --stat` 对账。
- **`test:seo-consistency`** 读 `SITE_URL`（不是请求 Host），对非同 origin 目标必红；跑绿要先 `SITE_URL=<target>` 起同 origin dev server（必须 `run_in_background`，`nohup &` 会被杀）。
- **`sudo pm2 list` 是空表**（root 与 ubuntu 的 PM2 home 不同）⇒ 用不带 sudo 的 `pm2 list` + `ss -ltnp | grep 3001`。
- **跨工作树复制 `.env` 必须改 `APP_ORIGIN`**，否则写操作全报 `AUTH_ORIGIN_REJECTED`。
