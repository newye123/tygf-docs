## 一句话

您要的两件事**代码都做完了、门都跑绿了**：

1. `tuyi@tuyigf.com` 的信**自动转到 `353099912@qq.com`**；
2. 每次收到邮件，**飞书里自动提醒您**，而且是在**您已经在看"新的内测申请"的那个会话里**（同一个机器人、同一个地方），不会多出一个要盯的角落。

**只差两件只能您做的事**（其余我一次做完）：给一把 Cloudflare API 令牌（3 分钟），以及点一下 Cloudflare 必然要发的那封验证邮件（1 分钟）。

## 一、我先查清了一件事：您说的"同一个位置"到底指哪个

我一开始以为是我给您发报告用的那个飞书通道。**实测发现是两个不同的通道**（比对了指纹，没打印任何一个地址）：

- 站内"新的内测申请"用的通道（`ADMIN_NOTIFY_WEBHOOK_URL`）；
- 我发执行方案/报告用的通道（您 10-14 指定的那一个）。

⇒ 所以本轮严格用**前者**：提醒模块直接复用申请通知那套发送代码，**天生落在同一处**，不另配 webhook、也不会多一个地方要盯。

## 二、整条链路长什么样

访客/用户发信到 `tuyi@tuyigf.com`
→ Cloudflare 邮件路由（**一条规则、两个动作**）
→ ① 转发到 `353099912@qq.com`（您的信箱收到）
→ ② 同时触发一个邮件 Worker
→ Worker 带着共享密钥调站内接口
→ 站内发飞书提醒（**与申请提醒同一个机器人、同一个会话**）

一条规则两个动作，所以不会出现"提醒有了但信没进信箱"或反过来。

## 三、我做的四件事（都已通过门）

- **站内提醒**：复用申请通知的同一个飞书通道；**只发线索**（发件人、主题、正文前 300 字、时间），**不把邮件全文发进系统**（正文留在信箱里）；同一封信不重复提醒。
- **站内入口接口**（它在公网上，所以按"半开放"对待）：共享密钥 + **定时安全比较**（不是简单 `===`）+ **没配密钥直接拒绝**（绝不"没配也放行"）+ 按 IP 限流 + 请求体 16 KB 上限 + 每个字段长度上限。
- **Cloudflare 邮件 Worker**：密钥走 secret 绑定，**不写进代码、不打进日志**。
- **一键配置脚本**：建/复用目标地址 → 上传 Worker → 建/更新规则，幂等，**不打印任何凭据**。

**另外**：我**没有**为这件事新建数据库表。邮件的档案就是邮箱本身，飞书那条是"提醒"不是"台账"；新建表要改数据库结构、要迁移授权、还要改部署脚本的迁移白名单，动静太大。以后您想在运营台里也翻这些邮件，我再单独加。

**一个位置上的说明**：这个入口只能放在**生产站**——因为测试站整站在 Cloudflare Access 后面（从外面访问一律 403），Worker 够不着它。生产站那边要随这一版上线一次。
