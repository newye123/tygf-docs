## 0. 一句话

原方案把工程预算放在"让服务端能证明活真的干过"上。这一轮从项目全局看，**现阶段真正的瓶颈不是这个**：收钱链还没开闸（支付族开关按红线必须为 false），而第一指标"首跑成功率"已经 28 天没有读数。所以 v2 的排序是：**先让指标能读数 → 再修会让客户丢授权的两处 → 账务只做零客户端那两件 → 全量对象证据等开闸后再谈**。

## 1. 上帝视角：这次整改会碰到项目的哪些面（每条带实测出处）

### A. 第一指标当前没有读数，而方案的一条改动会直接压低它

- 读数面：`总控/工具/northstar-ledger.jsonl` 全文 **4 行**，末行 `recordedAt 2026-09-25T14:40:19Z`（＝北京时间 09-25 22:40），文件 mtime 同为 `2026-09-25 22:40:19`；`northstar-manual-actions.mjs` mtime `2026-09-25 05:24`。本机 Qoder 定时任务表返回 **0 条**。
- 含义：从 09-25 到现在（10-23 20:54）**28 天没有新读数**。第一指标是 09-25 由 Owner 定的"首跑成功率"（口径件 `总控/口径_第一指标改首跑成功_20260925.md`）。它原先挂在哪个载体上跑（另一台机／服务器 cron），**未核实**。
- 为什么这条压过整改本身：整改六件里 P0-B"读不到就退出"是**首跑路径上的负向改动**——新装机器若首次配对时撞上文件被杀软占用，现在的行为是"回落默认配置、提示重新授权"（能继续跑），改完是"退出、且产品内没有出口"。没有读数，就没人能证明这次改动是净收益还是净伤害。

### B. 收钱链还没开闸，"防白拿"这件事今天没有现值

- 出处：`scripts/flags-drift.mjs:81` 把 `alipay|manualPayment|creditPacks|betaExclusiveBonus` 定义为支付族；`:139-140` 任一环境该族为 `true` 即记 `⚠ PAY` 并计入违规。项目红线同样是"支付 flag 保持 false，未批准不得翻转"（AGENTS.md 治理规则）。
- 含义：原方案 P1-A 的全部动机是"被改的客户端能不能白拿钱"。在支付未开闸、内测按积分跑的阶段，这条**没有当期收益**；而第二轮深钻还证明了一件事——就算开闸，P1-A 也挡不住真正的漏（少报），因为结算基数来自客户端上报（`src/lib/server/execution-batch.ts:2058-2065`、`:2218-2227`）。

## 2. 执行方案（v2 排序，八步）

顺序不能换。第 0 步不做，后面每一步的验收都是空话。

### 第 0 步｜先把第一指标恢复成能读数（先于一切整改）

1. 确认 `northstar-manual-actions.mjs` 现在还能不能跑通（采集根配置、交付件目录两处挂载），出一次**当日**读数。
2. 定载体：这个日更要么挂本机 Qoder 定时任务（当前 0 条），要么明确挂服务器侧调度——**不再挂"进程内定时器"**（项目既有纪律：进程内定时器不作可靠性边界）。
3. 读数口径沿用 09-25 那份：首跑成功率＝首次拿到交付件的去重设备 ÷ 当期新激活，14 天窗。

**验收**：`northstar-ledger.jsonl` 出现一行 `recordedAt` 为今天的记录；或者明确记"取不到数、原因 X"。**【需 Owner 一句】**：挂在哪台机、用哪个调度口。

### 第 1 步｜身份核对（1 分钟，判据换对象）

- 客户机取 `GET http://127.0.0.1:49152/ping` 的 `version` 与 `assistantBuildId`。
- 与**客户浏览器所连那台站点**的 `GET /api/runtime-provenance` 里的 `expectedAssistantVersion` / `expectedAssistantBuildId` 逐字比对（`src/lib/server/runtime-provenance.ts:84-88`，路由无鉴权）。
- 不再拿"已发布安装包清单"当比对对象——那是清单，不是拦人的那道闸（`src/lib/server/assistant-execution-contract.ts:75-84` 要求构建号等四项逐字相等）。
- 对不上 ⇒ 判"发布不同步"，先修发布，再谈任何行为结论。

**验收**：工单里两条原始输出并列，且两值同拍取自本次。

### 第 2 步｜3.7.25 热修（与多稿工作台第 2 步并成同一支 bump，五件一个包）

1. **停写自定义 ACE**：`download/local-assistant/persisted-state.js:18-26` 现在拿裸 `USERNAME` 当授权目标，还把"断继承"和"授权"塞同一条命令；改为不再主动写 ACE。
2. **启动只读修复**：配置文件存在但读不了时，跑一次 `icacls <绝对路径> /reset`（绝对路径、超时 5 秒、记退出码）把继承权限恢复回来；修不好进第 3 条。**不引入 `whoami`/SID 缓存/PowerShell 兜底那一整套**（原方案 P0-A 的写法，故障面比收益大）。
3. **写盘闸下沉到配置层**：`saveConfig`（`server.js:766-773`）在拿不到"读成功／文件本就不存在"这两种状态时**直接抛错、绝不写盘**。只在启动逻辑里拦不算完成——`ensureMachineId` 在三个请求路径上都会触发写（`:4793`、`:6241`、`:6750`、实现 `:8129-8142`），而且每个 HTTP 响应都会读一次配置（`:2606-2628` 经 `cors()`），读失败会被呈现成"未授权"、把用户推上重新授权＝写盘那条链。
4. **首跑分级（新增，v2 的关键改动）**：
   - 从未配对成功的机器（无 `assistantToken`／无授权记录）：读不到就按首次启动走，**允许回落默认配置**，因为此时没有东西可丢；
   - 已配对机器的"读不到"：不覆盖、停下来，并走第 5 条的出口；
   - 判据只看本机已有的配置字段，不需要新版本合同。
5. **自带离线恢复出口**：托盘致命闭锁（`TrayHost.cs:55-63`、`:117-132` 现在每 5 秒无条件重拉、不记失败）＋ 一条**看得见**的指令。可见性必须绕开两个既有事实：日志落盘前会把绝对路径替换成 `[path]`（`server.js:172`），且普通输出根本不进日志文件（只有 warn/error 进，`:195-206`）。做法：把"该删哪个文件"写进一个**不脱敏的本机明文诊断文件**并在托盘气泡里点名该文件。理由：重置接口早已停用（`server.js:8060-8066` 返回 410）、卸载保留会话文件（`installer.iss:82-84`），没有这条出口就是永久锁死。

**验收**：① 已配对机器上把配置做成不可读 → 不写盘、托盘停拉并给出删哪个文件；② 未配对机器上同样故障 → 能按首次启动继续；③ 恢复可读后连续重启 3 次不回退；④ `npm run test:*` 中与助手状态持久化相关的门全绿。**【需 Owner 一句】**：出包与测试站部署。

### 第 3 步｜发布闸：这轮只加约束，不动开关

- **保留** `--allow-unsigned-beta` 与生产清单，但要求带 `--beta-reason` 与 `--beta-expires YYYY-MM-DD`，到期后开关自动失效；调用参数留进发布记录（谁、何时、为什么）。
- **beta 目录要么完整做、要么这轮不做**：只做目录会空转——下载页读取器固定找安装包同目录那份 `local-assistant-release.json`（`src/lib/server/local-assistant-release.ts:44`），换个文件名就恒判"不可用"；而且 beta 助手的构建号会被第 1 步那道身份闸逐字相等拒掉（`assistant-execution-contract.ts:75-84`）。要真隔离，至少同时改：清单名按渠道解析 ＋ 身份闸按渠道取值。
- **下载页如实标注"当前版本未签名"**——这半件最便宜，不等证书。

**验收**：正向断言必须包含"测试站还能出包"（不带 beta 通道也能发未签名测试包），否则本步不合格。

### 第 4 步｜账务两件（服务端，零客户端改动）

目标写清楚：**不是防白拿，是让少报要付解释成本**（白拿的口子在第 02 节 B 条已证明挡不住）。

1. **最小证据闸**：`objectEvidenceDigest` 现在只看"是不是非空字符串"（`execution-batch.ts:1384-1399`），补形状校验 `^[a-f0-9]{64}$`，并在存在 `VERIFIED` 行时拒 `sha256("[]")`（值 `4f53cda1…02b945`，本会话实算）。
2. **少报收口**：结算实扣取 `max(报价 × 下限比例, 按上报算出的值)`，整批零完成仍全额退；完成率低于阈值才允许退款且必须逐行带 `reasonCode`（回执白名单已含该字段，`execution-batch.ts:2328`）；服务端按设备统计低完成率批次占比，超常进 `MANUAL_REVIEW`（现有形态，`:2231-2240`）。

**待 Owner 定数**：下限比例、完成率阈值。我不替你编。
**验收**：四条负控（什么都不发／发 `sha256("[]")`／摘要形状非法／低完成率无逐行原因）均不产生结算记录；正向原样回执结算不变。

### 第 5 步｜回执墓碑 2 行版 ＋ journal 明文面处置

- 墓碑只在**服务端确认已结算**的成功路径写（`server.js:4381`、`:7731`）；永久拒绝（`:4399`）与防御终态（`:4386`）写 `rejected` 并单独计数。**不要写进共用的清理函数**——那会把"被拒收"记成"已 ACK"，把真未知抹掉。
- 现存历史样本：只做只读分类，不删、不重投、不改结算，并**明确豁免**于任何清理逻辑。
- journal 明文面（原方案没看见的）：`.inputs.json` 存整份执行清单，含原文与译文（`execution-manifest.js:158`、`:174`；写点 `server.js:4185-4208`）；`receipts/*.json` 存本机绝对路径（`receipts.js:60-63`）。两者都走不加密、不收 ACL 的写盘路径（`server.js:4147-4158`）。原方案 P0-D 第 4 条假设的"30 天清理"**没有执行体**（启动唯一清理是学习记录 `purgeExpired()`，`server.js:8169-8174`；`execution-journal.js` 搜删除／清理／保留期 0 命中）。处置二选一：给这些文件加同样的权限收紧，或建真正的保留期清理并豁免历史样本——**不许只在文档里写"30 天清理"**。

**验收**：成功批次 ACK 后重启，`ACKED_SKIPPED` 加 1、`COMPLETION_UNKNOWN` 不增；人为造一条无墓碑无输入的 journal 仍计 1 条未知；journal 明文文件的处置有实测读数（`icacls` 原文或清理生效证据）。

### 第 6 步｜本地 HTTP 卫生三件（便宜，但别当安全修复卖）

`Vary: Origin`、私有网络访问预检响应、Host 白名单（端口从 `PORT` 取，别写死 49152——端口可由环境变量改，`server.js:143`）。**MAJ-1（本机进程可伪造来源）显式记为接受风险**，不写"已修复"。

### 第 7 步｜证书与四处签名位（排最后）

Inno 配置覆盖 setup／内层引擎／托盘／卸载器四件 ＋ RFC3161 时间戳。询价与主体资格未核实前不对外承诺时间。

### 第 8 步｜全量对象证据：四件前置齐了再开工

对象清单表（`ExecutionAttemptObjectResult` 建了但全仓 0 引用）＋ 行映射 ＋ 请求体上限方案（500 对象单独就 79,513 B，上限 65,536）＋ 隐私合同变更（四层同步＋fixture＋Owner 签字）。**并且要等支付开闸**——在那之前它没有当期收益。

## 5. 未核实（不假装已解决）
