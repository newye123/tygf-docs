结论：这个方案不行，实测已打回。

我今天在正在运行的 Photoshop 22 上做了对照测试。结论不是「阈值没调好」，而是「清缓存这个动作本身不还内存」。

三个数：

- 文档开着时清历史记录：历史从 32 条降到 2 条，确实清掉了；但 Photoshop 的私有内存 8,481.4 MB 一位没降。
- 没有文档时清历史/撤销：工作集 3,990.5 MB、私有内存 8,411.5 MB，之后 0 秒、5 秒、15 秒、30 秒四个时点完全不变。
- 真正让内存降下来的是关闭文档：私有内存 8,481.4 降到 8,411.4 MB，降了 70 MB。这一步我们每稿已经在做（执行器关闭文档）。

所以「到阈值就把当前稿处理完、再清缓存」不会让 Photoshop 变轻，只会多一次没有效果的动作；如果用户自己开着稿，清历史还会把用户的撤销记录一起删掉。ALLCACHES 更不能用，它会清剪贴板。

20 稿真机的结果也支持不建：20/20 成功，末 5 稿中位耗时 72,339 ms，比首 5 稿 75,794 ms 低 4.6%；失败率 0% 到 0%。没有变慢，也没有失败率上升。

GitHub 上找到的参考也不能直接用：

- WinMemoryCleaner、memreduct 是 Windows 系统级内存清理器，要管理员权限，作用全系统，不是 Photoshop 专用。
- photoshop_deep_cleaner_plus 清的是 PSD 文件元数据和体积，不是内存。
- Adobe 社区有批处理脚本在循环里调用 app.purge，但没有给出「清完降了多少内存」的读数；代码存在不等于有效。
- 没有找到成熟的「Photoshop 内存到阈值自动清缓存」开源实现；而且 GitHub 代码搜索要登录、API 也限流，这次检索不是穷尽的。

如果你还是想要一个「保险丝」，唯一有效且安全的做法不是清缓存，而是：Photoshop 私有内存连续两个稿件边界超过 12 GB（16 GB 机器按 60% 总内存下调到 9.6 GB），或者系统可用内存低于 1.5 GB 时，暂停投放新稿，提示用户保存工作后手动重启 Photoshop。绝不自动杀进程、不自动清缓存、不关闭任何文档。这个「暂停/恢复」目前批量链还没有，要新建状态机，成本不小；以现在的 20 稿数据，我不建议现在做。

我的建议：不实现这个清缓存保护闸，保留现有只读内存读数。产品代码这轮零改动、未提交、未部署。方案和原始证据在：

- 执行方案_20261020_批量内存阈值清缓存_对抗式审查与实测.md
- 证据_20261020_PS清缓存实测/（两份原始 JSON + 探针脚本）

一句话记住：清缓存清的是撤销列表，不是内存池；真正释放内存的是关文档，而这一步我们每稿已经做了。
