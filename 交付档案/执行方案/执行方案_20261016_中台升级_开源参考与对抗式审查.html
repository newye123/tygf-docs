中台升级：开源参考 + 对抗式审查

「继续看看怎么升级现在这个中台，继续到 github 上参考开源项目，然后使用对抗式审查给我一个执行方案」。先摸清现状，再看开源项目，四个候选方案逐个冷刀，裁决：不换平台，只做分层升级（元模型 + 多视图 + 字段级权限），飞书投影协议不变。

开源参考 8 家四方案裁决：丙采用P0 元模型基础（约半天）发出即执行

01判定

Verdict · 分层升级，不换平台

中台已有治理链路（发布预检、台账投影、回读闸、控制面），缺的是「可插拔的视图层与字段级权限」。整体替换为开源多维表格（NocoBase/NocoDB）会把飞书投影协议、Prisma Schema、计费体系、40+ smoke 合同全部推倒重来，AGPL-3.0 还带合规风险；纯前端组件又解决不了字段级权限。正确方案：数据层不动，视图层引入开源参考的「表/字段/视图/自动化」元模型，控制面层保留并加强，飞书投影作为首个外部视图客户端。

关键事实

NocoDB 与 NocoBase 同源公司，定位不同：NocoDB 是「数据库 → 表格 UI」，NocoBase 是「业务对象 → 系统构建」。Baserow 协议 MIT 最宽松，其余主流多维表格多为 AGPL-3.0（改动需开源，对内测版商业化有合规风险）。我们中台已有 Prisma Schema 与发布预检/台账治理，不缺「数据库」，缺的是「可插拔的视图层与字段级权限」。

03对抗式审查：四方案，逐个冷刀

候选描述最狠的刀裁决
甲中台整体替换为开源多维表格/低代码平台，飞书投影直接对接其 API与现有 Next.js 代码、Prisma Schema、飞书投影协议、计费/信用体系、本地助手协议全部不兼容；AGPL-3.0 改动需开源；40+ smoke 合同需重写；数据迁移成本极高弃
乙保留现有中台，借鉴开源能力做模块化升级（插件架构 + 字段级权限 + 多视图 + 工作流）代码量大，引入插件架构侵入性大；飞书投影协议与中台权限模型需重新对齐；过度设计风险（现有 admin 已有权限与备份）部分采用（字段级权限、多视图、工作流骨架）
丙中台分层升级：数据层保留 Prisma/SQLite；视图层引入「表/字段/视图/自动化」元模型；控制面层保留并加强；飞书投影为首个外部视图客户端元模型抽象层需新增代码；现有表结构需逐步对齐元模型；对现有 admin 页面有渐进式侵入采用（主方案）
丁不做大改，仅接入开源前端组件（@tanstack/table 已在用，追加拖拽/看板），能力不变不解决中台天花板（无字段级权限、无工作流、无多视图）；对「升级中台」诉求无响应降 P2（只做 UI 组件微升级）
攻防要点

①「换平台」解决不了「飞书投影协议」——协议是我们自己定的（机器列/Owner 批注），换平台反而要重构协议；②「纯前端组件」解决不了「字段级权限」——权限在后端 Prisma + API 路由，前端组件只能装饰；③元模型方案可渐进：先让飞书投影走新元模型，再把 admin 页面逐页迁移，不中断现有合同。

层职责开源参考现状

P0

元模型基础 + 飞书投影对齐（约半天，本轮）

新增元模型表：Table、Field、View、FieldPermission（字段：可读/可编辑/隐藏，角色级）、WorkflowTrigger（字段变更触发器骨架）。Prisma Schema 增加元模型模型，与现有业务表并行（不改现有表结构，零破坏）。飞书投影协议对齐新元模型：「机器列」映射到元模型字段并受字段级权限保护；「Owner 批注」列继续永不触碰。验收：夹具覆盖元模型读写；投影空跑 update=0；控制面全绿。

P1

多视图 + 插件式区块 + 工作流自动化

视图层：表格/看板/日历/画廊四视图，保存过滤与排序；视图区块插件（中台页面可嵌入自定义区块）；工作流：字段变更 → 自动化动作（更新另一字段、发通知、触发预检），先骨架，动作按需扩展。验收：新增一个中台页面使用多视图 + 区块；工作流端到端一次。

P2

AI 字段 + 多租户（后续，P1 全绿后启动）

AI 字段/自动提醒（Teable/Baserow AI 字段参考）；中台多租户与商业化（Plane 商业版参考：工作流审批门、审计日志）。

飞书投影协议（不变，作为外部视图客户端示例）

你在飞书手改「Owner 批注」→ 永不覆盖，日检读取并落实；机器列手改→视为你的命令，采纳+记账，元模型字段级权限校验；任务ID 手改→恢复原值+告警；新增整行→内容齐进「等您定」、空行→告警；删行→不生效，下次投影补回来，要停任务请在批注写「不做/删掉」。

05执行顺序与回滚

Sequence

① 元模型模型 + Prisma 迁移（sqlite，可回滚为删除新表）；② 飞书投影协议对齐 + 夹具验证；③ P1 多视图/区块/工作流，逐页迁移 admin；④ P2 AI 字段/多租户（按需）。

Rollback

元模型为新增表，删除即可恢复；飞书投影协议保留旧版兼容；不改现有业务表与 smoke 合同；无不可逆步骤。
