## 1. 五个硬缺口（对抗式审查的结论）

### G1　新壳没有「扫描设计稿」入口，执行门禁会死锁

- 批量执行前强制要求全部稿扫描完成，提示语写着"请回到「准备素材」点「全部扫描」"：`workbench-view.tsx:2495-2502`。
- 但新壳的 props 里根本没有扫描动作（只有换文件夹、重新扫描文件夹、下一步）：`attribution-stage.tsx:24-45`。
- 「全部扫描（按顺序）」的唯一按钮在老界面 `design-file-card.tsx:1368-1379`（处理函数 `:781-791`），而老界面在新壳激活时被 `hidden`：`workbench-view.tsx:3569`。
- 后果：用户选完文件夹、拍完板、点下一步，走到执行时被拦，却找不到按钮。
- **处置**：新壳文件夹栏下加一条"扫描设计稿"状态条（未扫描 N 个 → 一键扫描 → 进度 N/M → 完成消失），动作桥接到 `DesignFileCard` 的现有队列，不复制一套扫描逻辑；阻塞原因（PS 没开）要显示出来。

### G2　语言必须等读表，新模拟的矩阵在现状下是空的

- 语言唯一来源是已解析表：`workbench-view.tsx:1964-1970` 取 `parsedTables[...].languageColumns`，没读表就是空数组。
- 统计卡自己就写着"表还没读，读表后才有数"：`attribution-stage.tsx:171`；矩阵空态也这么写：`:574-578`。
- **处置**：第 1 步按归属选择**自动读表**（只读被选中的表，不读 orphans），解析后写进 `parsedTables`，语言列与矩阵随之出现。读表用现有端点 `local-assistant-client.ts:1329-1357`（5 MB 上限、四道边界），解析用 `table-file.ts:38-91`（与 CsvStep 同一套规则，按交付物选 sheet）。**不新增助手端点。**
- 注意：不能复用 `applyBulkTables`（`workbench-view.tsx:2141-2164`），它会把焦点拉到校对页并切当前稿；新增只写 `parsedTables` 的 `applyStageTables`。

### G3　`missing` 行在新壳里没有任何出口，第 2 步会永久锁死

- 新壳只有 `conflict` 行画了"选一个"：`attribution-stage.tsx:419-441`；SKU 面板只读：`:470-519`。
- 第 2 步的锁：`locked: !parsed ? '导入译文表后开始' : undefined`（`workbench-view.tsx:3142`）。
- 后果：某稿没表，用户既不能补、也不能跳过，只能退回老界面。
- **处置**：`missing` 行给两个动作——「去补表」（提示放表进文件夹后重新扫描）和「这稿先不做」（排除出本批，可撤销）。**不提供"随便选一张表"**，因为内核明确"不跨交付物借表"（`sku-attribution.ts:417-421`）。

### G4　归属记忆会绕过"一张表只够一份稿"

- 选择优先级是"人手覆盖 > 记忆 > 自动"：`workbench-view.tsx:1947-1958`，记忆键只有 `SKU·交付物`（`attribution-memory.ts:32-34`）。
- 冲突规则是"同 SKU 同交付物多份稿、只有一张候选表 → conflict"（`sku-attribution.ts:377-386`）。
- 结果：用户给 A 稿选了表，B 稿会被同一条记忆自动填上同一张表，`pendingConflicts` 变 0，界面看起来"都定了"。
- 确认弹窗也只拦"同一稿重复"：`workbench-view.tsx:2192-2193`，不拦"同一张表给两稿"。
- **处置**：在 `stageResolved` 末尾加去重守卫——一张表只能给一份稿；记忆撞车时不给 B 预选，落回 `conflict` 让用户定。`confirmBulkImport` 同步加"同表多稿"拦截。

### G5　新壳文案 100% 硬编码，违反 WF-010 的文案键纪律

- `attribution-stage.tsx` 没有导入 `useSiteCopy`（导入区 `:12-22`），从标题到图例全是硬编码（例：`:193`、`:194-196`、`:461`、`:563`、`:637-642`）。
- 规格里的教训：三处并存会导致"改了不生效"（`product-specs/workbench-flow.md:62-70`）。
- **处置**：新壳所有用户可见文案收进 `siteContent.workbench.step1*` 一组键（约 12 组），组件统一 `useSiteCopy('workbench')`；计数类用 `fillCopy`。验收加一条 grep：新组件里不允许再出现中文文案字面量（注释与 `aria-label` 走同一套键）。

### 另外一条：批次边界

- 现状选完文件夹仍是 0 稿，要点「把 N 个稿加入本批」：`attribution-stage.tsx:245-258`，处理函数 `workbench-view.tsx:2018-2032`。
- 新模拟是"文件夹就是这一批"，这条要改：**扫描结果回来就自动填批次**（上限 12，`design-file-card.tsx:121` 与 list-folder 默认 12 一致），换文件夹时如果当前批不是空的，先确认"换文件夹会换成新的一批"。
- 手工加稿 / 粘贴路径仍走老入口，不能被自动填充覆盖（用 `batchSource` 标记来源）。

## 3. 交互逻辑（施工按这个状态机写）

### 3.1 一屏五块

```
页头：准备素材 (?)                       [重新扫描] [下一步 · 逐稿校对 →]
文件夹栏：📁 路径  12 稿 · 51 表 · 只读   [换文件夹] [更多 ▾]
扫描条（仅未扫完时出现）：还有 9 个稿没扫描  [扫描设计稿]  进度 3/9  [停止]
四个统计：本批设计稿 / 已配语言格 / 处要你拍板 / 有表无稿
左右两栏：左＝要你处理的（冲突/SKU/有表无稿）  右＝选中那件的证据与选择
整宽矩阵：9 行 × 12 语言，格可点
```

### 3.2 每份稿的状态

| 状态 | 触发 | 界面 | 下一步 |
|---|---|---|---|
| `stale` | 加入批次、未扫描 | 灰点 + "待扫描" | 扫描条 |
| `scanning` | 扫描中 | 转圈 + "扫描中" | 等 |
| `prepared` | 扫描完成（有 summary） | 绿点 | 进入表的判定 |
| `needs-choice` | 冲突/同名不同内容 | 琥珀点 + "要你拍板" | 选一个 |
| `needs-table` | 没有候选表 | 红点 + "没有表" | 补表 / 先不做 |
| `reading` | 正在读表 | "读表中…" | 等 |
| `ready` | 表已解析 | 绿点 + 语言数 | 可下一步 |
| `read-error` | 读表失败 | 红点 + 原因 | 重试 / 补表 / 先不做 |
| `excluded` | 用户点"先不做" | 灰掉 + "已跳过（撤销）" | 可撤销 |
| `dup-collapsed` | 同名且指纹相同 | "2 份相同，按 1 份算（分开）" | 可恢复 |

**下一步可用条件**（缺一不可）：

1. 所有未排除的稿都 `prepared`（扫描完成）；
2. 所有未排除的稿都 `ready`（表已读、语言已知）；
3. 没有 `needs-choice` / `needs-table` / `read-error`。

不满足就点名："还有 2 件没定：5857 · 两套表、6897 · 独立站没表"，按钮禁用但可点出提示（不做"点了没反应"）。

### 3.3 进入第 1 步的自动序列

1. 选文件夹 → `list-folder`（现有）→ 拿 `FolderScanResult`。
2. 自动填批次：`scan.designs` 逐条 `addMultiPsdEntry`（上限 12，超出提示截断）。
3. 算归属计划 `buildAttributionPlan`（现有内核）。
4. 算选择：人手覆盖 > 记忆 > 自动，**末尾跑去重守卫**（G4）。
5. 对每个有选择的稿并行读表（并发 2）：`readPreparationTable` → `parseTableBytes({deliverable})` → 写 `parsedTables` + `stageTableSource`。
6. 语言/矩阵从 `parsedTables` 派生，读一张亮一行（骨架先占位，不整屏等）。
7. 冲突行按候选表读 probe（sheet 名、语言列、行数），用于"两套表结构不一样"的说明；**只读候选，不读 orphans**。
8. 扫描条出现；用户点「扫描设计稿」→ 桥接老队列 → 进度回传；PS 没开时显示"Photoshop 未连接，先打开 PS"。

**为什么扫描不自动开始**：扫描要开 Photoshop、9 份稿可能要几十秒到几分钟；自动启动会让"选个文件夹"变成重操作，而且 PS 没开就直接失败。手动一键 + 明确进度，代价是一次点击，换来可预期。

### 3.4 拍板一条冲突

- 右栏只留一句结论 + 「看证据（N 条）」折叠。
- 候选卡片显示：文件名、相对路径、交付物、**结构摘要**（几个 sheet、语言列、行数）。
- 两个按钮：`这一组 N 份稿都用这套`（默认）／`只这一份`（高级）。
- 选完立刻读这套表 → 该组稿变 `ready`，自动跳到下一条待定；toast 说清"影响了几份稿、几个格"。
- 记忆写的是 `SKU·交付物`，所以"这一组都用"与记忆语义一致；"只这一份"不写记忆。

### 3.5 同名稿（两份文件同名）

- 分组键：`basename`（小写）。
- 两份都扫描完成且有 `summary.fingerprint`（`preparation-contract.ts:279-280`）：
  - 指纹相同 → **折叠成一份**显示"2 份内容相同，按 1 份算"，提供「分开做」恢复；**不静默删除**。
  - 指纹不同 → 冲突卡："两份同名、内容不同"，选「两份都做」或「只留一份」。
- 未扫描 → 显示"先扫描才能比对内容"，给扫描按钮；不猜。

### 3.6 有表无稿 / 没表

- 有表无稿：保持现状（列出 9 个 SKU），常驻一句"不会被丢，也不会配错稿"，处理办法折叠。
- 某稿没表：`needs-table`，两个动作：
  - 「去补表」：提示把表放进文件夹 → 点「重新扫描」；不自动跨交付物借表。
  - 「这稿先不做」：排除，计数与矩阵同步去掉，可撤销。

### 3.7 换文件夹 / 重扫 / 并发

- 每次换文件夹 `rootEpoch += 1`；所有读表任务带 epoch，回来的旧结果直接丢。
- 换文件夹时若当前批非空：确认"会换成新的一批（当前选择与已读表清空）"。
- 同根重扫：**只增不删**；消失的稿标"文件不在了"，不自动移除；已读表保留。
- 每份稿一个读表 token；改选择后旧 token 作废，避免后到的旧结果覆盖新选择。

### 3.8 引导与帮助的触发

- 首登 4 步只在"计划已算出来 + 有稿"后弹；没数据不弹（不指空）。
- `localStorage['tygf:workbench:step1-guide:v1']='1'`；内容大改升 v2。
- 页头「?」→ 抽屉：5 条（选文件夹 / 扫描设计稿 / 拍板 / 看矩阵 / 下一步）+「带我看一遍」。
- 左栏、矩阵标题旁小「?」→ 一句话气泡；不做 hover-only。
- Esc 关、←/→ 翻步、焦点进卡片、窄屏底部卡片。

### 3.9 下一步

1. 校验 3.2 的三条；不满足 → 点名 + 不跳。
2. 若当前稿没有 `parsedTables`，自动切到第一份 `ready` 的稿（否则第 2 步会因 `!parsed` 锁住，`workbench-view.tsx:3142`）。
3. `setActiveStage('translation_review')`。
4. **不再打开旧批量导入弹窗**（`handleStageImport` 只留老界面用）。

## 4. 数据层改造（不碰内核）

### 4.1 新增 `src/lib/workbench/stage-table-loader.ts`

```ts
type StageTableStatus =
  | { status: 'idle' }
  | { status: 'reading'; tablePath: string }
  | { status: 'ready'; tablePath: string; parsed: ParsedCsv }
  | { status: 'error'; tablePath: string; message: string; code?: string }

loadStageTable({ root, draftKey, draftPath, tablePath, deliverable, epoch, token }): Promise<ParsedCsv>
```

- 内部：`readPreparationTable` → `parseTableBytes(bytes, name, { deliverable })`；
- 并发闸：同时最多 2 张（`runWithConcurrency`）；
- 取消：epoch + token 双校验，过期结果丢弃；
- 缓存：`parsedTables` 已有且 `stageTableSource[draftKey] === tablePath` 时跳过。

### 4.2 新增 `src/lib/workbench/stage-rows.ts`（纯函数，可单测）

- `dedupeChoices(plan, choices, remembered)`：一张表只给一份稿，撞车落回 conflict；

### 4.3 表格结构 probe

- **不改 `sku-attribution.ts`**：冲突仍由内核判，UI 只负责把"为什么冲突"说清楚。

### 4.4 视图层守卫

- `confirmBulkImport` 加"同表多稿"拦截（G4）；

## 10. 反方九问

1. **"全部替换"是不是把老界面删了？** 不删。主路径换掉，老界面收进「更多」；删能力是红线，要删得另开 L2 并经您明确同意。
2. **自动填批会不会把用户手工选的稿冲掉？** 只有"当前批为空"或"换文件夹经确认"才自动填；手工批用 `batchSource=manual` 标记，扫描回来不覆盖。
3. **第 1 步读 9 张表会不会卡？** 并发 2、只读被选中的表、读一张亮一行；单张 5 MB 上限，本地回环传输。失败单行重试，不拖整屏。
4. **为什么不发 3.7.25？** 不必。现有 `read-table` + 前端解析已经能拿到语言和 sheet；少一次助手发版，就少一轮安装包/版本闸风险。
5. **同名稿折叠会不会悄悄少做一稿？** 不静默。显示"2 份相同，按 1 份算"，旁边就是「分开做」；指纹不同一定问。
6. **跨交付物借表为什么不做？** 内核明确"不跨交付物借表"（`sku-attribution.ts:417-421`），借错表字会跑到图外。模拟里那格要改成「去补表」。
7. **扫描为什么不自动开始？** 要开 PS、可能几分钟；自动启动会把"选文件夹"变成重操作。手动一键 + 明确进度更可控。
8. **文案键迁移会不会又"改了不生效"？** 新壳全部走 `useSiteCopy`，验收 grep 中文硬编码；这条是 WF-010 的直接教训。
9. **失败了怎么退？** 界面回滚到 `730ee499` 归档；数据只在浏览器内存，无库改动，退款/计费不涉及。
