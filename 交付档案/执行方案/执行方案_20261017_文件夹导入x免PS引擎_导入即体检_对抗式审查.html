一句话判词

免 PS 引擎让单元卡直接带上「能不能替换、哪里会漏」的结论，工作台从扫描发生地变成复核＋替换地；替换由同一引擎完成，回执写明引擎身份并声明未使用 Photoshop；跨通道执行一律被安全闸拒（ISSUES #159）。半程事实与「36/38 字段」缺口全部如实标注，不唬人。

三个新能力（本方案纳入）

  • 导入即内容体检：逐稿真扫不再依赖 PS 与队列，单元卡直接带结论（覆盖率 / 近似点名 / 放错红标）
  • 免 PS 全流程替换：没装 Photoshop 的机器也能跑完；回执含引擎身份（运行时读取）＋读回校验＋「未使用 Photoshop」声明
  • 来源安全绑定：扫描来源＝执行来源；跨通道执行一律拒，且无「没凭记也放行」的宽松分支

诚实边界（不写、不做）

  • 字段缺口不补 0；不写「与 PS 完全一致」
  • 免 PS 替换对外文案在「真 PS 开档验产物」通过前不写「完全替代 Photoshop」
  • 引擎不在＋PS 不在＝如实提示「无法扫描」，不伪造
  • 不预接死代码：A 段接线排在 C 段之后（跨引擎合同变更＝独立班车）

03UI/UX 上帝视角（yt-uiux 五阶段 · 本轮重排）

一、需求淬炼

核心任务：把客户交付的文件夹拖进工作台，在替换之前看清每个单元「能不能替换、哪里会漏」，然后一键在本机完成全部替换——这台电脑没有 Photoshop 也全程可用。
用户：运营/排版 PM；Windows 本地助手；情绪＝怕漏译、怕张冠李戴、怕没装 PS 卡死。
成功标准：导入到看清结论 ≤1 分钟（12 稿）；放错稿 0 件进入替换；无 PS 机器可完成；跨通道误操作 100% 被拒。

二、信息架构

三页：导入对话框 → 单元列表（已带体检结论）→ 工作台（复核＋替换＋回执）。比 v2 少一环：「载入后才扫描」在引擎就绪时合并进导入结果——扫描不再需要 PS 队列，没有理由让用户等第二次点击。
关键路径：选夹 → 读日志/单元卡 → 载入单元 → 勾选放行（如需）→ 开始替换（免 PS）→ 回执。

五、UI 对抗审查（会怎么翻车 × 改法）

UI-F2 等待管理：结构/表体审先行；扫描逐稿进度；可中止（中止标「未扫」，载入后可补扫）。
UI-F3 双通道不困惑：按可用性自动选；来源徽章常显；切换＝重扫（讲明）。
