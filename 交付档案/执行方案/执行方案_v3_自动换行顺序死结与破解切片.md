## 1. 死结的三条腿（全部本会话自验，非引用）

**腿一：报价输入里没有任何排版数据。**
`src/app/api/workbench/execution-batches/quote/route.ts:63-69` 的 rows 只有 `rowToken / sourceCharacters / targetCharactersByLanguage / requiredObjectCount / scopeStatus`——**没有 layerId、没有 bounds、没有 typography**。经典报价 `createPhotoshopQuote` 同样只吃 snapshotId/manifestHash/billingScope。⇒ 报价时点服务端**算不出**"这层加一行放不放得下"。

**腿二：`target_text` 进摘要，`bindingPlanDigest` 不进。**
- `computeAssignmentDigest` 含 `target_text`：`src/lib/trust-chain/evidence-foundation.ts:205`。
- `computeBindingPlanDigest` 只含 `expected_source / layer_id / object_id`（+ excluded/ignored）：`src/lib/trust-chain/binding-core.ts:268-276`，**不含译文文本**。
- manifest 线上哈希也含 `target_text`：`src/lib/trust-chain/execution-manifest.ts:219-226`。
⇒ 插一个换行＝改 `assignmentDigest` 与 `manifestDigest`，但**不改** `bindingPlanDigest`。

**腿三：比对点全是硬拒。**
`src/app/api/local-assistant/execution-attempts/[id]/receipt/route.ts:107/111/114/117/120` 五处 409（manifest / rowSet / bindingPlan / translation / document 各一）；`src/lib/server/execution-batch.ts:687-688` `BATCH_MANIFEST_MISMATCH`；`execution-manifest.ts:460-473` readiness 五摘要 vs manifest 抛错；助手侧 `v15-runner.js:96-97` 归一后文本不等 ⇒ `REOPEN_READBACK_MISMATCH`。
⇒ **执行时才决定插行**：manifest 里的 target_text 与回执/回读实际写入的文本分叉 ⇒ 必炸上面某一条。

## 2. 破解：把"加行"收敛成报价前可复算的确定性决策

唯一不自相矛盾的形状：**插行发生在 `compileBindings` 内、只依赖"报价时点已经冻结的输入"**，三处调用（`server.js:6258/7556/7838`）同输入同输出。为此必须先把决策数据搬进那个冻结集：

- **需要搬进来的**：① 该层所属画板矩形 ② 该层下方最近元素顶边 ③ 图层缩放系数 ④ 文档分辨率（量纲换算）。
- **现状**：预扫描 `TYGF_V15_Preparation_Scanner.jsx:177-187` 只采**文字层自身 bounds**，`:151-152` 有字符级 horizontalScale；**画板矩形与非文字层顶边只有 `Reopen_Verifier.jsx:164-225` 在"执行并保存之后"才产**，晚于票据签发与 manifest 绑定。
- **推论（推翻 v2 排期）**：S1a 不是旁支，是 S2 的**硬前置**；且 S1a 产出的几何必须与 `scanId` 一起进 evidence/摘要链（否则报价与执行两次扫描结果不同，照样分叉）。

## 3. 计价：本轮自验为"不动"，但它是脆的
