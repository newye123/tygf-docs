## 阶段一 · 命名：收回 v9 的新词表，改成"沿用旧名 + 只加多稿层"

### 1.1 为什么收回（我改了主意，说清理由）

v9 我把批量工作台**另起了一套词表**（设计稿与译文来源 / 译文检查 / 生成交付 / 译文来源 / 对稿覆盖率 / 就绪 / 有 N 处要处理 / 更换译文表）。Owner 明确说**「不要跟单个设计稿跳得太脱」**。

⇒ 我重读了两句话，发现**它们其实不矛盾**：

| Owner 的原话 | 我上轮读错的点 | 更正后的读法 |
|---|---|---|
| 「这些名字**可不能是现在这个名字**哦」 | 读成了"连旧的步骤名也不能用" | **指的是我编的那些内部词**（译库 / 切片 / 来源矩阵 / 覆盖率矩阵 / owner value）——它们是给代码看的，不是给用户看的 |
| 「**不要跟单个设计稿跳得太脱**」 | — | 步骤名、卡片名、操作名**越像单稿台越好**——因为单稿台是用户已经熟悉的那套 |

⇒ **正解：步骤名与操作名全部沿用单稿工作台；只在我自己发明的内部词上换成用户话；多稿这一层用最朴素的说法。**

### 1.2 沿用单稿台的部分（一个字不改）

| 位置 | 单稿工作台 | 批量工作台（**沿用**） |
|---|---|---|
| 步骤 1 | 准备素材 | **准备素材** |
| 步骤 2 | 智能检测 | **智能检测** |
| 步骤 3 | 设计稿校对 | **设计稿校对** |
| 步骤 4 | 确认并生成 | **确认并生成** |
| 卡片 | 选择设计文件 · 只读预扫描 | **选择设计文件 · 只读预扫描** |
| 卡片 | 选择要处理的 PSD 文件 | **选择要处理的 PSD 文件** |
| 卡片 | 导入多语言译文表 | **导入多语言译文表** |
| 操作 | 选择文件… / 扫描 / 重新扫描 / 移除 | **选择文件… / 扫描 / 重新扫描 / 移除** |
| 操作 | 选择语言 / 重选译文表 | **选择语言 / 重选译文表** |
| 状态 | 正常 / 译文为空 / 重复原文 | **正常 / 译文为空 / 重复原文** |

### 1.3 只在"多稿"这一层新加的三处说法（最朴素）

| 位置 | 说法 | 为什么这么叫 |
|---|---|---|
| 列表区标题 | **12 个设计稿** | 单稿是"这个设计稿"，批量是"12 个设计稿"，同一件东西的复数 |
| 分配区标题 | **每个设计稿用哪张表** | 用户要回答的问题原话，不是"绑定"、不是"切片" |
| 总览区标题 | **这一批的进度** | 单稿有"第 2 步的进度"，批量就是"这一批的进度" |

**收掉的内部词**（不再出现在界面上）：译库、切片、归属、绑定、来源矩阵、覆盖率矩阵、owner value、slice、dataset。

### 1.4 仍然成立的"一个数 + 状态词"（只是不叫新名字）

- 度量：沿用单稿的**覆盖率**（不叫"对稿覆盖率"，避免又造词）；但**补上分母**（"覆盖率 96%（这一稿 12 个文字图层里对上 11 个）"）。
- 状态：单稿是逐行看状态；批量是**逐格看**，所以状态词必须能回答"我现在该做什么"：
  **就绪 / 待检查 / 有 N 处要处理 / 缺语言**（缺语言＝这一份**做不出来**）。
  ⇒ 这四个词是**新增的**（单稿没有"缺语言"这种整格状态），但都是普通话。

## 阶段二 · 上传交互（这是上一版模拟的**真缺口**）

上一版只画了「全部扫描」「批量导入译文表」两个按钮，**没有把上传做出来**。本稿把它做成可点的。

### 2.1 PSD 怎么上传（贴单稿的三件，多加"多"）

单稿是：路径输入 → 选择文件… → 扫描。批量是同样三件，**只是能一次给多个**：

| 方式 | 批量台的形态 | 交互 |
|---|---|---|
| **路径输入** | 同单稿一个输入框（单稿一次一个，批量也一次一个，可重复） | 填了不存在的路径 ⇒ **明确报"这个路径在磁盘上找不到"**，不静默跳过 |
| **选择文件…** | 同名按钮，**弹层里可多选**（12 个候选，带目录、图层数） | 勾选 → 确定 → 加入列表（上限 12，超了逐条点名） |
| **粘贴多个路径** | 单稿没有 ⇒ 批量新增：`每行一个` 的文本框 | 逐条校验，**找不到的路径逐条点名**（沿用既有口径"认不出的会跳过，跳过了哪些列给你看"） |
| **选文件夹** | 单稿已有（连子文件夹一起找，最多 6 层） | 沿用，不改 |
| **扫描** | 单稿一个「扫描」；批量加「**全部扫描（按顺序）**」 | 每稿独立显示 `未扫描 / 扫描中 / 已扫描 + N 个文字图层`，可逐个「重新扫描」「移除」 |

### 2.2 译文表怎么上传

| 方式 | 形态 | 交互 |
|---|---|---|
| **拖进来** | 拖放区（单稿也有拖放，只是这里说"可以一次放多张"） | 拖入 → 逐张解析 |
| **选择文件…** | 可多选（9 张候选，带目录、语种列数、行数） | 勾选 → 确定 |
| **粘贴表格内容** | 单稿已有 | 沿用 |

**逐张解析、逐张点名**：一张表解析失败（如 `日韩_备注列版.xlsx` 识别到 13 个语言候选列）**只这一张失败并点名，其它表不受影响**，可以继续。

### 2.3 关键的一步：**每个设计稿用哪张表**

上传完不能自动套用（既有口径：`design-file-card.tsx:1017-1023`「表格只列候选，不会自动套用」）。批量台多一层：**表比稿多**。

⇒ 界面做成一张表：**一行一个设计稿**，三列：

| 设计稿 | 用哪张表（下拉） | 依据 |
|---|---|---|
| `主图\SKU-AX1001_主图.psd` | （下拉，默认给出建议） | **同一个文件夹** / **同一层目录（有 N 张，要你定）** / **唯一的合表** |

- 建议规则按目录远近给，**冲突不自动选**（同一层有 4 张表时，文案明说"有 4 张，要你定"）。
- **下拉里的预选只是建议**；不点「**确认这 N 条**」就**不生效**。
- **下面的「这一批的进度」只按已确认的分配显示**；没确认前那格算「未分配」。⇒ 这一条我特意在模拟里做实了：确认前矩阵显示 12 格「未分配」，确认后才变成覆盖率。

### 2.4 模拟件实测（`模拟_20261021_批量改语言_准备素材_含PSD与译文表上传交互.html`）

- 「选择文件…」弹层：12 个设计稿候选（带目录、图层数）可多选；9～11 张译文表候选可多选。
- 实跑：加 4 个设计稿（"已加入 4/12"）→ 全部扫描（4 个同时「扫描中」→ 逐个转「已扫描」）→ 加 7 张表（"已导入 7 张"）→ 分配表出现 4 行、依据「同一层目录」→ **确认前矩阵 12 格全是「未分配」** → 点「确认这 2 条」后 → **4/4 已分配**，矩阵变成覆盖率。
- 「这一批的进度」＝ 12×12 矩阵（行＝设计稿、列＝12 语种、格＝就绪/待检查/有 N 处/缺语言/本稿不做）。
- 右上切「单稿工作台」＝ **原样保留**（准备素材 / 选择设计文件 · 只读预扫描 / 选择要处理的 PSD 文件 / 选择语言 / 重选译文表 / 智能检测，5 行审查表一字不改）。
- **0 console error**。
