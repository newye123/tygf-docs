Owner 令：「继续钻到无路可钻，给我一个讲人话的执行方案，我不做选择你来做」
Owner 追加令（16:3x 实测钟点见本行）：「还有现在安装要手动退出软件，无法做到全自动，这个也一起做了吧」

## 一、钻到底发现了什么（三句话）

1. **发布身份文件里只有一个版本号 `assistantVersion`，它同时兼三份工作**：① 当"低于它就拒绝服务"的下限；② 下载页上给客户看的"当前版本"；③ 发布说明里的版本号。
   ⇒ 后果：**每次为了发新版、更新下载页而改这个数字，都顺手把兼容下限抬了一格。** 没有人决定要砸客户，是**抬下限这个动作没有独立开关**。
   证据：`config/release-identity.json` 字段全表 = `assistantVersion, assistantFile, assistantBuildId, reportSchemaVersion, reportRendererVersion, replacementScriptSha256, nodeMajor, integrationBranch, productionBranch`——**没有 `minAssistantVersion`**（全仓 grep `minAssistant|assistantMin` → 0 命中）；一处三用见 `assistant-execution-contract.ts:69`、`download/page.tsx:103/116/125`、`local-assistant/latest/route.ts:12/17/24`。

2. **3.7.25 那次加请求头，把一个错误的假设发了出去。** 网页代码注释原文写着"旧助手会忽略这个头＝旧行为"（`local-assistant-client.ts:406-407`）——**这是错的**：浏览器发现助手没放行这个头，会把整个请求在预检阶段拒掉。助手自己的代码记着这笔实锤（`download/local-assistant/server.js:2686`、放行名单 `:2690` 到 3.7.28 才补上）。
   ⇒ 后果：3.7.15–3.7.27 的助手对现在的网页**物理不通**，客户看到的是"已连接但授权未确认"这种假警报，反复重新授权也没用。修法是改了助手（3.7.28），**于是所有老客户必须重装**。

3. **构建号那道门方向写反了。** 它是"不相等就拒"（`assistant-execution-contract.ts:75-84`），不是"不能更低"——所以**比网页更新的助手也会被拒**（内测客户从测试站装了新版回生产就被挡）。而契约本身三项（报告格式／渲染器／替换脚本指纹）**两边完全一样**，指纹同为 `882a4a8655ed`。

4. **"必须手动退出软件"不是 Windows 的脾气，是三处叠加，全都能修（10-27 16:3x Owner 追加令带出的调查）。**
   - 安装脚本里唯一会关程序的机制是 Inno Setup 的"关闭正在使用的程序"（`download/local-assistant/build/installer.iss:33-35`）。它靠系统的"重启管理器"给程序发关闭消息——**而托盘程序根本没有窗口**：`TrayHost.cs:48` 用的是裸 `ApplicationContext`，全文件没有 `Form`、没有 `WM_CLOSE`/`WM_QUERYENDSESSION` 处理（grep 0 命中）。收不到消息 ⇒ 关不掉。
   - 更糟的是**引擎杀了会复活**：托盘每 5 秒执行一次 `EnsureEngineRunning()`（`TrayHost.cs:55-63`），只要 `exiting` 没置真就立刻把 `图译工坊引擎.exe` 重新拉起来（`:120-133`）。于是安装器刚把文件释放开，文件又被占住。
   - 全仓**没有任何"自我了断"入口**给安装器调用：唯一的干净退出是托盘菜单里那条"退出本地助手"（`:93` → `ExitAssistant()` `:277-286`，它才会置 `exiting=true`、停定时器、杀引擎）——只能人手点。这就是您看到的"要先手动退出"。
   - 顺带挖出一条**已经存在的老虎**：`ExitAssistant()` 不看忙不忙，直接 `process.Kill()`（`:146`）。在跑批的时候点"退出本地助手"，会把 Photoshop 执行打断；助手自己有条实锤——打断后落下恢复锁，`server.js:2380` 的原文是「检测到未完成 Photoshop 执行或恢复标记；请先人工核实现场，**不会自动重试**」，且 `:2575` 写「恢复确认前不会接收新任务」。也就是说**今天客户手点退出，也可能把自己的助手锁成不能用**。这条我并入第 3 批一起修。
   - 最后一处：静默安装不会把助手再拉起来（`:101` 的 `skipifsilent`）——将来接自动更新时，会出现"装完了但没在跑，直到下次开机"。

## 二、我做的决定

| 编号 | 决定 | 为什么这么定 |
|---|---|---|

| D5 | **被挡时给出口**：版本不足提示里加"下载新版助手"按钮，文案写清"连托盘一起退出再打开" | 现在只说"请升级"，附近连个链接都没有（grep `href\|download\|Link` 0 命中）。最便宜的一条 |

**做完之后的效果**：以后"只是重打包、契约没变、没带必修修复"的发布，**客户不需要重装**；真需要装新版时，客户只做一件事——双击安装包，剩下的（关掉正在跑的助手、覆盖、再自己起来）由安装器做，**不需要手动退出软件**；真需要拒绝的那一版照样响亮拒绝并给一键下载，不静默降级。

## 三、执行顺序（我自己按这个走，不再问你）

**第 1 批（纯增量，风险最低）**：D5 下载入口 + 文案 → D2 头门控与错注释 → D1 拆字段（新字段缺省=现值，行为不变，先把管道铺好）
**第 2 批（改判定）**：D4 构建号降级 + 界面说法同批扫 → D3 机器检查与负控
 **第 3 批的形状已被封驳改过一次**（见 `交付档案/审查报告/审查报告_20261027_装新版不用手动退出_封驳与合成件实测.md`）：我原来写的"用 `--exit` 把退出标志置真"经合成件实测**不成立**——`--exit` 是另一个进程，改不到正在跑的那个托盘的进程内变量，日志里它返回 0 而互斥体 15 秒不释放。改成下面这版并已跑绿。
**第 3 批（本轮新增，Owner 令）——装新版不再需要手动退出**，五步一起做：
 1. 托盘加一个不带窗口的自杀入口 `图译工坊本地助手.exe --exit`。它**不替别人退出**，只做三件事：判忙（`GET http://127.0.0.1:49152/queue/status`，**只认 `busy === true`**，不得看 `errorCode`/`phase`——本机活助手实测空闲时 `errorCode` 也是非空的）、点着一个**命名事件**、等托盘互斥体消失。正在跑的托盘在自己的循环里看到事件就执行原本那条干净退出路径（停定时器→杀引擎→释放互斥体→退出）。返回码定死：0 已关／3 忙拒／4 叫不动。`busy` 字段由 `server.js:2650` 的 `publicQueueStatus` 公开。
 2. 安装脚本加 `PrepareToInstall`：先从注册表卸载项 `InstallLocation` 取实际安装目录（取不到回退默认目录，两条都没有 ⇒ **中止并说明，不许静默继续**），调用上面那个 `--exit`，然后用 `CheckForMutexes('Local\TYGFLocalAssistantTray')`（互斥体名见 `TrayHost.cs:42`）轮询等它自己走干净——**这一步不依赖重启管理器，所以"托盘没有窗口"那条不再是拦路虎**。返回码 3 ⇒ 中止安装并说人话（"本地助手正在跑替换任务，等这批跑完再升级"），不硬来。
 3. 老版本鸡生蛋的兜底：3.7.28 及更早的托盘**没有** `--exit`，第 2 步对它必然失败 ⇒ 轮询超时后按两个产品专名回退强杀，且**只在 busy 双采为假之后**才允许；哪条路走过的要落进安装日志。兜底后互斥体仍在 ⇒ 中止（合成件 T7 实测：`taskkill` 返回 128、安装中止 rc=7，不会硬装）。
 4. 装完自己起来：静默装也要拉起托盘（去掉 `skipifsilent` 的连带影响，改为安装收尾 `ssPostInstall` 显式启动，`RestartApplications` 交回我们自己控制避免拉两遍）；**拉起前先验互斥体**，仍被持有就跳过并留日志（合成件 T8 实测这条闸真落）。
 5. 顺手堵老洞：托盘菜单"退出本地助手"今天直接 `process.Kill()`（`TrayHost.cs:146/:277`）不看忙不忙，客户手点就可能把助手锁进恢复锁（`server.js:2380/:2575`）；该路径改走第 1 步同一个函数。
 **更正一条我说错的话**：我曾在方案里把 `CloseApplicationsFilter` 那行三个名字用分号分隔判成"写错了"（`installer.iss:35`）。**这是错的**——`scripts/smoke-pc-bundled-engine.mjs:321` 的 [D4] 就是按 `;` 切这一行、并要求列出内置引擎文件名 `tygf-engine.exe`（它以 serve 子进程常驻、持有自己的文件句柄；漏名会让删除退化成"重启后才删"，旧引擎作为孤儿永久留在 `{app}\bin`）。我动手时真把这道门跑红了，已改回原样并加注释"不要改成逗号"。Inno 自己怎么解析这个分隔符，本机没帮助文件、官方页取不到正文，仍属**未核实**——但我的自关机制不依赖它。
**第 4 批（可选：一键升级，默认关）**：助手侧 `POST /v1.5/update/apply` —— 下载→按 `public/downloads/local-assistant-release.json` 里**已经在发**的 `sha256`＋`size`（`signatureStatus` 现为 `UnsignedBeta`）校验→丢一个脱离父进程的安装器子进程（`/SILENT /NORESTART`）→自己走第 3 批的 `--exit`。开关 `autoUpdateEnabled` **出厂 false**，翻它要您点头（属红线级：一旦开就是所有客户机同时执行下载来的代码）。
**为什么第 4 批必须在第 1、2 批之后**：D2/D4 没修之前，版本门是"不相等就拒"。自动更新会把一个新构建滚到客户机上，而网页这边还按老规矩拒它——**结果是每台机器同一天集体连不上**，事故从"重装一次"升级为"没人能用"。
**每批都要**：`npx tsc --noEmit`、`npm run lint`、对应合同门、**负控必须能红**（新门首跑要逐数复核它自己产出的量纲），跑完贴原式与退出码；第 3 批的专项验证见下；第 3 批的验证是"合成一个假托盘 + 一份复用同一段 Pascal 的小 iss，证明安装器真能等到进程干净、真能在忙时中止"，最后用 ISCC 编译正式 `installer.iss`（本机 `C:\Users\ivan\AppData\Local\Programs\Inno Setup 6\ISCC.exe` 在，退出码为 0 才算）
**不做**：提交推送之外的任何生产动作；生产发布仍卡在那四条前置（合回生产独有 2 笔、生产库补 `ApplicationAttribution` 表、助手随发决定、多稿补声明），那一条线我另开一件跟
