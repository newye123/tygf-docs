F-01

英文站根本没在用思源黑体

已修

home-view-en.tsx:615 在根节点写死了内联 fontFamily: '"Segoe UI", "Helvetica Neue", …'，把 home-v17.css:41 的思源黑体整个盖掉。浏览器实测字体请求数 = 0。原注释的理由（"13.5 MB 中文可变字体，英文页别用"）站不住——理由错，但执行确实做到了"英文页不下载思源黑体"，只是方式是换系统字体。

F-02

不能直接引全量字体：13.47 MiB

已修

仓库那份 SourceHanSansSC-VF.woff2 实测 14,129,688 字节。英文页引它 = 每个首次访客下 13.5 MB，对营销页是 LCP/转化事故级代价。四条取小文件的路实测三条走不通：wawoff2 解不开这份 14 MB 文件（ConvertWOFF2ToTTF failed，对 24 KB 文件正常 ⇒ 体积限制而非文件坏）；本机 python 无 pip/ensurepip；Adobe 只在 847 MB release zip 里发 VF，raw.githubusercontent 实测 ~8 KB/s（300 秒只下 2.4 MB / 29.3 MB）；npm 的 Adobe 版包只发 CJK 分片、无拉丁分片。⇒ 唯一可复现路线是 Google Fonts CSS2 的 text= 按字集子集，实测 33,976 B / 231 码位 / wght 100–900。

F-03

"文案被挡住"不是图片盖字

已修

home-v17.css:120 给标题行写了 white-space:nowrap，而 home-v17.css:119 的 clamp(50px,6vw,78px) 是照中文标题定的：中文第一行 7 个字，英文第一行 23 个字母。实测 1440 桌面（栏宽 608px、产品卡左沿 678px）：标题真实绘制宽度 849px，溢出 241px，与产品卡重叠 171px；1081px 时重叠 278px。产品卡背景不透明白、DOM 在后、两者 z-index 都是 auto ⇒ 后绘制者直接盖住标题。

当初为什么没被发现：nowrap 让 <span> 的盒子宽度还是 608px，只有画出来的字跑到 849px。任何按元素盒子量的检查都会报"没溢出"——我自己第一次量也中了招。必须用 Range.selectNodeContents() 量真实绘制宽度。

被证伪的两条（不进 findings）

「英文站字体大是主因」：证伪。改前英文站一个字体都没下载，大是"应该怎么做"的问题，不是"现状是什么"的问题。

05Wave 1～4：英文登录页与英文工作台

分波原则：每一波自成闭环、能独立验收；未完成的波不暴露入口。

波做什么交付判据风险
W1 英文账号入口 + 英文登录页：/en/auth/login（+ /register /reset /sessions），英文文案、英文报错、英文邮件模板 英文访客在 /en 能注册/登录/登出/找回密码，全程英文；/en/auth/* 可见文本 CJK=0（守卫） 中 账号/会话代码不动，只加路由与文案
W2 i18n 接缝（先建能力，不铺文案）：LocaleProvider + t() + 逐模块英文字典 + 机械改写脚本 + "中文残留计数" 一个命令能报出"英文模式下还剩 N 处中文"，N 只减不增；改写脚本可回滚 中 接缝设计不对，W3/W4 返工
W3 按步骤铺文案：外壳（导航/页脚/账号菜单/阶段轨）→ 第 1 步素材 → 第 2 步检测 → 第 3 步就绪 → 第 4 步执行 每铺完一步该步骤英文页零中文残留；中文站页面逐字节不变 高 触碰共用组件
W4 英文工作台路由（/en#workbench）+ 双语切换 + 英文账号菜单；助手运行时文案与 HTML 报告（若 Owner 拍板要纯英文） 英文用户登录后进的是英文工作台；助手报错/报告也是英文 高 涉及助手制品与版本身份

W2 接缝的建议设计

  • 键用中文原文：t('智能检测') 而不是 t('workbench.review.detect')。机械改写脚本能自动生成键；中文原文就是它的 ID，改文案即改 ID，不会"键名和文案对不上"。
  • 英文字典按模块就近放（src/components/workbench/<模块>.en.ts），不堆一个大文件——1,463 条堆一起没法维护。
  • 缺翻译必须失败：守卫扫"所有 t('…') 都有英文条目"，缺一条即红，不能静默回退中文。
  • 中文站零改动：locale 缺省就是 zh，现有调用点一个不用改。

门禁要跟着改（不能不改）

  • 现有"源码必须出现某句中文"的断言，要改成"英文字典里必须有对应条目"——断言对象从组件源码换成字典，钉的东西不变（那句术语必须存在、必须与中文一一对应），但不再依赖中文留在组件里。
  • 实测点名清单：smoke-workbench-ui-contract、smoke-batch-workbench-guards、smoke-home-session-ui、smoke-content-studio-v1、smoke-preparation-bulk-import、smoke-assistant-auth-barrier、smoke-local-assistant-errors。
  • 不在本轮范围但英文用户会碰到：本地助手运行时文案与它产出的 HTML 报告、验证/重置密码邮件（现为中文模板）、运营台（不对外）。
