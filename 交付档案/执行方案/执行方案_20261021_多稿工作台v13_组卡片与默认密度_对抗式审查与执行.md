## 3 执行方案（分 6 段，每段自带判据）

### S1 · 纯函数模块 `src/lib/workbench/draft-groups.ts`（新增）

| 导出 | 作用 | 关键规则 |
|---|---|---|
| `deriveDraftGroups(entries, opts?)` | 把 `MultiPsdEntry[]` 分成组 | 组键＝`masterPath` 的**立即上级目录名**；无上级目录⇒`未分组`；分隔符归一（`/`↔`\`）＋大小写不敏感比较（沿用 `psd-selection.ts:183` 的 `pathKey` 口径）；组内保持原顺序，组间按名排序（`localeCompare` 的稳定替身） |
| `classifyDraftAttention(input)` | 单稿「要处理的」判定 | 优先级：`blockedItems>0` ⇒ `blocked`；否则命中 `not_scanned / scan_error / stale / no_table / unconfirmed_languages / coverage_below` 任一 ⇒ `needs_attention`；全空 ⇒ `ready`。**未知字段传 `null` 即不参与判定** |
| `summarizeGroups(groups, attentionByKey)` | 组级进度 | 每组：稿数 / 已扫描数 / 要处理数 / 挡住执行的数 |

> **为什么组键不用「根下第一层」**：Owner 的原话结构是「每个子文件夹都单独放着要改的 SKU 的 PSD 和表格」⇒ PSD 直接躺在 SKU 子文件夹里 ⇒ 立即上级目录名就是 SKU 名。深一层嵌套（`root/SKU-A/sub/x.psd`）会按 `sub` 分组——这是本方案的**已知边界**，如实写进 §7 残留风险，不假装覆盖。

**判据**：`tests/unit/draft-groups.test.ts` 单测覆盖 —— 同组同上级目录 / 不同上级目录分两组 / 无上级目录归「未分组」 / 分隔符与大小写归一 / 组内顺序稳定 / 阻断优先于其它理由 / 未知字段不误判。

### S2 · 组卡片组件 `src/components/workbench/draft-group-cards.tsx`（新增）

- 纯展示组件，props 全是普通数据（groups / attention / 扫描回调 / 当前稿键）。
- 每张组卡：**组名（即子文件夹名）** ＋ `N 个稿 · 已扫描 X · 要处理 Y` ＋ 组内明细（可展开，逐稿一行：文件名 / 状态 / 层数 / 扫描按钮）。
- **逐稿行渲染逻辑与平铺视图共用同一份**（同一函数），避免两个视图两套口径。
- 顶部常驻 `分组 / 平铺` 视图开关（默认「分组」）＋「平铺全部 N 个」出口。
- **保留逐稿扫描/重扫能力**（v12 F9：状态带换成集合语义后，单稿那颗「重新扫描」不能消失）。

## 7 风险与残留（如实登记）

1. **组键的已知边界**：深一层嵌套（`root/SKU-A/sub/x.psd`）按 `sub` 分组，不按 `SKU-A`。Owner 描述的结构不受影响；真遇到再改（改组键是纯函数一处的事）。

3. **他人在飞改动未提交**：工作树里混着别的会话的改动（11 改 + 10 未跟踪，含 `tests/unit/workbench-scope-runtime.test.tsx`）。本轮**只提交自己的路径**，不整树提交。
4. **默认密度是「折叠」不是「隐藏」**：全部条目仍在 DOM 里（`<details>`），只是默认收起；且有「查看其余」出口。
