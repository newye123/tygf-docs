# 执行方案 · 排版面板三问深查（体下拉为什么还在／顶部与明细通不通／灰底是不是全废）

> 基线：develop 工作树 HEAD `2fed25dc`（2026-10-23 实测 `git log -1`）；面板与能力表均为当轮工作树实读。
> 触发：Owner 2026-10-23 两张界面截图＋原话「应该做到上面，还有之前不是说只选中字体即可吗？字重还是按原来的走，怎么现在还有选择字重这一项在？还有图二这些全部都不可用？继续使用对抗式审查做更加深入的探查，钻到最深处去，给个执行方案」。

## 1. 结论（三问三答，先说人话）

**问一「应该做到上面」：顶部和下面的明细是同一个存档、本来就通，但好用的东西放错了地方。**
你截图里「体=Bold」和折叠区里的「NotoSansHans-Bold」是同一份数据的两面——选哪张脸只有一处存档（「typography-panel.tsx:452-462」→`commitFace`/`FontFamilySelect` 都写 `profiles「activeLang」`，折叠区摘要行读的就是它）。真正的问题是：**搜索式选字器（1293 款里打字找）只存在于折叠的「高级与结算明细」里**（「typography-panel.tsx:816-822」），顶部是一格 1293 项的原生下拉、没法找；解析出的 PostScript 脸名也只在折叠区显示（`:811-812`）。所以看起来像两截断的。
**修法**：搜索上移到顶部「字」格＋顶部直接显示解析出的脸名。这一刀纯界面、不碰引擎。

**问二「怎么还有选择字重这一项」：确实违约，但不能只删那一格。**
「体」下拉是 10-18 旧面板（PS 字符面板同款）的遗留；10-22 方案的 S5「界面减一格」本来就计划撤它，**一直没排上**。但直接删格是错的：执行器今天就是把**一张脸写给这一门语言的所有文字层**（「TYGF_V15_Thin_Executor.jsx:62-71」——`item.font = profile.face` 逐层执行）。更深的一层：**就算你不碰「体」、只选字族，代码也会自动回落到常规体**（「font-picker.tsx:47-56」 选族时按当前样式找，找不到就走 「typography-capabilities.ts:461」 的 regular 回落）⇒ 粗体层照样被压平。**违约的不是那个下拉，是"一语一张脸"这条旧管线**。撤格子必须和助手侧逐层配脸（S4）捆在一起交付，否则只是把决定藏进黑盒、错误照旧发生。

**问三「图二这些全部都不可用？」：不是。20 格里 4 格是活的，其余分三种"不可用"，原因各不相同。**

| 状态 | 格子 | 真实原因 |
|---|---|---|
| **活的（4）** | 字、体、行（固定磅值）、字距 | 今天就会随执行下发（「typography-capabilities.ts:62-159」 writable 判定来自映射函数真实产出） |
| **PS 写得进、我们没接（4）** | 自动字距、基线偏移、伪粗（T）、伪斜（I） | 执行器其实已经会写这三类（「TYGF_V15_Thin_Executor.jsx:73-85、122-131」），助手白名单也收（「typography-profile.js:24」），**只差浏览器映射函数不产这几个键**——结算条"本版尚未接入，不会发送"说的是实话 |
| **本版 PS 真机实测写不进（5）** | 语言、大小写（TT/Tt）、下划线（U）、删除线（S） | 10-17/10-18 真机探针实测：语言"读取即抛内部错误"、大小写/下划线/删除线"写了没有变化"（出处：「执行方案_20261022_字体排版按字号分档」:65、「审查报告_20261018_排版面板PS同款紧凑化」:33） |
| **还没试过（7）** | 字号、水平/垂直缩放、垂直对齐、消除锯齿、上标、下标 | 未实测，不猜它能写；可并入下次真机探针窗一次测清 |

灰底**没有谎报**，但"写不进"和"没试过"视觉上一模一样，看着像全废——这是表达问题，不是能力问题。

## 2. 深查证据（file:line，本会话当轮实读）

1. **体下拉的数据流**：`FontStyleSelect`（「font-picker.tsx:78-112」）选中后走 `commitFace`（「typography-panel.tsx:454-462」）→ 写 `face` 存档 → 结算明细的「字体」行与折叠区「脸名」行都读同一个 `current.face`。**顶部与明细共用一份状态，无第二份。**
2. **只选字族也压平粗体**：`FontFamilySelect` 的 onChange（「font-picker.tsx:47-56」）调 `pickFaceForFamily(group, style)`；当前样式找不到就 `regular` 回落、再不行取第一张（「typography-capabilities.ts:454-463」）。执行器拿到这张脸写给全部层（executor `:62-71`）。⇒ **今天的行为本身就不满足"字重按原来的走"。**
3. **逐层配脸的归一模块已存在但没接线**：`typography-family.js`（`ca74bd64`，153 行）当前只被 `scripts/smoke-typography-family.mjs:14` 与 `scripts/psprobe/weight_census_score.mjs:15` require；`server.js`／`v15-runner.js`／执行器 **require 命中 0**（本轮 grep 实测）。另一会话 TASK_LOG 20:46 那句"归一模块没接进执行链"**属实**。
4. **S4 的现场挡板已解除**：10-22 方案 V-4 说"四文件是别会话未提交现场"；本轮 `git status --porcelain` 实测 `server.js`／`v15-runner.js`／助手 `package.json` **均已不脏**（近期提交 `7637da17` 助手 3.7.24、`2fed25dc` 合流）。当前脏面换成了另一批站点文件，**其中含 `typography-panel.tsx`（3 行 site-routes 改造在飞）**——刀一动面板前要先处理这个共写。
5. **普查读数支持"未知档不动＋点名"做默认路径**：去重后 42 份母版／2,526 层，字重可判 **97.8%**、层内混字重 **2.6%**（66 层）、行距机制 31.6% 问文件问不出来（「scripts/psprobe/README.md:28」）。
6. **执行器对 autoKerning/faux 三键全链就绪**：白名单收（`typography-profile.js:24`）＋执行器会写（executor `:73-85、122-131`）＋读回留痕有码。唯一缺口＝浏览器映射函数 `toAssistantTypographyProfile` 不产这三个键（「typography-persistence.ts:149-155」 只产 face/leading/tracking）。

## 4. 执行方案（三刀）

### 刀一 · 顶部好用化（纯界面，不碰引擎）——今天落

1. **搜索式选字上移**：顶部「字」格换成搜索式入口（复用 `FontSearchPopover` 的键盘模型与过滤，做成顶格 combobox）；1293 项原生下拉降级为折叠区备选或直接替换。
2. **脸名上移**：解析出的 PostScript 脸名（如 NotoSansHans-Bold）在顶部选择行直接显示，不再只藏在折叠区。
3. **体格本刀不动**（理由见问二）。
- 共写处理：`typography-panel.tsx` 上有别的会话 3 行 site-routes 在飞改动——等它提交，或按 hunk 级暂存避开那 3 行（不卷入）。
- 判据：`npm run test:typography-picker` 与 `smoke-typography-wiring` 面板断言更新并通过；`npx tsc --noEmit` 不新增报错；390px 宽不溢出。
- 工时：约半天。

### 刀二 · S4 逐层配脸＋S5 撤体格（合同变更，捆死交付）——现场已具备条件，排期即做

1. **助手侧**：`typography-profile.js` 白名单加字族键；prepare 阶段用 `typography-family.js` 对每层原脸名定档、在本机清单里配同档脸，产出逐层映射进执行信封；配不上的层**不写＋报告点名**（Owner 已拍：缺档用最近档＋选定前预警＋报告点名；层内混字重 2.6% 整层不动＋点名）。
2. **执行器**：按层查脸替换 `applyTypography` 的单脸写法；EXECUTOR_VERSION bump＋出厂件重打。
3. **界面（S5）**：撤「体」格；字族下拉每项带「本机 N 档字重」；缺档当场预警；结算明细改按新口径（"本次会发 N 项"的算法同步改）。
4. **门与版本**：`smoke-typography-wiring/picker/profile/family` 全量更新；助手版本 bump、走 GitHub 三段轨上测试站。
- 工时：约 2—3 天（S4 约 1—2 天＋S5 约 1 天）。

### 刀三 · 表达与边角（可选）

1. "未实测"7 格并入下次真机探针窗一次测清，测完要么接通要么灰化，不再含糊。
2. 自动字距/伪粗要不要接：链路只差映射函数三个键（半天），但真稿伪粗占比 0.2%（4 层）⇒ **建议不接**，维持"不会发送"。
3. 统一基线/缩放在两份文档里的分类（Z-4）。
