# 下一刀设计备忘：结算证据的可验证性（2026-11-03 v0，待证伪）

## 要解决的洞（已实测）

enforce 开在测试站后仍拦不住的那一类：客户端把回执里的 `attemptStatus=FAILED`、`completedAssignmentCount=0`、`artifactDisposition=NONE`、`outputFingerprint=null` 一起改掉 ⇒ 服务端全额释放冻结，而成品已经在它自己盘上（`附件_20261103_P3灰度覆盖面探针.mjs` 变体③④，两模式都不扣）。

## 本备忘的提案（请逐条攻击）

- **S1 一次性执行凭证**：服务端在签发执行票据时额外发一个一次性 `executionNonce`（与 attemptId 绑定、落库存"已发未用"）；助手写回完成后必须把该 nonce 混入上报的产物摘要（`objectEvidenceDigest` / `outputFingerprint` 的计算里带上它），服务端核对该摘要是否由"本次签发的那个 nonce"派生。
  宣称的收益：拿不到 nonce 就伪造不出合法摘要；旧 run 的合法摘要也不能复用到新 run。
- **S2 交付件抽样上行**：按比例要求助手把成品 PSD（或其结构承诺：逐层"层 id + 写后文本"的哈希链）上传一次，服务端保存并按自己持有的期望文本核对；抽到就核，核不过冻结/追偿。
- **S3 把"完成"的定义换成服务端可独立观测的事件**：成品必须经服务端通道出件（服务端做最后一步装配或分发）才算完成。
- **S4 只做到可发现**：不改变"能白嫖"的事实，只把异常暴露出来（同 installId 高失败率、exeSha 分歧、终态 FAILED 但客户端后续又拉同一母版），配合人工处置与协议条款。

## 我认为的强度排序（待你推翻）

S3 > S2 > S1 > S4。若 S3 成本不可接受，退到 S2；S1 只是防重放；S4 防不住但最便宜。

## 请审查者专门攻击这四点

1. **S1 能不能挡住变体④**？攻击者控制客户端全部代码与明文脚本，他可以在**不写 Photoshop**的情况下自己算出"带 nonce 的正确摘要"再报 FAILED 吗？如果能，S1 的收益边界到底剩什么（只防重放？只防"拿别的 run 的证据凑数"？）。
2. **S2 的成本与绕过面**：上传 100 MB 级 PSD 的带宽/存储代价（真客户语料实测单稿 500 MB 量级？），以及"我可以选择不触发抽样"的绕过路径；结构承诺（层文本哈希链）与真实文件之间是否可被"报真哈希、留假文件"欺骗。
3. **S3 的产品形态代价**：服务端做最后一步意味着成品要从服务端下发 ⇒ 与"设计文件不出本机"的对外主张、与大体积文件的出网成本、与离线可用性各自的冲突点；这条到底是"另一个产品"还是"一次可分期的重构"。
4. **有没有比 S1-S4 更便宜又真能挡④的形状**：例如把"写回这一步"本身搬进一个服务端能观测其发生的过程（PS 端插件回调？本地签名不可信 ⇒ 无解？）；或反过来，**让白嫖的边际收益归零**（不付款就拿不到"可用的成品形态"，例如缺字体子集、缺最终装配、或成品只在本机与云端各留一半）。给可判定的说法。
