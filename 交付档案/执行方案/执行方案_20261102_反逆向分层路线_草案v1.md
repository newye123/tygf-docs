# 反逆向分层路线 · 执行方案草案 v1（2026-11-02）

状态：草案，待对抗式审查与交叉验证。作者：本会话（Qoder·明文残留体检线）。基线 `worktrees/develop@71529c7c`，现役助手 3.7.31。

## 0. 本质上要成什么（可判定一句）

**让"把我们的引擎读出来"不再等于"拿到能直接抄走的东西"**：值钱的判断改由服务端给出结果、客户端只持有不可读的计算体、且每次取用都留下可归因的痕迹。

推论（判据）：一条动作只有在命中下面三者之一时才值得做——① 让读出来**没用**（服务端化）；② 让读出来**很贵**（编译件/native，成本从"切一刀"变"反编译"）；③ 让读了**能被看见、能被断、能举证**（观测·吊销·归因）。三者都不沾的，一律归类为"心理安慰"，不进排期。

## 2. 最深的一层：为什么"加密 exe"解决不了

三件事共用同一份明文，构成闭环死结：

1. **计费与执行信任依赖客户端自算**：助手本地跑 `compileBindings` 得出 `bindingPlanDigest`，服务端只核对摘要、不重算 ⇒ 客户端必须持有**可读的**裁决代码；
2. **助手自身的完整性自校验依赖原文**：`server.js:122-141` 用 `fs.readFileSync` 重算 `generated/*.js` 的哈希才肯加载 ⇒ 只要还想在校验里读原文，`pkg.assets` 的明文副本就撤不掉；
3. **jsx 走云端分发**是"exe 不背包袱"的既得成果，但换来的是**用户机上落地明文**且内容寻址永不回收。

⇒ 结论：**只要"客户端算、服务端核"这个形状不变，任何混淆/加密都只是把同一份明文换个包装。** 解开的顺序只能是：先把裁决与结算权威搬到服务端（第 1 条断掉），再撤 `generated/**/*` 的 assets 通道并改自校验形状（第 2 条断掉），最后把 jsx 的"可读性"关掉（第 3 条）。这就是下面 E1 → E2 → E3 的依赖顺序，不能倒过来。

## 3. 分刀执行（每刀都要能红）

### E0 先装上眼睛（观测·审计·归因）｜半天｜不改产品行为

- 做什么：① 分发成功即落库（installId、脚本名、版本、exeSha256 前 12、时间），新增 Prisma 表；② 同版本多 `exeSha256` 的分歧信号 + 后台一页可查；③ `check-exe-no-plaintext.cjs` 接进出包链（`package-release.cjs` 的 preflight 段）并补 `generated/*.js` 探针，探针集用**双向自攻**：造含探针串的假 exe 断言红、现役真 exe 断言其"应红就红"；④ 修 `assistant-code.ts` 的密钥回退：非生产显式警告、生产任一 env 缺失即抛（改守卫形状）。
- 判据：拿一个假 installId 打一次 distribute，库里出现该行；`npm run release:package:test` 在探针命中时 rc≠0；把 `generated/binding-core.js` 塞进 exe 后闸必须红（这条今天做不到，今天它测不出 118 KB 明文）。
- 为什么第一：现在连"到底有多少台机器拿过明文脚本"都答不出；没有这个数，E1-E3 的收益无法验收，而成本无法谈。
- 风险：新增表属迁移，须走迁移台账；日志字段禁含用户素材。

### E1 裁决与结算权威搬到服务端｜主线，估 3-5 天分片｜改性质

- 做什么：新增服务端接口接收"扫描观测"（图层文本/读数/行绑定候选），在服务端跑 `compileBindings` + 匹配梯（`findTranslation` 那套判据），返回**绑定计划摘要 + 逐行决策 + 报价**；客户端改拿结果执行，不再本地自证。同步抬 `smoke-batch-row-contract` 夹具与 `test:trust-chain`。
- 判据（关键，必须能红）：**把客户端 `binding-core.js` 里的裁决函数替换成常量桩，端到端批量必须失败或决策与权威不一致**——今天换桩后一切照跑（这就是"读走即等于拥有"）。搬完后，抽出件单独跑只得到"提交观测、拿回结果"的壳，拿到代码不等于拿到判断。
- 依赖与风险：跨层合同变更（同一提交同步 浏览器投影／助手 evidence／服务端报价／结算闸 四层 + fixture + HANDOFF 标【合同变更】）；`compileBindings` 是纯函数可直接服务端复用（`binding-core.ts:758-773`）；服务端要能拿到扫描观测全文 ⇒ 涉数据上行，需按隐私口径核一遍（"设计文件不出本机"这类对外说法要同步改，见 LEGAL-1 教训）。
- 失败退路：新接口灰度（复用 `typographyBetaUsersV1` 式白名单键），旧路径保留到验证通过。

### E2 撤掉 exe 里的明文核心｜1-2 天｜紧随 E1

- 做什么：`download/local-assistant/package.json:7-11` 撤 `generated/**/*` assets；`server.js:122-141` 的运行时原文哈希自校验改为**构建期校验 + 启动期对 bytecode 摘要**（或彻底废掉"读原文"这层，因为 E1 后权威在服务端）；`.d.ts` 不进包。
- 判据：`node scripts/check-exe-no-plaintext.cjs <新 exe>` 必须 **rc=0 且探针含 generated 三段**；再用本轮那段 118,203 B 连续可读度量法对同一 exe 复跑，可读 JS 字节数须显著下降（给数字，不空口"更安全"）；助手在新 exe 上仍能起、仍能跑一单。
- 风险：**这是拆既有安全控制**——`generated` 自校验防的是"改本地核心骗过计费"，拆它必须确认 E1 已把计费的信任搬到服务端，否则是净降安全。E1 未落地则 E2 不许做。
- 顺带：`.jsx` 探针在 10-25 那枚 build exe 上仍报 2 leak（`TYGF_Fonts_Probe.jsx`，rc=1）⇒ 查它怎么进包的（Fonts Probe 不该进 exe），一并收掉。

### E3 把 jsx 从"可读明文"改成"不可读计算体"｜2-4 天｜最后做，收益最小

- 现状硬阻塞（实读）：助手用正则从**脚本源码文本**里读握手字段——`server.js:2040` `source.match(/var SCRIPT_VERSION = ['"]([^'"]+)['"]/)` 及同法读 `REPORT_SCHEMA_VERSION`；编译件下恒 `unknown` ⇒ 版本门 `:2018` 之后直接拒执行。必须先把它迁到 manifest。
- 做什么：① 版本/schema 握手改走 manifest（不再读源码文本）；② 启用 jsxbin（`@JSXBIN@` 在现役 exe 0 命中 ⇒ 从未上线；工具与 `scripts-compiled/` 目前**不在任何分支**，需先入库+挂门禁）；③ 分发管道四件同批（`config/script-versions.json` 的 `lfSha256`、`release-identity.json` 的 `replacementScriptSha256`、`smoke-photoshop-script`、`test:assistant-script-distribution`），否则重演 #74 静默跑旧件；④ 三版 PS（2021/2024/2026）真机各验一次，Adobe 官方警告 jsxbin 与部分脚本集成特性不兼容，且不许走 `eval("@JSXBIN@…")` 字符串形态。
- 判据：新缓存里 `grep -c "function findTranslation"` 必须为 0；端到端跑一单 12 语种成功；`/ping` 五个组件 sha 全等当前发布值。
- 措辞上限（不可越线）：jsxbin 是**成本抬高器**。对外与对内一律不许出现"防扫描/防破解成功"；诚实表述是"把复制粘贴级抬高到需要专门工具与人工反混淆"。
- 为什么放最后：本轮实测脚本明文只占本机真明文 **0.59%**，而 L1 那条 118 KB 明文的暴露门槛更低（装一次就有）。先修 L1 再修 L2。

### E4 归因与止损｜1 天｜可与 E1 并行

- 做什么：① installId 粒度"只停分发不停执行"的口子（今天只有账号级全断）；② 交付件溯源标记——在输出 PSD 的非视觉字段或回执里埋 installId 派生值，泄露时可归因；③ 蜜标：服务端对"同一 installId 异常高频取脚本 / 同 exeSha 多机复用"发信号。
- 判据：停一个测试 installId 的分发后，该助手拿不到脚本但已授权执行不报错；带标记的输出件在去掉可见痕迹后仍可提取出标记值。
- 风险：**不得为埋标记改动交付件视觉**；先验证 PS 是否保留自定义 XMP/元数据（实测前置，未验证不许当成能力承诺）。

### E5 客户端数据残留（与隐私有关，和逆向无关，但同批治理）｜部分已做

- 本轮已完成：临时件删除链修好 + 内部件全部打隐藏位（真机 2,218 件未隐藏 0，`bin/diagnostics/licenses` 未动）。
- 下一刀：`.tygf_v15_journals` 24 MB 明文（客户稿名+原文/译文预览）套现成 `encodeState` + 设保留期；**必须先真机验 #38 断点续跑**，不能只在单测里绿。

## 4. 明确不做

- **盘上静态加密（旧 C 案）**：对同权限攻击者增益 = 0（既往实测：一条 `reg.exe` + 同派生 76 ms 逐字节还原），且会被分发管道自动撤销，要真上还得改盘上复算语义 = 合同变更。不做。
- **反调试/反 dump/内存保护**：本机内存提取不可防是既定边界，投入产出比最差，且容易误伤真机批量（Owner 已定"绝不自动重启或清 PS"）。不做。
- **给 jsx 再加一层"加密后再 eval"**：只是把明文换个存放处，握手不解决就跑不起来；E3 的 manifest 前置绕过不了。不做（并入 E3 ①）。

## 5. 顺序与配额

E0（观测+闸+密钥守卫）→ E1（裁决服务端化，灰度）→ E2（撤明文核心）→ E3（jsx 编译件，三版真机）→ E4（吊销+归因，可与 E1 并行）。E5 的残留治理已部分完成，余下随 E0 之后插队。
按三令配额：每周新签任务书 ≤7，本路线建议只签 E0+E1 两张，E2-E4 待 E1 判据真红/真绿后再签。

## 6. 要 Owner 拍的点

1. **优先级取向**：A. 先装眼睛（E0，半天，不改产品行为，出"多少机器拿过明文"的真实数）；B. 直接上主线（E1，改性质但跨四层合同、要真机验）；C. A+B 同批。我建议 A 先落（半天、无风险），E1 紧随，因为 E2-E4 的验收全依赖 E0 的读数。
2. **隐私口径连带**：E1 要把"扫描观测（含图层文字）"上行到服务端才算得出裁决——这与现行对外说法（含 LEGAL-1 里查出的"设计文件不出本机"类表述）冲突。要不要改对外说法，或改成"仅上行必要字段"的最小化方案？这是产品口径，不是工程选择。
3. **Rust 引擎那条成本墙要不要复制**：实测 `bin/tygf-engine.exe`（43 MB，Rust 第三方 fork）0 处 JS 明文、要逆向得反编译机器码——这才是"贵"的形状。要不要把写回主干逐步 native 化（大工程，另立项），还是先只做 E1-E3。
4. 本轮已做的隐藏与删除修复：**要不要提交**（我没提交），以及那条新用例要不要进 CI。
