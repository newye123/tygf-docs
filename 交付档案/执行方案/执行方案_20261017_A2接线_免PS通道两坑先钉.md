# 执行方案（免 PS 引擎 · A2 接线）：对抗式审查 + 落地步骤 + 交互模拟件

**折行（断行/排版）这条我不再往前推**，按您的判断先放着。本件只做免 PS 引擎。

**一句话判词：A2 可以接了，但有两个会直接伤到用户机的坑必须先钉死——① 引擎失败绝不能沿用 PS 的"安全锁保持（recovery_required）"分支，否则您笔记本上会出现"重启前不再接收任何任务"的死锁态；② 来源凭记不能只落在扫描的临时 taskRoot 里，那次扫描一结束目录就被清，执行期根本读不到。**

## 一、本轮取证（两条都带坐标）

**坑 1 · recovery 锁是 PS 专用语义。** `server.js:2005` 的文案就是"Photoshop 执行器尚未确认退出，安全锁保持；恢复确认前不会接收新任务"，预扫描段也有同形处理（`requireScanRecovery` ⇒ `markBusyRecoveryRequired` ⇒ `phase: recovery_required`）。它存在的理由是 **COM 往返杀不干净**（进程停了不等于 Photoshop 那边动作结束，所以宁可不接新任务）。而引擎是普通子进程，`kill()` 是确定的、没有僵尸态——**把引擎超时/失败路由进这条分支，等于给一台没 PS 的机器凭空造一个需要人工救援的锁**。A2 必须让引擎失败走"普通失败 + 可重试"，不进 recovery。

**坑 2 · 凭记的存放位置。** 现在 `pc-scanner` 把 `scan-observation.json` 和 `scan-provenance.json` 都写进扫描的 `taskRoot`（`server.js:4724` 读 observation，`:4792` saveObservation 进缓存，`:4799` 出摘要给浏览器）。而 `taskRoot` 是每次扫描的临时目录（就绪扫描甚至用随机名 `readiness_<randomBytes>`，`:5279` 读完就 `secureDelete`）。执行发生在**之后的另一个请求**，manifest 键集里既没有 `master_path` 也没有 `scan_id`（`execution-manifest.js:29-34`）。⇒ **凭记只有活进"会被缓存/随件走"的地方才算存在**，光写文件不算。

候选两条（A2 第一步必须先量，不能猜）：
- **甲：把凭记塞进 observation 本体**（observation 本来就带 `psVersion:null` / `engineVersion` 两个字段，加 `engineExeSha256` 一项）——它随 `preparationCache.saveObservation/loadObservation` 一起活，执行期读得到；
- **乙：让服务端在 manifest 里下发来源**（`manifest.readiness` 已存在，加字段＝跨端合同变更，要走四层同步）。
甲更便宜且不动合同，乙更正确但要班车。**A2 先按甲做并留乙的接口缝**，若实测甲在执行期取不到（缓存被清/跨会话），立刻升级乙，不硬撑。

## 二、A2 落地步骤（每步都有可复跑判据）

1. **先量凭记可达性（半小时，只读）**：在隔离树里跑一次引擎扫描 → 让 `preparationCache` 命中 → 从缓存 `loadObservation` 读回，断言能取到 `engine`/`engineVersion`/`psVersion:null`。取不到就当场改判走乙，不进入第 2 步。
2. **引擎道接进 `runPreparationScan`（唯一替换点 `:4699-4717`）**：`decideScanChannel` 判 `engine` 时调 `runPhotoCraftScan({ ..., taskRoot })`，其余（busy、缓存、摘要、轮询、`scan_status==='FAILED'` 处理）一字不动——引擎写的 observation 与 PS 同构，所以下游不需要知道换了引擎。判据：`node --check`；开关关时 diff 行为面零变化；引擎道跑一次真稿产出的 observation 与 PS 扫描产物逐字段差集为空（复用本轮 `diff-scan-vs-proto` 那把尺，换成 PS 真扫 vs 引擎扫）。
3. **失败路径分流（坑 1 的修法）**：引擎失败 ⇒ `setBusy(false)` + 普通失败码 + 允许重试，**不调 `markBusyRecoveryRequired`**。判据：新增断言——引擎失败后 `status.phase !== 'recovery_required'`，且下一次请求能被接收（这条必须写成测试，不然将来一定被人"顺手统一"回去）。
4. **执行道接凭记（坑 2 的修法）**：`decideExecuteChannel` 的 provenance 从执行期实际可读的位置取（第 1 步量出来的那个位置）；取不到 ⇒ `PC_SCAN_PROVENANCE_MISSING` 拒，提示重新扫描（不是"等待 Photoshop"）。判据：`smoke-pc-channel` 那 7 条负控继续绿，另加一条"引擎扫的件交给 PS 执行 ⇒ 拒"和"PS 扫的件交给引擎执行 ⇒ 拒"。
5. **内置进包（E）**：`tygf-engine.exe` 改名 + `licenses\` bundle + 构建清单 + 开源许可页 + bump 3.7.16。这步之后才有"装到您笔记本"这件事。
6. **F 实机（您的无 PS 笔记本）**：扫描 → 批量改语言 → 打开客户报告核对 → 再用真 PS 开一次产物。四步都要真做，本地绿不算绿。
