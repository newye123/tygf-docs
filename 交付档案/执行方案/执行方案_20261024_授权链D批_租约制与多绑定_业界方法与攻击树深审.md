# 执行方案：授权链 D 批——租约制＋多绑定（业界方法调研＋攻击树深审版）

> 日期：2026-10-24　｜　对象：本地助手授权模型（接 A/B/C 三批之后的结构解）　｜　状态：**方案待拍板；未改代码**
>
> 起因：Owner 问「怎么做最能一劳永逸」「用户换账号/多浏览器多账号会不会打架」→ 令「去 GitHub 和网上看大家怎么用对抗式审查做更深的探查，钻到最深处，然后给执行方案」。
> 本方案＝业界方法调研成果 × 对我们授权链的攻击树/pre-mortem 深审 × D 批（租约制＋多绑定）设计。

---

## 0. 一句话结论

**D 批把授权从「每次操作走一趟云端验票」改成「配对一次拿短租期签名令牌、本地核验、后台续租」，并让助手同时持有多个账号的授权（按票据选）——业界桌面端授权的标准形态。**做完后：慢网络结构上不再堵操作（C2/C3/C5 的土壤消失）、换账号不再互相顶（多浏览器多账号共存）、离线可干活（租约内）、被偷的令牌最多活一个租期（轮换＋复用检测）。

## 1. 业界怎么打「对抗式深挖」（我们借什么）

| 业界方法 | 核心做法 | 来源 | 我们怎么用 |
|---|---|---|---|
| **制作者/检查者分离**（maker-checker） | 写的人永不审自己；审查者在**新鲜上下文**只看产物＋怀疑式清单，只读权限，最好跨模型家族 | [AugmentCode 对抗审查指南](https://www.augmentcode.com/guides/adversarial-code-review)；实证：LLM 对自己的输出最宽容、且**在错的地方最宽容**——提示词救不了，分权才行 | 已在做（Flash 执行＋主会话复跑验收）；本批起**成文化**：每阶段验收人≠实现人，验收者只拿 diff＋验收单 |
| **攻击树** | 把对手目标逐层拆成子目标×手段，每片叶子对一条缓解 | [UK NCSC](https://www.ncsc.gov.uk/collection/risk-management/using-attack-trees-to-understand-cyber-security-risk)、[Airbus](https://www.protect.airbus.com/blog/security-architecture-part-2) | §2 对现设计画两棵树（越权用／堵死合法用户），D 批设计逐叶对账 |
| **Pre-mortem** | 假设三个月后项目已失败，倒推死因 | [Plan Review Adversarial](https://smithery.ai/skills/neversight/plan-review-adversarial) | §2.3 十条死因→每条对应本设计的挡法 |
| **风险分级路由** | 认证/授权/支付路径＝最高审查优先级，advisory 起步、校准后再设阻塞门 | AugmentCode 指南 | D 批属最高级：全部新测试门阻塞化（不走 advisory） |
| **修复循环换审查者** | 修完必须换一个新审查者过，才升级给人 | 同上 | D 批每阶段：Flash/主会话实现→**另一端**复跑（本地↔服务器两视角互换） |

**租约/令牌的业界模式**（[Auth0 轮换＋复用检测](https://auth0.com/docs/secure/tokens/refresh-tokens/refresh-token-rotation)、[WorkOS 令牌族撤销](https://www.workos.com/blog/why-your-app-needs-refresh-tokens-and-how-they-work)、[oauth.net](https://oauth.net/2/grant-types/refresh-token)、[Cryptlex 浮动租约](https://cryptlex.com/docs/license-management/license-templates)、[LicenseSpring 硬件锁定](https://licensespring.com/platform/node-locked-licensing)、[10Duke 签名离线令牌](https://www.10duke.com/learn/software-licensing/offline-licensing)）：
- 访问令牌短命（15–60 分钟级）；刷新令牌**每次使用即轮换**，旧令牌被复用＝被盗信号→整族吊销
- 离线宽限 14–30 天是行业常态（微软 Office 30 天＋降级模式）；到期**硬停**不做无限宽限
- 离线校验靠**非对称签名**（本地只存公钥，伪造不了），不靠「本地文件难读」
- 令牌存 OS 级保护库（Windows＝DPAPI），不是混淆文件

## 2. 用最深打法重审现设计

### 2.1 攻击树 A：「让无权者用上本机能力」

```text
A. 无权使用本机能力
├─ A1 拿到别人的 .tygf_session 拷到别的机器
│   └─ 现状：混淆＋机器指纹（server.js:8216 硬件绑定）→ 已挡；★租约制后令牌含机器指纹签名，仍挡
├─ A2 抓包/重放旧票据
│   └─ 现状：票据短命＋代际（bindingGeneration）→ 挡；★租约令牌带 exp＋jti＋一次性轮换，窗口更小
├─ A3 在受害者浏览器里用自己的 pairingTicket 顶绑（换绑劫持）
│   └─ 现状：pairingTicket 由登录态签发 → 需先盗登录；★多绑定后「顶绑」本身不存在了（并行不互斥），
│      但新增 A3'：恶意者在自己浏览器登受害账号？＝登录安全问题，非本层；多绑定让此面**不扩大**
└─ A4 离线超期后继续用
    └─ 现状：无离线能力（每跳在线）→ 不存在；★租约制新增此面 → 缓解：租约短（72h）＋到期硬停＋
       续租需有效刷新令牌（轮换族）；宽限期内功能**全量**可用（不搞半残模式，行为可预期）
```

### 2.2 攻击树 B：「让合法用户被堵死」（我们真实吃过的一树）

```text
B. 合法用户无法工作
├─ B1 网络慢/抖 → 每跳验票超时（C2，今天实锤两次以上）
│   └─ ★租约制：本地核验，无每跳云端 → 叶子消失
├─ B2 换账号/多浏览器 → 机器级单绑定互斥（今天实锤）
│   └─ ★多绑定：按票据 activationId 选授权 → 叶子消失；服务器侧每账号 maxMachines 照旧
├─ B3 配对收尾组件同步失败卡半路（C5，两次实锤）
│   └─ ★配对变「发租约」一次性小载荷＋组件同步与授权解耦（后台补齐）；C 批先修重试兜底
├─ B4 错误码不说人话（C1，今天实锤）
│   └─ A 批先修；D 批新增状态全部带人话文案（租约剩余时长/为何停/怎么续）
└─ B5 授权入口消失/按钮骗人（C4）
    └─ A 批先修；★租约状态常驻卡头（剩余时长可视化，提前 24h 提醒续租）
```

### 2.3 Pre-mortem：假设 D 批三个月后失败，十种死因

| # | 死因 | 挡法（设计内建） |
|---|---|---|
| 1 | 离线硬停太早，用户在飞机/断网被掐 | 租约 72h＋到期前 24h 预警＋续租失败自动再试退避；硬停仅「过了租约仍续不上」 |
| 2 | 离线硬停太晚，被白嫖窗口拉大 | 72h 是行业短侧（对标 14–30 天上限）；轮换族复用检测即时吊销 |
| 3 | 令牌被从 DPAPI 挖出复制 | 令牌绑定机器指纹签名，他机无效；轮换后旧令牌作废 |
| 4 | 多绑定变成「一台机器无限账号」 | 每账号 maxMachines 由服务器在**发租约时**判定（不是配对时一次性）；助手侧上限 3 个激活并存 |
| 5 | 计费/信任链被绕过（铁律区） | 租约只管「能不能用本机能力」；执行计费、行合同、结算闸**仍走现有服务器链**，D 批零接触 |
| 6 | 静默降级（用户没发现授权失效还在跑） | 停＝真停（入口拒绝＋明确报错）；所有降级状态 UI 可见＋写入事件日志（沿用「折叠不得删报」精神） |
| 7 | 迁移把现有用户绑定弄丢 | 现绑定自动转为首张租约（一次性迁移脚本＋可回滚；灰度：先测试站→观察 48h→生产） |
| 8 | 服务端发租约接口被刷 | 签发走既有登录态＋频控；租约签发入审计表（谁/哪机/多久），异常发放告警 |
| 9 | 时钟回拨骗租约 | 令牌 exp 由服务器签；本地时钟漂移>阈值时以「最近一次成功续租时间＋租约长」封顶 |
| 10 | 又修出一堆「点了没反应」 | 全链路每态有人话＋事件日志；验收含 20 连慢网/断网/换号/双浏览器四剧本回放 |

## 3. D 批设计（对照业界模式逐项）

**模型一句话**：配对＝登录态签发「刷新令牌（存在 OS 保护库，绑定机器指纹）」；助手用它向服务器换「72 小时签名租约」（内含账号激活、机器指纹、能力范围、exp/jti）；本机每操作**本地核验租约签名**（公钥内置），零云端往返；后台静默续租（轮换＋复用检测）；助手可并存 ≤3 个账号的租约，按票据 activationId 匹配。

| 设计点 | 取值 | 业界对照 |
|---|---|---|
| 租约时长 | 72h（可配） | 低于行业 14–30 天上限，内测期取短侧 |
| 续租轮换 | 每次续租发新刷新令牌，旧族作废；复用即吊销整族 | Auth0/WorkOS 轮换＋复用检测 |
| 离线行为 | 租约内全功能；过期硬停＋人话指引 | Office 30 天/降级；我们更短更硬（铁律：不静默） |
| 存储 | Windows DPAPI（弃混淆文件方案，迁移期兼容读旧） | OS 保护库惯例 |
| 多绑定 | 助手存 ≤3 租约；服务器每账号 maxMachines 照旧；互不顶替 | 浏览器多账号同型 |
| 撤销 | 解绑→代际＋1→下轮续租即拒；已发租约自然到期（≤72h 窗口，明确告知） | 代际机制已有，复用 |
| 计费边界 | 租约≠计费；执行/结算链零改动 | 铁律隔离 |

**迁移**：现役绑定自动兑换首张租约（服务器一次性迁移）；旧验票路径保留一个版本作回退开关（flag 控制，默认关）。

## 5. 决策点

| # | 待拍 | 建议 |
|---|---|---|
| D-1 | D 批做不做 | **做**（这是「一劳永逸」的本体；不做＝慢网/换号类问题永久伴随） |
| D-2 | 租约时长 72h | 72h；要更长说一声（最长 7 天） |
| D-3 | 多绑定上限 | 助手侧 3 个账号并存 |
| D-4 | 发版节奏 | C 批 3.7.25 先行止血，D 批 3.7.26 跟上（间隔≥1 周观察） |

## 6. 不做

不动计费/结算/信任链（铁律区零接触）；不做无限离线（租约即上限）；不做静默降级；不改 MISMATCH 判定语义；生产站零操作直到灰度过关。
