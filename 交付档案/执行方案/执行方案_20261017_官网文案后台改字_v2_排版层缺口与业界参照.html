坑一：断行不是文案，是 JSX 结构

根因home-view.tsx:210 / :256 / :608

「改一个语言不难／难的是每个语言都要一起改」这句标题，在代码里是 titleL1 + titleL2a + <wbr /> + <span class="phrase">titleL2b</span> 四个东西。断点位置在 <wbr/> 上，不在字符串里——所以你在后台把 titleL2a 改长，断点不会自己挪，只会溢出。

坑二：回车被 CSS 吃掉

实测home-v17.css:82 · 全站 white-space:pre-* 命中 0

线上 .hero-copy 计算样式是 white-space: normal；我把它的文本换成带 \n 的两行，实测高度从 105px（3 行）变成 35px（1 行）——回车被当普通空白折叠。服务端也不剥 \n（只剥零宽、拒双向控制符），于是形成"存进去了但看不见"的静默失效。

坑三：改长就裁字

实测home-v17.css:80 .hero-title-line{white-space:nowrap}

首屏大标题那一行 nowrap 写死。线上实测：原文 7 字宽 597px，改成 11 字后 scrollWidth 799px ⇒ 溢出 202px（约 34%），而文档宽 1266px < 视口 1281px ⇒ 不出横向滚动条，字被切在容器外。编辑框里没有任何预警。

坑四：新标记会撞既有门（必须同批改）

约束smoke-seo-consistency.mjs:351/:363

那道门断言「JSON-LD 里每条 FAQ 问/答都必须能在页面文本里找到」＋「可见 FAQ 条数＝结构化条数」。一旦文案里带 \n 或 [[不折行]] 这类标记而渲染端原样输出，比对就红。所以标记必须在 JSON-LD 侧剥离、在渲染侧解析，两处同批改，否则就是"改完上不了线"。

坑五：没有 HTML 渲染口（这是好事）

边界src/components/site/ 内 dangerouslySetInnerHTML 命中 0

站点组件里唯一的 dangerouslySetInnerHTML 是 JSON-LD（(zh)/page.tsx:97，且转义了 <）。⇒ 方案不能靠"让运营写 HTML"（既有 XSS 面 + 会绕开所有守卫），只能"受限标记 → 解析成 React 节点"。这条约束反而让方案变简单。

对我们的含义
  • 换行不是"加个按钮"那么轻，也不是"要换整套 CMS"那么重——它需要一次约定：内容里 \n ＝硬换行，渲染器唯一负责把它变 <br/>，并且按字段声明是否允许（Keystatic 的 softBreaks 开关）
七家合起来给我的三条硬结论（也是"学到什么"的答案）

① 换行必须是内容数据 + 唯一序列化器负责（Sanity hardBreak 最干净；Tina 的私有 \ 是反面；Statamic/Apostrophe/Decap 干脆不给换行按钮）。② 排版给"角色枚举"，永远不给样式输入（Apostrophe styles{label,tag,class}、Sanity {title,value}、Payload enabledHeadingSizes；Payload 的 TextStateFeature 内联样式是官方自己标"默认关闭"的反面教材）。③ 能力要一处声明、删了就是禁用（Payload features 数组、Sanity disableActions、Tina toolbar、Bard setDefaultButtons）——我们现在的"纯文本、不支持加粗"是一句注释，不是一份声明，所以谁都能在下一次改动里悄悄放开。

为什么是甲 + 丙最小集

甲不动数据形状就能把"断行"从 JSX 搬进文案，Owner 立刻能自己决定在哪里断；丙解决"字体/字号"，但只给有限角色——因为全站一款思源黑体 + clamp() 字号是设计语言的一部分，给运营自由填字号＝把首页变成 Word。业界一致：Sanity 的 styles、Apostrophe 的 styles[].class、Payload 的 enabledHeadingSizes，全是"枚举可用样式"而不是"开放样式输入"。

但甲有一个必须一起处理的副作用：把断行写进内容＝断行点从此与视口无关。桌面上一句「难的是每个语言都要 / 一起改」断得刚好，到 390px 宽的手机上可能变成「难的是每个 / 语言都要 / 一起改」三行还带空洞。业界三条应对：① 换行点只在指定视口生效（hide-sm 式条件 <br/>）；② 该角色改回自动折行 + text-wrap:balance（我们 home-v17.css:79/:82 已经在用 text-wrap:balance/pretty，本来就有这条路）；③ 只允许"不折行短语"，不允许自由断行。我建议 ①+② 混做：大标题行保留手动断行但按视口降级，正文段一律自动折行。

05可点原型：改一句标题，断行、不折行、防溢出

这就是补完之后你要有的操作面。左侧编辑、右侧预览复刻的是线上同一套 CSS 语义（现状那档里 \n 真的会被折叠、标题行真的会被裁）。两条判据都从真实 DOM 量：不折行单元溢出像素、实际行数对角色预算。试试：现状档把标题改长几个字看它被裁；切到补齐档按【↵ 换行】把它断成两行，再断一次看行数超预算。

06执行顺序（换行/排版提到第一刀，且不用先碰生产锁）

1

排版层最小可用：硬换行 + 不折行短语 + 溢出预警（估 2—3 天）

五处同批改，缺一不可：① 渲染端新增 renderCopy() 纯函数（\n→<br/>、[[..]]→.phrase、**..**→<strong>）；② CSS 让 .hero-title-line 的 nowrap 由数据决定（有换行就分行）；③ 每个键声明是否允许软换行（抄 Keystatic 的 formatting.softBreaks：大标题行允许、按钮与小标签不允许），并且换行点按视口降级（窄屏改回自动折行 + text-wrap:balance，避免手机上断成三行）；④ JSON-LD 侧剥离标记（否则 smoke-seo-consistency:363 直接红）；⑤ 服务端 PATCH 的长度上限改按剥离标记后的可见字数计，标记白名单一处声明（抄 Payload「数组即能力集」：出现 <、未闭合 [[、非白名单符号即拒，删按钮＝禁能力而不是藏 UI）。

验收判据（可复跑）：npm run test:seo-consistency 0 FAIL；test:content-studio-v1 新增"标记语法"用例（含负控：<b>x</b> 被拒、[[a 未闭合被拒、不允许软换行的键带 \n 被拒）；浏览器实测三档视口（1280 / 768 / 390）——把首屏标题插入换行后，桌面按手动断行、390px 自动折行且无横向裁字；预览预警与线上实际一致（用 scrollWidth>clientWidth 与行数对角色预算判定，不是估算——本件 §05 原型已按这两条判据实现并跑过）。

这一刀不需要动生产写锁：全部改动在渲染与校验层，做完即可在测试站验证。生产放行是另一件事（上一版刀一），你说了不动生产我就不动。

2

把 33 个碎片键合并成整句（估 1—2 天，做完才叫"能自己断行"）

现在 titleL2a/titleL2b 这类键是断行的替身。合并＝一个区块一个完整字符串 + 标记表达断点；<wbr/> 与 .phrase 改由标记驱动。风险：键名变更会让线上已存的旧值失配（白名单按"当前内容树的字符串叶子"算），所以必须走"新键并存 + 自愈迁移"，不能直接改名。

判据：迁移后 getContentStudioState() 的 ACTIVE 树里碎片键数＝0，且首页渲染像素级不变（截图对比 scrollWidth/clientWidth 全等）。

3

排版角色（select）+ 漏标 lint 守卫（估 2 天）

角色枚举让运营在"大标题行/副标题行/小标签"之间选，字号仍归设计语言；守卫抄 eslint-plugin-i18next 的 no-literal-string，把"未标注的中文文本节点"变成写码即报错。

4

结构编辑（FAQ 条目增删排序）——仍排后面

它比排版层更重（数组写回 + 结构级 diff + 撞 FAQ 数量守卫），但没有排版层也照样能用；你要的"最基本"不在这里。

07待你拍的（三件，都不涉及动生产）

① 标记语法选哪套

需拍

甲（字符串 + \n + [[不折行]] + **强调**，零迁移）／乙（segments 数组，最干净但要 3—5 天且撞合同纪律）。我推荐甲，理由：95 个键形状不动，改动集中在渲染与校验，今天就能在测试站看到效果。

② 要不要给"字号"一个口子

需拍

只给 3 个排版角色（推荐），还是允许在角色内微调（±1 档）。后者等于把设计语言交给运营，首页三秒风格漂移。

③ 开工顺序确认

需拍

先做排版层（刀 1—2，不碰生产锁），还是先做上一版的"生产放行"。我的建议：先排版层——因为它做完你在测试站就能真用到，而放行只是把能力从测试站搬到生产。
