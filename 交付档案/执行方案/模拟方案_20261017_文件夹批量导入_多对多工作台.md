## 0. 一句话结论

**能做，而且正好接在现成的两根桩上**：助手端已经有「原生文件夹选择框」（现在只服务"选输出目录"），浏览器端已经有「多稿列表 + 一键扫描队列」。要新增的只是：助手把选到的（或粘贴的）文件夹**递归列一遍里面的 PSD/表格**，浏览器把这些路径灌进现有多稿列表/表格解析。两条路（打开选择框、粘贴路径）都走本机助手，因为**浏览器永远拿不到本地绝对路径**——这不是实现偷懒，是浏览器的安全设计（见 F-1 证据）。

## 1. GitHub 与开源参考（全部实测可查）

- **GoogleChromeLabs/browser-fs-access**（★1,591）：File System Access API 的标准包装库。参考价值在于确认定位——它解决的是"浏览器标签内读写文件**内容**"，从头到尾拿不到路径；PSD 扫描链路要的是绝对路径，所以这条路对我们**方向不对**（表格可另议，见 F-1 备选）。
- **mlabbe/nativefiledialog**（★1,997）与 **btzy/nativefiledialog-extended**（★1,078）：原生文件/文件夹对话框的通用轮子（Electron 等桌面壳内部就用它）。证明"要原生选择框，就得有一个本地进程去弹"是行业共识；我们的 `picker-dialogs.cjs` 是同一职能的 PowerShell 版实现（已带置顶/单实例/超时合同），**直接复用**。
- **Kriswd/Fdesign**（★6）：「Photoshop + Excel PSD 批量套版、Excel 批量出图」，文件夹进→批量出 的先例产品。
- **greenzorro/excel-ps-batch-export**（★20）：PSD 模板 + 表格驱动批量导出，同样以"输入文件夹"为入口。
- **jonahvsweb/Photoshop-Automated-Resize-to-Web.jsx**（★6）：PS 脚本界的老牌形态——"处理所选目录里全部支持的文件"，佐证「文件夹进」是用户对批量工具的默认期待。
- **WICG/file-system-access issue #145**（已关闭，未实现）：标题就是《The API should allow working with absolute paths》——官方立场是"不给绝对路径，想记住位置请存 handle"。这是 F-1 判定的最硬出处。
- MDN `showDirectoryPicker` 页：标注 experimental / 仅 HTTPS / 返回 handle 而非路径；Chromium 侧安全 issue 还在持续收紧它的激活条件（连 mouseover 触发都算漏洞）。

## 2. 现状核实（每条带 file:line）

- 加 PSD 的现状入口只有两个：`design-file-card.tsx:748-776`「添加 PSD」一张一张选（走助手 `/v1.5/select-file`）；`design-file-card.tsx:913-959` 粘贴多行路径。源码注释 `design-file-card.tsx:778-783` 自己写明了原因：**浏览器不给被拖入文件的绝对路径，所以连拖拽都做不了**，"粘贴路径"就是为绕开这条限制设计的。
- 助手已有文件夹对话框：`server.js:5455-5490`（`/v1.5/select-folder`，弹 `FolderBrowserDialog`，验票要求 operation=`select_file`，返回 `folderPath`）；对话框合同在 `picker-dialogs.cjs:1-113`（TopMost/单实例 Mutex/cancelled・timeout・launch-failed 可区分错误码）。
- 票证体系成熟：操作枚举 `execution-ticket.ts:33-43`（含 `select_file`），签发口 `src/app/api/local-assistant/ticket/route.ts:49-50` 白名单 + Origin 绑定 + 激活校验。**新能力骑在 `select_file` 票上即可，服务端票务零改动。**
- 表格现状：纯浏览器 `<input type=file multiple>`（`csv-step.tsx:400-406`），解析全程在前端（`csv-step.tsx:102-137` SheetJS/csv 双通道），多表格合并已有（`csv-step.tsx:139-185`）。红线注释 `csv.ts:1-2`：「纯前端解析，不上传表格内容到任何 API」。
- 上限常量：PSD 每单 12 个（`design-file-card.tsx:992` `MAX_PSD_ENTRIES`）；语言 12 / UI 行 300（`batch-limits.ts`）；单表 5MB（`csv-step.tsx:51`）。

## 3. 对抗式审查（结论按此拍）

- **F-1（方向判定，阻断级）**：浏览器三条路都拿不到绝对路径——`<input webkitdirectory>` 只给相对路径、`showDirectoryPicker()` 只给 handle（MDN）；官方 issue #145 明确拒绝。而扫描链路认 `masterPath` 绝对路径（助手+Photoshop 按盘符读文件）。**推论：文件夹导入必须落助手端，浏览器端方案在 PSD 上是死路。** 表格技术上可用浏览器方案（只需内容不需要路径），但那样"粘贴文件夹地址"这个 Owner 明确要的入口就做不了——为一致性，表格也走助手（内容全程不出本机，见 F-3）。
- **F-2（安全，必须缓解）**：新增"递归列目录 + 读文件"端点=给了本地任意网页一个文件系统侦察原语。缓解五闸：①票证同门（Origin 绑定 + 激活 + TTL，沿用 select_file 类）；②扩展名白名单（PSD 类只列不读；表格只读 .csv/.tsv/.txt/.xlsx/.xls）；③规模闸（深度≤8、命中上限、15s 超时，超了返回 partial+truncated 不硬撑）；④不跟随 symbolink/junction（防环）；⑤端点只读，无写/删/移动动词。残余风险如实标注：本机持有有效票据的其他页面理论上可枚举同类目录。
- **F-3（红线，须 Owner 知情）**：`csv.ts:1-2` 写死"表格内容不上传任何 API"。走助手后，**表格字节（≤5MB/个）会经 localhost 助手流回浏览器标签**——不出本机、不进云端、解析仍在浏览器，但字面口径变了。方案：改述该注释为「表格内容只在『本机助手⇄浏览器』之间流动，永不出本机、永不上云」，并在 L2 登记。这条不藏着，请您知情拍板。
- **F-4（性能，必须异步）**：助手是单进程 Node，同步递归会堵死 Photoshop 自动化的事件循环（正在跑的扫描会被卡住）。实现必须 `fs.promises` + 并发≤4 + 15s 时间闸；网络盘/超大目录慢时返回"已列到的部分+truncated"并如实显示，不静默。
- **F-5（上限策略）**：一个文件夹 26 个 PSD，单上限 12——按自然序（文件夹序→文件名，与资源管理器同序）取前 12，**超出的 14 个如实报告"未加入"，不做静默截断、不悄悄换排序**。上限本身是产品决定（1 稿=1 批次=计费口径），模拟里按现状演示。
- **F-6（重名）**：子文件夹重名（`客户A\首页.psd` 与 `客户B\首页.psd`）——列表行必须显示相对路径（或"文件夹名\文件名"），否则用户分不清谁是谁；去重按绝对路径（Windows 大小写不敏感）。
- **F-7（云占位文件，如实标注）**：OneDrive「按需下载」的占位 PSD，列目录阶段 Node 没有可靠 API 识别（blocks==0 只是启发式，待确认）——**不假装能提前发现**；实际会在扫描阶段由 PS 报"文件不可读"，走 D10 的停下点名。
- **F-8（跳过规则）**：跳过点开头目录（.git/.cache）、`$RECYCLE.BIN`、`System Volume Information`、符号链接；跳过计数如实报"跳过 N 个隐藏/系统目录"。
- **F-9（与 D10 的关系）**：导入只做"灌列表"，扫描仍走今天的「全部扫描（按顺序）」队列（失败即停点名、续跑跳过已扫）——**零新状态机**。单文件工作台零变化。
- **F-10（助手版本纪律）**：助手行为变化=必须 bump 版本（3.7.15→3.7.16）+ 装机包 + release identity 同步；验收必须含**助手端证据**（吸取 PhotoCraft F-3 教训：验收路径验不到助手侧=不合格）。
- **F-11（重复导入）**：同一文件夹再导一次=增量，已存在的绝对路径去重忽略（报"n 个已在列表"）；已扫描的不重扫（D10 口径）。
- **F-12（路径校验）**：粘贴相对路径/文件而非文件夹/不存在 → 可区分错误码（NOT_A_DIRECTORY / FOLDER_NOT_FOUND），逐类报因，不装死。

## 4. 设计（推荐架构，三层）

**助手端（download/local-assistant）**
- 扩展 `POST /v1.5/select-folder`：body 增加可选 `purpose`（`import_psd` | `import_tables`）与可选 `folderPath`（给了就跳过对话框直接校验该路径——服务"粘贴地址"入口）。返回追加 `listing`：`{ files:[{path, relPath, size}], total, ignoredCount, skippedDirs, truncated }`。
- 新增 `POST /v1.5/read-table-file`：body `{ path }` → 只读白名单扩展、≤5MB/个，返回 base64 内容（只给浏览器解析用）。
- 票证：两处都验 `select_file` 操作票（与 select-file/select-folder 同门）。
- 递归器：异步、并发≤4、深度≤8、15s 闸、跳过规则见 F-8、自然序排序。

**浏览器端（工作台）**
- `design-file-card.tsx` 批量卡新增两个入口：「从文件夹导入…（含子文件夹）」主按钮 + 「粘贴文件夹路径」输入框；导入报告行四种色（成功/部分/错误/信息）；列表行加相对路径层级显示（F-6）。
- `csv-step.tsx` 新增同样的两个入口；表格文件经 `read-table-file` 取回后**仍走现有 parseOneFile**（SheetJS/csv 双通道、合并、上限逻辑一概不动）。
- 新增纯函数 `planFolderImport(existing, listing, cap)`（浏览器侧）：去重、自然序、截断计数、返回四类清单——挂 smoke，与 D10 的 buildMultiScanQueue 同法。

**上限与跳过规则汇总**：PSD 上限 12（现状）；表格文件上限沿用现状合并口径；单表 5MB；深度≤8；15s 闸；跳过隐藏/系统/链接目录并计数；一切超限如实报告。
