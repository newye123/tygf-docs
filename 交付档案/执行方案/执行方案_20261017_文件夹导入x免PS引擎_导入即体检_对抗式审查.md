# 执行方案：把「免 PS 引擎」纳入文件夹导入 —— 导入即体检，替换不再依赖 Photoshop（对抗式审查）

**一句话判词**：PhotoCraft 引擎让「审查层」从扫描之后提前到导入那一刻，也让没有 Photoshop 的机器第一次能走完「导入 → 体检 → 替换 → 回执」全程；本方案把它接进 v2 单元模型，做对抗式审查与 UI/UX 上帝视角重排，产出配套模拟 v3（真机实测全绿）。先对表一件事：**「已内置」目前是半程**——引擎已装并且真稿扫描已跑绿，但「内置进安装包」「扫描器产品化」「执行接线」都还没落（§0 逐条给坐标），本方案按「可用原型、产品化在途」设计，不抢 PC 线（Qoder 会话）的班。

## §1 免 PS 引擎给方案带来的三个新能力

1. **导入即内容体检（R3 前置）**：扫描不再依赖 Photoshop 与浏览器内队列 → 导入期直接逐稿真扫（免 PS），单元卡直接带结论：覆盖率、近似点名、放错红标。影响：引擎就绪时，「载入 → 手动扫描」这一步消解，工作台从「扫描发生地」变成「复核＋替换地」。
2. **免 PS 全流程替换**：没有 Photoshop 的机器也能完成替换；回执含引擎身份（运行时读取）＋逐稿读回校验＋「未使用 Photoshop」声明。
3. **来源安全绑定**：扫描来源＝执行来源硬绑定（ISSUES #159）；跨通道执行一律拒；**不许有「没凭记也放行」的宽松分支**（沿用 PC 线已定纪律）。

**诚实口径（所有对外可见文案必须遵守）**：引擎扫描 38 项排版字段可得 **36 项**（缺「悬挂标点」；行距在多 run 混合态待重做修复）——如实标注、不补 0、不写「与 PS 完全一致」；免 PS 替换对外文案在「真 PS 开档验产物」通过前不写「完全替代 Photoshop」。

## §2 对抗式审查（本轮新面 · F-1 ～ F-10）

- **F-1 跨引擎残余风险**：第一道防线（同原文命中层数 > 投喂条数 ⇒ 整批拒）已把最容易静默漏译的那条形压成硬失败；彻底解（manifest 增「扫描引擎」标记 ＋ 跨引擎一律拒 ＝ 合同变更，四层同步 + fixture）必须独立班车，本方案不夹带。
- **F-2 凭记时效（待确认）**：引擎升级 → 哈希变 → 旧凭记如何处置需 A 段定策略；UI 预置「凭记校验不过 → 拒执行并引导重扫」的文案与入口。标「待确认」不编结论。
- **F-3 扫描耗时与规模**：224 MB/7.28s（冷缓存 4.3s → 7.28s 差异未定性，不编原因）；12 稿上限下导入期扫描约 30–90 秒；结构/表格审秒级先出结论，不被扫描堵住；逐稿进度可见、可中止；助手端串行（引擎单会话）。
- **F-4 字段缺口诚实呈现**：报告固定呈现「36/38 可得 + 缺哪些」；不补 0、不静默。
- **F-5 质量底账**：58 份批测 stored 0.34 vs typeset 0.82、泰文 fallback 4/90（`AI_MEMORY/TASK_LOG.md`）；免 PS 通道对外承诺按 F 段门槛（真 PS 开档验产物）放行。
- **F-6 双通道并存规则**：同一单元只允许一个来源执行；来源徽章常显；引擎就绪默认推荐引擎通道（无队列等待），切换＝重扫（文案讲明）。
- **F-7 安装包未内置期间的可用性断点**：引擎在＝全流程；引擎不在而 PS 在＝退回 v2 行为（载入后 PS 通道扫描）；都不在＝如实提示「这台机器无法扫描」（无法伪造）。
- **F-8 灰度失控风险**：开放前必须服务端判定（六面 · 面 3）；UI 引擎条预留灰度标注位。
- **F-9 C1 重做判据补强（实证）**：封驳版产物里 3 层 `textKind="[object Object]"`（stringify 缺陷，见 `tmp-real-scan-observation.json`）——「逐字段与原型对表」的差集必须把 `textKind` 枚举也纳入（封驳记录已含此意，此处强调保留）。
- **F-10 读回校验必须显示**：执行器读回相位是既有能力；回执必须写出「读回校验 ✓」，否则用户会以为没验。

## §3 UI/UX 上帝视角（yt-uiux 五阶段 · 本轮重排）

### 一、需求淬炼
- **核心任务（一句话）**：把客户交付的文件夹拖进工作台，在替换之前看清每个单元「能不能替换、哪里会漏」，然后一键在本机完成全部替换——这台电脑没有 Photoshop 也全程可用。
- **目标用户**：运营/排版 PM；Windows 本地助手；手里是客户给的一整个文件夹；情绪＝怕漏译、怕张冠李戴、怕机器没装 PS 卡死。
- **成功标准**：导入到看清单元结论 ≤ 1 分钟（12 稿规模）；放错稿 0 件进入替换；无 PS 机器全流程可完成；跨通道误操作 100% 被拒。

### 二、信息架构
- **三页**：导入对话框 → 单元列表（已带体检结论）→ 工作台（复核＋替换＋回执）。比 v2 少一环——v2 的「载入后才扫描」在引擎就绪时合并进导入结果；能合并的理由：扫描不再需要 PS 队列，没有理由让用户等第二次点击。
- **关键路径**：选夹 → 读日志/单元卡 → 载入单元 → 勾选放行（如需）→ 开始替换（免 PS）→ 回执。

### 三、线框（ASCII）

```
[导入对话框]                 [单元列表]                        [工作台]
┌──────────────┐   ┌───────────────────────┐   ┌────────────────────────┐
│ 路径（本机框） │   │ 读日志：结构/表体/引擎扫描 │   │ 顶栏：已载入 + 来源凭记  │
│ 默认递归含子夹 │   │ 单元卡×4：              │   │ 稿列表（已扫描·引擎）   │
│ [取消][开始读取]│   │  徽章·覆盖率·放错        │   │ 表格预览 + 体检警告     │
└──────────────┘   │  [载入工作台→]           │   │ 单元体检报告（矩阵/点名/闸）│
                    └───────────────────────┘   │ [开始替换(免PS)] [PS通道]│
                                                 │ 回执：身份+校验+放行    │
                                                 └────────────────────────┘
```

### 四、设计系统
- **色**：沿用正文体系——accent `#1b5bd0`（行动/链接）、ok `#0d6f4a`、warn `#8a5a00`、bad `#ae2318`、sunk `#eef1f5`；**新增 teal `#0d9488`＝「免 PS 引擎通道」语义**（徽章/状态条/CTA；暗色 `#5eead4`）。
- **字**：IBM Plex Sans（标题）/ Noto Sans SC（正文）/ IBM Plex Mono（数字、路径、哈希、计数）——沿用。
- **组件**：状态条（绿/蓝/黄/红/teal）、徽章（ok/gray/amber/red/sky/teal）、单元卡、覆盖率矩阵、替换回执卡。
- **判断**：工具界面信息密度优先，不给装饰留面积；关键数字全部等宽对齐。

### 五、UI 对抗审查（会怎么翻车 × 改法）
- **UI-F1** 「导入即体检」改变旧心智（扫描＝进工作台后的动作）→ 工作台顶栏明说「本单元导入期已由引擎扫描完成」，报告载入即可见；不出现第二遍扫描按钮。
- **UI-F2** 导入期等待 → 结构/表格审先行出结论；扫描逐稿进度；可中止（中止的单元卡标「未扫」，载入后可补扫）。
- **UI-F3** 双通道选择困惑 → 按可用性自动选（引擎就绪→引擎）；来源徽章常显；切换成本＝重扫（文案讲明）。
- **UI-F4** 放错红标：v2 可勾选放行 → 本轮改**硬拦截**（少一个能放错的口子）；代价是「确实属于本单元但覆盖率低」的极端情形要走移稿/补表重导——接受，待 Owner 确认。
- **UI-F5** 缺字段穿透 → 报告固定一行「字段可得性」说明。
- **UI-F6** 回执信任 → 引擎身份＋哈希＋读回校验＋放行记录四件套常显。
- **UI-F7** 窄屏 → 三页均单列流式；矩阵与表格横向滚动兜底。
- **UI-F8** 灰度标注 → 引擎条预留「预览版/白名单」位，按旗标注入。

## §5 执行序（本方案部分 · 与 PC 线解耦）

- **P0（无依赖，可先做）**：浏览器纯函数（单元划分 / 多表合并 dry-run / 体检规则）＋ 导入入口 ＋ 单元卡 v3 UI（含引擎条、三种扫描状态：已扫/未扫/拦下）——引擎未接线时**自动退回 v2 行为**（结构/表体审；载入后 PS 通道扫描）。
- **P1（依赖 C1 重做 ＋ C2 凭记；由 PC 线供件）**：导入期引擎扫描接线（助手侧调扫描器包裹版）＋ 体检报告数据（覆盖率预检 / 近似点名 / 放错红标）。
- **P2（依赖 A 段接线）**：替换入口（引擎通道）＋ 跨通道拒绝 UI ＋ 回执引擎身份行。
- **P3**：测试站验收 ＋ 无 PS 真机全流程。
- **判据**：P0＝纯函数单测 ＋ UI 模拟真机全绿（本页 v3 已先行演示判定逻辑）；P1＝同夹具双跑（引擎扫描 vs 原型）**逐字段差集为空**（含 `textKind` 枚举，F-9）；P2＝跨源批次必拒有测试证据、`pcExecutorEnabled=false` 时行为面零变化；P3＝无 PS 机 12 稿全流程 ＋ 真 PS 开档验产物。
