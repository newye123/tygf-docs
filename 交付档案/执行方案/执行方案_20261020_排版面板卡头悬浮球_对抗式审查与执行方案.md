# 排版面板入口：对抗式审查与执行方案

2026-10-20 · 测试站入口纠偏 · 「卡头按钮 + 悬浮球 + 右侧抽屉」

## 判定

测试站没有按设计稿走，不是样式没调好，而是**设计稿从未接到产品**。

2026-10-18 的三套入口设计只做在独立模拟台里，说明文档自己写明了边界：「产品里的排版面板……目前仍是内联展开；卡头按钮、悬浮球、抽屉这套入口和埋点尚未接到产品」（`交付档案/执行报告/排版面板入口设计稿_20261018/设计稿说明.md:39`）。测试站当时部署的 `6ff5c3c` 只补了一个右下角固定药丸 + 面板内联折叠，等于在旧入口上贴了一个补丁，设计稿里的卡头入口、右侧悬浮球、360px 抽屉、dialog 语义、Esc 焦点归还都没有落地。

本次把这套入口真正接进工作台，并选你指定的「轻量原生碳」。它不是设计稿三套皮肤里的现成一套，落地口径是：**轻量纸片的纸面承载 + 原生碳的碳色身份**——白底、碳色 1px 描边与文字、碳色 T 字标，不做纯黑实心块，避免和「下一步」主操作抢注意力。

## 对抗式审查

### A1 入口挪位会不会撞位置守卫？

不会。`TypographyPanel` 的 JSX 挂载点原地不动，仍在 `stage-preparation` 与 `stage-review` 之间（`src/components/workbench/workbench-view.tsx:2530` 附近）；抽屉本体在组件内 `createPortal` 到 `body`（`typography-panel.tsx:534`）。静态位置断言与 197 条 picker 断言均未改口径。

### A2 portal 出去会不会掉工作台令牌和字体？

会，如果不补作用域。`workbench-tokens.css` 明确记录：portal 容器不挂 `.wb-brand` 会退回旧色板。抽屉外层已补 `className="wb-brand"`（`typography-panel.tsx:537`），实测抽屉 `font-family` 为 `"Tuyigf Source Han Sans", "Source Han Sans SC", ...`，与工作台一致。

### A3 抽屉的键盘与读屏语义够不够？

`role="dialog"`、`aria-modal="true"`、`aria-labelledby` 指向标题（`typography-panel.tsx:545-547`）；Esc 关闭；Tab 在抽屉内闭环；打开时背景 `#workbench-surface` 设 `inert` + `aria-hidden`，并锁 `document.documentElement.style.overflow`；关闭时原样恢复。实测打开后焦点落在「关闭排版定制」按钮，背景 inert=true，`html.style.overflow=hidden`。

### A4 窄屏球会不会压住卡片？

不会。球用 `hidden xl:block`，1280 以下不渲染；卡头按钮文案在 `sm` 以下缩成「排版」。390×844 实测球容器 `display:none`，卡头按钮 68×30，文案「T 排版」，`scrollWidth=390`、`innerWidth=390`，无横向溢出。

### A5 未保存状态怎么让入口知道？

面板按「与已存盘内容是否不同」计算 `dirty`，通过 `onDirtyChange` 回传；卡头按钮与悬浮球各显示一个琥珀点（`workbench-view.tsx:2336`、`2558` 附近）。没有把「有没有值」误当 dirty（旧写法存完照样亮）。

### A6 关闭再开会不会丢草稿？

不会。本机偏好只在首次打开时读一次（`initialisedRef`），关闭时不重置 `profiles`；组件保持挂载、只不渲染 DOM（`typography-panel.tsx:530`）。单测覆盖「未打开时不渲染抽屉（组件仍挂载，未保存草稿留在状态里）」。

### A7 「轻量原生碳」到底长什么样？

- 卡头按钮：30px 高、12px 圆角、白底、`border-foreground/20`、碳色文字、碳色 4×4 T 字标、右侧 chevron。
- 悬浮球：44px 圆、白底 95% + 背景模糊、同色 1px 描边、碳色 T；悬停出右侧 tooltip。
- 抽屉：白底、360px / 92vw、左侧 1px 边、`shadow-2xl`；标题区沿用工作台的 T 图标与「内测预览」徽标。

### A8 部署会不会把别的任务带上去？

会，必须说清：本任务的提交是 `027118f`；但 `develop` 在其后又落了 `6a268fe`（本地助手 `ASSISTANT_DEVICE_INVALID` 事故修复）。发布预检的硬规则是「HEAD 必须是 `develop` 的后代、禁止从落后的树打包」，因此本次测试站候选只能是 `develop` 当前 HEAD `6a268fe`，它会同时带上那笔已提交的助手修复。两笔改动都已提交、工作树干净；若你要求严格只发 UI，需要先把发布线规则改成允许落后打包，这不属本任务授权，我没有动。

### A9 像素验证时抓到的真问题

第一版关闭抽屉后焦点掉到 `body`。原因不是没写 `focus()`，而是 `#workbench-surface` 还带着 `inert` 时调用会被浏览器静默丢弃；`requestAnimationFrame` 抢在 React 被动 effect 清理之前执行。改为在面板 effect 的 cleanup 里**先移除 inert、再聚焦打开前的 `document.activeElement`**（`typography-panel.tsx:256`、`270`），复测焦点回到卡头按钮（`aria-controls=typography-panel`）。这条已写进代码注释，避免以后又用 rAF 抢跑。

## 执行方案

1. **面板抽屉化**（`typography-panel.tsx`）
   - props 改为受控：`open` / `onClose` / `onDirtyChange`。
   - 关闭时不渲染 DOM，但组件保持挂载；首次打开加载本机偏好。
   - 抽屉 portal 到 `body`，外层 `.wb-brand`；遮罩点击关闭；Esc 关闭；Tab 焦点闭环；背景 inert + 锁滚动；关闭时焦点归还触发件。
2. **入口落地**（`workbench-view.tsx`）
   - 状态：`typographyDrawerOpen`、`typographyDirty`；开关回调。
   - 卡头右上角按钮：T 字标 + 「排版定制」/「排版」+ dirty 点 + chevron。
   - 右侧中部 44px 悬浮球：`hidden xl:block`，抽屉打开时卸载，tooltip。
   - 删除 `6ff5c3c` 的右下角药丸与 `expandSignal`；给 `.wb-brand` 加 `id="workbench-surface"` 供 inert 定位。
3. **测试**（`tests/unit/typography-picker.test.tsx`）
   - 适配新 props；新增 dialog 语义、Esc 关闭、关闭不渲染 3 条。
4. **验证与出包**
   - `npx tsc --noEmit`、定向 eslint、两条 typography smoke、vitest。
   - Playwright 在 1440×900 / 390×844 做真实像素读数与截图。
   - `npm run build`；发布预检与出包在隔离 worktree 执行，避免污染共享工作树。
   - 上传 zip + receipt，服务器执行 `deploy/deploy-test-release.sh`，回读 `.deploy-commit` 与 `/api/runtime-provenance`。

## 边界与遗留

- **写回未启用**：抽屉里仍如实显示「本次不发排版字段 / 仅保存在本机浏览器」，没有趁这次改造偷换能力口径。
- **本机助手 404**：本地 dev 未跑助手，字体清单探测为 `unsupported`，属预期；不影响入口与抽屉验证。
- **遮罩浓度**：当前 `bg-foreground/35` + 1px 模糊；若你觉得偏重，可降到 `/25`，这是一行样式，不改结构。
- **部署候选含他人提交**：见 A8；本次测试站若发 `6a268fe`，会把助手事故修复一并带上。
- **未推 origin**：本任务只提交本地 `develop`，没有 push。

## 结论

设计稿不是「实现得不像」，而是**根本没有接进产品**；这次把入口、抽屉、焦点与窄屏规则一次接齐，并用真实像素读数证明 1440 与 390 都没有溢出、球在窄屏不渲染、Esc 后焦点回到入口。后续只剩出包与测试站部署回读。
