## 4 领域事实：全部本机 PS 22.0.0 实测，下一个 AI 最容易重复踩

1. **字体只认 PostScript 脸名**。写显示名被**静默替换且不抛错**：`Arial`→`MyriadPro-Regular`、`Noto Sans SC`→`AdobeHeitiStd-Regular`、不存在的名字→`MyriadPro-Regular`。⇒ 写回后必须读回比对，不能信"赋值成功"。
2. `textItem.font` 读回来**就是字符串**；`item.font.name` 是 `undefined`。用它比对＝每次成功都误报换脸（我犯过，NC-A4b 钉住）。
3. **行距要先定自动开关**：`useAutoLeading=false` 之后再写 `leading` 才吃进；不关就写＝赋值成功、层高不变。百分比档走 `autoLeadingAmount`（默认 175）。
4. `String(item.leading)` 得 `"30 pt"`，`Number("30 pt")` 是 **NaN**，而 `NaN > x` 恒 false ⇒ 读回比对必须 `Number(item.leading)`，否则失败与成功读起来一模一样（我犯过，NC-A4c 钉住）。
5. **tracking 口径 = 1/1000 em**，闭式 `Δw = 间隙数 × tracking/1000 × 字号`（21 字符/12pt：500 ⇒ +120pt，实测 122→242；−100 ⇒ −24pt，实测 122→98）。可以拿来预测"这一改会不会顶破原稿行宽"，不必等 PS 出图。
6. **`noBreak=true` 在段落文本下把图层包围盒压成 0×0**，文字整层消失且不抛错 ⇒ 在锁死清单里，执行器与校验器都拒。
7. **composer（合成器）与 kind（点/段落）锁死**：切合成器改变折行位置，而"行数/已替换 N/N"的判据建立在自插硬换行上；点转段落后软换行**不落 0x0D**（实测 0 个换行符却是 5 行）⇒ 动它就是换计费与告知的地基，属合同变更。
8. **PS 22 没有原生 JSON**（`typeof JSON === 'undefined'`，`JSON.parse` 抛"引用错误: JSON 未定义"）。生产链的结果序列化靠助手 wrapper 注入的 polyfill（`server.js:935-991`）；新增嵌套字段要用它先验一遍（我做过了，`SER.json`）。字体探针那条通道**没有**这个 polyfill，所以探针必须手写序列化。
9. ES3 老雷仍在：无 `toISOString`、无 `String.prototype.trim`（ISSUES #141）；`case` 不能当对象键；`name` 是 ExtendScript 全局（会静默盖掉你的循环变量）；给对象写一个名叫 `hasOwnProperty` 的键会把继承来的方法覆盖掉。
10. **通道有差**：助手真跑批走 `DoJavaScriptFile` + wrapper；调试探针若走 `DoJavaScript` 字符串通道，环境不一样。验执行器要用文件通道，并把代码从出厂 jsx **按标记原样抽取**，别另写等价副本。
11. 本仓 `core.autocrlf=true`：被跟踪文件在工作树是 CRLF、新建脚本是 LF。⇒ 任何"按字节比两块源码"的守卫必须先归一行尾，否则它测的是"最后哪只手写的"（ISSUES #168）。
12. 机器实测的字体面数：PS 报 1605 行 / PostScript 唯一名 1587 / 扫目录 1293，交集 1235 ⇒ **PS 是权威清单**，不能用扫目录当准。
13. **"两侧各自绿"的接缝必须用真形状测**：A1 端点回对象数组、客户端只收字符串 ⇒ 每项被跳过，面板显示"读到 0 款"却报成功，助手门与前端门都绿。修法不是加断言文字，而是把解析抽成纯函数喂真数据（`typography-faces.ts` + `smoke-typography-faces`），并把"空清单"判成不可用而不是成功。同理，本轮六道负控里有两道**首跑没红**——因为断言写成了"源码里存在这行字"，文本在＝通过，改回不发也测不出；已改成带条件的形状断言。
