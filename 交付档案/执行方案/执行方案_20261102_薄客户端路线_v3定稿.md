## 0. 一句话

把"判断"从客户端搬走，客户端只剩"量尺寸 + 动手写 + 报事实"。之后别人逆向我们照旧可能，但**逆回来不再等于拿走能力**；顺带关掉一条已实测可走通的白嫖口子。

## 1. 先说这条已走通的账（比防逆向更要紧）

**钱的路径（我逐段复跑）**：`attempt/route.ts:43` 从请求体取 `totalAssignmentCount` → `:86` 落库 → 执行完 `attempt/report/route.ts:33,36` 收客户端回执 → `:61` 拿回执里**同一个自报值**去和库里那个自报值比 → `src/lib/trust-chain/settlement-adapter.ts:19-40` 把回执字段直译成结算输入（`:26` `artifactDisposition==='PUBLISHED' ? 'complete' : 'not_generated'`、`:32` `totalTextLayers: receipt.totalAssignmentCount`）→ `src/lib/server/photoshop-billing.ts:650-657` 算 `resultUsable` → `:659` `successfulStandardRows = resultUsable ? quote.standardRowCount : 0` → `:681-683` → `:719-729`。`resultUsable=false` 走的是 **`releaseReservation`（释放冻结额度、不扣）**，不是"扣了再退"。全链**没有任何服务端产物存在性复核**。

⇒ **走通只需四步**（A 路纸上推演、我逐条对齐行号）：正常 confirm 冻结 → 正常拿票据让 PS 真跑、文件落盘 → 回执谎报 `FAILED / completed=0 / artifact=NONE` → 结算全额释放。加重项：**诚实失败路径本来就把完整成品 rename 进 `outputRoot/quarantine`**（`v15-runner.js:251-253`、`working-copy.js:93-138`），所以谎报者连"保住成品"这段代码都不用改。

边界要说准，别夸大：

- 这条路要 `assistantToken` + 激活码 + reserved job（`ticket/verify/route.ts:80-86,93-96`），0 积分或未授权设备走不通 ⇒ 准确说法是**"已授权安装可以白嫖"**，不是"任何人都能白嫖"。
- 单文档链与批链要分账：批链里把 attempt 报成终态 `FAILED` 会跳出 `BATCH_RECEIPT_INCOMPLETE`（`execution-batch.ts:2016-2019` 的 pendingFrozen 只覆盖非终态），缺口只体现为 `:2060` `actualCredits` 变小；少报行也只落 PARTIAL（`:1449-1456,2058-2065`）。**但 A 路说"诚实路径今天也给 `TEXT_READBACK_VERIFIED`、不谎报也 0 费"——这条被我的复核推翻**：成功路径在 `v15-runner.js:305/333/349/359` 明确写 `REOPEN_VERIFIED`，`:255/:284` 那两处属于失败分支与中间态。批链今天照收费，靶子在单文档链。
- 一个真闸要认：`billing-challenge.ts:107-108,199-200` 对**报价行集 rowsDigest 确有服务端权威重算**。所以漏洞不在行集，在"结果是否成功"由客户端说了算。
- `standardRowCount` 全仓 43 处命中，全部当分子分母用，**没有一处与执行结果对撞**（`grep -rn standardRowCount src/app/api/local-assistant src/lib/server/local-assistant.ts` = 0 命中，rc=1）。

## 2. 要搬走的"判断"有多大（四路清点 + 我抽查）

- **binding-core**（今天以明文躺在 exe 里，母本实测 **76,418 B / 43 个函数**）：判断类 21（`compileBindings`、`looseKey`、`isNearMatch`、`compositeMatchForLayer`、`wrapTargetToSourceStructure`、`structuralTargetText`、`computeBindingPlanDigest`、`computeLedgerDigest`、`deriveObjectId`、`sameTextSignature` 等）。**全文件 0 处 `Date`/`Math.random`/`require`/`process`**（B 路复跑 0 命中）⇒ 纯确定性，**可原样搬到服务端，不用重写**——TS 源本来就在云端树 `src/lib/trust-chain/binding-core.ts`，服务端今天只 import 了它的 `sha256Hex`。
- **replacer（jsx）**：实测 2,043 行、101,528 B、具名函数 **62 个**（含匿名 71；草案写 63 是把 HTML 串里那个内嵌函数算进去了）。判断类约 24，判断内核约 490 行（≈24%）；0 调用点死码实测只有 `buildLegacyHtmlReport`（`1594-1716`，123 行，草案写"约 150 行"不实）。
- **扫描器与执行器也含判断**（草案前的假设"它们纯机械"被清单推翻）：`Thin_Executor.jsx` 的 `applyTypography:60`（写后读回 0.51pt 容差判 FONT_UNAVAILABLE 等）、`pickTypographyProfile:157`、`fail:201`；`Preparation_Scanner.jsx` 的 `typographyDerived:93`、`typographyOf:140`、`scanLayer:200`（隐藏层/空正文不入文字池、`layer_errors>0`→PARTIAL）。⇒ 搬判断不能只搬 replacer。
- **必须留在客户端的（架构边界）**：图层 bounds/渲染宽高、字体真实可用性与写后实脸名、`app.open` 后的 `textItem.contents`、`saveAs` 后 size/exists 复核、`sha256File`、删盘、母版指纹、`fsync`。⇒ **切割线**：客户端只上报"事实"（digest、存在性、字节数），服务端做判等、配对、质量结论、行-费映射、归因。这条线**今天已经存在一半**：`Reopen_Verifier.jsx:156-158` 自陈"只测量，判断在 Node 侧"，只是那个"判断"目前也在客户端进程里（`v15-runner.js:98/104`）。
- 撤明文的量：三段明文母本实测 `76,418 + 15,022 + 5,898 = 97,338 B`（草案的 97,794 用的是 exe 内 pkg 字典声明的 size，含包头，差 456 B）。
- 草案里"判据占 v15-runner 31.5%""prepare-batch 判断占 62%"两个数**已撤回**：分子区间未披露，B 路自算分别 23.5% 与 84.2%，无法定版。占比这类数留到 P1 出正式清单时用"带行区间 + 按字节"的口径重算。

## 4. 刀法（顺序不可换）

**P0 眼睛 + 止血前置（1-2 天）**
- 分发审计**从零建表**落库：`exeSha256` 今天根本没存（`distribute/route.ts:86-88` 解析、`:122-124` 只 `console.log`；`prisma/schema.prisma` 内 `grep -i exesha` 命中 0）⇒ 不是"存了不比对"，是要新建字段/表。
- 分发限流从内存 Map（`route.ts:34-46`，30/min，重启清零）换成**现成 DB 桶**——真位置是 `src/lib/auth/rate-limit-store.ts:17-49`（表 `rateLimitBucket`，`schema.prisma:216-224`；草案写的 `src/lib/server/rate-limit-store.ts` 不存在）。注意该桶要求 key 为 HMAC 摘要，installId 不能直填。
- 修 `check-exe-no-plaintext.cjs`：探针按 `__dirname` 解析、空探针集即 exit 1、补 `generated/*.js` 探针（取自构建输入 + 对照件 0 命中自证），并接进 `package-release.cjs` 的 preflight（现在只有 `:108-113` 那两道）。
- 判据：假 installId 打一次 ⇒ 库中出现该行；重启服务后限流仍生效；仓外 cwd 跑那枚红 exe ⇒ rc=1；现役干净件 ⇒ rc=0。**红/绿以哪枚 exe 为准要写死**（本机安装 3.7.31 报 CLEAN，树里 `build/dist/` 那枚 10-25 的报 2 leaks）。
- 草案里"P0 顺手加一条服务端重算 `objectEvidenceDigest` 拒伪件"**撤回**：`v15-runner.js:104` 对原始回读串取摘要、`:97` 判等却先做 CRLF→LF 归一 ⇒ 服务端直接重算会因行尾假红，必须先把归一口径钉成合同（属【合同变更】三层同改），列为 P3 的前置。

**P1 定界清单（1 天）**
- 出正式《函数归属清单》：每个 J 指定归宿，25 个未分类项人工读定版；把"只能在 PS 现场"的量列成受控清单；删掉 `buildLegacyHtmlReport` 等 0 调用点死码。
- 判据：脚本可测——对 jsx 与 `v15-runner.js` grep 已定归宿的 J 函数名，客户端侧命中即红。

**P2 `compileBindings` 上服务端（2-3 天，灰度白名单）**
- 复用现成 TS 源，新增服务端接口吃"观测 + 译文 + 决策"，返回绑定计划 + 权威 digest。
- **判据改法（A 路 F-6 把我原来的判据打死了）**：不能"改源 + 重生成"，因为服务端与助手吃同一份 `binding-core.ts`，两边同时变桩、`smoke-binding-core-generated.mjs:20/:48` 的同源断言照绿，端到端测不到东西。改成：**桩只注入助手进程**，断言"服务端权威 digest 与客户端上报 digest 不等 ⇒ 拒结算"——这条既能红，又不需要动源。
- oracle 反制同批：任何给判断的端点若不消耗一次性 challenge（`billing-challenge.ts:136,258,284`）、不经 DB 限流就返回 ⇒ 判为开放预言机，不收工。
- 合同变更三层同改（助手 evidence／服务端报价／结算闸）+ fixture + HANDOFF 标注；浏览器不 import 该模块（`local-assistant-client.ts:2109`），不是四层。

**P3 把"是否成功"的判定权收到服务端（2 天）——这条就是止血**
- 前置：先钉归一口径（见 P0 末）。
- 客户端只上报事实（`actualTextDigest`、落盘 size、存在性、attempt 阶段），服务端按自己持有的期望文本重算判等与质量结论；`resultUsable` 不再来自回执直译（改 `settlement-adapter.ts:19-40` 的入参来源）。
- 判据：三枚对照件——真成功、真失败、**谎报失败但产物存在**——金额必须由服务端重算决定，谎报件要么被拒要么照扣。这条判据能红，才叫漏洞关掉。
- 属单向门，真机点一遍 + 灰度。

**P4 搬扫描器与执行器里的判断（2-3 天）**：`typographyDerived`/`typographyOf`/`scanLayer`/`applyTypography`/`pickTypographyProfile` 改"客户端报读数、服务端出结论"；判据是一单 12 语端到端与搬前**逐行对拍**，差异必须逐条解释。

**P5 撤明文副本（1-2 天，P2-P4 之后）**：撤 `package.json:7-11` 的 `generated/**/*` assets；`server.js:122-141` 的"读原文算哈希"换成构建期 pin + 运行期比 bytecode 摘要，**pin 不得与被校验物同盘可写**（今天 `MANIFEST.json` 就同目录，篡改者可连核带期望值一起换）；`publish-local-assistant.cjs:85` 今天只防"同版本不同字节"，要补一条包内容断言。此后 jsx 退化为机械壳，**jsxbin 从"必须"降为"可选"**。

## 6. 反思：这一轮我漏了什么、为什么

- **照抄了子代理未披露区间的百分比**（31.5%、62%）就写进方案 ⇒ 正是我自己存过的规矩"引别手的指针与派生数要先复跑"违反现场。已撤回，占比留到 P1 用带行区间的口径重算。
- **引用了不存在的路径**（`src/lib/server/rate-limit-store.ts`）——C 路给的位置，我没 `git ls-files` 就抄了。真位置在 `src/lib/auth/`，已在 P0 更正。
- **压测脚本用完即删**，导致 A 路查无出处、把 372 KB 判为"无出处数字"。已把脚本落盘成附件，数字可复跑。
- **基线版本号混用**：把"本机安装 3.7.31"当成方案基线，而树里是 3.7.30／HEAD 3.7.28。已在页眉分开写。
- **只算了判据、没算产物去向**，于是漏掉"诚实失败路径已经把完整成品 quarantine 给用户"这条对漏洞成立性最关键的既有事实——A 路补上的。
- **没有两链分账**：单文档链与批链的收费闸不同，草案一句"批链稍好"讲得太粗，且把 A 路一条过头的结论（"诚实路径也不收费"）差点照抄——我复核 `v15-runner.js:305/333/349/359` 后推翻。
- **函数计数口径没锁**：62 / 63 / 71 三种数都出现过，取决于是否含匿名与内嵌函数。定稿统一为"具名 62（含匿名 71）"并写出正则。
