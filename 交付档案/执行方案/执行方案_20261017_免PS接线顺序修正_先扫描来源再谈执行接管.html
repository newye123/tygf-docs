甲不可行：manifest 没有能定位扫描观察件的键。严守卫有害：它会打死正常批次。⇒ 顺序必须换成 C（含来源凭记）在前、A 在后。

否决 1 · 甲方案不可行

execution-manifest.js:29-34 的键集只有 assignments / attempt_id / canonicalization_version / install_id / job_id / locale / output / protocol_version / readiness / runtime / schema_version / source / translation，无 master_path、无 scan_id（同文件 grep 命中 0）⇒ 执行期够不着扫描观察件，psVersion 这个锚用不上。就绪扫描还按随机临时目录落盘、不按 attempt 键存。

否决 2 · 严守卫会打死合法批次

"同原文多层且译文不同就拒"我差点实现：推演后发现引擎扫＋引擎执行时层号同一套权威 id，这种形是正常需求。在无法证明扫描来源就拒＝把唯一受控的 F 段路径也堵死，还谎称安全改进。⇒ 只保留已跑绿的计数守卫（命中层数大于投喂条数才拒，数学上必然有层翻不到，不误伤）。
