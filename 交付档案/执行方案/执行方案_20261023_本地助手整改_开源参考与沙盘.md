## 0. 一句话给 Owner

外部真正能用上的参考有六条，归成四类：**按进程 SID 授权与启动自愈**、**Inno 的四个签名位加 RFC3161 时间戳**、**事务性 outbox 加墓碑**、**Host 白名单加 PNA 响应头**。最该点名拒绝的三件是：**DPAPI**、**SQLite**、**混淆**——它们要么解决的不是我们的问题，要么会把故障换一种更难诊断的样子。

本轮真正值钱的是在自己代码里回读出来的三条：

1. **空证据也能收费**。现在云回执只发一个摘要、不发对象数组（`v15-runner.js:1078-1095`），服务端拿不到可重算的输入；而空对象数组算出的 `sha256("[]")` 是 `4f53cda1…02b945`，一个合法的非空字符串，能直接过现在的收费闸（`execution-batch.ts:1388`）。被改过的客户端不需要伪造任何内容，发这个哈希加一行 VERIFIED 就能结算。
2. **没有 `--beta` 这条路**。上一版方案写“未签名只能走 `--beta`”，但仓里只有 `--allow-unsigned-beta`，而且它把 `UnsignedBeta` 写进**生产** manifest（`publish-local-assistant.cjs:17,71-75,102,106`）。删一个 flag 不够，必须先做输出隔离。
3. **“只读启动”不存在**。`readRecoverableHiddenState` 读到 `.bak` 时会主动把备份复制回当前文件（`persisted-state.js:96-100`）；验收判据必须写成“`.bak` 哈希不变”，不能写“任何文件都不变”。

关于逆向工程那件事，结论只有一句：**客户端一定会被读懂，所以护城河不在“藏”，在“即使读懂也改不了结算”**。具体到我们，就是先把 P1-A 的证据校验做实，再谈其它。

## 1. 本轮做了什么、没做什么

## 3. 参考矩阵

判定分三档：**采纳**（本轮就进方案）、**试用/缓**（有条件、或等外部周期）、**拒绝**（看着能用，实际不划算）。

### 3.1 采纳

| 参考件 | 解决什么 | 我们的落点 | 证据 |
|---|---|---|---|
| `icacls` 的 `*SID` 语法 | 授权目标不再按名字解析，直接钉进程 token 的 SID | P0-A：`icacls <file> /grant:r *<SID>:F` | B（Microsoft 文档）＋A（临时文件实测 rc=0） |
| Windows 属主隐式 `WRITE_DAC` | 即使 ACL 被锁坏，属主仍能改回 DACL，可做启动自愈 | P0-A 第 3 步：`loadConfig` 之前先对当前与 `.bak` 各跑一次授权 | B（Windows ACL 语义） |
| Inno Setup `SignTool` + `SignedUninstaller=yes` + `[Files] sign` | 一次覆盖 setup、内层 exe、托盘 exe、卸载器四件 | P0-C：`installer.iss` 加配置，构建机放证书 | B（Inno 官方文档原文） |
| Authenticode + RFC3161 时间戳 | 证书过期后已发布安装包仍然有效 | P0-C：签名命令带 `/tr` 与 `/td sha256` | B（Microsoft / CA 文档） |
| 事务性 outbox + 幂等键 + 墓碑标记 | ACK 后不再把已成功尝试重新数成未知 | P0-D：`acked/` 目录放 `${attemptId}.json` 墓碑 | B（outbox 模式）/ D（具体实现） |
| Host 头白名单 + PNA 响应头 + `Vary: Origin` | 防 DNS rebinding；适配新版 Chrome 对本地网络的预检 | P1-B：`cors()` 补三项，另加 Host 校验 | B（Chrome / OWASP） |

## 4. 执行方案（按依赖排序）

顺序不能换：**P0.5 身份 → P0-A ACL → P0-B 状态机 → P0-C 发布闸 → P0-D 回执 → P1-A 证据 → P1-B 本地 HTTP → P2 取舍**。P0-A 与 P0-B 必须同一次发布，否则 ACL 修好了、状态机还会在别的故障下覆盖配置。

### P0.5 先核对身份（5 分钟，阻塞其余）

在客户机跑：

```powershell

Get-Content "$env:LOCALAPPDATA\Programs\图译工坊本地助手\release-identity.json"
```

期望：`assistantBuildId` 与 `public/downloads/local-assistant-release.json` 逐字一致；签名当前应为 `NotSigned`（P0-C 之前这是预期）。不一致就先把客户机升到真正的 3.7.24，再谈行为结论。

**验收**：工单里有一条 `/ping` 原始输出，`version` 与 `assistantBuildId` 对得上出厂件。

### P0-A 会话 ACL：按进程 SID 授权，启动自愈

改 `download/local-assistant/persisted-state.js`：

1. 新增 `currentUserSid()`：用绝对路径 `%SystemRoot%\System32\whoami.exe`，参数 `/user /fo csv /nh`，`timeout: 5000`，取第二个 CSV 字段并校验 `^S-1-\d+(-\d+)*$`；失败再走 PowerShell 的 `WindowsIdentity`；两者都失败返回 `null`，记 `ACL_SID_UNAVAILABLE` 并**跳过收紧**。**永远不再用 `process.env.USERNAME` 作为 ACL 目标**。
2. 重写 `restrictAclToCurrentUser`：先 `icacls <file> /grant:r *<SID>:F`，检查退出码与输出里没有 `Failed processing`；**授权成功并回读确认后**，再单独执行 `/inheritance:r`。两步分开，任何一步失败都不会把当前用户锁在外面。
3. 启动自愈：在 `loadConfig()` 之前，对 `CONFIG_FILE` 与 `.bak` 各跑一次授权（属主有 `WRITE_DAC`，读不了也能补 ACE）。
4. `setHidden` 改用绝对路径 `attrib.exe`，失败记退出码，不阻断写盘。
5. 测试：扩展 `smoke-local-assistant-state-persistence.mjs`；Windows 上临时文件跑 `icacls <file> /findsid <SID>` 必须命中；静态断言源码里不再出现 `process.env.USERNAME` 作为 ACL 目标；负控用一次性临时副本。

**验收**：`whoami /user` 的 SID 与 `icacls <session> /findsid <SID>` 命中同值；`/pair` 200；连续重启 3 次不回退。

### P0-B 状态机：五种状态，读不到绝不覆盖

改 `server.js` 与 `persisted-state.js`：

1. 新增 `readStateWithStatus()`，返回 `OK | MISSING | UNREADABLE | CORRUPT | DECRYPT_FAILED`：
   - `UNREADABLE`：文件存在但读抛 `EACCES/EPERM/EBUSY`；
   - `CORRUPT`：读到了但格式/JSON 校验失败；
   - `DECRYPT_FAILED`：格式对但 GCM 校验失败（换了机器、被改、MachineGuid 变了）。这一态上一版没有，必须单列，否则会被当成“损坏”而隔离掉一台其实只是换了硬件的机器。
2. 启动：
   - `UNREADABLE`：先跑 P0-A 自愈并重读；仍不可读 → 打印 `CONFIG_UNREADABLE`（路径、SID、建议），**退出，不调 `ensureMachineId` / `saveConfig`**。
   - `CORRUPT`：当前与 `.bak` 一起改名成 `.corrupt-<时间戳>` 留证，按首次启动处理，记 `CONFIG_QUARANTINED`。
   - `DECRYPT_FAILED`：不动文件，打印 `CONFIG_DECRYPT_FAILED`（提示“是否换过电脑/系统重装”），退出。
   - `MISSING`：按首次启动处理。
3. `start()` 目前是裸调 `ensureMachineId(loadConfig())`（`server.js:8171`），没有 `try/catch`。补上：任何写盘失败都打印明确码并**退出**，不要以未捕获异常崩掉，否则托盘里只会看到“连不上”。
4. `writeHiddenStateFile` 的轮转改成“新备份先立、旧备份后破”：
   - 写 temp + fsync + 回读校验（保留）；
   - 当前可读且有效：复制到 `${backup}.new` → fsync → 原子改名为 `.bak`；
   - 当前存在但不可读：**中止**，记 `STATE_CURRENT_UNREADABLE`；
   - 当前存在但无效：复制到 `${file}.corrupt-<时间戳>`，**`.bak` 不动**；
   - 最后才 `rename(temp, file)`；失败只删 temp。
   - 删掉现在 `removeFile(backupPath)` 再 `renameSync(filePath, backupPath)` 的“先删后换”（`persisted-state.js:68-70`）。
5. 测试：当前有效 → 写新值 → `.bak` 等于上一版；当前损坏 → 写新值 → `.bak` 仍是上一份有效版本，且出现 `.corrupt-*`；把当前做成目录（模拟读失败）→ 写盘必须失败且 `.bak` 哈希不变。

**验收**（按 C-07 改写）：模拟不可读后，`.bak` 的 sha256 与操作前逐字相同；当前文件只允许被 `.bak` 的内容替换；恢复 ACL 后能读回原配置；日志出现 `CONFIG_UNREADABLE` 而不是“请重新授权”。

### P1-A 证据摘要：把对象发上去，服务端重算

这是本轮最该先做的一条，因为它直接决定“被改的客户端能不能白拿钱”。

1. `v15-runner.js` 的 `buildCloudReceiptPayload` 增加 `objects` 字段，逐对象发 `{objectId, layerId, actualTextDigest}`（就是现在被哈希的那三项，见 `:1078-1085`）。体积按对象数线性增长，先按 500 对象压测一次。
2. 服务端 `execution-batch.ts` 重算：用同一套规范化（`canonicalizeJson`）对收到的 `objects` 算摘要，与 `objectEvidenceDigest` 比对。
3. 新增拒绝条件：
   - `objects` 为空或缺失，但存在 `VERIFIED` 行 → 422 `EVIDENCE_OBJECTS_MISSING`；
   - 摘要等于 `sha256("[]")`（`4f53cda1…02b945`）→ 同上拒绝；
   - `objectId` 重复 → 422 `EVIDENCE_OBJECT_DUPLICATE`；
   - `actualTextDigest` 不是 64 位 hex → 422；
   - 摘要不符 → 422 `EVIDENCE_DIGEST_MISMATCH`；
   - `VERIFIED` 行对应的对象不在 `objects` 里 → 该行降级为不可计费。
4. 收费闸保留 `REOPEN_VERIFIED` 这个前提，但不再只认“非空字符串”。

**验收**（含负控）：原样回执 → 正常结算；改一个字符 → 422；删一个对象 → 422；把摘要换成 `sha256("[]")` 并保留一行 VERIFIED → 422；空 `objects` → 422。四条负控全部不产生结算记录。

### P1-B 本地 HTTP：Host 白名单 + PNA + Vary

1. `cors()`（`server.js:2622-2628`）补 `Vary: Origin`；`OPTIONS` 预检在请求头带 `Access-Control-Request-Private-Network: true` 时回 `Access-Control-Allow-Private-Network: true`。
2. 新增 Host 校验：只接受 `127.0.0.1:49152`、`localhost:49152`、`[::1]:49152`；其余返回 421。Origin 校验保留。
3. 打包版移除 `http://localhost:3000` 的默认回退：`DEFAULT_CONFIG.serverUrl` 在 `process.pkg` 下用生产地址；`getAllowedOrigin` 对未匹配来源不再回 `localhost:3000`。
4. `isLocalDevServer` 在打包版恒为 false（除非显式开发开关）。

**验收**：打包版默认配置下，`Origin: http://localhost:3000` 的 `/pair` 返回 403，响应里没有 `Access-Control-Allow-Origin: http://localhost:3000`；`Host: evil.example` 返回 421；正常 Origin 的预检带 PNA 与 `Vary`。

### P2 逆向相关的取舍（不写“防破解”）

1. 不做 bytecode、加壳、反调试（理由见 §5）。
2. 保留中文错误文案（用户与支持需要）；只移除泄漏构建布局的路径字面量。
3. 威胁模型改写：从“防破解”改成“**本机管理员可读可换程序；我们只保证结算不被伪造、分发可验真**”。
4. `--self-test-assets` 只证明包里没有明文 JSX，不证明 `server.js` 不可读；文档里不要把它写成“防逆向”。

## 5. 逆向工程趋势：事实与对我们的含义

### 5.1 事实（2026-10-23 取数）

### 5.2 机理

- **静态重编译**把目标机的机器码翻成 C/LLVM IR，再按原语义重新编译；符号与结构一旦恢复，逻辑就是可读源码。
- **matching decompilation** 追求“编译回去逐字节一致”，等于用编译器当验证器，把“猜”变成“可证”。
- **AI 辅助**（Ghidra/REA 一类）把“读二进制”的单位成本打下来。它没有改变可能性，只改变了成本曲线。

### 5.3 对我们的三条结论

1. **护城河不在客户端**。`pkg` 打出来的 snapshot 有公开提取工具；资产移除合同只保证包里没有明文 JSX（`server.js` 的 `--self-test-assets` 分支），不保证 `server.js` 不可读。把预算花在混淆上，回报接近零。
2. **判定权必须在服务端**。P1-A 不是“安全加分项”，是“被改的客户端能不能白拿钱”的开关。先做它，再谈其它。
3. **分发完整性靠签名，内容可信靠重算**。签名回答“这个包是谁发的”（P0-C）；服务端重算回答“这个回执说的完成是不是真的”（P1-A）。两件缺一不可，也不能互相替代。

### 5.4 一条反向收益

逆向成本下降对我们同样有效：PS 自动化、字体回退、排版写回这些领域，公开实现变多，可以**读行为、做对标**。但许可不明或 AGPL 的代码不要复制进产品；用“输入输出对照”验证，不用“抄代码”。

## 7. 不做清单

- **不换加密方案**：现有 AES-256-GCM + MachineGuid 不是这次故障的原因；DPAPI 会新增更难诊断的故障。
- **不上 SQLite**：打包目标 `node18-win-x64` 没有可用模块，单文件状态也用不上。
- **不引入 `write-file-atomic`**：能力比现有写入器弱。
- **不做混淆 / 加壳 / 反调试**：见 §5。
- **不自动删、不自动重投那 24 条回执**：先分类，再决定。
- **不在证书到位前发“正式版”**：未签名只能进 beta 通道。
- **不拆客户过渡件**：等 ACL 修复在**那台机器**上连续重启验证通过，再一次性拆除并留回滚。
- **不为了“看起来安全”给浏览器发客户端证书**：不可行，且会破坏现有配对链路。
