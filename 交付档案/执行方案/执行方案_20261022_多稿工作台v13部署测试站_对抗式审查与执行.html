02对抗式审查：审出九条（前四条是真缺陷，已修）

2.1 代码侧 4 条真缺陷 —— 已修并提交 7359794

A1状态标签有两处（最要紧）

v13 把状态徽标抽到共享件后，workbench-view.tsx 里那张 DRAFT_STATE_LABEL 变成没人引用的死表——「同一件事两处文案」正是本项目反复点名的两套真相苗头（v12 F11 同族病）。

处置：删掉死表（九个状态的文案与 className 与旧 StateBadge 逐字比对一致），并在新门里钉死「旧表不许复活」（查代码不查注释，否则解释性注释会被误判）。

A2收起开关读的是闭包里的旧值

setExpandedOverride 的函数式更新里又去读外层 expandedOverride——单次点击结果正确，但读的是可能已过期的值。

处置：改成明确的函数式更新。

A3稿表面板少一行间距

原来内联 <ul className="mt-3">，抽成组件后那行间距没了。

处置：组件根节点补回 mt-3。

A4我自己写的门有一条过宽断言

断言「workbench-view 不许出现 state === 'prepared'」，但单稿档的 fileDotClass 颜色判断（既有语义、与计数无关）本来就要用它。

处置：收窄成「只查多稿计数那条路」。门是错的，不是代码错——不修就会变成天天被人绕过的假门。

2.2 部署链侧 5 条 —— 全部靠实测挡下

A5出包树必须干净

worktrees/develop 里有另一会话 22 项在飞改动。从那棵树出包＝把别人的半成品打进发布件。

处置：新建干净 detached 树 worktrees/release-7359794（HEAD 逐位等于 7359794、0 项 dirty、只有 .env.example 没有 .env），node_modules 用 junction 指向 develop（沿用 v12 出包树同一做法）。

A6main 落后 31 笔

出包前置闸写的是「rev-list --count HEAD..develop 非 0 即停并先对齐」。实测 main..develop=31、develop..main=0（严格祖先，对齐＝快进）。

处置：本次从 develop tip 出包（artifact 就是 develop tip，不存在「从落后的树打包」），不动 main（沿用 v12 部署先例），生产树原样不动。

A7整包 67MB 上传会被掐

交接文档记载本机→服务器约 26KB/s，两次都停在 14.1MB 被超时掐。

处置：分片 split -b 6m → 每片后台 scp → 服务器 cat 合并 → sha256 逐字比对后才部署。

A8本机三条环境补丁缺一不可
  • file 替身必须在 ASCII 路径 C:/tools/geo-retest/bin 且在 PATH 上（PortableGit 缺 file → astextplain 报 command not found → git log -G 退 128 → hygiene 门 fail-closed）
  • node 管道 spawnSync 一律 EBUSY → 必须 --require 管道→文件描述符 shim（已复制到 ASCII 路径）
  • CODEBUDDY_SAFE_DELETE_BULK_THRESHOLD 默认 50 会让 test:contracts 第 9 段起删不掉 → 放宽到 400
A9本机 bash 坏了

C:\WINDOWS\system32\bash.exe 是 WSL 的，WSL 虚拟磁盘 VHDX 找不到（ERROR_FILE_NOT_FOUND），编排脚本跑不了。

处置：改用 Git Bash（实测可用，cygpath 也在，to_win 转换正常）。

03顺带核过、确认没问题的（不折腾）

确认没问题

  • 零 prisma/schema 变更 ⇒ 部署走「跳过库变更」分支，不碰数据库。
  • 服务器磁盘：40G 用了 33G，剩 4.9G（88%）；备份目录 834M/17 条，部署脚本按 BACKUP_RETENTION_COUNT=10 裁剪 ⇒ 上传前先清旧包，够用。
  • 无在飞批次：近 1 小时只有 db 目录有改动；部署脚本那道「拦近 30 分钟在飞批次」的闸不会触发。
  • 助手包不重出：v13 是纯网页侧改动，助手侧零改动 ⇒ 不 bump 版本、不出 r5。

风险

  • 服务器磁盘只剩 4.9G：出包与构建都在服务器侧；上传前清旧包，部署后看 df。
  • 上传带宽 ~26KB/s：67MB 理论 40+ 分钟 ⇒ 分片后台 scp，不走前台。
  • 仍无浏览器实测：v13 的界面证据是真组件树渲染测试 ＋ 静态合同 ＋ 构建产物字符串，不是肉眼。
  • 开发树上另有会话在并行提交：本轮全程只用固定 sha 出包，别人的提交不影响这个包。
