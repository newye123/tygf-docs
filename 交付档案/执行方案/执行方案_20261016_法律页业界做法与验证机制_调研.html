结论

业界的答案不是「写得更漂亮」，而是「单一来源 + 负向断言 + 同笔同步」。我们这次照这个改。

01调研到的两个直接可用的先例

有测试的法律页Qintsg/SSPU-AllinOne · commit 4b62dea

github.com/Qintsg/SSPU-AllinOne

一个 Flutter 项目，把免责声明、用户协议、隐私协议、开源许可、第三方协议整合成一份统一法律说明，并让首启弹窗和 Windows 安装器共享同一份确认事实。提交说明里两条直接有用的东西：

Rejected：继续维护分离的使用协议/隐私协议入口
  —— 会让一次确认、重新同意策略和安装器许可文本长期分叉。

Directive：修改法律文本、第三方清单或安装器许可页时
  必须同步 assets/legal、协议确认键、关于页入口、文档与测试。

Tested：flutter test test/privacy_policy_page_test.dart;
         flutter test test/windows_installer_legal_test.dart

我读了 test/windows_installer_legal_test.dart 全文，断言长这样：

test('Windows x64 和 arm64 安装器引用同一份合并协议文件', () {
  const expected = r'LicenseFile={#WorkspaceDir}\assets\legal\legal_zh.txt';
  for (final script in _installerScripts) {
    expect(File(script).readAsStringSync(), contains(expected));
  }                       // ↑ 每个消费方都指向单一来源
  expect(File('assets/legal/legal_zh.txt').existsSync(), isTrue);
});

三个要点：① 法律文本只有一个文件，安装器和页面都引用它，不各存一份；② 断言的是「每个消费方都指向同一处」，而不是「内容看起来对」——这样任何一处想偷偷改文案，测试就红；③ 有负向断言（isNot(contains(...))），把「不该出现的东西」钉死。

开源内容 studiopayloadcms/payload

github.com/payloadcms/payload

Next.js 原生、全 TypeScript 的开源全栈框架，自带管理后台。它的 Versions 机制：

  • 每份文档自动生成独立版本集合 <slug>_versions，保留完整副本 + 修改时间 + 修改者（审计日志）
  • drafts 模式：可以存比已发布版本更新的草稿，配合 Access Control 控制谁能看草稿
  • autosave：边改边存草稿，不影响已发布版本
  • restoreVersion / findVersionByID：按版本回滚、按 ID 取历史版本
  • maxPerDoc：每份文档最多保留多少个版本

对照我们自己的 Content Studio：我们有 draft → diff → publish → revisions → rollback，形状是对的；缺的是按版本的审计日志（谁改的）、以及「谁能读草稿」的访问控制（我们现在是用环境锁一刀切挡在生产外）。

02对照后，我们的问题是什么

调研让我看清了 #130 的真正病根，也看清了法律页这一摊的问题：

我们的法律文本是三处并存、各自独立的：母本在 docs/（内部文件）、页面在 src/app/(zh)/{privacy,terms}/page.tsx（线上渲染面）、中文文案还在 src/config/siteContent.ts（代码单源，另有一层）。三处之间没有任何机制保证一致。

#130 就是这么来的：代码单源改对了，但生产库读的是 2026-09-17 冻结的旧覆盖，两边各说各话，而且没有任何一道门会红。

业界的做法是把「一致」这件事从纪律变成断言：法律文本单一来源，每个消费方引用它，测试断言每个消费方都指向那一处，再加负向断言钉住不该出现的字样。

三条刻意的边界
  1. 「待取证」「未核实」不再作为发布态占位。取证不到的事，要么写成事实（「该服务方公开政策未给出固定天数」），要么如实标注属谁的信息（「本服务运营主体未在本页公示」），不留待办占位。
  2. 不代第三方承诺。第三方保留期与注册主体以其公开政策与合同为准，我方不代其承诺——这句写进了表注。
  3. DNS 落某云网段只算观测，不算存储地结论。api.deepseek.com 解析落 AWS、paddleocr.aistudio-app.com 落百度网段，这两条只记观测、不写进结论列。
