## 一、对抗式审查先把我的方案砍了一刀（这是本轮最有用的产出）

上一轮我把下一步定为 PC-A4「执行期同源闸」。这一轮我先量了三件事，量完就知道那个顺序是错的：

1. 就绪扫描 `runReadinessScan`（`server.js:5267-5366`）**只会起 PS**：它写 `readiness-input.json`（`:5278`）、发 `TYGF_V15_Readiness_Scanner.jsx`、读回 `readiness-observation.json`（现役支 `:5307-5340`，读盘点 `:5339`）。
2. 就绪快照是执行清单的**前置**（`execution-manifest.js:195` 要核 `READINESS_FINGERPRINT_MISMATCH`）。
3. ⇒ 一台没有 PS 的机器现在**连清单都建不出来**，"引擎扫的层号交给 PS 执行"这条路径今天走不到。给一个不可达的分支加同源闸＝自欺，还会把恢复锁语义再抄一遍。

正确的下一片因此是 **A5＝就绪扫描引擎道**；A4 的闸做完之后才有对象可判。执行序改为 **A5 → A4**。

顺带查到一条**帮我们省事的**事实：就绪扫描器按 PSD 内部层 id 认层（jsx `:17-25` 的 `putIdentifier('Lyr ', id)`），而内置引擎报的也是同一套 id ⇒ 引擎道不需要新契约、不需要改 manifest 一个键。

## 二、做了什么（四件，全在隔离树）

1. `pc-scanner.js` 新增 `readEngineLayerIndex()`：只读会话 `doc.open` → `doc.inspect` → `doc.close`，把层树压成 `id → {isText, kind, text}`；**不编辑、不保存**。
2. `pc-scanner.js` 新增纯函数 `buildReadinessObservations()`：把"id 索引"映射成就绪契约要的 `observations[]`，三态逐条对齐 PS 侧（缺失 / 存在但非文本 / 文本读回）。抽成纯函数的理由和上一轮同一条：内联在 `server.js` 里就单测不到，而这三态直接决定用户看到哪个阻断码。
3. `server.js` `runReadinessScan` 头部按同一把尺判通道（`:5274` 复用 `decideScanChannel`；`:5272` 旗标关时**不起引擎探针**），引擎分支 `:5287` 起，现役 PS 分支（含 `:5315`/`:5331` 两处 `markBusyRecoveryRequired`）**一字未动**。引擎道还额外跳过拉 JSX 脚本那步（`:5279`，无 PS 机器可能没网/没云端）。
4. 新守卫 `scripts/smoke-pc-readiness.mjs`（7 段）挂进 `package.json` 与 `test:trust-chain`。

**A3 那条规矩扩到就绪道**：就绪原本两处恢复锁的语义都是"PS 执行器退出状态未确认"。引擎只读不改盘 ⇒ 引擎失败只落定错误码＋本机日志＋抛错，**绝不进那把锁**（否则就是给没有 PS 的机器造一个需要人工救援的死锁）。

**`pc-channel.js` 一处判据精度自纠**：原来把"没有凭记"和"凭记是 PS 扫的"合成同一个码。两者处置不同——前者＝缓存被清或从未扫过，后者＝用户换过通道、层号身份不可信。已拆成 `PC_SCAN_PROVENANCE_MISSING` / `PC_SCAN_PROVENANCE_PS_SOURCE`。

## 三、我差点写错的两个"不等价形状"（请复验的人重点看这两条）

- **组层被我跳过了**：第一版只收非组节点 ⇒ 就绪会报 `OBJECT_MISSING`，而 PS 侧对组层报的是"存在但非文本"（`OBJECT_NOT_TEXT`）。两个阻断码给用户的指引不一样。已修正并写进 [A]/[F] 断言。
- **空正文写成 `null`**：PS 侧读回是 `String(textItem.contents)`＝**空串**；写 `null` 会让下游把"读回为空"走成缺失形。已修正，负控 N3 专咬这一条。
- 另外一处**判据自身的坑**（今天第二次踩）：我用文本断言"引擎分支里不许出现 `markBusyRecoveryRequired`"，而我自己的注释里就写着这句话 ⇒ 判据自命中。已改为**只读代码行、过滤注释行**。
