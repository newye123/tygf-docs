- 审查时刻（本会话 `date`）：2026-10-22 10:09:52 +0800
- 结论：**打回现有排版模型**。不是“字重坏了”，而是现有模型在结构上只允许“每种语言一套排版”，全稿只能落成一个脸；字号格被锁死，所以“按字号选字重”不是没做好，是根本表达不了。字距/行距另有 4 条“设了也不会发/不会用/不告诉你”的断点。

## 0. 先给 Owner 的三句话

1. **现在的“改字体”是每语言一份设置，执行时套到这一语言的每一个文字层。** 72pt 的大标题和 14pt 的正文拿到的是一模一样的脸和粗细，所以看起来“全稿只有一个粗细”。要按字号分开，必须把数据模型从“一份”改成“按字号阈值的一组档位”。
2. **字距/行距/视觉控件里，有真做不到的，也有做了但没接线的。** 百分比行距、自动字距、伪粗/伪斜在执行器和助手里已经能写，但浏览器根本没发；固定行距能发，但没点“保存到本机”就静默不参与执行；字体没装上时 Photoshop 会静默换脸，而执行结果里的失败清单没有任何界面消费。三件事叠在一起，用户看到的就是“功能全是坏的”。
3. **方案不改字号本身。** 原稿字号只作为“选哪一档”的依据；改字号会让译文重新折行，和现有行数判据、溢出预估耦合，本版不做。做到的是：≥48pt 用 Bold、≥20pt 用 Medium、其余 Regular，每档独立字距/行距/自动字距/伪粗斜，执行后逐层读回并把失败说清。

## 2. 现象 → 根因

### 2.1 “改字体只能全部改成一个粗细”

**已证实，等级 A。**

- 浏览器只按语言取一份 profile：`src/lib/workbench/typography-persistence.ts:232-240`（`loadTypographyProfileForLanguage` 返回单个对象）。
- 单语言派发取一份：`src/lib/workbench/local-assistant-client.ts:1500`、`:1525`；批量派发同样只取一份：`:2005`、`:2030`。
- 执行器把这一份套到每个 assignment 的 `textItem`：`download/local-assistant/scripts/TYGF_V15_Thin_Executor.jsx:221`。
- 字号格在界面上是死的：`src/components/workbench/typography-panel.tsx:456-457` 直接渲染 `—`；能力表标成“未实测”：`src/lib/workbench/typography-capabilities.ts:81-85`；助手白名单把 `fontSize/size` 列为锁死键：`download/local-assistant/typography-profile.js:25-29`。

**失效场景**：同一篇稿里 72pt 标题、24pt 小标题、14pt 正文。用户选一次“思源黑体 Bold”，三层全变 Bold；选 Regular，三层全变 Regular。没有第二个维度可以表达“大字号重、小字号常规”。

### 2.2 “字距、行距设了没用”

这不是一条缺陷，是四条独立断点。四条都已在代码里证实：

1. **没点“保存到本机”＝执行时完全不读。** 面板的 `save()` 在 `typography-panel.tsx:331-344`；派发只从 localStorage 读（`typography-persistence.ts:232-240`），没有任何“未保存草稿”的提示或拦截。入口上只有一个脏点（`workbench-view.tsx:3238`、`:3593`）。用户改完直接点执行，看到的值全在，发出去的是旧值或空值。
2. **百分比行距在界面上不可达。** `typography-panel.tsx:461-470`：下拉框只有“沿用/固定pt”，`percent` 选项只在当前已经是 `percent` 时才渲染（`:469`）——没有任何路径能第一次切到它。即使存储里有 percent，映射函数也只发 fixed：`typography-persistence.ts:158-165`。而助手校验器和执行器其实都支持 percent（`typography-profile.js:5`、`TYGF_V15_Thin_Executor.jsx:92-94`）。
3. **排版失败没有任何界面消费者。** 执行器确实产出了 `typographyRequested` / `typographyIssues`（`TYGF_V15_Thin_Executor.jsx:258-259`），但全仓检索只有三处：执行器自身、`server.js:1428` 的一行注释、`scripts/smoke-typography-wiring.mjs:144` 的字符串断言。`v15-runner.js` 只在 `:214` 把 profile 写进信封，从不读回执行器的排版结果；结果既不进本地回执，也不进 `attempt` 状态，前端自然看不到。字体没装、行距没吃进，用户看到的仍是“成功”。
4. **字体清单读不到时，连手填脸名也被关掉。** 手输框只在 `faces.length > 0` 时渲染（`typography-panel.tsx:754`），而且输入的名字只要不在清单里就立刻把 `face` 清空（`:764-773`）。设计注释说“清单读不到时用户仍可手填脸名写回”，实际代码把这条退路关了。

### 2.3 “视觉等等这些无法使用”

要分两类说，不能混：

- **已经实现、只是没接线**：`autoKerning`（度量标准/光学）、`fauxBold`、`fauxItalic`。助手白名单收了（`typography-profile.js:24`），执行器实现了（`TYGF_V15_Thin_Executor.jsx:73-85`、`:122-131`），但浏览器的 profile 形状里没有这三个键（`typography-persistence.ts:52-57`、`:149-167`），面板上的 8 个开关也全是禁用态（`typography-capabilities.ts:162-211`）。这三项本轮直接接通。
- **本版 PS 确实写不进 / 不该写**：水平/垂直缩放、基线偏移、消除锯齿、语言、大小写、下划线/删除线。能力表里已按“本版写不进/未实测”标了（见第 4 节）。本轮不碰，也不用“未实测”含糊过去。

### 2.4 预览本身会把“字重分档”做废

`previewStyle`（`typography-panel.tsx:72-87`）只把 `bold` 映射成 700、`italic` 映射成斜体；Light、Thin、Medium、SemiBold、Black 全部按 400 渲染。固定行距直接用 `leadingPt` 像素值套在 14px 的样例上。

**后果**：即使后台真的按档位写了 Medium 和 Regular，面板预览看起来也完全一样，Owner 仍会得出“还是只有一个粗细”的结论。所以预览保真不是美化，是验收项。

## 5. 目标与验收（可判定）

**一句话目标**：在同一种语言的一次执行里，排版偏好必须能按原稿字号分档，逐档决定字体脸、字距、行距、自动字距、伪粗/伪斜；执行后能逐层读回，并把失败在界面上说清。

**验收判据（实现完成后逐条打勾，缺一不算完成）**

1. 三字号夹具（72/36/14pt）一次执行后，三层分别得到三档设定的脸/字距/行距；本地回执里有逐层 `sizePt / tierId / face / tracking / leading` 的实际值与读回值。
2. 故意给某一档一个本机不存在的脸名：文本替换仍成功；结果面明确显示“第 N 层字体被替换为 MyriadPro-Regular（FONT_FALLBACK_APPLIED）”，不再静默。
3. 老版本（v1/v2）保存的单一 profile 升级后仍原样应用（迁移为“默认档”），不清空、不改变行为。
4. 百分比行距 120%：24pt 层读回 `autoLeadingAmount=120`；固定行距 18pt：读回 `leading=18` 且 `useAutoLeading=false`。
5. 字距 -50‰ 与 +200‰ 读回精确相等；自动字距 METRICS/OPTICAL 读回成功；伪粗/伪斜读回 true。
6. 字体清单为空时，手输合法 PostScript 脸名仍能发送；执行后读回失败必须报告，不得清空输入或假装成功。
7. 未保存改动不再被静默忽略：要么自动保存并读回，要么执行前明确拦下并给“保存并执行/不保存继续”。
8. 预览里 Light/Medium/Bold 必须肉眼可分；浏览器没有该字体时，明说“预览不可用”，不许拿 400 冒充。
9. 现有 5 组排版测试继续全绿；新增测试覆盖档位校验、匹配、迁移、映射、结算一致性、失败归因。
10. 测试站真机跑完整批；生产部署前由 Owner 明确点头。

## 6. 方案：按字号阈值分档

### 6.1 数据模型

不按“字号区间”做，而按“**阈值从高到低**”做：每条规则写“≥ X pt 用这套”，最后永远有一个“默认档”兜底。这样不会出现区间空档，也不会因为两个区间边界写反而漏层。

```ts
// 浏览器本地存储 v3（键仍是 tygf:v15:typography，读得动 v1/v2）
interface TypographyRule {
  id: string                 // 'r1'…，稳定
  label: string              // '大标题' / '正文'，用户可改
  minPt: number              // ≥ 1，≤ 2000；规则按 minPt 降序
  profile: TypographyProfile // 复用现有字段 + autoKerning/fauxBold/fauxItalic
}
interface TypographyTiersByLanguage {
  version: 3
  rulesByLanguage: Record<string, TypographyRule[]>
  fallbackByLanguage: Record<string, TypographyProfile | null>
}
```

**迁移**：读到 v1/v2 的单一 profile 时，`rules=[]`、`fallback=那份 profile`。语义与今天完全一致（所有字号都用它），用户不会“升级完发现设置没了”。

**下发体（助手侧）**：

```json
{
  "typographyTiers": {
    "version": 1,
    "rules": [
      { "id": "r1", "label": "大标题", "minPt": 48,
        "profile": { "face": "NotoSansSC-Bold", "tracking": -20,
                     "leading": { "mode": "percent", "value": 110 },
                     "autoKerning": "METRICS" } },
      { "id": "r2", "label": "小标题", "minPt": 20,
        "profile": { "face": "NotoSansSC-Medium", "tracking": 0,
                     "leading": { "mode": "fixed", "value": 24 } } }
    ],
    "fallback": { "face": "NotoSansSC-Regular", "tracking": 0,
                  "leading": { "mode": "follow" } }
  }
}
```

约束（助手校验器强制执行，浏览器同口径）：

- `rules` 最多 8 条；`minPt` 唯一、降序；`1 ≤ minPt ≤ 2000`。
- 每条 `profile` 只允许 `face / tracking / leading / autoKerning / fauxBold / fauxItalic`；`autoKerning` 只收 `follow/METRICS/OPTICAL`；`leading` 三态；其余键一律拒绝（沿用现有“未知键拒绝”原则，`typography-profile.js:51-53`）。
- `fallback` 可以为空（未命中的字号不改排版），但面板必须显式显示“未命中不改”，不能默认成“随便挑一档”。

### 6.2 匹配语义

执行器在写完每层文字后，读该层当前字号，按 `minPt` 从高到低找第一条 `sizePt >= minPt`，命中就用它的 profile；都不命中用 `fallback`；`fallback` 为空则该层零写入。字号读不出（NaN/null）时用 `fallback` 并记 `SIZE_UNREADABLE`，不猜。

**关键决定**：不改字号。原稿字号只做选择器，所以不会因为本功能引起重新折行。

### 6.3 链路（兄弟字段，不进执行清单）

```
Web 面板（按语言 + 按档位编辑）
  → prepare / batch 请求体加 typographyTiers
  → 助手校验器（typography-profile.js）
  → execution-envelope.json 的兄弟字段 typographyTiers（不进 manifest、不改 digest）
  → ExtendScript 执行器按层字号选档，写脸/字距/行距/自动字距/伪粗斜
  → executor-result.json 产逐层读回证据
  → v15-runner 把排版证据挂到本地回执的兄弟字段（同 layoutGeometry 先例）
  → attempt 状态只带摘要（避免 5 秒轮询传大数组）
  → 执行完成界面显示“应用了几层 / 哪几层失败”
```

为什么不塞进 `execution-manifest`：清单键集是精确校验的，digest 只算清单（`server.js:1430-1434` 注释已写明这条边界）；进清单等于改四层合同、报价口径和已有冻结证据。排版是偏好，走兄弟字段即可。

### 6.4 逐层证据（解决“失败看不见”）

执行器结果增加：

```json
{
  "typographyRequested": true,
  "typographyMode": "tiers",
  "typographyLayers": [
    { "objectId": "obj_…", "layerId": 123, "sizePt": 72,
      "tierId": "r1", "ok": true,
      "fields": {
        "face":     { "wanted": "NotoSansSC-Bold", "got": "NotoSansSC-Bold", "ok": true },
        "tracking": { "wanted": -20, "got": -20, "ok": true },
        "leading":  { "wanted": 110, "got": 110, "ok": true }
      } }
  ],
  "typographyIssues": [
    { "field": "face", "code": "FONT_FALLBACK_APPLIED",
      "wanted": "NotoSansSC-Bold", "actual": "MyriadPro-Regular",
      "count": 2, "layers": ["obj_…", "obj_…"] }
  ],
  "typographyTruncated": false
}
```

- 逐层记录上限 500 层；超出只置 `typographyTruncated:true`，问题计数不丢。
- `typographyIssues` 保留聚合计数，但补 `layers` 样例（最多 20 个 objectId），这样既能看总量，也能定位到层。
- 本地回执挂 `receipts.typography`；云端回执不动（云端载荷由白名单字段构建，`v15-runner.js:1059` 起）。`test:trust-chain` 作为回归闸。

### 6.5 视觉控件的接线

- `autoKerning`：面板从“度量标准/光学/沿用”三选一，映射到 `METRICS/OPTICAL/follow`。执行器已有读回逻辑（`TYGF_V15_Thin_Executor.jsx:73-85`）。
- `fauxBold` / `fauxItalic`：两个开关，只在用户显式打开时发送 `true`；不发送 `false`（避免把原稿本来有的伪粗斜关掉）。
- 百分比行距：下拉框永远提供“沿用 / 固定pt / 百分比”三项；百分比走 `autoLeadingAmount`，固定走 `useAutoLeading=false + leading`（执行器已有）。
- `SEND_PROBE` 加入这三个键后，`SENDABLE_KEYS` 会自动变 6 个，能力表和结算条跟着变——这是现有单源设计的正确用法（`typography-capabilities.ts:40-54`）。

### 6.6 预览保真

把脸名里的样式词映射到 CSS 字重（Thin 100 / ExtraLight 200 / Light 300 / Regular 400 / Medium 500 / SemiBold 600 / Bold 700 / ExtraBold 800 / Black 900），斜体单独映射；预览按该档的代表字号渲染，固定行距按“预览基准字号”折算并在旁边标“预览按 Npt 折算”。

浏览器没有这款字体时，不静默退回 sans-serif 假装正常：显示“本机浏览器没有这款字体，预览不可用；以执行回执为准”。这条比“看起来像”更重要。

### 6.7 保存与执行的一致性

推荐做法：**输入即保存（防抖 400ms）**，保存后读回比对（现有 `saveTypographyProfiles` 已经做读回），状态显示“已保存 hh:mm:ss”或“保存失败：原因”。保留“立即保存”按钮作为手动确认。

如果 Owner 不喜欢自动保存，退路是执行前闸：`execute-step` 拿到 `typographyDirty` 后弹“保存并执行 / 不保存继续 / 取消”。两条都行，但**不能维持今天的静默忽略**。

### 6.8 面板结构（360px 抽屉内）

- 顶部：语言页签（现有）。
- 第二行：档位页签：`默认（其余字号）` + `大标题 ≥48` + `小标题 ≥20` + `+ 新增档`。
- 当前档的编辑区：沿用现有 12 格字符面板（字族/样式/行距/字距），新增自动字距、伪粗、伪斜；字号格仍然显示“原稿字号”但不让改。
- “本稿字号分布”：从 `psdSelection.summary.typographyLayers` 统计（72pt ×2、36pt ×4、14pt ×38），每个字号后面标“会落到哪一档”；点一个字号可直接建档。
- 结算条：全局“会发 N 项 / 覆盖 M 层”；每档“命中 K 层”；这一档 0 命中时给黄色提醒；未命中且有兜底时显示“其余 N 层用默认档”。
- 预览：按当前档渲染，字重真实映射。
- 手输脸名：始终可用（即使清单为空），只做形状校验；旁边写明“无法核对是否安装，执行时会读回”。
