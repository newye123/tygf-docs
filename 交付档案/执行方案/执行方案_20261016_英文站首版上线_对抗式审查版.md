## 一、你的问题，一句话回答

不是把中文改成英文就行。英文站是一个独立语言版本，需要独立的网址段（/en）、独立的网页语言标记（lang="en"）、独立的标题描述与社交分享卡、中英文互指的 hreflang、sitemap 里把两语并列、给 AI 搜索用的 llms.txt 英文段、站内中英文切换按钮、英文 404 页面，还需要一个正式的英文名。现有英文站“只有文字”，缺的正是这些骨架。

红线很明确：不改任何中文用户可见文案与行为；不动支付、API（src/app/api/**）、工作台；中文用户感知应该是“完全没变”。

## 二、开源项目怎么做（可参考）

- Docusaurus（seata.io 中英文站）：独立 i18n 目录存放各语言文件，navbar 有语言切换，单域名下 /en 路径。
- VitePress：locales 配置，root 为默认语言，各语言独立标题/描述/导航。
- Nextra（基于 Next.js）：[lang] 路由 + _dictionaries 翻译词典。

共同点：独立路由、独立文案源、显式语言切换，绝非“搜替换中文”。

## 三、本轮做什么（IN SCOPE，共 9 项）

1. 路由重组：现有中文页面按原 URL 不变，移入 src/app/(zh)/ 路由组；删掉根布局 app/layout.tsx，由 (zh)/layout.tsx 当中文根布局（lang="zh-CN"）；新建真实目录 src/app/en/，放英文根布局（lang="en"）、首页、download 页、404 页。关键：必须用真实目录 en/，不能用 (en)/ 路由组，否则 Next.js 会报两个平行页面撞车（`src/app/*` 与 `src/app/en/`，参考 `worktrees/develop/changes/active/20261013-english-seo-geo.md` 第 18-24 行）。
2. 英文文案单源：新建 src/config/siteContentEn.ts，英文 FAQ 6 条 + 营销文案，对照现行中文 siteContent.ts 诚实镜像，不写未经核实的新承诺；英文站不从数据库 SiteSetting 读内容（避开 #130 那种数据库漂移污染英文页）。
3. SEO/GEO 骨架：src/app/sitemap.ts 加 /en 和 /en/download，带两语互指的 alternates（zh-CN/en/x-default，x-default 指中文根）；中文页补 alternates 互指；每页只有一条 canonical；两个布局都补 openGraph.url；中文侧补 alternateLocale: ['en_US']；public/llms.txt 加 ## English 段；JSON-LD 英文侧 inLanguage: en。
4. 语言切换：中文页头部/页脚加 English 入口（指向 /en）；英文页自带中文回链。
5. 测试门扩展：scripts/smoke-seo-consistency.mjs 加英文断言（两个英文路径在 sitemap、hreflang 三语闭环、英文 JSON-LD inLanguage: en、FAQ 可见、llms.txt 英文段），并补英文 FAQ 披露断言（镜像中文 :366-367），防止 #130 类旧声明悄悄打进英文站。
6. 部署脚本补齐：deploy/deploy-release.sh 加 NEXT_PUBLIC_SITE_URL 注入（目前只有测试线有，生产靠回退值碰巧对，域名一变全链路会静默换错域名；参考对抗审查 F5）。
7. 文件路径修正：两个 smoke 脚本里的页面路径引用按 (zh)/ 调整（src/app/admin/page.tsx → src/app/(zh)/admin/page.tsx，src/app/page.tsx → src/app/(zh)/page.tsx）。
8. 不动清单：src/app/api/**、robots.ts、global-error.tsx、globals.css、icon.png、package.json、next.config.ts、prisma/**、数据库、中文可见文案，全部不动。
9. 记录：AI_MEMORY/CHANGELOG.md 留痕。

## 四、对抗式审查：反对方会怎么质疑，怎么拆招（五路）

结构路——质疑：改路由会不会把中文旧 URL 弄坏？
拆招：(zh) 是路由组，不改 URL；新增 /en 才是真实段；中文首页 HTML 与改前一致，可用 curl 本地对比验证。

内容路——质疑：英文 FAQ 说“作者会用 email 联系你”，中文说微信，矛盾吗？
拆招：这是对抗审查抓出的 F6（siteContentEn.ts:96 与中文 FAQ 的承诺分歧），需 Owner 拍板确认 email 是否为真实运营承诺；本轮不阻塞代码修改。

SEO/GEO 路——质疑：og:url 和 sitemap 不做会怎样？
拆招：对抗审查 F2/F3 实测：og:url 双语皆缺，og:locale:alternate 不对称；社交分享 URL 归属不明确。补两行 metadata 一劳永逸；llms.txt 硬编码生产域名（F7），必须和 /en 页面同一次提交上生产，否则 llms.txt 先上线会指路 404。

法律合规路——质疑：本轮不建 /en/terms 和 /en/privacy，英文用户找不到条款怎么办？
拆招：这是 G3 落口子，现行 /en/terms 和 /en/privacy 返回 404（fail-closed，正确）。但英文页脚和正文里根本没有法律页链接（F4：en/layout.tsx:82-114 只有 Download + 中文站，Privacy Policy 是纯文本无锚点），英文用户确实无路可达。裁决：英文页脚加带语言标注的 /terms、/privacy 链接（注明中文），或排期英文法律页；由 Owner 拍板，不阻塞代码。

测试与回滚路——质疑：万一上线出问题怎么回退？
拆招：零数据库、零迁移，纯前端路由重组 + 新增页面；未提交时撤回本片路径改动；已提交时 git revert。风险点在构建期路由表，所以验收必须跑 tsc、lint、seo-consistency 以及本地启动后的 /en 200 检查。

## 五、上线门（按顺序）

1. 先修 F1（英文披露断言）、F2/F3（og:url + alternateLocale）、F5（deploy-release.sh 注入），重跑 smoke 全绿。
2. F4（英文法律链接）和 F6（email 承诺口径）由 Owner 拍板，不阻塞代码。
3. Owner 授权后合并进 main 上生产；部署后手动重提 Bing sitemap（4→6 个 URL）+ IndexNow。
4. gate token 轮换：测试站口令曾在诊断输出回显，建议 Owner 批准后轮换 nginx Set-Cookie 并 reload（属访问门变更，未经批不执行）。
5. /en/terms、/en/privacy、英文 OG 图片、英文 email/应用商店文案、助手协议英文化，留给第二片。
