## 一、名字这件事：不是换个说法，是分两套词表

您说"这些名字可不能是现在这个名字"——对，因为**现在这些名字是单稿工作台的资产**（动了就破坏"原样保留"那条前提），而且旧名也表达不了新东西：「准备素材」里没有"表从哪来"这一层，「重选译文表」是单稿的一稿一表语义。

⇒ **批量工作台有自己的词表，单稿工作台一个字不改。**

| 位置 | 单稿工作台（旧名，保留） | 批量改语言工作台（新名） |
|---|---|---|
| 视图名 | 单稿工作台 | **批量改语言** |
| 导轨 | 准备素材 → 智能检测 → 设计稿校对 → 确认并生成 | **设计稿与译文来源 → 译文检查 → 设计稿校对 → 生成交付** |
| 第 1 步标题 | 选择设计文件 · 只读预扫描 | **设计稿与译文来源** |
| 文件卡 | 选择要处理的 PSD 文件 | **选择设计稿** |
| 语言行 | 原文 / 选择语言 / 重选译文表 | **原文 / 选择语言 / 更换译文表** |
| 度量 | 覆盖率 | **对稿覆盖率**（说清分母＝这一稿的文字图层） |
| 状态 | — | **就绪 / 待检查 / 有 N 处要处理 / 缺语言** |
| 来源视图 | — | **译文来源**（行＝设计稿，列＝语种，格＝这一份从哪张表取） |
| 单元格标签 | — | **主表 / 合表第 N 片 / 专表 / ＋补充** |

**五条规则**（写进方案当硬约束）：

1. **用用户嘴里的词，不用内部词。** ✗ 译库·切片·绑定·覆盖率矩阵　✓ 译文表·这一稿用哪张表·对稿覆盖率（内部词只活在代码里）。
2. **旧名只归单稿台，新名只归批量台，不混用。** 界面上冒出旧名 ＝ 串台了，是 bug。
3. **每个数字都要有分母和对象。**「72 就绪」单独出现没意义 ⇒ 必须同时给「88 本批要做的交付物」。
4. **状态词要能回答"我现在该做什么"。**「缺语言」＝这一份**做不出来**，不是"再等等"；「有 N 处」是批量台唯一的文案钩子，N 必须实时变。
5. **一处一个说法。** 批量台说「译文表」，就不许别处冒「译库/表格包」。

**命名单独立一单**（它本身是产品行为、牵动多处文案），先过您审，再进代码。
