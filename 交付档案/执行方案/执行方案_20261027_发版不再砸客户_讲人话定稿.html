执行方案（讲人话版·决定我已做）｜让"发新版"不再等于"逼客户重装"

日期：2026-10-27 16:0x（初版）／16:39 修订（并入 Owner 新令） Owner 令：「继续钻到无路可钻，给我一个讲人话的执行方案，我不做选择你来做」 Owner 追加令（16:3x 实测钟点见本行）：「还有现在安装要手动退出软件，无法做到全自动，这个也一起做了吧」 ⇒ 本件不含选项，只含我已经做的决定和要做的事。 ⇒ 追加令的效果：原 D6"自动更新只立项"被推翻，见修订后的 D6 与第 3 批。

01一、钻到底发现了什么（三句话）

  1. 发布身份文件里只有一个版本号 assistantVersion，它同时兼三份工作：① 当"低于它就拒绝服务"的下限；② 下载页上给客户看的"当前版本"；③ 发布说明里的版本号。

⇒ 后果：每次为了发新版、更新下载页而改这个数字，都顺手把兼容下限抬了一格。 没有人决定要砸客户，是抬下限这个动作没有独立开关。

证据：config/release-identity.json 字段全表 = assistantVersion, assistantFile, assistantBuildId, reportSchemaVersion, reportRendererVersion, replacementScriptSha256, nodeMajor, integrationBranch, productionBranch——没有 minAssistantVersion（全仓 grep minAssistant|assistantMin → 0 命中）；一处三用见 assistant-execution-contract.ts:69、download/page.tsx:103/116/125、local-assistant/latest/route.ts:12/17/24。

  1. 3.7.25 那次加请求头，把一个错误的假设发了出去。 网页代码注释原文写着"旧助手会忽略这个头＝旧行为"（local-assistant-client.ts:406-407）——这是错的：浏览器发现助手没放行这个头，会把整个请求在预检阶段拒掉。助手自己的代码记着这笔实锤（download/local-assistant/server.js:2686、放行名单 :2690 到 3.7.28 才补上）。

⇒ 后果：3.7.15–3.7.27 的助手对现在的网页物理不通，客户看到的是"已连接但授权未确认"这种假警报，反复重新授权也没用。修法是改了助手（3.7.28），于是所有老客户必须重装。

  1. 构建号那道门方向写反了。 它是"不相等就拒"（assistant-execution-contract.ts:75-84），不是"不能更低"——所以比网页更新的助手也会被拒（内测客户从测试站装了新版回生产就被挡）。而契约本身三项（报告格式／渲染器／替换脚本指纹）两边完全一样，指纹同为 882a4a8655ed。
  1. "必须手动退出软件"不是 Windows 的脾气，是三处叠加，全都能修（10-27 16:3x Owner 追加令带出的调查）。

- 安装脚本里唯一会关程序的机制是 Inno Setup 的"关闭正在使用的程序"（download/local-assistant/build/installer.iss:33-35）。它靠系统的"重启管理器"给程序发关闭消息——而托盘程序根本没有窗口：TrayHost.cs:48 用的是裸 ApplicationContext，全文件没有 Form、没有 WM_CLOSE/WM_QUERYENDSESSION 处理（grep 0 命中）。收不到消息 ⇒ 关不掉。

- 更糟的是引擎杀了会复活：托盘每 5 秒执行一次 EnsureEngineRunning()（TrayHost.cs:55-63），只要 exiting 没置真就立刻把 图译工坊引擎.exe 重新拉起来（:120-133）。于是安装器刚把文件释放开，文件又被占住。

- 全仓没有任何"自我了断"入口给安装器调用：唯一的干净退出是托盘菜单里那条"退出本地助手"（:93 → ExitAssistant() :277-286，它才会置 exiting=true、停定时器、杀引擎）——只能人手点。这就是您看到的"要先手动退出"。

- 顺带挖出一条已经存在的老虎：ExitAssistant() 不看忙不忙，直接 process.Kill()（:146）。在跑批的时候点"退出本地助手"，会把 Photoshop 执行打断；助手自己有条实锤——打断后落下恢复锁，server.js:2380 的原文是「检测到未完成 Photoshop 执行或恢复标记；请先人工核实现场，不会自动重试」，且 :2575 写「恢复确认前不会接收新任务」。也就是说今天客户手点退出，也可能把自己的助手锁成不能用。这条我并入第 3 批一起修。

- 最后一处：静默安装不会把助手再拉起来（:101 的 skipifsilent）——将来接自动更新时，会出现"装完了但没在跑，直到下次开机"。

02二、我做的决定

编号决定为什么这么定
D1拆字段：新增 minAssistantVersion（兼容下限），assistantVersion 退回"当前发布版本"本职这是根因。不拆，以后每一版都继续砸客户
D2修物理断链：网页只在助手声明支持时才发 x-tygf-install-id；并把那句错注释改掉让 3.7.15–3.7.27 重新可用、不用重装。能力握手已有先例可抄（local-assistant-client.ts:381-385 的 typographyApplyReady）
D3抬下限要有判据 + 机器检查：只有契约三项变化、或随车带安全/防丢数据修复、或新增助手必须支持的接口，才允许抬；抬了必须在同笔写原因，否则出包红。落在已有的 check-release-identity 门上我上一版方案里"靠人自觉"的判据按本项目纪律＝无效，必须能红
D4构建号从"拒绝条件"降为"证据字段"：照常进签名执行清单（execution-manifest.ts:98/183/283），但不再据此拒绝；同批改掉界面那句"确认构建、报告 schema 和 renderer 三项一致"（batch-execution-mode.ts:232）它不提供兼容性信息，还会误伤更新的版本；但它在证据链里，不能一删了之
D5被挡时给出口：版本不足提示里加"下载新版助手"按钮，文案写清"连托盘一起退出再打开"现在只说"请升级"，附近连个链接都没有（grep `href\download\Link` 0 命中）。最便宜的一条
D6改口（Owner 10-27 晚令「安装要手动退出软件，这个也一起做了吧」）：本轮就做"装新版不用手动退出"——第 3 批；而"助手自己下载新版"的完整自动更新排第 4 批，且必须排在第 1、2 批之后，默认开关关着见 §一-4：今天必须手动退出的原因已经查到底，是可修的三处叠加；而自动更新一旦接上，就会把"版本门砸客户"从一次性事故变成每台机器同时中招——所以次序不能反
D7不降下限到 3.7.15（我上一轮一度想这么干，已收回）3.7.15→3.7.28 有 27 笔助手改动，含 Host 回环白名单、会话文件不被默认配置覆盖、技术目录搬出客户素材目录、回执链不自崩——这些都不体现在契约字段里，放过来就是静默绕过

做完之后的效果：以后"只是重打包、契约没变、没带必修修复"的发布，客户不需要重装；真需要装新版时，客户只做一件事——双击安装包，剩下的（关掉正在跑的助手、覆盖、再自己起来）由安装器做，不需要手动退出软件；真需要拒绝的那一版照样响亮拒绝并给一键下载，不静默降级。

03三、执行顺序（我自己按这个走，不再问你）

第 1 批（纯增量，风险最低）：D5 下载入口 + 文案 → D2 头门控与错注释 → D1 拆字段（新字段缺省=现值，行为不变，先把管道铺好）

第 2 批（改判定）：D4 构建号降级 + 界面说法同批扫 → D3 机器检查与负控

第 3 批的形状已被封驳改过一次（见 交付档案/审查报告/审查报告_20261027_装新版不用手动退出_封驳与合成件实测.md）：我原来写的"用 --exit 把退出标志置真"经合成件实测不成立——--exit 是另一个进程，改不到正在跑的那个托盘的进程内变量，日志里它返回 0 而互斥体 15 秒不释放。改成下面这版并已跑绿。

第 3 批（本轮新增，Owner 令）——装新版不再需要手动退出，五步一起做：

1. 托盘加一个不带窗口的自杀入口 图译工坊本地助手.exe --exit。它不替别人退出，只做三件事：判忙（GET http://127.0.0.1:49152/queue/status，只认 busy === true，不得看 errorCode/phase——本机活助手实测空闲时 errorCode 也是非空的）、点着一个命名事件、等托盘互斥体消失。正在跑的托盘在自己的循环里看到事件就执行原本那条干净退出路径（停定时器→杀引擎→释放互斥体→退出）。返回码定死：0 已关／3 忙拒／4 叫不动。busy 字段由 server.js:2650 的 publicQueueStatus 公开。

2. 安装脚本加 PrepareToInstall：先从注册表卸载项 InstallLocation 取实际安装目录（取不到回退默认目录，两条都没有 ⇒ 中止并说明，不许静默继续），调用上面那个 --exit，然后用 CheckForMutexes('Local\TYGFLocalAssistantTray')（互斥体名见 TrayHost.cs:42）轮询等它自己走干净——这一步不依赖重启管理器，所以"托盘没有窗口"那条不再是拦路虎。返回码 3 ⇒ 中止安装并说人话（"本地助手正在跑替换任务，等这批跑完再升级"），不硬来。

3. 老版本鸡生蛋的兜底：3.7.28 及更早的托盘没有 --exit，第 2 步对它必然失败 ⇒ 轮询超时后按两个产品专名回退强杀，且只在 busy 双采为假之后才允许；哪条路走过的要落进安装日志。兜底后互斥体仍在 ⇒ 中止（合成件 T7 实测：taskkill 返回 128、安装中止 rc=7，不会硬装）。

4. 装完自己起来：静默装也要拉起托盘（去掉 skipifsilent 的连带影响，改为安装收尾 ssPostInstall 显式启动，RestartApplications 交回我们自己控制避免拉两遍）；拉起前先验互斥体，仍被持有就跳过并留日志（合成件 T8 实测这条闸真落）。

5. 顺手堵老洞：托盘菜单"退出本地助手"今天直接 process.Kill()（TrayHost.cs:146/:277）不看忙不忙，客户手点就可能把助手锁进恢复锁（server.js:2380/:2575）；该路径改走第 1 步同一个函数。

更正一条我说错的话：我曾在方案里把 CloseApplicationsFilter 那行三个名字用分号分隔判成"写错了"（installer.iss:35）。这是错的——scripts/smoke-pc-bundled-engine.mjs:321 的 [D4] 就是按 ; 切这一行、并要求列出内置引擎文件名 tygf-engine.exe（它以 serve 子进程常驻、持有自己的文件句柄；漏名会让删除退化成"重启后才删"，旧引擎作为孤儿永久留在 {app}\bin）。我动手时真把这道门跑红了，已改回原样并加注释"不要改成逗号"。Inno 自己怎么解析这个分隔符，本机没帮助文件、官方页取不到正文，仍属未核实——但我的自关机制不依赖它。

第 4 批（可选：一键升级，默认关）：助手侧 POST /v1.5/update/apply —— 下载→按 public/downloads/local-assistant-release.json 里已经在发的 sha256＋size（signatureStatus 现为 UnsignedBeta）校验→丢一个脱离父进程的安装器子进程（/SILENT /NORESTART）→自己走第 3 批的 --exit。开关 autoUpdateEnabled 出厂 false，翻它要您点头（属红线级：一旦开就是所有客户机同时执行下载来的代码）。

为什么第 4 批必须在第 1、2 批之后：D2/D4 没修之前，版本门是"不相等就拒"。自动更新会把一个新构建滚到客户机上，而网页这边还按老规矩拒它——结果是每台机器同一天集体连不上，事故从"重装一次"升级为"没人能用"。

每批都要：npx tsc --noEmit、npm run lint、对应合同门、负控必须能红（新门首跑要逐数复核它自己产出的量纲），跑完贴原式与退出码；第 3 批的专项验证见下；第 3 批的验证是"合成一个假托盘 + 一份复用同一段 Pascal 的小 iss，证明安装器真能等到进程干净、真能在忙时中止"，最后用 ISCC 编译正式 installer.iss（本机 C:\Users\ivan\AppData\Local\Programs\Inno Setup 6\ISCC.exe 在，退出码为 0 才算）

不做：提交推送之外的任何生产动作；生产发布仍卡在那四条前置（合回生产独有 2 笔、生产库补 ApplicationAttribution 表、助手随发决定、多稿补声明），那一条线我另开一件跟

04四、对抗式审查：这份方案自己哪里会坏

#攻击我的处置
1D1 拆字段后，minAssistantVersion 会不会被所有人理解成"当前版本"，反而更乱新字段加注释 + D3 机器检查强制"抬它必须写原因"；缺省等于现值 ⇒ 落地当天行为零变化
2D2 只在不支持时不发头 ⇒ 多账号选槽对旧助手退化成单槽旧行为，会不会有人以为功能坏了这是正确的退化（3.7.15 本来就没有多槽）；但界面要能看出"这版助手不支持多账号选槽"，所以 D2 附带一条能力提示，不静默
3D4 拆掉构建号拒绝后，信任链清单会出现"期望≠实际而无人拦"成立（§一-3 已证）。所以 D4 必须同时定信任链口径：构建号照记为证据，"一致"不再是有效性条件；这条不写清就不许动 D4
4D3 的机器检查会不会又变成一个"永远绿"的门用本项目老规矩：新门必须带负控（抬版本不写原因 ⇒ 必须红），并且用它的消费者验它（真跑一次出包链，不是只跑单测）
527 笔我到底读没读只按提交主题判读，未逐笔读 diff。D7 因此是保守判断（宁可不放）。真要按版本精确划下限，需要逐笔定性——我把它排进第 2 批，划在哪一格由逐笔结果定，不预先承诺
6这套做完能推生产吗不能，本次发布仍卡四条前置。这套解决的是"以后不再每版砸客户"
7第 3 批第 2 步"先查忙再关"有个时间窗：查完到真关之间，一批任务刚好起步引擎的 busy 是在 acquire 那一刻置真的（server.js:2447），窗口＝一次本机 HTTP 往返。处置：PrepareToInstall 连采两次 busy，两次都为假才放行；合成验证件里专门造一个"第二次变忙"的情形，看它是否中止
8老版本兜底那条 按映像名强杀 的爆炸半径到底多大不是零风险，如实登记：它会带走同机器上同名进程（含另一个 Windows 账户里的副本），Inno 里没法按可执行文件路径过滤。前置条件是 busy 已两次为假，且这两个名字是产品专名。这条路径我绝不在您本机跑（您的机器上有别的会话在跑的现场），只作为客户机上的兜底，标未验证
9注册表里取不到安装目录（装到别处／卸载残留被清）会不会让自关静默失灵会退化成"没杀掉→复制失败"＝回到今天的状态，不会更坏。处置：注册表 + 默认目录两条都试；两条都拿不到 ⇒ 中止并说明，不许静默继续装
10装完显式拉起时，端口 49152 还被残留进程占着 ⇒ 引擎起不来，但安装器已经报"成功"真会出现（尤其走了第 8 条强杀兜底之后）。处置：拉起前用同一枚互斥体判据确认场地干净；不干净就不拉、留一行日志，界面上的"未连接"提示仍按 §一-2 修好的路径说话。这条我在合成件里用"占住互斥体的假托盘"真跑一遍
11改托盘／改安装脚本必然要出 3.7.29，会不会只改代码不改版本声明已有门管着：smoke-release-consistency.mjs:154 与 :217 会把 installer.iss 的版本一起对账，漏同步＝出包红（不是我新立的规矩，是既有九文件+1 的同步面）
12第 4 批的信任面：哈希和下载地址来自同一个 HTTPS 响应成立且不可消除：站点或 CDN 被攻陷＝每台客户机执行任意代码。PrivilegesRequired=lowest（installer.iss:31）只把爆炸半径压到"该用户自己的权限"，不改变"能执行任意代码"。缓解只有三条：URL 主机名硬编码在助手代码里（不让 manifest 决定去哪取）、只认同响应的 sha256+size、出厂开关 false 且翻闸要您点头。对外说法也不能写成"已支持自动更新"，只能写"可选的一键升级，默认关闭"
