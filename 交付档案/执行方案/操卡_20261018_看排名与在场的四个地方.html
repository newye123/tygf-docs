01卡一 · Google Search Console（唯一现在就有数据的地方）

  • 打开 https://search.google.com/search-console/about → 用 9-17 那次建资产的 Google 账号登录（域名资产是 sc-domain:tuyigf.com，靠 DNS 里那条 TXT 认的，那条 TXT 记录不要删）。
  • 看三格，就三格：

- 左栏「效果」→「搜索性能」：看 展示次数、点击次数、平均位置。10-14 那次实拍是「效果 5 次点击」。

- 左栏「索引」→「页面」：看 已编入索引 / 未编入索引 两个数。10-14 实拍是 3 已编入 / 4 未编入。

- 左栏「索引」→「网站点地图」：确认 https://tuyigf.com/sitemap.xml 仍显示成功、已发现页数＝8（我今天现读 sitemap 就是 8 条 <url>）。

  • 这一格能说明什么：Google 愿不愿意收录、给了多少次展示。
  • 不能推成什么：① "平均位置"不是位次——Google 官方定义它是"你站点页面的最高位置的平均"，官方自己建议"更关注展示与点击，而不是位置"；② 表里没列出的词≠没人搜：Google 定义的两三个月只有几十人搜的查询在表格和 API 里一律不列（加任何过滤器就整体被忽略），Ahrefs 用 146,741 个站实测 46.08% 的点击来自这些隐藏词；③ 这里完全没有 ChatGPT／豆包／Kimi 的引用信息。
  • 另有一格叫「生成式 AI 性能报告」（2026-06-03 宣布、2026-08-31 铺到全球所有站点）：只有展示次数，没有点击、没有查询词、没有位次，而且API 里拿不到（searchconsole 的 discovery 文档 rev 20260805 里 generative／ai mode／datasource 全部 0 命中）。基线只能从 2026-08-20 之后起算（Google 自认 08-13 起该报表因日志 bug 系统性偏低）。

02卡二 · Bing Webmaster Tools（IndexNow 那条链真的通到这儿）

  • 打开 https://www.bing.com/webmasters，用您那个微软账号登录；若列表里没有 tuyigf.com，点「导入 Google Search Console 属性」最快。
  • 看三格：「索引」→「网页」；「性能」→「排名和点击次数」；「关键字」。
  • 这一格能说明什么：Bing 系（含 ChatGPT 检索、Copilot 走的索引）认不认我们。IndexNow 那 8 条 URL 推的是 Bing/Yandex/Naver/Seznam/Yep，不含 Google、不含百度，所以这格是 IndexNow 唯一的回看面。
  • 不能推成什么：不能推成"Google 也收了"。
  • 顺带一条已生效的平台变化：Bing 旧 SOAP/POX 接口 2026-08-31 已退役、Bing Search API 2025-08-11 已停，⇒ 程序化抓 Bing 结果这条路官方已经关上；我们仓里 scripts/submit-indexnow.mjs:128 打的是 https://api.indexnow.org/indexnow，不在这条退役线上（这点我核过原式）。

03卡三 · 百度站长平台（现状：不是"点一下"，是先修链路）

  • 打开 https://ziyuan.baidu.com/，用百度账号登录 →「资源平台」→ 站点 tuyigf.com。
  • 先确认「验证状态」。已知事实：验证文件本身是好的（我今天再读 https://tuyigf.com/baidu_verify_codeva-eNLQKp1jN0.html＝200、32 字节），但根账 #131 仍是 OPEN·major——10-13 那次文件验证与 HTML 标签验证各试多轮（累计 6+ 次），百度报错在「无法连接到您网站的服务器」↔「网站服务器错误」↔「301 网页存在跳转」之间抖动。
  • 本轮补上了一条机制候选（不是定案）：我今天用自建哨兵量了本站取数完整率——12 秒耐心下 Next 渲染面六件 18 次尝试有 10 次没拿满，其中连接级超时 UND_ERR_CONNECT_TIMEOUT 4 次；而且百度那枚验证文件自己也在这条尾巴上（p50 23.9 秒、两次里有一次只拿到 0 字节）。⇒ 如果百度抓取方的耐心低于这个量级，它报的就是「无法连接」，与 10-13 的现场一致。

04卡四 · Cloudflare（这一格是本轮新找到的，免费、不引脚本）

  • 打开 https://dash.cloudflare.com/ → 选 tuyigf.com 这个 zone → 左栏 AI Crawl Control（旧名 Crawler Traffic Management；各套餐含 Free 都可用、零配置）。
  • 看 Crawlers 表：每一行是一个爬虫（GPTBot、ClaudeBot、PerplexityBot、Google-Extended…），列里有 Requests（允许数与失败数，带趋势） 和 Robots.txt violations。
  • 这一格能说明什么：这些 AI 爬虫到底来过没有、来过几次、有没有被拦。这是我们目前唯一能看到的"AI 侧真实取用"读数——我们自己的 nginx 日志只记进到源站的那些，被边缘挡掉的那部分只有这里看得见。
  • 不能推成什么：Cloudflare 官方自己写明"失败请求可能来自任意规则或响应错误，不只是 AI Crawl Control 的 block"⇒ GPTBot 来过 ≠ 我们被引用。
  • 顺手两格：Analytics → 域名（cookieless 统计的读数，如果我们没开就仍是空）；自适应分析（Adaptive Analytics）保留期自 2026-10 起每套餐至少 30 天，且同一批数据可以用 GraphQL Analytics API 拉——这条让"每周自己拉一份 JSON 存下来"零成本可行，也是 §执行方案 C4 之外唯一不需要 OAuth 的自动化路径。
