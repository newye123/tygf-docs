## 2. 对抗式审查：先打自己七枪

### 枪 1｜`showDirectoryPicker()` 这条路是死的

网上最常见的答案（MDN / 各类"选文件夹"教程）是浏览器 `showDirectoryPicker()`。**它拿不到绝对路径**：返回的是 `FileSystemDirectoryHandle`，只能按 handle 读文件内容，`handle.name` 只有文件夹名。

而我们的扫描接口只收绝对路径：

```js
// download/local-assistant/server.js:4817-4823
const rawPath = typeof body.masterPath === 'string' ? body.masterPath.trim()... : ''
if (!rawPath || !/\.(psd|psb)$/i.test(rawPath)) return json(res, 400, { code: 'PREPARATION_NOT_PSD' })
const masterPath = path.resolve(rawPath)
```

**⇒ 浏览器侧递归列举在架构上不可用。递归必须落在助手侧。**

### 枪 2｜助手侧"选文件夹"已经有了，但语义被占用了

```js
// download/local-assistant/server.js:5470-5505
// POST /v1.5/select-folder — 为本次执行选择另存目录，不修改全局 taskRoot。
if (req.method === 'POST' && p === '/v1.5/select-folder') {
  ...
  if (result.operation !== 'select_file') return json(res, 403, { code: 'SELECT_FOLDER_NOT_AUTHORIZED' })
  const out = await picker.runPickerCommand({ command: picker.buildPickerCommand({ mode: 'folder' }) })
  ...
  return json(res, 200, { ok: true, folderPath: path.resolve(out) })
}
```

好消息：**绝对路径有了**，picker 置顶合同也是现成的（`picker-dialogs.cjs` 单一事实源）。
坏消息：它当前被"选另存目录"占用（注释原文），复用它做"选导入来源"会让一个端点担两种语义 —— 将来改输出目录的校验会误伤导入。**新开一个 `/v1.5/preparation/pick-folder` 更干净**，picker 命令直接复用。

### 枪 3｜**P0：跨目录批量执行今天就会 403**（本次最重要发现）

服务端执行前有一道闸：

```js
// download/local-assistant/server.js:5721-5726
const configuredRoot = path.resolve(cfg.taskRoot)
const masterRelative = path.relative(configuredRoot, masterPath)
if (!masterRelative || masterRelative.startsWith('..') || path.isAbsolute(masterRelative)) {
  return json(res, 403, { ok: false, code: 'MASTER_OUTSIDE_CONFIGURED_ROOT' })
}
```

`cfg.taskRoot` 只在一个地方被写：扫描时。

```
src/components/workbench/design-file-card.tsx:247   await setAssistantTaskRoot(masterPath)   // 单稿扫描
src/components/workbench/design-file-card.tsx:534   await setAssistantTaskRoot(entry.masterPath) // 批量逐稿扫描
src/components/workbench/execute-step.tsx           —— 一处都没有 ——
```

而批量执行循环只切 `psdSelection`，不碰 taskRoot：

```js
// src/components/workbench/workbench-view.tsx:1390-1402（起点）
setPsdSelection({ masterPath: entry.masterPath, ... })
// src/components/workbench/workbench-view.tsx:1428-1437（推进下一稿）
setExperimentIndex(nextIdx)
setPsdSelection({ masterPath: nextEntry.masterPath, ... })
```

**推演**：选了 `D:\项目\A\1.psd` 与 `D:\项目\B\2.psd`，批量扫描按顺序跑完 ⇒ taskRoot = `D:\项目\B`（最后一稿）。点执行，第 1 稿的 masterPath 是 `D:\项目\A\1.psd`，`path.relative('D:\项目\B', 'D:\项目\A\1.psd')` = `..\A\1.psd` ⇒ **403 `MASTER_OUTSIDE_CONFIGURED_ROOT`**。

**已跑真机验证（node 直算服务端同一判据）**：

```
同目录两稿（今天的用法）        taskRoot=D:\项目\B  master=D:\项目\B\2.psd  rel=2.psd        → PASS
跨目录第1稿（文件夹导入必然出现） taskRoot=D:\项目\B  master=D:\项目\A\1.psd  rel=..\A\1.psd   → 403 MASTER_OUTSIDE_CONFIGURED_ROOT
跨目录第2稿                   taskRoot=D:\项目\B  master=D:\项目\B\2.psd  rel=2.psd        → PASS
```

**为什么一直没暴露**：今天加稿的两条路（粘贴路径 / 逐个选文件）用户习惯把同一批 PSD 放同一目录，dirname 相同 ⇒ 闸恒过。**文件夹导入天然产生多子目录，一选就撞。**

修法（P0-1，1 行级）：执行每一稿前 `await setAssistantTaskRoot(entry.masterPath)`，与扫描时的约定完全一致（taskRoot = 该稿所在目录），不改服务端任何判据。

  for (const f of fs.readdirSync(taskRoot)) {   // ← 单层

如果采用"把所选根目录当 taskRoot"，子目录里的 PSD 不会被 stage 进 `psd/`。
但按枪 3 的修法（**逐稿用自身 dirname 当 taskRoot**），`readdirSync` 一定能看到该稿本身 ⇒ **不受影响**。

⇒ 判定：**不修**。写进已知边界，不引入"根目录当 taskRoot"的设计。

### 枪 5｜12 上限：两条入口的告知不一致，其中一条是静默丢

```js
// src/lib/workbench/psd-selection.ts:45-56
export function addMultiPsdEntry(selection, entry, maxEntries = 12) {
  ...
  if (selection.entries.length >= maxEntries) return selection   // ← 静默丢弃
```

```js
// src/components/workbench/design-file-card.tsx:801（粘贴路径那条）
if (parsed.overflow.length > 0) reasons.push(`${parsed.overflow.length} 个超出上限 ${MAX_PSD_ENTRIES}（未加入）`)
```

同一个上限，粘贴路径会明说"3 个超出上限（未加入）"，而 `addMultiPsdEntry` 那条什么都不说。**违反"不静默跳过"红线。**

⇒ 文件夹导入必须走**第三条、唯一正确的那条**：扫描前先算总数，超了就明示"共 N 个，按名称排序取前 12，其余 M 个未加入"，并且**把"未加入的 M 个"列出来**（不折叠成一句话）。同时把 `addMultiPsdEntry` 的静默 return 改成返回结构化结果，让调用方能告知。

### 枪 6｜译文表与 PSD 的配对没有唯一解，自动绑必错配

表格格式是宽的：`csv-step.tsx:104` 接受 `/\.(csv|tsv|txt|xlsx|xls)$/i`。

但"子文件夹里找到的 `文案.xlsx` 属于哪一稿"没有确定答案。可选规则至少四种：
1. 同目录就近绑（`A/1.psd` ↔ `A/文案.xlsx`）
2. 文件名同前缀（`1.psd` ↔ `1.xlsx`）
3. 全批共用一张表（1 表 × N 稿，这本来就是支持的模式）
4. 按顺序一一对应（危险：错位即错译）

**⇒ 判定：文件夹扫描只负责"列出来 + 标出每个表在哪一层、和哪些 PSD 同目录"，绝不自动绑定。** 绑定仍由用户在语言区显式选择。这条要写进 UI 文案，不能含糊。

### 枪 7｜与 v6 那五件（A1–A5）的关系：不能并行做

`交付档案/交接与对账/交接_20261017_批量台v6上线实施_给接手AI.md` §3-A 列了五件：A1 文案净化 / A2 译文表导入卡 / A3 矩阵门控 / A4 死控件接线 / A5 顶带导轨计数。

本次改动与 A1（文案净化）、A2（表卡前置）、A4（死控件接线）**落同一批文件**（`design-file-card.tsx` / `execute-step.tsx` / `workbench-view.tsx`）。并行做必然互相覆盖 —— 这正是 10-18 合流时踩过的坑（`git checkout --ours` 把对方整段回退）。

**⇒ 顺序定死：先 P0-1（执行链）→ 再文件夹导入（P1-1）→ 再换肤（P1-2）→ 最后 A1 文案净化（P2）。** 换肤必须最后做，否则每改一次 UI 都要重刷 192 处用色。

## 3. 开源参照：查了，但结论是"抄纪律，不抄依赖"

| 项目 | 事实 | 本项目是否采用 |
|---|---|---|
| **fdir**（thecodrr/fdir） | MIT、<2KB gzip、零依赖、百万文件 <1s、被 rollup/plugins、pulumi、mdn/yari、netlify/build 使用 | **只抄算法纪律**：迭代栈代替深递归、`withFileTypes` 一次拿类型、忽略目录黑名单、软链不跟随 |
| **VS Code** 打开文件夹 | 先列顶层，子层懒加载；有 `.gitignore` 感知；大目录显示进度 | 抄"先给总数再给清单"，不抄懒加载（我们要一次判 12 个上限） |
| **Eagle / Bridge** 素材导入 | 递归导入后**平铺成网格**，不保留层级；同名冲突显式提示 | 抄"平铺 + 显式冲突提示"，不抄"保留层级树"（批量台是线性列表） |
| **File System Access API**（MDN） | `showDirectoryPicker()` 无绝对路径；需 HTTPS + 瞬时激活；实验性 | **不可用**，见枪 1 |
| **chokidar / globby** | 成熟但带依赖树 | **不可用**：助手零依赖 `pkg` 单 exe（`package.json` 无 dependencies，无 `node_modules`），加依赖破出包 |

**递归 walker 复用现成写法**（`server.js:3716-3724` 已有一个局部 `walk()`，用于结果哈希）：

```js
function walk(dir) {
  if (!fs.existsSync(dir)) return
  for (const entry of fs.readdirSync(dir, { withFileTypes: true })) {
    const full = path.join(dir, entry.name)
    if (entry.isDirectory()) walk(full)
    else if (entry.isFile()) files.push(full)
  }
}
```

改为迭代栈 + 深度上限 + 忽略表 + 软链跳过，约 30 行，零依赖。

### P0-2｜助手侧新增递归列举端点

- 新端点：`POST /v1.5/preparation/pick-folder`（picker 复用 `picker-dialogs.cjs`，`mode:'folder'`）
  返回 `{ ok:true, folderPath }`（绝对路径），`cancelled:true` 当用户取消
- 新端点：`POST /v1.5/preparation/list-folder`
  入参 `{ folderPath, maxDesigns: 12, maxDepth: 6 }`
  出参：
  ```json
  {
    "ok": true,
    "root": "D:\\项目",
    "designs": [{ "path": "...", "relPath": "A/1.psd", "size": 12345, "mtime": "..." }],
    "designTotal": 17, "designKept": 12,
    "tables": [{ "path": "...", "relPath": "A/文案.xlsx", "ext": "xlsx", "dir": "A" }],
    "tableTotal": 3, "tableKept": 3,
    "skipped": [{ "relPath": "deep/x.psd", "reason": "DEPTH_EXCEEDED" }],
    "truncated": true
  }
  ```
- 纪律（必须逐条落实，否则就是新的静默跳过）：
  1. **排序＝自然排序**（numeric-aware）按 `relPath`：`2.psd` 排在 `10.psd` 前，与 Windows 资源管理器一致
  2. **超限必明示**：`designTotal > designKept` 时前端必须显示"共 17 个，取前 12，其余 5 个未加入"并**逐条列出**未加入的 relPath
  3. **忽略目录黑名单**：`node_modules` `.git` `output` `report` `psd` `__MACOSX` `.Trash`
  4. **软链不跟随**（`entry.isSymbolicLink()` 跳过并计入 skipped）
  5. **深度上限 6**，超限计入 `skipped` 并告知，不静默
  6. **路径必须是 `folderPath` 之下**：`path.relative` 校验，越界 400
  7. 全程只读：不写文件、不改 `cfg.taskRoot`（避免与枪 2 的语义冲突）

### 8.2 两处偏离原方案（都是执行中发现更优解）

**偏离一：不新开 `pick-folder` 端点，复用 `/v1.5/select-folder`。**
原方案说"新开更干净"。实际读过实现后发现该端点**只弹框并回传路径，无任何副作用**（不写文件、不改 `taskRoot`），复用不会与"选另存目录"互相干扰；新开反而要复制一份 picker 置顶合同（`picker-dialogs.cjs` 的 TopMost 约定），是重复而非隔离。

**偏离二：换肤不改 192 处 className，改为覆盖色板变量。**
构建产物里 `.bg-teal-600{background-color:var(--color-teal-600)}` ⇒ 在工作台作用域内覆盖 `--color-teal-*` / `--color-sky-*` 等变量，一次收敛全部调用点，零漏改、零 diff 噪音、可整体回退。
语义保留：teal=主强调、sky=进行中（同族更浅一档，否则与"成功"撞色）、emerald=成功、amber=待处理、rose=失败。
圆角用 `--radius: 0.75rem`（`rounded-xl` 编译成 `calc(var(--radius) + 4px)` ⇒ 卡片正好 16px，与官网 `--radius-sm` 一致）。
