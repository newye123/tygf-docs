英文站字体「晚发现」：H1 先以回退字体绘制再换字

这一轮不看代码，看线上。用真浏览器 ＋ SSH 隧道对已上站的测试站做了一轮巡检， 查出一个真实的用户可见缺陷：英文站没预加载自己的字体，浏览器要等 CSS 下载完 才开始找字体 —— 实测字体请求发生在 3380 ms（文档 0 ms、CSS 1393 ms）， 比中文站晚了整整一个发现阶段 ⇒ 英文首页那个 H1（就是 LCP 元素）先用回退字体画一遍、再换成思源黑体。

02对抗式审查：查出来的东西，逐条自审

2.1 真缺陷（要修）

F1英文站没预加载自己的字体 ⇒ 字体「晚发现」

真浏览器请求时间线（已上站的 /en）：document@0ms → stylesheet@1393ms(3 个) → script@1394ms → font@3380ms。字体是最后一个关键资源，比 CSS 晚约 2 s 才被发现 ⇒ H1（LCP 元素）先用回退字体画一遍、再换成思源黑体（可见 FOUT）。中文站对照：/ 预加载了 4 个分片，英文站一个 font preload 都没有 ⇒ 两站不对称。

⇒ 加 <link rel="preload" as="font">。放在 src/app/en/layout.tsx（不是只放首页） —— site-fonts.css 的规则是 html[lang="en"] body，全部 /en 页面（首页/下载/条款/隐私）都渲染英文正文；这与中文站「只首页预加载」不同（中文站其余路由不渲染中文正文，预加载会白拉分片）。

2.2 门缺口（这才是根因 —— 缺陷能上线，是因为没人管）

F2真浏览器那道门量了字体请求，却没断言「必须预加载」

⇒ 「晚发现」这类缺陷能过门。⇒ 加：英文页必须有 link[rel=preload][as=font] 指向自己的字体子集；中文页必须预加载全部 4 个分片（把现状钉住，防回退）。

F3出包门也不管预加载

build-en-font-subset.mjs --check 只校验「字体文件与清单一致」，不涉及「谁引用它、谁预加载它」⇒ 删了 preload 没有任何一道门会红。⇒ 加结构性断言：声明这个 @font-face 的 layout 必须预加载它（按 <link …> 块解析，判块内同时出现 preload 与该字体文件名）⇒ 这道门在 test:contracts 链尾，每次出包都会跑。

2.3 巡检本身没固化（我自己的责任）

F4全站死链巡检是手写探针，没变成可复跑的门

⇒ 下次还是得靠人记得跑。如实记为未固化，另立项，不假装有门。

2.4 差点误报（动手前查清，没写进任何文档）

F5「已提交的助手源码 require 了未提交的文件 ⇒ 干净检出下助手加载不了」

git grep 搜的是工作树（含别人在飞的改动）⇒ 改用 git show HEAD:… 看提交版本 ⇒ HEAD 里没有那个 require。证伪，不成立，已提交树是自洽的。已记一笔，免得下一班重复查。

2.5 顺带核过、确认没问题的

  • 英文页真浏览器读数：bodyFontFamily ＝ "Tuyigf Source Han Sans EN", … ✓；document.fonts ＝ Tuyigf Source Han Sans EN=loaded ✓；.home-v17--en ✓；.nav-lang-switch ✓；控制台 0 错误 ✓；无横向溢出 ✓。
  • 英文 H1 是两行两个 .hero-title-line 元素（innerText ＝ Make changing languages\neasy on designers）⇒ 之前 textContent 看着「少个空格」是拼接假象，不是文案缺陷。
  • 公开面 18/18 全 200；站内 21 条链接 0 条 4xx/5xx；中文首页引的是 4 个分片、不引旧全量 VF。
  • 预加载不新增任何对外文案，不改 llms/robots/sitemap ⇒ 不触发对外事实面复核。
