三、第一批：把官网说法修准，并让修订真正生效

3.1 先建立一份短的“承诺—证据—页面”清单

实施者先列出待改句子、替换句子、实际能力证据、出现页面和内容键。所有公开承诺进入这份清单；结论无法查证的先删掉保证语气，不自行补数字。

建议首屏主标题：把定稿译文，批量写回可编辑 PSD。

建议副标题：用你本机的 Photoshop 处理可直接替换的文字图层，保存后重开核对；需要判断的绑定和版式问题集中查看，交付前由设计师确认。

按钮：在第二批完成之前，继续使用真实可用的下载与申请入口；第二批验收后增加“查看交互演示”。不提前发布指向未完成页面的按钮。

具体口径：

- 换行：“按原稿已有多行结构辅助换行；单行长译文及复杂排版仍需检查。”不能写“所有长译文自动折行、不超画布”。

- 回读：“核对保存后的文字是否符合计划；视觉排版仍需人工确认。”不能写“回读一致证明零漏改或版式正确”。

- 失败：“保存前与重开后的失败分开说明，失败结果不得作为通过验收的交付件。”具体隔离路径和是否停止后续语言，必须先沿实际执行分支核实再写。

- 覆盖：“可编辑文字、智能对象、不可读文字、栅格化内容分别说明。”不能保证扫描出所有像素中的文字。

- 数据：“设计文件本体留在本机；在线流程处理哪些文字、路径和摘要，以核实的数据流为准。”不可宣称关闭 AI 后全部输入都不出设备。

- 数字：“40 层 × 12 语种 = 480 次”为明确标注的假设示例，不能改写为所有客户都能节省 480 次或固定耗时。

- 阿语、泰语等：“复杂文字需在目标 Photoshop 环境复核方向、连字与排版。”未验证具体版本前，不给通用菜单指引或兼容保证。

隐私政策处理边界：可做与现有处理事实一致的表述修正，但不得在本批承诺新增“学习可单独退出”。涉及同意规则、用途、存储地、撤回权实施的变化先进入后续工程并核查合规依据。只要同一数据事实在官网与协议里仍冲突，该事实相关文案就不能发布；不能靠“政策暂不动”绕开不一致。

- src/config/siteContent.ts、src/config/site.ts：只改本批确认的公开文案键；不把工作台、支付或功能开关一起重写。

- src/components/site/home-view.tsx、home-view-en.tsx：仅必要的文案消费、示意数字、入口与模板链接；保留当前表单提交合同。

- src/app/(zh)/download/page.tsx、src/app/en/download/page.tsx：展示发布版本与 SHA-256；包不可用时明确显示状态并禁用下载，不显示上一个版本摘要冒充当前包。

- src/app/(zh)/guide/ps-batch-replace-text/page.tsx：修正已核实的旧说法。先改善现有教程，不以新建三篇对比文章作为本批完成条件。

- public/llms.txt、public/llms-full.txt：与可见页面同口径；robots.ts、sitemap.ts、首页 JSON-LD 仅在实际有变化时增量修改，不重复注入。

- public/samples/translation-master-sample.csv：优先复用；若导入行为测试证明需要修订，改现有文件并更新引用。

- 条款页面只在前述数据事实修订确有需要时纳入，逐句记录理由；服务权限变更不在此授权范围。

下载校验验收：下载实际二进制计算 SHA-256，对齐页面、发布接口和产物三方；链接与摘要指向同一个版本。摘要不等于数字签名，不把“哈希一致”写成“微软已认证”；不指导用户关闭系统防护。

3.3 代码之外，后台文案也要同步

1. 对目标环境读取当前发布版本 ID、摘要、页面内容及有效默认值，保存可回滚快照；此时只读，不写库。

2. 只针对承诺清单列出的键建立内容补丁。后台有其他人修改的文案，不能整份覆盖为仓库默认值。

3. 在独立测试数据库用绝对 DATABASE_URL 演练：旧发布内容 + 新代码 → 建草稿 → 预览 → 发布 → 访客读回 → 回滚。数据库路径须实测确认，不能落到 develop 共享库。

4. 草稿发布前重新读取基准；有漂移则重新对账、重新生成草稿，禁止强行覆盖。验证现有 :698 检查确实拒绝陈旧草稿。

5. 测试站与生产分别创建自己的内容版本，不跨环境复用 revisionId。发布按钮或接口属于对应环境写操作，按该环境授权执行。

6. 发布后检查游客实际可见 DOM 和 JSON-LD，不用对 HTML 全文 grep 代替用户可见文本检查。

本批完成条件：所有列入本批的公开承诺都有证据；默认与存储覆盖两种状态均经过运行验证；既有申请、下载和导航没有回归；没有死链接。代码完成、测试站完成、生产完成分别记录。

五、第三批：真实视频与成果包

先盘点现有素材、使用权和运行记录。找得到且满足要求就复用；当前方案未核实素材齐备，不能写成已有。

执行样例采用自有或明确许可的 PSD、定稿译文表与可公开字体。至少覆盖：正常可编辑文字、多行结构换行、单行长译文、需人工判断的绑定，以及扫描覆盖限制。无法同稿自然覆盖时分两套，不为了“全绿样例”删掉例外。

每套交付包附：输入 PSD/PSB、译文 CSV、各语种输出、预览图、原始 HTML 报告、环境说明与文件 SHA-256 清单。说明助手版本、PS 版本、执行日期、处理范围、跳过项、人工复核结果及剩余问题；绝不包含本机绝对路径、客户资料、授权信息或令牌。

录屏使用实际运行画面，长度随事实决定，不强制伪装为 90 秒完成。若剪辑或加速，明确标注；不拼接不同版本来证明一次完整成功。

机器回读和人工视觉检查分开记录。真实机器不可用时，可以完成脚本与素材准备，但本批仍为 NOT RUN/待验收，不能用 mock、DOM 自动化或函数测试替代。

验收后才增加视频及成果包入口。只有第一、二批发布而第三批未完成时，发布清单明确写“尚未包含真实成果包与实跑视频”，页面不显示假按钮；这属于事先定义的分批发布，不把缺项静默降级。

六、顺序、文件归属与隔离

默认一个实施者串行推进；本方案不要求自动派生并行 Agent。以后若安排多人，所有文件仍必须只有一个写者。

- 第 0 步，整合者：冻结候选基线、读取目标内容版本、生成承诺清单、登记保护现场。若当前 worktree 有并发修改，使用经核对的隔离工作树，禁止带入未验收改动。

- 第 1 步，实施者：第一批内容与下载修订；整合者处理后台内容补丁及首页接线。

- 第 2 步，实施者：第二批演示模块、页面与测试；第一批验收后才接入口。

- 第 3 步，实施者与真机验收者：第三批素材、录屏、成果包。软件检查可自动完成；视觉验收按真实可用机器与人员记录。

- 每一批后：审查实际 diff → 针对性测试 → 负控 → 保存运行证据 → 独立发布决定。不得积累三批后只跑一次 build。

遇到需要修改 trust-chain、local-assistant、auth、计费或 consent-gate 的要求，退出本批施工范围，转到第九节后续工程。这里是明确分期，不是允许绕过相关功能。

七、验收清单：验功能和反例，不验一句成功口号

以下是待执行验收项，不代表本轮已经通过。每项记录环境、commit、运行命令或步骤、退出码、结果文件；不能用静态文件存在判 PASS。

V1 宣传事实：逐句对照承诺清单与对应行为证据，单行长译文等反例不能仍出现全自动保证。页面截图与可见文本均保留。

V2 文案生效：预置旧 ACTIVE 内容，跑新代码和内容修订后访客读到新值；陈旧草稿发布被拒；无关后台文案保持不变。

V3 SEO：解析真实响应中的 JSON-LD；FAQ 与可见问答一致，同页面不重复注入；canonical、语言替代链接、robots 与 sitemap 指向真实可访问路由。搜索收录只作后续观察，不列为本批必然结果。

V4 模板：真实导入器读取现有 CSV，列名和样例语种正确，编码及下载响应可用。错误列名样例应明确报错。

V5 下载：同版本页面、接口、实际包 SHA-256 一致；包不可用或摘要不完整时不能显示可验证成功。

V6 既有流程：原申请表、登录、下载及工作台入口仍可运行；不自动发码、不绕身份。只测涉及入口，不修改工作台在飞功能。

V7 演示行为：空译文/歧义处理前后状态真实变化；未处理不可越过；重置回到初态；中英文一致，键盘和移动端可用。

V8 演示边界：捕获浏览器网络，证明不触发真实执行/计费/授权/AI/本机助手；页面与报告清楚标“演示”。

V9 真实素材：实际下载、解包、哈希核对、Photoshop 打开、逐层读回与视觉复核，录屏与报告指向同一执行记录。

V10 回滚：目标环境的代码版本、后台内容版本及静态资产作为一组回滚；实测旧页面仍可用，不能只回滚 Git 却留下新内容覆盖。

负控至少包含：

- 把一条待改错误承诺放回被访问页面，V1 必须失败；不能只把词放进注释里验证。

- 用旧 ACTIVE 覆盖新默认值，V2 必须发现访客仍看到旧文案。

- 删除/破坏 JSON-LD 或提供无效路由，V3 必须定位失败。

- 演示按钮直接跳“完成”或触发真实接口，V7/V8 必须失败。

- 用缺输出稿或缺运行记录的包替代样例，V9 必须失败；文件存在不能过关。

所有破坏只在隔离副本进行，逐次还原并核哈希。新测试脚本必须先证明自己能抓到坏样例，再接受其绿色结果。

若实际改到身份、执行范围或合同，原分期即失效：回到工程审查并追加 test:trust-chain、test:batch-row-contract 与助手生成件/版本检查，不能在本批悄悄完成。
