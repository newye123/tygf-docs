## 1. 方向（一句话）

> **每个子文件夹放一套要改的 SKU 的 PSD ＋ 它的表。选一个工作文件夹，系统自己读、自己配、自己审。**

| | 内容 |
|---|---|
| 入口 | **一个按钮：选择工作文件夹**（免的是"逐个上传"，不免"指一个根目录"——助手是本机进程，浏览器拿不到绝对路径） |
| 绑定 | **目录即绑定**。组内 **1 张表 ⇒ 全组共用**；**多张表 ⇒ 按同名一对一**（`SKU-AX1001_主图.psd` ↔ `SKU-AX1001.xlsx`）；**配不上的 ⇒ 逐条点名**，绝不静默套用 |
| 界面 | **组卡片列表**（一组一张卡：复选框、规则说明、进度条、问题数、「打开这一组」）＋ **组内详情**（这一组的 PSD 表 ＋ 该组语言进度条 ＋ 单稿同款智能审核表 ＋ 该组要处理的事） |
| 命名 | 步骤名/卡片名/操作名**全部沿用单稿工作台**；只加"多稿层"三处说法：**12 个设计稿** / **每个设计稿用哪张表** / **这一批的进度**；四个整格状态词：**就绪 / 待检查 / 有 N 处要处理 / 缺语言** |
| 单稿工作台 | **零改动**（旁挂式：批量台的能力全在新文件里，**五个不变式闸**守着） |
| 执行层 | **不触发合同变更**：合并发生在构建 fragments 之前 ⇒ 信任链的分组与冲突检查原样复用 |

## 2. 模型（绑定原子只有一条）

```
一行译文  = (归属, 原文, 出现序号) → 目标文本
一份交付物 = (设计稿, 语种)
```

**表不是原子**——它是行的容器。于是：

| 真实关系 | 在模型里是什么 |
|---|---|
| 1 稿 : 1 表 | 默认：每格取主表该语种的行 |
| N 稿 : 1 表 | 多个稿的默认行集来自同一张表（表内无「同原文不同译文」时合法） |
| 1 稿 : M 表 | 某些语种换成别的表（语种覆盖）＋ 某些行从补充表并进来 |
| N 稿 : M 表 | 上述组合 |

⇒ **四种关系是同一个模型的四个取值，不是四种模式。**
⇒ **人只有三种操作**：换这稿的主表／把某几门语言指到别的表／给这稿加一张补充表；其余 144 格由系统推导并画出来。

## 4. 审查结论（9 轮沉淀，保留 9 条）

| # | 级 | 结论 | 落点 |
|---|---|---|---|
| 1 | 🔴 | **配错表可以静默通过全部闸门**，把错译文写进客户 PSD。错绑 ＋ 原文重叠 ＋ 表内无冲突 ⇒ 覆盖率 100%、全闸门放行 | 绑定的**证据**必须可见（对稿覆盖率）；错的表**点名** |
| 2 | 🔴 | **"写错风险＝0"是错的**（同日 08:59 v7 审查 F9）。它引的是浏览器预览匹配器、且只在"两稿原文完全不重叠"时成立 | 已点名推翻；写入层真相是信任链 `binding-core.ts:657/:930-939` |
| 3 | 🔴 | **"免上传"不能被读成"免确认"** | 配对结果必须**列出并可改** |
| 4 | 🟠 | **最大的落地风险不是技术，是"用户不知道要这么摆目录"** | 第一屏讲清约定 ＋ 读完**回显**「已按目录分成 N 组」＋「重新读取」＋ 配不上的**逐条点名** |
| 5 | 🟠 | **合并粒度必须是 (稿, 语种)，不能是整表** | 合并只在每格内发生（`execute-step.tsx:792-807` 的 `buildRowsByLang` 是浏览器侧唯一行来源） |
| 6 | 🟠 | **"整表给多稿共用"要能整张共用**（表内无「同原文不同译文」时） | 判据**可计算**：有冲突 ⇒ 必须切片；无 ⇒ 可整张共用 |
| 7 | 🟠 | **"每稿一表"是实现特例，不是自然法则** | 绑定原子下沉到 (稿×语种)→行集；四关系自动涌现 |
| 8 | 🟡 | **12 语种上限会被一列"备注"打死**（`csv.ts:707`） | 语言列上限判定改为"排除已识别非语言列后再算"；报错点名可疑列 |
| 9 | 🟡 | **逐层哈希可被字典反查** | 默认只回传**聚合得分**；逐层哈希降级为可选加强模式（带盐、单独论证） |

## 5. 落地顺序（7 阶段，每阶段可独立验收/回滚）

| 阶段 | 做什么 | 验证 |
|---|---|---|
| **0** | **`#workbench` 快照断言脚本**（`batchMode=false` 下抓关键 DOM 节点数/文案集合/按钮集合存基线） | rc=0、基线可复现。**必须第一个做**——「与原行为逐字节一致」是仓库既有成文验收尺（`app-shell.tsx:41-47`），**没有断言脚本它只是一句话** |
| **1** | **目录约定的文案与引导**（审查 4） | Owner 过目 |
| **2** | **读目录 ＋ 配对规则**（纯函数） | 单测：共用/同名/名不符/超 12/软链/超 6 层 |
| **3** | **组卡片列表 ＋ 组级开关 ＋ 组级进度** | 实拍 3 组；开关与进度联动 |
| **4** | **组内详情**（用哪张表可改 ＋ 该组语言进度 ＋ 智能审核**复用单稿 `ReviewStep`**） | 配对结果可见可改；审核表与单稿一致 |
| **5** | **版本一致性检查**（稿指纹变 ⇒ 该组重新核对，复用 `preparation-contract.ts:466-473` 的 `INVALIDATED`） | 改版稿能被点名 |
| **6** | **接执行**（走通「确认并生成」；助手得分接口**独立一单、只读**） | 按组执行、按组计费；积分与预估一致 |

**五个不变式闸**（任一不过不许合入）：**结构**（入口那行不许动）｜**渲染**（多稿能力必须包在 `batchMode` 内）｜**行为**（快照逐字节比对）｜**diff**（改既有文件必须落在 batchMode 块内或只加带默认值 prop）｜**单一真值**（渲染形态只认视图传下来的 `batchMode`，先例 ISSUES #151）。

**不做**：执行链、报价、结算闸、助手协议、支付开关、`binding-core` 匹配键 ⇒ **不触发合同变更门**（不跑 `test:batch-row-contract` / `test:trust-chain`）。
