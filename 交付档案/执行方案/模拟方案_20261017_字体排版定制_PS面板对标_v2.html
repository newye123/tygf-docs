自我更正入账：本页第一版把「字距调整方式」和「段落合成器」写成"做不了"，那是我枚举成员名猜错（ROMAN / JAPANESEWIDE）造成的——按真名 OPTICAL / ADOBEEVERYLINE 重测后两项都成立（H5）。同一小时我在行距上犯过一次同样的错（G 探针）。规矩：写"这个不行"之前必须先把成员名穷举一遍，否则一律标未核实。

③ 新线索：把点文本转成段落文本，让 Photoshop 自己换行

H4 探针实测：同一段 105 字符、无一个换行符，kind=POINTTEXT 时包围盒 705×13；置 PARAGRAPHTEXT 后设 width=180pt ⇒ 174×97（按闭式反算正好 5 行）。也就是说 PS 自己的排版引擎能替我们做"译文顶宽就换行"这件事。

这条路的甜头

  • 09-23 那三族里最大的一族「设计稿只有一行、译文更宽」（31 处）可能一行代码解决：给框宽，PS 自己折。
  • 用的是 PS 自己的字体度量和断行规则 ⇒ 我们那套 em 估算 + 整数 DP 求解器的误报面（实测 24.5% 是误报）直接消失。
  • 缩进／段前后距／对齐这些"只对段落文本有效"的旋钮同时被解锁（① 表里那 5 个"写了没反应"的项）。

代价（三条，每条都能单独否决它）

  • 取证会静默失真：我们现行"渲染行数"主法＝数交付件里的 0x0D（点文本下视觉行≡硬换行，定义级正确）。段落文本的折行是软换行，不落 0x0D——H4 那段文字一个换行符都没有却是 5 行 ⇒ 数 CR 得 1、真值 5。这条不解决就不能上线。
  • 禁则闸门失效：PS 自己折在哪我们看不见也管不着——片假名连写内部禁断、小假名不得落行首、数字与单位不得断（对手交付件里 13 例）这些我们已立案的禁则，全变成黑箱。
  • 交付件的图层结构变了：点文本→段落文本是设计文件层面的改动，客户的后续编辑习惯、我们"母版结构不动"的对外说法、以及报价/结算链对图层几何的假设都要重判。
我的判断（对抗式审查后）：不进这一班车，单列研究项，且先只做取证实验。 理由：它诱惑力全在"少写求解器"，但它砸的是我们唯一能证明"渲染成什么样"的那条腿；一个看不见折行的交付件等于把 #75 的病重新打开。要真走，前置是"软换行可取证"——候选办法是逐行宽度反推或像素带扫描（后者已实测在生产量级跑不完）。可立刻做的：把它当"高级选项"给内测用户手动开，同时强制上报"该层已转段落文本"，取证标"未采集"，绝不计入"已验证"。

对我们最要紧的两条外部事实

  • 避头尾会改变行数：日文换行由 JIS X 4051 定，句号/读点/闭括号不得居行首（Wikipedia 换行规则）；开着它为了避开禁则字符会额外换行或挤压行宽（Adobe Asian type in Photoshop）。⇒ 一旦我们让 PS 自己折行（③ 那条路），日/中译文的行数就取决于这个开关，而 PS 22 的 DOM 根本没有这个开关。
  • UXP 那套文本 API 帮不上我们：ParagraphStyle.kinsoku / mojikumi / layoutMode 的属性页标 min-version 24.1，而 changelog 把 Text support 记在 24.2（两页口径自相矛盾，ParagraphStyle、Changelog）。我们产品下限是 PS 22 ⇒ 只能走 ActionManager，而 key 名一个都没查到出处。

取 key 名的唯一可靠办法（记下来，别再猜）

在真机上装 Alchemist / ScriptingListener，手点一次"避头尾=JIS 宽松"，读它打出来的 AM 代码（Action Manager 教程、jardicc/alchemist）。我这轮三次靠猜枚举名犯错（PARABOLATEXT、JAPANESEWIDE、ROMAN），猜出来的判据比没有判据更坏——它会让下一只手以为"已经测过"。

顺带一条外部印证：官方类型定义里 AutoKernType 就是 MANUAL / METRICS / OPTICAL（Types-for-Adobe PS 2015.5），与我 H5 实测一致；那份定义还列了 hyphenation / hangingPuntuation / textComposer 等属性，但没有 kinsoku / mojikumi / tsume（全文 0 命中）。

未核实（不许当结论用）

① 任何 kinsoku / mojikumi / 合成器的 ActionManager key 名（一个都没查到出处）；② 日文设计"常用第几档间距组合"；③ "翻译场景该不该关连字"的权威建议；④ Crowdin / Phrase / Lokalise / memoQ 有没有"按语言设排版规则"——只查到 per-string 长度约束与视觉上下文，没查到排版预设＝未核实，不等于没有；⑤ 稿定设计 / 美图设计室 / Photoshop 自身能否指定字体；⑥ 删除线与下划线"开"档的成员名（我只试了 OFF 形）。
