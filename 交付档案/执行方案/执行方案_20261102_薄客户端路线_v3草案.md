# 薄客户端路线 · 执行方案 v3 草案（2026-11-02）

基线 `worktrees/develop@71529c7c`，现役助手 3.7.31。这是"一劳永逸"那一版的**草案**，待 A 路对抗审查与 B 路交叉验证后再定稿。

## 0. 一句话

把"判断"从客户端搬走之后，客户端剩下的只是"量尺寸 + 动手写 + 报事实"。这样**别人逆向我们照旧可能，但逆回来不再等于拿走我们的能力**；而且顺手关掉一条实测存在的收入漏洞。

## 1. 先说那条比防逆向更要紧的账（本轮实测，我逐条复跑）

- 单文档链扣不扣钱的依据：`src/lib/server/photoshop-billing.ts:650-660` 的 `resultUsable` 由上报里的 `deliveryStatus / status / summary.unmatchedLayers / summary.skippedLayers / summary.exportedFiles / summary.errorCount` 决定，`:660` 再算 `successfulStandardRows = resultUsable ? job.quote.standardRowCount : 0`。
- 而这些字段全部是**客户端算出来的**：`src/lib/trust-chain/settlement-adapter.ts:19-32` 就是把助手回执直译成这些字段（`artifactDisposition==='PUBLISHED' ? 'complete' : 'not_generated'`、`totalTextLayers: receipt.totalAssignmentCount`）。
- 回执里的"条数对得上"是**自报对自报**：`src/app/api/local-assistant/attempt/route.ts:43` 从请求体取 `totalAssignmentCount` 存进 attempt（`:86`），`attempt/report/route.ts:61` 再拿回执里同一个自报值去和它比。
- 云端 `standardRowCount` 在执行/结算侧**没有任何比对点**：`grep -rn standardRowCount src/app/api/local-assistant src/lib/server/local-assistant.ts` 命中行数 = 0（我复跑）。
- 批链稍好但同源：`src/lib/server/execution-batch.ts:1388-1391` 的唯一收费闸是 `verificationLevel === 'REOPEN_VERIFIED'` 且 `objectEvidenceDigest` 非空——**两个值都由客户端给，摘要从不与服务端事实重算比对**；`v15-runner.js:1133/1136` 行身份缺失即跳行（少报＝少计费）。
- 判据的源头也在客户端：`v15-runner.js:98` 的回读文本判等、`:104` 的 `actualTextDigest`，都在助手进程里算。

⇒ **结论**：因为我们把裁决与结算判据以明文放在用户机器上（`generated/binding-core.js` 等三段 97,794 B 原样进 exe；jsx 激活后明文落盘），任何拿到安装包的对手只需**把上报改成"没成功"**，这一单就不扣钱，而成品文件已经写在他盘上了。今天没有任何审计能发现这件事（分发审计不落库、`exeSha256` 存了不比对、限流是重启即清零的内存 Map）。**"薄客户端"这条线的首要收益不是防逆向，是止血。**

## 2. 函数归属清单（四路并行清点，主审已抽查）

要搬走的"判断"总量比预想小：

- **replacer（jsx，63 个函数）**：判断类 24 个（`findTranslation:718`、`confusableSkeleton:786`+`findSuggestionCandidate:807`、`requiresPreflightDecision:781`、`normalizeMatchText:519`/`normalizeLinebreakMatchText:531`、`readCSV:600`/`readAllCSVs:684`、`scanPreflightIssues:911`、`freezePreflightManifest:1097`/`preflightAllows:1152`/`verifyPreflightSnapshots:1136`、`deriveOutcome:353`/`finalizeLanguageReport:341`/`computeStatus:407`、`issueDefaults:152`/`issueCodeForType:131`、`processPSD:1197` 里的裁决树部分）。机械类 21、数据类 18。**判断内核约 490 行，只占全文约 24%**；另实测 `1594-1716` 等约 150 行是 0 调用点死码，可直删。
- **binding-core（exe 内明文，43 个函数）**：判断类 21（`compileBindings`、`looseKey:561`、`isNearMatch:581`、`compositeMatchForLayer:353`、`wrapTargetToSourceStructure:1455`、`structuralTargetText:1504`、`computeBindingPlanDigest:239`、`computeLedgerDigest:209`、`deriveObjectId:201`、`sameTextSignature:166` 等）。**全文件 0 处 `Date`/`Math.random`/`require`/`process`** ⇒ 纯确定性，**可原样搬到服务端，不需要重写**（源本来就在 `src/lib/trust-chain/binding-core.ts`，TS 版就在云端树里）。
- **助手 Node 判定层**：`v15-runner.js` 判据点占全文 **31.5%**（判据行区间 19,152 B / 60,733 B）；`prepare-batch-core.js` 判断占 62%（9,282/15,022 B）；`text-diff-core.js` 整件即搬。**要搬的判定层总量约 30 KB。**
- **执行器与扫描器也含判断**（推翻我原来的假设"它们纯机械"）：`Thin_Executor.jsx` 的 `applyTypography:60`（写后读回 0.51pt 容差判 FONT_UNAVAILABLE/FALLBACK_APPLIED 等）、`pickTypographyProfile:157`（源脸名+字号→命中哪组档）、`fail:201`；`Preparation_Scanner.jsx` 的 `typographyDerived:93`（换行三态分类+六桶直方图）、`typographyOf:140`、`scanLayer:200`（隐藏层/空正文不入文字池、智能对象分类、`layer_errors>0`→PARTIAL）。⇒ **搬"判断"不能只搬 replacer，扫描器与执行器里的判据同批。**

**必须留在客户端的（架构边界，别自欺）**：只能在 Photoshop 现场拿到的量——图层 bounds/渲染宽高、字体真实可用性与写后实脸名、UnitValue/自动行距读回异常、`app.open` 后的 `textItem.contents`、`saveAs` 后的落盘 size/exists 复核、`sha256File`、删盘动作、母版指纹。⇒ **切割线精确定义**：客户端只做"测量 + 执行 + 上报事实（digest 与存在性）"，服务端做"判等、配对、风险结论、质量结论、行-费映射、归因"。今天 `v15-runner.js:104` 已经在产出 `actualTextDigest`，而 `execution-batch.ts:1388` 只验它非空——**这条缝最细、最先可动**。

## 4. 刀法（顺序不可换，每刀都要能红）

**P0 先修眼睛与止血闸（1 天，不改产品行为）**
- 分发审计落库 + `exeSha256` 存下来做多包体分歧 + 分发限流从内存 Map 换成现成 DB 桶（`src/lib/server/rate-limit-store.ts:21`）。
- 修 `check-exe-no-plaintext.cjs`：探针按 `__dirname` 解析、探针数为 0 即 exit 1、补 `generated/*.js` 探针（取自构建输入并带对照件 0 命中自证）。
- 结算侧加**一条服务端重算**的最小断言：`objectEvidenceDigest` 必须与服务端按已存期望文本重算的摘要一致，不一致拒收。这条不等架构改完，是今天就能收的口子。
- 判据：假 installId 打一次 distribute，库里出现该行；重启服务后限流仍生效；仓外 cwd 跑那枚红 exe ⇒ rc=1；伪造一份"上报说失败但产物存在"的回执 ⇒ 被拒。

**P1 定义并锁定"测量/判断"边界（1 天）**
- 产出《函数归属清单》正式版（本方案 §2 为初稿，需人工读完那 25 个未分类项后定版），并把"只能在 PS 现场"的量列成受控清单（§2 末）。
- 判据：清单里每个 J 都有指定归宿（服务端／客户端），且客户端侧对 J 的引用数为 0（脚本可测：对 jsx 与 `v15-runner.js` grep 这些函数名，命中即红）。
- 删掉 replacer 里约 150 行 0 调用点死码（顺带缩小可读面）。

**P2 搬裁决核心：`compileBindings` 上服务端（2-3 天，灰度）**
- 现成件复用：TS 源已在 `src/lib/trust-chain/binding-core.ts`；新增服务端接口吃"观测 + 译文 + 决策"，返回绑定计划 + 摘要 + 报价行。客户端改为拿结果执行。
- 判据（必须能红）：把客户端那份 `compileBindings` 换成常量桩（改**源** `binding-core.ts` + `build-local-binding-core.mjs` 重生成产物；直接改 `generated/*.js` 会被 MANIFEST 哈希挡成 503，测不到本判据），端到端必须失败或与服务端权威不一致。
- oracle 反制同批：任何"给判断"的端点若不消耗一次性 challenge（`billing-challenge.ts:136,258,284`）、不经 DB 限流就返回 ⇒ 判为开放预言机，不许收工。
- 合同变更纪律：助手 evidence／服务端报价／结算闸 三层同改 + fixture 更新 + HANDOFF 标【合同变更】（浏览器不 import 该模块，`local-assistant-client.ts:2109` 自陈 ⇒ 三层不是四层）。

**P3 搬质量结论与计费依据（2 天）——这条才是止血**
- 把 `resultUsable`、`deliveryStatus`、逐行 `VERIFIED/FAILED`、`verificationLevel` 的**判定权**收到服务端：客户端只上报 `actualTextDigest`、落盘 size、存在性等**事实**；服务端按自己持有的期望文本重算判等与结论。
- 判据：改客户端上报（把失败说成成功、或把成功说成失败）都**不再改变金额**——金额只由服务端重算结果决定；构造两枚对照件（真成功/真失败）跑通，再构造一枚"谎报"件断言被拒。
- 风险：这条动的是计费口径，属单向门，必须真机点一遍并留灰度白名单。

**P4 搬扫描器与执行器里的判断（2-3 天）**
- `Preparation_Scanner` 的三态分类/入池判据、`Thin_Executor` 的排版档命中与写后判等，全部改为"客户端报读数、服务端出结论"。
- 判据：扫描器与执行器里 J 类函数引用数 0；一单 12 语端到端跑通且结论与搬前逐行一致（对拍，允许差异必须逐条解释）。

**P5 撤明文副本（1-2 天，P2-P4 之后）**
- 撤 `download/local-assistant/package.json:7-11` 的 `pkg.assets: generated/**/*`；`server.js:122-141` 的"读原文算哈希"换成构建期 pin + 运行期比 bytecode 摘要（**pin 不能与被校验物同盘可写**，否则篡改者连核带期望值一起换）。
- 判据：P0 修好的闸对新 exe rc=0 且探针含三段；"含我方源标记的最长连续可读 run"实测降到阈值下（给数字）；真机起得来、跑成一单。
- jsx 侧（原 E3）在此之后：`findTranslation` 等判断已不在 jsx 里，jsx 退化为"读结构+写图层+回证据"的机械壳，**是否再上 jsxbin 就变成可选项而不是必需品**。

## 5. 代价（要拍的口径，不是工程问题）

- 执行必须联网（离线不可用）。
- 图层正文 `sourceText` 要上行给服务端算——**服务端今天已经存着确认表全文**（`prisma/schema.prisma:896 tableJson`），但把"扫描观测正文"上行仍是新出站，须与对外说法同批改（"设计文件不出本机"这句今天是假的，属 LEGAL-1 已登记的假话面）。
- 服务端要多一份算力与一份新接口；按 §3 量级，成本可忽略，但要防被当预言机刷（P2 的一次性凭证 + DB 限流是硬前置）。
- 跨层合同变更（三层同改 + 真机对拍），属高风险改动，不能一边跑线上一边换。

## 6. 做完之后，哪些既有担忧自动降级

E2（撤 assets）在 P2-P4 之后才真正安全；E3（jsxbin）从"必须"降为"可选"；代码签名（工程已写好 `publish-local-assistant.cjs:61-102`，现役 `UnsignedBeta` 只差证书预算）变成运维体面问题而非防泄漏问题；"免 PS 引擎要不要 native 化"回归为性能/成本议题。⇒ **这条线是唯一一处"做一遍就不用每年重做"的投入**，其余都是每年过期的补丁。

## 7. 永远做不到的一半

内存态还原、PS 执行现场观察、以及"看着客户端怎么调服务端"这些防不住，也不该花钱防。做完这条线，剩下的防护只剩两件事：**能被看见**（审计落库、包体分歧）与**能被断**（installId 粒度停发、账号吊销）。工程上能交付的终点是"漏了可归因、可止损、且漏的部分不值钱"，不是"读不到"。

## 8. 待拍与未核实

- 待拍：P0+P1（两天，止血+定界）是否立刻开工；P3 的计费口径改动要不要真机点验（我建议要）；`sourceText` 上行的对外口径怎么改；Rust 引擎那条成本墙要不要单独立项（`bin/tygf-engine.exe` 43,252,736 B、0 处 JS 明文，但品牌串 `photocraft`/`PhotoCraft` 未除净，偏移 35708723/35723686，兼有第三方 fork 合规面）；证书买不买。
- 未核实：replacer 里 25 个"未分类"函数需人工读定版；合成压测≠真稿分布（真语料 66 psb/46 psd 那批可复测）；`.next/static` 内 `compileBindings` 0 命中取自旧构建，当前 HEAD 构建后是否仍为 0 未复扫；PS 是否保留可埋溯源标记的自定义元数据。
