## §0 第一性原理（一句话，可判定）

**这件事本质上要成的是：用户对某门语言指定的排版，要么在交付件里真的成立并且能证明，要么明确不成立并说出来。**

由此推出三条硬判据（后面每一步都受它管）：
1. 任何"设置"若最终没落到 PS 里，界面与回执**不得**呈现为已生效（含"保存成功"这种半步）；
2. 任何"生效"必须留下**读回值**，不能只有"写入没抛错"；
3. 任何本版本 PS 根本做不到的旋钮，**不做成控件**（假控件与假成功同罪）。

## §4 字段合同（envelope 旁路，不进摘要）

```
envelope.typography = {
  schema: 'tygf-typo-v2',
  byLanguage: {
    JA: { face?: string,            // PostScript 脸名；缺省=follow
          tracking?: number|null,   // 1/1000 em
          leading?: { mode:'follow'|'percent'|'fixed', value?: number|null },
          autoKerning?: 'follow'|'METRICS'|'OPTICAL',
          fauxBold?: false, fauxItalic?: false }
  }
}
```
- **不进 `executionManifestDigest`**（摘要只算 manifest，`v15-runner.js:145`），因此**不动四层合同**；但必须配一条锁死断言（V4）。
- 全 follow/空 ⇒ 执行器零写入（零风险路径，也是回滚路径）。
- 执行器写入顺序（探针定的唯一安全序）：`contents` → `face` → `autoKerning` → `leading`（percent 走 `autoLeadingAmount`；fixed 先 `useAutoLeading=false`）→ `tracking` → `faux*`；**每项 try + 读回**。
- 失败码：`FONT_UNAVAILABLE`（本机没这名）、`FONT_FALLBACK_APPLIED`（读回≠所设）、`TYPOGRAPHY_INVALID`、`LEADING_NOT_APPLIED`（关自动后仍读不回）。
