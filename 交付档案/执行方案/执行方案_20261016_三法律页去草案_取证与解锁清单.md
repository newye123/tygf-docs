## 一、为什么不能直接删「草案」

删掉「（草案）」，页面就在对外说三件事：本页已定稿、内容已核实完毕、可以据此主张权利义务。而实际情况是：

1. **母本自己设了闸门。** `docs/隐私政策_草案_20260818.md:16` 末尾写着「定稿前请法律顾问过目」；`docs/第三方处理方清单_20261006.md:5` 写着「标注『待取证』『未核实』的条目补齐前，本页**不得作为定稿对外提供**」。删字不改变这两条。
2. **页内还有自陈未完成的句子。** 隐私页第五节的表注（`src/app/(zh)/privacy/page.tsx:90`）原文是「表中『未核实』与『待定稿』表示取证或法审尚未完成，不表示不存在；**补齐前本页为草案，不作为定稿提供**」。只删标题的「（草案）」而不动这句，页面会自相矛盾。
3. **对抗审查已经裁决过这一条。** `docs/records/20261010_SEO_GEO_v2_对抗审查100轮与调整方案.md:106` **AR-41**：攻击「自陈隐私页仍标注草案」→ 裁决「**采纳（前置未满足，暂不发）**」，修订为「披露定稿后才进入发布流程」。即：不是把字删掉，而是把前置补齐。

所以本项的正确执行路径是 **「补前置」**，不是「改字」。

## 三、本轮新取的硬证据（可复核）

以下全部在本轮现场采集，命令与输出一并留档，符合母本 `第三方处理方清单_20261006.md:33` 的取证纪律（代码端点／部署记录／运维交接三者之一）。

### 3.1 本站服务器 = 腾讯云 CVM，区域 ap-singapore

```
$ sudo dmidecode -s system-manufacturer      → Tencent Cloud
$ sudo dmidecode -s system-product-name      → CVM
$ curl http://metadata.tencentyun.com/latest/meta-data/placement/region  → ap-singapore
$ curl http://metadata.tencentyun.com/latest/meta-data/placement/zone    → ap-singapore-4
$ curl https://ifconfig.me                   → 43.134.175.26
```

**结论**：托管地区＝新加坡（腾讯云 `ap-singapore` 可用区 `ap-singapore-4`）。母本第 1 行原注「『新加坡』为盘上一致断言，但**云商控制台／IP 归属类硬证据未取** ⇒ 法域未核实」——实例元数据接口就是云商侧的权威来源，这条缺口现已补上。

### 3.2 CDN 与安全防护 = Cloudflare（存在性已确认）

```
$ curl -sSI https://tuyigf.com/ | grep -iE "^(server|cf-|via)"
  Server: cloudflare
  cf-cache-status: DYNAMIC
  CF-RAY: a4b71e940d7d7a2d-LAX

$ curl -sS https://tuyigf.com/cdn-cgi/trace
  fl=618f207  h=tuyigf.com  colo=LAX  sliver=050-tier1
  gateway=off  warp=off  rbi=off  tls=TLSv1.3
```

`/cdn-cgi/trace` 是 Cloudflare 专有端点，能返回该格式即等于 Cloudflare 自证在链路上。另有部署键位佐证：`CF_ACCESS_TEAM_DOMAIN=https://silent-surf-9c17.cloudflareaccess.com`（Cloudflare Access 在用）。

**结论**：母本第 4 行的「存在性本身未核实」→ **已确认存在，处理方为 Cloudflare**。托管形态是全球边缘节点（本次观测落 `colo=LAX`）。
