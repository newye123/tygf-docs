## 一、自我否决两条（这是本轮对抗审查的对象＝我自己的提案）

**否决 1：甲方案不可行。** 甲＝"引擎接管前取本机扫描观察件、看 `psVersion` 是否为空"。实测取不到：`execution-manifest.js:29-34` 的 manifest 键集是 `assignments / attempt_id / canonicalization_version / install_id / job_id / locale / output / protocol_version / readiness / runtime / schema_version / source / translation`（加三个可选），**没有 `master_path` 也没有 `scan_id`**（`grep -n "master_path|scan_id|scanId"` 在该文件命中 0）。执行期拿不到定位扫描观察件的键，`psVersion` 这个锚就够不着。另：就绪扫描按随机临时目录落盘（`server.js:5239` 一带的 `readiness_<randomBytes>`），不按 attempt 键存，事后也无法回查"这次执行对应哪次扫描、谁扫的"。⇒ 甲作废。

**否决 2：不加"同原文多层且译文不同就拒"的严守卫。** 我差点实现它，推演后发现它会打死正常路径：引擎扫＋引擎执行时层号是同一套权威 id，"同一段原文出现在两层、各翻成不同译文"是合法需求。在无法证明扫描来源的前提下就拒，等于把唯一受控的 F 段路径（您那台没 PS 的笔记本）也一起堵死，还谎称是安全改进。⇒ 撤回，只保留已跑绿的那条计数守卫（命中层数 **大于** 投喂条数才拒——那种情况数学上必然有层翻不到，不会误伤合法批次）。

## 二、由此得出的硬结论

执行接线的合法性前提，是**扫描自己留下一份按 attempt 可查的来源凭记**。没有它，只有两个坏选项：要么允许跨引擎执行（静默漏翻译风险），要么一律拒（功能死）。所以：

- **C（扫描兜底）必须先做，而且要做两件事**：① 引擎扫描产出与现役 `Preparation_Scanner.jsx` 同构的 `scan-observation.json`；② **同时写一份按 attempt 键定位的来源凭记**（记 `engine`/`psVersion`/`manifestDigest` 之类，供执行期校验）。
- **A（执行接线）在 C 之后**，且必须校验凭记：来源不是引擎 ⇒ 拒执行并提示重新扫描；**不许有"没凭记也放行"的宽松分支**——那正是把静默降级放回来的口子。
- 在 C 落地之前，旗标保持默认关，**A 不预先接线**（预先加配置键＋没人调用的分支＝无法端到端验证的死代码）。
