## 0. 一句话结论

**对，现在只读了“被自动选中的那一张表”，没有把文件夹里的每张表都读出来罗列。**

当前实际是“先按文件名猜表 → 每份稿各读一张 → 只显示被选中的结果”。所以：

- 没被选中的表只有文件名，没有语言列、行数、sheet、读表状态；
- 同一张表被 12 份稿共用时会重复读 12 次；
- 页面底部的“语言覆盖矩阵”是**按稿**的覆盖数，不是 mock 里的“每格来自哪张表”的**译文来源矩阵**；
- 用户看不到“这批到底有哪些表、每张表有什么、哪张没读、哪张读失败”。

这份方案把第 1 步改成 mock 的“设计稿 + 译文来源”结构，并补上 mock 没画出的**译文表清单**：

1. **先建表册**：文件夹里每张表都登记、都读表头（sheet / 语言列 / 行数 / 读状态），逐张罗列。
2. **再建绑定**：设计稿 → 表 / sheet / 交付物 / 语言；自动配对只是建议，人可以改。
3. **最后出矩阵**：行=设计稿，列=语言，每格写“来自哪张表、覆盖多少、缺什么”；点格开详情。
4. **只有被绑定的表才读全文**（默认推荐）；如果 Owner 要“每张表都读全文”，单列为全量模式，另算性能与授权预算。

## 1. 现在差在哪（不是一句 UI 问题）

### G1 表只有“文件名”，没有“表的内容”

`FolderTableEntry` 只有 `path / relPath / ext / dir`（`src/lib/workbench/local-assistant-client.ts:1091`）；`FolderScanResult.tables` 只是列表，带 `tableTotal / tablesTruncated`（`:1103`），**没有 languages / sheets / rows / readState**。

因此当前界面能说“有 7 张表”，但不能说“德语在哪张表、哪张表有 A+、哪张表 756 行、哪张表读失败”。

### G2 读表缓存按“稿”存，不按“表”存

- `parsedTables` 是 `Record<draftKey, ParsedCsv>`（`workbench-view.tsx:265`、`:479`）；
- `stageTableStates` 是按 `draftKey` 存（`:2027-2033`）；
- `stageTableSourceRef` 也是按稿记来源（`:2033`）。

同一张表服务 12 份稿，就会被读 12 次；表清单没有“表级状态”，也没法一次读完全部表。

### G3 自动配对发生在读表之前

`buildAttributionPlan` 只用文件名里的 SKU/交付物做候选（`src/lib/workbench/sku-attribution.ts:301-331`）；读表是选中之后才做（`stage-table-loader.ts:51`）。所以：

- 不知道表里有没有目标语言，就先配了；
- 不知道多 sheet 里哪张 sheet 有哪门语言；
- 不知道表读失败，直到选中后才发现；
- 看不到“没被选中的表”的内容。

### G4 现有矩阵不是“译文来源矩阵”

`attribution-stage.tsx:1024-1092` 的矩阵是按 SKU 行 × 语言列显示**覆盖数量**；它不显示“这一格取自哪张表 / 哪个 sheet / 是否专表 / 是否补充表”。mock 的 `译文来源` 矩阵（`:401-421`）每格是 `src`（来源）、`pc`（覆盖）、`rel`（关系），点格开详情（`:423-452`）。

### G5 表选择器没有语言/行数/状态

`TablePickerDialog` 现在只能从 `scan.tables` 列路径/相对路径和 usedBy；用户选表前看不到“这张表有没有德语、几行、读没读成功”。这就是“没有罗列”的直接体感。

### G6 多 sheet 只按一份稿的交付物选一张

`parseTableBytes` 的注释明确：多 sheet 必须按交付物选 sheet，未选中的 sheet 写 warnings（`src/lib/workbench/table-file.ts:33-38`）。但当前读表缓存是“一稿一份 ParsedCsv”，同一张含「主图 / A+」两个 sheet 的表，服务两种稿时会被当成两份各自读，表级视角丢失。

### G7 每张表一次授权，读全表会放大 10 秒超时

`readPreparationTable` 每次调用都 `fetchTicket()` 再打 `/v1.5/preparation/read-table`（`local-assistant-client.ts:1331`）；助手验票是 10 秒单跳上限（`download/local-assistant/server.js:2654`）。12 张表就是 12 次验票，任何一次卡 10 秒就会出现“等待工作台授权响应超时”。**这是本方案最大的工程风险，不是 UI 风险。**

### G8 没有“全表读取”的进度、重试、取消、上限说明

当前只有逐稿 `reading/ready/error`（`stage-table-loader.ts:15-24`）；没有表级队列、总进度、取消、失败重试、表数量上限、读表头/读全文两档。

### G9 页面结构不是 mock

mock 是「统计 → 左设计稿列表 + 右译文来源矩阵 → 点格抽屉」；当前是「文件夹栏 → 扫描条 → 要你处理的队列 → 语言覆盖矩阵」。两者不是同一套信息架构。

### 2.2 表清单每行必须有什么

| 字段 | 说明 | 不显示的后果 |
|---|---|---|
| 表名 + 相对路径 | 同名表靠路径区分 | 选错表 |
| sheet 列表 | 主图 / A+ / 其他；每 sheet 的语言、行数 | 多 sheet 丢失 |
| 语言列 | 该表实际有哪些语言（不是猜的） | 缺语言到执行才发现 |
| 行数 | 非空译文行数 | 空表/半张表看不见 |
| 读状态 | 未读 / 读表头 / 读全文 / 失败 / 被截断 | 以为都读了 |
| 被谁用 | 绑定到哪些稿/交付物；几份 | 孤儿表/共用表看不见 |
| 问题 | 重复副本、同 SKU 冲突、缺列、读失败 | 静默选错 |
| 操作 | 读全文、重试、用于当前稿、打开详情 | 无路可走 |

### 2.3 矩阵每格必须有什么

- 来源表短名（主表 / 专表 / 合表第 N 片 / 补充表）；
- 覆盖状态（✓ / % / 缺语言 / 未读 / 读失败 / 不适用）；
- 点击打开抽屉：稿、语言、来源表、sheet、覆盖、缺什么、表里语言列、交付物名、可换表/补读；
- 「只看有问题的」筛选；
- 缺语言必须是红格，不能只显示 `·`。

### 2.4 保留的现有能力（不许删）

- 文件夹入口、原生选文件夹、只读预扫描、扫描全队列、停止、重扫；
- 每稿手动「选择译文表…」/「换一张表…」；
- 同名稿合并/保留两份；
- 一表一稿去重；
- 12 份稿上限与逐条列 dropped；
- 语言覆盖矩阵（可升级为来源矩阵，但不能丢“覆盖数量”这个信息）；
- 逐稿手动导入旧界面。

## 3. 核心数据设计：先表册，后绑定，再矩阵

### 3.1 新模块 `table-inventory.ts`（纯函数，不碰 React）

```ts
export type TableReadStage =
  | 'listed'       // 文件夹扫描只拿到路径
  | 'surveying'    // 正在读表头/语言/sheet/行数
  | 'surveyed'     // 表头已读，可罗列、可配对
  | 'reading'      // 正在读全文
  | 'ready'        // 全文已读，可用于执行
  | 'error'        // 读失败
  | 'truncated'    // 表太大/太多，明确未读

export interface TableSheetInfo {
  name: string
  deliverable: DeliverableKind
  languages: string[]
  rows: number | null
  warnings: string[]
}

export interface TableRecord {
  id: string                 // 规范化绝对路径的稳定 id
  path: string
  relPath: string
  ext: string
  size: number | null
  fingerprint: string | null // 重复副本判定，读完才有
  stage: TableReadStage
  sheets: TableSheetInfo[]
  languages: string[]        // 所有 sheet 语言并集
  rows: number
  error?: { code: string; message: string }
  usedBy: string[]           // 绑定到的稿 masterPath
  readAt: string | null
}

export interface DraftTableBinding {
  draftPath: string
  tableId: string
  sheetName: string | null
  deliverable: DeliverableKind
  source: 'auto' | 'manual' | 'memory'
  languages: string[]
}

export interface SourceMatrixCell {
  draftPath: string
  language: string
  tableId: string | null
  sheetName: string | null
  sourceLabel: string
  coverage: number | null
  status: 'ready' | 'wait' | 'missing-language' | 'unread' | 'error' | 'na' | 'supplement'
  issues: string[]
}
```

**关键**：`TableRecord` 按表存，不按稿存；`DraftTableBinding` 才是稿的视角。这样一张表服务 12 份稿只读一次，表清单和矩阵共用同一份事实。

### 3.2 读表的两档（必须区分，不许混叫“已读”）

| 档位 | 做什么 | 结果 | 用途 |
|---|---|---|---|
| 表头调查 `survey` | 读每个表的 sheet 名、语言列、行数、空表/损坏 | TableRecord.stage=`surveyed` | 表清单、自动配对、缺语言预判 |
| 全文读取 `full` | 读完整行，按交付物/sheet 解析 | stage=`ready` + ParsedCsv | 覆盖率、第 2 步译文检查、执行 |

推荐默认：**所有表都做 survey；只有被绑定的表做 full**。如果 Owner 要求“每张表都读全文”，增加显式“全量读全文”按钮，单独算 5 MB/张、并发 2、超时与内存预算；不要默认把所有表全文塞进内存。

### 3.3 表的身份与重复

- `id` 用 `resolveTableReadPath` 的真实路径规范化（根内、拒软链；服务端已有边界，`server.js:5283`）；
- 读完取 `fingerprint`（SHA-256，浏览器 `crypto.subtle` 或助手返回），同内容不同路径标“重复副本”；
- 同 SKU + 同交付物多张表标“冲突”，不静默选第一张；
- `tablesTruncated` 为真时表清单必须写“只读前 N 张/扫描只列了前 N 张”，不能把截断说成全量。

### 3.4 读表调度

- 并发 2（沿用 `runStageTableBatch` 的预算，`stage-table-loader.ts:68`）；
- 每张表独立状态、独立重试；一张失败不拖整屏；
- 文件夹切换/重扫/停止时用 epoch/token 丢弃旧结果（现有 `stageFolderRequestRef` 同款）；
- 读表顺序：先被自动建议的、再未用的、最后异常/大表；表清单仍按名称/状态可排序；
- 每张表 5 MB 上限（现有 `MAX_TABLE_BYTES`，`table-file.ts:11`），超过标 `truncated` 并给路径，不静默；
- 记忆/重复：同一 `id` 只读一次；同内容副本只读一次全文，另一个标重复。

### 3.5 授权预算（本方案 P0）

**现状**：每张表一次 `readPreparationTable` → 一次 `fetchTicket` → 一次 10 秒验票。12 张表就是 12 次，测试站并发部署时已经实测 `VERIFY_TIMEOUT`（本机助手日志 21:57–22:01，10s，TLS/REQUEST_TIMEOUT）。

**推荐（需要助手 3.7.25）**：
- 新增 `/v1.5/preparation/survey-tables`：一次请求带 `root + tablePaths[]`，助手在本地读取所有表头/结构，返回 `sheets/languages/rows/warnings`，**不返回 base64 全量字节**；
- 一次 `preparation_scan` 票、一次验票；5 MB/张、根内、拒软链、只读边界复用 `read-table-path`；
- 全文仍由 `read-table` 按绑定表读，次数从“表数”降到“绑定表数”；
- 若要图三现代文件夹框，也在 3.7.25 一起做（IFileOpenDialog FOS_PICKFOLDERS）；但这需要 Owner 单独批准，不在本方案默认范围。

**过渡（不发助手新版）**：
- 用现有 `readPreparationTable` 逐张读表头，并发 2；最多 12 张；每张失败可重试；
- 明确标注“当前授权逐表进行，表多时会慢/可能超时”，不假装一次全读；
- 不把“全表读取”做成无上限；先以 12 张为硬上限，超过时只 survey 前 12 张并列出剩余未读。

### 3.6 `parsedTables` 迁移（不能破坏第 2 步）

第 2 步和现有执行链仍读 `parsedTables[draftKey]`（`workbench-view.tsx:479`、`:577`、`:622`）。迁移用**适配层**，不直接改所有消费者：

```ts
// 新事实
tableParsed: Record<tableId, ParsedCsv>       // 按表+sheet/交付物缓存
bindings: Record<draftPath, DraftTableBinding>

// 旧接口适配（第 2 步继续用）
parsedTables[draftKey] = tableParsed[binding.tableId]
```

- 读全文只写 `tableParsed`；`parsedTables` 变成派生视图；
- 换表/移除/跳过只改 binding，不再删“稿级表对象”；
- `stageTableStates` 改为 `tableStates[tableId]`，`stageReadStatesByPath` 由 binding 派生；
- 表级状态是权威，稿级状态是投影；禁止再出现“同一张表读 12 次、每份稿状态不同”。

## 4. 交互状态机

```text
folder empty
  → pick folder
  → scanning folder
      → list designs/tables
      → survey tables（逐张，边读边出表清单）
          → surveying（进度 x/y）
          → partial（有失败/截断，可重试/继续）
          → surveyed（所有可读表都有表头）
  → auto-match（建议，不直接执行）
      → bindings ready / needs human / missing table / conflict
  → read full（只读绑定表，可重试）
      → bindings ready
  → matrix ready
  → gate next（扫描完成 + 每稿有表 + 绑定表全文 read + 无未处理冲突）
```

- **表清单在 survey 阶段就开始出现**，不等全部读完；每张表有独立状态；
- 点击“下一步”只检查“本批每份稿有没有可用表”，不因未使用的 orphan 表未读而拦死；
- 表读失败时：该表行红、相关稿红、可重试/换表；其它稿可继续；
- 文件夹切换/停止：取消未完成队列，epoch 丢弃，旧表册清空；
- 用户关闭标签：全部内存态丢失，重新导入（现有边界，不改）。

## 5. 对抗式审查（最坏情况逐条打）

| # | 最坏情况 | 会怎么坏 | 本方案怎么挡 |
|---|---|---|---|
| A1 | 用现有 `readPreparationTable` 逐张读 12 张 | 12 次验票，任一 10s 超时 → 表册不完整；用户以为“全读” | 推荐 3.7.25 批量 survey 端点；过渡方案硬上限 12 张 + 单表重试 + 明示“逐表授权”，不宣称一次全读 |
| A2 | 12 张表 × 5 MB，base64 传回浏览器 | 60 MB 内存 + 解析卡 UI | survey 只返回表头/元数据，不传全量；全文只读绑定表；并发 2；必要时 Web Worker |
| A3 | 同一张表被 12 份稿共用 | 读 12 次、内存 12 份、状态不一致 | 按表 id 缓存；binding 引用；旧 `parsedTables` 只做投影 |
| A4 | 一张表有「主图 / A+」两个 sheet | 只读一个 sheet，另一份稿拿到错行 | survey 列全部 sheet；full 按交付物/sheet 读；未选 sheet 进 warnings，不静默丢 |
| A5 | 文件名认不出 SKU | 自动配对为空，表册仍应可读 | survey 与配对解耦；所有表照常罗列；未知 SKU 不静默去重；人手选表 |
| A6 | 表很多/扫描被截断 | 只显示前 N 张却像全量 | `tablesTruncated` 逐条列出未读；表清单写“只列了前 N 张”；不假装 |
| A7 | 表损坏/空表/超过 5 MB | 一张失败拖整屏或静默跳过 | 表级 `error/truncated`；行内红、可重试、可换表；其它表继续 |
| A8 | 读表途中换文件夹/重扫 | 旧结果写进新批次 | epoch/token；旧结果丢弃；表册清空；请求取消 |
| A9 | 用户只想要一张表，但被强制全读 | 等很久/浪费授权 | survey 先出清单；绑定表优先读；未用表可“读全文”按需；不强制全文 |
| A10 | 自动配对选错表 | 执行错译文 | 自动只建议；矩阵格显示来源；手动优先；同 SKU/交付物冲突显式；不静默 |
| A11 | 第 2 步/执行链拿不到表 | 迁移破坏下游 | `parsedTables` 适配层；先保旧接口；contract tests 覆盖执行链；不直接替换 |
| A12 | 表内容含敏感数据 | 读全表/上传风险 | 全程本地助手读；不写日志/不上传；survey 只回元数据；根内/拒软链/5 MB 边界 |
| A13 | 用户把“表头已读”当“全文已读” | 覆盖率/执行判断错 | 两档状态分开命名；表清单和矩阵都显示“表头/全文”；gate 只认 full |
| A14 | 12 表并发触发助手限流 | 部分 429/超时 | 并发 2；逐表退避/重试；429 单独提示；不自动重放一次性票 |
| A15 | mock 的每语言专表/补充表直接照搬 | 当前执行的“一稿一表”合同被破坏 | 本方案 Phase 1 只做一稿一表 + 来源矩阵；每语言覆盖/补充表列 Phase 3，走合同变更 |

**结论**：如果只做“UI 加一个表列表”，一定失败；必须先做表级事实（registry）、再读表头、再做矩阵。否则表清单和矩阵会各说各话。

## 8. 验收

### 功能

1. 含 12 份稿、7 张表的文件夹：表清单显示 **7/7**（若扫描截断则明确列出未列数量），每张有 sheet、语言、行数、状态、usedBy。
2. 同一张表被多稿共用：只读一次（表级 `readAt`/`full` 状态一致），多稿绑定引用它。
3. 多 sheet 表：主图/A+ 两种稿各自拿到正确 sheet，未选 sheet 有 warnings。
4. 缺语言/空表/损坏/超 5 MB：行内可见错误/截断，可重试/换表；其它稿不被拖垮。
5. 矩阵：每格有来源表短名 + 覆盖/缺语言/未读；点格抽屉有表/ sheet / 语言 / 问题；「只看有问题的」有效。
6. 手动选表/换表仍优先于自动；同 SKU + 同交付物一表一稿仍守住；未知 SKU 不去重。
7. 换文件夹/重扫/停止：旧表册与旧读表结果不写进新批次。
8. 第 2 步仍能拿到 `parsedTables[draftKey]`，执行合同不变。
