## 02 不变式（这五条是回归的判据）

1. **单稿档既有节点逐字不变**。证据：`git diff` 里单稿分支只多出 `) : (` 和 `)}` 两行，分支内部 **0 行改动**（`workbench-view.tsx:2747-2789`）。

3. **扫描队列只有一个 owner**：`design-file-card.tsx` 内部；状态带只做跳转。
4. **不可逆边界写在用户看得见的地方**：确认框里「开始之后不能撤销」「没有 PSD 备份」是硬文案，不许删。
5. **确认之前零副作用**：D1 只是 `setScopeConfirm`，不调任何 API、不冻结、不写盘；`run` 仍是原来那条函数。

## 07 残留风险（如实）

1. **没有渲染级回归**：本轮的门是静态源码断言，不是 DOM 快照。若有人把 ②③ 的 JSX 改成等价但不同的结构，断言可能放过。**建议下一步补最小渲染 harness**（`@testing-library/react` + jsdom），只跑 4 个断言：单稿档 chip 文案、多稿档 chip 文案、状态带两档文本、确认框按钮。
2. **没有浏览器实测**：dev server 需要共享开发库与登录态，本轮未启动（避免碰共享库）。所以「看起来对不对」只有源码与文案层面的证据。
3. **批量确认框没有预估金额**：每稿行数要各自报价，前端拿不到统一数，文案如实写「按受理时报价并冻结」，不给假数字。
4. **未提交**：工作树里混着其他会话的改动，本轮不做提交（提交会把别人的半成品一起带上）。
