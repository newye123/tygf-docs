01项目与仓库结构（最容易搞错）

项目：把 PSD 设计稿里的文字翻译成多语言并回写 PSD。形态是「浏览器工作台 + 本地 Windows 助手（跑 Photoshop）+ 云端批次链（计费/回执/信任链）」。核心链路 readiness → attempt → ticket → /v1.5/execute。

F:\工具开发\图译工坊内测版\ ← 容器根，分支 master，只放治理/记忆/交付档案 ├── AI_MEMORY/ ← 记忆系统 ├── 交付档案/ ← 所有交付件 ├── 总控/ ← 治理条文 ├── scripts/ ← 中台脚本（飞书发送/台账投影/对账闸） └── worktrees/ ├── develop/ ← 分支 develop，大部分开发在这里 ├── production/ ← 分支 main，生产代码在这里 ├── v1.5-trust-chain/ ← 分支 codex/v1.5-trust-chain └── …（另有 40+ 历史 worktree，多为 detached，勿动）
三条铁律：① 查业务代码必须进 worktree，容器根没有业务代码；② git worktree list 只列出一个，其余是独立 clone 或未注册的树，别据此判断「没有其他工作树」；③ 不同 worktree 是不同分支，同名文件内容可能完全不同。

05红线（违反即停）

  1. 不得静默降级——没跑就是没跑，不许把未执行的标成 PASS
  2. 不得从 develop 直建生产
  3. 结论必须有 file:line 证据；不确定标「待确认」，不许编
  4. 禁止无出处的否定式断言：说「我们没有 X」必须给 grep 原式 + 真实退出码，否则写「未核实」
  5. 跨文件引用写 路径:行号，禁止大段抄录
  6. 只改授权目录和文件，先核对 Git 现场
  7. 禁止 git reset --hard / checkout -- . / clean -fd / force push
  8. 密钥只放环境变量，禁止明文进文档/提交
  9. 不动 archives/、backups/、既有方案文档，除非明确要求
部署、翻闸、开 flag、删分支、删文件 = Owner 的决定。AI 只查、只建议、只列风险，不替他拍板，更不先斩后奏。支付 flag 必须保持 false。

06已知的坑（踩过三次以上）

坑说明
字节数 ≠ 字符数中文 md 的 14,011 B = 7,603 字符。判断卡片大小先确认单位
计数 0 先怀疑探针&& 链中前序 grep 无命中会短路后续命令，静默不执行 ⇒ 看起来像「0 命中」
四本 ISSUES.md 撞号容器根/develop/production/v1.5-trust-chain 各一本，引用必须写「哪本:行号」
MSYS 路径 node 不认mktemp -d 返回 /tmp/...，传给 node 后 existsSync 为假 ⇒ 静默空跑。须 cygpath -w
node spawn 子进程被拦node 脚本调 lark-cli 必失败（EBUSY/EINVAL），Bash 工具直接执行成功 ⇒ 「mjs 纯变换 + bash 编排」
助手版本纪律助手端改动需发版 + 用户在测试机重装，开发机通过不算通过
真机验收不可替代开发机 SSD 通过 ≠ 真机通过，需 Windows / Photoshop 真机验证
多窗口并行串基线曾发生部署事故。动手前先 git status / git log 对账
部署探针会自动部署每 30 分钟检查，条件满足即自动部署测试站——改 develop 前先想清楚
