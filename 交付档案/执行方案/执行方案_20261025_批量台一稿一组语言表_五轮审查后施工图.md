## 4. 数据模型（精确到签名）

```ts
// 新增 src/lib/workbench/table-grouping.ts —— 纯函数、无 IO、无 React
export interface DraftTableGroup {
  draftKey: string
  draftPath: string
  sku: string | null
  deliverable: DeliverableKind
  tablePaths: string[]        // 组内表，按 relPath 稳定排序
  excludedPaths: string[]     // 用户排除项，按归一后的表身份存（重扫不复活）
  rejects: GroupReject[]      // 没进组的表：逐张给原因，绝不静默
  evidence: GroupEvidence
}

export interface GroupEvidence {
  skuMatched: number          // 文件名 SKU 对上的张数
  languageCount: number       // 合并后**实际**语言列数（份数口径唯一来源）
  languagesUnique: boolean
  structureMajority: boolean
}

export type GroupRejectReason =
  | 'NO_SKU_IN_FILENAME'   // 5857-ES.xlsx / Copy of … / 表格-终稿-…
  | 'SKU_MISMATCH'
  | 'LANGUAGE_UNKNOWN'     // 文件名给不出语言
  | 'LANGUAGE_DUPLICATE'   // 同语言两张
  | 'STRUCTURE_OUTLIER'    // 原文集与多数不同
  | 'LANGUAGE_LIMIT'       // 第 13 门
```

```ts
// workbench-view.tsx：单一写者 + 派生只读
const [tableGroups, setTableGroups] = useState<Record<string, DraftTableGroup>>({})
// 兼容层：旧代码 10 处读 choices 一行不改，P1 可独立上线
const choices = useMemo(
  () => Object.fromEntries(Object.entries(tableGroups).map(([k, g]) => [k, g.tablePaths[0] ?? ''])),
  [tableGroups],
)
```

```ts
// 新增 src/lib/workbench/group-merge.ts
export interface GroupMergeResult {
  parsed: ParsedCsv          // 写进 parsedTables[draftKey]，下游零改动
  digest: string             // 表身份 + 原文 + 译文 的 sha256
  sourceTableIds: string[]
  rejected: Array<{ tableId: string; reason: GroupRejectReason; detail: string }>
  languageCount: number
}
```

**纪律**：`tableGroups` 是唯一写者，`choices` 只读派生。这样 P1 不会把 10 个读 `choices` 的地方一起改坏（探针五已证：传数组会当场崩，属白屏级）。

## 5. 组准入 5 条（安全边界，一条不能少）

| # | 判据 | 不满足时 | 为什么必须有 |
|---|---|---|---|
| **①** | 文件名 SKU ＝ 本稿 SKU（2026-10-26 定：**进 P0 硬门槛**） | 拒绝入组，进人工 | **唯一能挡 F14 的门**（同原文、别稿译文在引擎里完全合法） |
| **②** | 文件名能给出语言 | 拒绝入组，转「读表头再判」（2026-10-26 定：**默认就是先读再判**，不等人点） | 实测 4/12 真实命名给不出语言 |
| **③** | 组内语言不重复（2026-10-26 定：**让人选，不按目录优先**） | 标冲突，让人选一张 | 今天会静默先到优先（`merge-tables.ts:167`） |
| **④** | 原文集与多数一致 | **只提示、不自动排除**，逐张列出 | 结构检查只能拦"原文不同"，拦不了"原文相同"（F14） |
| **⑤** | 合并后语言列 ≤ 12 | 明确话术「本批最多 12 门」 | 13 门时抛 `CSV_TOO_MANY_LANG_COLUMNS`，话术要能看懂 |

> ①+② 的代价是两次字符串判断；收益是把「自动全选」从"赌文件名干净"变成"文件名不干净就转人工"。

## 6. 状态机 ＋ 失败窗口矩阵（AGENTS.md 十二问逐条答）

**状态转换**

```
listed ──读表头──▶ readReady | readError
listed/readReady ──归组(5 条准入)──▶ groupReady | rejects(逐张)
groupReady ──合并──▶ merged | mergeError(可排除单表)
merged ──覆盖率──▶ 实证 | 存疑 | 不符
(merged, evidence) ──报价──▶ quoted ──confirm──▶ confirmed ──▶ 逐语言 attempt ──▶ receipt
任何「组/排除项/表内容」变化 ⇒ digest 变 ⇒ quoted 作废，回到 merged
```

| 时刻 | 崩溃/刷新后留下什么 | 恢复路径 | 会不会产生第二份业务事实 |
|---|---|---|---|
| 读表第 k/12 轮 | 表头只在内存 | 重跑读表（**只读、幂等**） | 不会 |
| 合并后、报价前 | 合并结果在内存，绑定在 localStorage | 重读 12 轮 + 重算（确定性纯函数） | 不会 |
| 报价成功后改表/排除 | 报价单与 digest 不匹配 | 既有 digest 比对拦 confirm（`billing-challenge.ts:153` 同类先例） | 不会（拦下，不新建） |
| 双击「开始生成」 | — | 既有 `single-flight.ts` 单飞 | 不会 |
| 重扫文件夹 | 排除项按 `normalizeTableId` 存 | **必须先补 `..` 归一**，否则同一张表两种 id → 排除项静默复活 | 不会，但会重复计费范围 |
| 只读了 3 轮就点下一步 | 组里 132 张 `listed` | 允许进（组已定），合并时只并已读的，其余进 `rejects:LANGUAGE_UNKNOWN` | 不会，但份数要按实际列算 |

**不落库的决定**：合并结果**不持久化**，只持久化「组绑定 + 排除项」。理由：v3 已定「存绑定不存内容」；表内容会变，缓存内容会造假。代价是刷新后重读 12 轮（读是只读的，可接受）。

## 7. 口径统一（F16：一套判据）

现状：`merge-tables` 只认 `normalizeText` 相等；`coverage.ts` 三档（strict / whitespace / **substring**）。同一批数据一个 100% 一个 2/3。

**改法（最小）**

- 抽 `matchKey(text)`：`normalizeText` ＋ 归一 NBSP(`\u00A0`)、全角空格(`\u3000`)；合并与覆盖率**都走它**；
- 覆盖率三档保留，但 **`substring` 不计入"可交付"**，只作提示（否则 "100% Cotton" 会替 "100% Cotton Fabric" 顶包）；
- 判定链：`matchKey` 相等 → 可交付；子串命中 → 存疑；都不中 → 不符。

## 8. 份数口径（F17）

```
份数 = Σ_每稿 group.evidence.languageCount      // 合并后的实际语言列
```

实测缺一门时合并不报错、只出 11 列；按 12 门算，12 稿会虚高 12 份。这个数字直接进报价，不能虚。
