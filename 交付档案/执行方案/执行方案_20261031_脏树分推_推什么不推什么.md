## 二、推荐推送的 5 批

### P0 封存现场（不推业务代码，但必须第一步做）

- 动作：在脏树之外另建一条本地分支（例如 `wip/salvage-20261031`），把 107 项做一次**本地提交**（不推送），作为可回退的封存点；同时把整棵工作树原样备份一份。
- 理由：不封存就 merge/rebase，107 项有丢的风险；封存后一切从干净树重建，脏树只当"素材库"。
- **这一步是提交动作，需要你点头。**

### P1 术语收口（低风险，修的是线上半截）

- 文件：`src/lib/workbench/terms.ts`、`src/lib/workbench/workbench-machine.ts`、`tests/unit/terms.test.ts`。
- 为什么先推：远端已经是半截状态——屏头/导轨叫「审核确认」，按钮和 `terms.ts:29` 还叫「设计稿校对」，同一个环节两个名字，用户现在就能看到。
- 三个文件必须同批：只推实现不推测试、或只推测试不推实现，单测都会红。
- 验证：`npx vitest run tests/unit/terms.test.ts` + 工作台状态机对应 smoke。

### P2 表格与模板修复（中风险，修的是真实会拒单的坑）

- 文件：`src/lib/workbench/translation-template.ts`（记录编号白名单）、`src/lib/workbench/csv.ts`（**合到 20MB**，不是保留脏副本的 2MB）、`src/lib/workbench/stage-table-loader.ts`（缓存按交付物分键）、`src/lib/workbench/batch-error-policy.ts`（新增 `PHOTOSHOP_PRIVILEGE_MISMATCH`）、`src/lib/workbench/funnel-event-contract.ts`，以及 `table-allocation`、`translation-template-provenance`、`row-translation-grid`、`multi-draft-stage-queue` 等单测。
- 为什么推：模板里「记录编号」不合规时助手会**整批拒**（ISSUES #195 形态），现在用户导出的还是旧模板，一直在踩；另外 CSV 通道 2MB、XLSX 通道 20MB 的错配也是这一批修。
- `csv.ts` 与 `stage-table-loader.ts` 必须 hunk 合并（远端改过）。
- 验证：`npm run test:table-grouping`、`npm run test:contracts`。

### P3 本地预览（可选，风险最低）

- 文件：`src/lib/workbench/local-workbench-preview.ts`（未跟踪）＋ `account-gate.tsx` ＋ `activation-gate.tsx` ＋ `tests/unit/local-workbench-preview.test.ts`。
- 只在 `NODE_ENV=development` + 开关为 1 + localhost 三条同时满足时生效，线上无效。
- 建议：可以推；也可以先不推，等你需要本地看界面时再进。**不加没人要的东西**——你若不需要，就留在本地。

## 六、执行顺序、提交信息与回滚

1. 每批一个独立提交，提交信息三件套：做了什么 / 怎么验证（真实命令＋rc）/ 怎么回滚。
2. 每批验证基线：`npx tsc --noEmit`、`npm run lint`、`npm run test:contracts`；涉及计费合同再加 `npm run test:batch-row-contract`、`npm run test:trust-chain`。
3. 推送走三段轨：`git push origin <分支>` → 从 GitHub 取码部署测试站 → 你验收后再谈生产。生产站当前停在 `80eb4263`，不在本方案范围内。
4. 回滚：每批独立提交，`git revert <sha>` 即可；P4 整批回滚要连安装包与 manifest 一起退。
