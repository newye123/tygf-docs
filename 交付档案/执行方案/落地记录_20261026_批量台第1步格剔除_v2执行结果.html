界面上多了什么

为什么写在这一处

剔除只写进这一稿要做哪几门那份语言集合（当前稿 targetLanguages，别的稿它那一份会话快照）。逐稿执行本来就靠 activateDraft 换会话（workbench-view.tsx:3699/:3757），执行语言从 selectedLanguages 取（execute-step.tsx:714→:1046）。写这一处＝七处自动跟随；写别处＝再造一套会打架的账。
份数也只有一处算：|ready 槽位 ∩ 这一稿要做哪几门|（slot-scope.ts:9），四个显示位全改读它。
没碰：计费公式、payload 结构、服务端、助手侧、支付 flag。test:batch-row-contract 与 test:trust-chain（56 秒）当回归跑绿。

执行中我自己撞上的三件事

① 前向引用把 React Compiler 撞红：函数放在它引用的 memo 之前，npm run lint 报 5 条 preserve-manual-memoization（整个组件放弃优化）。用脚本把 71 行整块搬到 memo 之后（搬运前后字节数相同），lint 归零。
② 两个快照副本共享同一个对象：我原先把同一份 updated 既塞 ref 又塞 state，编译器直接报「may be modified later」——这正是审查警告的「两套账」换了形态。改成各写一份独立对象，并把这条钉进门里（契约 7 现要求两处都写 { ...updated }）。
③ 负控咬出我自己的两条假绿：门原来判「函数名前缀」，把函数改名照样命中＝N-β 假绿。改成判挂载点接线与按钮落点，再加一条交给 tsc（引用悬空静态门看不见、类型系统看得见）。现在五条全红。
