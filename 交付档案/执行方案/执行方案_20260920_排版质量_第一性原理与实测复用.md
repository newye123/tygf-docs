## 1. 复用结论（GitHub 调研 + 我自己在真机真件上实测 + 两路对抗审查）

**没有一件能当依赖直接装。** 三条硬约束决定的：
1. `scripts/build-local-binding-core.mjs:20-24,105-121` 是**裸 tsc**，没有打包器、不解析 `node_modules`；`binding-core.ts:1349` 自己写着"零依赖约束禁止 import，必须内联"；exe 至今**从未打包过任何第三方模块**（`server.js:13-20` 只用 Node 内置，`pkg.assets` 只有 `generated/**`）⇒ 所有"pkg-safe"论断在**这条构建路径上等于未验证**。
2. 摘要面：`bindingPlanDigest` **不含译文文本**（`binding-core.ts:239-267`），动译文文本动的是 `assignmentDigest`/`translationDigest`（`readiness.js:17-33` ⇄ `evidence-foundation.ts:205`），炸点在 **ticket/verify、execution-manifest、receipt**（409 `BATCH_RECEIPT_TRANSLATION_MISMATCH`）⇒ 报价不受影响，但**已冻结批次会变成"能报价、执行不了"**。
3. 许可证：`hyphen` 的 `id` 模式是 **GPL-2.0**（必须丢），ru/it/th 是 **LPPL**（要随包附声明）；`tex-linebreak` 与 **`fontkit` 的 npm tarball 里都没有 LICENSE 文件**（需从上游仓库取原件 + 建 `NOTICE`/`copies/`）。

| 候选 | 我的实测/审查结果 | 裁决 |
|---|---|---|
| `foliojs/linebreak`（UAX#14，MIT） | 跑通：DE 53 字符→3 空格断点+1 机会点；**ZH 15 / JA 23 个字级机会点（禁则生效）**；KO 混合；**TH 26 字符仅 1 个机会点 ⇒ 泰文实际断不出** | **思想复用，代码内联**：只取 UAX#14 的 class/pairs 表快照（钉死 Unicode 版本），放在**非摘要**的度量/预检模块；泰文另找词切分（无词典就是不可行，不许猜） |
| `ytiurin/hyphen`（ISC + TeX 模式） | 实测可用：de-1901/de-1996/fr/es/it/pt/ru/th/id/zh；**vi / ko / ms / ja 直接 MISSING** | **只内联 DE FR ES IT PT**（且要按文件里的 `hyphenatedWordSize/preHyphen/postHyphen` 生效）；**丢 id（GPL）**；对 vi/ko/ms **明说"无连字符能力"**，不得静默 |

| `Agamnentzar/ag-psd` | 286 MB PSB **48 ms**、RSS 611 MB（= 1.9× 文件大小，**超红队给的 1.6× 判据**）；PSB 官方 README 写"不支持"但代码可读 version 2；**坑：CR→LF 归一、uniform 样式被折进 `text.style`，多 run 层必须回 `styleRuns`**（我的普查 v1 就因为这条把 KO/TH 漏成 9 层） | **KEEP（助手侧预检 + 我们自己的取证工具）**，禁进写回链路与摘要边界；解析前必须过"≤10 s 且 RSS≤1.6×"的门，不满足退回 PS DOM 扫描并标注降级 |
| comic-translate / BallonsTranslator / manga-image-translator | 字号阶梯缩小（正是我们要避免的静默降级）；后两者 GPL-3 | **只借形状**（逐行预算、无解显式抛错）；**不引代码不引数据** |
