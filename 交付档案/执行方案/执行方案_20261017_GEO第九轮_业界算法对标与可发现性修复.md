### 2.1 对我自己这份方案的对抗审查（六个会失败的口子）

1. **dateModified 造时间戳的口子**：`sitemap.ts:4` 注释已明写「不写 lastModified：无真实内容时间时不伪造（Google 会忽略不实的 lastmod）」。量表要 `dateModified`（`p2.freshness` 3/6，「0 declare dateModified」）⇒ **只允许写真实来源**（文案后台发布记录的 `updatedAt`，或该页内容的 git 提交日期）；拿不到就继续不写，**宁可丢这 3 分**。
2. **「改了也白改」的口子**：`site-settings.ts:255-271` 的 `deepMerge` 只在双方都是非数组对象时逐键递归，其余 `return override`（合并点 `:324-328`）⇒ **数组型文案字段只要生产库存着，改代码单源＝没改**（#163 未决）。所以本轮凡**需要改文案**的项目（前 200 字、问句标题文本、数据带出处）**全部排在 #163 之后**，本轮只做不需改文案的结构性动作。
3. **加链接会不会动主流程**：只在**页脚／导航**增真链接，首屏层级与 CTA 一字不动 ⇒ 属展示面，不升 L2；符合 Product Drift Guard「不以优化为名删改用户可见能力」。
4. **边缘缓存是我不能碰的**：站点在 Cloudflare 后、HTML 响应带 `Vary: rsc, next-router-state-tree…` 且 `Cache-Control: no-store`。no-store 很可能是为防后台改字后陈旧。**我不擅自改缓存语义**；只把 Cloudflare 侧可安全实施的形状交 Owner，并给回退。
5. **本机单点观测不能定案**：`/terms` 超时、`ai.txt` 探到 `http=000`（TLS 失败，**不是 404**）、`robots.txt` 首拍 8.0 s／次拍 1.0 s——全是我一台机器一条网络；且本机 `curl` 需 `--ssl-no-revoke` 才能过部分站点。**定案证据必须是服务器侧 nginx 日志**（按 UA × 路径 × 状态 × 时长）。⇒ 凡「慢／不可达」结论在本方案里一律带「本机单点、待服务器侧复采」。
6. **把演示数字当成产品统计的失真口子**：首页那张「执行报告」示意卡的 `12 个 PSD／48 个目标位置／回读一致率 93.8%`（`siteContent.ts:252-278`）在可见文本里**没有「示意」标注**（该块 `kicker/title/desc` 均无；`示意界面` 那句在另一个分区 `:701`）。抽取器与 LLM **分不清这是样例数据还是实测结论**（既有边界注释 `:669` 把「示意卡内部演示数据」列为不改写范围）。⇒ 在做「数据带出处」之前**必须先给演示数字打上文本层标识**，否则我们等于自己往引擎里喂一个假统计。这一条与论文 `:245`「哪怕是假设的数字也加」是同一个坑的反面。
