06业界怎么做（调研与取舍）

来源结论对本项目的含义
GitHub《Renaming a repository》改名后旧 URL 的 git 操作全部重定向；若在旧名下新建仓库，重定向立即失效本次故障不是改名；"URL 指向哪"只能实测
GitHub《Repository limits》单文件硬限 100 MB，推荐不超过 1 MBTASK_LOG.md 已 2.26 MB，超推荐线两倍
git 官方 git-bundle(1)明确支持全量与增量备份，用于离线传输用它做第二副本是正路
GitLab 官方备份文档备份时为每个仓库生成 git bundle 再打包大厂同款，不是土办法
monorepo / polyrepo 通用权衡同仓便于一次拿全，分仓隔离权限与体积代码仓与记账仓已分开，这个结构是对的，不该为备份而合并
取舍保留两仓结构不动——合并会把 Owner 决策、内部事故记录暴露给所有代码仓协作者；1.2 MB 记账内容也不值得挤进代码仓的历史。
