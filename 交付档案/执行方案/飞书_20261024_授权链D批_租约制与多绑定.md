# 授权链「一劳永逸」方案：按业界最深的打法审完，租约制＋多绑定设计已出

**结论**：按你的要求，我把 GitHub 和业界「对抗式深挖」的方法先学来（攻击树、事前验尸、写者和审查者分权、风险分级），再用这套打法把我们的授权链审到了叶子级。结构解方案已出：**配对一次拿 72 小时签名租约、本机核验零云端往返、后台自动续租、多账号并存不互顶**。约 4-6 人日，等你拍板。

**先说业界怎么把审查做深（我们借了四件）**：

1. **攻击树**（英国国家网安中心、空客都在用）：不问"有没有问题"，而是把"对手想干成什么"拆成一棵树，每片叶子配一条对策。我画了两棵——「让没权限的人用上」和「让有权限的人被堵死」——第二棵里今天撞的每一个坑（超时、互顶、卡半路、报错怼脸）全在里面，D 批让四片叶子直接消失。
2. **事前验尸**：假设三个月后这次改造失败了，倒推十种死因（离线硬停太早掐断飞机用户、太晚被人白嫖、令牌被偷、迁移丢绑定、绕过计费……），每种死因在设计里预先挡好。
3. **写者不审自己**：有实证研究表明 AI 审自己的代码时恰恰在最错的地方最宽容——所以"干活的和验收的必须是两拨"我们已成惯例（Flash 干活我复跑），这次写进方案成文。
4. **风险分级**：授权和支付属最高审查级——这批改动全部配阻塞式测试门，不走"仅供参考"模式。

**方案核心一句话**：现在的设计是"每做一件事都走一趟云端验票"，慢网络一抖全线瘫；改成"配对一次、拿一张 72 小时的签名租约、平时全在本机核验、租约在后台悄悄续"。这是微软 Office、各类专业桌面软件的标准形态（离线宽限行业常态 14-30 天，我们取最严的 72 小时）。**换账号、多浏览器多账号，从此互不打架**——助手同时记最多 3 个账号的租约，来谁的票据用谁的。

**安全不降反升**：令牌每次续租就轮换，旧的被再用＝判定被盗、全家吊销（Auth0 等的标准做法）；存储从"混淆文件"升级到 Windows 系统级保险库（DPAPI）；离线到期是"真停"不做静默降级——铁律不破；计费和信任链一行不碰。

**节奏**：A/B 批（止血止痛）立即做 → C 批 3.7.25（超时/重试/换绑一步化＋批量读表头＋现代文件夹框，一次发版）→ D 批 3.7.26（这次的结构解，隔一周观察后再上）。C 批的超时补丁在 D 批上线后大部分自然退役，但过渡期必须它兜底，不白做。
