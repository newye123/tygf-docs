## 0. 一句话结论

**五个问题分三批修：A 批纯前端（不用发助手版，立即修）＋ B 批随下轮 develop 部署的服务端小修＋ C 批助手 3.7.25（需你批一次发版，把验票超时、组件同步重试、回调双轨、换绑一步化四件事一次带上）。**「顶掉另一个账号」在现机制里就是「重新配对」，配对链的最后一步在这台电脑上已两次失败，C 批不修它，换绑随时卡半路。

## 2. 对抗式审查（每条修法的最坏情况 → 挡法）

| # | 级 | 最坏情况 | 挡法 |
|---|---|---|---|
| R1 | 🔴 | **A 批把错误码「翻译得太好」把排障信息丢了** | 人话与码并存：主行讲人话＋出路，括号/详情保留原码；error-messages.ts 单源表扩键，不改形制不变量（preflight 已有该门） |
| R2 | 🔴 | **A2「重试」真做 pair → 半成功状态重复配对出脏数据** | 云端 pair 幂等（同 machine 重复兑换不+count，schema `AssistantCodeRedemption @@unique([assistantCodeId,machineId])`）；本地四步流水线每步幂等（save→readback 天然校验）；重复 pair 安全 |
| R3 | 🔴 | **C 批放宽超时 → UI 卡更久、用户以为死了** | 分级：首跳 10s 不变（快网无感），重试跳放宽至 22s＋总预算 30s；等待 UI 必须可取消＋显示进度（第几次/共几次） |
| R4 | 🔴 | **C 批组件同步后台重试 → 没 ready 就放行执行＝静默降级（违铁律）** | 重试只解决「到达 ready」，不降门槛：执行/扫描前的 `componentReady` 硬闸原样保留；后台重试退避（30s×∞ 上限 10 次），ready 前所有需组件的操作明确报「组件同步中」 |
| R5 | 🟠 | **直接改 `.tygf_session` 的 serverUrl → 写坏会话文件，助手起不来** | 不直接改混淆文件。C3 的正解是代码层统一「云端调用一律按签发 origin（requestCloudBase）」，serverUrl 仅作兜底显示；若确需改配置，经助手自带设置路径并先备份 |
| R6 | 🟠 | **换绑一步化 → 别人在你浏览器上一点就把你的助手顶走** | pairingTicket 由登录态签发＝天然身份确认；换绑前 UI 明示「顶掉后 X 账号在本机失去能力」；换绑成功回执里写明旧绑定失效（bindingGeneration 已支持） |
| R7 | 🟠 | **A 批新增常驻入口 → 又一个塞满卡头的按钮** | 入口形态＝卡头助手状态点（已有「本地助手已连接/未连接」那个位置），不加新按钮；banner 仍可关 |
| R8 | 🟡 | **三个批次互相等待 → 又拖成都不发** | A/B 批不等 C 批：A 随 develop 下一轮走，C 批 3.7.25 与「批量读表头端点＋现代文件夹框」（另一方案待批项）**合并一次发版**，一次审批办三件事 |
| R9 | 🟡 | **服务端 verify 单跳 3.7–6.4s 本身慢** | B 批查 verify 路由的慢点（DB 往返/外部调用），能服务端消的消；消不掉的靠 C 批分级超时兜住 |
| R10 | 🟡 | **修完没有验收尺** | 每个 C 项带实测验收：C2＝慢通道连续 20 次验票 0 超时；C5＝kill 网络中途配对→恢复后自动补齐到 ready；C3＝grep 服务端调用无 localhost 路径；C1＝换账号登录出现人话提示且两个出路可点 |

## 3. 修法清单（三批）

### A 批：纯前端（不发助手版，develop 下一轮带上）

- **A1** 卡头助手状态点常驻化：banner 关闭后，「本地助手状态」仍是入口（点开＝横幅同款面板：状态/重新连接/去换绑）
- **A2** 「重试」按钮接真 `pairAssistantRequest`（幂等已证，R2）：能修就修，不能修把文案改「重新检查状态」，不再骗人
- **A3** 错误码人话映射（error-messages.ts 扩键）：
  - `ASSISTANT_INSTALL_BINDING_MISMATCH` →「当前登录的账号和这台电脑上助手绑定的账号不是同一个。两条路：①用绑定账号登录；②到账号中心解绑后用现在这个账号重新连接（会把助手顶到这个账号）」＋保留原码
  - `PAIR_BOUND_COMPONENT_SYNC_FAILED` →「已绑定成功一半（云端与授权都已落），组件还在同步。稍后刷新即可，**不要解绑**」
  - `VERIFY_TIMEOUT` →「与服务器核对授权超时（这条网络较慢）。稍后再试；反复出现请反馈」
- 文案走 t()＋dict-en；不删原码不吞错

### B 批：服务端小修（develop 下一轮带上）

- **B1** verify 路由性能核查（单跳 3.7–6.4s 拆解：DB 查询/绑定查证/网络出口），可消则消
- **B2** `ticket/verify` 的 MISMATCH 响应附带结构化上下文（两侧激活的掩码预览），供 A3 的人话提示显示「绑定的是 35***@163.com 那台」

### C 批：助手 3.7.25（**需 Owner 批一次发版**，与「批量读表头端点＋现代文件夹框」并车）

- **C1'** 验票分级超时：首跳 10s／重试跳 22s／总预算 30s／重试 2 次；等待可取消
- **C2'** 组件同步幂等后台重试（退避），`componentReady` 硬闸不降（R4）
- **C3'** 云端调用统一按签发 origin（`requestCloudBase`），`serverUrl` 降为兜底显示；消灭 localhost 双轨
- **C4'** 换绑一步化：登录目标账号点「连接助手」即完成顶掉，回执写明旧账号失效（R6 安全件）

## 5. 决策点（一个）

**D-3.7.25：批不批这次助手发版？**一次带上：授权链四修（C1'–C4'）＋批量读表头端点＋现代文件夹框。批 → 三件事并一车，约 1.5–2 人日＋发版流程；不批 → A/B 批照做（体验与提示先好起来），慢通道超时与换绑卡半路的问题继续在。

## 6. 不做

不改 MISMATCH 的判定语义（该拒仍拒）；不直接改写 `.tygf_session`；不做任何静默降级；不动生产站与支付链；A/B 批不碰助手二进制。
