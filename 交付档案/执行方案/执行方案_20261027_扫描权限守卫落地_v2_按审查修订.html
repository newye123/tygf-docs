三、边界

  • 不提交、不推送、不出包、不部署；测试站与生产不碰；支付 flag 不动。
  • 不改 installer.iss（本机无 ISCC.exe；这条是事故源头，但属安装器路径，永远需人审＋构建机）。
  • 不碰同树别手在飞改动；不整树 git add。
  • 不重启、不杀现役助手（PID 46636／36708 属 Owner 正在用的实例，只读取证）。

四、回退法

  1. 执行前出 patch 存证：git diff -- 我这 5 个文件 > tmp/privilege-guard-20261027.patch
  2. 回退 = git apply -R 该 patch；不用 git checkout --（共享树上会连带吞别手在同文件的改动，审查 P-01 已证同树正在被写）。

五、交付后交给 Owner 的三选一

  • A 改动留脏区不提交：零风险，但可能被别手提交吞掉或随他人部署意外上线。
  • B 我这 5 个文件单独提交（先逐 hunk 证明只含我的改动）：我的活不丢，测试站下次部署会带上（不部署不生效）。
  • C 连安装器根治一起排期（构建机＋签名＋三段轨）：别人不再踩，但要出包授权。

推荐：先 B，C 另立单。
