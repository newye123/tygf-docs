# 执行方案 · 用户字体排版定制（试验版）· 2026-10-14

> 目标：网页端为**每种语言**提供一套私人定制排版（选字体 + 字距 + 行距 + 粗细），在脚本写入前由本地助手读取用户定制并应用到 PSD 写回。
> 定位：**试验版**（内测可开、生产闸不碰、支付 flag 不碰）；创收入口留 P2。
> 依据：《审查报告_20261014_用户字体排版定制_五路对抗式审查》（同目录）；基线 `worktrees/develop@756978c`。
> 方案性质：待 Owner 拍板后执行；P0 可即刻进行（零代码改动、零仓库落盘）。

---

## 0. 一句话路径

```
P0 spike（半天，手跑 jsx，零改动）→ P1 试验版（一次助手下班车 + 网页面板 + envelope 旁路）→ P2 契约化/学习库/创收（另立项）
```

**核心工程决策**：用户排版定制全程走 **envelope 旁路字段**（`typography`），**不进 `executionManifestDigest`**——试验期不触碰四层合同，风险锁在本机；P2 再决定是否冻结进计划合同。

## 1. P0 · spike：把四个 PS 语义钉死（0.5 天，零代码）

**做法**：一次性手跑脚本（PS「文件→脚本→浏览」或 ExtendScript 里直接跑；**不落仓库、不进版本纪律**），在真实 working copy 或副本上回答：

| # | 问题 | 记录项 |
|---|---|---|
| S1 | `app.fonts` 名称格式（显示名 vs PostScript 名）、数量、样本 30 个 | 名称样本表；与 `textItem.font` 接受值对齐规则 |
| S2 | `textItem.font / tracking / leading / fauxBold` 可写性 + **设置顺序**（先字体后 contents vs 先 contents 后字体）| 逐字段：可写/只读/无效；顺序 A/B 各测 3 层 |
| S3 | 读回归一：设 `font=X` → 读回 == X？（显示名/PS 名归一规则）| 归一函数草案；不等时的观测值 |
| S4 | 缺字体：设本机没有的字体名 → 抛错 / 静默改回 / UB | 三态判定 + 对应失败码设计 |
| S5 | 多脚本混排层（日文+拉丁）设字体的行为 | 主 run 是否被改；PS 是否另加 fallback run |
| S6 | PS 版本谱：至少 PS 2021 与产品声明下限；`#141` 教训（ES3 严格性）核对 | 版本—结论表 |

**产出**：一页台账（PS 版本/结论/意外），直接决定 P1 的字段白名单与失败码。**S2/S3 不过，P1 缩水为"仅字体选择"或暂停**。

**并行小项**：浏览器预览可行性抽查——本机装日文字体后用 CSS `font-family` 渲染预览的正确性（含 Adobe Fonts 在浏览器不可见的说明文案）。

## 3. 风险与止损

| # | 风险 | 止损 |
|---|---|---|
| R1 | `tracking/leading` 在目标 PS 版本不可写或行为怪异 | P0 S2 定音；缩水为"仅字体选择"，字距/行距顺延 |
| R2 | 混排层字体语义歧义（用户设置的字体只对主 run 生效） | P0 S5 定死语义；报告如实标注"多脚本层以 PS 兜底为准" |
| R3 | 预览与 PS 实际不一致（Adobe Fonts 等） | 预览标注"+PS 内可见"；不作预览=终态的承诺 |
| R4 | envelope 旁路字段被旧执行器/校验意外拒绝 | P1 首测即验"旧执行器读新 envelope"；不行则退"manifest 版本号升位、字段可选"备选 |
| R5 | 用户需更新助手才可用（版本 bump 摩擦） | 内测范围可控；不做强制推送；文案说明 |
| R6 | 摘要误动（有人把 typography 塞进 manifest） | smoke 锁定：envelope 旁路存在时 `executionManifestDigest` 不变 |
| R7 | 字体清单隐私（机器画像） | 试验版只留本机；上云需新同意位（P2） |
| R8 | 违反"不得静默降级" | 读回判据强制；`#66` 同族防线（ISSUES:641-648） |
