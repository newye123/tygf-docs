执行方案：排版面板改漂浮可拖浮窗

2026-10-23 · 对 Owner「字小 / 太高 / 直接做成漂浮的、可移动」三问的执行方案 · 附可点模拟 HTML
结论：把右侧通天抽屉改成内容自适应高度的漂浮面板——标题栏可拖动、位置记在浏览器里下次还在、方向键也能移动、背景不再被灰罩锁死；字号整体抬一档。不引入任何新依赖，手写约 80 行拖拽逻辑（Excalidraw/tldraw 同款做法）。

① 两个抱怨的病根（对着代码量的）

字小

面板正文共 39 处使用 9–11px 字号（typography-panel.tsx 实测 grep 计数）。处置：分档抬——11→12、10→11、9px 徽章→10。

太高太空

容器是 fixed inset-y-0 right-0——通到屏幕上下两端；空态时里面只有一句话。处置：高度改跟内容走，超 72vh 才内部滚动。

② 调研：四种做法（含依赖实测，不是抄宣传页）

方案实测证据判定
手写 pointer-events 拖拽
（标题栏监听 + setPointerCapture，拖动期间只改 transform，松手落 state）		Excalidraw / tldraw 同款思路；React 19 原生支持推荐零依赖、零 peer 风险、无障碍自己说了算
react-rnd 10.5.3（拖+缩二合一）实测其 lib/index.js:451 已向 react-draggable 传 nodeRef——React 19 移除了 findDOMNode，旧链会炸，新版靠这个续命；2026-03 仍维护不选能用但重：带缩放，本单用不上
react-draggable 4.7.2（只拖）实测源码 chunk-ACOTSM7X.mjs:497 自陈「React 19 移除 findDOMNode，必须传 nodeRef」不选只剩拖一半，白添依赖
@floating-ui/react是定位引擎，不管拖拽不对症

社区共通要点（多库交叉印证）：拖柄只在标题栏；位置持久化且恢复时夹回视口（防换分辨率跑到屏幕外）；非模态浮窗 role="dialog" aria-modal="false"；Esc 关闭限定「焦点在面板内」；标题栏 touch-action:none；dockview 专为浮窗做了 WAI-ARIA 状态。

③ 对抗式审查：方案会在哪 15 个口子上失败

审查对象＝我自己刚提的方案（报给您之前先砍自己）。每条给处置。

#口子处置
F1拖动每帧 setState → 整面板（几十个输入框）重渲染，拖起来卡拖动期间 ref 直改样式，松手才 commit 一次（模拟 HTML 已按此实现）
F2关闭按钮 X 也会触发拖柄，点 X 变拖走拖柄起点排除 data-no-drag 元素
F3记住的位置在换分辨率/缩放后跑到屏幕外恢复夹回视口；window resize 监听实时夹回
F4非模态后 Esc 仍挂 document：在工作台输入框按 Esc 会误关面板Esc 仅当焦点在面板内生效
F5删灰罩/inert/滚动锁/焦点陷阱后，旧测试三处必红aria-modal→false；「背景 inert」两条断言改写成反向负控；Esc 用例改焦点门控
F6手机上标题栏拖动被页面滚动抢走标题栏 touch-action:none；pointer events 覆盖触摸
F7拖动时文字被选中拖动期间标题栏 user-select:none
F8默认位置写死 left/top 丢失右侧锚点默认仍落右上（与旧抽屉同视觉锚点）
F912px 字号在 24px 高字格里溢出行高 1.4≈16.8px，安全；出包前真浏览器复核
F1039 处字号一刀切，微徽章会破分档抬：正文 11→12、10→11，9px 徽章只抬到 10
F11浮窗打开时悬浮球仍隐藏是否合理保留：面板默认落右上、悬浮球也在右侧，重叠点不到——刻意取舍
F12缺守卫，防止有人改回「全高抽屉＋inert」smoke 新增三条：面板源码不得再出现 inert / aria-modal="true" / inset-y-0（负控塞回去必须红）
F13位置存储坏 JSON / 未来版本独立小键 tygf.typographyPanelPos.v1；解析失败回默认；不与字体偏好共用结构
F14非模态还抢焦点（旧模态义务）会把打字中的人拽走打开时不聚焦面板，焦点留在触发按钮，aria-expanded 照旧
F15关闭后焦点归还掉进不可聚焦背景（10-20 实测过的坑）焦点归还保留：surface 永不 inert，onClosed 回调照旧由 workbench 还给触发器
否证记录：调研前我判断「react-rnd 在 React 19 装不上（peer 停 ≤18）」——实测 peer 是 >=16.3.0 无上限，这个否证不成立；真坑在下游 findDOMNode，且 10.5.3 已修。结论仍不选它，理由从「装不上」改为「用不上还重」。

④ 执行步骤（S1–S8，一个提交）

S1 模态→非模态

删灰罩、surface inert、滚动锁、焦点陷阱；aria-modal=false；Esc 加焦点门控。

S2 拖动

标题栏 pointerdown→setPointerCapture；拖动期间 ref 直改样式；up 落 state；touch-action:none；data-no-drag 排除 X。

S3 位置持久化

tygf.typographyPanelPos.v1；恢复夹回视口；resize 监听夹回。

S4 键盘

标题栏可聚焦；←↑→↓ 移 8px、Shift 加速 32px；Esc 焦点门控。

S5 尺寸与字号

高度跟内容走、上限 min(72vh,640px) 内部滚动；宽恒 min(360px,92vw)；字号分档抬。

S6 workbench-view

预期零改动（悬浮球门控、三处灰度开关、aria-expanded 不动）；只跑回归。

S7 测试与守卫

改三条旧断言＋新增：持久化往返、data-no-drag、方向键移动；smoke 加 F12 三条防回潮。

S8 验证闸

tsc / lint / vitest / 两条 smoke；dev 起来真浏览器拖一遍（含窄屏与夹回）。

不做（明说边界）：不做缩放（您没要，宽度恒 360）；不做多面板；不改入口与灰度逻辑。

⑤ 您可以这样验收

  • 打开排版面板：不再通天通地，高度跟内容走，字明显变大；
  • 按住标题栏拖到任意位置，刷新页面位置还在；
  • 面板开着时，后面工作台能正常点击滚动（没有灰罩）；
  • Tab 进标题栏按方向键面板会动；焦点不在面板里按 Esc 不误关；
  • tsc / lint / vitest 全绿，两条 smoke 断言只增不减。
