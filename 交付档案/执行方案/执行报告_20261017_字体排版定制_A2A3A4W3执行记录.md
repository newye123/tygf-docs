## 0. 本质上要成什么（一句话判据）

用户在面板上设的每一个排版值，**要么在 Photoshop 里真的变成那个样子，要么明确告诉他"这条没生效、为什么"**——不许静默换脸、不许静默不生效、不许静默忽略。

可复跑判据：真稿跑完后读执行结果里的逐字段留痕（所设 / 读回 / 码）；**任一字段"所设≠读回"而结果里没有对应码 ⇒ 本方案未成立**。

## 1. 对抗式审查：这一轮砍掉/改形的五处（都是实测，不是推）

**① "typography 走 envelope 旁路"原来是含糊的说法，现在有了准确形状，而且比我原先假设的更硬。**
执行清单的键集是**精确校验**的：`assertExactKeys(manifest, [...])`（[execution-manifest.js:28](../../worktrees/develop/download/local-assistant/execution-manifest.js#L28)），多一个键抛 `$:FIELDS_INVALID`；`computeExecutionManifestDigest` 自己就先跑这道校验（[:181](../../worktrees/develop/download/local-assistant/execution-manifest.js#L181)）。
⇒ 实测后果不是"静默改口径"，而是**带排版键的清单连摘要都算不出来、派发当场死**。旁路落在 `execution-envelope.json` 顶层与 `manifest` 同级（[v15-runner.js:190-203](../../worktrees/develop/download/local-assistant/v15-runner.js#L190)），四层合同一字未动。

**② "按语言一份 profile"在执行侧解析不出来——已改形。**
语种码只在 `manifest.locale`（单语链）与各 attempt；旁路字段拿不到"语言→值"映射。改成**每个 attempt 携带一份已定语言的 profile**，助手侧零路由，也少了"表里没这个语言"这类新失败态。

**③ composer / kind / noBreak 锁死。**
切合成器改变折行位置，而行数与"已替换 N/N"判据建立在自插硬换行上；点转段落后软换行不落 `0x0D`（实测零换行符却是 5 行）；`noBreak=true` 实测把图层包围盒压成 **0×0**（文字整层消失且不抛错）。这三条都在执行器里禁止，并有形状断言钉住（NC-A4f 验证过它有牙）。

**④ 未知键从"忽略"改成"当场拒"。**
拼错的 `trackng` 若被静默忽略，用户以为设了、实际没设——与 #157「假保存」同族。

**⑤ 这一轮砍到我自己两处：真机一跑就现形。**
- 脸名读回我写的是 `item.font.name`——PS 22 里 `textItem.font` 读回来**就是字符串**，`.name` 是 `undefined`。后果：**每一次成功写回都会被误报成"换脸了"**。真机 P1 抓到。
- 行距读回我用 `String(item.leading)`，PS 给的是 `"30 pt"`，`Number("30 pt")` 是 **NaN**，而 `NaN > 0.51` 恒 false——**"没吃进"和"吃进了"读起来一模一样**，这条断言是假的。真机 P1 抓到。
两处都已改并按数值读回，且各配一道负控（NC-A4b / NC-A4c）。

另外证实：**PS 22 没有原生 JSON**（`typeof JSON = 'undefined'`，`JSON.parse` 抛"引用错误: JSON 未定义"）。生产链的结果序列化靠助手 wrapper 注入的 polyfill（[server.js:935-991](../../worktrees/develop/download/local-assistant/server.js#L935)）。新增的 `typographyIssues` 是嵌套数组，我把那段 polyfill **原样抽出来**在真机上序列化、回 node 侧 parse 比对，确认逐字段同形（探针 `probeL_serializer.jsx` → `SER.json`）。
