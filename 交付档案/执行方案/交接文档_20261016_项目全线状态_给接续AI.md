## 1. 项目一句话

**图译工坊（tygf）**：把 PSD 设计稿里的文字翻译成多语言并回写 PSD 的工具。形态是「浏览器工作台 + 本地 Windows 助手（跑 Photoshop）+ 云端批次链（计费/回执/信任链）」。

## 2. 仓库结构（**最容易搞错的地方，先看这里**）

工作区 `F:\工具开发\图译工坊内测版` 是 **容器仓库 + 多 worktree**：

```
F:\工具开发\图译工坊内测版\        ← 容器根，分支 master，只放治理/记忆/交付档案
├── AI_MEMORY/                     ← 记忆系统（见 §4）
├── 交付档案/                       ← 所有交付件（审查报告/执行方案/执行报告/…）
├── 总控/                           ← 治理条文（官制、待投递指令、待复验队列）
├── scripts/                       ← 中台脚本（飞书发送、台账投影、对账闸）
└── worktrees/                     ← 各条线的独立工作树
    ├── develop/                   ← 分支 develop，**大部分开发在这里**
    ├── production/                ← 分支 main，**生产代码在这里**
    ├── v1.5-trust-chain/          ← 分支 codex/v1.5-trust-chain（PhotoCraft/探针线）
    └── …（另有 40+ 历史 worktree，多为 detached，勿动）
```

**三条铁律**：
1. **查业务代码必须进 worktree**，容器根没有业务代码（`容器根` 只有治理文件）。
2. **`git worktree list` 只列出一个**（容器根本身）——其余是**独立 clone 或未注册的树**，别据此判断「没有其他工作树」。
3. **不同 worktree 是不同分支**，同一个文件名在不同树里内容可能完全不同。

## 6. 红线（违反即停）

1. **不得静默降级**——没跑就是没跑，不许把未执行的标成 PASS
2. **不得从 develop 直建生产**
3. **结论必须有 `file:line` 证据**；不确定标「待确认」，**不许编**
4. **禁止无出处的否定式断言**：说「我们没有 X」必须给 grep 原式 + 真实退出码，否则写成「未核实」
5. **跨文件引用写 `路径:行号`**，禁止大段抄录原文
6. **只改当前任务授权的目录和文件**，先核对 Git 现场
7. 禁止 `git reset --hard` / `git checkout -- .` / `git clean -fd` / force push
8. **密钥只放环境变量**，禁止明文进文档/提交
9. **不动 `archives/`、`backups/`、既有方案文档**，除非明确要求

## 7. 已知的坑（踩过三次以上）

| 坑 | 说明 |
|---|---|
| **字节数 ≠ 字符数** | 中文 md 的 14,011 B = 7,603 字符。判断卡片大小先确认是字节还是字符 |
| **计数 0 先怀疑探针** | `&&` 链中前序 grep 无命中会**短路后续命令**，静默不执行 ⇒ 看起来像「0 命中」 |
| **四本 ISSUES.md 并存且撞号** | 容器根 / develop / production / v1.5-trust-chain 各一本，`#137` 在不同账里是不同问题。**引用必须写 `哪本:行号`** |
| **git bash 的 MSYS 路径 node 不认** | `mktemp -d` 返回 `/tmp/...`，传给 node 后 `existsSync` 为假 ⇒ 静默空跑。跨 bash→node 传路径必须 `cygpath -w` |
| **node 进程内 spawn 子进程被拦** | node 脚本调 `lark-cli` 必失败（EBUSY/EINVAL），而 Bash 工具直接执行成功 ⇒ 要「mjs 纯变换 + bash 编排」 |
| **助手版本纪律** | 助手端（`download/local-assistant/`）改动需**发版 + 用户在测试机重装**，开发机通过不算通过 |
| **真机验收不可替代** | 开发机 SSD 通过 ≠ 真机通过，需 Windows / Photoshop 真机验证 |
| **多窗口并行容易串基线** | 曾发生部署事故。动手前先 `git status` / `git log` 对账 |
| **部署探针会自动部署** | 计划任务 `TYGF-Deploy-Probe` 每 30 分钟检查，条件满足即自动部署测试站——**改 develop 前先想清楚** |
