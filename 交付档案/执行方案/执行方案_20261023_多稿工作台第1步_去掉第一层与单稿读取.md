## 0. 结论

这次不动“自动归属内核”，只改**入口与读取出口**：

1. 删掉批量页的第一层多选卡；进「准备素材」直接是第二层。
2. 第二层的入口做成单稿工作台那张卡的样子：**卡头与单稿共用**（「准备素材」+ 右上「排版定制」），卡内路径输入 +「选择文件夹…」+「读取文件夹」+“只读预扫描”。
3. 文件夹读取收到父层统一管理，不再靠被隐藏的第一层组件——否则进度和错误会留在隐藏层里，用户看不到。
4. 每份稿补一个「选择译文表…」出口。这是单稿“人选表”的逻辑，也是内核自己在缺表时承诺的出口（`sku-attribution.ts:328` 原文“或手动选一张表”），现在界面没做。
5. 单稿的「选择文件…」**保留原来的 Windows 原生文件框**（Owner 2026-10-23 18:xx 明确要这种，能直接选文件）；居中改为把原生框的 owner 放到**应用窗口中心**，不再跟着按钮跑右下角。**不发助手 3.7.25。**
6. 批量入口恢复 Windows 原生文件夹框（图四的 FolderBrowserDialog），**选的是文件夹本身**。图三的 OpenFileDialog 只能选 PSD/PSB 文件，不能当文件夹选择器；上一版“选文件再取父目录”已撤回。要做到“直接选文件夹 + 图三现代外观”，需助手 3.7.25 的 IFileOpenDialog(FOS_PICKFOLDERS)，本轮不擅自发。

## 1. 对抗式审查发现

### G1 第一层与第二层重复，而且状态藏在隐藏组件里

- 第二层只在已有 `folderSnapshot` 时渲染（`workbench-view.tsx:4224`）；没有文件夹时落回第一层多选卡（`:4273`）。
- 第一层的文件夹读取状态（`folderScanning`/`folderError`）在 `DesignFileCard` 内部，父层只拿到最后的 `onFolderSnapshot`。
- 如果只是把第一层 `hidden` 掉，读取进度和错误会留在隐藏组件里；用户点“读取文件夹”后会以为卡死。
- **处置**：文件夹读取改到父层 `loadStageFolder(path)`，统一 loading/error；第一层不再可见，隐藏组件只留 PSD 扫描队列与经典界面。

### G2 单稿文件夹/文件入口的现状

- 单稿卡在 `design-file-card.tsx:1469-1525`：路径输入 +「选择文件…」+「扫描」+“只读预扫描”。
- 批量页第一层是另一套多选卡，读完后才换成第二层，确实多一步。
- **处置**：新的第二层空态直接复用单稿卡的视觉与操作顺序；标题写“选择设计稿文件夹 · 只读预扫描”。

### G3 Windows 文件框偏右下的根因

- 单稿「选择文件…」调用助手 `/v1.5/select-file`；助手用 PowerShell `OpenFileDialog`，owner 定位在按钮锚点（`picker-dialogs.cjs:65-99`），所以出现在右下。
- 改这个位置必须发助手 3.7.25 并重装；项目对助手行为变更还有 runtime identity/安装包纪律。
- **处置**：单稿继续用原生 `selectDesignFileDirect`；传给助手的 anchor 从“按钮坐标”改成“应用窗口中心”（`window.screenX + outerWidth/2`）。助手按 anchor 放 owner，原生框再以 owner 为中心，因此不需要发助手 3.7.25。若 Windows 仍按自己的记忆位置弹，才需要 3.7.25 的 `StartPosition=CenterScreen`。

### G4 12 份稿全部“认不出 SKU”，界面没有手动出口

- 截图里的文件名同时有 `0202` 和 `5660` 两个 4 位数；SKU 规则只认**唯一** 4 位，多个候选返回空（`sku-attribution.ts:71-87`）。
- 内核在缺表分支写的是“请把 SKU 写进文件名（如「5857」），**或手动选一张表**”（`:328`），但第二层缺表时只有「重新扫描文件夹 / 这稿先不做」（`attribution-stage.tsx:722-733`）。
- **处置**：每份稿都能「选择译文表…」，列出当前文件夹里的表（可搜索），选中后按单稿同一套 `parseTableBytes` 读表；自动配对降为建议。认不出 SKU 的稿不需要改文件名。

### G5 12 份上限与 966 个设计稿

- 文件夹里 966 个设计稿，`list-folder` 默认只收 12 份（`design-file-card.tsx:121`）。
- 本轮**先保留 12 份上限**，不把第一层的多选以另一种形式搬回来；如果要在一批里从 966 个里挑稿，另开一刀“从文件夹选稿”。这是独立的批次边界问题，不混进这次入口调整。

## 2. 交互：进第 1 步以后怎么走

### 2.1 没有文件夹

- 页面直接显示第二层的空态：**单稿同款卡头**（「准备素材」+ 右上「排版定制」）+ 单稿样式的入口卡。
- 卡内：路径输入、`选择文件夹…`、`读取文件夹`、`只读预扫描`说明。
- 点「选择文件夹…」：弹 Windows 原生文件夹框（FolderBrowserDialog），直接选文件夹本身；选完读整夹。
- 读取中：按钮转圈，卡内写“正在读取文件夹…”；失败：卡内写人话原因，不消失。
- 读取成功：同一页切成第二层数据态（四个统计、左右两栏、矩阵）。

### 2.2 有文件夹

- 与现在第二层一致：统计/队列/矩阵。
- 「换文件夹」仍先确认；扫描进行中禁止换；仍选文件夹本身。
- 单稿同款卡头：批量空态和数据态都能看到「排版定制」入口，不再只在单稿出现。
- 每份稿的右栏：
  - 有候选：候选卡 + `选择其他译文表…`；
  - 缺表：`选择译文表…`（主）、`重新扫描文件夹`（次）、`这稿先不做`；
  - 已选：读表状态 + `换一张表…`。
- 选表弹窗：列出 `scan.tables`，搜索框，显示相对路径/扩展名；点击即选；表不在文件夹时给「逐稿手动导入…」出口。

### 2.3 单稿页

- 「选择文件…」仍打开 Windows 原生文件框（PSD/PSB 过滤），选中即回填并扫描；owner 锚点改为应用窗口中心，避免偏右下。
- 弹窗居中；旧助手（<3.7.24）退回系统对话框。

## 3. 数据与状态

- `stageFolderLoading` / `stageFolderError`：父层文件夹读取状态。
- `stageManualChoices: Record<draftPath, tablePath>`：人手选表，优先级 **手动 > 候选覆盖 > 记忆 > 自动**。
- `stageResolved` 合并顺序调整；手动表只要存在于 `scan.tables` 就接受，不要求是 SKU 候选。

- `stageGateRowsFromPlan`：有手动选择的 missing 行视为有表；下一步仍要求扫描完成、表已读。
- 「有表无稿」统计过滤掉已被手动选走的表，避免选完还显示“有表无稿”。

## 7. 风险

- **第一层隐藏后扫描入口**：隐藏组件仍负责 PSD 扫描队列；不能卸载，否则扫描轮询丢失。继续 `hidden` 挂载，只收走它的可见 UI。
- **手动表不在 SKU 候选里**：读表按这份稿的交付物选 sheet；可能读错 sheet。弹窗显示表名/相对路径，读表后显示语言与警告；错了可换表。
- **未知 SKU 不做一表一稿去重**：没有身份依据时不替用户做决定；同 SKU 同交付物仍拦。
- **12 上限**：本轮不放大；966 个里挑稿另开一刀。
- **原生框居中依赖助手按 anchor 放 owner**：单稿和批量都传应用窗口中心 anchor；若 Windows 仍按记忆位置弹，需助手 3.7.25 的 `StartPosition=CenterScreen`。
- **批量选择器仍是老外观**：图三只有 OpenFileDialog，不能选文件夹；本轮已恢复“真正选文件夹”的 FolderBrowserDialog（图四外观），功能正确。要图三现代外观的文件夹框，需助手 3.7.25 的 IFileOpenDialog(FOS_PICKFOLDERS)；本轮没有擅自发。粘贴 PSD/PSB 路径仍会自动取父目录，作为路径框的容错。
