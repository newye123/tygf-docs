## 直接回答：没有装上就一步到位的

最接近的是 **Puck**（MIT、13,484★、v0.23.0 发布于 2026-08-07、最近 push 10-16）。但官方文档明写"页面必须描述为 Puck data"，它的 `Render` **接管整棵渲染树**——意味着首页要重写成 root/components 树、95 个键迁成它的 JSON、草稿/发布/回滚/审计还得自己接，约 2—3 周；而且**你最痛的"字体 / 指定位置断行"它不送**（角色枚举仍要你在 fields 里自建）。它 0.20 起的 `contentEditable` 字段确实能就地改文案，`overrides` 官方自陈 highly experimental。

## 本轮实测的两条本地事实，直接决定选型

- 技术栈：React 19 + Next 16.3.8 + Tailwind 已配置，14+ 个组件在用 Tailwind 工具类。
- **但首页不用 Tailwind**：`home-view.tsx` 791 行、38,457 B、7 个 section，**246 个 className token 里 Tailwind 形 = 0**，全部来自 400 行的 `home-v17.css`。

⇒ 唯一"真能一步调字号/间距"的 **Onlook**（Apache-2.0、26,930★）README 实测句是"run on any Next.js + **TailwindCSS** project"；且它走"改代码 → 发 PR"，**没有草稿/发布/回滚/审计**语义；桌面版末版 v0.2.32 停在 2025-07-17（约 15 个月未发版），已转 web 形态。要用它，先得把首页 Tailwind 化——那是改版式实现，不是加功能。

## 值得直接抄的两个包（这是"一步到位"的诚实版本）

**Tiptap**（MIT、38,752★、最近 push 10-16）仓库里有两个包：

- `packages/extension-hard-break` —— 硬换行节点与 `setHardBreak()` 的最小正确实现；
- `packages/extension-text-style` —— **把"文字样式"做成可枚举属性、渲染成 class**，也就是我 v3 说的"排版角色"的最小实现。

不引入整个编辑器，只抄这两个扩展的设计进我们的"行数组 + 角色枚举"模型。真引入整个编辑器的代价已经算过：95 个键 × 每键一个编辑器实例、SSR 水合、before→after 清单要从字符串 diff 改成节点树 diff。

## 其他候选一句话结论

- **Payload**（MIT、45,299★）：唯一**不用搬库**的 CMS（官方支持 Postgres + Drizzle、可嵌 Next.js）。但它的 Live Preview 是后台里 iframe 载前端，不是官网上的覆盖层；审计无官方插件（社区件仅 4★）。换它＝换掉整个内容后台。
- **BlockNote**（核心 MPL-2.0，`xl-*` 是 GPL-3.0，10,304★）/ **Plate**（MIT、16,656★）：塞进弹层约 2—4 天，但纯文本键要变 JSON、中文断行语义仍得自己定，收益只有"一个工具栏"。**别把 BlockNote 的 `xl-*` 代码抄进产品**（GPL-3.0）。
- **GrapesJS**（26,311★）只吃 HTML/CSS、无 React 组件绑定；**Builder.io** 编辑器本体不在仓库（仍 SaaS）；**Plasmic**（MIT、7,110★）可 fork 自托管但内容模型要在它那儿重建；**Keystatic / Tina / Decap** 要搬 git/文件存储；**Sanity** 要搬 Content Lake；**Storyblok / DatoCMS 无开源编辑器**（org 里全是 SDK）。
- 有一个形状几乎和我们自研层一样的项目：**`adamsiwiec1/editable-website`**（MIT、**0★**、2026-09-21 有 push），官方描述"Next.js starter for an in-place editable marketing website… Local JSON store you can swap for any CMS"。不能当依赖，但可当"这条路业界也有人走"的参照实现读。
- GitHub 搜 `landing page visual editor next.js` 的 `total_count = 0`；搜"营销页文案 + 排版角色"专用开源件无相关命中 ⇒ **这个具体组合业界没有现成品**（属"查不到"，不是"官方声明不存在"）。

## 三条路线摆平了比

1. **自研补一层（v3：行数组 + 角色枚举 + 三视口预览）——推荐，把握 85%。** 3—4 天，回归面只在 `home-view.tsx` 与 `siteContent.ts`，无新依赖、不动存储、不背 0.x 库升级债。
2. **换 Puck——2—3 周，把握 70%。** 只有在你打算以后大量新增页面、并接受画布式排版时才划算；现在 7 个 section 的首页买不到对应收益，且你最痛那件事它不解决。
3. **Onlook 直改代码——把握 70%。** 前提：首页 Tailwind 化 + 接受"改的是代码、走 PR、无发布/审计"。适合你本人用，不适合当运营功能上线。

## 这轮才分清的一件事

如果你的真实需求是"**我今晚就能把这句换个行、那个词调大**"——那既不是 CMS 也不是编辑器，是路线 3，或者直接在代码里改 + 发版（也就是生产现在唯一的正规通道）。
如果是"**以后运营或我自己随时改，不碰代码**"——那是路线 1。
这两件事不该混成一个需求。你之前说"最基本的都没有"，我按第二件在做；如果其实是第一件，那答案完全不同，说一声我就换轨。

## 待你拍

1. 需求归属：上面那两件事，你要的是哪一件（或两件都要，分先后）。
2. 若选路线 1：开工刀一（行数组 + 角色枚举 + 三视口，3—4 天，不碰生产写锁）。
3. 若选路线 3：要不要先把首页 Tailwind 化（这是它的前置，且是改版式实现，不是加功能）。
