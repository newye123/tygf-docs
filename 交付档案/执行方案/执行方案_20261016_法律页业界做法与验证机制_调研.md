## 一、调研到的两个直接可用的先例

### 1.1 有测试的法律页：`Qintsg/SSPU-AllinOne` commit `4b62dea`

一个 Flutter 项目，把免责声明、用户协议、隐私协议、开源许可、第三方协议整合成**一份统一法律说明**，并让首启弹窗和 Windows 安装器**共享同一份确认事实**。

它的提交说明里写了两条对我们直接有用的东西：

> **Rejected**：继续维护分离的使用协议/隐私协议入口 —— *会让一次确认、重新同意策略和安装器许可文本长期分叉*。
>
> **Directive**：修改法律文本、第三方清单或安装器许可页时**必须同步** `assets/legal`、协议确认键、关于页入口、文档与测试。
>
> **Tested**：`flutter test test/privacy_policy_page_test.dart`、`test/windows_installer_legal_test.dart`。

我读了 `test/windows_installer_legal_test.dart` 全文，它的断言长这样：

```dart
test('Windows x64 和 arm64 安装器引用同一份合并协议文件', () {
  const expected = r'LicenseFile={#WorkspaceDir}\assets\legal\legal_zh.txt';
  for (final script in _installerScripts) {
    expect(File(script).readAsStringSync(), contains(expected));   // 每个消费方都指向单一来源
  }
  expect(File('assets/legal/legal_zh.txt').existsSync(), isTrue);
});
```

三个要点：

1. **法律文本只有一个文件**（`assets/legal/legal_zh.txt`），安装器和页面都**引用**它，不各存一份。
2. **断言的是「每个消费方都指向同一处」**，而不是「内容看起来对」。这样任何一处想偷偷改文案，测试就红。
3. **有负向断言**（`isNot(contains(...))`），把「不该出现的东西」钉死。

### 1.2 开源内容 studio：`payloadcms/payload`

Payload 是 Next.js 原生、全 TypeScript 的开源全栈框架，自带管理后台。它的 Versions 机制：

- 每份文档自动生成独立版本集合 `<slug>_versions`，保留**完整副本 + 修改时间 + 修改者**（审计日志）。
- `drafts` 模式：可以存比已发布版本**更新**的草稿，配合 Access Control 控制谁能看草稿。
- `autosave`：边改边存草稿，不影响已发布版本。
- `restoreVersion` / `findVersionByID`：按版本回滚、按 ID 取某个历史版本。
- `maxPerDoc`：每份文档最多保留多少个版本。

对照我们自己的 Content Studio：我们有 draft → diff → publish → revisions → rollback，**形状是对的**；缺的是**按版本的审计日志（谁改的）**、以及**「谁能读草稿」的访问控制**（我们现在是用环境锁一刀切挡在生产外）。

## 二、对照后，我们的问题是什么

调研让我看清了 #130 的真正病根，也看清了法律页这一摊的问题：

**我们的法律文本是三处并存、各自独立的：**
- 母本在 `docs/`（内部文件）
- 页面在 `src/app/(zh)/{privacy,terms}/page.tsx`（线上渲染面）
- 中文文案还在 `src/config/siteContent.ts`（代码单源，另有一层）

三处之间**没有任何机制保证一致**。#130 就是这么来的：代码单源改对了，但生产库读的是 `2026-09-17` 冻结的旧覆盖，两边各说各话，而且**没有任何一道门会红**。

业界的做法是把「一致」这件事**从纪律变成断言**：法律文本单一来源，每个消费方引用它，测试断言每个消费方都指向那一处，再加负向断言钉住不该出现的字样。

**三条刻意的边界：**

1. **「待取证」「未核实」不再作为发布态占位。** 取证不到的事，要么写成事实（「该服务方公开政策未给出固定天数」），要么如实标注属谁的信息（「本服务运营主体未在本页公示」），不留待办占位。
2. **不代第三方承诺。** 第三方保留期与注册主体以其公开政策与合同为准，我方不代其承诺——这句写进了表注。
3. **DNS 落某云网段只算观测，不算存储地结论。** `api.deepseek.com` 解析落 AWS、`paddleocr.aistudio-app.com` 落百度网段，这两条只记观测、不写进结论列。

### 3.2 母本同笔同步（并改名）

三份母本 `git mv` 退役旧名（`_草案_20260818` 这类名字继续留着会持续误导），改为 `docs/隐私政策_v1.0_20261016.md`、`docs/用户协议_v1.0_20261016.md`、`docs/第三方处理方清单_v1.0_20261016.md`，状态改为「v1.0 定稿，2026-10-16 生效」，并**新增第五节「验证纪律」**，把上面三条边界和「改法律文本必须同笔同步」写成明文。

### 3.3 新增一道发布门禁：`test:legal-pages-drift`

这是本次最有价值的一步——把「一致」从纪律变成断言。脚本 `scripts/smoke-legal-pages-drift.mjs`，**46 条断言**，已接进 `release-preflight.cjs` 的 `RELEASE_GATES`（第 17 道门）：

**源码层（本门，源码树跑）**
- 三个页面源码**不得**出现「草案」「待取证」「未核实」「待定稿」「生效日期：待定」——**负向断言**
- 三个页面源码**必须**出现 `生效日期：2026-10-16`
- 三份母本存在、状态为 v1.0 定稿、记载生效日期；**旧「草案」文件名必须已退役**
- 清单页与母本必须列出**同一批处理方**（本站服务器 / DeepSeek / 腾讯云 SES / Cloudflare / PaddleOCR）
- 母本第五节「验证纪律」必须成文

**线上渲染面（`smoke-seo-consistency.mjs`，对 `SEO_TARGET` 跑）**
- `/privacy`、`/terms`、`/privacy/subprocessors` 三个页面**不得**出现上述五个字样
- 三个页面**必须**出现生效日期 `2026-10-16`

两层分工：线上那道抓「生产真的没占位了」，源码那道抓「线上对了但源码留着占位、下次构建又带回来」。**#130 恰好是后一种。**

## 四、没做的、和仍然成立的边界

- **英文版法律页仍未建立。** `/en/privacy`、`/en/terms` 不存在，`smoke-seo-consistency.mjs` 的双语活对列本就不含条款/隐私英页。这是下一件要做的事，不是这次能顺手做的。
- **本服务运营主体名称仍未公示。** 这不是取证能解决的问题——是 Owner 侧信息。页面如实写「主体信息未在本页公示，合规查询请通过文末邮箱联系」，没有编一个名字。
- **法律顾问过目**：Owner 已明确「没有法律的」，本次按业界做法（单一来源 + 断言 + 同笔同步）把**可机械验证**的部分做扎实了；**不可机械验证**的部分（条款措辞的法定充分性）仍建议后续请专业人士过一遍。这一点已写进母本遗留段。
- **Content Studio 的审计日志与草稿访问控制**（Payload 有、我们没有）未做——属独立工程项，不在本次范围。
