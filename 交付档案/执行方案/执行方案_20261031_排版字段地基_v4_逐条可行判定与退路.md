## 一、这轮新查到的三件事

### 1. 「新能力怎么送到旧客户端」——别人的答案只有两条路

我把三种主流做法都查了，结论很干脆：

- **MCP 协议**：双方先握手，各自报「我会什么」，然后只用交集。字段名 `protocolVersion` / `capabilities` / `clientInfo`。但它只能让失败变得「优雅」，不能让旧程序突然学会读新文件——因为「我会什么」这句话是**装在旧程序里**的代码算出来的。
- **VS Code 的「提案 API」**：新能力靠 `enabledApiProposals` 白名单放行，核心函数 `checkProposedApiEnabled`。**这跟我们的问题一模一样**：名单是写死在宿主里的静态表，旧宿主永远不会认识新名字。
- **Chrome DevTools 协议**：客户端**不写死**能力名，而是去问服务端要一份目录（`/json/protocol`），谁有什么一目了然。

**落成一句话**：想彻底甩掉「文件名白名单」，只有把「写死的名单」改成「问服务端要目录」——但**问目录这个动作本身要写进旧程序**。所以第一步永远躲不掉一次重装。

### 2. 「一份字段清单怎么不漂移」——别人的答案是生成＋比对

- Protobuf 系：`.proto` 是唯一真源，`protoc` 生成各语言代码，**生成的产物一起提交**，CI 重跑生成器，工作区一变就红（grpc-gateway 的 CI 就是这么干的）。
- OpenAPI 系：`openapi-typescript --check`、`graphql-codegen --check` 都是同一招——「重跑一遍，和提交里的产物 diff，不一致就退出码 1」。
- 反例（手写重复＋契约测试兜底）：Django 的 `makemigrations --check --dry-run`，不生成，只算差异、只报红。

**落成一句话**：我们的字段清单散在约 10 处、跨三种语言，不可能只留一份；正确做法是**一份 JSON 真源 → 纯文本生成三份产物 → 一道 `--check` 门**。这个生成过程**不需要启动 Photoshop**，纯字符串模板，所以在我们的产物线上跑得动。

### 3. Photoshop 的段落属性到底哪些能写——这条**推翻了我上一版的一句话**

上一版我把「避头尾 / 段落合成器 / 连字」三项打包说成「读不到也写不了」。**查完官方脚本文档，只有「避头尾」写不了，另外两项加六项缩进／间距／对齐，Photoshop 的脚本接口里全都有。**

实测文档（theiviaxx 的官方参考镜像，逐属性抄出来的原话）：

| 属性 | 文档原话 | 判定 |
|---|---|---|
| `justification` | "The paragraph justification." | 有 |
| `firstLineIndent` | "The amount to indent the first line of paragraphs. Range: -1296 to 1296." | 有 |
| `leftIndent` / `rightIndent` | 同上范围 | 有 |
| `spaceBefore` / `spaceAfter` | "The amount of space before/after each paragraph." | 有 |
| `hyphenation` | "If true, hyphenation is used." | 有 |
| `hyphenateBeforeLast` / `hyphenateAfterFirst` / `hyphenateWordsLongerThan` / `hyphenateCapitalWords` / `hyphenLimit` / `hyphenationZone` | 六项连字细则 | 有 |
| `textComposer` | "The text composing engine to use." 取值 `ADOBEEVERYLINE` / `ADOBESINGLELINE` | 有（仅段落文本） |
| `hangingPunctuation` | "If true, uses **Roman** hanging punctuation." | 有，但**只管西文**，中文不管用 |
| `kinsoku` / `mojikumi` / `burasagari` / `tsume` | 文档里**一个都没有** | **无** |

两条必须说清的保留：

- 这个镜像页把**每一个**属性（包括我们已经在写的 `font`/`size`/`tracking`）都标成 "readonly"——说明这个标签不可信，官方 2020 版 PDF 同一属性标的是 Read-write。**能不能真写进去，按规矩要真机取证**，我不拿文档当实测。
- `textComposer` 只对**段落文本**（有文本框的）有效；点文本（一行没有框的）写它没有意义。设计稿里这两种都有，所以这条要逐层判断。

**「避头尾」为什么不写**：它只在 PSD 文件内部的引擎数据里有键名（`KinsokuOrder`、`Burasagari`、`PhotoshopKinsokuHard/Soft`），要通过第三方库**整段重写文件的文字引擎数据**才改得到。开源库里唯一能写的 ag-psd 会**把整份引擎数据按它自己的模型重造**，还会用硬编码的默认避头尾集覆盖原文件里的——意思是你改了避头尾，可能连带把人家稿子里别的段落设置冲掉。这个风险不该由一次「排版定制」承担。

## 二、四件地基：逐条判

### 地基 1 · 字段清单单一真源 —— **可行**

做一份 `typography-fields.json`，每条写：字段名、PS 接口名、单位、范围、**会不会改变折行**、**核实到什么程度**、界面叫什么。

然后三个纯文本生成器产出三份产物（执行器用的 ES5 片段、前端用的 TS 常量、助手校验器用的 .mjs），另加一道 `--check` 门：重跑生成器 → 和提交里的产物 diff → 不一致就红。

- 不启动 Photoshop，纯字符串模板，构建环境跑得动。
- 验收与负控：**改一处 JSON 忘了重新生成 ⇒ 门必须红**；**派生产物没提交 ⇒ 门必须红**（这两条是它唯一的价值，缺一条这地基就白做）。

### 地基 2 · 「以后加字段不用重装」 —— **只能做到「最后一次重装」**

现状两道硬闸，我都核过行号：

- 客户端和服务端各写死一份**五个文件名**的清单（`src/app/api/local-assistant/scripts/distribute/route.ts:25`、`download/local-assistant/script-distribution.cjs:27-31`），陌生名字直接丢。
- 版本下限卡的是**当前发布版**（`route.ts:103`，低于下限直接 403）。

所以**新增一个文件名，永远到不了旧助手**。两条可行路径：

- **路径 A（选它）**：注册表**塞进已经在白名单里的执行器 `.jsx` 里**，不新增文件名。载荷做成「自描述信封」——带 `formatVersion`，旧版读到不认识的键就忽略（这正是 Protobuf 的未知字段容忍）。以后加字段＝改信封内容，不碰文件名。
- **路径 B（记为后续）**：把白名单换成「服务端目录」（Chrome DevTools 那招）。这需要旧助手先会「问目录」，同样要一次重装，且改动面更大。

**所以诚实的说法是**：下一次装包之后，加字段不再需要重装。这是能给的「一劳永逸」的上限。

### 地基 3 · 字号放开＋报告话术 —— **可行**（但报告那两句话要改字）

- 计费侧无风险：渲染行数没进计费（`v15-runner.js:109`，`smoke-wrap-billing-isolation.mjs` 钉着 bindingPlanDigest 不变）。
- **对外报告有风险**：`report-renderer.js:646` 在「渲染行数 ≠ 计划行数」时直接写「**换行未在 Photoshop 生效，需人工检查**」，而那个行数是**几何估算**（`TYGF_V15_Reopen_Verifier.jsx:134` `round(heightPoints/leadingPoints)`，行距取不到时按字号 ×1.2 兜底，`:127`）。改字号会让这个估算搬家，于是可能出现「其实是估算偏差，报告却说 PS 没生效」。
- 改法：这句话必须带「估算」字样，并配两条负控（估算偏差不得写成「未生效」；真没生效不得写成「一致」）。

### 地基 4 · 发版不被「忘登记哈希」卡死 —— **可行，但必须改设计**

- 现在的门是逐字节比对（`scripts/smoke-photoshop-script.mjs:116`），改了 JSX 不登记就红。这道刹车是 2026-09-19「5 件里 3 件是旧件」事故后加的，**不能废**。
- 但不能「打包前自动补登记」：预检要求工作树干净（`scripts/release-preflight.cjs:114`），而打包取的是 `git archive HEAD` —— 自动补出来的值根本进不了包，还会让预检先红。
- 正确设计：派生器是**独立一步**，产出一笔**待提交**改动；门核「**HEAD 里的文件** vs 登记表」。负控：派生产物没提交 ⇒ 门必须红。

## 三、段落九项：逐条判（这是本轮最大的变化）

| 项 | 能不能做 | 怎么落地 | 会不会改折行 |
|---|---|---|---|
| 对齐方式 | **能** | 写 `justification`，读回比对 | 否 |
| 首行缩进 | **能** | 写 `firstLineIndent`，读回比对 | 否 |
| 左缩进 | **能** | 写 `leftIndent` | 否 |
| 右缩进 | **能** | 写 `rightIndent` | 否 |
| 段前距 | **能** | 写 `spaceBefore` | 否 |

## 九、独立复核后的改判（v4 定稿版）

复核结论 **PASS_WITH_FIXES**（无红线、全部可逆），但有四件事必须改，我逐条复跑了原文：

### D7 · 地基 2 的真闸，根本不是文件白名单 —— 是**装在安装包里的校验器**

`download/local-assistant/typography-profile.js:184` 的 `unknown-field` 判定，拿的是同一文件 `:43` 的 `ALLOWED_KEYS`（七个键）。这个文件**不在**可分发白名单里（`script-distribution.cjs:27-31` 只有五个 .jsx），也就是说：**载荷在执行之前就被它拒了**。

⇒ 「把注册表塞进 .jsx 载体」单做**什么也送不出去**。必须同时把校验器改成「键集从下载来的执行器里取」，否则下一次装包之后加字段仍然要再装一次。
这条是整份方案里唯一会决定「一劳永逸」成不成立的地方，已改。

### D8 · 版本下限读的是 `minAssistantVersion`，不是「当前发布版」

`route.ts:99-103` 的注释原文：「下限读 minAssistantVersion 而非 assistantVersion（2026-10-27 D1）」。今天两者数值相同（都是 3.7.30），所以 v4 的结论没错，**但归因错了**。另外执行器自己的版本号（`EXECUTOR_VERSION`）根本不上传服务端，永远不会触发 403。

### D9 · 段落「八项能写」→ 改成「**六项现在就能写**」

- `composer` 在今天的契约里是 `locked-field`（`typography-profile.js:44`），要开是**合同变更**，不是「能」。
- `hangingPunctuation` 文档明写只管西文（"Roman hanging punctuation"），中文稿没有效果。
- `hyphenation` 及其六项细则对中文没有实际意义。

⇒ 对中文稿真正有用且现在可写的是：**对齐、首行缩进、左缩进、右缩进、段前距、段后距 = 六项**。书写器（composer）算第七项，需重开合同。

### D10 · 避头尾的「只能重写引擎数据」——「只能」降级为**未核实**

`psd-tools` 的 `terminology.py` 是 `PITerminology.h` 的镜像（文件头自写自动生成），是**头文件摘录**，不是 Photoshop 活着的 ActionManager 字典全枚举。所以「AM 里没有避头尾」这句我证不了，只能写未核实。

另外复核指出一条我没写进方案的**低风险路线**：不经过 ag-psd 整棵重造，而是**只动引擎数据里那几个键**。ag-psd 会冲掉原设置，是「这个库」的性质，不是「这件事」的性质。这条进研究项，不进班车。

### D11 · 生成器要一次产出三样，并挂在 `test:contracts`

生成器必须**同一次**产出：执行器里的字段段 ＋ `config/script-versions.json` 的哈希 ＋ `EXECUTOR_VERSION`。分开做就是死循环（生成→哈希红→登记→哈希绿→登记表又要单独提交）。

`--check` 必须挂在 `test:contracts` 里（照 `build-zh-font-subset.mjs --check` 的位置），否则又是一个「写了没人跑」的孤儿闸——`agents.md` 已点名这是假绿高危形态。

### D12 · 缩进／段距是 `UnitValue`，不是数字

`firstLineIndent` 等六项在文档里都是 `UnitValue`。执行器为 `leading` 已经踩过一次这个坑（`TYGF_V15_Thin_Executor.jsx:113-118`：`String(item.leading)` 读回是 `"30 pt"`）。注册表的「单位」列必须写 `UnitValue + .value`，否则读回比对会静默判错。

### 复核顺带确认的一条好消息

`docs/records/20260920_排版普查_实测基线.md:41` 记着：**扫描侧今天已经能读到全部九项**（`justification`/`autoHyphenate`/`kinsokuOrder`/`burasagari`/`hanging`/`everyLineComposer` 等）。所以「退路 3：只读不写、面板显示原稿值」不需要新建通道，接线即可——包括避头尾也能**读出来给你看**，只是改不了。
