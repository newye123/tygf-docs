## 0. 先说人话：这件事能不能成、卡在哪

**能成，而且不必等云端。** 但要把三句大实话摆在前面：

1. **现在系统"学"的不是你的选择，是原稿长什么样。** 扫描器把 PSD 里每一层的字体、字号、行距读上来传给云端（`server.js:2963-2985`），云端把它们统计成"偏好画像"（`typography-contract.ts:309-315`）。这份画像回答的是"这份稿原来用了什么"，回答不了"你希望改成什么"。拿它直接做推荐，推出来的是**原稿的复刻**，不是你的偏好。
2. **现在没有"按字号分档"这个数据模型。** 一个语言只存一份排版设置（`typography-persistence.ts:13-34`、`:232-240`），执行时这一份套到该语言的**每一个**图层（`TYGF_V15_Thin_Executor.jsx:221`）。所以哪怕今天算法算出"标题该用 Bold、正文用 Regular"，也没有地方存、没有地方发、执行器也不会分层用。
3. **现在没有任何"把建议送到用户面前"的运行路径。** 规则解析器恒返回空建议（`rule-resolver.ts:16-21`），部署接口只允许 `shadow`（`deploy/route.ts:22`），建议开关只在管理端概览里显示一下（`overview/route.ts:42`）。管理端点"部署"，执行链一个字都不会变。

所以正确的顺序不是"先开学习开关"，而是：

> **先把"字号档 → 字重/字距/行距"这个模型做出来（本机就能跑）→ 在本机用原稿字号结构给确定性建议 → 再把你的每次选择记成本机历史 → 最后才谈云端个人学习。**

这样第一阶段不碰云端、不碰隐私、不碰计费、不碰 manifest，就能立刻减少操作。

## 1. 学习完之后，到底能少做哪些操作

| 操作 | 今天 | Phase A 本机 | Phase B 本机历史 | Phase C 云端个人 |
| --- | --- | --- | --- | --- |

| 按字号调字距 | 只有一个全局值 | **能**：小字号给正字距，大字号不加大 | 记住你的修正 | 个人化 |

## 4. 执行方案

### Phase A（P0，本机推荐，先做）

**A0 网页侧最小版（1–2 人日，不改助手）**
- 在排版面板顶部加"按原稿建议"：从 `psdSelection.summary.typographyLayers[].typography.fontSizePt` 取字号分布，用确定性一维三分（排序后取自然断点，不用随机算法）得出小/正文/大三个区间。
- 只填**一份**现有 profile：用正文档的字重与字距、行距；大标题与小字只做提示，不落到执行。**价值：少填几个格；局限：仍是一语言一个粗细，要如实写在按钮旁。**
- 样本不足（可见层 < 6 或不同字号 < 2）时按钮禁用，写清"证据不足，按原样保留"。

**A1 分层版（3–5 人日，需改助手并 bump 版本）**
- 数据模型 v3（向后兼容，v1/v2 照常读）：
  ```ts
  interface TypographyTier {
    id: 'small' | 'body' | 'display'
    face: string            // PostScript 脸名；空 = 该档不改字体
    tracking: number | null // 1/1000 em
    leading: { mode: 'follow' } | { mode: 'percent'; pct: number } | { mode: 'fixed'; pt: number }
  }
  interface TypographyProfile {
    // ...现有字段不动
    tierPolicy?: {
      thresholds: { smallMaxPt: number; displayMinPt: number }
      tiers: { small: TypographyTier; body: TypographyTier; display: TypographyTier }
    }
  }
  ```
- 映射到助手时只发显式设置的档（`toAssistantTypographyProfile`）；信封 `typography` 增加兄弟字段 `tiers`，**不进 manifest、不进 digest**。
- 执行器在 `applyTypography` 前读该图层当前字号（`textItem.size.value`，缺失时归 body），按阈值选档；无 `tiers` 时走原路径，行为逐字节不变。
- 建议规则（全部纯函数、可单测）：
  - 大标题：比正文粗一档，但**不高于**同族可用的最粗脸；原稿标题与正文同脸时，不主动加粗。
  - 小字：不推更细；正文为 Regular 时，小字建议 Medium（可读性），否则沿用。
  - 字距：只允许 `0 / +10 / +25`；小字不得用负字距。
  - 行距：优先原稿行距分布中位数；无数据时 1.35 × 字号，且标注"估算"。
- 字重来源：`/v1.5/fonts` 只回 `postscriptName/displayName/family/style`，**没有数值 weight**（`server.js:1530-1567` 实测字段；`typography-faces.ts:12-19` 同）。因此在 `style` 文本上做**显式白名单**解析（Thin/Light/Regular/Medium/SemiBold/Bold/Black 及常见变体），解析不出就返回"未知"，**绝不猜**。只在用户已选 family 内挑脸，不跨族替代。
- UI：每个档一行（档名、字号范围、将使用的脸、字距、行距、受影响层数、理由一句）；「应用」只写 localStorage，不触发执行；执行前仍按现有预览显示这次会用到的值。

### Phase B（P1，本机历史，2–3 人日）

- 新增本机键 `tygf:v15:typography-history`，每条只存：语言、字号结构签名（分桶计数 + 阈值）、三档实际值、回读是否通过、时间。**不存正文、图层名、路径、文件名。**
- 上限 50 条，按时间淘汰；匹配条件：同语言 + 字号结构余弦相似度 ≥ 0.8。命中才显示"沿用你上次的做法"，否则显示"证据不足"。
- 失败样本不参与推荐；用户每次手动修正后写一条 `modified`，下次同结构优先用修正值。
- 全程本机，零云端，零隐私面变更。

### Phase C（P2，云端个人学习，必须 Owner 批准）

前置（缺一不可）：
1. 隐私页与注册同意范围改写：明确"字体名/字重选择可用于排版建议"，保留"不上传正文/路径/文件名"；给用户一个可撤回的开关（今天是"撤回=停用"，不满足"可单独关闭"）。
2. 新增决策族 `typography_tier_choice`，进 `ALL_DECISION_FAMILIES`；**只对 personal scope 启用**，template/brand/public 继续关闭。
3. 合成 `objectId = tier:<lang>:<bucket>`；context 只放语言、档位、字号桶、文本类型、字族类别；`finalCode` 用规范化档位摘要（如 `w+1|tr+10|ld:follow`），不存原始脸名明文。
4. 只在"执行成功 + 用户确认采用 + 回读通过"后记 `accepted`；用户改过记 `modified`；显式忽略记 `rejected`。
5. `LEARNING_SUGGESTIONS_ENABLED` 控制是否显示建议；`LEARNING_AUTO_APPLY_ENABLED` 永远 false。
6. 合同四层同步 + `test:trust-chain` + `test:batch-row-contract` 全绿才可上测试站。

### Phase D（P3，模板/品牌，后置）

- 先做**结构指纹**（字号分布 + 层数 + 结构特征，不含正文/路径）作为学习侧模板身份，与信任链的字节指纹并存、互不替代。
- layout 验证必须有人工/视觉确认，机器坐标测不出"压没压到色块"；在 `layout=passed` 链打通前，模板/品牌推荐不开。
- 公共推荐（跨用户）不在本轮范围。

## 5. 验收清单（可复跑）

1. 分档纯函数：同输入同输出；单元测试 ≥ 20 条断言；阈值边界（等于 smallMax/displayMin）有显式用例。
2. 证据不足：层数 < 6 或不同字号 < 2 时按钮禁用，且界面写明原因。
3. 同族没有更粗脸：不推荐，文案写明"该字体族没有可用字重"，不跨族替代。
4. 预览能显示三档边界与各档受影响层数（用 `typographyLayers` 现算，不新扫描）。
5. 点"应用"只写 localStorage；未点执行前不产生任何助手请求。
6. 执行器：无 `tiers` 时行为与 HEAD 逐字节一致；有 `tiers` 时按层字号选档；字号不可读时归 body 并在报告记一行。
7. 向后兼容：v1/v2 profile 读得动；旧数据不迁移、不猜脸名。
8. 合同：manifest 键集与 digest 不变；`npm run test:trust-chain`、`npm run test:batch-row-contract` 均 rc=0。
9. Phase C：默认 flag 全 false；建议卡必须同时给"为什么这样建议"和"为什么可能不适用"两句。
10. 隐私：Phase C 上线前，隐私文案与同意范围已更新；未更新则不得开启云端推荐。

## 6. 风险与回滚

| 风险 | 触发条件 | 处置 |
| --- | --- | --- |
| 阈值切错，建议明显不合理 | 字号分布是连续长尾 | 阈值可手改；界面显示每档层数；不自动应用 |
| `style` 解析把 "Semibold"/"Demi" 认错 | 厂商命名不统一 | 白名单 + 未知即不推；单测覆盖常见族 |
| 执行器读不到字号 | UnitValue / 锁定图层 | 归 body 档并记非阻断提示；不抛错中断 |
| 助手版本升级摩擦 | A1 改助手 | 按发布规矩 9 文件 + 1 exe 同步；先 Web-only A0 顶一阵 |
| 与在飞会话冲突 | `server.js` 当前有他手未提交改动 | 动助手前先确认那批改动归属；本轮未碰任何业务文件 |
| Phase C 目的外使用 | 隐私文案未改就上线 | 硬前置，未改不上 |

回滚：Phase A/B 无数据库迁移，清 `tygf:v15:typography` 与 `tygf:v15:typography-history` 即回到现状；Phase C 用现有规则回滚接口 + flag 关闭，不删学习表。
