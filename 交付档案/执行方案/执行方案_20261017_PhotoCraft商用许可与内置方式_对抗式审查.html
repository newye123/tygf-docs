02取证细节（每条给可复跑坐标）

E-1 许可真身Cargo.toml:9 / commit cf93edc9

双许可由上游作者设立。根 license = "MIT OR Apache-2.0"，LICENSE-MIT 版权行 Copyright (c) 2026 ArtCraft Team and the PhotoCraft contributors。添加它的提交在 2026-10-04，作者 Brandon Thomas，提交名直译"许可：MIT OR Apache-2.0 文件、NOTICE、ArtCraft 商标条款、署名"。

E-2 未被篡改git show HEAD:LICENSE-MIT | sha1sum

我们 fork 的 git blob 与最初下载的原始快照同哈希：LICENSE-MIT 0accf067…、NOTICE 0b2eedb1…、LICENSE-APACHE 598f87f0…。直接对工作树文件算会得到不同值——那是 CRLF（本机 autocrlf 的已知现象），所以必须取 blob 再算，否则会误判成"许可证被改过"。

E-3 商标条款替我们说话docs/brand/LICENSE-brand.txt:30-37

"Forks and modified versions"原文：分发修改版必须移除 ArtCraft Marks（或换成自己的），不得称 ArtCraft、不得呈现为 ArtCraft 产品；允许用纯文本说明"基于 ArtCraft 团队的 PhotoCraft"。docs/brand/ 里 9 个 artcraft-logo*／artcraft-mark* 文件全部被定义为 Marks，一个都不能带。⇒ 您要的"用户不用知道它存在"与上游要求同向。

E-4 依赖面刻意宽松docs/architecture.md:579 / crates/raw/Cargo.toml:17-27

他们自己的文档写明"候选依赖里有 LGPL（rawler）与 GPL-or-commercial（Slint），选 MIT/Apache 会限制可用范围"。实测 RAW 解码用纯 Rust 自研（flate2 + zune-jpeg）没引 rawler；全仓 Cargo.toml 对 rawler|slint|qt|ffmpeg|libvips 命中 0；ATTRIBUTION.md 规定第三方素材必须宽松许可且许可文本随件。345 只 crate 逐只核验已跑完（345/345）：零 copyleft 阻断——唯一带 copyleft 选项的是 r-efi（MIT OR Apache-2.0 OR LGPL-2.1-or-later，三选一，取 MIT/Apache 即免 LGPL），"GPL/LGPL 为唯一选项"的形制 0 只；crates.io 标 non-standard 的 av1-grain 单独下包读原文＝BSD-2-Clause。分布前几：MIT OR Apache-2.0 154、MIT 60、Apache-2.0 OR MIT 23、Unicode-3.0 22。方法标注：闭包按 Cargo.lock 依赖边算，含未启用的可选依赖 ⇒ 345 只是上界，真实出厂件只少不多（对许可审查是安全方向）。

E-5 二进制里真带了别人的东西crates/text/build.rs / fonts.rs:26-40 / spell.rs:16

4 只字体（Inter 三档 + JetBrains Mono，均 SIL OFL 1.1）被无条件 include_bytes! 内嵌；SCOWL 英文词表同样内嵌（其许可允许"以任何目的分发与销售"，条件是版权与许可声明随副本）。⇒ 随包必须附 OFL-Inter.txt、OFL-JetBrainsMono.txt、LICENSE-SCOWL.txt。GUI 专用图标里那只 CC BY 3.0 不在我们 exe 内（ui-egui 不在闭包），不进清单——但这条要靠"只打 CLI"的纪律长期为真，所以清单由构建脚本生成而非手抄。

03对抗式审查（会怎么翻车）

L-1 阻断worktrees/develop/src/app/(zh)/

"藏起来就不用提"是错的。义务挂在"分发副本"上不挂在品牌上。用户看不见 PhotoCraft 合法，但许可文本/版权行/NOTICE 必须随包，且产品里要有"开源许可"入口。实测站内没有这个面（(zh)/ 仅 privacy·terms·download·pack·survey·auth·admin），记忆里提到的 src/config/legalDocs.ts 在 develop 不存在（ls 报 No such file，现文案在 src/config/siteContent.ts）。⇒ 出厂同笔新建，否则复现 LEGAL-1 那类"文档与代码相反"。

L-2 重installer.iss:44-58

改名是义务不是选项。引擎落地为 {app}\bin\tygf-engine.exe，进程名/日志/错误文案不出现 PhotoCraft，界面只说"内置排版引擎"。

L-3 重GitHub API newye123/photocraft

补丁已经公开。实测 "private": false、"visibility": "public"、"fork": true——让 PSD 能被真 PS 打开的那两个修复，竞品现在就能拿走。要独占需脱离 fork 网络（public fork 不能直接转 private；可行＝按许可复制成非 fork 独立仓并迁 CI）。这是商业决策，不是合规义务。

L-4 重assets/fonts/OFL-*.txt

OFL 字体名不可改、字体不可单独售卖、许可文本必须随字体副本。我们 exe 已内嵌 ⇒ 硬约束；顺带：别把 Inter 改名成自有字体。

04内置落地（一次装完，用户零感知）

1

文件落位

installer.iss 增两条 Source：dist\bin\tygf-engine.exe（改名件）装到 {app}\bin\；licenses\** 装到 {app}\licenses\。bundle 内容＝MIT＋Apache 文本、NOTICE、ATTRIBUTION、OFL×2、SCOWL，加构建脚本自动生成的《第三方开源组件清单》（组件·许可·版本·上游地址·我们的变更说明）。不手抄。

2

运行时寻址（接上一轮 F-1/F-2）

pcExePath 不再读用户配置＝固定 BUNDLED_DIR\bin\tygf-engine.exe；pcExeSha256 出厂钉值且缺值即拒。用户改本机 JSON 换不掉引擎，"我们分发的那个副本"才可核验。

3

话术与界面

界面只说"本次由内置排版引擎处理（未调用 Photoshop）"；禁出现 PhotoCraft/ArtCraft 与其图形；"基于 ArtCraft 团队的 PhotoCraft"只写在开源许可页与随包 NOTICE 复现里。

4

构建身份

继续 GitHub Actions 云构建（本机免 Rust）。每次产出构建清单 {上游 commit, 补丁 commit, Cargo.lock sha256, exe sha256, 许可 bundle sha256}，随包＋进发布记录；运行时 --version＋sha256 现算回写回执。若走 L-3 独占路线＝另建非 fork 独立仓迁 CI，等您点头。

5

体积与更新

exe 43,341,312 B ⇒ 包从 ~12.5 MB 涨到量级 ~56 MB（未压缩口径）；Inno Setup LZMA 压缩后实数待测再定对外说法——不把没量过的数当结论。自动更新面要把引擎体积计进下载成本。

6

法务面同笔

新增开源许可页（站内＋助手关于页）。隐私面不需要新增第三方处理方条目：引擎全程本地、闭包内无 HTTP 客户端（实测仅 tokio，无 reqwest/hyper/ureq/rustls；exe 内 URL 串只见 XMP/PSD 命名空间常量与噪声，无遥测端点）——但"文件不出本机"这句要把这两项证据一起入档。

验收判据（可复跑）

包内 licenses\ 7 类文件齐且与上游快照字节一致；{app}\bin\tygf-engine.exe 哈希等于构建清单；重扫 exe 内 ArtCraft 命中 0；无 PS 机器上助手报"内置引擎就绪"；开源许可页站内可达且列全内嵌组件；依赖逐只核验已跑完 345/345，零 copyleft 阻断；清单里要显式记录 r-efi 取的许可选项与 22 只 Unicode-3.0 组件的版权保留义务；升引擎版本时该扫描必须重跑（做成 CI 门，不靠人工）。

05要您拍的三句

  • 独占不独占：补丁迁非 fork 私有仓（别人拿不到，代价＝脱离上游更新、自己维护全量源码）vs 继续 public fork（白嫖上游修复，代价＝补丁公开）。推荐先 public fork 出厂，这条链现在缺的是"能用"不是护城河。
  • 体积换体验：接受包涨到量级 ~56 MB（一次装完、用户零感知）？推荐接受——"用户不用知道"只有内置路线成立。
  • 承诺范围：首版只承诺 PSD/PSB 文字层，HEIF/RAW 不写进文案也不开入口。理由按 L-5 更正：不是专利（实测无 HEVC 解码、AV1 免版税），而是承诺范围只能等于证据范围。推荐照此收窄。
