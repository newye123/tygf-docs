      01账号菜单放大：只差这一行

      左边是被后台备注污染的菜单；右边把“用户自有身份”和“运营内部字段”彻底分开。邮箱是登录凭证，也是用户唯一能确认“这是我”的信息；后台备注只在运营台出现。

      现状：`BetaUser.name` 当显示名

      • 展示名字来自 BetaUser.name，后台标签写的是“姓名 / 运营备注名”。
      • 该字段由申请表单或邀请码归属自动写入，用户本人无法查看或修改。
      • 即使前端不显示，/api/auth/me 仍把它发给浏览器。

      建议：邮箱是身份，备注留在后台

      • 主行只显示登录邮箱；第二行说明账号状态（已登录 / 待验证 / 不可用）。
      • 头像首字母从邮箱本地部分取，不再受备注影响。
      • 服务端同时裁剪 name、betaUserId、sessionId。

      02五种状态，导航各做什么

      状态修复前修复后为什么
      loading直接画“登录”34px 圆形骨架未知 ≠ 未登录；骨架尺寸与头像一致，零布局跳动
      anonymous登录登录唯一应该出现“登录”的状态
      authenticated仍然“登录”头像 + 菜单登录态必须替换入口，而不是并列出现
      blocked（403）“登录”，点进去再失败头像 + 琥珀点，菜单说明原因账号被停用不是“没登录”，不能诱导反复登录
      unreachable按未登录处理，静默消失保留上次已知状态 + 可重试网络不可达不能当成退出登录（沿用 AccountGate 的 P-17 口径）

      03为什么不能只改首页那一行

      只改前端会留下什么

      • Network 面板仍能读到后台备注：GET /api/auth/me → name。
      • 刷新瞬间仍会先画“登录”，再被 JS 换成头像——这就是另一张截图里的闪烁。
      • 开两个标签页，一边退出，另一边还挂着头像。
      • 首页为了一个下拉菜单，把整套工作台 UI 打进公共包。

      建议的落点

      • 服务端裁剪：`/api/auth/me` 只回 email / emailVerified / accountStatus。
      • 服务端首帧：首页已是 force-dynamic，直接把会话摘要传给客户端，首屏就是对的。
      • 一个登录态源：Provider 共享状态，组件不再各自 fetch。
      • 按需加载：菜单组件只在已登录时动态加载，访客不为它付体积。

      04视觉与交互口径

      桌面

      • 头像 34px，落在原“登录”位置，右侧留白不变。
      • 菜单 268px，左对齐到头像的右边缘，避免贴边溢出。
      • 菜单项：工作台 / 设备与会话管理 / 退出登录（红色，最后一项）。
      • 头图与导航的绿色保持 #2d7356，不使用工作台的黑白主题 token。

      手机

      • 导航链接折叠后，头像仍在“申请试跑”左侧。
      • 点击区域 ≥ 44×44（视觉 34px，透明外扩 5px）。
      • 菜单宽度 256px，最大高度不超过视口，内部可滚动。
      • 键盘：Enter/Space 打开，Esc 关闭，焦点回到头像。
      一句话验收：登录后，首页导航不再出现“登录”两个字；账号菜单里除了邮箱，不该出现任何后台填的内容；刷新页面第一帧就是头像，不是“登录”再跳成头像。
