2 · 对抗式审查（先审本方案自己）

面会怎么失败处置
重复建设已有日志轮转、目录清场、进程自愈不建服务、不建进程；一个模块 + 一处接线；日志单独文件
写侧强制力采样抛错会把「这稿失败」放大成「功能坏了」全程 try/catch，失败返回 null，不 await、不阻断；注入会抛的实现做负控
危险动作自动重启 / 清缓存会关掉用户未保存文档本轮零动作：不 kill、不 purge、不改首选项、不改 JSX
外泄面日志落在用户机器上，等于对外文件只写 attemptId + 数字 + 枚举；正则负控扫盘符 / UNC / 邮箱 / .psd
并发阻塞事件循环、两行乱序、多手同改异步 execFile；单行追加；按 attemptId 配对；只动干净的 v15-runner.js，不碰他人正在改的 server.js，不提交
更便宜反方案不做也能上线这是唯一能把「要不要保护闸」变成可证伪判断的读数；替代方案更贵且拿不到逐稿序号
可证伪判据读数接歪了照样出绿三条合成日志负控 + 样本不足判定

3 · 执行步骤

  1. 新增 memory-probe.cjs：异步 tasklist 读每枚 Photoshop 的 PID 与工作集，叠加系统可用内存与本进程 RSS，写一行 [mem] 到 logs/batch-memory.log（2MB 轮转）。
  2. 接线 v15-runner.js 的 runV15Execution：进入采 phase=start，finally 采 phase=end（状态 / 完成数 / 耗时）。
  3. 新增 scripts/analyze-batch-memory.mjs：首 5 vs 末 5 的 p50 耗时、PS 工作集中位、失败率，给出「衰减 / 未衰减 / 样本不足」。
  4. 新增 scripts/smoke-assistant-memory-probe.mjs：解析、坏输入、脱敏、三条判定负控、轮转，全断言；挂 npm run test:assistant-memory-probe。
  5. 真机一击：对当前正在跑的 Photoshop 跑一次只读采样，证明真实环境解析成立（不碰文档、不杀进程）。
  6. 记账与送达：TASK_LOG 置顶；ledger 追加「待复验」并投影（失败不阻塞）；方案发飞书。
