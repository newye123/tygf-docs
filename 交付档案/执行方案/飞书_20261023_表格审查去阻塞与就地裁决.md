# 表格审查为什么卡人：查完的结论与方案（2026-10-23 晚）

## 先给结论

你说的两件事是**同一个病**：问题清单在第 2 步（智能检测），能点动的裁决却在第 3 步（设计稿校对）；而且只要你在那张表里开始补译文，检测就被打断、刚拿到的建议全部作废。

所以顺序应该是：**先止谎（半天）→ 让"补译文"不再打断检测 → 再谈四步并三步**。反过来做只会把病挪个地方。

还有一件我要先纠正自己：我一开始也以为"给漏译行加一条 AI 建议"就行，**查完发现不是**。产品现在四处明文禁止模型翻译（"禁止翻译、润色、补写"），而且有缺译行的时候**系统根本没调 AI**。这不是加按钮的事，是产品口径的事，所以我建议不要放开，改给三条不需要翻译的出路（下面第三节）。

## 查出来的四条，每条都有代码位置，我自己复现过

第一条最要紧，因为它在骗人。表里只要有一行没译文，语义核对就**一次都没跑**（程序直接走"对齐修复"这条后备路），但界面照样显示"检测完成"，备注还写着"请人工确认后一键应用"——而那个"一键应用"按钮的条件是"有可应用的建议"，后备路给空译行产出的建议内容就是空，被前端当"没变化"丢掉了。**结果是：提示让你去点一个不存在的按钮，同时把"没核对"这件事盖住了。**

第二条：一次语义核对最多看 300 行，超出的行数被记在一个内部字段里，但**界面上从来没有读它**。你那类 6,000 层的真稿，用户会以为全审过了。

第三条最伤手感：检测的中断判断用的是"整表译文快照"，所以你**每敲一个字，正在跑的检测就被中止一次**；而采纳建议前比的也是整表哈希，只要改过任意一格，点"采用"就只得到一句"表格结构或修复计划已变化，旧建议没有被应用，请重新运行"——重跑一次最长要等 15 分钟，12 种语言还是串行。**"补译文"这个动作本身就在销毁建议。**

第四条就是你说的"第三步多余"的真相：冲突候选在第 2 步**只是两行纯文本**（「候选：A / B」），不能点；同屏唯一能点的按钮是"确认当前译文安排"，意思等于"就按现状走、不改内容"。真正能二选一的地方在第 3 步。**第 3 步不是多余，它是唯一能点的地方**——所以要修的是"把手点的地方搬回第 2 步"，不是删一步。

顺便一句：代码里"全部确认知晓"那个按钮的注释，作者自己写着"N 个一模一样的点击是流程剧场"。这个判断和你的手感一致。

## 我去 GitHub 和官方文档看了，也顺手更正了仓里一句旧话

仓里 10 月 3 日那份 UI 研究写着「GitHub 上有没有开源的可以直接抄？结论：这个领域没有」。它当时的搜法是"PSD 批量翻译"（结果最好的一个只有 35 星标，功能同题的那个 0 星标）。**那句在它自己的搜索范围里成立，但搜错了问题。**我们的真问题是"逐行审阅＋给建议＋不阻塞执行"，这条有很成熟的工业先例，都在本地化（CAT）工具里：

- Weblate：建议永不自动写进正文，按键才落地；批量补漏译**只填空行、不覆盖已有译文**，填完标"待复核"。
- memoQ：警告可以直接忽略并置灰，**只有"必然导致交付坏"的错误级才拦导出**——我们现在把"缺一行译文"也当闸用，这是分层用错了。
- Phrase（TMS）：三档强制——默认可跳过、管理员可按检查项关掉跳过、必须拦的拦的是"标记完成"而不是导出，风险进交付报告。这是最像我们"报价／执行"两段式的。
- Trados：自动确认只给"100% 精确匹配"，模糊匹配必须人工——**用门限决定自动程度，不是用拦截**。
- Crowdin：批量预翻译会回报"动了什么、没动什么"；编辑器的质检是保存时的警告条，可以继续。
- Google Docs 的建议模式／Notion 的建议编辑：建议和正文分层存放，可以全部接受，但接受前给整篇预览。
- GitHub 的批量采纳建议：可以一次应用多条，但"这一条依赖另一条／行已被改动／建议过期"一律踢出批量、强制逐条——**正好治我们"改一格作废整批"这个粗暴闸门**。

另有一半必须一起看：一键采纳会让人盲点。用了自动化建议的人对错误建议的盲从比例高约 26%；今年一个 107 名开发者的实验里，94% 最终合并了被植入恶意路径的 AI 产出，有人自述"已习惯直接点批准"。被证明有效的办法是**认知强迫函数**（批准前必须做一个动作），而"提醒你警惕"无效。所以我给的方案里硬性带三条：建议必须显示改前改后、必须标注来源（同表搬运还是模型判断）、批量采纳必须附报告和被踢出的条目。置信度只用来排序和决定能不能进批量，**不能代替你签字**（这是我们仓里的老规矩）。

## 我建议怎么做（四段，每段可以单独上）

第一段，半天，止谎。把"检测完成"改成三种说法：AI 已核对多少行；本轮没做语义核对，因为表里有几行缺译，补齐才会跑，并给一个"去补第一处"的按钮；只看了前 300 行，还有多少行没看，点这里继续。缺译那一行不再只写"请补全译文"，而是给三条出路：**补**（一键光标落到那格）、**借**（同一张表其他语言已有现成译文，点了就搬过来，标"待复核"）、**排**（这格本来就不该有译文，比如版权行，一键标不翻译）。后备路的备注里"一键应用"四个字删掉——没按钮就不许说。

第二段，两天，让补译不再打断检测：判断"表变了没有"从整表哈希改成**按行**，只有受影响那条建议失效，其余照样能采用；补完只重跑那几行，不重新排队整表。

第三段，三到四天，就是"第三步"的解：候选在第 2 步变成可点选项（点了才落地），表级二选一搬回第 2 步；第 3 步只留它真正独占的东西（Photoshop 就绪、握手、绑定检查），改成后台自检、只在出问题时出现，出现时按"禁用＋原因＋出路"讲清楚，绝不把功能变没。导轨从四步变三步。

第四段，一天半，放行粒度：删掉那个"流程剧场"按钮；12 次逐语言确认改成**一张跨语言汇总卡**——每个语言一行，写着有几个问题、能不能自动放行、哪几处要你定，你一次批准"除冲突外全部放行"，冲突项单独点名不自动。同时把"什么才拦你"写成一份封闭清单：只允许三种情况拦（一批里没有任何可执行行、报不出价、Photoshop 不可用却点了执行），出现第四种就报警。

排期建议：一 → 二 → 四 → 三。第一段先上，你当天就能看出检测到底跑没跑过。

## 需要你拍三件（一句就够）

一，AI 代译放不放开？**我建议不放开**，用"补／借／排"三条出路。要放开的话，代价是产品定位从"我准确写入你给的译文"变成"我也能翻"，质量责任、对外说法、模型成本一起变，还得改四处禁令；真放也要只在"没有品牌风险的文字"上、默认关、界面明写"机器建议·未经人工确认"。

二，第 3 步怎么处理？**建议并进第 2 步**（裁决就地做，就绪检查转后台）。次选是保留但折叠成一行自检状态。

三，放行粒度要不要做到完全零确认？**建议不要**——要先把前两条缺陷（AI 没跑、只审 300 行）修成真跑真全审，否则等于让你没看过的行默认可执行。

## 你现在就能自查的三件事

一，眼下这张表里有没有缺译行？有的话，今天所有"检测完成"都没跑过 AI。验证方法：看那行备注是不是「对齐修复计划（未调用 AI，不消耗 token）」。
二，表行数有没有超过 300？超了就只有前 300 行进语义核对，界面不会告诉你。
三，补译文的时候如果检测正在跑，它已经被你敲的第一下打断了，后面的"采用"不会生效，只会让你重跑一次。
