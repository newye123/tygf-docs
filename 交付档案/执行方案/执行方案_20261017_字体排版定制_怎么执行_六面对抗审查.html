字体排版定制：怎么执行

Owner 令「继续用对抗式审查看看怎么执行」。本件把上午的实测（PS 22 探针 A—H5＋I）与三路调研（开源排版面板 7 件、PSD 引擎数据三方字段对照、避头尾/连字/合成器的业界处理）压成一条可执行链，并且第一段已经执行完、留了运行证据。

§0 第一性原理（可判定的一句话）

用户对某门语言指定的排版，要么在交付件里真的成立并且能证明，要么明确不成立并说出来。
推出三条硬判据，后面每一步都受它管：① 没落到 PS 里的设置，界面与回执不得呈现为已生效（含"保存成功"这种半步）；② 任何"生效"必须留下读回值，不能只有"写入没抛错"；③ 本版本 PS 做不到的旋钮不做成控件——假控件与假成功同罪。

§3 两处砍到自己（写进规范，不是道歉）

B1 收回"白名单加 textComposer"
切档实测会改变折行（147×13→149×13），而我们的"计划行数 vs 渲染行数"判据建立在我们自己插的硬换行上；开放它＝引入一个我们无法预测折行的变量，报告会冒出解释不清的"计划 3 行、渲染 4 行"。本版固定"跟随"、只在回执记录当前值；要开放，前置是 L3 合同包把渲染行数升为按 PS 实测行边界——而 PS 22 拿不到逐行原点。
B2 更正"postScriptName 逐脸唯一"
我只数了前 40 条；全量转储后是 1587/1605。规矩：任何"唯一/全部/恒等"式断言必须全量数过——与"必须穷举枚举成员名"是同一病的两个面（今天已因此三次下错否定结论）。

§4 字段合同（envelope 旁路，不进摘要）

envelope.typography = {
  schema: 'tygf-typo-v2',
  byLanguage: {
    JA: { face?: string,            // PostScript 脸名；缺省 = follow
          tracking?: number|null,   // 1/1000 em
          leading?: { mode:'follow'|'percent'|'fixed', value?: number|null },
          autoKerning?: 'follow'|'METRICS'|'OPTICAL',
          fauxBold?: false, fauxItalic?: false }
  }
}
不动四层合同
摘要只算 manifest（v15-runner.js:145），旁路字段不进摘要 ⇒ 不触发合同变更纪律；但必须配一条锁死断言（V4）。
执行器写入顺序
contents → face → autoKerning → leading（percent 走 autoLeadingAmount；fixed 先 useAutoLeading=false）→ tracking → faux*，每项 try + 读回。
失败码
FONT_UNAVAILABLE／FONT_FALLBACK_APPLIED（读回≠所设）／TYPOGRAPHY_INVALID／LEADING_NOT_APPLIED。
