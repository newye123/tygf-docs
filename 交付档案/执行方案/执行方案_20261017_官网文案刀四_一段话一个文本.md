## 一、对抗式审查：先抓我自己上一轮的定义错误

我把问题定义成"标题被切成四格"，于是只归并了标题。真实规律是**"一段话被 JSX 的节点边界切开"**——标题只是其中一种。实测全量（脚本按"同父路径下键名以 `A/B/C/Strong/L1/L2a…` 结尾"归组）：

**16 组、43 个键，本该是 16 个文本。** 其中我上一轮只处理了 7 组（标题），漏掉 9 组：`hero.copy`（3 格）、四处 `lead`（各 2 格）、`status.quote`（3 格）、`cost.batchStepLast`（2 格）、`try.form.scopeLabel`（2 格）、`try.form.successSub`（3 格）。

**更要紧的是：这 16 组不是同一种病，不能一律"合并成一个字符串"。** 逐组读渲染代码后分三类（每类都给了 `file:line`）：

| 类 | 事实 | 处理 |
| --- | --- | --- |
| A 真·一段话 | `<p class="section-lead">A<br/>B</p>`（`home-view.tsx:262/290/348/403`）、`<p class="hero-copy">A<b>Strong</b><br/>B</p>`（`:161`）、7 处标题 | **合并成一个键**，`\n`＝换行，`**…**`＝粗体 |
| B 排版尾巴 | `<span>X<span class="nowrap">Y</span></span>`（`cost.batchStepLast` `:242`、`scopeLabel` `:703`）——Y 是**不许断行**的尾巴，不是第二句话 | **保留两个键**，但编辑层并排进同一个弹层（人看到"一处"）。不把 nowrap 变成运营台每次要理解的自造符号 |
| C 句里嵌动态值 | `successSub` 一句里夹着微信号与邮箱（`:634`），中间还插了 `<b>` | **合并成一个键**，值里用 `{wechat}`／`{email}` 占位符；服务端校验占位符必须齐全，缺了拒 |

## 二、本刀做什么

**1）一个渲染 helper：`renderRichText(text)`**（新增 `src/components/site/rich-text.tsx`）。规则只有两条，且**只输出 React 节点，绝不 `dangerouslySetInnerHTML`**：
- `\n` → 断行（`<br/>` 或按容器切成 `.title-line`）；
- 成对的 `**…**` → `<b>`；未闭合的 `**` 按字面显示；单独的 `*` 按字面。
属性类文案（`placeholder`／`aria-label`）**不过这个 helper**——那里的星号就是星号。

**2）内容树合并**：`siteContent.ts` 里 A 类 12 组（7 标题＋4 lead＋hero.copy）共 30 个键 → 12 个键；C 类 `successSub*` 3 键 → 1 键（含 `{wechat}`/`{email}`）。**文字一个字不改**，只改切法与换行/粗体的表达。`siteContentEn.ts` 同步同形，防两棵树漂。

**3）渲染端改造**：`home-view.tsx` 对应 12＋1 处改为读单键并走 `renderRichText`；`.phrase`/`<wbr/>`/`<br/>` 从这些位置撤下（B 类那两处的 `nowrap` 尾巴**保留**）。

**4）编辑层**：一个段落＝**一个多行 textarea**（上一轮标题已这么做，这轮扩到 lead／hero.copy／successSub）；框下方给**只读渲染预览**，让写的人当场看见 `**` 变粗、`\n` 断行对不对；`measureFit` 对可折行容器只软提示不拦保存（现状），对 nowrap 行仍拦。

**5）服务端两道新校验**（都进 `createSiteContentDraft` 咽喉，与角色枚举同一处）：
- `CONTENT_MARKUP_UNBALANCED`：`**` 数量为奇数 ⇒ 拒（防把星号漏在页面上）；
- `CONTENT_PLACEHOLDER_MISSING`：`successSub` 那类模板键缺 `{wechat}` 或 `{email}` ⇒ 拒。

## 三、明确不做（附理由）

- **不装富文本编辑器**（Tiptap／PortableText／Lexical）：那要接管渲染树，可行性对照那轮已否过（Puck 同形问题），而且我们只需要两样语法。
- **不引入任意 HTML**：只认 `\n` 与 `**`，其余一律字面。
- **B 类不合并**：见上表，合并等于把排版约束塞进文案语法。
- 不动英文首页读内容树那件事（那是"全站可改"的另一刀，等拍）；不 push、不部署、不翻生产锁、不碰计费／回执／行排除四层。

## 四、验收判据（每条可复跑）

1. `npm run test:content-studio-v1` 源码钉：`renderRichText` 存在且**不含** `dangerouslySetInnerHTML`；`siteContent.ts` 里 `leadA|leadB|copyA|copyB|copyStrong|titleL*` 命中数＝**0**；`home-view.tsx` 同。
2. 行为钉（同一 smoke 内直接调用 helper）：`'a\nb'` → 2 段；`'A**B**C'` → 中间那段加粗；`'A**B'`（未闭合）→ 原样含 `**`；`'a*b*c*d'` 奇数个星号 → 服务端判 `CONTENT_MARKUP_UNBALANCED`。
3. `npm run test:content-studio-draft`：合并后的键仍在白名单内可写；`successSub` 缺 `{wechat}` → `CONTENT_PLACEHOLDER_MISSING`；出厂树本身过咽喉（上一轮那条反向钉继续绿）。
4. `npx tsc --noEmit` RC=0；`npm run lint` 0 errors。
5. 真渲染 `npm run dev` + `curl /`：逐字对比**合并前后页面可见文本必须完全一致**（脚本剥标签取文本，两版取差集＝空），且页面上 `**` 出现次数＝0、`<b>` 数量与旧版一致。
6. 对外主张守卫与 EN 禁写闸复跑（文字未改，理应零新增命中；有命中就是我把句子改动了）。
7. 模拟台同步：lead／hero.copy 也变成单框。

## 五、风险与回退

- **#173 同族，但面更大**：这轮 43 键 → 约 18 键，库里存过**人改值**的旧键会静默回落模板默认（`sanitizeAgainst` 只遍历模板键）。部署前旧键计数判据必须扩到 `leadA|leadB|copyA|copyB|copyStrong|titleL1|titleL2[abc]|successSub*`，命中 >0 先把值搬进新键再部署。
- 回退：改动集中在 `siteContent.ts`／`siteContentEn.ts`／`home-view.tsx`／`home-view-en.tsx`／新增 `rich-text.tsx`／咽喉两处校验，单笔 `git revert` 可退；不涉 DB 迁移、不涉合同四层。
- 一处诚实边界：`\n` 与 `**` 是我们自造的极小语法，业界对应物是 PortableText／Markdown 的硬换行与 marks。选它是因为**只加两样、可校验、可逐字回退**；若以后要行内链接、颜色、字号，就不该再往这个语法上叠，那时才轮到富文本层。
