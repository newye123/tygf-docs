字体排版按字号分档

对现有「每种语言一份排版」模型的只读审查，以及一份可执行的落地案。结论是换模型，不是补控件：字号格锁死、一份 profile 套全稿，所以「按字号选字重」在现有结构里根本表达不了；字距/行距另有四条「设了也不会发、不会用、不告诉你」的断点。

01判定

VERDICT · 打回

不是「字重坏了」，而是现有模型在结构上只允许每种语言一套排版。72pt 标题和 14pt 正文拿到的是一模一样的脸和粗细——所谓「全稿一个粗细」，是模型的必然结果，不是某个开关的 bug。

为什么不是「有条件放行」：在旧面板上再加几个控件，仍然是一份 profile 套全稿，Owner 的核心诉求无法满足；失败仍不可见，等于把「看起来能设」又做一遍。为什么不必紧急回滚：排版失败不会推翻文本替换（TYGF_V15_Thin_Executor.jsx:47-48 明确「排版是偏好，替换才是承诺」），也不碰计费与回执，可按正常节奏替换。

本轮能直接修好的

  • 三条已实现、只差接线：自动字距（度量/光学）、伪粗、伪斜。助手白名单收了、执行器写了，浏览器从不发送，开关永久禁用。
  • 百分比行距：助手与执行器都支持，但下拉框第一次切不过去，映射层也只发固定值。
  • 失败可见：执行器已经产出排版失败清单，只是没人消费；补逐层证据与界面摘要即可。
  • 预览保真：把脸名里的样式词映射成真实 CSS 字重，Medium 与 Bold 才看得出差别。

必须换模型才能做到的

  • 按字号选字重：现存储是「每语言一份」，不是「每语言一组阈值档位」。不改形状，任何 UI 都只是换皮。
  • 字号不能当编辑项：改字号会重新折行，牵动行数判据与溢出预估；本版只把原稿字号当「选档依据」。
  • 同字号不同角色：14pt 的标题与 14pt 的正文，本轮无法区分；这要按图层覆盖，单独立项。

02现象 → 根因

「改字体只能全部改成一个粗细」

已证实 · A

浏览器只按语言取一份 profile（typography-persistence.ts:232-240），单语言与批量派发各取这一份（local-assistant-client.ts:1500、:2005），执行器再把它套到每个文字层（TYGF_V15_Thin_Executor.jsx:221）。同时字号格在界面上是死的（typography-panel.tsx:456-457），能力表标「未实测」（typography-capabilities.ts:81-85），助手白名单把 fontSize/size 列为锁死键（typography-profile.js:25-29）。

失效场景：同一篇稿 72pt 标题、24pt 小标题、14pt 正文。选一次 Bold，三层全 Bold；选 Regular，三层全 Regular。没有第二个维度能表达「大字号重、小字号常规」。

「字距、行距设了没用」——这不是一条，是四条

已证实 · A

① 没点「保存到本机」＝执行时完全不读。保存只发生在 typography-panel.tsx:331-344，而派发只从 localStorage 读（typography-persistence.ts:232-240），全链路没有「未保存草稿」的提示或拦截，入口上只有一个脏点（workbench-view.tsx:3238、:3593）。

② 百分比行距第一次选不到。typography-panel.tsx:461-470 只有「沿用/固定pt」，percent 选项仅在当前已是 percent 时渲染（:469）；即便存了，映射层也只发固定值（typography-persistence.ts:158-165）。而助手与执行器其实都支持百分比（typography-profile.js:5、TYGF_V15_Thin_Executor.jsx:92-94）。

③ 排版失败没有界面消费者。执行器产出了 typographyRequested/typographyIssues（TYGF_V15_Thin_Executor.jsx:258-259），但全仓检索只有执行器自身、server.js:1428 一行注释、smoke-typography-wiring.mjs:144 的字符串断言三处；runner 不读回，回执与 attempt 状态都没有，界面自然看不到。

④ 字体清单读不到时，手填脸名也被关。手输框只在 faces.length > 0 时渲染（typography-panel.tsx:754），输入的名字不在清单里就立刻清空 face（:764-773），与设计注释「清单读不到仍可手填」相反。

「视觉等等这些无法使用」——要分两类，不能混

实现已存在 / 本版写不进

已实现、只差接线：autoKerning、fauxBold、fauxItalic。白名单收了（typography-profile.js:24），执行器写了（TYGF_V15_Thin_Executor.jsx:73-85、:122-131），但浏览器的 profile 形状没有这三个键（typography-persistence.ts:52-57、:149-167），面板上的 8 个开关全是禁用态（typography-capabilities.ts:162-211）。

本版 PS 确实写不进 / 不该写：水平/垂直缩放、基线偏移、消除锯齿、语言、大小写、下划线/删除线。这些不拿「未实测」含糊过去，直接写进「不做什么」。

预览本身会把「字重分档」做废

已证实 · A

previewStyle（typography-panel.tsx:72-87）只把 bold 映射成 700、italic 映射成斜体；Light、Medium、SemiBold、Black 全按 400 渲染，固定行距直接按原始 px 套在 14px 样例上。

后果：即使后台真的按档位写了 Medium 与 Regular，预览看起来也完全一样，Owner 仍会得出「还是只有一个粗细」。所以预览保真是验收项，不是美化。

05目标与验收

一句话目标

在同一种语言的一次执行里，排版偏好必须能按原稿字号分档，逐档决定字体脸、字距、行距、自动字距、伪粗/伪斜；执行后能逐层读回，并把失败在界面上说清。

1

三字号夹具

72/36/14pt 一次执行后，三层分别得到三档设定的脸/字距/行距；本地回执里有逐层 sizePt / tierId / face / tracking / leading 的实际值与读回值。

2

失败不再静默

故意给某一档一个本机不存在的脸名：文本替换仍成功；结果面明确显示「第 N 层字体被替换为 MyriadPro-Regular（FONT_FALLBACK_APPLIED）」。

3

旧偏好不丢

老版本（v1/v2）保存的单一 profile 升级后仍原样应用（迁移为「默认档」），不清空、不改变行为。

4

行距两种模式都精确

百分比 120%：24pt 层读回 autoLeadingAmount=120；固定 18pt：读回 leading=18 且 useAutoLeading=false。

5

字距与视觉项读回

字距 −50‰ 与 +200‰ 读回精确相等；自动字距 METRICS/OPTICAL 读回成功；伪粗/伪斜读回 true。

6

手填脸名可用

字体清单为空时，手输合法 PostScript 脸名仍能发送；执行后读回失败必须报告，不得清空输入或假装成功。

7

未保存不再被忽略

要么自动保存并读回，要么执行前明确拦下并给「保存并执行 / 不保存继续」。

8

预览肉眼可分

Light/Medium/Bold 必须肉眼可分；浏览器没有该字体时，明说「预览不可用」，不许拿 400 冒充。

9

测试全绿且有负控

现有 5 组排版测试继续全绿；新增测试覆盖档位校验、匹配、迁移、映射、结算一致性、失败归因，且能在旧执行器上变红。

10

真机验收

测试站真机跑完整批；生产部署前由 Owner 明确点头。

06方案：按字号阈值分档

为什么用阈值，不用区间

每条规则写「≥ X pt 用这套」，按 minPt 从高到低匹配，最后永远有一个「默认档」兜底。这样不会出现区间空档，也不会因为两个边界写反而漏层。

// 浏览器本地存储 v3（键仍是 tygf:v15:typography，读得动 v1/v2）
interface TypographyRule {
  id: string                 // 'r1'…，稳定
  label: string              // '大标题' / '正文'，用户可改
  minPt: number              // ≥ 1，≤ 2000；规则按 minPt 降序
  profile: TypographyProfile // 现有字段 + autoKerning/fauxBold/fauxItalic
}
interface TypographyTiersByLanguage {
  version: 3
  rulesByLanguage: Record<string, TypographyRule[]>
  fallbackByLanguage: Record<string, TypographyProfile | null>
}

迁移：读到 v1/v2 的单一 profile 时，rules=[]、fallback=那份 profile。语义与今天完全一致（所有字号都用它），用户不会「升级完发现设置没了」。

下发体（助手侧）

{
  "typographyTiers": {
    "version": 1,
    "rules": [
      { "id": "r1", "label": "大标题", "minPt": 48,
        "profile": { "face": "NotoSansSC-Bold", "tracking": -20,
                     "leading": { "mode": "percent", "value": 110 },
                     "autoKerning": "METRICS" } },
      { "id": "r2", "label": "小标题", "minPt": 20,
        "profile": { "face": "NotoSansSC-Medium", "tracking": 0,
                     "leading": { "mode": "fixed", "value": 24 } } }
    ],
    "fallback": { "face": "NotoSansSC-Regular", "tracking": 0,
                  "leading": { "mode": "follow" } }
  }
}
校验约束（助手强制，浏览器同口径）

rules 最多 8 条；minPt 唯一、降序、1 ≤ minPt ≤ 2000。每条 profile 只允许 face / tracking / leading / autoKerning / fauxBold / fauxItalic；autoKerning 只收 follow/METRICS/OPTICAL；leading 三态；其余键一律拒绝（沿用现有「未知键拒绝」原则，typography-profile.js:51-53）。fallback 可为空（未命中的字号不改排版），但面板必须显式显示「未命中不改」。

匹配语义

执行器写完每层文字后，读该层当前字号，按 minPt 从高到低找第一条 sizePt >= minPt，命中就用它的 profile；都不命中用 fallback；fallback 为空则该层零写入。字号读不出（NaN/null）时用 fallback 并记 SIZE_UNREADABLE，不猜。关键决定：不改字号——原稿字号只做选择器，所以不会因本功能引起重新折行。

链路（兄弟字段，不进执行清单）

Web 面板（按语言 + 按档位编辑）
  → prepare / batch 请求体加 typographyTiers
  → 助手校验器（typography-profile.js）
  → execution-envelope.json 的兄弟字段 typographyTiers（不进 manifest、不改 digest）
  → ExtendScript 执行器按层字号选档，写脸/字距/行距/自动字距/伪粗斜
  → executor-result.json 产逐层读回证据
  → v15-runner 把排版证据挂到本地回执的兄弟字段（同 layoutGeometry 先例）
  → attempt 状态只带摘要（避免 5 秒轮询传大数组）
  → 执行完成界面显示「应用了几层 / 哪几层失败」

为什么不塞进 execution-manifest：清单键集是精确校验的，digest 只算清单（server.js:1430-1434 注释已写明这条边界）；进清单等于改四层合同、报价口径和已有冻结证据。排版是偏好，走兄弟字段即可。

逐层证据（解决「失败看不见」）

{
  "typographyRequested": true,
  "typographyMode": "tiers",

    { "field": "face", "code": "FONT_FALLBACK_APPLIED",

  • 逐层记录上限 500 层；超出只置 typographyTruncated:true，问题计数不丢。
  • typographyIssues 保留聚合计数，但补 layers 样例（最多 20 个 objectId），既看总量也能定位到层。
  • 本地回执挂 receipts.typography；云端回执不动（云端载荷由白名单字段构建，v15-runner.js:1059 起）。test:trust-chain 作为回归闸。

视觉控件与预览

接线

  • 自动字距：面板「沿用 / 度量标准 / 光学」三选一，映射 follow/METRICS/OPTICAL；执行器已有读回逻辑（TYGF_V15_Thin_Executor.jsx:73-85）。
  • 伪粗 / 伪斜：两个开关，只在用户显式打开时发 true；不发 false，避免把原稿本来有的伪粗斜关掉。
  • 百分比行距：下拉框永远提供「沿用 / 固定pt / 百分比」三项；百分比走 autoLeadingAmount，固定走 useAutoLeading=false + leading。
  • SEND_PROBE 加这三个键后，SENDABLE_KEYS 自动变 6 个，能力表和结算条跟着变——现有单源设计的正确用法（typography-capabilities.ts:40-54）。

预览保真

  • 脸名样式词映射到 CSS 字重：Thin 100 / ExtraLight 200 / Light 300 / Regular 400 / Medium 500 / SemiBold 600 / Bold 700 / ExtraBold 800 / Black 900；斜体单独映射。
  • 按该档代表字号渲染；固定行距按「预览基准字号」折算，并在旁边标「预览按 N pt 折算」。
  • 浏览器没有该字体时，不静默退回 sans-serif：显示「本机浏览器没有这款字体，预览不可用；以执行回执为准」。

保存一致性与面板结构

推荐：输入即保存（防抖 400ms），保存后读回比对（现有 saveTypographyProfiles 已做读回），状态显示「已保存 hh:mm:ss」或「保存失败：原因」，保留「立即保存」按钮作为手动确认。若 Owner 不喜欢自动保存，退路是执行前闸：「保存并执行 / 不保存继续 / 取消」。两条都行，但不能维持今天的静默忽略。

  • 顶部：语言页签（现有）。
  • 档位页签：默认（其余字号） + 大标题 ≥48 + 小标题 ≥20 + + 新增档。
  • 编辑区：沿用现有 12 格字符面板，新增自动字距、伪粗、伪斜；字号格显示「原稿字号」但不让改。
  • 本稿字号分布：从 psdSelection.summary.typographyLayers 统计（如 72pt ×2、36pt ×4、14pt ×38），每个字号标「会落到哪一档」；点一个字号可直接建档。
  • 结算条：全局「会发 N 项 / 覆盖 M 层」；每档「命中 K 层」；0 命中给黄色提醒；未命中且有兜底时显示「其余 N 层用默认档」。
  • 手输脸名：始终可用（即使清单为空），只做形状校验；旁边写明「无法核对是否安装，执行时会读回」。
