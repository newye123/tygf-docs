# 工作台四步流程产品规格

> 状态：当前产品真相（基于 Owner 已批准方向；本轮实现仍需最终验收）
> Owner 参考：2026-08-30 上传的 `工作台模拟-现状vs调整后.html`，并与后续更晚的安全修复做过冲突仲裁。

## WF-001 四步含义
1. **准备素材**：选择/扫描设计文件 + 导入译文。
2. **智能检测**：让用户看见检测、自动优化、修正建议和需要确认的事项；不得静默跳过。
3. **设计稿校对**：完成 PSD/译文对账，并在本步骤完成本地助手 / Photoshop 就绪检查。
4. **生成交付**：只负责确认语言、文件名、保存位置、费用并启动真实生成；不得第一次到本步骤才要求用户完成 Photoshop 就绪。

## WF-002 第 1 步引导
- 不提供“上传图片”入口。
- “下载示例表格”保留在导入区右上角。
- 空态必须显示“不知道表格格式怎么办”的短提示。
- 表格格式说明默认展开，并包含多语言/单语言示例。
- 删除不增加信息量的副标题“支持导入表格或粘贴文本生成替换表”。

## WF-003 第 2 步可见性
- 描述以“智能检测 · 当前语言”开头。
- 普通提示不阻断；真实歧义、硬信息风险等 `NEEDS_CONFIRMATION` 必须明确确认后才能继续。
- Smart Review Product Spec 优先：`NEEDS_CONFIRMATION / AUTO_CORRECTED / AUTO_OPTIMIZED / INTERNAL_ONLY` 必须保持可见、可解释。

## WF-004 第 3 步 Photoshop readiness
- Photoshop readiness 属于“设计稿校对”的完成条件。
- 就绪时优先显示单一绿色状态“已连接 · Photoshop 就绪”。
- 展示文字图层 / 可自动替换 / 需人工处理的简洁摘要。
- 详细文字图层默认折叠，减少主流程噪音，但能力不得删除。
- 版本不匹配、未连接、Photoshop 无响应分别显示一个明确状态卡和可执行下一步。
- 不允许同屏重复展示含义相同的版本/连接错误。

## WF-005 第 4 步只负责生成
- 保存位置压缩为键值信息，不重复堆叠防御性说明。
- 显示执行范围、语言与行数、预计费用。
- 就绪时显示一条绿色“点击开始替换后将在本机生成”的状态。
- 新增的批量能力门、服务端权威报价、失败结算和恢复安全逻辑必须保留，即使高保真稿中没有画出。
- **单语言模式的目标语言 = 智能检测阶段选择的当前语言**（当前语言缺失或已被移出语言集合时回退语言列表第一项）；不得固定为语言列表第一项（ISSUES #55，2026-09-18 真机）。

## WF-006 后续明确决定优先于旧模拟稿
高保真稿中“重置只在失败态显示”的视觉方案，不覆盖后续提交 `8e96d83 fix(workbench): restore completion reset action`。成功完成后必须仍有明确的“完成/重置回第 1 步”出口，避免用户被困在已完成项目中。

## WF-007 默认保留
如果高保真稿与后续安全/恢复能力冲突：保留后续安全能力，只调整信息层级、文案和步骤归属，不为了“像稿子”删除能力。

## WF-008 第 2 步信息架构与术语（2026-09-17 UX P1，纯前端 + 文案）
- 阶段头常显两个主动作：「检测全部语言」（批量智能检测；沿用批次预检，整批失败不伪造语言级失败）与「编辑译表」（右侧抽屉只读预览，编辑统一在下方列表，避免双轨编辑互相覆盖）。
- 语言卡（多语言页签）显示每语言状态：已确认 / 有建议 N / 检测中 / 排队中 / 未检测 / 失败 / 结果未知；点卡切换当前语言。
- 检测失败或结果未知的语言提供显式「重跑这一语言」；**不做自动重试**（对齐 `product-specs/smart-review.md`）。
- 批次级错误与语言级错误分层显示；批次状态徽标：处理中 / 已完成 / 部分失败 / 含未知结果 / 已取消 / 启动失败。
- 覆盖披露不变：未覆盖行数在语言行明示，由单次审查上限派生，不得静默。
- 用户语言术语（单一来源 `src/lib/workbench/workbench-terms.ts`）：智能检测｜检测全部语言｜编辑译表｜译表工作稿｜与设计稿对账｜表里多出的行｜设计稿里缺译文的对象｜补一行译文｜保留原文（不替换）｜忽略这行（不写入、不计费）。技术词（batch / reconciliation / missing / unmatched）只出现在报告与对账单。
- 已有能力保留：单语言「智能检测」按钮、确定性审查、确认门、应用建议、导出对账结果/缺译对象清单、对象抽屉与排除/忽略动作均不变。

## WF-009 第 2 步译前版式例外清单（2026-09-19 自动换行工作包 P5，纯前端）
- 「译前版式例外」区块必须可逐条浏览**全部**例外（默认前 8 条，「再显示 N 条」展开；多语言时提供按语言筛选），不得只暴露 Top-N 而把其余藏起来。
- 每行显示：语言｜图层名｜原因（结构缺陷 / 预计超宽 / 字体兜底渲染）｜设计稿行数 → 计划写入行数｜估算最宽行占比｜原稿与译文预览。技术码（STRUCTURE_LOSS 等）不出现在界面。
- 每行提供显式处置「保留原文（不替换） · 所有语言」：复用既有对象级排除决策（`excludedLayerObjectIds` → 冻结进 bindingPlanDigest），作用域是**全部目标语言**（objectId 级，不分语言），按钮与提示必须如实写明；再次点击撤销。除用户显式点击外不得自动排除任何对象。
- 交付报告（F1 未覆盖节）必须提供**待译清单导出**（CSV：完整原文 + 图层 + 原文行数 + 各受影响语言空列），用户填完可当译文表直接重新上传；该导出只读自"未覆盖对象"同一判据，**不得另立第二套口径**，也不参与计费与摘要。
- 例外条数超过清单上限时明示「另有 N 处未列出」，统计数字仍含全部，不得静默截断。
- 本区块只提示与交由用户决策，不阻断下一步，不改计费口径（计费仍按译表行数）。

## WF-010 工作台减法第一片 C1（2026-10-03 L2 `changes/active/20261003-workbench-reduction.md`，纯前端＋文案来源）

- **流程仍是四步**。"四步→三步"是**目标态、分阶段推进**，未拍板前不得当作既成事实写进界面或本规格；本片（C1）只做两件事：删 workbench 段死文案键、去掉两套重复渲染（卡头步骤数字徽章、步内「上一步」）。
- **本片一个用户能力都不删、不隐藏、不合并**。判"重复"的口径：两处的**动作与防护都等价**才算重复；等价性给不出证据的（例：步内按钮带 `disabled` 而底部条没有、或两处启用条件不等价）一律不删，写进变更单 §6 待拍板。
- 步骤指示单一来源＝左侧导轨 `stage-rail.tsx`；卡头不再重复显示步骤数字/勾。
- 步内导航单一来源＝底部操作条 `WorkbenchActionBar`（`prevStage` 有值时给出「上一步」；主按钮为唯一前进动作）。
- 屏幕文案的取值路径记牢：`src/lib/workbench/site-copy.ts:43` 是 `{ ...siteContent[section], ...override }`——**库里覆盖赢**，所以"改文件默认值"不等于"改屏幕"；任何要求"改文案必须上屏"的门禁若只核文件默认值，属门禁缺口（归 WB-TAP-GATE），不得反过来当已生效证据。
- **本次减法的验收指标（第二指标）＝用户完成一次交付全程的动手次数 ≤5**。第一指标仍是 Owner 定的"首跑成功率"（2026-09-25 15:4x 定），本指标不得取代它。
- 硬编码中文串须收回文案键（本片先收 `execute-step.tsx` 提交态那两条），三处并存（`siteContent.ts` 默认值／`workbench-terms.ts`／组件内硬编码）是"改了不生效"的根因，归并属 C2。
