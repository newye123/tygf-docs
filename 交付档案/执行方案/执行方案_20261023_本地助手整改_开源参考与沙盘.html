0代码 / 部署 / 出包改动

这三件本轮就要做

  • P1-A 证据重算：把逐对象证据发上云端，服务端自己算摘要；空对象数组、空摘要、缺对象、重复对象一律拒收。
  • P0-C 发布闸隔离：生产路径无条件拒绝未签名；beta 走独立目录与独立 manifest。不是删一个 flag。
  • P0-A + P0-B 同一次发布：ACL 按进程 SID 授权并启动自愈；状态机区分五种状态，读不到绝不写。

这三件不要做

  • 不换加密：现有 AES-256-GCM 不是故障原因；DPAPI 在同用户下仍可被解密，还会新增“解不开”的故障。
  • 不上 SQLite：打包目标是 node18-win-x64，模块不在；单文件状态也用不上。
  • 不做混淆 / 加壳：逆向工程趋势已证明收益低，还会伤自家可诊断性。
本轮最重的一条

云端回执只发了摘要、没发对象数组（v15-runner.js:1078-1095）；空数组的 sha256("[]") 是 4f53cda1…02b945，一个合法的非空字符串，能直接过现在的收费闸（execution-batch.ts:1388）。被改过的客户端不需要伪造内容，发这个哈希加一行 VERIFIED 就能结算。

04执行方案：顺序不能换

P0-A 与 P0-B 必须同一次发布：只修 ACL，状态机还会在别的故障下覆盖配置。P1-A 是“被改的客户端能不能白拿钱”的开关，不是安全加分项。

0.5

身份核对（5 分钟，阻塞其余）

客户机跑 /ping、读 release-identity.json、验安装包签名；buildId 与出厂件不一致就先升级再谈行为结论。

A

ACL：按进程 SID 授权，启动自愈

  • 绝对路径 whoami.exe 取进程 token SID，失败再走 PowerShell；两者都失败就跳过收紧，记 ACL_SID_UNAVAILABLE。
  • 先 /grant:r *SID:F，回读确认后再单独 /inheritance:r；两步分开。
  • 在 loadConfig() 之前对当前与 .bak 各跑一次自愈。
  • 永远不再用 process.env.USERNAME 作为 ACL 目标。
B

状态机：五种状态，读不到绝不写

  • OK / MISSING / UNREADABLE / CORRUPT / DECRYPT_FAILED。换机器要单列，否则会被当成“损坏”隔离掉。
  • UNREADABLE：自愈后仍读不到 → 打印 CONFIG_UNREADABLE 并退出，不调 ensureMachineId / saveConfig。
  • CORRUPT：当前与 .bak 一起改名留证；DECRYPT_FAILED：不动文件，明确提示。
  • 写盘改成“新备份先立、旧备份后破”；start() 的 ensureMachineId 包 try/catch，别再以未捕获异常崩掉。
C

发布闸：先隔离 beta，再补证书

  • 生产路径无条件拒绝未签名，没有任何 flag 能写生产 manifest。
  • 新增 --channel=beta：独立目录、独立 manifest、独立下载页。
  • installer.iss 加 SignTool、SignedUninstaller=yes、[Files] sign，覆盖四件。
  • 证书按个人 OV 询价；代码闸本周可落，证书时间不承诺。
D

回执：ACK 墓碑 + 恢复分类

  • 墓碑放独立 receipts-acked/，不要放 pending 目录（那里会扫描所有 .json）。
  • 恢复日志拆成 ACKED_SKIPPED 与 COMPLETION_UNKNOWN。
  • 现有 24 条先只读分类，不自动删、不自动重投。
1A

证据摘要：把对象发上去，服务端重算

  • 载荷增加 objects：{objectId, layerId, actualTextDigest}，就是现在被哈希的那三项。
  • 服务端用同一套规范化重算并比对。
  • 空集、空摘要、重复 objectId、非 64 位 hex、摘要不符、VERIFIED 行缺对象，全部拒绝或降级。
  • 负控包含 sha256("[]") 这一条：修复前能过，修复后必须 422。
1B

本地 HTTP：Host 白名单 + PNA + Vary

  • cors() 补 Vary: Origin；预检按需回 Access-Control-Allow-Private-Network: true。
  • Host 只接受 127.0.0.1:49152、localhost:49152、[::1]:49152，其余 421。
  • 打包版移除 localhost:3000 默认回退；isLocalDevServer 在打包版恒 false。
2

逆向相关的取舍：不写“防破解”

  • 不做混淆、加壳、反调试；保留中文错误文案。
  • 威胁模型改写为“本机管理员可读可换程序；我们只保证结算不被伪造、分发可验真”。
  • --self-test-assets 只证明没有明文 JSX，不证明 server.js 不可读。

机理：静态重编译 + matching + AI 辅助

把机器码翻成语义等价的源码，再用编译器逐字节验证；AI 把“读二进制”的单位成本打下来。它没有改变可能性，只改变了成本曲线。

结论一：护城河不在客户端

pkg snapshot 有公开提取工具；资产移除合同只保证包里没有明文 JSX。把预算花在混淆上，回报接近零。

结论二：判定权必须在服务端

P1-A 直接决定“被改的客户端能不能白拿钱”。先做它，再谈其它加固。

结论三：签名管“谁发的”，重算管“是不是真的”

P0-C 与 P1-A 缺一不可，也不能互相替代。签名挡不住本机管理员改程序；重算挡不住换掉整个客户端——但能让它拿不到钱。

一条反向收益

公开实现变多，PS 自动化、字体回退、排版写回都可以读行为、做对标。但许可不明或 AGPL 的代码不要复制进产品。

07不做清单与未决

不做

  • 不换加密、不上 SQLite、不引入 write-file-atomic。
  • 不做混淆 / 加壳 / 反调试。
  • 不自动删、不自动重投那 24 条回执。
  • 证书到位前不发“正式版”。
  • 不拆客户过渡件，先在那台机器连续重启验证。
  • 不给浏览器发客户端证书。

未决（缺什么证据）
