## 0. 结论与依据（已核实）

- **服务端零改动即支持多绑定**：每账号激活 upsert 出自己的 AUTO-DEVICE 码（`pair/route.ts:105-123`），兑换唯一键是（码，机器）（`:157-165`），maxMachines=1 按**账号**计——同一机器挂多个账号的码并存合法，令牌按（机器,码,exp,jti）签发（`:252`）。
- **堵点两处，全在客户端**：①助手存储 `assistantAuthorizations[origin]` 单槽，配对即覆盖（`server.js:3855-3873`）；②验票取槽不看请求来自哪个账号（`server.js:2797 authorizationForOrigin(loadConfig(), cloudBase)`）。
- **选槽钥匙现成**：工作台多数请求体已带 `anonymousInstallId`（`local-assistant-client.ts:629/864/1368` 等）；票据签发也含安装号。缺的只是「所有助手请求统一带」＋「助手按它选槽」。

## 1. 改动设计

### 1.1 新模块 `download/local-assistant/authorization-store.cjs`（纯函数，仿 pair-completion.cjs 先例）

```text
数据形（每 origin）：
{ token, expiresAt, activationId, installId,            // 镜像＝最近一次（旧版兼容读）
  bindings: { [installId]: { token, expiresAt, activationId, savedAt } } }  // ≤3，超限按 expiresAt 最旧逐出

函数：
loadSlot(stored, installId?)   // 有 installId 且命中→该槽；否则镜像（=旧行为）
saveSlot(stored, {token,expiresAt,activationId,installId})   // 写入 bindings+更新镜像；不覆盖其他账号
migrate(raw)                   // 旧单槽形→新形（旧槽入 bindings.legacy），幂等
countBindings / listBindings   // 状态展示用（authorization/check 回显）
```

### 1.2 `server.js` 接线（最小面）

- `saveAuthorizationForOrigin(origin, token, expiresAt, activationId, installId)`：经 store 写入（迁移后保存）；**配对（/pair, :5018 附近）把 body.anonymousInstallId 传入**——从此配对＝加槽，不顶人
- `authorizationForOrigin(cfg, origin, installId?)`：经 `loadSlot` 取；无 installId＝镜像（兼容旧前端）
- `verifyTicket`（:2797）与 `authorization/check`：从 `x-tygf-install-id` 头或 `body.anonymousInstallId` 取钥匙传入；两处都没有→现行为
- `activationSnapshot` 支持 installId 维度（check 回包带 per-install 状态与绑定数）
- **判定语义零改动**：选错槽/无槽仍是现行错误码（MISMATCH/TOKEN_MISSING）——多绑定只解决"该亮哪枚"，不放松任何校验

### 1.3 前端 `local-assistant-client.ts`

- 请求辅助函数（所有助手 fetch 的公共出口）统一加头 `'x-tygf-install-id': installId()`——一处改，全端点生效；无激活态时不加（现行为）

### 1.4 兼容矩阵（必须成立）

| 前端 | 助手 | 行为 |
|---|---|---|
| 新 | 新 | 多绑定全功能 |
| 旧 | 新 | 无头→落镜像槽＝旧行为 |
| 新 | 旧 | 头被忽略＝旧行为（单槽互顶，不更坏） |
