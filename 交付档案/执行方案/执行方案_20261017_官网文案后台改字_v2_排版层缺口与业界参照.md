## 线上实测：为什么"最基本的"其实是最深的坑（五个）

**坑一 断行不是文案，是 JSX 结构。** 「改一个语言不难／难的是每个语言都要一起改」这句标题在代码里是 `titleL1` + `titleL2a` + `<wbr />` + `<span class="phrase">titleL2b</span>` 四个东西（`home-view.tsx:210`，同形还有 `:256`、`:608`）。断点在 `<wbr/>` 上，不在字符串里——你把 `titleL2a` 改长，断点不会自己挪，只会溢出。首页这种"半句话"键有 **33 个**（占 95 键的三分之一）。

**坑二 回车被 CSS 吃掉。** 线上 `.hero-copy` 计算样式 `white-space: normal`；我把它的文本换成带 `\n` 的两行，实测高度从 105px（3 行）变成 **35px（1 行）**——回车被当普通空白折叠。服务端不剥 `\n`（只剥零宽、拒双向控制符），于是"存进去了但看不见"的静默失效。全站 `white-space:pre-*` 命中 **0**。

**坑三 改长就裁字。** 首屏大标题那行 `.hero-title-line{white-space:nowrap}` 写死（`home-v17.css:80`）。线上实测：原文 7 字宽 597px，改成 11 字后 `scrollWidth` 799px ⇒ **溢出 202px（约 34%）**，而文档宽 1266px < 视口 1281px ⇒ 不出横向滚动条，字被切在容器外。编辑框里**没有任何预警**。

**坑四 新标记会撞既有门。** `smoke-seo-consistency.mjs:351/:363` 断言「JSON-LD 里每条 FAQ 问/答都必须能在页面文本里找到」＋「可见 FAQ 条数＝结构化条数」。文案里带 `\n` 或 `[[不折行]]` 而渲染端原样输出，比对就红。所以标记必须**在 JSON-LD 侧剥离、在渲染侧解析**，两处同批改。

**坑五 没有 HTML 渲染口（这条是好消息）。** 站点组件里唯一的 `dangerouslySetInnerHTML` 是 JSON-LD（`(zh)/page.tsx:97`，且转义了 `<`）。⇒ 方案不能靠"让运营写 HTML"（XSS 面 + 绕开所有守卫），只能"受限标记 → 解析成 React 节点"。

## 业界七家怎么做到的（件里每家一张卡：数据流 + 配置项原名 + 换行/排版 + 映射到我们）

**Sanity（硬换行语义最干净，第一顺位抄）。** `@portabletext/react` 的 components 里有 `hardBreak` 一项，README 原文：「Component to use for rendering 'hard breaks', eg `\n` inside of text spans. Will by default render a `<br />`. Pass `false` to render as-is」。⇒ **换行就是内容里的 `\n`，渲染端唯一序列化器负责出 `<br/>`**。排版角色＝`styles` / `lists` / `marks.decorators` 三张 `{title, value}` 枚举表，开发者写死、运营只能选；decorator 的 value 可以自定义成 `nowrap` 这类排版角色，运营全程碰不到 CSS。结构变更走 array 的 rows/grid + `sortable` + `disableActions:['add','remove','duplicate',…]` 逐项关权限。没有叫 `breaks` 的开关、没有 `text-break` style（查不到＝未核实）。

**Payload（能力白名单最明确，第二顺位抄）。** 存 Lexical 节点树 JSON，官方转换器一整套（`lexicalToJSX` 等）。白名单写法是 `features: ({defaultFeatures}) => [...]`——**数组就是最终能力集，删掉即禁用能力，不是隐藏按钮**；字号枚举 `HeadingFeature({enabledHeadingSizes:['h1','h2']})`。硬换行**没有官方 feature**（源码 features 目录实测无 linebreak 项），换行来自 Lexical 核心 `LineBreakNode`，Payload 既不给按钮也不给开关。**反面教材**：`TextStateFeature({state})` 官方原文"在 TextNode 内存 key-value 属性并赋内联样式"，默认关闭——这就是"让运营改内联样式"会长什么样。结构：Blocks 抽屉/复制/拖拽（`isSortable:false` 可关），array 有字段级 `minRows/maxRows` + `validate` 返回错误串。

**Tina（与我们同构，抄白名单别抄换行）。** `data-tina-field={tinaField(data,'title')}` + `useTina` ⇒ 和我们 `sc('homeV17.hero.titleLine1')` 完全同形，证明这条路不是野路子，也证明它是三条路里最贵的（无自动发现，嵌套与重复项都要手标）。硬换行：官方原文按 **Shift+Enter** 插入，存盘后 markdown 里表现为**独立一行的 `\`**，并明写"这不是标准 markdown，是 Tina 特有行为"；那个 `\` 渲染端是否还原成 `<br>`＝未核实 ⇒ 正是要避开的"私有约定"。白名单：字段属性 `toolbar: ToolbarOverrideType[]`，官方示例就是"只给三个" `toolbar:["heading","bold","italic"]`；排版角色只有 `headingLevels` 这类受控枚举，无 class 选择 API（未核实）。

**Apostrophe（排版角色的官方实证，角色枚举抄这家）。** `<Area doc name="main"/>` + widget 调色板；官方原话多数 widget「are edited in a dialog box when the user clicks on the edit button」⇒ **页面上只做结构操作，改内容进弹窗**——"就地 vs 表单"不是二选一，是按动作分。关键先例：富文本 `styles` 支持 `{label, tag, class}`，官方例 `{label:'Centered heading', tag:'h2', class:'centered'}` ⇒ 运营选"居中标题"这种角色，选不到 CSS。工具栏白名单逐字里**没有 br/break**。

**Keystatic（抄 `softBreaks` 这个概念）。** 存 git 文件（`.mdoc`），admin UI 挂 `/keystatic`（它自己的 React 页），不是站页面。值钱的一条：`fields.child` 官方原话「embed an editable region inside of a component block preview」，`kind:'block'|'inline'`，配置里有 **`formatting: { inlineMarks, softBreaks }`**——**"换行"在他们那儿是一个字段能力开关，不是"运营自己按回车碰运气"**。多行纯文本正解是 `fields.text({multiline:true})`。

**Decap（这层不抄，但它印证了一件事）。** widget 配置项准确名 `buttons`/`editor_components`/`modes`/`minimal`/`default`/`sanitize_preview`（没有 `formats`），默认按钮清单里**没有换行**。它的 `publish_mode: editorial_workflow`＝草稿开 PR、approve＝合并删分支——那是给多人+审稿人设计的，单人改官网等于给每次改字加一次 git 操作。反过来它也证明：**"生产禁写、走代码合入"是一条正经路线，不是偷懒**。

**Statamic + 底层 Tiptap（只抄 HardBreak 这一手）。** 官方 Live Preview 是控制屏 iframe，不是页面就地改；Bard 按钮白名单（源码 `fieldtypes/bard/buttons.js`，6.x）逐字里**无 hard_break**，可 `Bard::setDefaultButtons(['h2','h3','bold','italic'])` 收窄。硬换行能力在底层 Tiptap 的 `HardBreak` 节点扩展里 ⇒ 上层 CMS 默认都不给换行按钮。`marks`/`sets` 作为配置项名＝未核实（文档页 JS 渲染抓不到）。

**七家合起来的三条硬结论。** ① 换行必须是**内容数据 + 唯一序列化器负责**（Sanity `hardBreak` 最干净，Tina 的私有 `\` 是反面，Statamic/Apostrophe/Decap 干脆不给按钮）。② 排版给**角色枚举**，永远不给样式输入（Apostrophe `styles{label,tag,class}`、Sanity `{title,value}`、Payload `enabledHeadingSizes`；Payload 的 `TextStateFeature` 是官方自己标"默认关闭"的反面教材）。③ 能力要**一处声明、删了就是禁用**（Payload `features`、Sanity `disableActions`、Tina `toolbar`、Bard `setDefaultButtons`）——我们现在"纯文本、不支持加粗"是一句注释，不是一份声明，所以谁都能下次改动里悄悄放开。

## 三种可抄范式与选择

- **甲 字符串 + 受限标记（推荐）**：仍是字符串叶子，`"难的是每个语言都要\n[[一起改]]"`，`[[ ]]`＝不折行短语、`** **`＝强调。编辑面加三个按钮 + 实时预览。**零迁移**：95 个键形状不动。
- **乙 结构化 segments 数组**：最干净，但要把 33 个碎片键合并 + 数组写回 + 结构级 diff，3—5 天且撞合同变更纪律。
- **丙 排版角色枚举（select）**：`role: h1-line | lead | chip` 映射到既有 CSS 类。解决"字体/字号"，与甲正交，可后置。

**推荐甲 + 丙最小集。** 全站一款思源黑体 + `clamp()` 字号是设计语言的一部分，给运营自由填字号＝把首页变成 Word。

**但甲有个必须一起处理的副作用（业界也提醒了）**：把断行写进内容＝断行点从此与视口无关。桌面断得刚好的一句，到 390px 手机上可能断成三行还带空洞。三条应对：① 换行点按视口降级（窄屏改回自动折行）；② 该角色用 `text-wrap:balance`（我们 `home-v17.css:79/:82` 已经在用）；③ 只允许"不折行短语"不允许自由断行。**建议 ①+② 混做**：大标题行保留手动断行但按视口降级，正文段一律自动折行。

## 执行顺序（排版层提到第一刀，且不需要先动生产锁）

**刀一 排版层最小可用（估 2—3 天）。** 五处同批改：① 渲染端 `renderCopy()` 纯函数（`\n`→`<br/>`、`[[..]]`→`.phrase`、`**..**`→`<strong>`）；② CSS 让 `.hero-title-line` 的 nowrap 由数据决定；③ **每键声明是否允许软换行**（抄 Keystatic `formatting.softBreaks`：大标题行允许、按钮与小标签不允许）+ 换行点按视口降级；④ JSON-LD 侧剥离标记（否则 `smoke-seo-consistency:363` 直接红）；⑤ 服务端 PATCH 长度上限按**剥离标记后的可见字数**计，标记白名单**一处声明**（抄 Payload"数组即能力集"：出现 `<`、未闭合 `[[`、非白名单符号即拒；删按钮＝禁能力而不是藏 UI）。

验收判据：`npm run test:seo-consistency` 0 FAIL；`test:content-studio-v1` 新增标记语法用例（负控：`<b>x</b>` 被拒、`[[a` 未闭合被拒、不允许软换行的键带 `\n` 被拒）；浏览器三档视口（1280/768/390）实测——桌面按手动断行、390px 自动折行且无横向裁字；预览预警与线上实际一致（用 `scrollWidth>clientWidth` 与行数对角色预算判定，不是估算）。**这一刀全部在渲染与校验层，做完即可在测试站验证，不需要动生产写锁。**

**刀二 把 33 个碎片键合并成整句（估 1—2 天）。** 做完才叫"能自己断行"。风险：键名变更会让线上已存旧值失配（白名单按"当前内容树的字符串叶子"算）⇒ 必须走"新键并存 + 自愈迁移"，不能直接改名。判据：迁移后 ACTIVE 树里碎片键数＝0，首页渲染像素级不变。

**刀三 排版角色 select + 漏标 lint 守卫（估 2 天）。** 角色枚举让运营在"大标题行/副标题行/小标签"之间选；守卫抄 `eslint-plugin-i18next` 的 `no-literal-string`。

**刀四 结构编辑（FAQ 增删排序）。** 仍排最后——没有它照样能用，你要的"最基本"不在这里。
