# tuyigf.com V10 全站 UI/UX、文案与工程执行方案

时间：2026-10-31。当前产物：可直接浏览、切换和操作的前端模拟，不影响线上站点。

## 产品叙事与策略取舍

高频目标用户：需要在可编辑 PSD / PSB 中批量制作多语言商品详情页的设计团队。前提：已有译文、Windows 和 Photoshop 环境。

官网的第一价值目标是让访客在十秒内回答三个问题：它处理什么、我需要准备什么、我能拿到什么。第二价值目标是展示典型难题，包括重复原文、长译文、缺失译文、字体与版式差异、人工终检。第三价值目标是通过实际操作建立可信度，再促成高匹配试跑。

主标题：译文已经有了，PSD 还要逐个语言改？
副标题：导入设计稿和现成译文，匹配文字图层，批量制作不同语言版本。每份 PSD、每个语言都能分别指定字体、字号、字距和行距。有歧义的地方集中确认，交付前逐项核对。
主 CTA：看看具体怎么用。
次 CTA：体验独立字体配置。

## 工作台 UI/UX 决策

工作台使用稳定的左侧导航、右侧密集表单与内容区，避免营销页浮动装饰干扰数据操作。对象之间保持项目、文件、语言、字符规则、任务、异常、交付记录的关系。

字体样式优先级：单文件 × 语言覆盖 > 语言默认 > 保留源文件参数。当前前端允许字符参数：字体家族、字号 pt、字距 tracking（1/1000 em）、行距 pt、自动字距（保留、度量、视觉）。规则保存后提供矩阵总览与任务创建快照。真实工程必须将“已保存配置”和“Photoshop 已应用”区分为不同任务事件。

每条状态都需要语义文字：待处理、待确认、执行中、失败、模拟完成、人工已通过。单靠颜色不能体现安全性。

## 工程对接工作包

### P0：适用范围与真实源文件（必须先做）
- 统一 PSD/PSB 图层扫描器数据结构：文件 id、路径（尽量避免无关路径上传）、图层稳定 id、组层级、文字内容、编辑状态、字体与字符段落结构。
- 建立字体枚举接口：Windows 安装字体、Photoshop 可用字体和缺字覆盖。网页模拟的字体名单不能作为生产依据。
- 版本兼容测试：Photoshop 2021 及更多明确验证版本；智能对象、嵌套分组、混合样式和大文件。

### P1：规则与执行引擎
- 将字符设置存在明确层级：项目 -> 文件 -> 语言 -> 对象（如未来支持单层覆盖）。
- 规则 version 与任务 snapshot 冻结，避免后续修改影响历史审计。
- Photoshop 执行后读取结果、保存、重新打开，分别产生日志与状态。
- 对无法可靠匹配的对象使用人工确认，避免静默猜测。

### P2：正式官网和后台联调
- 使用真实后端替换申请表、登录、项目、导出和账单接口。
- 将单文件 hash 模拟路由改成可独立索引的生产路径，提供各页面标题、描述、canonical 和站点地图。
- 加入可访问性和法务审核，尤其是数据上传、第三方文本模型、字体设置的存储位置和数据删除。

### P3：可信宣传材料
- 录制真实 Windows + Photoshop 演示：导入、匹配、字体矩阵、人工复核、执行与交付。所有模拟录屏标注不可作为性能证明。
- 获授权 PSD Stress Test 样本，覆盖字体缺失、德语长词、日语禁则、多语言对比、批量中断与重试。
- 用同一文件与翻译表统计人工准备时间、处理干预、终检、返工时间，对比总人工时间，而非单纯引擎处理速度。
- 将已验证的功能、数据和真实客户案例更新到首页与实测页。

## 转化衡量

埋点建议：首屏 CTA、四步页访问、字体矩阵进入、字体规则保存、任务向导开始、向导完成、有效试跑申请、首次真实任务完成且通过终检、重复使用。将访问到申请、申请到实际试跑、试跑到第二次使用分别观察。
