## 3. 二次核对发现

### 3.1 348 是写入操作数，不是唯一图层数

替换明细表共 348 行，每种语言 29 行，合计 12 × 29 = 348 次语言 × 对象写入操作。报告同时记录 37 个唯一文字对象，其中 8 个未覆盖对象。因此可推算 29 个对象与译文表匹配，37 - 8 = 29。该 29 是结构推算值，原报告没有独立字段直接写出。

### 3.2 疑似未翻译汇总与明细不一致

按替换明细逐行比较原文和译文，严格相同的记录为 79 条。分语言核对后，除日语外，其余 11 种语言均为 7 条；日语明细为 2 条，而汇总表为 6 条。因此汇总 83 与明细 79 相差 4 条，差异集中在日语。不能把 83 或 79 直接当作漏翻数量。品牌、型号、材料和规格信息可能被有意保留。

### 3.3 规格值需要确认

替换明细中，图层 ID `6350` 的原文包含 `80.0g / 2.8oz`。12 种语言的目标文本均保留了克数表达，但没有保留 `2.8oz` 数值。该项为基于替换明细的二次内容完整性检查，不是原报告独立统计字段。需要业务方确认省略盎司数值是否符合产品规格与目标市场规范。

### 3.4 版式风险不能直接判定为溢出

40 条版式复核均显示译文比原稿宽，且报告记录行数不变。宽度增加属于风险信号，不能单独证明发生裁切、遮挡或溢出。需要查看 Photoshop 实际渲染结果，并由人工确认。

### 3.5 未命中数据需要分页与来源行定位

原报告汇总 432 条表格侧未命中，但 HTML 中只展开 200 条预览，且没有源表行号。新版报告应显示“432 条汇总 / 200 条可见预览”，并将缺失行号明确标记为未记录，不能补造行号。

### 3.6 两个摘要字段口径未说明

原报告同时显示 8 个未覆盖对象和 0 个未纳入替换。两个字段可能对应不同的业务状态，但原报告没有给出定义。新版 UI 应保留原值并标注口径待确认，不能自行把 0 改成 8。

## 4. 产品与 UI/UX 设计结论

1. 把“写入操作数”“唯一文字对象数”“语言数”“文件数”“风险条目数”分开显示。
2. 把“写入验证状态”和“最终交付状态”分开。12 种语言写入/保存重开验证通过，项目仍处于需复查状态。
3. 将待处理事项分成内容完整性、未覆盖对象、版式风险、译文表未命中、原文保持不变、溯源证据六类。
4. 共享译文表可能带来正常未命中项；必须支持映射、忽略、保留原文和批量导出，不能将所有未命中一律判为错误。
5. 对原文与译文相同的内容支持“确认保留”与“标记漏翻”，并记录人员、时间和原因。
6. 规格、数字、单位、型号与 URL 建立独立内容检查规则。
7. 宽度、行数变化和实际视觉溢出分开记录；机器检测只能产生风险信号，最终视觉验收由人工完成。
8. 交付中心按语言显示 PSB/JPG 状态，并区分“文件名已记录”“文件实体可访问”“保存重开验证”“人工视觉批准”。
9. 溯源信息默认收起，支持按语言展开，保留版本、构建 ID、审查快照、规则版本、清单哈希和 Provenance 摘要。
10. “本地回执未记录未验证对象”不能覆盖其它待复核清单，应以不同区块呈现。
