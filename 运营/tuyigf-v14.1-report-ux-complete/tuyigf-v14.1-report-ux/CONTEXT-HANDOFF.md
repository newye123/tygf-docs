# 图译工坊项目上下文交接总文档

> 本文是新会话或新开发者恢复项目的第一入口。更新时间：2026-10-31。当前项目包：Tuyi Workshop V14.1。

## 0. 30 秒恢复摘要

图译工坊（Tuyi Workshop）是面向已有译文的多语言 PSD/PSB 本地化改稿工具。它将译文表映射到 Photoshop 可编辑文字图层，按“设计文件 × 目标语言”设置字体与字符参数，执行文字写入、验证、保存和交付。产品不负责机器翻译，也不自主重做原设计版式。

当前有三条并行主线：

1. **V14.1 前端与 UI/UX：** 已有可交互 HTML 原型，并新增真实执行报告中心。
2. **报告数据模型：** 已审计用户上传的 2026-10-31 执行报告，发现并标记了统计口径差异和内容风险。
3. **V15 本地生产引擎：** 只有工程方案，真实 PSD 扫描、Photoshop 写入和本地 Agent 尚未实现。

继续工作时必须以本项目包中的文件为准，不要从旧会话摘要猜测版本或报告数字。

## 1. 产品目标与边界

### 产品目标

- 批量处理已有译文的多语言 PSD / PSB 文件。
- 读取可编辑文字图层并提取图层路径、文本和可用的排版元数据。
- 将 CSV / TSV / XLSX 译文表与 PSD 文字对象可靠匹配。
- 按文件、按语言设置字体、字重、字号、行距、字距、基线等参数。
- 在 Photoshop 中执行真实文字写入，并完成读回、保存、重开和预览验证。
- 按语言输出可编辑源文件与 JPG / PNG 预览。
- 输出可追溯的执行报告、异常清单、人工决定与最终视觉验收状态。

### 产品不负责

- 不自动生成或翻译译文。
- 不自主重构或重新设计原有视觉版式。
- 不把浏览器预览当作 Photoshop 实际渲染。
- 不把机器检测信号自动判定为内容错误或视觉失败。

## 2. 用户与生产场景

主要场景：跨境电商视觉设计团队和设计外包团队，需要将已经审核的多语言译文写回 Amazon 主图、A+ 页面、详情页等 PSD / PSB 文件。语言可能包括英语、德语、法语、西班牙语、日语、意大利语、波兰语、韩语，以及项目中实际配置的其它语言。

核心生产对象：

- 源设计文件（PSD / PSB）
- 译文表（CSV / TSV / XLSX）
- 文字对象 / 图层路径
- 目标语言与字体配置
- 每个语言输出文件
- 逐对象写入日志与验证证据
- 最终视觉复核与交付状态

## 4. 本次真实执行报告的事实与口径

数据来源：用户上传的 `图译工坊执行报告.html`，归档在 `reference/original-execution-report.html`。

原报告字段：

- 源文件：(B级)Amazon-5857-主副图-8-祝叶子。
- 更新时间：2026-10-31 08:24:46。
- 总体状态：已生成，需复查。
- 348 已替换文字层；348 计划层数；37 文字层全量；40 版式需复核；8 表内无对应；0 未纳入替换；83 疑似未翻译；432 未命中行。
- 12 种语言，每种 29 / 29，均标记写入完整，保存关闭后重新打开验证通过。
- 输出文件记录 24 个，12 PSB + 12 JPG。
- 8 个未覆盖设计对象保持原文，不计费。
- 表格侧未命中总数 432，HTML 只展示 200 条预览，源行号显示“—”。
- 40 条版式风险全部为“比原稿宽”，行数均不变。
- 本地回执写明“未记录未验证对象”，此句不代表没有其它待处理事项。

二次核对：

- 替换明细有 348 行，12 种语言各 29 行。因此 348 应称为“写入操作数”，不能称为 348 个唯一图层。
- 37 个唯一文字对象减去 8 个未覆盖对象，可推算 29 个匹配对象；这是推算，不是原报告独立字段。
- 原文与译文严格相同的逐条记录为 79 条，报告汇总为 83 条。日语汇总 6 条，逐条明细核对为 2 条，差 4 条。
- 图层 ID 6350 原文含 `80.0g / 2.8oz`，12 种语言目标文本均未保留 `2.8oz` 数值。需要确认是否有意只保留克数。
- 40 条宽度增加只说明存在宽度风险，不能证明实际溢出。
- “8 个未覆盖”与“0 未纳入替换”统计口径未说明。
- 432 条未命中中，只有 200 条在原 HTML 中展开，且无行号。

禁止声称：视觉验收通过、348 个唯一图层、432 条全部错误、83 条都是漏翻、40 条都发生溢出、输出 PSB/JPG 实体随本项目包提供。

## 5. 报告 UI/UX 的当前设计

报告中心分五个区块：

1. 结果概览。
2. 待处理事项。
3. 语言与文件交付。
4. 替换明细。
5. 溯源与证据。

交互包括：替换明细搜索/语言筛选/分页/CSV 导出；未命中预览搜索/语言筛选/分页/CSV 导出；版式清单筛选；交付清单导出；溯源 JSON 导出；打印/保存 PDF。

状态分离：

- 写入回读验证。
- 保存重开验证。
- 待人工视觉复核。
- 人工视觉批准。
- 最终交付完整。

当前报告只能显示前三类中已由报告支持的状态；没有人工视觉批准证据。

## 6. 设计方法：Unslop 融合

参考 https://github.com/heydamir/unslop 。最初讨论建议将 UI Craft 独立能力纳入 YTVPM v4.5.0；本次 Tuyi Workshop 只吸收其审查方法和设计规则，没有修改或发布 YTVPM Skill 包。已吸收“先审查再修改”“视觉方向契约”“九轮精修”“渲染后验收”等思想。方法改编文档在 `docs/UIUX-DESIGN-SYSTEM.md`，报告 UI 具体规范在 `docs/REPORT-UX-SPEC.md`。

核心约束：

- One Screen · One Primary Task · One Focal Moment · One Proof。
- 修改必须有问题证据。
- 保留产品本身的视觉特征，不机械删减渐变、圆角、动效。
- 机器状态、人工决定和最终视觉验收分开。
- UI 不得暗示尚未接通的 Photoshop 功能已经可用。
