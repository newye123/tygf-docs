# Tuyi Workshop UI/UX 设计系统与 Unslop 吸收规则

## 设计审查流程

将 Unslop 的“先审查，再修改”和产品专属视觉方向原则吸收到图译工坊设计流程中。此处是方法论改编，参考项目为 https://github.com/heydamir/unslop ，原项目使用 CC BY 4.0；如分发改编规则，保留作者与来源说明。

### 1. Slop Audit

- Heavy：信息结构、视觉层级、状态模型均有明显问题，允许整体重构。
- Light：保留已验证的结构，只修复明确的问题。
- No Slop：不做无依据改动，停止并给出少量建议。
- 每个修改都要关联问题证据和验收标准。

### 2. Direction Contract

- Product：服务对象与工作目标。
- Character：工具的性格与可信度。
- World：品牌和产品所在的视觉环境。
- Moments：关键操作与关键结果的视觉焦点。
- Signature：能形成产品识别的细节。
- Product Truth：界面所展示的功能必须与真实能力边界一致。
- Evidence Authority：截图、执行报告、测试结果和推断必须区分来源。

### 3. 九轮精修

1. Spacing：间距、栅格、对齐和密度。
2. Color：语义色、状态色和对比度。
3. Icons：图标体系与可识别性。
4. Copy：按钮、状态、提示语和错误说明。
5. Typography：字体、字号、字重、行高。
6. Layout：页面结构与视觉层级。
7. Details：边框、圆角、阴影和交互状态。
8. Visuals：真实素材、表格、图表与证据。
9. Motion：反馈、过渡和状态变化。

### 4. UI 的产品原则

- One Screen · One Primary Task · One Focal Moment · One Proof。
- 状态必须说明对象、动作、证据和下一步。
- 机器检查、人工决定、真实 Photoshop 执行和最终视觉验收分层。
- 不用“成功”标签覆盖待复核事项。
- 不将异常提示数量等同于错误数量。
- 不把模拟交互包装成生产能力。
- 视觉调整不能改变产品数据语义。

## V14.1 的视觉决定

- 主色沿用克制青绿，背景为冷灰白，文本为深灰绿。
- 成功色只用于回读、重开等有证据的机器状态。
- 琥珀色用于待复核；红色只用于高优先级内容风险。
- 报告首页优先展示“总体状态 + 核心计数 + 下一步处理”，长表格进入二级区块。
- 溯源哈希等排障信息默认折叠。
