# 图译工坊运营执行方案：从证据到合格试跑

## 目标与当前判断
图译工坊的运营目标是找到有重复多语言 PSD/PSB 工作量的客户，验证其是否愿意用代表性项目试跑，并最终判断是否有重复使用和付费信号。现阶段不以总曝光量作为主目标，也不预设效率提升比例。

已有资料表明：项目报告来自不同批次，统计口径不完全一致；部分报告含待复核、未覆盖、未命中、疑似未翻译或版式异常。因此，运营资产化必须先过证据门槛。

## 30天只验证三个核心假设
1. 存在一个可识别的客户群，持续遇到已有译文写回 PSD/PSB 的重复任务。
2. 真实产品演示、明确限制和数据透明度，能够帮助该客户群判断是否愿意试跑。
3. 在试跑范围、数据处理、费用和QA标准事先明确后，至少有部分客户愿意提供获授权的代表性样本。

## 工作流
证据盘点 → 目标账户评分 → 需求访谈 → 内容与演示 → 合格试跑 → 最终QA → 反馈与复用 → 商业提案。

## 客户分层
### A类：优先联系
有公开证据显示其经常做多语言电商设计；可编辑 PSD/PSB 是常规交付；有设计负责人或项目负责人可联系；业务重复频率较高。

### B类：验证型联系
有跨境设计或本地化业务，但还不清楚是否持有 PSD/PSB 源文件、译文是否由其确认，或多语言需求是否重复。先用访谈验证，不急着推试跑。

### C类：暂缓
主要业务是纯翻译、不接触设计源文件；只有偶发单次任务；没有授权测试材料；或已经拒绝联系。不要投入大量跟进。

CRM采用“适配度”和“互动意向”分开评分。适配度高但无互动的公司可进入首轮触达；互动意向高但产品不适配的线索也不能直接判为合格。

## 内容策略
12条内容已放入内容日历。它们覆盖问题教育、适配筛选、数据透明、报告解释、实机演示、测量方法和试跑转化。每条内容均有证据要求、CTA、主要指标和宣传风险。

发布前要先过四道门：
1. 是否对目标设计师解决一个具体问题？
2. 是否有真实证据，或者明确标注为示意？
3. 是否说明适用条件和人工QA边界？
4. 是否只有一个主要CTA，并能记录对应指标？

## 定向触达策略
- 首批账户以15家为起点，优先有公开业务证据的公司。
- 每封首信写出为什么联系这家公司，避免通用群发。
- 首次联系后3至5天可做一次有价值的跟进；8至12天可做最后一次礼貌跟进。
- 对方拒绝、退订或不希望继续联系，立即停止。
- 触达的目标是发现真实流程、频率、痛点和适配条件，不是追求发送量。
- 首封不附客户设计稿、不要求直接发送机密PSD、不先承诺免费。

## 试跑策略
试跑开始前书面确认：
- 输入文件、目标语种、源文件可编辑性、译文确认状态；
- 环境和产品版本；
- 数据处理范围、授权和脱敏；
- 测试范围、QA标准、交付物、费用和响应时间；
- 异常、失败、返工和数据删除方式。

“试跑完成”要求有输出、异常记录、最终QA和用户反馈。“首次任务成功”要求通过事先约定的QA。“重复使用”要求客户完成第二次真实任务。“付费客户”只按实际付款或正式采购记录计数。

## 指标体系
主漏斗：
目标账户 → 有效触达 → 有效回复 → 需求访谈 → 合格试跑 → 试跑完成 → 首次任务QA通过 → 重复使用 → 付费。

每周看：
- 新增目标账户数与证据完整率；
- 个性化触达、有效回复、拒绝联系和访谈完成；
- 访谈中反复出现的真实痛点；
- 试跑资格通过率、完成率、首次任务QA通过率；
- 14/30天重复使用、实际付费；
- 内容的目标用户互动、案例/演示访问和合格CTA；
- 数据隐私异议、兼容性不匹配和QA失败等护栏指标。

## 对抗式复盘
每周选一个最重要假设，写清：
- 目前的主张是什么；
- 什么证据可能推翻它；
- 需要什么观察或测试；
- 当前证据强度；
- 下周采取什么最小动作；
- 什么结果会停止或修改这个动作。

没有足够样本时，只记录方向性信号，不宣布确定的胜负。
