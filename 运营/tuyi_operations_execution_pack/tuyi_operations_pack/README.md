# 图译工坊运营执行包 v1

日期：2026-10-27
定位：将已有项目证据转化为可验证的客户需求、合格试跑和付费信号。此包是原有90天手册的执行层，不重复其宏观路线图。

## 本包内容
- `tuyi_operations_tracker.xlsx`：运营工作簿，含30天计划、内容日历、客户CRM、试跑追踪、周指标、实验记录、宣传主张审查和客户访谈。
- `30天执行计划.csv`：按日安排的执行任务。
- `30天内容日历.csv`：12条内容的主题、正文、证据要求、CTA和衡量指标。
- `获客话术库.md`：不同客户类型的首封邮件、跟进、LinkedIn和英文版本。
- `试跑SOP.md`：资格判断、试跑前确认、基线测量、QA、访谈和商业化判断。
- `客户发现访谈提纲.md`：25分钟访谈流程和记录规则。
- `运营对抗式审查.md`：每周检查运营动作的证据、失败模式和停做条件。

## 运营焦点
前30天先验证三个假设：
1. 目标客户是否真的有重复的多语言 PSD/PSB 交付痛点。
2. 真实工作流演示和明确的适用边界是否比泛化功能宣传更容易推动合格试跑。
3. 客户是否愿意在清楚理解数据流、QA责任和试跑范围后，提供授权样本进行验证。

## 不应提前做的事
- 没有QA和授权就发布客户案例。
- 没有端到端计时就宣传固定节省比例。
- 没有确认价格政策就称“免费试跑”。
- 没有数据流审查就承诺“所有数据不离开本机”。
- 没有实际付费记录就计入付费客户。
- 低流量时对小样本AB测试结果下强结论。
- 为了提高发送量而大量群发或联系已拒绝的对象。

## 每周复盘必须回答
- 本周有哪些动作真正完成？
- 哪些目标客户信号被观察到？
- 哪些是事实，哪些只是推断？
- 漏斗最大阻塞在哪里？
- 下周只优先验证哪个假设？
- 哪个动作应停止，哪个动作值得继续？
