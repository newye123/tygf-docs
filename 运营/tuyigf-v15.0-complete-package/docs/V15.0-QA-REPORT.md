# V15.0 QA Report

Date: 2026-10-31, implementation follow-up: 2026-10-31

## Automated backend tests

Command:

```powershell
cd local-agent
python -m pytest -q
```

Latest result in the build environment: **31 passed**.

Coverage includes:
- direct TypeLayer text extraction and EngineData `.value` fallback
- font metadata from `typesetting`, `font_names`, raw style data and FontSet index fallback
- multi-character style-run preservation
- text type, effective group visibility, opacity and bbox extraction
- unknown metadata remains null/unknown
- non-finite transform values are JSON-safe
- non-text layers excluded; known empty text layers retained
- deterministic task-local object IDs
- full PSD/PSB header validation, PSB version and reserved-byte checks
- health endpoint and explicit read-only/worker-timeout capabilities
- bearer-token enforcement, cross-origin rejection and Host-header/DNS-rebinding guard
- upload and scan lifecycle with controlled scanner adapter
- source task-copy hash comparison before/after scanning
- deletion blocked while a scan is active
- JSON and CSV export
- extension rejection and upload size limit
- default scanner worker process isolation
- worker timeout fails closed and removes temporary result file
- worker result-size cap rejects oversized JSON and removes the temporary file
- invalid PSD signature fails closed

## Not verified in this environment

- Actual `psd-tools` parsing, because the package could not be installed in this build environment and no real PSD/PSB fixture corpus was supplied.
- Windows 10/11 installation and execution.
- Photoshop comparison for real text, font, bbox, visibility and lock metadata.
- Large PSB memory/runtime behavior.
- Photoshop rendering equivalence.

## Release gate

Do not mark V15.0 production-ready until a Windows workstation with `psd-tools>=1.23` scans at least 20 representative PSD/PSB files and the extracted metadata is compared with Photoshop. The current browser smoke test uses mocked data; it validates UI behavior only.
