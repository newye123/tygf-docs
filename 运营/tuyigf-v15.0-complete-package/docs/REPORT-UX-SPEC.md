# 执行报告中心 UI/UX 规范

## 目标

将长篇执行 HTML 从“连续统计表”改造成任务状态、待处理事项、语言交付、逐对象记录和溯源证据分层的报告中心。该页面是 V14.1 的独立展示模块，使用上传报告中的实际数据，不连接生产后端。

## 信息架构

1. 结果概览：总体状态、源文件、时间、写入操作、语言数、输出文件数和待复核摘要。
2. 待处理事项：规格数字/单位、未覆盖对象、宽度风险、原文保持不变、表格未命中、统计口径差异。
3. 语言与文件交付：12 种语言的 29/29 状态、PSB/JPG 文件名、保存重开验证。
4. 替换明细：348 条操作记录，按语言、图层、原文、译文和状态检索，分页导出。
5. 溯源与证据：按语言折叠展示版本、构建身份、审查快照、规则版本和 SHA-256。

## 状态模型

- `write_verified`：文字写入回读匹配。
- `reopen_verified`：保存后重新打开并验证。
- `visual_review_pending`：等待人工查看 Photoshop 渲染结果。
- `visual_approved`：人工终检通过，需记录审核人和时间。
- `delivery_complete`：必需文件齐全且所有阻断项处理完毕。

当前样例报告只能证明报告所记录的写入/回读/重开状态。没有视觉批准证据，因此总体状态显示“已生成 · 需复查”。

## 关键展示规则

- 写入操作数与唯一对象数分开。
- 统计卡片只展示关键指标；完整定义放在统计口径说明中。
- 风险信号不等同于错误，不等同于失败。
- 共享译文表未命中允许按对象映射或忽略，必须保留决策记录。
- 未覆盖设计对象提供补译、映射、批准保留原文三种后续动作；当前静态样例只展示数据，不执行真实重跑。
- 原文与译文相同需要白名单/人工批准，不自动认定漏翻。
- 规格数字与单位检查应保留原值和译文值，并要求确认。
- 版式宽度增加只标记风险，不显示“溢出”结论。
- 原报告未提供的行号、输出文件实体、审核人和视觉批准时间不得补造。
- 溯源区默认折叠，便于技术排障但不压迫常规阅读。

## 视觉方向

- 沿用图译工坊青绿、冷灰、白底的工具型视觉体系。
- 以数据层级和留白组织信息，不使用大面积装饰渐变或无意义图标。
- 仅在总体状态和真正需要警示的项目上使用强调色。
- 表格支持横向滚动、搜索、语言筛选和分页。
- 桌面优先，移动端使用单列卡片和横向表格容器。
- 支持打印/保存 PDF。

## 当前实现边界

此版为静态数据驱动的 HTML 报告展示原型。筛选、分页、CSV/JSON 导出和打印在浏览器本地执行。没有连接任务数据库、文件存储、Photoshop 或本地 Agent；没有真正重跑任务或修改报告源数据。
