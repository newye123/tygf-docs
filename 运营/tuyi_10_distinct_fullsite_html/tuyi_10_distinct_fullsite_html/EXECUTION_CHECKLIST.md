# 官网改版执行清单

目标：从 10 个全站概念中选出一个能被真实证据支撑的方向，完成小范围理解测试，再进入生产改版。该清单不预设流量、转化或效率结果。

## 阶段 0：确认事实与发布边界

负责人建议：产品负责人、技术负责人、交付负责人。

- [ ] 确认当前正式发布版本，解释下载页 v3.7.15 与交接材料 v3.7.28 的差异。
- [ ] 确认批量语言上限、支持的文字图层类型、已验证 Photoshop 版本及已知限制。
- [ ] 由技术负责人逐项确认 PSD/PSB 文件本体、图层文字、译文、路径、日志、诊断数据和第三方 AI 请求的实际流向。
- [ ] 确认第三方处理方、数据处理地区、保留期限、删除方式、支持模式和故障排查上传机制。
- [ ] 确认真实试跑的收费方式、范围、响应时间、交付物、客户授权与后续流程。
- [ ] 选定一个候选真实项目，找回原始报告、源文件、最终输出和 QA 记录。

**验收条件：** 版本与数据流存在明确的书面结论；任何不能确认的内容从对外文案中删除或明确标注为待验证。

## 阶段 1：先评审四个高价值方向

优先顺序：

1. `03-evidence-dossier.html`：审查真实报告和证据链。
2. `08-data-trust-map.html`：审查隐私与企业客户的信任问题。
3. `09-time-economics-lab.html`：审查效率主张的测量方法。
4. `02-interactive-photoshop.html`：审查产品理解和仿编辑器是否造成误解。

- [ ] 让 5 至 8 位目标用户独立浏览，每人先不解释产品。
- [ ] 记录他们如何描述产品输入、输出、人工 QA 和数据流。
- [ ] 记录他们把哪些示意内容误认成真实界面、实际数据或产品承诺。
- [ ] 记录最影响试跑决策的一个未解决疑虑。

**验收条件：** 选择方向时优先考虑正确理解率、合格申请质量和错误预期风险，不只看喜欢哪种视觉。

## 阶段 2：把模拟内容替换为真实证据

- [ ] 用真实产品屏幕录制替换仿编辑器和虚构工作台，或者持续保留清晰的“示意界面”标签。
- [ ] 选择一份通过最终 QA、去重、授权和脱敏检查的真实案例。
- [ ] 报告中分别展示已替换文字层、未覆盖对象、未命中译文、疑似未翻译、版式待复核和最终 QA 状态。
- [ ] 对外展示效率前，完成同一项目的手工与辅助流程端到端工时测量。
- [ ] 不展示未经授权的客户 Logo、源稿、评价、业务数据或原始路径。

**验收条件：** 每个客观主张都有来源、口径、负责人和复核日期。

## 阶段 3：连接真实 CTA 与跟踪

建议事件名：

| 事件 | 触发条件 | 需要记录的字段 |
|---|---|---|
| `homepage_view` | 首页加载 | 页面版本、来源、设备类别 |
| `demo_open` | 点击真实演示入口 | 页面版本、来源 |
| `evidence_open` | 打开案例或证据页 | 页面版本、来源 |
| `privacy_open` | 打开数据处理说明 | 页面版本、来源 |
| `trial_start` | 开始填写正式试跑表单 | 页面版本、来源 |
| `trial_submit` | 正式表单提交成功 | 页面版本、来源、资格结果 |
| `trial_qualified` | 负责人按定义判定合格 | 项目类型、目标语言数量区间、是否有已确认译文 |
| `trial_completed` | 试跑完成并记录 QA | 项目 ID、处理状态、异常分类、完整工时 |
| `repeat_use` | 客户再次使用 | 项目 ID、时间间隔 |
| `paid_conversion` | 发生真实付费 | 来源、产品方案、成交日期 |

不要把邮箱、源文案、译文或客户文件路径放进普通分析事件。敏感字段的处理应由技术和隐私负责人确认。

**验收条件：** 在测试环境逐个触发事件并核对后台记录；表单没有真实提交成功回执时，不显示成功状态。

## 阶段 4：响应式、可访问性和浏览器验收

- [ ] 在 Chrome、Edge、Firefox 各测试一次主要路由。
- [ ] 测试 320、390、768、1440 CSS 像素宽度。
- [ ] 使用键盘完成导航、选项切换、表单提交和结果读取。
- [ ] 检查焦点可见、标题换行、颜色对比、表格溢出和错误提示。
- [ ] 检查系统缩放与减少动态效果偏好。
- [ ] 对下载、外链、邮件通知和正式申请做一次端到端测试。

**验收条件：** 无阻断性路由错误；模拟界面与真实产品区分清晰；表单和主要操作有可见反馈。

## 阶段 5：小规模上线与复盘

第一轮只发布一个主方向和一个备用方向。先用访谈与真实申请判断理解问题，再决定是否进行统计意义上的 A/B 测试。

每周复盘：

- 独立访问和来源。
- 演示、案例和数据政策点击。
- 试跑开始、提交、合格、完成。
- 首次任务成功的定义与证据。
- 端到端工时、返工、异常原因。
- 14/30 天重复使用与付费。

**决策规则：** 如果点击增加但不合格申请、隐私误解或对产品能力的错误预期也增加，不应将其判定为胜出方案。
