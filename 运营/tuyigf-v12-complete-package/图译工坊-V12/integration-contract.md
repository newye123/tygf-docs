# 正式工程对接接口建议

## 1. 文件扫描

输入：本机文件 ID、PSD / PSB 路径、扫描范围。
输出：文件格式、文档尺寸、文字层 ID、层级路径、原文、原样式、文本类型、文本框、可编辑状态、扫描版本、错误。

**本机处理**：设计文件字节不上传。若有原文和路径字符串传云端，需按正式隐私说明披露。

## 2. 译文表解析

输入：CSV / TSV / Excel、多语言列映射、源文字、文件关联。
输出：译文对象 ID、语言、内容、定位、格式错误、同原文多译及重复数据。

必要性：支持一个文件映射多表、同原文不同上下文、跨文档共用译文表。没有确定关联时要求人工确认。

## 3. 字体设置

建议配置结构：

```json
{
  "document_id": "example-psb-01",
  "language": "ja-JP",
  "scope": "translated_text_layers",
  "style": {
    "font_postscript_name": "ExampleFont-Regular",
    "weight": "Regular",
    "size_pt": null,
    "leading_pt": null,
    "tracking": null,
    "kerning": "preserve",
    "baseline_shift_pt": 0
  },
  "fallback": "preserve_original",
  "confirmed_by_user": true
}
```

规则优先级建议：原稿默认 → 语言默认 → 文件与语言指定 → 图层或组的人工例外。每份执行清单冻结一个生效快照。

安装字体数据需由本地助手读取，并提供 PostScript 名称、家族、字重、版本和字符覆盖提示；不得把浏览器模拟字体当作已安装字体。

## 4. 执行前检查

检查 Photoshop 版本、助手连接、文件是否可写、图层是否可编辑、字体是否可用、译文是否覆盖全部必需对象、可能导致长词/数字/单位问题的内容。

## 5. 执行与核验

逐文件、逐语言、逐对象执行。每层写入后读回，保存后关闭重开进行持久化验证，日志和失败重试采用稳定的 document_id、language 和 layer_id。

执行状态、内容完整性检查、视觉排版人工终检分开记录；不能用一个“成功”覆盖三个维度。

## 6. 安全与计费

执行前给出范围与费用估计。未匹配、跳过和失败项的计费遵循生产规则；须保留足够审计证据供用户复核。
